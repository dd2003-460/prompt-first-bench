# T53-taste-sop: 审美/taste SOP 的分解树 (2026-11-12, D 指令)

D 原话: "我需要你培养审美/taste的sop。你有什么想法吗，主要是高视角:信息理论，互信息，残差分析，等等这些下，prompt工程可以做到什么，类似什么，迁移什么，轻松从理论导出什么或者不能"

## 核心问题（先定义 taste 是什么）

taste = 在多个"都对"的选项中选"更好"的那个的判断力。SOP 化 = 把这个判断拆成可执行的检查步骤 + 可计算的量。
"高视角"约束 = 每个 taste 判据必须能锚定到信息论/统计量的某个量上，否则就是装饰（对齐 D 的信息搜集原则：每条信息要能变成可计算量的输入）。

## 分解树（正交子项）

### S1. 把 prompt 工程当信道看 —— 能导出的（conf 0.8）
模型是固定解码器，prompt 是唯一可控的信源端编码。可迁移的量：
- I(prompt; output)：prompt 携带的任务相关信息有多少 → 对应"信息密度"判据：删掉一句后输出分布不变 = 这句 I≈0 = 废话，删
- H(output | prompt)：给定 prompt 后输出的剩余熵 → 对应"确定性"判据：H 高 = 模型还在猜 = prompt 欠约束；但 H=0 也不好（过拟合单一路径，没留探索空间）→ 最优区间而非越大越好
- 冗余度：prompt 内自信息重叠（同义反复句）→ 压缩律直接适用：功能等价选更短
- 类比：rate-distortion —— 预算 B(T) 下保真度最大化，我们的 token 预算就是 rate，任务完成度是 distortion
缺口: [待核验] "删句测 I" 在本地 27B 上的实操成本（每句一次差分 run？）

### S2. 残差分析 = taste 的核心引擎（conf 0.85）
这是 D 点名的、也是我认为最值钱的一块。逻辑链：
- 预测（先验函数 Route B 的产物）vs 实测 → 残差 r = observed - predicted
- **|r| 小的方向 = 已懂 = 不用再花预算**（对齐思考预算 L0）
- **|r| 大的方向 = 不懂 = 调研入口**（对齐 D 的研究优先红线：防御性语言=调研入口）
- taste 判据由此导出：**好方案 = 让下一步残差最小的方案**。两个候选都"能跑"时，选那个跑完后预期残差更小的——因为它的失败模式更可预测
- 反例判据：一个改动如果"怎么改残差都不变"（对指标无杠杆），无论多优雅都是装饰
- 和我们已有资产对接：degraded rate 曲线 = 时间序列残差；grokking 探针 = 残差的延迟结构（先正后负）
缺口: 残差需要预测基准，而预测基准来自先验函数 → S2 依赖 Route B 落地（L35 已确认数学语言就绪）

### S3. 哪些理论能轻松导出，哪些不能（边界表）
| 理论工具 | 能导出 | 不能导出 | 原因 |
|---|---|---|---|
| 互信息 | 删句测试、信息密度排序 | prompt 各句的因果贡献 | MI 是关联不是因果，句子间有交互项 |
| 率失真 | 预算分配（哪块值得多花 token） | 具体怎么措辞 | 只给"多少"不给"什么" |
| 残差/预测误差 | 调研入口、停止条件 | 残差的方向修正 | 告诉你在哪错，不告诉你往哪改 |
| 压缩律(MDL) | 方案选择（同等解释力选短） | 新假设生成 | 只能评判不能创造 |
| Goodhart 定理 | 指标防御设计 | 指标本身的设计 | 告诉你别信单一指标，不告诉你该信哪个组合 |
共性规律：**信息论工具全是"评判器"不是"生成器"** —— 它们能告诉你什么是好的（压缩比高、残差小、MI 大），但不能告诉你下一个好方案长什么样。taste 的生成侧（直觉/类比/跨域迁移）目前无理论覆盖，这本身就是 gap 声明。

### S4. SOP 本体（产出物形态）
一份 `~/.hermes/rules/taste.md`（或 pfb/sop/ 下），内容 = 上面三块的执行版：
1. 五个检查动作（每个带触发条件和可计算判据）：删句测试 / 残差定位 / 杠杆测试 / 压缩律比对 / Goodhart 自查
2. 三个 taste 锚点案例（用我们自己的历史：v17 Goodhart 案、D34 query 瘦身、T53b hook 臂 Δ+0.025 的判定）
3. 一条元规则：任何 taste 判断落盘时必须写成 "判据 + 数字 + conf"，禁止纯形容词
缺口: 放 rules/ 还是 pfb/sop/？我倾向 pfb/sop/（它是研究方法论，不是行为约束），rules/ 只放指针

### S5. 验证方式（防 SOP 自己变成装饰）
- 回测：拿历史 3 个决策（D34 瘦身为什么对 / v17 为什么翻车 / #31 为什么值得跑）跑一遍 SOP，看判据能不能复现当时的正确判断
- 前测：下一轮 prompt 修改前强制走一遍五检查，记录是否拦住了低价值改动
缺口: 回测需要当时的原始数据都在盘上（D32/D34 树应该有）
