## 背景（给 arena agent 的上下文）

我们在做 prompt-first benchmark：测不同 prompt 风格（v0 朴素空间直觉 / v1 代数判据 / v2 混合引导式）对 LLM 事实调研质量的影响。n=30 结果：v1（代数）≈ v0（Δ=+0.019，噪声级），主增益在研究+验证臂。T26 Q4 发现 v1 有独有的 fabrication 失效面（4 种模式），v0 有不可审计缺陷。现在要设计 v2 混合臂的可执行形态。

成璐的组合设想（他的原话搜索结论）："正交完备检查、回退、占位留空、调研后填充合在一起的工作——没找到。" 即：
- 完备性检查用 LLM 判断（已知无法证明穷尽，接受）
- 失败时递归回退重新分解（ADaPT, NAACL 2024 Findings：只在执行者做不了时才继续分解，ALFWorld/WebShop/TextCraft +28.3%/+27%/+33%）
- 不确定的区域先占位 `[待核验]`，不编
- 调研阶段回来填充占位

## 需要调研的具体问题

### Q1: STaD 重建测试怎么落地为 prompt？
- 原始论文（arXiv 2604.18177）的重建协议具体是什么？输入输出格式？
- coverage 87.5-99.3% 是怎么算的？（人工标注还是模型自评？）
- 如果让**另一个模型**（异构 judge）做重建，prompt 怎么写才能避免"模型对错都倾向同意"（CoVe 反例：yes/no 封闭题 precision 退化）？
- GitHub 上有没有现成实现？

### Q2: ADaPT 的失败检测机制
- "执行者做不了"是怎么判定的？（执行超时？自报失败？外部 verifier？）
- 判定本身靠执行者生成的成功启发式 → 校准问题怎么处理的？
- 回退粒度：回到哪一层？保留已完成的子任务吗？
- 有没有开源实现（ALFWorld/WebShop 环境代码）？

### Q3: 组合臂的 prompt 结构
- 把 STaD 重建 + ADaPT 回退 + 占位留空 + 调研填充串成一个多轮流程，轮次间状态怎么传递？
- 每轮的 prompt 应该包含上一轮的哪些产物？（全量 vs 摘要 vs 只传缺口清单）
- 这个组合里哪些环节最可能引入新的 fabrication 风险？（参考 T26 Q4 的 4 种模式）

### Q4: Agent-Oriented Planning 检测器（成璐贴的来源）
- "抽出原问题所有关键要素→逐个匹配子任务→检查未预见依赖"这个检测器的出处和细节
- 它和 STaD 重建的区别：逐要素匹配 vs 整体重建，哪个更抗 fabrication？
- (paperswithcode) 链接对应的具体论文是哪篇？
