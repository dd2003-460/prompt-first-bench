## 分解 = K^t tradeoff 单循环（S34）

本分解树本身是 K^t 复杂度在条件 C 下的 tradeoff 产物，不是"四个维度的检查清单"。
四个环节是同一循环的不同面：正交 = 压缩的约束、完备 = 压缩的终止条件、
目标函数 = tradeoff 的判据、tradeoff = 压缩本身。

### 压缩·结构化（分解树本身 + 正交约束）
- 四层互不重叠：管线流程（怎么收口）/ 研究 idea（研究什么）/ 工程前置（跑实验要什么）/ 工程维护（挂起的活）。
- I2a/I2b/I2c 正交：实例折叠=结构变换、冗余检测=度量筛选、信息密度=目标函数定义——不同轴。
- I3 与 I1 正交：I1 收口现有数据口径，I3 补测 webllm 维度——一个收口一个开新。

### 停止条件·预算（何时停 = 完备的终止条件，S33 阶段性）
拆到"充分到方便优化"即停，缺口标 [待核验] 不阻塞：
- **缺：I2 的目标函数正交维度**。候选 {压缩比, 覆盖保持率, 解码时间, 可靠性} 是否完备？[待核验: 是否漏"新鲜度"（S30 条件域漂移检测）]
- **缺：SM 重构的验收判据**。可机判：重构后 SM 输出 JSON 里 f(H) 节点数 ≈ 14（K-bound），实例节点由脚本生成不占 LLM token。[待设计]
- **缺：I2c 信息密度指标的公式定义**。5-run 基线 144x/0.7% 的算法是否可推广到 62 run？[待核验]

### 新信息·理论（压缩的依据 = 目标函数定义 K 下界）
- **T53b 本 goal 目标** = 验证 S5 prompt 格式假设（formula vs text 臂消融）。K 下界 = 统计量（coverage/depth 均值±SE + 95%CI，n=10）。
- **I2 目标** = 验证"general 改法"是否真的压缩了（节点数↓ 且覆盖不丢）。这是**科研目标**（高复用、高可靠）——K 下界 = 14 原子（11 效率函数 + 3 微架构系数）。
- **SM 重构**（工程前置）= K^t 框架 S28 的落地，属 autoresearch 项目，pfb 消费不研究。

### 新信息·自然/社会校验（C' 来源，唯一正和信息）
- **I1** = 62 run 已有信息 → 统计量；校验 = 统计显著性（95%CI 不跨 0）+ 敏感性（去极端轮次 Δ 不变）。
- **I2** = 新条件 C'（general 改法）→ 实例折叠/冗余检测展开隐含信息 → 压缩成新结论；校验 = 新 batch 的 A/B 对比。
- **I3** = webllm 维度补测；校验 = 配对实验 with/without Δ。
- **SM 重构**（工程前置）= 校验 = f(H) 节点数 ≈ 14 + 脚本展开与 LLM 展开一致率。
