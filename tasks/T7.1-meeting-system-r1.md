# T7.1: 30 人团队会议室预约系统选型（全流程首跑）

**状态**: ready（T6 verdict pass 后开跑，2026-10-28 r27）
**执行通道**: arena agent mode @ prompt-first-bench 仓库（已绑定）
**流程**: 00-common-review → 01 → 02 → 02.5 → 03 → 04 → 04.5（严格按仓库内 loop/prompt-first/ 阶段 prompt 执行）

## 任务定义

为 30 人研发团队选一套会议室预约系统：预算 ≤2 万元/年，需支持 macOS/Windows/Web 三端、日历集成（Google Calendar + Outlook）、门禁联动可选。产出可交付的选型报告（推荐方案 + 备选 + 淘汰理由 + 成本明细）。

## 执行步骤（arena 侧）

1. 按 00-common-review 做前置检查（目标可分解性、域边界）
2. 01-goal-decomposition：候选类别枚举 + **候选集冻结声明**（修订规则①）
3. 02-information-research：每候选逐一核验，**每条主张附来源 URL/路径+时间戳，无法核验的显式标"存在性断言-未核验"**（修订规则②）
4. 02.5-cross-check：关键结论 ≥2 独立来源交叉
5. 03-action-decomposition：每步标 **owner=user/agent**（修订规则③），需用户交互的步骤显式标阻塞点
6. 04-execution-verification：执行检索/验证动作，真实记录输出与失败；需用户交互的步骤留默认假设并标注，不伪造
7. 04.5-final-review：反方复核，逐项核验三条修订是否生效，verdict + repair_stage 落 loop-artifacts/stages/04.5/
8. git add -A && git commit && git push origin <当前分支>

## 验收标准（Lead 侧）

- 六阶段工件齐全于 loop-artifacts/stages/
- 三盲点修订生效证据逐条核对（同 T6 核验方式）
- 最终选型报告可交付（非半成品）
- verdict 记录在案

## 对照价值

T7.1 与 T6 首测同属"选型"类但不同域（软件 vs 硬件），是基线对照：若 T7.1 也 pass，则"初步稳定"样本 = 2 域 PASS（T7 验收标准 §4）。
