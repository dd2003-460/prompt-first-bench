## §1 结构条款

### C1 — 三区结构（强制）

queue 恒为三区，顺序固定：`## 待办` → `## 已完成` → `## 新导出候选`。
- 新导出的候选一律追加「新导出候选」区（见 C7）；goal 被消费执行后其行**就地翻转** `[x]`（不跨区移动——历史先例：r113-r150 全部收口均为就地翻转，完成行沉淀在「新导出候选」区是既有事实形态）。
- 「已完成」区保留给早期未走候选流程的直接完成项（L18-L21 先例，f7d3674 基准）。
- 新候选恒追加至该区**末行**；收口翻转就地进行，两者顺序无关（逆序非违规，r150 收口 L24/L25 交错实例）。
- 证据：queue L6/L15/L23 三标题（f7d3674 基准）；r146 sweep 近 20 轮收口逐行确认无跨区移动实例。

### C2 — checkbox 三态语义（强制）

| 态 | 语义 | 生命周期 |
|---|---|---|
| `[ ]` | 未完成（可执行或被阻塞） | 收口轮翻转为 `[x]` |
| `[x]` | 完成（含被吸收核销） | 终态；元数据段补全（C8） |
| `[~]` | 材料已备、待人工裁定的**设计内终态**——message 明言不划掉 | 不翻转；裁定完成后由裁定执行轮翻 `[x]` 或删行 |

- `[~]` 不参与 assert-queue-lint (b) 检查（docstring 预注册；r146 sweep 对现存 3 行 L32/L55/L56 逐行确认语义一致，f7d3674 基准）。
- 证据：assert-queue-lint.py docstring (b) 节；queue erratum-27 / o3-claim-rejudge / jaccard-adjudicate 三实例均带「待成璐裁定」「不划掉」注记。

### C3 — 未完成行五段式（强制，适用所有新增 `[ ]`/`[~]` 行）

```
- [ ] <goal 短名> | <一句话目标> | <产投比依据>
```

- 最少 2 个 `|` 分隔符（三段）；扩展内容（blocked 注记、联动说明、风险标记）并入第三段，不另起段。
- 短名 = 首空白前 token，不含括号元数据（lint 短名提取式：剥 `~~` + 截断首个左括号，r149 X4 裁定）。
- 证据：queue L3 格式说明行原文；r151 阶段 02 S2 实证——现存 10 个未完成行 **10/10** 满足 ≥2 pipe（本条款是对既有 100% 一致事实的成文化，非新规）。

### C4 — 完成行形态（推荐五段式 + em-dash 简写豁免）

- **推荐**：与 C3 同构的五段式 + 元数据括号（C8）+ 结果注记（C5）。
- **豁免**：`- [x] <短名> (<元数据>) — <单段摘要>` em-dash 简写合法（0 或 1 个 pipe 均可）。
- 豁免依据：存量低 pipe 行全部为 `[x]`（r151 02 S2 实数 15：严格 em-dash 零 pipe ×8 + 单 pipe 混合 ×7），且 r149 02.5 X2 裁定明确「不设 pipe 计数下限」——对已完成行追加分段严格性会红屏存量（工具首跑即失信用）。
- 豁免边界：简写只豁免**分段数量**，不豁免 C2（checkbox 必须真翻转）、C5（若含结果注记须用标准标记）、C6（若涉跨区重复须含吸收声明）。
- 存量改写与否 = 开放裁定项，见 §4 存量状态节（不代裁）。

### C5 — 结果注记标记（强制，适用所有新增结果注记）

- 标准形态：`**结果**：` —— 加粗闭合在「结果」后、冒号在加粗外，**半角冒号**（U+003A）。
- 禁止新增变体：`**结果：`（早期写法，存量 4 处 L8-L11 不再增加，f7d3674 基准）、全角冒号 `**结果**：`（U+FF1A，零存量）、裸文本 `结果：`（零存量）。
- **判定锚定加粗标记形态而非「结果」子串**：行体描述性文字含「结果」二字不构成结果注记（queue L29 本 goal 行自注实例 + L55 rejudge 行实例）——未来任何收紧检查不得按裸子串误伤。
- 机器侧影响：assert-queue-lint (b) 现行匹配 = 覆盖 `'**结果：'/'**结果**：'/'**结果**:'` 全变体的宽松实现（r149 W2 修复）——该鲁棒性以本条款存在为前提；未来收紧为精确匹配见 §3 R2。
- 矛盾登记（首例应用 §5 原则）：两代写法并存 20 vs 4，按「多数派 + 最新轮次」取 v2（r142 后零 v1 新增）；早期 4 处登记于 §4 不强行改写历史。
- 证据：r151 02 S3 实证 24 处结果注记 = `**结果**：`×20 + `**结果：`×4（v1 四行冒号同为全角 U+FF1A，独立 codepoint 核验）；r149 04.5 攻击 7 原文「这是惯例不是契约」——本条款即该攻击的承接落地。

### C6 — 吸收登记行（强制：声明存在性）

- 同一短名跨区出现 >1 次时，≥1 行须含「吸收」字样声明，否则 = lint (a) FAIL（真失控形态）。
- 带声明的跨区重复 = SIGNAL（报告不拦截）——合法登记形态。
- **合法声明位置 = 短名后的 meta 括号内 `被 <来源> 吸收` 短语**（如 `(2026-10-30, 被队首同名 goal / r116 吸收)`）——现存 3 组跨区实例（L52/L53/L54 ↔ L9/L10/L11）全部符合；L51（RV3G5-blocker-disposition-table）短名全文件唯一，属「吸收说明」非跨区重复，不受本条约束。
- 宽匹配边界登记：现行机判为整行子串匹配，行内任何位置出现「吸收」即豁免（r149 攻击 2 部分成立登记；误豁免方向安全）。收紧规格见 §3 R3（观察项，不预修）。
- **防误伤条款**：叙述性提及「吸收」不构成合法声明（L28 queue-dedup-lint 收口行结果注记内多处叙述性使用「吸收」实证——其短名唯一，根本不触发 (a)；未来若某行仅靠正文叙述含「吸收」而短名真跨区重复，须按 C6 主条款补 meta 声明）。

### C7 — 候选追加位置（强制）

新导出候选追加「新导出候选」区**底部**，不插队、不插入「待办」区。
- 证据：queue L3 说明行「新导出的候选追加到底部」；r146-r150 五轮收口追加行为逐一核实均在区尾。

### C8 — 元数据段（推荐）

完成行翻转时补 `(date, rNNN: hash, branch)`：
- date = 收口日（YYYY-MM-DD）；rNNN = 轮次；hash = 收口 commit 短 hash（多 commit 用 `+` 连接，r150 先例 `f20946f+4008a30`）；branch = `ralph/<goal-slug>`。
- 允许降级：缺 branch 或 hash 的简写元数据合法（L44 型 `(2026-10-30, r106: 6fbd47b)` 无 branch 仍 PASS）——本条款推荐级而非强制级，因存量低 pipe 行中部分无完整元数据。
- 日期锚定**日期本身**而非括号字符（半角 `(` 或全角 `（` 均认——L58 `~~RV3G6-audit8-erratum~~（2026-10-30 完成）` 全角括号实例实证）。
- 核销轮特例：补翻历史漏翻行时元数据段注明「rNNN 核销轮补翻」（L37 threshold-crossdomain-reverify 先例，f7d3674 基准）。
