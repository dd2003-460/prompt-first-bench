# GPU 选卡题 · 机械连续 judge（rubric_gpu_mech）

# origin: ai · 2026-11-25 · 对齐本地先例 score_m7.py（纯规则判分，无 LLM judge）
# D 指令："这是错误的judge，请你找机械和连续版本的"

## 为什么 v2 二元清单是错的 judge
v2 的 8 项 pass/fail 仍由 LLM（Lead）读原文打勾 = 离散 + 主观。只是把 1-5 分压成 0/1，没脱离"LLM 当裁判"。
机械 = 确定性脚本 f(输出)→数字，无 LLM 参与、可复现、每个数可审计。
连续 = 比率/计数（0-1），不是 0/1 打勾或 1-5 分档。

## 形态（抄 score_m7.py）
- 每个可验证要求 = 一条正则（检测"概念 + 上下文"，非裸提及）
- 子分 = 命中数 / 模式数 ∈ [0,1]（连续）
- 总分 = 子分均值 ∈ [0,1]
- 输出：每子分 + 全部 hits（哪条正则命中）→ 可逐条审计
- gold 参照集（型号白名单/维度集）来源透明，声明如下

## 三档连续子分

### S1 候选广度（count，饱和于 12）
n = 提及的不同真实硬件 SKU 数（白名单见下），S1 = min(n/12, 1.0)
白名单（来源=真实市场 SKU，非模型编造）：
  消费级: 4090 3090 4080 3060 4060 "RTX 6000 Ada" A6000
  数据中心: A100 H100 H200 L40S L40 A40 A800 H800
  AMD: MI250X MI300X MI300A
  非典型: FPGA TPU Mac/Apple(M1/M2/M3/M4) CPU+大内存
（白名单共 18 项，目标广度 12 = 覆盖三类 + 若干代际即饱和）

### S2 维度覆盖（ratio，满分 10 维）
gold 维度集（来源=题面"影响决策的维度" + GPU 部署标准考量）：
  功耗/散热 · 显存带宽 · PCIe/拓扑 · 互联带宽(NVLink) · 软件栈/驱动
  二手/矿卡风险 · 价格波动 · CPU/内存 · 机箱/供电 · 量化方法(GPTQ/AWQ)
n = 讨论到的不同维度数，S2 = n/10

### S3 要求合规（score_m7 式 patterns，6 条）
P1 容量下限: (32\s?K|32768).{0,60}(上下文|context|KV)
P2 精度质量论证: (BF16|FP8|INT8|NVFP4|W4|量化|精度).{0,120}(质量损失|可接受|困惑度|perplexity|下降|损失)
P3 单多卡TCO: (单卡|多卡|2\s*[×x*]).{0,120}(TCO|总成本|成本)
P4 数字溯源: (\[待核验\]|待核验|来源[:：]|凭记忆|刚查|已验证)
P5 条件性推荐: (若|如果|取决于|在.{0,10}条件下|前提|假设).{0,80}(推荐|选择|建议)
P6 非典型方案: (FPGA|CPU\s*\+|大内存|二手|矿卡|混合架构|非典型|TPU|Mac|Apple)
S3 = 命中数 / 6

## 总分
Overall = mean(S1, S2, S3) ∈ [0,1]（连续）

## 判分对象
- Arm A：单段 content
- Arm B：6 阶段拼接全文（同 T8a 盲化口径）
- 两臂同一把尺子，脚本确定性 → 可复现、可审计

## 已知局限（诚实标注）
1. 正则可被"关键词堆砌"刷分（提及但无实质）——机械 judge 固有，但远优于 LLM judge 的主观性。
2. 白名单/维度集是人为圈定的 gold，覆盖"该想到什么"，不判"想得对不对"（正确性需另一层，见下）。
3. 正确性（数字算没算对、推荐合不合理）不在本 judge 范围——那是 gold 答案比对层，机械 judge 只管"覆盖/合规"维度。若要判正确性，需 gold 参考答案 + 数值容差比对（另一套）。

## 生死线（沿用 T8b prereg，判据=Overall 均值）
B > A 且 recall ≥2/3 → 流程有效（附成本代价）；recall 高但持平 → 纯结构；B ≤ A 或 recall <1/3 → 无效。
