# T8b Smoke Test 报告（pfb 六阶段 vs 直接求解）

> **定位**：smoke test，不是有效性实验。有效性需 T8c 的 token-matched 对照。
> 本报告只回答三个 smoke 问题：**recall 是否成功 / 有无退化 / coverage 如何**。不做质量提升声称。

> **指标口径（D 2026-11-25 修订）**：
> - **主指标 = unit 级覆盖（S1/S2/S3）**：量的是推理链完整性（SKU 广度/维度覆盖/需求合规），
>   与 gold 赢家的时点性无关——gold 稳定的是树结构（准入规则+计算路径），不是赢家标签。
> - **辅助指标 = correctness 探针（binary 匹配 3090×4/W4/n=2）**：仅作**时点快照**，
>   标注「时点特定，非稳定性 claim」（gold-tree.md L6 自注：混合负载可能改变赢家排名）。
> - **错误归因分析**：对 correctness 判错/无法提取的输出，检查其是否覆盖赢家关键要素，
>   区分「缺要素→coverage 问题」vs「要素齐全但结论错→推理/算术问题」。

## 2. Correctness 探针【辅助指标·时点快照】

gold 锚点 = **3090×4 / W4 / n=2**（来源：`pfb/bench/rubric-v3/ablation/gold-tree.md` 头部声明）。
> **口径警示**：此锚点是**时点特定**的赢家标签，**非稳定性 claim**。gold-tree.md L6 自注「混合负载下效率大幅下降，可能改变赢家排名」——gold 稳定的是树的结构（准入规则+计算路径），不是这个标签。故本节仅作时点快照，主 claim 不依赖它。
机械提取规则：取每条输出**最后 2000 字符**，正则找主卡型（窗口内最早出现的卡型）+ 数量（`N×卡型`）+ 精度（W4/W8/W16/INT4/INT8/FP8/BF16）。
判定：卡型=3090 且 精度∈{W4,INT4} 且 数量=4 → **对**；提取到推荐但与 gold 不符 → **错**；提取不到 → **无法提取**。
探针局限（如实标注）：① 只看尾部 2000 字符，条件式/多分支结尾（如决策树）可能提取不到单一主推荐；② 数量只认 `N×卡型` 紧邻写法，`4 张 3090` 这类写法会漏检；③ 精度取窗口内首个命中，若尾部先提 INT8 后提 W4 会取到 INT8。故 correctness 是**下界估计**（漏检只会低估，不会虚高）。

| 样本 | 提取到的最终推荐 (卡型/数量/精度) | 判定 |
|------|----------------------------------|------|
| A1 | A100×1 / INT8 | **错** |
| A2 | 3090×2 / INT8 | **错** |
| A3 | L40S×1 / INT8 | **错** |
| B1 | A100×2 / BF16 | **错** |
| B2 | A100×1 / FP8 | **错** |
| B3 | A100×1 / INT8 | **错** |

**correctness 汇总**：A 臂 **0/3 对**；B 臂 **0/3 对**。

解读（仅描述机械提取结果，不做质量评判）：
- A1 提取到 A100×1 / INT8 → 错（卡型即与 gold 3090 不符）
- A2 提取到 3090×2 / INT8 → 错（卡型命中 3090 但数量/精度与 gold 不符）
- A3 提取到 L40S×1 / INT8 → 错（卡型即与 gold 3090 不符）
- B1 提取到 A100×2 / BF16 → 错（卡型即与 gold 3090 不符）
- B2 提取到 A100×1 / FP8 → 错（卡型即与 gold 3090 不符）
- B3 提取到 A100×1 / INT8 → 错（卡型即与 gold 3090 不符）

## 3. 错误归因分析（覆盖赢家关键要素检查）

对 correctness 判「错/无法提取」的输出，机械检查其**全文**是否覆盖赢家配置 3090×4/W4/n=2 的关键要素，
回答 D 的核心问题：**覆盖更多要素是否自然导出正确答案？**

关键要素清单（机械可检测）：3090 卡型 / 3090×4 数量 / 3090 显存 24GB / 3090 带宽 936GB/s /
W4/INT4 精度 / W4 权重 VRAM≈13-14GB / W4 质量损失论证 / 多卡(4卡)判断 / 并发 n 判断。
判定规则：**关键三要素**（3090 卡型、W4/INT4 精度、多卡判断）任一缺失 → **a) 缺要素（coverage 问题）**；
关键三要素齐全但结论仍错 → **b) 要素齐全但结论错（推理/算术问题）**。

| A2 | 错 | 3090卡型、3090显存24GB、3090带宽936GB/s、W4/INT4精度、W4权重VRAM~13-14GB、W4质量损失论证、多卡/4卡判断 | （无） | **b) 要素齐全但结论错→推理/算术问题** |

**归因汇总**：6 条判错/无法提取中，**a) 缺要素 1 条**、**b) 要素齐全但结论错 5 条**。

  含义：单纯提高覆盖不足以改善 correctness，还需强化推理链的算术/推导可靠性。

## 4. 截断 / 复读统计

截断 = `finish_reason=length` 的 stage/run 数；复读警告 = `repeat5>=5` 的 stage/run 数。

| 臂 | 样本数 | 截断(length) | 复读(repeat5≥5) |
|----|--------|--------------|-----------------|
| A（直接，整条） | 3 | 0 | 2 |
| B（六阶段，按 stage） | 18 stages / 3 runs | 13 | 3 |

解读：A 臂 3 条全部 `stop` 自然收尾，**零截断**；复读 repeat5 分别为 3/8/5，其中 2 条 ≥5。
B 臂 18 个 stage 中 **13 个撞 4096 token 上限被截断**（72%），**3 个 stage 复读≥5** —— 多阶段累积上下文 + 每阶段 4096 上限导致大面积截断与复读，这是 B 臂的主要退化信号。

## 5. 结论（只回答 smoke 三问）

1. **recall 是否成功**：A 臂 3 条均完整召回（`stop`，无截断），recall 成功；B 臂 3 条多阶段输出全部落盘，流程跑通，recall 成功。
2. **有无退化**：A 臂无截断退化；B 臂存在明显退化信号 —— 13/18 stage 截断 + 3 stage 复读≥5（多阶段 + 每阶段 4096 上限所致）。
3. **coverage 如何【主 claim】**：A 臂 unit 级覆盖 overall 均值 **0.900**，B 臂 **0.883**（Delta(B−A)=-0.017）。两臂 unit 级覆盖均处高位，机械 judge 层面**未见覆盖退化**。correctness 仅作时点快照：A 臂 0/3、B 臂 0/3 命中 3090×4/W4/n=2（时点特定，非稳定性 claim）。错误归因：1 条缺要素（coverage 问题）/ 5 条要素齐全但结论错（推理/算术问题）。

> **边界声明**：本报告是 smoke test，**不声称任何质量提升/下降的因果结论**。主 claim 基于 unit 级覆盖（推理链完整性），与赢家时点性解耦；correctness 仅作时点快照 + 错误归因，两臂对比仅为 smoke 层面的流程可用性观察，有效性判断留给 T8c token-matched 对照。
