# T8b Smoke Test 报告（pfb 六阶段 vs 直接求解）

> **定位**：smoke test，不是有效性实验。有效性需 T8c 的 token-matched 对照。
> 本报告只回答三个 smoke 问题：**recall 是否成功 / 有无退化 / coverage 如何**。不做质量提升声称。

## 0. 数据完整性声明（重要）

- **Arm A（直接求解）**：3 条完整自由文本，`finish_reason=stop`，正常落盘。
- **Arm B（pfb 六阶段）**：`raw_outputs_t8b.json` 中 `arm_b=[]`（空）。
  - 原因：runner `run_exp_t8b.py` 只在**全部 3 条 B 跑完后**才 `json.dump` 落盘 arm_b；
    run 3 在 stage 04 后进程被回收（日志止于 `[B-pfb-run3-04]`，无 `DONE`、无 `WROTE arm_b + finished`），
    故 3 条 B 的**阶段文本全部丢失**，只剩 `t8b_run.log` 里的元数据（finish_reason / repeat5 / token 数）。
  - 后果：**Arm B 的 coverage 分数与 correctness 无法计算**（无文本可打分）。
    下文 B 臂只报告**可恢复的截断/复读统计**（来自 log 元数据）。
  - 补救：需重跑 `python3 run_exp_t8b.py b`（建议改成每 stage 增量落盘，防再次丢数据）。

## 2. Correctness 探针（本次新增关键维度）

gold 锚点 = **3090×4 / W4 / n=2**（来源：`pfb/bench/rubric-v3/ablation/gold-tree.md` 头部声明）。
机械提取规则：取每条输出**最后 2000 字符**，正则找主卡型（窗口内最早出现的卡型）+ 数量（`N×卡型`）+ 精度（W4/W8/W16/INT4/INT8/FP8/BF16）。
判定：卡型=3090 且 精度∈{W4,INT4} 且 数量=4 → **对**；提取到推荐但与 gold 不符 → **错**；提取不到 → **无法提取**。
探针局限（如实标注）：① 只看尾部 2000 字符，条件式/多分支结尾（如决策树）可能提取不到单一主推荐；② 数量只认 `N×卡型` 紧邻写法，`4 张 3090` 这类写法会漏检；③ 精度取窗口内首个命中，若尾部先提 INT8 后提 W4 会取到 INT8。故 correctness 是**下界估计**（漏检只会低估，不会虚高）。

| 样本 | 提取到的最终推荐 (卡型/数量/精度) | 判定 |
|------|----------------------------------|------|
| A1 | A100×1 / INT8 | **错** |
| A2 | 3090×2 / INT8 | **错** |
| A3 | L40S×1 / INT8 | **错** |
| B1 | —（无文本） | **无法提取(无文本)** |
| B2 | —（无文本） | **无法提取(无文本)** |
| B3 | —（无文本） | **无法提取(无文本)** |

**correctness 汇总**：A 臂 **0/3 对**；B 臂 **0/3（全部无法提取，无文本）**。

解读（仅描述机械提取结果，不做质量评判）：
- A1 提取到 A100×1 / INT8 → 错（卡型即与 gold 3090 不符）
- A2 提取到 3090×2 / INT8 → 错（卡型命中 3090 但数量/精度与 gold 不符）
- A3 提取到 L40S×1 / INT8 → 错（卡型即与 gold 3090 不符）
- 三条均未收敛到 gold 赢家 3090×4/W4/n=2（correctness 0/3）。

## 3. 截断 / 复读统计

截断 = `finish_reason=length` 的 stage/run 数；复读警告 = `repeat5>=5` 的 stage/run 数。

| 臂 | 样本数 | 截断(length) | 复读(repeat5≥5) |
|----|--------|--------------|-----------------|
| A（直接，整条） | 3 | 0 | 2 |
| B（六阶段，按 stage） | 17 stages / 2 runs | 12 | 4 |

解读：A 臂 3 条全部 `stop` 自然收尾，**零截断**；复读 repeat5 分别为 3/8/5，其中 2 条 ≥5（A2=8、A3=5 达到阈值，A1=3 未达）。
B 臂 17 个 stage（run1/2 各 6 个走完，run3 止于 04 共 5 个）中 **12 个撞 4096 token 上限被截断**（71%），**4 个 stage 复读≥5** —— 多阶段累积上下文 + 每阶段 4096 上限导致大面积截断与复读，这是 B 臂的主要退化信号（但文本已丢失，无法量化对 coverage 的影响）。

## 4. 结论（只回答 smoke 三问）

1. **recall 是否成功**：A 臂 3 条均完整召回（`stop`，无截断），recall 成功。B 臂流程能跑通 6 阶段（run1/run2 各走完 6 stage），但 runner 落盘缺陷导致 B 臂文本丢失，**B 臂 recall 无法验证**（需重跑确认）。
2. **有无退化**：A 臂无截断退化；B 臂存在明显退化信号 —— 12/17 stage 截断 + 4 stage 复读≥5（多阶段 + 每阶段 4096 上限所致）。correctness 上 A 臂 0/3 命中 gold，说明直接求解也未收敛到 3090×4/W4/n=2。
3. **coverage 如何**：A 臂 overall 均值 **0.900**（S1=0.944, S2=0.867, S3=0.889），处于高位（S1/S2 接近饱和）。B 臂 coverage 无法计算（无文本）。

> **边界声明**：本报告是 smoke test，**不声称任何质量提升/下降的因果结论**。coverage 高 ≠ 答案对（correctness 探针正是为此新增）；B 臂结论受数据丢失限制，重跑前不作定论。
