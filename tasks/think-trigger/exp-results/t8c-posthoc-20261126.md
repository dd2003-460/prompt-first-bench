margin 33.7%。breakeven V100 价格 = $2032.9（oracle 二分实跑）。

## 变更 2: token 预算 24576 → 73728（B' 臂截断修复）

**触发**: smoke n=3 下 B' 臂 3/3 截断。根因诊断（smoke sidecar 实测）:
B' 六阶段真实 token 需求 ≈ 69227 > 总预算 24576（截断态已耗 94% 总预算，
碎片化 4096/阶段 cap 是表象，总预算不足是本质）。

**修复**: MAX_A 24576→73728 (=6×12288, 覆盖 69K 需求下限), MAX_B 4096→12288。
A' 同步 73728 保 matched 上限语义（A' 实际用量 ~13K，上限不改变其行为）。

**对照语义澄清**: 原「同预算天花板 24576」改为「同预算上限 73728、各自自然消耗」。
理由: 预算不足以完成流程时，测到的是「预算饥饿」而非「流程价值」——
B' 的流程开销正是被测对象之一，预算必须覆盖其真实需求下限，
否则 H1 的否定证据被预算伪影污染（无法区分「流程无用」vs「流程没跑完」）。
A' 臂不受影响（其需求 ~13K ≪ 73728，行为与 24576 上限下相同）。

**影响**: smoke 数据（旧预算下）作废，n=3 重跑；n=9 成本估算更新
（A' ~117K + B' ~621K ≈ 738K tokens 两臂）。

## 变更 3: 04.5 复核阶段单独上限 12288 → 16384（MAX_B_REVIEW，2026-11-27）

**触发**：smoke 重跑 B 臂 run3-04.5 finish_reason=length（1/3 截断）。
**归因（usage 权威口径）**：raw_outputs_t8c.json 的 usage 字段——
run0-04.5 reasoning_tokens=2740(stop) / run1=1192(stop) / run3=**11338**(length)。
真因 = 27b reasoning token 方差极大（1192↔11338，9.5×），run3 思考 token 吃掉
12288 预算的 92%，正文（content ~950 tok）没写完被截断。**非复读**（该阶段
unique5=0.975 健康）、**非正文过长**（content 反而比 run0/1 短）。
注：commit 5c718d398 message 里"reasoning 14866 tok"系 reasoning 字段字符数
（14866 chars），非 token 数；token 权威值 = usage.reasoning_tokens = 11338。
**修复**：`run_exp_t8c.py` 加 MAX_B_REVIEW=16384，仅 04.5 生效（其余 5 阶段仍
12288）。服务端 probe 证 max_tokens=32768 可接受，16384 覆盖实测 11338 留 ~45% 余量。
**与 token-matched 的偏离声明**：名义上限从 6×12288=73728 变为 5×12288+16384=77824
（B' 臂名义上限 +4096）。偏离依据：B 臂实测总消耗 29-41K ≪ 名义上限，matched 语义
（两臂同预算上限各自自然消耗）未被实质破坏；A' 臂 MAX_A=73728 不变。
**配套（HarnessRetry，commit 5eb66906f）**：call() 加 finish_reason==length 截断重试
（同 prompt 同 cap 重采样 ≤2 次，3 次仍 length → 返回 last + length_retries 字段，
上层按 §1 判 indeterminate）。双保险：CapFix 降低 04.5 截断概率，HarnessRetry 兜底
残余截断。mock 单测 3 场景全过（test_call_retry.py）。
**验证**：T8c-CapFix-Verify（重跑 B 臂 1 样本 04.5 确认 finish=stop）就绪待跑。
