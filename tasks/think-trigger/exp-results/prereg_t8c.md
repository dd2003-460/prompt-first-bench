# T8c 修正设计（D 2026-11-25 质疑"真的设计好了吗"后）

# origin: ai · 取代 T8/T8b 的"有效性"定位；T8b 降级为 smoke test

## 诊断（T8a 数据坐实）
- Δ(B-A)=+0.015, SE=0.049, 噪声/信号=3.3x, t=0.30 → 检测需 n≈262/组（27b 不可行）
- 臂内极差 0.089–0.144 > 臂间差 0.015 → 27b 自身方差淹没信号
- 三个根因：①无 ground truth（GPU 选卡是判断题，judge 只量覆盖≠对错）②token 预算混淆（B 天然多花 token，无匹配对照）③单任务+高方差

## 重新定位
T8b = **smoke test**，只回答三件事（都可机械判）：
1. recall：B 是否呈现六阶段结构（二值）
2. 退化：B 输出是否完整/非截断/非复读（机械）
3. 覆盖度：B 覆盖多少决策维度（机械 judge，标注"覆盖≠正确"）
**不 claim 质量提升。**

## 有效性 claim 的修正设计（T8c，若要做）
1. **token 匹配对照臂 A'**：A'_direct 给与 B 相同的总 token 预算（~24576）。
   → B vs A' = 纯 scaffold 效应；A' vs A = token 效应。隔离混淆。
2. **power 前置**：先小样本估 Δ 和 SD，算 n。若 n=5 测不出 → 不烧 27b，
   如实报告"该效应在 27b 上低于可测下限"，不硬跑。
3. **多任务（≥3 类）**才能谈推广，单任务只作 pilot。
4. **若要真测"质量/正确性"**：换 ground-truth 载体（数值/代码题，正确率机械可判），
   那是另一个实验，不是 T8。GPU 选卡题保留作覆盖度 smoke test。

## 决定
- T8b 让它跑完（沉没成本 + smoke test 有用）→ 报 recall + 退化 + 覆盖度
- 有效性 claim 等 T8c（token 匹配 + power 前置），不急着烧 27b
- judge_gpu_mech.py 保留，定位=覆盖度 smoke test，非质量 judge
