## 1. 缺口的本质（本轮核验结论）

缺的不是一个数，是**两个函数形式**：
- `l2_hit → MFU`（N-3.1.3.3 路径）：命中率↑ → 权重/激活复用↑ → 有效计算效率↑
- `l2_hit → η_bw`（N-3.2.4.2 路径）：命中率↑ → HBM 流量↓ → 有效带宽需求↓

L5-blackbox.md B2/B3 明确：两者都**无闭式**（"理论峰值和实测差 2–3 倍，这个差距没有闭式"），属黑箱 S-b。
所以严格标定 = 实测，不是推导。纯本地（无 GPU）只能做框架设计 + 锚点落盘。

## 3. 估计框架（F-A 法，L4 已验证有效）

l2_hit 总弹性 = 两条路径贡献之和（gold-tree §2：同号，真实弹性叠加）：

```
ε(c_pass, l2_hit) = 0.401 × ε(MFU, l2_hit) + 0.599 × ε(η_bw, l2_hit)
                    └── 已知(实测) ──┘   └────── 待标定（本实验目标）──────┘
```

标定目标 = 括号内两项。标出后：
- SHARED 节点 share 可回填：share_MFU路径 ≈ 0.401·ε(MFU,l2_hit) / ε_total，η_bw 路径同理（守恒和=1）
- §2 正交性判断的 conf 可从 0.8 上调（当前 0.8 的扣减项之一就是"敏感度分配读不出"）

## 4. 最便宜探针（执行条件：1 张 GPU + ~2h）

扰动命中率、分别测两条路径的响应斜率：
1. 固定负载，构造两组 L2 局部性不同的工况（如 KV 复用率高低两组 batch 策略），各跑 B2/B3 SOP
2. 斜率 d(MFU)/d(hit) 与 d(η_bw)/d(hit) 即两项待标定弹性的近似（区间 [0.35,0.55]/[0.60,0.85] 内线性化，误差标 [待核验]）
3. 交叉验证：两路径斜率同号（gold-tree §2 先验），异号 = 实验伪影，重查

**不做的事**：不动 vLLM 8787（推理服务，非 benchmark 环境）；不在 27b 上做（它是被测对象不是测量仪器）。
