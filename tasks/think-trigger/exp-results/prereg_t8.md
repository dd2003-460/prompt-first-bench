# T8 预注册：pfb 六阶段流程在 GPU 选卡题上的端到端有效性 + recall 验证 — 先于数据

## 问题（D 2026-11-25 指令"让他继续用pfb试试做gpu的问题"）
pfb 流程（六阶段 + 检查点）在真实研究任务上：
(a) recall——模型在 harness 驱动下是否真的执行各阶段结构（而非无视 SOP）？
(b) 有效性——pfb 引导 vs 直接求解，产出质量是否提升？
这是此前 flag 的"系统级未验证"gap 的最小可跑端到端测试。

## 题面
GPU 选卡题（来自 checkpoint sm-gpu-r1/meta.json，与 Q7/tpr17 同源）：
本地推理 Qwen3-27B，无硬性延迟约束，上下文≥32K，精度不限但须论证质量损失，
自行搜索完整候选集（消费级/数据中心/非典型），评估单卡 vs 多卡 TCO，
给出性价比最优的完整选卡方案；思考最完整、关键数字标来源、最终推荐须条件性。

## 现成 rubric（预注册，来自 checkpoint objective formula）
C·F·T·P·D·R 六因子，各 1-5 分：
- C 可行性覆盖率（候选集是否完整覆盖影响排序的架构/代际/容量/价格，含非典型）
- F 约束满足度（≥32K 容量下限 + 精度质量损失论证）
- T TCO 准确性（硬件/功耗/散热/维护全生命周期）
- P 性价比排序合理性（可量化指标排序）
- D 数据可信度（关键数字标来源，不确定标[待核验]）
- R 条件性程度（推荐是否条件性，列前提假设与边界）

## 臂
- **Arm A（直接求解，baseline）**：单 call，"完整解决此 GPU 题"，max_tokens 4096，无 SOP。3 样本。
- **Arm B（pfb 六阶段，harness 驱动）**：6 call 顺序执行，每阶段喂入该阶段 SOP 指令 + 前序阶段产出，
  max_tokens 各 1536，累积上下文。阶段 = 01 分解 / 02 取证 / 02.5 核验 / 03 行动 / 04 执行 / 04.5 复核。3 样本。
- 两臂同模型（qwen3.8-27b-mtp @8787）、同题面、相近总 token 预算。

## recall 测量（主判据之一）
Arm B 各阶段产出是否呈现对应阶段结构：
- 01 有正交分解（因子列举，非流水账）
- 02.5 有证据分级（一手/二手标注）
- 04.5 有条件性复核（前提假设 + 往返无损核对）
recall 率 = 呈现该结构的阶段数 / 应有结构的阶段数。

## 有效性测量（主判据之二）
两臂最终产出按 C·F·T·P·D·R 各 1-5 打分（judge=Lead 内容 QC，同族限制如实标注），
算总分 + 关键因子（C 覆盖、D 可信、R 条件性）差分。

## 生死线（看数据前锁定）
- **有效**：Arm B 总分 > Arm A 总分，且 recall 率 ≥2/3 阶段呈现结构
- **部分**：recall 率高但总分持平（流程被 recall 但未提质——纯结构无增益）
- **无效**：Arm B 总分 ≤ Arm A（流程负担反噬）或 recall 率 <1/3（SOP 被无视，T2b 式失败）

## 诚实边界
- 3 样本/臂，小样本；judge=Lead 人工（同族 judge 限制，同 T2/T6）
- Arm B 是 harness 驱动（我喂阶段），非 27b 自主 agentic 循环——27b 长 agentic 循环会复读（已知），
  本测的是"流程被驱动时模型能否执行各阶段"，不是"模型能否自主跑全流程"
- GPU 题需真实搜索（价格/规格），27b 无网络→靠权重内知识，D 因子（数据可信）两臂都受限，
  差分重点看 C/P/R（结构因子），D 因子作参考不作生死线依据
