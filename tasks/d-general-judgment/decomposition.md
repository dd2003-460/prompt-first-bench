# D 式 General 判断：让 LLM 像 D 一样质疑方向/前人/更快/性价比
# origin: human (D 2026-11-28 指令) + ai (分解)

## Goal
让 LLM（27b 或其他）在做 research 时，自动做 D 式 general 判断：
1. **质疑方向**：这个问题问对了吗？方向对不对？
2. **查前人**：有没有人已经解决了？有没有现成方案/文献/基准？
3. **找更快**：有没有更低成本的替代路径？
4. **性价比**：值不值得做？产投比高不高？

D 的原话："看到一个东西就下意识质疑好不好走，能不能省事"——这是先验的怀疑态度，不是被动的缺口检测。

## 与 M 线的关系
M 线（think-trigger）做的是"思考机制落地"（分解质量/strategic 层质疑）。
本 goal 更 general：不是"让 LLM 做实验设计检查"（执行层），而是"让 LLM 在战略层做判断"。
M 线是特例（strategic 层质疑 = 方向质疑的一个子集）。

## 已知约束（来自 M 线实验）
- 习惯（prompt 注入）能给"层次敏感度"但不能给"行动"
- 信息（检索通道）能给"查的能力"
- 触发（缺口信号）能给"什么时候查"
- 但 D 的 general 判断更 general：不是"发现缺口→查"，而是"看到东西→下意识质疑"
- 纯 prompt 注入买不到"自发去查前人"（trigger-verdict-20261128.md）
- 触发器 = harness 机制（检测防御性语言→注入反思），非 prompt 内容

### S2: 机制（怎么实现）

  a. prompt 注入（习惯层）+ 检索通道（信息层）+ 触发器（harness 层）
  b. agent 循环（每轮强制过 4 维检查）
  c. 专用 judge 模型（训练/微调）
  d. 混合：prompt + harness + 检索

- 缺口：[待设计] 4 维判断的 ground truth 怎么标（D 标？LLM-judge 标？）

### S4: 实现（具体怎么做）
