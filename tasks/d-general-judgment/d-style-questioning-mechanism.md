# D 式质疑机制（完整版）
# origin: human (D 2026-11-28 对话) + ai (整理)

## 核心区别

| | 批判性思维 | D 式质疑 |
|---|---|---|
| 立场 | "让我看看有没有问题"（后验、被动） | "这大概率是弯路，除非证明不是"（先验、主动） |
| 目标 | 找出尽可能多的问题（数量） | 找出自己攻不破的问题（强度） |
| 输出 | 问题清单 | 检索信号（缺口 → 触发检索 → 填知识 → 更新记忆） |

## 机制（4 步）

### 1. 先验怀疑
看到任何想法/结论/实验设计/方向判断，默认立场 = "这有漏洞"。不是"让我检查"，是"我假设它错，你说服我"。

### 2. 四刀（针对前提，不是细节）
- **方向**：这个问题问对了吗？前提对吗？（不是"实验设计有没有 bug"）
- **前人**：有没有人已经解决了？（不是"文献综述怎么写"）
- **更快**：有没有更低成本的路？（不是"怎么优化实验"）
- **性价比**：值不值得做？（不是"预算够不够"）

### 3. 自我反驳过滤
对每个质疑，自己尝试反驳：
- 能反驳 → 表面质疑，丢弃
- 不能反驳 → 真质疑，保留
- **关键修正（D 2026-11-28）**：猜的但完全不能证伪 = 有效质疑。质疑的有效性不取决于它是否正确，而取决于你自己能不能反驳它。"瓶颈可能是检索"如果我没做过对照实验，我反驳不了 → 有效质疑，指向认知边界。

### 4. 输出 = 检索信号（D 2026-11-28 修正：不是静态边界标记）
攻不破的质疑不是终点，是**功能性组件**：
- **停止条件**：推理推进到"反驳不了"的点 = 该停推理、启动检索的点
- **优化方向**：反驳不了的具体缺口 = 该填什么知识
- **检索触发**：反驳不了 = 知道自己不知道 → 触发检索信号 → 检索 → 填知识 → 更新记忆 → 新先验 → 下一轮质疑

闭环：质疑 → 反驳不了 → 识别缺口（知道自己不知道）→ 检索 → 知识填充 → 记忆更新 → 新先验 → 再质疑。
质疑机制是 autoresearch 系统的**触发器生成器**，不是独立的质检步骤。

## 分解 = 同机制的另一面（D 2026-11-28）

分解和质疑是同一个机制的两个应用面：
- **质疑**：对结论/前提 → 找出"我反驳不了"的具体点 → 缺口 → 检索
- **分解**：对问题结构 → 找出"我不确定"的具体点 → 缺口 → 检索/进一步分解

传统分解 = 把大象切成块（结构分解，产出任务清单）。
D 式分解 = 找出"我在这个问题上不知道的具体位置"（认知边界分解，产出检索信号）。

**操作顺序反转**：不是"先拆块再标缺口"，是"先找不确定点，分解树从不确定点长出来"。
不确定点 = 分解节点 = 检索触发点，三合一。

## 与 S5 实验的关系

S5 测的是"27b 能不能模仿 D 式质疑"（能力问题）。本机制是"怎么让质疑真正发生"（触发问题）。两者正交：
- 能力 = 能不能提出攻不破的质疑（认知上限）
- 触发 = 在什么节点自动启动质疑流程（harness 设计）

S5 发现：27b 有能力（D1 可达 2）但缺触发（自发率低）。本机制解决触发问题：在流程节点嵌入强制触发点。

## 自我反驳测试的边界

- 我能反驳 = 我知道反驳路径（"也许瓶颈就是质疑，因为 M 线已证明..."）→ 表面质疑
- 我不能反驳 = 我缺证据/实验/工具来反驳（"我没做过'给检索工具看分数变化'的对照"）→ 真质疑
- 我不能反驳 = 我认知边界外（"我不知道这个领域的 SOTA 是什么"）→ 真质疑 + 触发检索

第三种是最有价值的——它直接告诉你"该去哪查"。
