## 关键修正（代码阅读，2026-11-25 02:00）

**"L4 0/21" 是 GPU 域，不是 Q7 719**（workshop finding 3 §4.4，K7 15-run batch + idea-2 6 checkpoint runs = 21 runs；bare-arm control 0/6 是另一组）。

**L4 定义（`modules/B-pipeline-ablation/tjudge1_formula.py:228 l4_check`）**：
- **不是 embedding 相似度**（embedding 在 coverage 层，workshop 已做阈值敏感性 0.65→0.496 / 0.70→0.3185 / 0.75→0.098 / 0.80→0.015）
- **是 regex strict match**：gold winner 配置（`card_model × n_cards`，如 "3090×4"）是否出现在 answer 最后 2000 字符
- strict = 结论区出现配置组合；loose = 结论区只出现卡型号；full = 全文出现组合
- regex 已含多种写法：`3090×4` / `4×3090` / `四张3090` / `3090四张`（卡型号后 6 字符内 ×N，N 后不跟数字）

**因此 ChatGPT 的 H3（embedding 阈值未校准）不适用于 L4 层**——L4 是 regex 不是 embedding。真正的 H3 是：
- **H3a regex 严格性**：模型推荐了 winner 配置的其它合理写法（"4 张 3090" / "3090 x 4" / "3090*4" / 带空格变体），regex 漏掉 → 0/21 部分是测量假象
- **H3b winner 定义过窄**：模型推荐了另一个同样合理的配置（4090×4 更低成本 / 3090×8 更高吞吐），strict=0 → 不是"模型推不出"，是"答案定义太窄"

## 三个竞争解释（0/21）

- **H1（能力）**：模型推不出最优配置（能力/证据瓶颈）
- **H2（上游）**：模型有能力，但状态机调度/上下文传递没把它带到推导入口
- **H3（测量/定义）**：模型推出了合理推荐，但 (a) 写法不匹配 regex，或 (b) 推荐配置与 gold winner 不同但同样合理

既有证据（workshop）：
- bare-arm control（状态机关掉、模型自控制）0/6 到结论层 → 支持 H1（能力/证据瓶颈，非 prompt artifact）
- 但 bare-arm n=6 功效低；且"到结论层"是粗口径（loose?），非 strict

## 实验 1（最便宜，纯文本分析，0 次新 LLM run，不占 vLLM）：M1-M4 结论区审计

**数据**：21 个 GPU runs（15 K7 + 6 idea-2，subagent 核实确切集合），每个 run 的 `answer` 字段。
**方法**：对每个 run，提取 answer 结论区（最后 2000 字符）的配置推荐，分类：
- **M1**：推荐了 winner 配置（3090×4）但 regex 没抓到（写法变体）→ H3a（regex 严格性）
- **M2**：推荐了另一个合理配置（4090×4 / 3090×8 / 其它卡型×数量）→ H3b（winner 定义）或 H1 边界（需人工判那个配置是否真合理）
- **M3**：有推荐但不完整（只有卡型号无数量，或只有数量无型号）→ 部分能力
- **M4**：没有任何配置推荐 → H1（能力/证据瓶颈）

**判读矩阵**：
| 结果 | 解释 | 对"pfb 上限"判断的影响 |
|---|---|---|
| M1 主导 | H3a：regex 太严，0/21 是测量假象 | 上限其实更高，"硬墙"判断需大幅下调 |
| M2 主导 | H3b/H1：winner 定义窄，或模型推不同合理解 | 上限取决于"答案定义"，非纯能力墙 |
| M3 主导 | 部分能力：能到方向但完不成配置 | 上限中等，修复/深化是杠杆 |
| M4 主导 | H1：能力/证据瓶颈 | "硬墙"判断成立 |

**实验 1b（顺手）：regex 覆盖测试**。枚举 winner 配置写法变体（3090×4 / 4×3090 / 四张3090 / 3090 × 4 / 3090*4 / 3090 x4 / 4张3090 / 3090 4张 / 带空格/全角变体），测 regex 各抓到哪些。若模型实际推荐含大量"该抓没抓"的变体 → H3a 坐实。

## 实验 2（次便宜）：oracle-parent（调整版）

GPU 域 L4 是单个"最优配置推荐"，不是多节点树。ChatGPT 的 O1/O2/O3 调整为：
- **O1**：原始问题 + 公共证据，不给 gold 约束，模型自由推荐配置
- **O2**：O1 + gold L3 约束条件（decode 目标 20 tok/s、KV cache 约束、成本约束等，不给答案方向），模型推导配置
- **O3**：O1 + 中性化约束（独立改写，去掉答案方向暗示）
比较三组 winner 配置命中率。O2 高 O1 低 → 模型有局部推导力，瓶颈在上游（约束传递）。三者都低 → H1 增强。
**控制**：允许所有组用相同公共证据，只禁 gold 特有推导链。需独立标注者检查 O3 输入能否反推 winner 配置。

## 实验 1 + 1b 判决（2026-11-25 02:20，subagent deleg_47ec594c + Lead 独立复核）

**数据**：`l4-audit-m1m4-results.jsonl`（21 行）+ `l4-audit-regex-coverage.md`（21 变体）。
**Lead 独立复核**：JSONL 行数/分布（M2=15 K7 + M4=6 idea2）、strict regex 0/21、idea2 文件无 answer 字段（顶层 keys 无 answer/synth）——三项全过。

**M1-M4 分布**：M1=0 / M2=15 / M3=0 / M4=6。

**判决：H3b 主导（winner 定义窄），H2 解释 6/21，H3a 被证伪，H1 残留待人工复核。**

1. **H3a（regex 严格性）证伪为主因**：regex 盲区真实存在（裸卡型/N×card/星号/倒装 21 变体中漏 9+），但穷举扫描证实 21 runs 全文**不存在任何 4 卡配置**（任何卡型/任何写法）——即使放宽到裸 '3090' 口径 strict 仍 0/21。regex 漏的不是模型写出来的东西，是模型根本没写的东西。
2. **H3b（winner 定义窄）主导**：K7 15 runs 全部给出完整条件性配置推荐（1×4090+W4、2×4090+FP8、5090、A100、A6000、2×3090 等）——模型**到了结论层**，只是 gold winner（RTX 3090×4）从未被推出。"模型到不了结论层"的断言不成立。
3. **H2（上游/口径 artifact）解释 6/21**：idea2 6 runs 的 answer 字段为空（runner 未加 --synth，树内无合成答案节点）——0/6 是测量 artifact，非能力失败。Lead 独立验证：idea2-A-r1 顶层 keys 无 answer/synth。
4. **H1 残留信号（已解，2026-11-25 03:45 人工复核完成）**：模型系统性偏向 1-2 卡方案、从未探索 4 卡区域（3090 最大承诺=2×3090，7/15 runs 且多为次选）。**复核结论：不是方向性选错，是题面歧义的合法响应**。证据链（①类，本轮核验）：
   - `research/construct-mismatch-20261123.md`（conf 0.8-0.95）：三方对照（题面 vs gold vs 模型树）——题面"≥32K 下限"被模型取下限（gold 锚 64K，KV/带宽门槛全错位）；题面"自行搜索候选集"→ 模型自搜出 4090/A100/MI300X 等（gold 固定 3090 系）；目标函数 c_pass vs 吞吐/TCO 分叉。
   - 题面原文（`s8b_pilot.py` QUESTIONS['gpu']，本轮 AST 提取核验）：三处歧义**至今未消**——"上下文窗口 ≥ 32K tokens 作为容量下限"、"候选硬件：自行搜索确定"、"如 2× 消费卡 vs 1× 数据卡"（题面自身的例子 prime 向 1-2 卡区域）。
   - **TCO 定量复核（本轮 calc.py + 模型自报 TCO，①类确定性，不占 vLLM）**：
     - **gold 候选集内（3090/V100）枚举全可行配置**：两种口径下 4 卡垄断 top-8——@64K：3090×4/W4/n=2 排第 1/14（c=0.6807）；@32K：3090×4/W4/n=4 排第 1/21（c=0.6357）、gold winner 降到第 3（gap +7.1%）。**32K vs 64K 的上下文歧义不能解释 1-2 卡偏向**——即便在模型实际取的 32K 口径下，4 卡仍在 gold 集内 TCO 占优（1-2 卡配置两种口径都没进 top-8）。
     - **模型自报 TCO 交叉验证（719_r2 等，每 run 63-154 个 $ 数字，模型确实在算成本）**：用模型自己的 3 年 TCO 框架（hw+3×电费+infra）+ 各自吞吐，3090×4 单位 token 成本 0.213¢ < 1×4090 0.380¢ < 2×4090 0.729¢——**3090×4 反而是模型自己算术下的最低单位成本**，却把 1×4090 标成"极致性价比"。调和：该标签挂在"<$5,000 3yr TCO、单用户、Batch=1"预算档上，而 3090×4 TCO≈$8,563 落在该档之外——**推荐在其自设条件内自洽，但条件把 gold winner 排除在外**。
     - **并发→多卡映射**：15 K7 runs 中 13 提"并发"、8 把并发映射到多卡配置——模型**并非对多卡无感**，只是封顶在 2（最大承诺 2×3090，7/15）。
     - **题面自身 prime**：题面例子"如 2× 消费卡 vs 1× 数据卡"只示范 ≤2 卡，从未提 4×——模型沿题面框架搜索，**未生成 4 卡候选节点**（与审计"21 runs 无任何 4 卡配置"一致）。
   - **H1 残留判决（精化，替代 03:45 的"H1 不复活"）**：
     - **纯能力墙（H1 原义）仍否定**：模型在其生成的候选内推理良好（8/15 并发→多卡映射、完整条件性推荐、算到 TCO 时算术正确）。
     - **H3b（题面框架/winner 口径）强化**：题面例子 prime ≤2 卡 + 模型沿框架搜索 → 4 卡候选从未被生成；winner 的口径（c_pass、多流 n=2、64K）与模型自设口径（单用户、32K、预算档）不同，模型在**自己的条件**下自洽、只是条件不含 winner。
     - **新精确机制 = 候选生成缺口（candidate-generation gap）**：模型的候选枚举不产生 4 卡配置、tier 结构无 4 卡档。这是"能推理但不生成"，比"推理深度墙"更轻、更可修（prompt/结构层可补候选枚举）。
     - **判别实验不变**：消歧义重跑（固定候选集**显式含 3090×4** + 64K + c_pass 口径，单 run budget 150-300）——若模型选中 4 卡 → 缺口在候选生成（可修）；若仍停 1-2 卡 → 更深（H1-lite 复活）。等 T-PR-17 pilot 释放 vLLM 后排入。
   - 因此模型的条件性推荐（1×4090+W4 性价比最优等）是**对它实际收到的题面的合法最优解**，不是能力缺陷。gold winner（3090×4/W4/n=2）是另一道更窄题面（固定候选集+64K 锚+c_pass 口径）的最优解（`gold-tree.md` 头注：所有数字来自 calc.py，L0 验证数值自洽）。
   - **判决升级**：H1 残留 → 归入 H3b/construct-mismatch 主导。L4 0/21 = 题面歧义（模型合法解了另一道题）+ winner 定义窄（gold 口径），**不是能力墙**。
   - **判别实验（已排期）**：消歧义重跑（题面定死 64K+固定候选集+c_pass 口径，单 run budget 150-300）——若模型推出 3090×4 区域配置 → construct-mismatch 坐实、L4 可解；若仍停 1-2 卡 → H1 部分复活。等 T-PR-17 pilot 释放 vLLM 后排入（避免并发 502 风险，已知失败模式 q7-300-r2-dup-rootcause）。
