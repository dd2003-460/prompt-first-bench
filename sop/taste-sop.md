# Taste SOP（审美判据 · 执行版）

> origin: ai · 2026-11-13 · 从 T53-taste-sop-decomp.md S1-S4 导出
> 用途：任何 prompt/机制改动前走五检查；任何 taste 判断落盘时带判据+数字+conf
> 高视角约束：每个判据必须锚定到信息论/统计量，否则是装饰

## 核心定义

taste = 在多个"都对"的选项中选"更好"的那个的判断力。
好方案 = 让下一步残差最小的方案（S2 核心引擎）。

## 五个检查动作

### 1. 删句测试（信息密度 · MI 视角）
- **触发**：写/改 prompt 后，觉得某句"可能没用"
- **操作**：删掉该句跑一次，对比输出分布。输出不变 → I(prompt;output)≈0 → 废话，删
- **判据**：删句前后关键指标（verified 率/coverage/degraded 率）变化 < 噪声水平 → 该句 I≈0
- **不能做的事**：MI 是关联不是因果，句子间有交互项——不能逐句独立测完就下结论

### 2. 残差定位（调研入口 · 预测误差视角）
- **触发**：跑完一轮实验/bench，拿到实测数据
- **操作**：r = observed - predicted。|r| 小的方向 = 已懂 = 不花预算；|r| 大的方向 = 不懂 = 调研入口
- **判据**：连续 2 轮 |r| < 阈值 且弱项子项集合不变 → 收敛，停迭代
- **对接**：degraded rate 曲线 = 时间序列残差；grokking 探针 = 残差的延迟结构（先正后负）
- **依赖**：需要预测基准（先验函数 Route B），当前只有数学语言没有实现 → 用上一轮结果做朴素预测

### 3. 杠杆测试（Goodhart 防御）
- **触发**：准备改一个机制/参数，预期能提升某指标
- **操作**：问"这个改动对目标指标的杠杆是多少？"如果怎么改指标都不变 → 无杠杆 → 装饰
- **判据**：改动前后目标指标 Δ < 2×测量噪声 → 无杠杆，不做
- **反例**：v17 Goodhart 案——优化了代理指标但真实能力没动

### 4. 压缩律比对（MDL · 功能等价选更短）
- **触发**：两个方案都能跑通/都达标
- **操作**：选更短的那个（token 数/代码行数/概念数量）。同等解释力 → 选简单
- **判据**：方案 A 和 B 在验收指标上 Δ < 噪声，但 A 比 B 少 N 个概念/token → 选 A
- **案例**：D34 query 瘦身——题面从长描述压到核心约束，分解质量没降反而树更干净

### 5. Goodhart 自查（指标防御）
- **触发**：发现某指标持续改善但"感觉不对"
- **操作**：检查是否在优化代理而非目标。问"如果只看这个数字，会不会做出错误决策？"
- **判据**：指标改善 + 下游真实任务表现不改善 → Goodhart 信号 → 换指标或加约束
- **案例**：T53b hook 臂 Δ+0.025 ns——分数微升但机制没变，判定为噪声不是改进

## 三个 taste 锚点案例

| 案例 | 判断 | 用了哪个判据 | 为什么对/错 |
|------|------|-------------|-----------|
| v17 Goodhart 翻车 | 优化代理指标导致真实能力退化 | #5 Goodhart 自查 | 只看了分数没看下游任务 |
| D34 query 瘦身 | 长题面压到核心约束 | #4 压缩律 | 功能等价（分解质量没降）+ 更短 |
| T53b hook 臂 Δ+0.025 | 判定为噪声不是改进 | #3 杠杆测试 | Δ < 2×噪声，机制没变 |

## 元规则

**任何 taste 判断落盘时必须写成 "判据 + 数字 + conf"，禁止纯形容词。**
- ✅ "quotient 23.7% vs 目标 ≤20%，略超线，先拿完整数据再修 (conf 0.8)"
- ❌ "quotient 有点高了，可能需要调一下"

## 边界声明（诚实 gap）

信息论工具全是**评判器**不是**生成器**——它们能告诉你什么是好的（压缩比高、残差小、MI 大），但不能告诉你下一个好方案长什么样。taste 的生成侧（直觉/类比/跨域迁移）目前无理论覆盖。这不是回避，是当前边界。
