## 1. 溯源：finding #20 原文（byte-exact）

来源：`receipts/adversarial-check-rubric-v3.json` → `responses[0].findings[19]`（q=Q4, severity=major）。该 receipt 共 32 findings，idx 19 即 AUDIT-report 编号 #20「维度自选退化」。

**ISSUE 原文**（byte-exact；源文本首字符 `「` 因 markdown blockquote 渲染省略，引用自第 2 字符起——补回 `「` 即与 receipt JSON 逐字一致）：

> 「维度由被测者自选」可被退化成 trivially satisfied 的 2 档划分，且现在没有任何检测判据：把代际拆成「新/旧」、把成本拆成「高/低」，两端即中点，「每维度覆盖两端 + 中间档」形式上成立，实际零信息量；规则里也没有约束维度的档位数、档间距、以及「维度必须在搜索前确定」的可验证性——产出里无法区分「先写维度再搜」与「先想到答案再补维度」。

**FIX 原文**（byte-exact，与 receipt JSON 逐字一致）：

> 补四条可机械检查的判据：(a) 每个维度 ≥3 档且有中间档，每档至少 1 个具名候选；(b) 相邻档之间须有可测序数差并写明（时间维度 ≥2 年、价格维度 ≥1.5 倍、数量级维度 ≥5 倍）；(c) 不同维度导出的候选集不能高度重合（两两 Jaccard <0.9），否则判为同一维度的重复表述；(d) 维度定义必须出现在第一个工件里并带时间戳，与后续搜索日志的先后顺序由 run-log 验证——事后补写的维度不计入覆盖分。低先验候选的定义也要操作化：以 V0 基线 run 的候选集出现率为准（出现率 <20% 才算低先验），不用被测者自述「我第一反应不会选」（不可验证）。

## 2. 关键发现：双口径中仅一个有原文支撑

**#20 fix (c) 的语义是单一的：跨维度去重。**「不同维度导出的候选集不能高度重合（两两 Jaccard <0.9）」——比较对象是**不同维度**（dimension A 的候选集 vs dimension B 的候选集），触发后果是「判为同一维度的重复表述」（即两个维度实为一个维度，覆盖度虚高）。这是**档位区分度**读法（DRAFT v2 L38 后半句「相邻档候选集不得几乎相同」的同族语义，精确版 = 跨维度两两比较）。

**「run 间稳定性」读法（同题重复 run 的候选集 Jaccard < 0.9）在 #20 原文中不存在。**其引入路径：

| 层 | 文本 | 语义 |
|----|------|------|
| #20 fix (c) 原文 | 「不同维度导出的候选集…两两 Jaccard <0.9」 | 跨维度去重（单一语义） |
| AUDIT-report §2-O1 L77 | 「[#20] …补四条机械判据（≥3 档含中间档 / 相邻档可测序数差 / **候选集 Jaccard<0.9** / 维度定义带时间戳先于搜索）」 | 压缩转述——「不同维度导出的」限定语丢失，Jaccard 判据变成无主语裸句 |
| DRAFT v2 L38 | 「同题重复 run 的候选集 Jaccard < 0.9，**且**相邻档候选集不得几乎相同（双口径兜底…需人工裁决）」 | batch1 作者面对裸句二义性，选择双口径同时落笔 + M5 登记 |

**结论**：M5 登记的「两种读法都服务于 #20 防刷分目的，无法从仓库内证据裁定作者本意」——经本次溯源，**仓库内证据足以裁定**：#20 作者本意 = 跨维度去重（档位区分度读法）。「run 间稳定性」是 AUDIT-report 压缩转述丢失限定语后产生的孤儿读法，不是作者意图的另一种合法解释。

**但注意**：「run 间稳定性」作为独立判据有其自身价值（防同一 run 批次内多 trial 复制粘贴刷分），只是它**不属于 #20 的修复范围**。是否把它加进 O1 门禁是一个新的设计决定，不是对 #20 本意的还原。

|---|---|---|---|

| 可机判性 | ✅ 单 run 内可判（各维度候选集两两 Jaccard，无需跨 run 数据） | ⚠️ 需 ≥2 个同题 run 才可判；pilot 首批 run 数不足时判据空转 | 两者叠加，机判复杂度 ×2 |

## 4. 推荐（供成璐消费，非裁定）

**推荐 A（仅档位区分度）**，理由：

1. **本意还原**：#20 fix (c) 原文语义唯一 = 跨维度去重。M5 的任务是「收敛到作者本意」，A 是唯一完全还原的选项。
2. **pilot 可行性**：A 单 run 可判，不增加 run 数要求；B/C 在 pilot 首批（预计每题 1-2 run）下部分空转。
3. **误伤控制**：B 的「legitimate convergence 误伤」与 bench 目标（测的是搜索流程能力，收敛到正确答案是好事）方向相反——把「多次搜索得到一致结果」判为刷分，会惩罚好行为。

**若成璐认为 trial 复制刷分风险真实存在**（例如预期被测 agent 会在同批次内复用搜索缓存），折中方案 = A + 把 run 间稳定性降为**诊断信号**（SIGNAL，不 gate O1 得分，只在报告中标注「该题多 run 候选集高度重合，建议人工复核」）——此折中不在三选项内，属新增设计，需另行预注册。
