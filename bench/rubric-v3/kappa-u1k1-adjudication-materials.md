## 2. 关键发现（四个事实，全部仓库内可验）

**F-A：「预注册下限」无数字落点。** o3-claim-list 全文（grep「0.6」零命中）从未写出下限数字；读者看到的 0.6 是从 DRAFT v2 L16/L208 **外部推断**的。§4.3 的「预注册」二字目前名不副实——预注册动作没发生。

**F-B：0.6 的来历 = 2-judge 时代的沿用值，且当时就有已知缺陷。** 唯一出处 = C3 v3 R5（tasks/T8-C3-v3-adversarial-check.md L10）。该场景 = 2 judge 换位双判 + **连续加权分**，其对抗核验质询 3（同文件 L17）原文指出：「κ≥0.6 是双判一致性门槛，但 M8 是连续加权分（0-1），Cohen's κ 需要二分类化——怎么切分？切分点本身引入任意性」。DRAFT v2 R-02 用条目二值化解决了切分问题，但 0.6 数字原样沿用——**从未对「条目层二值」新口径做过任何标定**。

**F-C：判者数错配。** 0.6 出自 2-judge 场景；o3-claim-list §4.1 已定 N=3。Cohen's κ 是 2-judge 指标，N=3 下整体无定义（只能两两配对后聚合）。**同一份数据，不同公式算出的 κ 数值不同**（§3 S2 小例：跨越 [−0.185, 0.5]），0.6 在新公式下的严格性 ≠ 在 Cohen's κ 下的严格性。

**F-D：机判 schema 已隐含一个未裁定的选择。** assert-kappa-receipt.py docstring L19 写死「条目层二值 **Cohen's κ**（DRAFT v2 R-02 口径）」，L22-L23 + L99-L101 约束 `judges` **恰两个**（「≥3 judge Fleiss'κ 属 R5.2-third-scorer 范围」）。即：schema 层已经按「Cohen's + 2 judge」实现，而协议层（§4.1）规定 N=3——**这个矛盾在 r136 落盘时即存在**（RV3G4kra 04.5 A4 以「扩展路径明确」驳回过），U-K1 裁定必须连带处置它（见 §5）。另：脚本现状语义 = κ<0.6 只输出 SIGNAL 不 FAIL（L115-L119）——§4.3 承诺的「低于下限则作废重判」硬门禁**不在任何机判层**，协议承诺与机判实现存在落差。

## 3. 三方案对照表

记号：n = 条目（cell）数，r = 判者数（本协议 r=3），x_ij ∈ {0,1}。公式定义式为教科书标准形式（Cohen 1960 / Fleiss 1971），仓库内无第二来源 → **unverified**（网络受限条款）；正确性由 §3.4 手算小例内部互检兜底。

| 维度 | **F1：Cohen's κ**（2 判者） | **F2：Fleiss'κ**（r≥2 原生多判者） | **F3：pairwise 平均 Cohen's κ** |
|------|---------------------------|-----------------------------------|-------------------------------|
| 定义式 | po = 一致率；pe = 边际独立期望一致率；κ = (po−pe)/(1−pe) | P_i = (k_i/r)(1−k_i/r)，k_i = 条目 i 的 yes 计数；P̄ = mean(P_i)；p̄ = 全局 yes 比例；κ = (P̄ − p̄(1−p̄))/(1 − p̄(1−p̄)) | 每对判者算 Cohen's κ，取 mean（或 median）——须额外预注册聚合方式 |
| N=3 整体可用性 | ❌ **无定义**（定义域 = 恰 2 判者）；只能退化为 F3 | ✅ 原生（r≥2 均适用，r=3 是设计场景之一） | ✅ 派生可用（C(3,2)=3 对） |
| 条目粒度 | 条目级 × 2 判者 | 条目级计数矩阵（k_i ∈ {0,1,2,3}）——与 §4.3「条目层」措辞逐字对齐 | 条目级 × 逐对 |
| 与 §4.2 聚合规则的数据关系 | 无关（2 判者无 ≥2/3 概念） | **共享 k_i**（投票计数）——κ 门禁与聚合零摩擦 | 需保留逐判者原始标注（比 k_i 信息更多） |
| 判者可交换假设 | n/a | **有**——3 判者视为同质样本，单判者 outlier 被平均掉 | 无——保留判者身份，outlier 可见（与 §4.2「第 3 判者的 no 理由必须记录在案」的分歧日志文化一致） |
| degenerate 行为（全一致/全互补） | po=pe → **0/0 未定义** | P̄=P̄_e → **0/0 未定义** | 同 F1（逐对未定义） |
| pre-execution identity 场景 | 旧数据自测 = 完全一致 = 未定义（S3 实证） | 同左 | 同左 |
| 缺失标注处理 | 不适用（2 判者） | 缺判者 → 该条目 k_i 不可算，须预注册剔除规则 | 该 pair 在共同子集上算——子集大小不一时 mean 有偏，median 稳健 |
| 可机判性（给定 rejudge-results.json） | 零歧义 | 零歧义 | 零歧义（前提：mean vs median 已预注册） |
| 与 0.6 的历史绑定 | **强**（0.6 的唯一出处就是 2-judge Cohen's 时代） | 弱（仓库内首次出现 = bench.md L121，作为 third-scorer 目标，从未用于门禁） | 中（Cohen's 的聚合，语义最近 0.6 原意） |
| S2 小例实测值（§3.4） | n/a（需拆对） | **−5/27 ≈ −0.185** | mean = **2/5 = 0.4**；median = **1/2** |

### 3.4 数值自检小例（精确 Fraction，已独立复算零 mismatch）

**S2 主例**——3 判者 × 4 条目（行=判者 J1/J2/J3，列=条目；条目 4 全一致 yes = Fleiss' degenerate cell）：

| 条目 | J1 | J2 | J3 | k_i |
|------|----|----|----|-----|
| 1 | 1 | 1 | 0 | 2 |
| 2 | 1 | 0 | 0 | 1 |
| 3 | 0 | 0 | 0 | 0 |
| 4 | 1 | 1 | 1 | 3 |

四口径读数（Fraction 精确值）：

| 口径 | 计算 | 值 |
|------|------|-----|
| Fleiss'κ | P_i=[2/9,2/9,0,0]，P̄=1/9，p̄=8/12=1/2，P̄_e=1/4 → (1/9−1/4)/(3/4) | **−5/27 ≈ −0.185** |
| pairwise-mean | pair(1,2)=1/2，pair(1,3)=1/5，pair(2,3)=1/2 → 均值 (1/2+1/5+1/2)/3 = (6/5)/3 | **2/5 = 0.4** |
| pairwise-median | 同上三值的中位数 | **1/2** |
| naive 全条目一致率 | 3 对中 0 对逐条目全一致 | **0** |

**结论**：同一份数据，四个口径跨越 **[−0.185, 0.5]**。0.6 阈值在所有口径下都不达标，但结论强度表述完全不同——Fleiss' 说「负一致性」（比随机还差），pairwise-mean 说「中等一致性、距阈值 0.2」，naive 说「零全一致」。**公式选择直接改变门禁报告的话语**，这是 U-K1 不能靠直觉裁定的量化证据。

**S1 辅例**（Cohen's κ 性质锚点，2 判者 × 4 条目）：judge1=[1,1,0,0] vs judge2=[1,0,0,1] → po=1/2, pe=1/2, **κ=0**（观察一致完全是边际结构产物）；judge1=[1,1,1,0] vs judge2=[1,1,0,0] → po=3/4, pe=1/2, **κ=1/2**（边际更不平衡 → 同 po 附近 κ 更大）。两例同时演示边际敏感性与「完全一致 → 0/0 未定义」的 degenerate 边界。

**S3 辅例**（pre-execution 退化态）：identity-baseline（h_claim := h_id 恒等）下若拿旧 hit-matrix 双判自测，两「判者」完全一致 → po=pe → κ 未定义。含义：κ 门禁只能在真实多判者数据上有意义；rejudge 未执行前的正确断言行为 = SIGNAL blocked-on-external（assert-o3-claim-rejudge.py 现状），不是 PASS 也不是 FAIL。

## 4. 排序 + 适用条件（决策输入，非裁定）

**F1 整体出局**（数学事实：N=3 无定义）。它的剩余角色 = F3 的构件 + 0.6 阈值历史出处的说明。实际裁定空间 = **F2 vs F3**，分歧浓缩为一个权重问题：

| | 选 **F2 Fleiss'κ** 如果… | 选 **F3 pairwise** 如果… |
|---|---|---|
| 核心诉求 | 门禁要**单值、零歧义、可机判**；接受「判者同质」假设 | 门禁要能**暴露单判者 outlier**（哪个 judge 偏离），与分歧日志文化一致 |
| 对 S2 型分歧模式的态度 | 「多数一致 + 单点分歧」给出负值是**特性**（惩罚结构性不一致）不是 bug | 负值过度惩罚——outlier 应被点名而非拉低全体分数 |
| 额外预注册负担 | 无（单值） | 须预注册 mean vs median（否则门禁判断本身二义） |
| 对 assert-kappa-receipt.py 的改动面 | judges 放宽为 ≥2 + method 取值域含 fleiss | judges 放宽为 ≥2 + method 取值域含 pairwise-cohen（+ 聚合方式字段） |
| 风险 | outlier 隐形（3 判者里 1 个系统性偏严会被平均掩盖） | mean/median 分居阈值两侧时的二义态；子集缺失时 mean 有偏 |

**runner 排序（显式声明：差距小于 jaccard-m5 的 A≫B/C，不构成强推荐）**：F2 略优先于 F3——理由是**门禁场景的第一需求是单值可机判**（§4.3 的用途是「过/不过」二分，不是诊断报告），outlier 可见性可以由 §4.2 既有的分歧日志承担（「第 3 判者的 no 理由必须记录在案」），不必让 κ 公式兼职。若成璐认为 outlier 检测是门禁本体职责而非日志职责，F3 是合理选择。

**折中出口（与公式选择正交，可叠加）**：把「低于下限 = 作废重判」降为「低于下限 = **SIGNAL + 人工裁决**」。依据：(a) assert-kappa-receipt.py 现状语义已经如此实现（F-D），叠加后协议与机判层零冲突；(b) 0.6 未对新公式标定（F-B/F-C），作硬门禁的风险 > 作信号的风险；(c) AUDIT-report #30 处置已有「κ 验收以人-人一致性为目标参照」的软化先例。代价：§4.3 的「作废重判」承诺弱化——需同步修订 §4.3 措辞（冻结件修改，APPROVALS 登记）。

**阈值处置三选项（F-B/F-C 的落地方式，供裁定时一并勾选）**：
- **α 重新标定**：以人-人一致性基线重标 0.6 → 仓库内无人-人数据，**新增外部依赖**（blocked-on-external 候选，见 §6 导出）；
- **β 维持 0.6 + 显式声明**：裁定文字写明「0.6 为 C3 v3 沿用值，未对新公式重标定」——零外部依赖，阈值严格性是历史惯性（如实标注）；
- **γ 降 SIGNAL**：见上折中出口，0.6 从门禁线变报告线。
