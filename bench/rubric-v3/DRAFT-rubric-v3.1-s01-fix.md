# rubric-v3.1 修订方案（S01 效度修复）

# origin: ai
# 触发：r270 arena 异源 judge 结果——J1-strict 对 S01 分解类工件通过率 0.6%（1/159），
# 而 r268 同源 judge 给 94.2%。根因：rubric v3 的 ①来源真实性 测试 literal 执行时，
# 对"纯模型知识、无外部来源"的分解文档全部判 A 级 fail。这是 rubric 效度问题，不是工件质量差。

## 1. 问题定位

rubric v3 的 J1 三测设计假设：工件是「交叉核验」产物，每条主张都应有可定位来源。
但 T8 消融矩阵的 stage01 工件类型是**目标分解**（因素清单/问题树/待研究项），
其内容本质是模型自身的结构化推理，不引用外部来源是正常形态。

r270 实测数据：
| 阶段 | 工件类型 | r270 J1 通过率 | r268 J1 通过率 |
|---|---|---|---|
| S01 | 分解（模型知识为主） | 0.6% (1/159) | 94.2% (146/155) |
| S02 | 调研（含外部来源） | 21.3% (30/141) | 89.3% (125/140) |
| S03 | 行动分解（内部引用） | 86.4% (95/110) | 83.5% (86/103) |

S01 的 0.6% 不是"分解写得差"，是 ① 测试对这类工件不适用。
S03 的 86.4% 说明当条目有内部引用（U/G/P/Z 编号指向同工件内定义）时，① 能正常工作。

## 2. 修订选项

### 选项 A：按工件类型分轨（推荐）

在 J1 prompt 中加一段【工件类型适配】：

```
【工件类型适配（最高优先级，先于三测判定）】
先判断工件类型：
- 「分解类」（stage01 / 因素清单 / 问题树 / 待研究项 / 目标分解）：
  ① 来源真实性 改为「自洽性」测试——条目必须指向可核查的对象
  （具体因素名+子因素、具体未知点+验证方向、具体约束条件），
  纯形容词/泛泛而谈 = fail；有实质对象 = pass（note 注明「分解类-自洽」）。
  ②③④ 照常执行。
- 「核验类」（stage02 / 交叉核验 / 文献调研 / 含外部来源的主张）：
  ①②③④ 按原 v3 规则执行，无改动。
- 「行动类」（stage03 / 行动分解 / 任务分配）：
  ① 内部引用（指向同工件或前序阶段的 U/G/P/Z/S 编号）= B 级，照常。
  ②③④ 照常执行。
```

理由：
- 最小改动：只加一段前置判断，不改 ②③④ 任何文字
- 与 r270 的 S03 高通过率一致（内部引用已被接受为 B 级）
- 分解类的"自洽性"测试保留了区分度（泛泛而谈仍 fail），不会变成全过
- 与 v3 的 goal 声明一致：v3 本来就区分了"研究分解类工件"（见 ② 的层级边界段）

### 选项 B：S01 单独用 J2-lenient 判

不动 J1，S01 阶段改用 J2（宽松判官）评分。
缺点：失去 strict/lenient 双判对照，G2 spread 计算口径不一致。不推荐。

### 选项 C：S01 退出评分

S01 不参与 pass rate 计算，只评 S02+S03。
缺点：消融矩阵的 config 对比少了一个维度，且 S01 恰恰是"分解能力"的测量点。不推荐。

## 3. 配套修改

1. **item_extraction**：分解类工件的条目抽取正则需确认能抓到 F1/F1.1/P3 这类编号
   （r270 显示抽取正常，31/45/21 条等，无需改）。
2. **acceptance_criteria**：AC1（J1 vs J2 一致率 ≥0.85）在分轨后需重算基线；
   AC3（B-none < 0.3）和 AC4（A-full − B-2del-eo ≥ 0.3）不受影响（它们针对 S02/S03）。
3. **回执格式**：receipt JSONL 每行加 `artifact_type` 字段（decomp/research/action），
   便于后续按类型过滤分析。

## 4. 验证计划

1. 用 rubric-v3.1 重放 r270 的 18 份工件（本地 qwen3.8-27b，temp=0）
2. 预期：S01 J1 通过率从 0.6% 升到 60-90%（与 r268 同源水平接近）
3. S02/S03 通过率应与 r270 基本一致（±10pp 内，因为 ②③④ 没动）
4. J1 vs J2 一致率重新计算，目标 ≥0.85
5. 若 S01 仍 <50% → 说明"自洽性"测试定义还需细化，回到选项 A 迭代

## 5. 不做的事

- 不改 ②③④ 任何文字（r270 证明它们在 S02/S03 上工作正常）
- 不改 G2 spread 口径（那是另一个问题，需要 opportunity set 预注册，不在本次范围）
- 不改 item_extraction 正则（r270 抽取正常）

## r272 验证结果（2026-11-05 00:11）

**S01 维持高位**：J1 150/155 = 96.8%（B-nofreeze/D2/s01 4 个 P* 条目被 ② 一致性 fail，属 judge 提取波动）。

**S02 泄漏修复**：A-full/D1/s02 J1 从 r271 的 0/45 恢复到 36/45（r269 = 37/45，Δ -2.2pp ✓）。分解类 note 零出现在 s02。

**残留问题（非 rubric bug，是 judge 提取波动）**：
- B-none/D2/s02 J1: 9/9 → 5/9（P-A~P-D 在工件正文中不存在，r269 的 pass 是 judge 幻觉；r272 正确 fail）
- A-full/D2/s02 J1: 13/17 → 17/17（同一批 P-A~P-D，r269 正确 fail，r272 幻觉 pass）
- 方向相反 = 纯随机波动，temp=0 下仍出现（vLLM 采样非确定性）

**结论**：rubric v3.1 收紧版逻辑正确。剩余 ±10pp 波动来自 judge 对短编号条目的提取稳定性，不是规则问题。

## r273 终版（2026-11-05 00:20）

在 r272 基础上加显式排除句："不满足 (a) 或 (b) 的任何工件（包括 stage02/stage03、以及任何含外部来源核验主张的工件，即使其中出现 F*/G*/U* 等编号的因素条目）：一律按下方原规则执行"。预期与 r272 一致（r272 已无泄漏），主要目的是锁定 prompt 为终版并留档。

## r273 验证结果（2026-11-05 00:28）

**S01 完美**：J1 155/155 = 100%。分解类 note 正确出现在所有 s01 cell。

**但 B-nofreeze/D1/s02 泄漏复发**：19 个 F* 条目被标"分解类-自洽"而 pass（该工件首行是"# 阶段 02：资料搜集与交叉验证报告"，不含"阶段 01"/"目标分解"）。judge 无视了标题判定规则，用正文内容（因素枚举矩阵）做了类型判断。

**A-full/D1/s02 J1 再次崩到 0/45**（r269=37/45, r272=36/45）：45 个 item 全 fail，29× "①无来源;仅口头断言"。这是 judge 对该工件的严格模式漂移——工件本身含大量"基于模型训练数据"的声明，judge 在 r269/r272 中部分放行（视为"未实抓但含具体估算"），r273 中全部判死。三次 run 同一工件 37→36→0，说明该 cell 的判定对 prompt 微小变化极度敏感（temp=0 下 vLLM 采样仍非确定）。

**根因**：prompt 指令遵循不稳定。27B 模型对"只看首行标题"这种元指令的执行不可靠——它看到因素枚举就路由到分解类，不管标题写什么。

## r274 标题判定版（2026-11-05 00:35）

把类型路由改为纯机械规则："看工件首行标题——含'阶段 01'或'目标分解'→分解类；含'阶段 02'/'阶段 03'或任何其它字样→原规则。禁止用正文内容做类型判断。" 去掉 (a)+(b) 双条件（(b)"正文主体是因素枚举"本身就是泄漏入口），只留标题单一判据。
