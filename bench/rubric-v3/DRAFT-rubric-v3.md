# Rubric v3 草案 — pfb 完整 pipeline 评分标准（outcome + process 双层）

> origin: ai · 2026-10-29 · r59
> 状态：**草案，待 arena 对抗核验后定稿**
> 依据：decomp L1 消融结论（reports/decomp-technical-report.md §5.4-5.5）+ T8 文献调研 R1-R5 + 成璐指令（矛盾层级计分 / 过程行为清单 / 候选集覆盖度）
> 适用对象：pfb 六阶段 pipeline（01→04.5）跑完后的终态产出 + 全程行为记录

---

## 0. 设计原则（先读这个）

1. **outcome 和 process 分开报，不合成总分**。过程好结果差 = 执行 bug；过程差结果好 = 运气或任务太简单。合在一起互相抵消，消融测不出东西。（与 T8-C3 的 M8-truth/M8-cover 拆分逻辑一致。）
2. **所有分数对比 baseline 才有意义**。baseline = 无引导 prompt（C9-plain 档）或开源框架 prompt（AutoGen/LangGraph/ReWOO 档）。单看绝对分不判显著性。
3. **深度 > 广度**。挖到 L3 深层矛盾 1 个 > 表面 trade-off 5 个（权重体现见 §2）。
4. **每个维度给 0/1/2 三档**，判据必须机械可判（judge 照表打分，不留自由裁量空间）。judge 校准门禁沿用 C3 v3 的 R5（换位双判 + κ≥0.6 + 长度去偏），评分前不过门禁不开评。

## 1. Outcome 层（结果标准）—— 看 pipeline 终态产出

### O1 候选集覆盖度（新增 · 成璐指令）

**测什么**：最终产出的候选硬件集是否覆盖了"非直觉但可能最优"的老卡区间，以及每个老卡候选被挖到多深。

**计分 = 覆盖分 + 深度分，按 tier 加权：**

**a) 覆盖分（新-老维度，0/1）**
- 0：候选集只含近两代旗舰/主流卡（A100/H100/4090/5090 档），无任何 2020 年前卡型
- 1：含 ≥1 个老卡候选（V100/P100/T4/2080Ti/1080Ti 档）

**b) 深度分（每个低先验候选独立计，三项各 0/2，tier 权重 w=2）**

"低先验候选" = 按 §4 维度规则必须纳入、但模型第一反应不会选的选项（硬件域 = 老卡/非主流架构；其他域由任务画像定义）。对每个这样的候选 k，检查产出中是否包含以下三项，每项按 tier 给分（未触及=0，有实质内容=2×w=4）：

| 项 | 判据（有实质内容 = 该候选名下有具体证据/数据/分析，不是提一句名字） |
|----|------|
| D1 生态/工具链现状 | 当前支持生态的可查证据（框架 kernel 支持版本、社区活跃度、近期 commit/issue；调研域则是对应立场/流派的一手来源） |
| D2 真实成本/价值 | 实际价格或价值的对比数据（二手价 vs 发布价 vs 同类；带来源），不是规格书名义值 |
| D3 本负载下真实瓶颈 | 在任务画像下的瓶颈判断，用实测数据或机制推理 |

**O1 = 覆盖分(0/1) + Σ_k [4×D1 + 4×D2 + 4×D3]**，其中 D_i ∈ {0,1}（未触及=0，有实质内容=1），即每个低先验候选深度满分 12（三项全满），不设候选数上限——挖得越深越多，分数越高，无封顶。

**为什么这样设计**：生态/成本/瓶颈这三项本身就是 gold tree 的深层节点（L4 叶子/L5 黑盒档），如果只在 O1 里给平档 0/1/2 就低估了；现在按 tier 权重 w=2 计分，且与 O3 的 gold 命中分开算——O1 测"你找没找到这些候选并挖了它们"，O3 测"你挖出来的东西对不对"，两个维度正交，交叉关联不重复计分。

**baseline 预期**：无引导 prompt 在覆盖分上大概率 0（模型先验偏向热门选项），深度分无从谈起。这是本维度最可能产生显著 Δ 的地方。

### O2 矛盾挖掘深度（升级现有 C5 · 层级化）

把 v2 rubric 的 C5（0-2 平档）拆成按深度加权：

| 层级 | 定义 | 示例（27B 硬件域） | 分值 |
|------|------|------|------|
| L1 表面 trade-off | 候选/属性间的直接冲突 | A100 算力高但保值低 vs 3090 反之 | 0.5 个/项 |
| L2 机制矛盾 | 假设/约束/场景之间的冲突，需建模才能看见 | 9:1 缓存比 vs 20 tok/s 硬约束在某卡上不可同时满足；prefill 算力墙 vs decode 带宽墙随并发漂移 | 1 个/项 |
| L3 深层物理/经济矛盾 | 需要领域知识或实测才能发现的机制级矛盾 | fp32 累加路径导致理论 FLOPS 与实测吞吐差距；TCO 中显卡残值随供需周期漂移（不是常数折旧）；混合负载下批处理碎片化+KV 碎片+调度尾延迟使效率衰减 43-53% | 2 个/项 |

**计分**：O2 = min(2, Σ各层级分值)，封顶 2 分（与 v2 总量纲兼容，可映射旧分）。
**标注要求**（沿用 v2）：每个矛盾必须标已解/未解 + 验证路径，否则该项减半。
**gold 对齐**：评分时对照该域的 gold 树深层节点（decomp 域 = bench/gold/L4-L6 的精度三路径/卡价区间 B4/混合负载 L6 整层）。命中 gold 已有深层节点 = 确认有效矛盾；发现 gold 没有的新深层矛盾 = 额外加分候选（记入 gold 更新提案，不在本次计分内，防 judge 主观膨胀）。

### O3 gold 覆盖度（outcome 主分）

**测什么**：终态产出是否命中该域 gold 树的节点，按层级加权。

- 命中 L1-L3 结构节点（标量化/恒等式切分/正交完备/原子化）：基础分
- 命中 L4 叶子（具体公式+变量）：加倍
- 命中 L5 黑盒（显式标注无知+区间+测法）：加倍——**黑盒标注是能力不是缺陷**，漏标才是错
- 命中 L6 修正层（对初始树的推翻/修正，如混合负载）：三倍——这是"反复调研迭代"的直接证据

**判据**：judge 拿产出逐节点对照 gold tree.md，输出命中矩阵。不需要语义模糊匹配，节点 ID 对得上就算命中。

### O4 条件化结论质量

| 档 | 判据 |
|----|------|
| 0 | 给无条件推荐（"选 X"） |
| 1 | 有条件但条件不完整（缺前提参数或区间） |
| 2 | 结论形状 = "在 P1,P2,... 前提下选 A，因为 Q；若 P_k 超出 [a,b] 则排名翻转为 B"，前提可替换、翻转边界显式 |

decomp gold 的标准答案形状就是这条（"u≈0.35、G≈0.68 的前提下 3090×4 第一" + "u<0.35 就别买卡租"）。

### Outcome 总分 = O1+O2+O3+O4（满分另定，建议 O3 占大头）

## 2. Process 层（过程标准）—— 看六阶段全程行为记录

四项都是**可观测行为**，从 transcript/loop-artifacts/回执里机械提取，不靠 judge 印象分。

### P1 调研外包优先

| 档 | 判据 |
|----|------|
| 0 | 关键事实全部自己 AI 琢磨，无 arena/外部调研派发记录 |
| 1 | 有派发但时机晚（先自己做了大半才外包）或外包范围窄（只核单个数字） |
| 2 | 信息搜集类工作（前沿调研/矛盾核验/规格查证）默认走 arena 派发，任务书落仓库，本地只做整合 |

**证据**：arena 会话 ID + 任务卡路径 + 派发时间点 vs 首次触碰该问题时间点。

### P2 拆解并行

| 档 | 判据 |
|----|------|
| 0 | 线性串行执行，无任务分解 |
| 1 | 有分解但全串行，或分解粒度粗（>5 步的大块） |
| 2 | DAG 分解 + 无依赖节点并行派发（≥2 路并行有记录），每节点输入/输出/验收明确 |

**证据**：decomposition.md 的分解树 + 并行派发的时间戳重叠。

### P3 交叉验证

| 档 | 判据 |
|----|------|
| 0 | 关键结论单源，无第二来源 |
| 1 | 部分关键结论有 ≥2 源，但回执不全（缺 provider 记录） |
| 2 | 所有进入最终结论的关键事实都有 ≥2 独立来源回执（web-llm 回执 successful_provider_ids ≥2 或等价证据链），矛盾答案有记录和处理 |

**证据**：web-llm/*.json 回执 + 02.5 阶段工件。

### P4 追问到边界并正确停（最难也最有价值）

**测什么**：矛盾追问是否撞到真正的边界，且**停在正确的边界类型上**。

| 档 | 判据 |
|----|------|
| 0 | 矛盾出现即绕过（编理由/跳过/写"需要进一步研究"后不再碰） |
| 1 | 追到了边界但停错了地方：该有数学证明的地方停在"查不到资料"，或该去实操取证的地方硬推理论 |
| 2 | 每条关键矛盾的终止点都显式声明边界类型：①**数学/理论边界**（推到定理/不等式/信息论极限，写下"到此为止因为 X 定理"）②**实操边界**（成本/授权/买不到硬件/时间预算，写下"到此为止因为 Y 需要 Z 资源"）③**信息边界**（公开渠道穷尽，登记 research_required + 获取路径） |

**为什么重要**：这条测的是"知道什么时候该停"——L1 消融没测过这个维度，而它是 pfb 一阶段相对 decomp 单步的核心增量价值。停错边界 = 要么浪费算力空转，要么该证的不证直接猜。

**证据**：每条 OPEN/矛盾条目的终止注记，judge 对照边界类型三分类打档。

### Process 总分 = P1+P2+P3+P4（各 0-2，满分 8）

## 3. 实验设计（怎么跑出这些分数）

### 3.1 域选择

第一格沿用 decomp 27B 硬件域（gold 现成、baseline 分数现成可直接复用 L1 的 C9-plain/AutoGen 数据做冷启动对照），但题面升级为 **rubric-v3 版**（见 §4 候选空间完备性指令）。第二格选一个 gold 需新建的域（建议：推理基础设施选型或科研方法论，T17 已有半成品），测 gold 覆盖度在新域上的可构建性 + §4 通用补丁在第二域上不改一字是否仍然有效。

### 3.2 变体矩阵（prompt 侧）

| 变体 | 内容 | 测什么 |
|------|------|--------|
| V0-baseline | 无引导白话题面（= C9-plain 档） | baseline 锚点 |
| V1-full | 完整 pfb 六阶段 prompt + 候选集扩展指令（§4） | 完整 pipeline |
| V2-nocoverage | V1 去掉候选集扩展指令 | 隔离 O1 的 prompt 归因 |
| V3-noboundary | V1 去掉"停止条件表+边界类型声明"要求 | 隔离 P4 的 prompt 归因 |

V2/V3 是定向消融：如果 O1/P4 分数在 V1 显著高于 V0 但在 V2/V3 掉回 V0 水平，说明是那条指令的因果贡献，不是整体氛围效应。

### 3.3 统计

- 分析单元 = (题, 评分项)，配对差值 + 任务块聚类 SE（R3）
- n 由 MDE 反推：以 L1 的效应量（契约 Δ=10.63/20 分制）为上限估计，O1/O2 这种新维度预期效应更小，n 可能要 ×2（R3 的 underpowered 教训）
- Holm 校正多对比
- judge 校准门禁（R5）前置：换位双判 + κ≥0.6 + 长度去偏检查，不过不开评

## 4. 候选空间完备性指令（通用 prompt 补丁 · 替代原"四分区"域特定版）

**问题诊断**：C0 题面写"常见的候选硬件"，模型自搜集合系统性偏向先验强的选项（新卡），低先验但可能最优的选项（老卡/非主流方案）缺席。原因不是模型不努力，是"常见"这个词把搜索空间锚定在了先验分布上——任何域都有同样的病：选型题漏冷门方案、调研题漏反面证据、方法题漏被放弃的路线。

**为什么不用域特定补丁**：之前那版"四分区+老马区三问"只适用于硬件选型域，换个域就废了。pfb 要的是跨域通用的机制，所以补丁只约束**搜索空间的构造方式**，不指定具体分什么区——分区由被测者按任务自行定义，这是它自己的分解能力的一部分（测出来正好归 O3/P2）。

**补丁设计**（加进题面，V1/V2 的区别就在这一段）：

```
【候选空间构造规则】（硬性，不许跳过）
1. 候选空间不许直接枚举。先显式写出你的划分维度（≥2 个正交维度，
   例如：代际/架构/成本区间/成熟度/来源渠道——按任务自选），
   然后沿每个维度分别搜索，合并去重。
   划分维度的选择本身要给出理由：为什么这几个维度能张成整个空间。
2. 每个维度至少覆盖两端 + 中间档（如代际维度必须同时覆盖最新和
   发布 ≥5 年的旧选项；成本维度必须同时覆盖最高和最低可行档）。
   某端确实没有合格候选，写明搜了什么、为什么没有，不许静默跳过。
3. 对每个"低先验候选"（你第一反应不会选、但按维度规则必须纳入的），
   必须回答该域的关键评估问题（由任务画像决定，通常包括：
   当前生态/工具链支持现状、真实成本或价值、在本任务负载下的真实瓶颈）。
   用实测数据或可查证据，不许用规格书名义值或印象分。
4. 搜索预算：候选空间构造阶段的搜索不设次数上限，
   直到每个维度都覆盖到两端或有显式的"无合格候选"声明为止。
   wall-clock 上限 2h；触发上限时按实际状态继续后续阶段，不罚分。
```

**设计逻辑**：
- "维度由被测者自选 + 要给理由"= 通用性：硬件域会选代际/架构/成本，调研域会选时间/立场/方法论流派，哪个域都不需要改补丁
- "每维度覆盖两端"= 反先验锚定的最小机制：先验偏差总是集中在"中间热门"，强制覆盖两端就把冷门选项逼进视野
- "低先验候选必须深评"= 对应 O1 深度分的判据来源：提了一嘴不算，有证据才算
- "不许静默跳过"+ 停止条件 = pfb 既有范式（M8-cover 逻辑 + 停止条件表）
- 2h wall-clock 上限 = 实操边界显式化，防止"不设上限"变成 run 时长爆炸（开放问题 4 的解法）

**预言（跑之前写死）**：
- Pr1：V1 在 O1（覆盖分）上 > V0，且 V2 ≈ V0（去掉指令后贡献消失）——证明因果归因干净
- Pr2：V1 的候选空间中"低先验候选"占比 > V0（跨域通用指标，不依赖具体卡型）
- Pr3：如果低先验候选进入最终排名前 3，说明 baseline 的先验偏差造成了实质决策错误——论文级发现，单独标记

## 6. 开放问题（待对抗核验重点质询）

1. O3 的 gold 节点命中制会不会退化成"背 gold"？——产出如果是照着 gold 写的，命中率高但没测到能力。对策：judge 只看终态不看过程来源，且第二格用新建 gold（跑之前冻结）；但如果模型在 pipeline 过程中读过 gold 文件就污染了——需要执行环境隔离（被测 agent 的 workspace 里没有 gold/）
2. O2 的 L3 判定很依赖 judge 的领域知识，κ≥0.6 能不能达到？——可能需要 L3 项改用"是否命中 gold 深层节点 OR 被 gold 维护者（Lead）确认为真矛盾"的二元判定，降低连续判断
3. P4 的边界类型三分类有没有第四类（比如"问题本身 ill-posed"）？——草案先留三类，核验时质询
4. 候选集扩展指令的"搜索预算不设上限"会不会让 run 时长爆炸？——需要设 wall-clock 上限（如 2h）作为实操边界，但上限触发时的产出按实际状态计分不罚分
5. V0 baseline 复用 L1 的 C9-plain 数据还是重跑？——L1 的题面没有候选集构造要求，O1 维度上 C9-plain 的分数是"未定义"而非 0 分，严格说要在 v3 题面上重跑 V0
