## 0. 任务定义（本 run 的切入点）

从零起。题面四个事实：64K 上下文、含一段长期不变可缓存的前缀、每并发流 ≥20 tok/s、通过率 <100% 要重做。

前四件事里，前三件都在描述**机器**，只有最后一件在描述**任务**。本 run 从这里切：这台机器买回来之后，**它不是一直在干活的**。没有任务排队的时候，卡在空转、电在空烧、钱在按小时贬。所以「每完成一个任务花多少钱」这个数，分母不是机器的能力，是机器的**实际产出**——而实际产出 = 能力 × 占空比。

- **根**：C_task [$/task] = S_hourly ÷ (N_max × D × p)
- S_hourly = 每小时固定成本（**不随产出变**，这是本 run 全部推论的支点）
- N_max = 满负荷每小时能完成几个任务（机器属性）
- D = 占空比：墙钟时间里真正在跑任务的比例（**任务属性，不是机器属性**）
- p = 通过率

关键推论立刻可见：**D 掉到 10%，成本就涨 10 倍，与买哪张卡无关。** 所以先问「你要跑多少任务」，再问「买什么卡」。

## 1. 拆解树

```
C_task 每通过任务成本
├─ 分母① 能力 N_max = 3600 ÷ T_task        ← 机器属性，前面所有拆解都在这一支
│  ├─ T_pre = 64K×(1−rho_pre) ÷ v_pre
│  │  └─ rho_pre 可缓存前缀占比                 〔只能测；题面留白〕
│  └─ T_dec = out_tok ÷ v_dec(64K 深度)         〔只能测〕
├─ 分母② 占空比 D                          ← 本 run 的主角
│  ├─ D = min(1, Q ÷ N_max)，Q = 任务到达率
│  │  ├─ 队列不足区：D = Q/N_max < 1（机器等任务）
│  │  └─ 队列饱和区：D = 1（任务等机器）
│  └─ Q 的量纲换算：月任务量 V ÷ 730 h
├─ 分母③ 通过率 p                               〔只能测〕
└─ 分子 S_hourly（固定成本，与 D 无关）
   ├─ capex_h = P_buy ÷ H_life                  〔只能查 / 可调〕
   └─ power_h = [P_idle×(1−D) + P_load×D] × E_unit
      ├─ P_idle 空闲墙功率                      〔只能测〕← 空转也在烧电，不是零
      ├─ P_load 满载墙功率                      〔只能测〕
      └─ E_unit 电价 ¢/kWh                      〔只能查〕
```

## 2. 两个 regime 的代数（为什么「速度」在某些情况下完全不重要）

**队列不足区（D<1）**：机器只能做 Q 个任务/小时，做多做不了。
C = S_hourly ÷ (Q × p) —— **N_max 不在式子里**。此时换一张快 2 倍的卡，成本一分不降（只会让 D 从 0.04 掉到 0.02，机器更闲）。

**队列饱和区（D=1）**：任务排队等机器。
C = S_hourly ÷ (N_max × p) —— 此时 N_max 全额变现，快卡才有意义。

**两个 regime 的唯一判据**：你的月任务量 V 是否大于 N_max × 730。**这不是硬件问题，是需求问题。**

## 4. 占空比怎么把成本拉开：同一台 3090，65 倍

固定：3090×1（$1,450，24000 h 摊销）、P_idle=0.07 kW（卡 21 W + 平台 50 W）、P_load=0.40 kW、电价 0.1351、T_task=49.8 s → N_max=72.3 任务/h、p=0.9。

| 月任务量 V | Q 任务/h | D | 平均墙功率 kW | S_hourly | C_task |
|---|---|---|---|---|---|
| 500 | 0.68 | 0.9% | 0.073 | $0.070 | **$0.114** |
| 2,000 | 2.74 | 3.8% | 0.083 | $0.072 | $0.0290 |
| 10,000 | 13.7 | 19% | 0.132 | $0.078 | $0.00635 |
| 51,000 | 69.9 | 97% | 0.389 | $0.113 | $0.00179 |
| ≥52,800（饱和） | — | 100% | 0.400 | $0.114 | **$0.00176** |

**同一台机器、同一个任务，成本从 $0.114 到 $0.00176，差 65 倍。** 这个跨度大于本树里任何一个硬件变量能造成的跨度（3090 与 A100 40G 之间只差 3.6 倍）。

**成本结构的翻转也在这里**：D=1 时电费占 47%（0.054/0.114），D=4% 时电费只占 14%（0.011/0.072）、**capex 占 86%**。所以「电费是大头」这句话只在机器 24×7 满载时成立；对一个月跑两千个任务的单机用户，**买卡钱才是大头，电费几乎可以忽略**——这与多数成本讨论的默认假设相反。

## 5. 换卡还有意义吗：三种卡在两个 regime 下的对照

| 配置 | capex_h | N_max 任务/h | 饱和区 C | V=2,000/月（D<1）C |
|---|---|---|---|---|
| 3090×1 | 0.060 | 72.3 | **0.00176** | **0.0290** |
| 4090×1 | 0.067 | 81.3 | 0.00190 | 0.0317 |
| A100 40G | 0.250 | 149.4 | 0.00216 | 0.1055 |
| A100 80G | 0.417 | 204.5 | 0.00280 | 0.1777 |

**结论 1：两个 regime 下 3090 都赢**（饱和区赢 4090 8%、赢 A100 40G 23%；队列不足区赢 4090 9%、赢 A100 40G 3.6 倍）。所以「regime 决定排序」这个先验假设在本题不成立——**但 regime 决定成本的量级（65 倍）和「该测什么」**，见 §7。

**结论 2：饱和区的胜负只差 23%，且有一个明确的价格翻转点。** 令 3090 饱和区成本 = A100 40G 饱和区成本：
( P/24000 + 0.054 ) ÷ 65.1 = ( 6000/24000 + 0.041 ) ÷ 134.5
解得 **P ≈ $2,080**。也就是说：**二手 3090 涨到 $2,080 以上时，满负荷用户该改买 A100 40G。** 现价 $1,450（90 天高点 $1,502）离这个阈值只有 43% 的距离——这是一条可以直接挂在采购单上盯的线，比「哪个更划算」的定性结论有用得多。

**结论 3：队列不足区的排序退化成「买最便宜的、能通过硬约束的那张卡」。** 因为此时 S_hourly 里 capex 占 86%、且 N_max 不进公式。这也是为什么本 run 不把「哪张卡快」当选型依据。

## 6. 黑盒声明

1. **D 占空比**（本 run 的核心未知，题面没给、也不属于硬件）：区间 **[0.02, 0.5]**，取自三份报告的 2%–48% 带。测法：**先看日志**——过去三个月每天真正在跑任务的小时数 ÷ 24×天数，**10 分钟就能算出来**，这是全树最便宜、收益最大的一次测量。
2. **Q 或 V（月任务量）**：同上，是 D 的输入。若是新项目，用「预计日活任务数」代替，区间必然宽，那就按 §4 的表把 3 个情景都算出来，而不是赌一个点。
3. **rho_pre 可缓存前缀占比**（题面留白）：区间 **[0.5, 0.95]**。**注意它在队列不足区完全不影响结论**（N_max 不进公式），只在饱和区影响 N_max 的 ±4%。这是本 run 与「先测前缀占比」的直觉相反的地方。
4. **P_idle 空闲墙功率**：区间 **[0.07, 0.20] kW**（含多显示器/驱动 bug 情形的上界，见矛盾 1）。测法：插座功率计在**没跑任务时**读一次，5 分钟。
5. **p 通过率**：区间 [0.5,0.95]，跑 100 任务，1 天。它只平移成本不改排序。
6. **v_dec(64K 深度)**：区间 [12, 30] tok/s，只影响饱和区的 N_max。

## 7. 「该测什么」随 regime 变（本 run 的元结论）

| 待测项 | 队列不足区（D 小） | 队列饱和区（D=1） |
|---|---|---|
| rho_pre 前缀占比 | **不重要**（不进公式） | 影响 N_max ±4% |
| v_dec(64K) | 不重要 | 影响 N_max ±30% |
| p 通过率 | **重要**（分母一次乘） | 重要 |
| P_idle | 不重要（绝对值小） | 不重要 |
| **D / V** | **最重要（决定 65 倍量级）** | 已确定为 1 |
| 二手成交价 | **重要（占成本 86%）** | 重要（决定翻转点） |

所以调研顺序不是固定的：**先花 10 分钟把 D 算出来，再决定后面该测什么。** 如果 D 是 2%，那么「64K 深度下 decode 到底多少 tok/s」这个所有人都在争论的问题，对本题的答案没有任何影响。

## 8. 矛盾清单

**矛盾 1 · 3090 空闲功耗：16–23 W vs 100–120 W（差 5–6 倍）**
- 源 A：igor'sLAB 评测 16 W、ServeTheHome 评测 21 W、NVIDIA 开发者论坛单显示器读数 22.85 W（显存 405 MHz）。
- 源 B：**同一个 NVIDIA 论坛帖**里 99.83 W（显存频率被钉在 9485 MHz）；GeForce 论坛多名用户 102–120 W（多显示器 + 高刷 + G-Sync），断开一台显示器即从 102 W 掉到 28 W。
- 同一个量（一台 3090 空闲时的功耗），差 5–6 倍，**机制清楚**（显存锁频 / 多显示器），构成本 run 认定的真矛盾。
- **更可信：源 A（16–23 W）对本场景**。理由：本题是**无显示器的服务器**用途，源 B 的异常读数都发生在有显示器且多屏高刷的桌面环境；机制上也不该在 headless 场景复现。
- 后果：若真取到 100 W，D=4% 时电费从 $0.011 涨到 $0.020/h，电费占比从 14% 升到 22%，**成本变差 13%，但 capex 仍是大头、排序不变**。这条矛盾影响的是「要不要买台带屏的工作站」，不是选卡。

**矛盾 2 · 自建推理的平均 GPU 利用率：5% vs 22% vs 2–5%**
- 源 A：Cast AI《2026 State of Kubernetes Optimization》企业服务器平均 **5%**；另一份单团队本地部署估 **2–5%**。
- 源 B：Spheron 2026-04 FinOps 文章称典型自建推理集群 **22%**（夜间与周末全闲），并称开连续批处理后可从 <20% 提到 >70%。
- 同一个量（自建机器的平均利用率），5% 与 22% 差 4.4 倍，**同一量不同值 → 判为真矛盾。**
- **更可信：源 A 的 2–5% 更贴近本题**。理由：本题是**单个用户、本地跑一类固定任务**，不是有多租户排队的集群；源 B 的 22% 来自有持续请求流的部署。且源 A 有 2026 年的全量报告背书。
- 后果：这条矛盾**不改变排序**（§5 结论 1 在 2%–48% 全带内都成立），但它决定你落在 §4 表的哪一行——**而这一行之间的差距是 65 倍，比选卡的 3.6 倍重要一个数量级。**

**未判为矛盾的**：电价（商业/工业口径不同）、3090 二手价区间（$800–1,450 各源差异大，但属区间宽度；本 run 取中位 $1,450 作保守上界）、A100 二手价（$4–9k 各源重叠）。

## 9. 瓶颈判定

**瓶颈 = D（占空比），即「这台机器到底有多忙」这个题面没给、也不属于硬件的量。**

- 理由一（量级）：D 从 100% 掉到 4%，成本涨 16 倍；掉到 0.9%，涨 65 倍。选卡最多改变 3.6 倍。**D 是唯一能造成一个数量级以上差异的变量。**
- 理由二（结构）：D 还反过来决定成本结构（电费占比 47% vs 14%），以及**决定哪些技术指标值得测**（§7）。它是元变量，不是并列变量。
- 理由三（可测性）：D 反而是全树里**最容易测**的——翻日志算「过去三个月每天有任务的小时数」，10 分钟，零成本。**瓶颈同时是最廉价的测量点，这是本题最重要的一个不对称。**
- 反例检查：如果这是新建项目、没有历史日志（D 未知且无数据），那么瓶颈转移为「需求预测」，此时正确动作不是买卡，而是**先按 §4 表把 3 个情景都算出来，并优先选一张能随时转手的卡**（二手 3090 的残值在矛盾外的价格数据里约为发售价的 97%，转手成本低）。这条反过来给了一个选型理由：**在高不确定场合，选流动性好的卡比选便宜的卡更重要。**

## 10. 自检

- **完整**：S_hourly ÷ (N_max × D × p) 还原 C_task；分母三支（能力/占空比/通过率）穷尽机器与任务两侧；分子两支（capex/power）穷尽固定成本。✓
- **不重叠**：capex 抢钱、power 抢电、N_max 抢算力与带宽、D 抢**时间**（与前三者不抢同一个底层资源——这是本 run 能把它单列一支的理由）。**已知耦合**：D 同时出现在分子（power_h = P_idle×(1−D)+P_load×D）和分母（N_max×D），一处出现两次；本 run 在 §4 表里已按同一 D 取值同时代入，没有重复计，但**这意味着 D 的误差会被放大一次以上**（D 估错 2 倍，成本估错约 2.2 倍而非 2 倍）。**已知遗漏**：任务排队延迟/失败重试的等待时间没进 D（只算了“在跑”的时间），若队列有明显等待，实际 D 会更低；也未建运维人力与机位成本。
- **未做**：D 的历史日志统计（10 分钟就能做，本 run 没数据）、p 实测、v_dec 深度实测。**按本 run 的结论，第二项在低占空比区优先级低于第一项。**
