# Q7 Gold Tree — SSD RAID vs HDD+SSD 分层 vs 云对象存储：每 TB 年有效可用容量成本

> 题面：`bench/questions/Q7-storage-arch.txt`｜域：storage（与 Q1–Q5 的 AI/ML 无重叠）
> 全部数值来自任务期间的独立调研（2026-08 ~ 2026-11 的价目页/规格页/政策文件），**未引用 `gold-tree.md`（Q1）任何数值**。
> 节点计数：**44 节点 / 主干深度 4 / 叶子 16 个**。汇率 1 USD = 7.1 CNY（conf 0.8，随时波动，见 §未验证）。

## 结论先行

- **纯成本：HDD+SSD 分层胜**，约 **¥341–527 /TB·年**；全闪 NVMe **¥523–1,062**；云对象存储 **¥525**（温数据留在标准层、冷数据冷归档、计算同地域）。**分层的下界与云的区间重叠**，所以「分层必胜」是伪结论。
- **真正的分水岭不是单价，是 N-1 的换算系数 1.805**：EC 8+3（1.375）× 元数据（1.05）× 预留水位（1.25）。**谁直接拿「硬盘 $/TB」当答案，谁就低估了 72%。**
- **题面的「温数据每天扫 1-2 次」把云方案从「存储费主导」翻转成「请求费 + 出口费主导」**：同地域内网免费时云仍可用；一旦需要跨区/出公网，100TB/日 × 30 天 × 0.50 ¥/GB ≈ **¥150 万/月**，云方案当场出局。
- **RTO 才是排除项**：本地全量回灌 500TB 在 10Gb/s 下约 **114 小时（≈5 天）**；云冷归档全量取回 ≈ 4 万人民币 + 小时到天级等待。若题主有「RTO < 4 小时」的硬约束，**三个方案在题面给定架构下都不成立**，必须加副本/热备——这正是题面遗漏的成本项。

## 四处 ★ 判断

**★F-A：分母被 1.805 倍缩放，这是全题最容易被忽略的乘法。**
要存 500TB 可用数据，EC 8+3 需 687.5TB，加元数据 5% → 722TB，再加 80% 使用率水位 → **902TB 原始盘**。任何「用 $/TB 乘以 500」的算法都会低算 80%。同理，全闪方案买的是 902TB 的 NVMe，不是 500TB。

**★F-B（承 A）：SSD 与 HDD 的折旧年限不同，直接比 $/TB 是错的。**
NVMe 按 TBW/DWPD 计寿命，500TB 温数据日扫 1–2 次属读密集、写放大低，H 可取 4–5 年；但若做任何重建/重平衡写入，3 年换盘。HDD 5 年。**年化后 NVMe 相对 HDD 的劣势会再放大 20–60%。**

**★F-C：「每天扫 1–2 次」把云方案的定性彻底改掉。**
100TB/日读、对象 1MB → 1 亿次/日 → 请求费 ¥100/日（¥3.65 万/年，可接受）；对象 128KB → 8.2 亿次/日 → ¥819/日（¥29.9 万/年，与存储费同量级）。**同一条题面，两个数量级的差，全在对象大小上。** 若对象更小或走公网出口，云方案连讨论的必要都没有。

**★F-D：RTO 是排除项而不是加权项。**
本地 500TB 全量回灌 @10Gb/s ≈ 114 小时；这个数字与「运维便宜」不构成权衡关系——它直接否掉 RTO<24h 的场景。云冷归档虽快照可用，但全量取回要 ¥4.1 万（400TB×0.10 ¥/GB）且需数小时解冻。**题面要求「含 RTO 代价」是对的：不加这一项，分层方案会被高估。**

## 算例（可复算）

前提：C_usable = 500TB（冷 400 + 温 100）；f_ec=1.375，f_meta=1.05，f_water=1.25 → **f_total=1.805**；H=5 年；电价 0.65 ¥/kWh；PUE 1.3；1 USD=7.1 CNY；对象 1MB。

**A 全闪 NVMe**：raw = 902TB → 902 × ($117–300)/TB = $105.5k–270.6k；+15% 机头网络 → $121k–311k → ¥861k–2,209k ÷5 = **¥172k–442k/年**。电：(902/15.36×12W=705W + 机头 1.2kW) ×1.3 ≈ 2.48kW → 21,700 kWh → ¥14.1k。运维 ¥75k。合计 ¥261k–531k → **¥523–1,062 /TB·年**。

**B 分层**：冷 400TB → raw 722TB HDD × ($28–45) = $20.2k–32.5k；温 100TB → raw 180.5TB NVMe × ($117–300) = $21.1k–54.2k；+15% → $47.5k–99.7k → ¥337k–708k ÷5 = ¥67k–142k/年。电：(722/24×6.3W=190W + 180.5/15.36×12W=141W + 1.2kW) ×1.3 ≈ 1.99kW → 17,400 kWh → ¥11.3k。运维 ¥75k。备件 5% CAPEX ¥17k–35k。合计 ¥170k–263k → **¥341–527 /TB·年**。

**C 云**（冷归档 + 标准，同地域内网）：
- 冷 400TB × 0.016 ¥/GB·月 = 400×1024×0.016×12 = **¥78,643/年**
- 温 100TB × 0.12 ¥/GB·月 = 100×1024×0.12×12 = **¥147,456/年**
- 请求：100TB/日 ÷1MB = 1.05 亿次/日 × 365 = 383 亿次/年 → 383,000 百万次 × ¥1 = **¥38,300/年**
- 出口：同地域内网 **¥0**（若出公网：¥1,530 万/年，fail）
- 合计 **¥264,399/年 → ¥529 /TB·年**

**RTO 对照**：B 全量回灌 500TB @10Gb/s = 500×1024 GB ÷ 1.25 GB/s = 409,600s ≈ **114 小时**；A 单盘重建 24TB ÷ 285MB/s ≈ 24h（实际约 2×）；C 冷归档全量取回 400TB × 0.10 ¥/GB = **¥40,960** + 解冻数小时。

## 判据（谁赢，取决于两个外生条件）

| 条件 | 胜者 | 理由 |
|---|---|---|
| 只看 5 年纯成本、RTO 放宽 | **B**（¥341–527） | 冷数据用 HDD 吃掉 80% 容量，是最省的结构 |
| RTO < 4 小时 是硬约束 | 三者都不成立 → 需热备/双活（题面未含此成本） | 回灌 114h、取回 ¥4 万，均超约束 |
| 计算不在同地域、必须出公网 | B 或 A | C 的出口费 ¥153 万/月直接出局 |
| 无运维人力 / 希望按量 | **C** | 与 B 的区间重叠（¥529 vs ¥341–527），买的是「没有 RTO 责任」 |
