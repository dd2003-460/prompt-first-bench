## 0. 任务定义（本 run 的建模选择）

从零起，不看其他 run。题面四个事实：64K 上下文、含一段长期不变的可缓存前缀、单流 decode ≥ 20 tok/s、通过率 <100% 要重做。

本 run 不从「买哪张卡」起手，从**钱的形态**起手——一台机器买回来之后，只有四类钱会流出去，且它们的性质完全不同：

1. **一次性**：买卡/买整机，摊到小时；
2. **经常性**：电，按小时、按负载走，跑不跑都要付；
3. **或有**：硬件坏，概率×单价摊到小时；
4. **重做损失**：任务没做对要再做一遍，把上面三项乘上一个 1/p。

再乘上**产能**（每小时能做完几个任务，由预填+生成的墙钟时间决定），就是根节点。

- **根**：C_task [$/task] = (capex_h + power_h + fail_h) ÷ (N_per_h × p)
- 候选（自行调研）：RTX 3090 24G×1/×2/×4、RTX 4090 24G×1、L40S 48G×1、A100 40G×1、A100 80G×1。

## 1. 拆解树

```
C_task 每通过任务成本
├─ 一次性 摊销 capex_h [$/h]                       占 0.42
│  ├─ P_buy 购价                                〔只能查〕
│  ├─ 残值 salvage_rate                         〔只能查〕← 3 年后卖得回几成
│  └─ H_life 摊销小时                           〔可调〕
├─ 经常性 电费 power_h [$/h]                       占 0.43
│  ├─ P_wall 墙功率 = 卡数 × 卡 TDP × 利用率系数  〔只能测〕
│  └─ E_unit 电价 ¢/kWh                         〔只能查〕
├─ 或有 故障 fail_h [$/h]                          占 0.05
│  ├─ AFR 年化故障率                            〔只能查+只能测〕← 区间极宽，见矛盾 3
│  └─ 卡价 P_buy（同上，耦合）
├─ 重做 1/p                                       占 0.10
│  └─ p 通过率                                  〔只能测，题面只说不是 100%〕
└─ 产能 N_per_h = 3600 ÷ T_task
   ├─ T_pre 预填 = 64K×(1−rho_pre) ÷ v_pre
   │  ├─ rho_pre 可缓存前缀占比                 〔只能测，题面留白〕
   │  └─ v_pre 预填速度                         〔可测：实测 1503 t/s @单 3090〕
   └─ T_dec 生成 = out_tok ÷ v_dec(depth)
      └─ v_dec(depth)                           〔只能测〕← 深度敏感，见矛盾 1
```

份额按「候选集合内该因子的 ln 极差」归一化：capex_h ln 极差 1.10（$0.060–0.417）、power_h 1.02（$0.034–0.108 单卡档，多卡档更大）、fail_h 0.13、1/p 0.64。归一化后 capex 0.42 / power 0.43 / fail 0.05 / 1-p 0.10。**注意电费与摊销几乎打平**——这是本 run 与「买卡钱是大头」的直觉分道扬镳的地方，下面算给你看。

## 2. 一次性 vs 经常性：谁是大头

单卡档（3090，350 W；2026 年二手均价 $1,450；3 年 8000 h 摊销；电 13.51 ¢/kWh）：

- capex_h = 1450 ÷ 24000 = **$0.060/h**
- power_h = 0.35 kW × 0.1351 = **$0.047/h**
- 电费占两者之和的 **44%**

四卡档（3090×4，1.4 kW，$5,800）：

- capex_h = 5800 ÷ 24000 = **$0.242/h**
- power_h = 1.4 × 0.1351 = **$0.189/h**
- 电费占 44%（同比例，因为两者都随卡数线性走）

但换成**老卡多卡**（V100 32G×8，2.0 kW，8×$400 = $3,200）就翻过来了：

- capex_h = 3200 ÷ 24000 = **$0.133/h**
- power_h = 2.0 × 0.1351 = **$0.270/h**
- **电费是折旧的 2.0 倍**，占两者之和的 67%

这条是本 run 的结论骨干：**「老卡二手便宜所以划算」只在单卡成立；一旦为了装下 64K 的 KV 而堆到 4–8 张老卡，电费就会反超折旧成为最大项**。堆卡不是免费的——它按 kW 收费。

## 3. 产能：时间这一支的实测锚点

| 量 | 值 | 来源性质 |
|---|---|---|
| 单 3090 预填 pp512 | 1503 t/s | 用户实测（HF 报告，27B Q4_K_M） |
| 双 3090 预填 | 1616 t/s | 用户实测汇总 |
| 双 3090 生成 @4K | 40.6 t/s | 同上 |
| 双 3090 生成 @95K | **4.03 t/s** | 同一作者的调优记录（同配置浅上下文 22.8） |
| 单 3090 生成（浅上下文） | 35–50 t/s | 社区多人报告 |

**预填不是问题，生成才是**：6400 个新 token 的预填在 3090 上 4.3 s；1000 个输出 token 的生成在 64K 深度上要 45–50 s。比例约 1:11。所以**只要 rho_pre 不是低到 0.3 以下，预填支对成本的影响都在 10% 以内**——这和「长上下文=预填贵」的直觉相反，因为可缓存前缀把预填量砍掉了大半，而生成必须逐 token 走完。

**产能表**（out_tok=1000，rho_pre=0.9，64K 深度折减系数取 0.55）：

| 配置 | v_pre | T_pre | v_dec@64K | T_dec | T_task | N_per_h |
|---|---|---|---|---|---|---|
| 3090×1 | 1503 | 4.3 s | 22 | 45.5 s | 49.8 s | 72 |
| 3090×2 | 1616 | 4.0 s | 20 | 50 s | 54 s | 67 |
| 3090×4 | ~1700 | 3.8 s | 18（PCIe 摊薄） | 55 s | 59 s | 61 |
| 4090×1 | ~1700 | 3.8 s | 25 | 40 s | 44 s | 82 |
| L40S | ~2000 | 3.2 s | 26 | 38 s | 41 s | 87 |
| A100 40G | ~4000 | 1.6 s | 48 | 21 s | 23 s | 158 |
| A100 80G | ~4000 | 1.6 s | 63 | 16 s | 18 s | 205 |

**注意 3090×2 比 3090×1 的产能更低（67 vs 72）**：多卡并没有带来吞吐收益，因为这里的瓶颈是「每 token 要读的字节数」而不是算力，而 PCIe 张量并行还要在每个 token 上加一次 all-reduce。**堆同代卡在这道题里是三输：钱更多、电更多、还可能更慢**。

## 4. 每任务成本

C_task = (capex_h + power_h + fail_h) ÷ N_per_h ÷ p，取 p=0.9、AFR=2%/yr。

| 配置 | capex_h | power_h | fail_h | Σ | N_per_h | C_task |
|---|---|---|---|---|---|---|
| 3090×1 | 0.060 | 0.047 | 0.0012 | 0.108 | 72 | **0.00167** |
| 3090×2 | 0.121 | 0.095 | 0.0024 | 0.218 | 67 | 0.00362 |
| 3090×4 | 0.242 | 0.189 | 0.0048 | 0.436 | 61 | 0.00794 |
| 4090×1 | 0.067 | 0.061 | 0.0013 | 0.129 | 82 | 0.00175 |
| L40S | 0.333 | 0.047 | 0.0067 | 0.387 | 87 | 0.00494 |
| A100 40G | 0.250 | 0.034 | 0.0050 | 0.289 | 158 | 0.00203 |
| A100 80G | 0.417 | 0.041 | 0.0083 | 0.466 | 205 | 0.00253 |

排序：**3090×1 (0.00167) < 4090×1 (0.00175) < A100 40G (0.00203) < A100 80G < 3090×2 < L40S < 3090×4**。

结论只有一句话：**单卡 3090 赢，而且赢得不多**（比 4090 便宜 5%，比 A100 40G 便宜 18%）。多卡全部出局——不是因为慢，是因为「每小时烧的钱」按卡数线性涨，而「每小时做完的任务数」不但不涨还可能跌。

## 5. 黑盒声明

1. **rho_pre 可缓存前缀占比**（题面唯一的量留白）：区间 **[0.5, 0.95]**。影响 T_pre，在 3090 档只影响总时间 ±4%；在 A100 档影响 ±9%。测法：抓 30 条真实任务日志算前缀长度分布，半天。
2. **v_dec 在 64K 深度的真值**：本 run 用折减系数 0.55（区间 **0.30–0.85**）。这是全表最敏感的一个数：折减取 0.30 时 3090 的 T_dec 涨到 83 s，C_task 涨到 0.0027，会被 A100 40G 反超。测法：`llama-bench -p 65536 -n 128` 单流，1 小时。
3. **p 通过率**：题面只说「不是 100%」。区间 [0.5, 0.95]。跑 100 任务，1 天。
4. **AFR 年化故障率**：见矛盾 3，区间 [1.5%, 9%]。它只占 Σ 的 1–2%，**即使取上界也不改变排序**——本 run 把它降级为「不敏感支」，不投调研时间。
5. **利用率系数**（卡没满载时实际墙功率 / TDP）：区间 **[0.6, 1.0]**。影响 power_h 至 ±40%，测法：插座功率计 10 min。

## 6. 矛盾清单

**矛盾 1 · 同一台卡的生成速度：22.8 t/s vs 4.03 t/s（5.6 倍）**
- 源 A：sanj.dev 调优记录浅上下文 22.8 t/s（4096 批优化后）。
- 源 B：同一篇文章，95K 上下文 4.03 t/s。
- 同一个量（这台机器的生成速度）在两个上下文深度上差 5.6 倍，**属题面定义的「同一个量上明显不一致」**，原样记录。
- **更可信：源 B 对本题**。理由：题面固定 64K，落在深上下文区；用 22.8 等于假设 KV 显存读取免费。
- 后果：若按源 A，3090×1 的 C_task 会算成 0.00088，与 A100 的差距从 1.2 倍拉到 2.3 倍——**排序不变但结论强度变**。

**矛盾 2 · 3090 的残值：三年归零 vs 二手价仍达发售价 97%**
- 源 A：openclawdc 2026-09，eBay 291 条挂牌中位 **$1,450**，为 2020 年发售价 $1,499 的 **97%**。
- 源 B：Fluence 2026 年文章称二手 **$800–1,000**，并说已稳定在 $800–1,300；按此三年残值折半以上。
- **更可信：源 A**（有样本量、有日期、有 90 天区间 $1,244–1,502）。源 B 无取数日期。
- 后果：**这一条改变 capex_h 的口径**。若残值取 50%（源 A 隐含的「卡几乎不贬值」推不出 3 年 50%，只能推出「过去 3 年只贬 3%」），capex_h 从 1450/24000 降到 725/24000 = $0.030/h，**电费支占比从 44% 涨到 61%**——反而加强本 run 的「电费是大头」结论。反之若残值按 0 计（源 B 口径下更保守），capex_h 就是上表的数。本 run 取残值 0 作为保守上界，并在结论里注明：**真按二手行情算，电费支会超过折旧支，3090 型的性价比还会更好**。

**矛盾 3 · 年化故障率：1.5–2.5% vs 9%**
- 源 A：clusterbid 汇总，H100 数据中心卡 1.5–2.5%/yr（正常负载），HBM 占故障 60%。
- 源 B：Meta Llama-3 405B 训练集群反推 **≈9%/yr**，三年累计 ≈27%。
- **更可信：源 A 对本场景**。理由：源 B 是满负载训练集群（MFU 38%、持续满载），本题是推理，功率与热循环都轻得多；且源 B 的数字是「由训练中断事件反推」，方法学上是上界。
- 后果：fail_h 在 Σ 里只占 1–2%，两种取值下 C_task 差 <1.5%，**不改变任何排序**。这是一个「查得到真矛盾但发现它不重要」的例子，如实记下。

**未判为矛盾**：电价（商业 13.51 vs 工业 8.66 ¢/kWh 是两种客户类型，不是同一个量的两个矛盾值，属口径选择）、A100 二手价（$4–9k 区间各源重叠）。

## 7. 瓶颈判定

**瓶颈 = 电费支（power_h）**，而不是买卡的钱。

- 幅值证据：在 4 卡及以上配置里，电费占（折旧+电费）的 44%–67%；V100×8 档电费是折旧的 **2.0 倍**。
- 结构证据：capex_h 一次谈定、三年不变；power_h 跟着卡数、负载、电价走，**且它对「堆卡换显存」这个最自然的策略收税**——每多一张卡，power_h 线性上涨，而产能（N_per_h）不涨反跌（3090×1 72 → ×4 61）。
- 反例检查：如果把这题换成「每天只跑 1 小时」，capex_h 摊到任务上会暴涨、power_h 占比会掉，瓶颈立刻回到买卡钱。**所以瓶颈是「这台机器要长时间开着跑」这个前提的函数**——本 run 的判断只在 24×7 连续负载假设下成立，这个前提必须写进结论。
- 落到行动：优先测**实际墙功率**（插座功率计，10 分钟，成本最低、收益最大），而不是先纠结二手卡价。

## 8. 自检

- **完整**：一次性 + 经常性 + 或有 + 重做，四类钱互斥且穷尽（自建、无云租金、无运维人力——运维人力按题面「本地跑」判为不在范围内，若有需单列一支，见下）。产能支与钱支相乘还原 C_task。份额 0.42+0.43+0.05+0.10 = 1.00。✓
- **不重叠**：四类钱各占各的账。**已知耦合**：P_buy 同时进 capex_h 和 fail_h（坏一张卡要按购价赔），本 run 在两处都用了它，未重复计金额但共享同一变量——若卡价变动 40%，两条支同向动，合计影响比我分开报的 0.42+0.05 略大。**已知遗漏**：运维人力/机位/网络未建支，题面没提，我判断属「本地自用」范围外；若实际要雇人运维，这一支可能直接压过电费。
- **未做**：rho_pre、v_dec(64K)、p、墙功率四项实测。其中 v_dec 是唯一能翻排序的（黑盒 2）。
