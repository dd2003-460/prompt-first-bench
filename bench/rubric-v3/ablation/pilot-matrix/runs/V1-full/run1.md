## 0. 根节点

**C = 每验收通过任务的成本（美元/任务）**

```
C = c_hour / (3600/T × S × p)
c_hour = capex/H + P_kW × elec        H = 26,280 h（3 年连续）
S      = min( ⌊(VRAM−W−1)/KV₆₄ₖ⌋ , ⌊单流 tok/s ÷ 20⌋ )
T      = 3500/prefill_tps + 500/单流tok/s
```

题面未定、由本 run 声明：前缀命中 60.5K / 新输入 3.5K / 输出 0.5K；W(Q4_K_M)=17.1 GB；KV(q8_0 @64K)=2.0 GB/流；电价 = 東京電力 従量電灯B 第 3 档 40.49 円/kWh ÷ 150 = 0.270 USD/kWh；p=0.90。

### 1.6 非默认候选的三问（D1 规则 3，逐条必答）

**c1 · Mac Studio M3 Ultra**
- ① **生态成熟度**：MLX + llama.cpp 原生、Metal 后端成熟；但 CUDA-only 的 kernel（Marlin/AWQ、FlashInfer、TensorRT-LLM）全部不可用，vLLM 需走 CPU/Metal 分支，**吞吐显著低于同带宽 CUDA 卡**。成熟度定为「可用但弱」。
- ② **经济状况**：$3,999 买 96 GB + 819 GB/s + 270 W，是本表**每 GB 显存最便宜**的方案之一（$41.7/GB）；但该型号 2026-08-25 停产，现货被抬到 $14,000+，采购风险是全表最高。
- ③ **实测瓶颈**：不是带宽而是 **prefill**——统一内存的 prompt processing 历来是弱项（同代 Mac 在 8K 长提示上出现「首 token 前等十几分钟」的实测），本题 3.5K 新输入会直接吃掉单任务耗时的大头。

**c2 · DGX Spark (GB10)**
- ① **生态**：原生 CUDA 13 + DGX OS，生态**最好**的一档；但 GB10 的内存带宽决定了它只能跑「能装得下但跑不快」的模型。
- ② **经济**：$4,699 表价、$6,950 现货（2026-10 涨 48%），单位带宽成本 $25.5/(GB/s) —— 是 3090（$1.66）的 **15 倍**。
- ③ **实测瓶颈**：**硬约束直接不合格**。273 GB/s ÷ 17.1 GB = 16.0 tok/s 的 roofline 上限，实测 27B dense 级模型在同类机器上只有 9.7–14 t/s，**低于 20 tok/s/流**。

**c3 · AMD Strix Halo (Ryzen AI Max+ 395)**
- ① **生态**：ROCm + Vulkan + llama.cpp 可用；社区 toolbox（kyuz0）已相当活跃，但 kernel 覆盖率低于 CUDA，MoE 类模型有专门优化、dense 没有。
- ② **经济**：$3,449–3,799 买 128 GB，是**每 GB 最便宜**的统一内存机；功耗 120–140 W，电费全表最低。
- ③ **实测瓶颈**：实测 dense Qwen3.6-27B **Q8 只有 6.5 tok/s**（openclawdc 2026-09 引社区基准），Q4 下按 roofline 也不过 215/17.1 = 12.6 t/s——**同为硬约束不合格**，而它在 MoE（gpt-oss 120B 52–57 t/s）上很快，说明**这台机器的强项与本题的模型形态不匹配**。

**d1 · Tenstorrent Blackhole p150**
- ① **生态**：编译器栈（TT-Metalium/TT-NN）开源可改，但**模型覆盖率极低**，27B dense 的现成支持需自行移植；且非 CUDA，团队学习成本高。
- ② **经济**：$1,399 买 32 GB + 512 GB/s，纸面 $/GB 极优；但 Galaxy 整机 $110,000 起、无云市场可比价，**总拥有成本无法用市场价交叉验证**。
- ③ **实测瓶颈**：**信息边界**——公开渠道没有任何 27B dense @64K 的实测吞吐；按其 512 GB/s 与典型加速卡效率估算单流 ≈ 10–20 t/s，落在硬约束边界的灰区。**无法证实，即不能作为推荐**。

**d2 · 云 GPU 按小时租**
- ① **生态**：完全成熟（就是同一批 CUDA 卡）。
- ② **经济**：$0.22–0.50/h，无 capex；按本题负载折算每任务成本可能低于自建（尤其利用率低时）。
- ③ **实测瓶颈**：**违反题面的前提**——题面要求「在本地跑」。它作为**成本基准线（benchmark）**仍有价值：自建方案若贵于租用，说明买断在这条负载上不划算。本 run 用它做对照而非候选。

## 4. 瓶颈

**BOTTLENECK: N-2.2 并发流数 S（具体是 N-2.2.2 速度闸在 24/32 GB 卡上的取值 = 1）**

打分：N-2.2 = 0.55×0.70×3.0 = **1.16**；N-1.1 = 0.34×0.62×4.4 = 0.93；N-2.1 = 0.55×0.30×3.7 = 0.61；N-1.2 = 0.34×0.28×5.2 = 0.50。

理由（三条，按重要性）：

1. **在 24–32 GB 这一档，S 被硬约束锁死在 1，于是「卡快不快」只影响 T，不影响 S；而 S 是唯一能成倍放大产能的因子。** 1×3090（34 t/s）与 1×5090（26.2 t/s）的 S 都是 1，$/任务因此只差一点（1.11m vs 1.97m，差的部分主要来自 5090 更高的 capex 与更高的功耗，而不是速度）。
2. **一旦 S 从 1 抬到 2–3（2×3090 / A100 / RTX PRO 6000），$/任务立刻掉一个台阶**（1.11m → 0.65m → 0.33m）。这条台阶比任何单卡内部的差距都大：**A100 的单流只比 3090 快 1.9×，但因为显存能撑 3 条流，$/任务快 3.3×**。
3. **反例校验**：L40S 带宽 864 GB/s（比 3090 低 8%）、显存 48 GB（能撑 14 条流），但单流只有 ~29 t/s，速度闸把它锁在 S=1——**48 GB 的显存在这里完全没用上**，于是它比 A6000 贵 2.3× 却慢 10%。这说明瓶颈不是「显存」，也不是「带宽」，而是**两者的乘积**：只有「带宽够撑出多条 20 t/s 的流」且「显存能同时装下这些流的 KV」时，钱才花得值。

**瓶颈的下一层**：S 的两个闸门里，本题画像下**速度闸先于显存闸触发**（24 GB 卡：显存闸 2、速度闸 1）。原因很朴素——20 tok/s 这条硬约束，对着 17.1 GB 的权重，等价于要求「有效带宽 ≥ 342 GB/s 且每多一条流就要多一份」；而 24 GB 卡本来就只有 6.9 GB 剩给 KV，2 条流都已经很勉强。

## 7. 矛盾清单（D2：每条声明边界类型）

**X1 · RTX 3090 街价：$1,550 vs $1,804(eBay 中位) vs $1,264(8 月均价)**
- 源 A：specpicks（2026-09）引 Hardware Corner **$1,550 street**。

## 9. 交付

- **最优：1×A100 80GB（二手 $5,000–6,500），0.370×10⁻³ $/验收任务**；次优 2×3090（0.717m）、RTX PRO 6000（0.870m）。
- **D1 四分区搜索的真实收益不是找到更好的候选，而是排除了三个「看起来更好」的候选**：DGX Spark 与 Strix Halo 的带宽 roofline 上限（16.0 / 12.6 t/s）低于 20 tok/s 硬约束，**这是非默认分区才暴露出来的失效模式**；Tenstorrent 则是不可判定。
- **D2 边界类型的真实收益**：13 条 OPEN/矛盾里，7 条是信息边界（可测/可查，一天内能消掉），2 条是实操边界（要花钱或现场才能定），2 条是理论边界（不等式，永远消不掉）。**这直接决定了「下一步该干什么」——先去消信息边界，别去争理论边界**。
- **该先测的三件事**：①并发阶梯（决定 S，是唯一能翻转排序的量）；②η（决定每张卡的真实单流）；③p（决定要不要为返工多留预算）。
- **一句话**：这道题的答案不是「哪张卡最贵/最便宜」，而是「哪套配置能同时满足『带宽撑得出 ≥2 条 20 tok/s 的流』和『显存在装下 17.1 GB 权重后还放得下这些流的 KV』」——A100 80G 是唯一在 $6,500 内同时满足两者的单卡。
