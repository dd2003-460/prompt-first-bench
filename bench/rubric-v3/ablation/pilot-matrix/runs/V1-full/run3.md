## 0. 根节点

**C = 每验收通过任务的成本（美元/任务）**

```
C = (capex/H + P_kW×elec) / (3600/T × S × p)
S = min( ⌊(VRAM−17.1−1)/2.0⌋ , ⌊单流 tok/s ÷ 20⌋ )
T = 3500/prefill_tps + 500/单流tok/s
```

本 run 声明：前缀 60.5K / 新 3.5K / 出 0.5K；W=17.1 GB；KV(q8_0@64K)=2.0 GB/流；电价 0.270 USD/kWh（東京第 3 档）；p=0.90；H=26,280 h。

**先给出本 run 的核心恒等式**（后面全部结论由它推出）：

> **S = ⌊单流 tok/s ÷ 20⌋**，所以每提升一档 S，单流速度必须跨过一个整数门槛：
> **S=1 需 ≥20 · S=2 需 ≥40 · S=3 需 ≥60 · S=4 需 ≥80 · S=5 需 ≥100（tok/s）**
> 而 C 与 S 成反比。**这道题的本质是：花多少钱能让单流速度跨过第 40 / 第 60 个 tok/s。**

注意这里不是「总吞吐」而是「单流」——因为硬约束是**每流** ≥20 tok/s。批处理确实能提高总吞吐，但**它不能让单流更快**；在连续批处理下，单流速度会随并发上升而下降，所以 S 的上限由「单流在并发下能否维持 20」决定，最宽松的估计就是上面的整除关系。

## 1. D1 · 候选集四分区（按「容量从哪来」切）

### 1.1 分区推导

画像里对硬件的三条要求是：装得下（17.1 GB + 2 GB×S）、每条流 ≥20 tok/s、单位任务成本最低。前两条是**两个独立的物理资源**（容量 vs 带宽），而且**它们不能互相兑换**——显存再大也换不来 tok/s，带宽再高也装不下模型。于是分区沿这两个轴切：

| 分区 | 容量来源 | 带宽水平 | 默认先验？ |

## 4. 瓶颈

**BOTTLENECK: N-2.2.2 速度闸（S 的整数阶梯）**

打分：N-2.2 = 0.60×0.78×3.0 = **1.40**；N-1.1 = 0.30×0.66×12.9 = 2.55——**资本摊销的裸分更高**，但它的 12.9× 里有一半来自「2×Mac $10,300」这个**已经被速度闸判死的候选**；把不合格者剔除后 capex 区间收到 $800–6,500（BOUND 8.1），乘积 1.60，与 1.40 接近。而 N-2.2 的 BOUND 是**结构性**的：它由一条硬约束直接生成，且不可用钱绕过。

三条论据：

1. **显存闸在本候选集里几乎全部闲置**：统一内存机的显存闸是 38–118 条流，但速度闸只给 1 条。**买的容量 97% 用不上**——这是本题画像下最普遍的浪费。
2. **速度闸是离散的，C 对它是台阶函数**：单流从 19.8 提到 20.0（+1%），S 从 0 变 1（∞ 倍）；从 39 提到 40（+2.5%），S 从 1 变 2（成本 −50%）。**在这个结构里，边际收益最大的不是买更快的卡，而是"刚好跨过门槛"**——Mac M5 Max 差 0.2 tok/s 出局，就是这条规律的极端案例。
3. **它同时解释了「多节点为什么不行」**：2×Mac 把容量翻倍到 256 GB（显存闸 118），但互联只有 7 GB/s，单流上不去，S 依然 =1，而 capex 翻倍。**容量可以通过互联池化，带宽不能** ——这是本 run 最重要的一条判据。

**X3 · 2× Mac Studio 的互联吞吐：TB5 标称 120 Gb/s vs 实测 50–60 Gb/s**
- 源 A：computingforgeeks（2026-10）「Jeff Geerling 实测 TB5 约 50–60 Gb/s，RDMA 把延迟从 300 µs 压到 <50 µs」。
- 源 B：同文引 Apple 规格「Thunderbolt 5，最高 120 Gb/s」。
- **更可信**：B 是理论值，A 是实测。**采信 A**（7 GB/s 有效），据此判定 2×Mac 的 S 无法突破 1。
- **边界类型：① 数学/理论边界** —— 层切分 TP 下每 token 都要跨节点 all-reduce，`单流 tok/s ≤ 2×互联带宽 ÷ 每token跨节点字节`；7 GB/s ÷ (17.1 GB/2) ≈ 0.8 次/秒 → 即使完全流水，单流也被互联卡在几十 tok/s 量级。**到此为止因为 Amdahl 式互联上限**，加钱买线也解决不了（TB5 没有交换机）。

**X4 · 统一内存的 27B 性能：厂宣「能跑 128 GB 模型」 vs 实测「dense 27B Q8 6.5 t/s」**
- 源 A：AMD/Intel 侧宣传与 MoE 基准（gpt-oss 120B 34–57 t/s）。
- 源 B：openclawdc（2026-09）引 kyuz0 社区基准：dense Qwen3.6-27B Q8 **6.5 t/s**；本 run 的 roofline 计算 12.6（Q4）/7.4（Q8）。
- **更可信**：B 与 roofline 自洽（6.5 vs 7.4 上限，效率 88%）。**采信 B**。
- **边界类型：① 数学/理论边界** —— `tok/s ≤ 带宽 ÷ 每 token 读量`，Strix Halo 215÷17.1=12.6、Spark 273÷17.1=16.0。**不等式不可突破**，所以这两台在本题上不是「待优化」而是「不可行」。

**X5 · Intel Arc Pro B70 能否跑 27B@64K：厂商/评测说「能」 vs 社区实测只有 16.0 t/s（B60）**
- 源 A：edagher92 arc-llm-lab（2026-10）B60 量化实测 **16.0 tok/s（无 drafter）**、42.3（带 DFlash2 草稿模型）；B70 32 GB/608 GB/s 无实测。
- 源 B：bentech（2026-04）单 B70 跑 Qwen3.5-27B UD-Q5 在 150k 上下文只有 **~12 tok/s**；双 B70+B60 约 10。
- **更可信**：两者都是实测，且方向一致（Arc 在长上下文下慢）。**采信 B 的 12 t/s 做悲观、A 的 roofline 20.5 做乐观**；因为 12 < 20，Arc B70 应判**不合格**，本 run 表中给的是乐观值（20.5），已在脚注标明。
- **边界类型：③ 信息边界** —— 缺 B70 的 27B@64K 同口径实测；`research_required: 借 B70 跑 llama.cpp Vulkan @64K；路径 = 社区 arc-llm-lab`。

**OPEN 清单**
- O1「统一内存机能不能靠批处理提升单流」→ **① 数学边界**：批处理提升**总吞吐**，但**单流速度只会下降不会上升**（每个 decode step 要处理 S 倍的 KV）。**到此为止因为批处理的方向性**——它救不了单流门槛，只能救产能。
- O2「把 KV 压到 q4 能不能让 S 翻倍」→ **① 数学边界**：它只放大**显存闸**（2.0→1.1 GB/流），而本候选集里显存闸本来就不是瓶颈（38–118 vs 速度闸 1–3）。**到此为止因为瓶颈不在那一侧**。
- O3「多买一台能不能翻倍」→ **② 实操边界**：容量能翻倍、带宽不能（TB5/200GbE 都比板载慢 1–2 个数量级）。到此为止因为需要 Z = 更换互联技术（NVLink 交换机起步价数万美元）。

## 9. 交付

- **最优：1×A100 80GB（二手），0.370×10⁻³ $/验收任务**；次优 2×3090（0.717m）、RTX PRO 6000（0.874m）。
- **本 run 的核心结论是一条判据，而不是一个型号**：**S = ⌊单流 tok/s ÷ 20⌋，每上一档要跨 20/40/60/80/100 这道整数门槛，而成本与 S 成反比。** 所以决策问题从「哪张卡便宜」变成「花多少钱能跨过第 40 或第 60 个 tok/s」。
- **D1 按容量来源分区的收益**：它证明了**容量与带宽不可互换**——8 个非默认候选里 5 个出局，全部因为「装得下但跑不进门槛」；而唯一挤进前三的非默认候选（2×3090）恰恰不是统一内存，而是**两块便宜卡用 PCIe 拼带宽**。
- **反直觉三条**：①多节点方案全表最贵（用 2× 的钱买 1× 的 S）；②Mac M5 Max 差 0.2 tok/s 直接出局；③$1,100 的 Arc B70 与 $2,000 的 3090 打平（但实测可能不合格）。
- **该先测的三件事**：①各机 27B@64K 的实测单流（决定 S 档，是唯一能翻转排序的量）；②Mac M5 Ultra 能否到 40 t/s（+3.6% 就能腰斩成本）；③Arc B70 在 64K 下的真实速度。
- **一句话**：这道题的答案不在「谁的显存大」，而在「谁的**单流**能跨过 40 / 60 这两个整数门槛」——A100 用 1,935 GB/s 跨过了 60，2×3090 用两块便宜卡拼过了 40，而所有统一内存机（200–600 GB/s）都停在 20 与 40 之间出不来。
