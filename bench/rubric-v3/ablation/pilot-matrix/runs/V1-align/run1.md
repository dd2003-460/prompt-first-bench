## 0. 根节点

**C = 每完成一个「验收通过」任务的成本（USD/任务）**

题面画像里有一句话决定了整棵树的形状：**「上下文里有一段长期不变的前缀，可以被缓存」**。这句话在成本上同时是**收入**（省掉 60.5K token 的 prefill）和**支出**（那 60.5K 的 KV 必须常驻在某处，且每个 decode step 都要读一遍）。本 run 就沿这条线切。

**统一口径（本文全部数值由此推出）**

| 量 | 取值 | 来源/推导 |
|---|---|---|
| 权重 W（27B，Q4_K_M） | 17.1 GiB | compute-market 2026-09：Q4_K_M 16.8 GB |
| KV 每 token（fp8/q8_0） | **80 KB** | 区间 68–128 KB：compute-market「64K≈5 GB」偏低、知乎实测 263,408 tok/17 GB ≈ 68 KB、架构算 128 KB/token；取 80 KB 为中值 |
| 64K 总 KV | **5.0 GiB** | 80 KB × 65,536 |
| 其中**前缀** KV（60.5K，常驻） | **4.72 GiB** | 80 KB × 60,500 |
| 其中**每流增量** KV（3.5K） | **0.27 GiB** | 80 KB × 3,500 |
| CUDA graph/激活开销 | 1.5 GiB | vLLM `gpu-memory-utilization 0.90` 后的固定损耗 |
| 电价 | 0.270 USD/kWh | 東京 40.49 円/kWh |
| H | 26,280 h（3 年） | — |

```
C = (capex/H + P_kW × 0.270) / (3600/T × S × p)
S = min( ⌊(VRAM − 17.1 − 4.72 − 1.5) / 0.27⌋ ,  ⌊单流tok/s ÷ 20⌋ )
T = 3500/prefill_tps + 500/单流tok/s        （前缀命中，prefill 只算 3.5K 新输入）
p = 0.90
```

**由这张表直接得到第一个结论**：前缀缓存不是免费的，它**永久占掉 4.72 GiB**。24 GB 卡（3090/4090/B60）扣掉权重 17.1 + 前缀 4.72 + 开销 1.5，只剩 **0.7 GiB** ——够 2 条流的增量 KV，但**刚好卡在「装得下」和「装不下」的边界上**。这条边界是本次分区的主轴。

## 1. D1 · 候选集四分区

### 1.1 分区推导依据

题面里唯一可被「放在哪」的东西就是那 4.72 GiB 的常驻前缀 KV。它每一个 decode step 都要被完整读一遍（attention 要看完 60.5K 个历史 token），所以**它的存储层级 = 它的带宽上限**。按「前缀 KV 常驻在哪一级存储」切，四个分区天然互斥且穷尽：

| 分区 | 前缀 KV 常驻位置 | 读它走什么总线 | 有效带宽量级 |
|---|---|---|---|
| **a 全显存** | 单卡 VRAM | 板载 GDDR/HBM | 700–3,000 GB/s |
| **b 显存+主机内存分层** | 一部分在 DDR5 | PCIe 4.0 x16 | **25 GB/s** |
| **c 统一内存** | 与 CPU 同一物理内存池（无 PCIe 边界） | LPDDR5X 直连 | 200–1,200 GB/s |
| **d 跨卡/跨机池化** | 分摊在 2 张以上卡的 VRAM | NVLink / PCIe / 以太网 | 30–900 GB/s |

**互斥性检查**：同一台机器不会同时属于 a 和 b（b 的定义就是「显存装不下前缀，必须溢到 DDR5」）；c 没有 PCIe 边界，不是 b；d 是 2 张以上卡，不是 a。**穷尽性检查**：任何一台能跑 27B 的机器，其前缀 KV 只能落在「板载显存 / 主机内存 / 统一池 / 多卡分摊」四者之一。✅

与常见的「按卡型枚举」（消费卡/专业卡/整机）相比，这一刀的好处是：**它把「同一张卡换个主板就变成另一个分区」这件事显式化了**——3090 单卡在 a，3090 + 128 GB DDR5 走卸载就在 b，两张 3090 就在 d，三种形态成本差 3 倍以上。

## 3. 硬约束筛选

只有一条硬约束：**每流 ≥20 tok/s**。但它在 b 组身上有一个**隐藏的第二重含义**：

> **前缀 KV 若不在显存，每生成 1 个 token 都要把 4.72 GiB 从主机内存搬一遍。**
> PCIe 4.0 x16 实测 25 GB/s → 4.72/25 = 0.19 s/token → **5.3 tok/s 上限**。

这与 grigio（2026-09）在统一内存机上关掉 KV offload 方向相反的实测互为印证：他把 KV 留在 CPU 内存，prefill 掉到 133 t/s（vs 691）、gen 掉到 **2.85 t/s**（vs 32.7）——"catastrophic"。**PCIe/内存总线带宽就是 b 组的天花板。**

## 5. 瓶颈

**BOTTLENECK: N-2.2.2「速度闸」——单流 20 tok/s 这条线把 S 锁在 1–3，而 S 直接乘在分母上。**

打分：N-2.2 = 0.55×0.76×3.0 = **1.25**；N-1.1 = 0.35×0.62×12.6 = **2.73**（裸分更高，靠的是 $10,065 的 PRO 6000 这一个极端点；剔除它后 capex 区间收窄到 $800–6,500，BOUND 8.1，乘积 1.76）。两者接近，所以用**三条结构论据**定夺：

1. **显存闸在本候选集里几乎全被速度闸压住**：M5 Ultra 和 M5 Max 的显存闸分别是 269 和 387 条，速度闸给 1 条。**买的容量 99.6% 用不上**。反过来，没有任何一台机器是「速度够但显存不够」——说明显存那一侧根本不是约束。
2. **前缀缓存把显存闸往前推了一格，但没有改变谁赢**：4.72 GiB 的常驻前缀让 24 GB 卡从「余 6.2 GiB」变成「余 0.7 GiB」，这确实把 3090/4090 从「2–3 条流」压到「2 条流」；但它们的速度闸本来就是 1。**所以缓存的经济价值不在显存侧，全部在 prefill 侧**：60.5K 的 prefill 从 79 s 降到 1.3 s（A100 口径），T 降 6 倍。
3. **它同时解释了 b 组为什么注定失败**：b 组把「显存不够」的解法指向主机内存，可前缀 KV 每 token 要被读一遍 → 25 GB/s 的 PCIe 除以 4.72 GiB = **5.3 tok/s**。**容量可以溢出到主机内存，带宽不能** ——这是本 run 最硬的一条判据。

**瓶颈的下一层**：速度闸的分子是「单流 tok/s」，它在本画像下约等于 `板载带宽 ÷ (W + 前缀KV) = BW ÷ 22.1 GiB`。所以真正决定 S 的是**板载带宽除以 22 GiB 这个比值**：A100 = 87、5090 = 81、2×5090 = 145、M5U = 54、Spark = 12.4。**要跨过 20 需要 442 GB/s、跨过 40 需要 884 GB/s、跨过 60 需要 1,326 GB/s。** 这三条线把候选集切得比任何价格表都干净。

**四条要点**

1. **冠军 A100（0.370m）只比 2×5090 快 16%**，而 2×5090 的 capex 还低 20%。**这两个方案在同一档（S=3），差距全在 $/h 上**（0.396 vs 0.495）。
2. **5090 单卡跃到第 4（0.512m）** 是本 run 最大的意外：它在 V0 类口径（按名义带宽估 26 t/s）里排倒数，但按 **64K 深度实测 45.4 t/s** 就跨过了第 40 个 token，S 从 1 变 2，成本直接腰斩。**「单流在 64K 深度下的实测值」是唯一能翻转排序的参数**。
3. **b 组的 4090 与 3090 打平（1.172 vs 1.175m）**：4090 快 13% 但贵 50%，两者互相抵消。**这一组的天花板是 PCIe，不是卡型。**
4. **c 组全军覆没在速度闸**（1.92–2.92m），尽管它们的显存闸有 269–387 条。**统一内存机在本画像下的问题不是「装不下」，而是「每 token 要多读 4.72 GiB」**——前缀缓存对它们反而是**负资产**：缓存越大，每 step 读得越多。

## 8. 矛盾清单

**X1 · RTX 5090 在 64K 深度下的单流：45.4 t/s vs 26.2 t/s**
- 源 A：知乎实测（2026-03），Qwen3.5-27B Q6_K 22 GB、64K、q8_0 KV → prefill 2,689、gen **45.4**。
- 源 B：contextstudios（2026-09）同模型 64K → prefill 718、gen **26.2**。
- **更可信**：A。它同时给出 prefill 2,689（与 1,792 GB/s 的配置自洽）并做了上下文倍增崩溃测试（32K 51.0 → 64K 45.4 的衰减曲线合理）；B 的 prefill 718 与 5090 的算力严重不符，疑为 PCIe 或量化设置异常。**采信 A（45.4），并把 B 放进敏感性**。
- **边界类型：③ 信息边界** — `research_required: 同一台 5090 上用同一 GGUF、同一 KV 类型跑 llama-bench tg @64K；路径 = 借机或找社区复现`。

**X2 · 27B 的 KV 每 token 到底多大：68 KB vs 80 KB vs 128 KB**
- 源 A：知乎实测（2026-05）「17 GB KV 容量 = 263,408 tokens」→ **68 KB/token**（fp8）。
- 源 B：架构算式 `2 × 64 层 × 4 KV头 × 256 维 × 1 B = 131,072 B` → **128 KB/token**。
- 源 C：compute-market（2026-09）「Q4 + 64K KV ≈ 22 GB」→ 反推 **80 KB/token**。
- **更可信**：C 作为中值最稳（它同时被 A 和 B 夹住）；A 与 B 差 2 倍说明 A 测的很可能是 2 个 KV 头或 32 层的变体。**本 run 取 80 KB，两条边界进敏感性**。
- **边界类型：① 数学/理论边界** —— 该量完全由 `层数 × KV头数 × 头维 × 字节宽` 决定，可精确算出；争议只在于「哪个 27B 变体」。**到此为止因为它是架构常数，不需要实测**（需要的是确认用户跑的是哪个变体）。

**X3 · 双 3090 的 TP 增益：+50% 还是「在噪声内」**
- 源 A：openclawdc（2026-08）「715 tok/s（NVLink）vs 483（无）」→ **+48%**。
- 源 B：bestllmfor（2026-05）「NVLink 对 TP=2 只有 **4.1%** 提升，在热噪声内」。
- **更可信**：A 的 48% 是在 **vLLM TP=2 + 高并发**下测的（all-reduce 进关键路径），B 的 4.1% 是在 Llama 3.3 70B 特定配置下。两者不冲突：**并发越高、NVLink 越重要**。本 run 用 A 的口径（TP 增益 1.47×）算单流，B 的口径会让 2×3090 降到 0.95m。
- **边界类型：③ 信息边界** — `research_required: 27B dense @64K 在 2×3090 上的 TP2 单流；路径 = 自测 vLLM --tensor-parallel-size 2`。

**X4 · Arc Pro B60 能不能靠投机解码救回来：16.0 vs 42.3 t/s**
- 源 A：edagher92（2026-10）「16.0 tok/s 无 drafter，42.3 tok/s 带 DFlash2」。
- 源 B：bentech（2026-04）单 B70 跑 27B 在 150K 上下文 **~12 t/s**。
- **更可信**：两者都实测、方向一致（基础带宽决定下限）。**采信「不带 drafter 不合格」**；42.3 是 eval-suite 的墙钟吞吐（含 prefill），不等于单流 decode，不能直接当 S 的门槛值。
- **边界类型：③ 信息边界** — `research_required: B60 在 64K 下带 drafter 的单流 decode；路径 = arc-llm-lab 的 bench-history`。

**X5 · Mac Studio M5 Max 的带宽：460 vs 614 GB/s**
- 源 A：vdf.ai（2026-09）「460 GB/s（40 核 GPU 为 614）」。
- 源 B：presenc（2026-10）同一说法——**不构成独立验证**。
- **更可信**：无法判定，两者同源。取 460（保守），结论不变（S=1，2.92m）。
- **边界类型：③ 信息边界** — `research_required: 40 核 M5 Max @64K 实测；路径 = 借机或 MLX 社区基准`。

**OPEN**
- **O1「把前缀 KV 放到 NVMe 上，靠大页预读」** → **① 数学/理论边界**：NVMe 顺序读 7 GB/s ÷ 4.72 GiB = **1.4 次/秒**，比 PCIe 还差一个数量级。到此为止因为 `decode 必须每 step 读完整前缀` 这一必要条件。
- **O2「用更小的模型让前缀变小」** → **② 实操边界**：换模型 = 换任务质量，p 会变，不在硬件选型范围内。到此为止因为你没有 27B 等价的更小替代（Z = 质量评估）。
- **O3「多机通过 RDMA 共享同一份前缀 KV」** → **② 实操边界**：200 GbE = 25 GB/s，与 PCIe 同级，仍卡在 5.3 t/s。到此为止因为需要 400 Gb/s 以上互联（Z = InfiniBand 交换机，>$10k）。
- **O4「能不能用 GQA 改造模型把 KV 压 8 倍」** → **② 实操边界**：需要重训，不属于选型。到此为止因为 Z = 训练算力。

## 10. 交付

- **最优：1×A100 80GB 二手，$0.370×10⁻³/验收任务**。次优 2×5090 TP2（0.430m）、RTX PRO 6000（0.494m）、单卡 5090（0.512m）。
- **本 run 的核心判据**：**前缀 KV 常驻的存储层级决定一切**。它每 decode 一步要被完整读一遍，所以「4.72 GiB ÷ 该层带宽」就是单流上限：全显存 21–135 t/s、统一内存 10–54、**主机内存 5.3、NVMe 1.4**。**容量可以溢出，带宽不能**。
- **前缀缓存是双刃剑**：它把 T 里的 prefill 从 ~79 s 砍到 ~1.3 s（省 6 倍），同时吃掉 4.72 GiB 显存——**24 GB 卡因此从「余 6.2 GiB」掉到「余 0.7 GiB」，正好卡在装得下的边上**。这条边界是本题最容易被忽略的一处。
- **三个反直觉**：① 单卡 5090（$2,999）排到第 4，只因它在 64K 深度实测 45.4 t/s 跨过了第 40 个 token；② 两台 5090 的 $/任务（0.430m）只比 A100 贵 16%，而 capex 便宜 20%；③ 统一内存机显存闸 269–387 条却全部输——**它们每 token 要多读 4.72 GiB，前缀缓存对它们是负资产**。
- **该先测的三件事**：① 每台机器 64K 深度的单流（唯一能翻转排序的量）；② 27B 变体的 KV/token（68 还是 128 KB，决定 24 GB 卡是否出局）；③ 前缀命中率是否真能到 100%。
- **一句话**：这道题真正在问的不是「哪个卡便宜」，而是「**那 4.72 GiB 常驻前缀放在哪一级存储**」——放显存就赢，放主机内存就只剩 5 t/s，放统一内存则被自己的带宽锁死在 S=1。
