## 0. 根节点

**C = 每完成一个「验收通过」任务的成本（USD/任务）**

题面画像里有三个硬事实同时成立：**64K 上下文固定**、**每流 ≥20 tok/s**、**通过率 <100% 要重做**。第一条件直接决定了「一台机器能同时挂几个会话」，第二条件决定了「这些会话能不能真的跑满」。本 run 就沿这两个数的**较小者**切。

### 0.1 一个会话要占多少显存（本 run 的标尺）

| 项 | 值 | 依据 |
|---|---|---|
| 权重 W（27B Q4_K_M） | 17.1 GiB | compute-market / whatllmcanirun 一致（16.8–17.1 GB） |
| 单会话 64K KV（fp8） | **5.0 GiB** | 80 KB/token × 65,536；被 `4060 Ti 16G 跑 27B 需 Q3` 与 `24GB = 64K 刚好` 两处独立证据夹住 |
| CUDA graph/激活 | 1.5 GiB | 固定开销 |
| **一个完整会话的底盘** | **23.6 GiB** | 17.1+5.0+1.5 |

**这个 23.6 GiB 是全表最重要的一个数**：它意味着 **16 GB 卡（4060 Ti / T4）连一个完整 64K 会话都挂不起来**——不是慢，是装不下。而 24 GB 卡只有 **1 个**会话位。

### 0.2 成本式

```
槽位 slots = ⌊(VRAM − 17.1 − 1.5) / 5.0⌋
S = min( slots , ⌊单流tok/s ÷ 20⌋ )          ← 容量闸与速度闸取小
T = 3500/prefill_tps + 500/单流tok/s           ← 前缀命中，只 prefill 3.5K
C = (capex/26280 + P_kW × 0.270) / (3600/T × S × 0.90)
```

**由 S = min(槽位, 速度) 立刻得一条件**：**买超过「速度所能喂饱」的槽位是纯浪费**。这句话是本 run 的评判标准，最后一条结论（M5 Ultra 256GB 比 96GB 贵 45% 却做同样多的事）就是它的直接推论。

## 5. 瓶颈

**BOTTLENECK: N-1.1.2「过供系数」与 N-2.2.2「速度闸」的乘积——具体说，是 `S = min(槽位, 速度)` 里的那个 min 让「槽位」在 15 个候选里只对 2 个生效。**

打分：N-2.2 = 0.48×0.79×3.0 = **1.14**；N-1.1 = 0.42×0.58×61.5 = **14.98**。裸分上 N-1.1 压倒性——但它 61.5× 的 BOUND 来自 $260 到 $16,000 这个价格区间，其中**一半的价差买的是槽位，而槽位有 13/15 个候选完全用不上**（过供系数 1.0–23.5）。把过供剔掉后，capex 的有效区间收窄到 $1,399–6,500（BOUND 4.6），乘积 1.12，与 1.14 打平。

所以定它做瓶颈，用三条结构论据：

1. **过供是本画像里最大的隐性成本**：M5 Ultra 256GB 比 96GB 贵 45%，性能一模一样（同芯片同 48 t/s），多出的 32 个槽位全死。A100 12 槽用 3 个（过供 4×）、PRO 6000 15 槽用 3 个（5×）、A6000 5 槽用 1 个（5×）。**只有 5090 是 2 槽配 2 条速度，唯一不付过供税的机器。**
2. **速度闸决定了「值多少槽」**：因为 S = min(槽, 速度)，任何超过 ⌊单流/20⌋ 的槽位价值为零。而 ⌊单流/20⌋ 在天花板 3（A100/2×5090）和 2（5090/M5U）之间，**所以一台机器的合理槽位永远是 1–3 个**，任何 5 槽以上的机器都在为用不上的容量付费。这条判据把 d 组整个排除掉了（21–47 槽）。
3. **它解释了两种「不合格」为什么不同**：a 组是槽位 0（容量不够），P40/Spark 是速度 0（带宽不够）。**同一个 S=0 可以由两个完全相反的极端造成**——这正是 min 结构的特性，也是本 run 最值得记住的一点。

**瓶颈的下一层**：速度闸的分子 = `板载带宽 ÷ 22.1 GiB`。跨 20 需 442 GB/s、跨 40 需 884 GB/s、跨 60 需 1,326 GB/s。而槽位 = `(VRAM−18.6)/5`。**两条线在 32 GB/1,792 GB/s 附近第一次相交——那正好是 RTX 5090。**这是本 run 最重要的一条几何观察：5090 不是「最快的卡」，而是**唯一一台两条约束线刚好相切的机器**。

3. **M5 Ultra 256GB 是本 run 最贵的一课**：145% 的 capex 换来 0% 的产能（1.121m vs 0.773m，+45% 成本）。**它证明「过供税」是可以直接量化的：$4,000 ÷ 原来 0.773m 的产能 = 每个死槽位 $125。**
4. **P40 的 $9.96/GB 完全没用**：$260 买到 24 GB，却因为 13 t/s 的 27B 吞吐连 20 的门槛都过不去。**这是「$/GB 是伪指标」最干净的反例**——它能装下模型，但装不下吞吐。

**X1 · RTX PRO 6000 的价格：$8,565 / $13,250 / $16,000 / $19,999**

- 源 B：wccftech（2026-07-02）「$13,250，比上月涨 30%」；B&H（页面未标日期）「**$19,999.99** OEM 现货」。
- **更可信**：A（igorslab 给了三级价格与验证链接）。B 的 $19,999 是渠道现货加价，不是官方价。**本 run 采信 $16,000**（当前官方价），$13,250 进敏感性。
- **边界类型：② 实操边界** —— 到此为止因为需要**采购时点的官方报价单**（Z = 企业采购渠道/框架协议），公开渠道只能给到区间。

**X2 · Mac Studio M5 Ultra 在 27B 上的速度：48 t/s（实测）vs 我的 roofline 54 t/s vs M3U 的 28.8 t/s**
- 源 A：presenc（2026-10）引 MacStories 独立评测「dense 27B **48 t/s**」。
- 源 B：terminalbytes（2026-09）「M3 Ultra 跑 Qwen3.8 27B 28.8 t/s」——上一代，不是矛盾源，是基线。
- **更可信**：A。但**关键未知是上下文深度**：MacStories 的 48 t/s 大概率是短上下文，本任务要 64K。按 1.2 TB/s ÷ 22.1 GiB 的 roofline 是 54，48 已经是 89% 效率，**64K 深度下实际会更低**（每 token 多读 5 GiB）。本 run 采信 48 并做 -25% 敏感性（→36 t/s，成本 0.971m）。
- **边界类型：③ 信息边界** — `research_required: M5 Ultra 96GB 在 64K 深度下 27B Q4 的 tg；路径 = 本机 llama-bench -d 60000 或 MLX 社区基准`。

**X3 · 双 5090 的 TP2 单流：70 t/s（折算）vs 单卡 45.4**
- 源 A：知乎 8×5090 压测（2026-05）：单实例 2,500 tok/s 聚合、KV 96%。
- 源 B：同上文章的双卡篇（2026-05）「双卡显存解决 32GB 不足，吞吐提升 40–50%，首 token 延迟增加 20–30%」→ 单流提升 ~1.5×，与 70/45.4 = 1.54 吻合。
- **更可信**：两者互证，取 1.54×。但 TP2 的收益要付 20–30% 的 TTFT 代价，本 run 用 S（终端速度）而非 TTFT 判断，所以不扣。
- **边界类型：① 数学/理论边界** —— TP 的加速比被 AllReduce 限制在 `1/(1/n + ε)`，n=2 时上限 2×；实测 1.54× 是 77% 效率。**到此为止因为 Amdahl**。

**X4 · Tesla P40 的 27B 吞吐：13 t/s（本 run 推算）vs 26 t/s（gpudojo 估计）**
- 源 A：gpudojo（2026-09）「Estimated: Generation ~26 tokens/sec, Prefill ~214 tokens/sec」——注意它标的是 **Estimated**，且未说明模型规模。
- 源 B：specpicks（2026-10）「llama.cpp CUDA 榜单，Llama 2 **7B** Q4_0：P40 54.74 t/s，3090 158.16 t/s」——**7B**。
- **更可信**：A 的 26 与 B 的 54.7 都是「小模型」口径。按 3090 的 27B/7B 衰减比（34.0/158 = 0.215）反推，P40 在 27B 上约 54.7×0.215 = **11.8**，与 3090 同模型的 34 之比为 0.35。**本 run 取 13**，并承认这是推算而非实测（已标 B2）。
- **边界类型：③ 信息边界** — `research_required: P40 单卡 27B Q4 @64K 实测；路径 = 借卡跑 llama-bench`。

**X5 · 16 GB 卡到底能不能跑 27B：whatllmcanirun 说「能，20 t/s」vs openclawdc 说「只能 IQ3」**
- 源 A：whatllmcanirun（2026-10）「gemma 3 27b Q4_K_M 14.7 GB，20 tok/s，fit=Ok」。
- 源 B：openclawdc（2026-08）「27B 只能压到 IQ3_XS（~11 GB），12–18 t/s」。

- **边界类型：① 数学/理论边界** —— 16 − 17.1 < 0，权重本身就超了；A 的 14.7 GB 是 Q4 下界。**到此为止因为算术**。

| B4 | 前缀命中率 | N-2.1 | 0.7–1.0 | 读 vLLM `prefix_cache_hit_rate` |
| B5 | M5 Ultra 的 64K 折扣 | c3/d1 | 0.6–1.0 | MLX 跑 64K 深度 tg |
| B6 | 过供的**机会成本**（多出的槽位能否换成钱） | N-1.1.2 | 0–30% | 若机器兼做别的任务，槽位可复用——需记录日均利用率 |

**OPEN**
- **O1「能不能靠多开槽位把 5090 的 2 槽变成更多？」** → **① 数学/理论边界**：槽位 = ⌊(32−18.6)/5⌋ = 2，要 3 槽需 33.6 GiB，**差 1.6 GiB**。到此为止因为 `(VRAM−18.6)/5` 的整数下取整。
- **O2「把 KV 压到 q4_0 能不能让 5090 上到 4 槽？」** → **① 数学/理论边界**：q4_0 KV 减半 → 2.5 GiB/会话 → 5 槽；但速度闸仍是 2。**到此为止因为 S = min(槽, 速度)，槽位不再是约束**。
- **O3「a 组能不能靠 CPU 卸载硬跑 64K？」** → **② 实操边界**：CPU 卸载后每 token 要跨 PCIe 搬 KV，实测掉到个位数（同族的 `--no-kv-offload` 实测 2.85 t/s）。到此为止因为需要 Z = 更快的互联（CXL/NVLink-C2C），消费主板没有。
- **O4「M5 Ultra 256GB 的 4 万槽位能不能出租摊销？」** → **② 实操边界**：需要多租户隔离与 SLA（Z = 运营体系），不属于单机选型。到此为止因为超出本题范围。

## 10. 交付

- **最优：1×A100 80GB 二手，$0.370×10⁻³/验收任务**。次优 2×5090 TP2（0.430m）、单卡 5090（0.512m）。
- **本 run 的判据**：**`S = min(槽位, ⌊单流/20⌋)`，而槽位 = `(VRAM−18.6)/5`**。一台机器合理的槽位永远只有 1–3 个，因为速度闸天花板就是 3。**任何 5 槽以上的机器都在为用不上的容量付费**（过供 4–23.5×）。
- **过供税是可量化的**：M5 Ultra 从 96 GB 升到 256 GB 多花 $4,000，产能不变，成本从 0.773m 涨到 1.121m（+45%）。**在本画像下，为槽位付钱是本表最贵的错误，比买错品牌贵得多。**
- **两种「不合格」要分开看**：4060 Ti/T4 是**容量不够**（0 槽，权重就装不下），P40/B60/Spark/Strix 是**带宽不够**（跑不进 20 t/s）。前者无解只能换卡，后者理论上可以靠 drafter 或多卡救（但成本会毁掉优势）。
- **唯一「恰好匹配」的机器是 RTX 5090**：32 GB 给 2 槽，45.4 t/s 给 2 条流，过供 1.0×。它排第三不是因为快，而是因为**没有一寸浪费**。
- **该先测的三件事**：① 各机 64K 深度单流（决定速度闸）；② 27B 变体的 KV/token（决定槽位）；③ M5 Ultra 在 64K 下的真实衰减（决定它 0.773m 还是 0.971m）。
- **一句话**：这道题的两个约束一个管「装几个」一个管「跑多快」，**成本由两者中更小的那个决定**——所以最划算的机器不是容量最大的，也不是最快的，而是**容量刚好等于速度**的那一台（5090），除非你愿意为 3 条流付 A100 的钱。
