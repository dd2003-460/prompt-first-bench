## 0. 先把「根」钉死

根节点：**每验收任务成本 C（日元/任务）**——这一轮我把计价单位改成**日元**（机器在东京、电价按日元结算），避免美元汇率再叠一层不确定性。换算是最后一步才做的。

```
C = c_hour / (N_task/h × p)

c_hour  = capex/H + P_kW × elec          （持有成本：摊销 + 电）
N_task/h = 3600/T × S                     （每小时尝试任务数）
T        = prefill_新输入 + decode_输出
S        = min( ⌊η·BW/(20·W)⌋ , ⌊(VRAM−W)/KV₆₄ₖ⌋ )   ← 两个闸门取小
```

四件题面没给、必须自己声明的：

- **A1 前缀可缓存比**：64K 中 60.5K 命中（可跳过），3.5K 新输入，0.5K 输出。若命中比下降，只是 prefill 项变大（§5 敏感性）。
- **A2 精度**：Q4_K_M 为主口径（17.1 GB）；Q8_0（29 GB）做对照。
- **A3 摊销**：3 年连续 = 26,280 h。若只是「上班时段用」，资本项按实际占机小时摊，见 §5。
- **A4 电价**：40.49 円/kWh（東京電力 従量電灯B 第 3 档，含税）。**不换算成美元**，全程日元。

## 2. 瓶颈

**BOTTLENECK: N-2.2.1 带宽闸（η·BW / 20·W）**

Armdahl 打分：N-1.1 资本 0.55×0.72×4.4 = **1.74**；N-2.2 0.45×0.70×3.0 = **0.95**。

按裸数字资本摊销赢，但我要说明**为什么最终仍判带宽闸**——这次的理由和「A100 很贵」无关，是结构性的：

1. **资本摊销的 BOUND 4.4× 几乎全部由「L40S $8k vs 3090 $1.3k」这一个离群点贡献**。而 L40S 之所以贵还留在表里，只因为我一开始把它当「48 GB 数据卡」纳入——它在本题里并不占优（§3 里它最贵）。把 L40S 剔掉后，capex 区间收到 $1,300–3,999，BOUND 掉到 3.1×，乘积 1.23，与 0.95 已在一个量级。
2. 更重要的是**方向性**：capex 是买的时候一次定的，买了就沉没；带宽闸则是**这条硬约束（≥20 tok/s/流）在每台机器上的实际投影**，它决定「一台机器同时能跑几条流」，而 S 是分母里唯一的整数跳变。C 对 capex 是线性连续敏感（±30% → ±20%），对 S 是台阶敏感（3→1 → 2.4×）。**在一个几乎全是线性的成本式里，唯一非线性的因子就是瓶颈。**
3. 实测支持这个判断：A6000 有 48 GB（显存闸能放 7 流）、只比 2×3090 贵 $700，但它的 768 GB/s 只能撑出 26.9 t/s → **S=1**，$/验收任务 2.089m vs 2×3090 的 1.063m。**同一档显存、同一档价钱，S 差 3，成本差 2×**。钱不是瓶颈，带宽折出来的并发数才是。

瓶颈往下再指一层：**η 有效率**（0.25–0.62 的黑盒）比 BW 本身更决定结果——5090 的 η 只有 0.25（1792 GB/s 只跑出 26.2 t/s），Mac 的 η 约 0.55。所以瓶颈的瓶颈是「这块卡的软件栈能不能把带宽吃满」，而不是「这块卡的带宽标称多少」。

（$ 列由 円 按 150 折算；m = 10⁻³ USD）

**排序**：2×3090 (1.06m) < 1×3090 (1.18m) < Mac M3U (1.89m) < A6000 (2.09m) < 5090 (2.19m) < L40S (3.21m)。

三条值得写下来的观察：

1. **48 GB 这个门槛没有兑现成优势**。A6000 与 L40S 都有 48 GB（显存闸 7 流），但带宽闸把 S 压在 1，多出来的显存完全用不上——**买显存不等于买吞吐**。只有当显存与带宽同时放大（2×3090：48 GB + 1872 GB/s）时才真的有收益。
2. **Mac Studio 输在 prefill，不是输在 decode**。它 819 GB/s 统一内存、96 GB 容量、270 W 功耗（电费只有 3090 方案的 1/3），单看 c_hour 是全场最低的 $0.225/h。但它 64K 下的 prefill 只有 ~450 t/s，3.5K 新输入要 7.8 s，占 T 的 29%；而它能撑出的并发只有 1 流。**统一内存机在「长前缀可缓存 + 短输出」的画像下被 prefill 拖死**——这恰好是本题画像。
3. **1×3090 与 2×3090 只差 11%**，而 2×3090 的成本是 1.7×。这说明在 p=0.90、Q4 口径下，**单卡已经接近这个任务画像的经济最优**；继续加卡的边际收益迅速掉到 0（因为 S 从 3 再往上，T 的 prefill 项开始主导，而 prefill 不随并发变快）。

## 6. 矛盾清单

**X1 · RTX 3090 二手价 $1,201–1,299 vs $1,699–1,996（差 50%）**
- 源 A：runaihome（2026-08-31 发布，引 GPUDojo 8 月追踪）「$1,201–1,299（均价 $1,264）」；openclawdc（2026-08）「$1,000–1,300」。
- 源 B：（同站在 2026-09 的后续文章里给出的）eBay 均价 $1,463；另有抓取页给中位 $1,804。
- **采信 A 的 $1,300**：A 组带方法说明（ResalePrices eBay-US 在售 + gpudojo + bestvaluegpu 三处交叉），B 组是「asking price 中位」而非成交价。这条我把 $1,804 也算了进去——它会翻掉单卡 vs Mac 的排序（见 §5），所以不能只留一个数。

**X2 · 64K 单流的 KV cache：4.0 GB（按 config 算）vs 5.8 GB（按实测峰值反推）（差 45%）**
- 源 A：qdna（2026-09）与 computefit（2026-08）都按官方 config 算：`2 × 4 heads × 256 dim × 16 层 × 2 bytes = 64 KiB/token` → 64K **4.0 GB**；n1n（2026-08）给的表 32K=2.0 GB、128K=8.0 GB 与之自洽。
- 源 B：syntalith（2026-09）实测「Q5_K_M/Q8 缓存、65,536 ctx 时峰值 22,287 MiB」，扣掉 16.5 GB 权重与运行时开销，**反推 KV ≈ 5.8 GB**。
- **判为「都对，口径不同」并采信 A 的 4.0 GB 做主口径**：B 是 Q8_0 KV + 测的是峰值（含临时 buffer/碎片），A 是 FP16 KV 的确定值。差异不影响结论（§5 中把 5.8 代回去，S 不变）。这条写在这里是为了不让后来者以为「实测比计算更可靠」——在 KV 上实测含太多运行时噪声。

**X3 · L40S 二手 $7,000–9,000（按 48 GB 数据卡卖），而 A6000 48 GB 只要 $2,600–3,800（同容量、带宽只差 11%）**
- 源 A：pcserverandparts（2026-09）L40S used $7,000–9,000，理由是「数据中心许可 + 最佳 $/token」。
- 源 B：runaihome（2026-08）A6000 48 GB $2,600–3,800。
- **采信两源数字，但不采信 L40S 的「最佳 $/token」定位**：那是**云端租用**场景（$0.55–1.66/h，与购买无关）。买断场景下 L40S 用 2.5× 的钱只换到 12% 的带宽，是本表最差选择。这是一处典型的「租用经济学被误移植到买断决策」的来源冲突。

**X4 · Mac Studio M3 Ultra 价格 $3,999 起 vs $14,000+**
- 源 A：bestllmfor（2026-08）「$3,999–9,499（96 GB–512 GB）」，谈的是配置起价。
- 源 B：myminingrig（2026-09）「512 GB 现货被抬到 $14,000+」，openclawdc（2026-09）「8-25 停产，二手封条件 $9,500 起」。
- **采信 A 的 $3,999**（96 GB 档，本题只需 96 GB），并把停产风险单列：若只能买到被抬价的现货，Mac 的 capex 变 2.5×，$/验收任务从 1.89m 涨到 4.4m，彻底出局。**这不是价格矛盾，是「型号生命周期」矛盾**——买一台已停产机器做 3 年摊销，本身就是本表最脆的假设。

## 8. 交付结论

在 Q4_K_M、64K（3.5K 新输入 / 0.5K 输出）、≥20 tok/s/流 的画像下，代价最低的是 **2×RTX 3090，约 1.06×10⁻³ 美元/验收任务**（1×3090 紧随其后 1.18×10⁻³）。48 GB 档的 A6000 与 L40S 因为带宽撑不出第 2 条流，买到的显存全部闲置；Mac Studio 虽然电费只有别人的三分之一、容量 96 GB，却输在 prefill 与单流吞吐上。

**精度不是调优变量而是门槛**：Q8 会让几乎所有配置跌破 20 tok/s/流，因此在本题里 Q4 是可行域的一部分，而不是「省钱妥协」。

**最该先测的三件事**：①每张卡 64K 下的 η 有效率（瓶颈的瓶颈）；②真实的 p（它决定要不要再买第二张卡，因 1×3090 与 2×3090 只差 11%）；③Mac 的 prefill（若 >900 t/s，Mac 会从 1.89m 掉到 1.35m，压过单卡 3090）。
