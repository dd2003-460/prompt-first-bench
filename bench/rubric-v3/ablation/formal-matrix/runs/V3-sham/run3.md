## 0. 根节点与本 run 的切法

**C = 每完成一个验收通过任务的成本 [USD/任务]**

**本 run 切「钱的时间结构」**：前几轮的公式里，`H`（摊销年限）被当成一个常数 26,280 h（3 年 × 24/7）写死。但题面没说要用三年。

**而 H 是一个能被用户单方面决定的参数**——它不改硬件、不改价格、不改带宽，**只把钱摊到不同的时间跨度上**。所以本 run 要做的是：

1. 把 `H` 当变量扫（1 年 / 3 年 / 5 年）；
2. 加进**残值**（设备卖掉能收回多少）——这是 `H` 的另一半，前几轮完全没算；
3. 看这两个量能不能改变答案。

```
c_hour(H, r) = capex × (1 − r) ÷ H + P_kW × 0.270
C = c_hour ÷ (3600 ÷ T × S × p)
```

W=17.1 GB；KV 64K=5.0 GiB；开销 1.5 GiB；p=0.90；电价 0.270 USD/kWh（東京 40.49 円÷150）。

## 2. 分解树

```
C 每验收任务成本 [$/任务]                          SHARE 1.00  BOUND 6.6x
├── A c_hour(H, r) [$/h]                         SHARE 0.41  BOUND 2.8x
│   ├── A1 **capex × (1−r) ÷ H**（本 run 的主轴）   SHARE 0.62  BOUND 6.6x
│   │   ├── A1a capex                             leaf 可查
│   │   ├── A1b **H（摊销年限）**                    **1–5 年，用户可选**
│   │   └── A1c **r（残值率）**                      **0.45–0.70，按品类分化**
│   └── A2 电费 P_kW × 0.270                      SHARE 0.38  BOUND 3.0x（0.30–0.675 kW）
├── B task/h                                     SHARE 0.49  BOUND 7.9x（135–1,066）
│   ├── B1 T [s]                                 SHARE 0.17  BOUND 2.4x
│   └── B2 S = min(容量闸, 速度闸)                 SHARE 0.83  BOUND 3.0x
└── C p = 0.90                                   SHARE 0.10  BOUND 1.18x
```

份额：0.41+0.49+0.10 = 1.00 ✅；A1 0.62+A2 0.38 = 1.00 ✅；B1 0.17+B2 0.83 = 1.00 ✅。

**A1b 与 A1c 是同一支的两个旋钮**：`H` 拉长 → 单位时间资本成本下降；`r` 抬高 → 同样效果。**两者都会「让贵卡变便宜」，但对便宜卡几乎无感**——因为便宜卡的 capex 本来就小，摊得再薄也省不了多少。

## 4. 瓶颈

**BOTTLENECK: A1「capex × (1−r) ÷ H」——但不是因为它的区间宽，而是因为它是全树唯一「用户单方面能改、且能改 3 倍」的支。**

打分（H=3、r=0）：A1 = 0.41 × 0.62 × 6.6 = **1.68**；B2 = 0.49 × 0.83 × 3.0 = **1.22**；A2 = 0.41 × 0.38 × 3.0 = 0.47。

**「可操作性」这个维度让 A1 从「最大」变成「最该先动手」**：

| 支 | 区间 | **用户能否单方面改变** | 改造成本 |
|---|---|---|---|
| A1b（H） | 1–5 年（**5 倍**） | **能** | $0 |
| A1c（r） | 0.45–0.70（1.6 倍） | **能**（选品类、选买入时机） | $0 |
| A1a（capex） | $1,750–9,465（5.4 倍） | 能（换卡） | 换硬件 |
| A2（电费） | 0.30–0.675 kW（2.3 倍） | 能（限功耗） | $0 |
| B2（S） | 0–3（4 倍） | **不能** | **只能换硬件** |

**三条论据**：

1. **H 与 r 合起来能把 A100 的 $/任务从 0.403m 压到 0.218m（−46%），一分钱硬件都不用改。** 而 B2 想从 3 提到 4，需要带宽翻倍到 >2,760 GB/s——**市面上除了 SXM5 的 H100（3,350）没有**。
2. **H 与 r 的作用是「乘性」的，且对每个候选的系数不同**：A100 的 `(1−r)/H` 从 0.333 降到 0.100（3.3 倍），3090 从 0.333 降到 0.167（2.0 倍）——**因为 A100 的残值率更高。** 所以**这两个旋钮不是「一视同仁地降本」，而是「更偏向保值资产」**。
3. **它解释了二手市场的一个反常现象**：RTX 3090 的二手价在 2026 年 3–10 月**是涨的**（gpuresource 报「Price Trend → Stable (memory premium)」；gpudojo 报中位 $1,804）。**当一个资产的残值率被抬高时，它的持有成本就下降——这才是「买旧卡划算」的真正机制，而不是「旧卡便宜」。**

**瓶颈的下一层**：**H 不是物理量，是会计约定。** 题面没给 H，也没给 r，**这意味着本 run 的答案对「你打算用几年」高度敏感，而这件事比硬件选择更靠前**。**在 H=1 年下，3090 与 A100 的差距只有 11%——一台 $1,750 的机器与一台 $7,400 的机器几乎打平。而在 H=5 年下，差距是 3.2 倍。**

**X1 · GPU 的寿命是 1–3 年还是 6–9 年**

**X2 · 残值率能不能直接套到「二手买入价」上**

- **采信：对二手买入的 A100，r 取 0.55（保守），而不是 0.70。** 此时 A100 是 0.312m，**仍是第一**。

**X3 · 「买旧卡划算」的机制是什么**

- **怎么终止**：3090 在本题排第 4，**残值再高也进不了前三**（S=1 是硬约束）。**停止。**

## 8. 交付

- **最优：1×A100 80GB**——H=3 年时 0.403m，H=1 年时 0.932m，H=5 年时 0.298m，加 50% 残值后 0.271m。
- **本 run 的判据**：**`H` 与 `r` 是用户单方面能改的两个旋钮，合起来能把成本压 46%，一分钱硬件都不改。**
- **最重要的一条**：**在 H=1 年下，$1,750 的 3090（1.911m）与 $7,400 的 A100（0.932m）差距只有 2.05 倍；而在 H=5 年下差距是 3.22 倍。** 换句话说——**「你打算用几年」这个问题，比「买哪张卡」更能决定你的单位成本。**
- **最反直觉的一条**：**残值率与摊销年限在数学上等价**（`(1−r)/H`）。**「三年后卖掉收回一半」= 「只摊 1.5 年」。** 所以「买保值的东西」与「用得久一点」是同一个优化。
- **最实用的一条**：**买二手卡会让 `r` 的计算基准错位**——厂商品类的「3 年残值 70%」是按**原价**算的，而你按**二手价**买入时，剩下的折旧空间已经小得多。**把 0.70 直接套到二手买入价上，会高估 25% 的残值收益。** 本 run 对 A100 用 0.55 作为保守值。
- **第二实用**：**「买旧卡划算」的真正机制不是「旧卡便宜」，而是「旧卡的残值率被 24 GB 显存溢价托住」**（gpuresource：「Price Trend → Stable (memory premium)」）。**当一件资产的残值率高时，它的持有成本就低——这才是二手策略的会计本质。**
- **该先测（或先定）的两件事**：①**你打算用几年**（H）；②**三年后这东西还能卖多少**（r）。**这两个参数对答案的影响，大于绝大多数硬件参数的差别。**
