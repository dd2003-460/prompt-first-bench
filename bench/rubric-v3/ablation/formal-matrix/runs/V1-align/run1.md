## 0. 根节点与口径

**C = 每完成一个验收通过任务的成本（USD/任务）**

题面里有一句话决定了整棵树：**「上下文里有一段长期不变的前缀，可以被缓存」**。它在成本上同时是**收入**（省掉 60.5K token 的 prefill）和**支出**（这 60.5K 的 KV 必须常驻某处，且每个 decode step 都要被完整读一遍）。本 run 就沿着「**前缀 KV 常驻在哪一级存储**」去切。

```
C = (capex/H + P_kW × 0.270) / (3600/T × S × p)
S = min( ⌊(VRAM − 17.1 − 4.72 − 1.5) / 0.27⌋ , ⌊decode ÷ 20⌋ )
T = 3500/prefill + 500/decode      （前缀命中，只 prefill 3.5K 新输入）
```

口径：W=17.1 GB；前缀 KV（60.5K）= **4.72 GiB**；每流增量 KV（3.5K）= 0.27 GiB；KV 密度 80 KB/token（区间 68–128）；开销 1.5 GiB；H=26,280 h；p=0.90；电价 0.270 USD/kWh。

## 1. D1 · 候选集四分区

### 1.1 分区推导

题面唯一「有位置属性」的东西就是那 4.72 GiB 的常驻前缀 KV——它每一个 decode step 都要被完整读一遍，**所以它的存储层级 = 它的带宽上限 = 单流上限**。按「前缀 KV 常驻在哪一级存储」切，四个分区互斥且穷尽：

| 分区 | 前缀 KV 常驻位置 | 读它走什么总线 | 有效带宽量级 | 候选数 |
|---|---|---|---|---|
| **a 全显存** | 单卡 VRAM | GDDR6X/GDDR7/HBM | 768–1,935 GB/s | 5 |
| **b 显存+主机内存分层** | 部分在 DDR5 | PCIe 4.0 x16 | **25 GB/s** | 2 |
| **c 统一内存** | 与 CPU 同一物理池（无 PCIe 边界） | LPDDR5X 直连 | 215–1,200 GB/s | 4 |
| **d 跨卡/跨机池化** | 分摊在 ≥2 张卡 | NVLink / PCIe / 以太网 | 30–1,872 GB/s | 2 |

**互斥性**：同一台机器不会既属 a 又属 b（b 的定义就是「显存装不下前缀、必须溢到 DDR5」）；c 没有 PCIe 边界，不是 b；d 是 ≥2 张卡，不是 a。
**穷尽性**：任何能跑 27B 的本地机器，其前缀 KV 只能落在「板载显存 / 主机内存 / 统一池 / 多卡分摊」四者之一。✅

与「按卡型枚举」相比，这一刀的好处是：**它把「同一张卡换个配置就变成另一个分区」显式化了**——3090 单卡在 a，3090+128 GB DDR5 走卸载就在 b，两张 3090 就在 d，三种形态成本差 3 倍以上。

② $2,600，比 3090 贵 49%。

## 3. 瓶颈

**BOTTLENECK: N-2.2.2「速度闸」——单流 20 tok/s 这条线把 S 锁在 0–3，而 S 直接乘在分母上。**

打分：N-2.2 = 0.55 × 0.81 × 3.0 = **1.34**；N-1.1 = 0.35 × 0.70 × 4.7 = **1.15**。

三条结构论据：

1. **显存闸在本候选集里几乎全被速度闸压住**：M5 Max 的显存闸是 475 条流，速度闸给 1；M5 Ultra 是 269 对 1。**买的容量 99% 用不上**。反过来，没有任何一台机器是「速度够但显存不够」——除了 b 组，而 b 组的问题恰恰是 PCIe 带宽。
2. **前缀缓存把显存闸往前推了一格，但没有改变谁赢**：4.72 GiB 的常驻前缀让 24 GB 卡从「余 5.4 GiB」变成「余 0.68 GiB」，把 3090/4090 从「2–3 条流」压到「2 条流」；但它们的速度闸本来就是 1。**所以缓存的经济价值不在显存侧，全在 prefill 侧**：60.5K 的 prefill 从 79 s 降到 1.4 s。
3. **它同时解释了 b 组为什么注定失败**：b 组把「显存不够」的解法指向主机内存，可前缀 KV 每 token 要被读一遍 → 25 GB/s ÷ 4.72 GiB = **5.3 tok/s**。**容量可以溢出到主机内存，带宽不能。**

**瓶颈的下一层**：速度闸的分子 = `板载带宽 ÷ 22.1 GiB`。跨 20 需 442 GB/s、跨 40 需 884 GB/s、跨 60 需 1,326 GB/s。这三条线把候选集切得比任何价格表都干净。

## 6. 矛盾清单（每条声明边界类型）

**X1 · 前缀 KV 的每 token 体积：68 KB vs 80 KB vs 128 KB**
- 源 A：知乎实测（2026-05）「17 GB KV 容量 = 263,408 tokens」→ **68 KB/token**（fp8）。
- 源 B：架构算式 `2 × 64 层 × 4 KV 头 × 256 维 × 1 B = 131,072 B` → **128 KB/token**。
- 源 C：compute-market（2026-09）「Q4 + 64K KV ≈ 22 GB」→ 反推 **80 KB/token**。
- **更可信：C 作为中值**（被 A 和 B 夹住）；A 与 B 差 2 倍，说明 A 测的很可能是 2 个 KV 头或 32 层的变体。**本 run 取 80 KB**，两条边界进敏感性。
- **边界类型：① 数学/理论边界** —— 该量 = 层数 × KV 头数 × 头维 × 字节宽，可精确算出；争议只在「哪个变体」。到此为止因为它是架构常数，不需要实测。

**X2 · KV offload 的代价：可用 vs 灾难**
- 源 A：buildmvpfast（2026-03-26）「vLLM supports CPU offloading natively ... The latency hit is real but manageable」。
- 源 B：localaimaster（2026-05-02）排障表「CPU offload very slow | Cause: PCIe bottleneck | Fix: Disable; use FP8 KV instead」。
- **更可信：B 对本画像**。A 的「manageable」是短上下文/高吞吐场景；本题是 64K 常驻前缀，每 step 都要读完整 4.72 GiB，**PCIe 25 GB/s 直接给出 5.3 t/s 的硬上限**。两者不冲突：A 说的是「偶尔换页」，B 说的是「常驻在主机」。
- **边界类型：① 数学/理论边界** —— `tok/s ≤ PCIe 带宽 ÷ 每 token 读量` = 25 ÷ 4.72 = 5.3。到此为止因为 decode 必须每 step 读完整前缀。

**X3 · 2× 3090 的 TP 增益：+50% 还是「在噪声内」**
- 源 A：openclawdc（2026-08-21）「715 tok/s with NVLink vs 483 without」→ +48%。
- 源 B：insiderllm（2026-09-24）「Two GPUs don't give you twice the speed — twice the VRAM」，70B Q4 单请求 ~21 tok/s。
- **更可信：A 对增益值、B 对「单流 vs 总吞吐」的区分**。两者不冲突：并发越高、NVLink 越重要。**本 run 用 1.47×** 算单流；若按 B 的「无增益」，2×3090 会掉到 0.95m（仍是第 3）。
- **边界类型：③ 信息边界** —— `research_required: 27B dense @64K 在 2×3090 上的 TP2 单流；路径 = vLLM --tensor-parallel-size 2 打 1 并发`。

**X4 · Mac M5 Max 的带宽：460 vs 614 GB/s**
- 源 A：vdf.ai（2026-09）「460 GB/s（40 核 GPU 为 614）」；openclawdc（2026-09-21）「M5 Max up to 614 GB/s」。
- 源 B：promptquorum（2026-09-25）「M5 Ultra 1.2 TB/s」，未拆 Max 的核数档。
- **更可信：A 拆了核数**（32 核 460 / 40 核 614）。**取 460 保守**；两种取值都不改变结论（S=1，2.78–2.92m）。
- **边界类型：③ 信息边界** —— `research_required: 40 核 M5 Max 的 27B@64K 实测；路径 = 借机实测或 MLX 社区基准`。

**X5 · 24 GB 卡「够不够装 64K」**
- 源 A：openclawdc（2026-09）「24 GB 够跑 Qwen3.8-27B 到 64k 上下文」。
- 源 B：本 run 的算式：24 − 17.1 − 4.72 − 1.5 = **0.68 GiB** 余量，只够 2 条流的增量 KV（0.27×2 = 0.54）。
- **两者不冲突但含义相反**：A 说「装得下 1 个会话」，B 说「装得下 1 个会话、装不下 3 个」。**本题要的是并发，不是单会话。**
- **边界类型：① 数学/理论边界** —— 到此为止因为算术（0.68 GiB 的余量是确定的）。

## 8. 交付

- **最优：1×A100 80GB（$7,400 含平台），0.402×10⁻³ $/验收任务**；次优 A100 40GB（0.453m）、2×3090 TP2（0.727m）。
- **本 run 的核心判据**：**前缀 KV 常驻的存储层级决定一切**。它每 decode 一步要被完整读一遍，所以「4.72 GiB ÷ 该层带宽」就是单流上限：全显存 21–87 t/s、统一内存 10–54、**主机内存 5.3、NVMe 1.5**。容量可以溢出，带宽不能。
- **前缀缓存是双刃剑**：它把 T 里的 prefill 从 ~79 s 砍到 ~1.4 s（省 56 倍），同时吃掉 4.72 GiB 显存——**24 GB 卡因此从「余 5.4 GiB」掉到「余 0.68 GiB」，正好卡在装得下的边上**。
- **三个反直觉**：①b 组（3090 + 128 GB DDR5）比单卡贵 14%，却慢 6 倍；②最便宜的统一内存机（Strix Halo $3,999）与最贵的（M5U $5,499）同为 S=1，成本差 2.1 倍；③多卡唯一的价值是把带宽叠起来，不是把容量叠起来。
- **该先测的三件事**：①每台机器 64K 深度的单流（唯一能翻转排序的量）；②27B 变体的 KV/token（68 还是 128 KB，决定 24 GB 卡是否出局）；③前缀命中率是否真能到 100%。
- **一句话**：这道题真正在问的不是「哪个卡便宜」，而是「**那 4.72 GiB 常驻前缀放在哪一级存储**」——放显存就赢，放主机内存只剩 5 t/s，放统一内存则被自己的带宽锁死在 S=1。
