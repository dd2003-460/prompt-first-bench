## 0. 根节点与口径

**C = 每完成一个验收通过任务的成本（USD/任务）**

题面的硬约束「每流 ≥20 tok/s」在 27B@64K 上等价于一条带宽门槛：每 token 要读 ~18.6 GiB（17.1 权重 + 5.0 KV），所以 **20 t/s 需要 372 GB/s 的有效带宽**（按 80% 实现效率 → 465 GB/s 的标称带宽）。这一条把候选按**显存介质**天然分层——这是本 run 的切法。

```
C = (capex/H + P_kW×0.270) / (3600/T × S × p)
S = min( ⌊(VRAM−18.6)/5.0⌋ , ⌊decode/20⌋ )
decode ≈ 带宽 × 实现效率 ÷ 22.1 GiB（含 KV 读放大）
```

口径：W=17.1 GB、KV=80 KB/token → 64K=5.0 GiB、开销 1.5 GiB、H=26,280 h、p=0.90、电价 0.270 USD/kWh。

**跨 20 / 40 / 60 t/s 所需的标称带宽**：442 / 884 / 1,326 GB/s。这四条线（含 GDDR5 的 347）恰好把介质分在了不同档位。

## 1. D1 · 候选集四分区

### 1.1 分区推导

按**显存物理介质**四切。这一刀合法的理由是：题面的性能约束经 `带宽 ÷ 22.1 GiB` 换算后，**恰好是按介质分层而不是按容量分层**：

| 分区 | 介质 | 带宽范围 | 能跨到第几档 | 候选数 |
|---|---|---|---|---|
| **a GDDR5/6/6X** | 分立 GDDR，128–384 bit | 347–1,008 | 第 1 档为主，个别第 2 档 | 5 |
| **b GDDR7** | 分立 GDDR7，512 bit | 448–1,792 | 第 1–3 档 | 3 |
| **c HBM2/2e/3** | 堆叠 HBM，5120 bit | 1,555–2,039 | 第 2–3 档 | 3 |
| **d LPDDR5X 统一内存** | SoC 共享池 | 215–1,200 | 第 0–2 档（跨 5.6 倍） | 4 |

**互斥**：一台机器的显存介质只有一种（GDDR 或 HBM 或 LPDDR5X），统一内存机没有独立显存。**穷尽**：本地推理硬件的显存只有这四类介质。✅

```
C 每验收任务成本 [$/任务]                        SHARE 1.00  BOUND 7.1x（2.86m / 0.40m）

│   │   ├── 平台价                              leaf 可查
│   │   └── H = 26,280 h                        leaf 可定
│   └── N-1.2 电费 P_kW × 0.270                  SHARE 0.34  BOUND 3.4x（0.20–0.68 kW）
├── N-2 task/h                                  SHARE 0.54  BOUND 8.7x（124–1,066）
│   ├── N-2.1 T [s]                             SHARE 0.19  BOUND 3.8x（8.4–31.5）
```

## 3. 瓶颈

**BOTTLENECK: N-2.2.2「速度闸」——具体是 `⌊带宽 × 效率 ÷ 442⌋` 这个由显存介质 + 实现效率共同决定的整数。**

打分：N-2.2 = 0.54 × 0.81 × 4.0 = **1.75**；N-1.1 = 0.36 × 0.66 × 16.5 = **3.92**。裸分 N-1.1 压倒性，但它 16.5× 的区间几乎全部来自 **H100（$28,000）与 RTX 3090（$1,750）这两个极端点**——而 H100 的带宽只比 A100 高 5%，价格却高 3.8 倍，被自己的价格拖死。把「贵而无用」的极端点剔除后，capex 收敛到 $1,750–9,465（5.4×），乘积 1.28，低于 1.75。

三条结构论据：

1. **S 是台阶函数，而台阶由介质决定**：GDDR5 卡在 0（347 < 442）、GDDR6/6X 卡在 1（768–1,008）、GDDR7 分裂成 1（5090）与 2（PRO 6000）、HBM 在 2–3、LPDDR5X 分裂成 0（215–273）、1（614–1,200）。**同一个「GDDR7」标签下，5090 的 26.2 与 PRO 6000 的 58.3 差 2.2 倍**——介质名称不决定成败，**实现效率才决定**。
2. **它解释了「贵卡为什么不一定输」**：H100 单价是 3090 的 16 倍，带宽只高 2.2 倍，S 从 1 到 3，$/任务 1.101m vs 1.119m——**两者几乎打平**。台阶结构让 16 倍的价格差被稀释到 1.6%。
3. **它也解释了「便宜卡为什么不一定赢」**：P40 的 $/h 是全表最低（0.166），但 347 GB/s 跨不过第 1 档，**连一个合格任务的分子都进不去**。

**瓶颈的下一层**：介质的成本效率是**倒挂**的。每 $1 买到的带宽：P40 1,367 / 3090 685 / 5090 612 / A100-40 549 / A6000 303 / A100-80 305 / M5U 224 / L40S 118 / PRO 115 / H100 73（GB/s per $K）。**排序几乎与「能否用」完全相反**——最便宜的带宽最没用。**这是本题最重要的一条经济学观察：带宽的边际价值是阶跃的，所以按 $/带宽 排序会系统性地推荐错的卡。**

## 6. 矛盾清单（每条声明边界类型）

**X1 · 同介质同带宽的两张 GDDR7 卡：58.3 vs 26.2 t/s**
- 源 A：techpowerup（2026-08-12）与规格表：PRO 6000 与 5090 同为 1,792 GB/s GDDR7。
- 源 B：contextstudios（2026-09）实测 5090 在 64K 下 26.2；PRO 6000 的 58.3 由「1,792 × 0.55 ÷ 17.1」反推（B-r2 类写法）与 vLLM 30B 批处理 8,425 t/s 佐证。
- **判为未解决**：两者不是同一口径（一个是 64K 实测，一个是带宽反推）。**采信 26.2 对 5090、58.3 对 PRO 6000**，但把「5090 效率只有 0.32」标为本次最大的单点不确定——它一翻，5090 就从 2.248m 掉到 1.03m。
- **边界类型：③ 信息边界** —— `research_required: 5090 与 PRO 6000 在同一 GGUF、同一 64K 深度下的横评；路径 = llama-bench 双机各跑一次`。

**X2 · L40S 值不值：FP16 快 2.3 倍 vs 带宽只高 12%**
- 源 A：flopper.io（2026-10-28）「2.3x the FP16 throughput (362 vs 155 TFLOPS)」。
- 源 B：同页「Low-batch token generation scales with bandwidth ... 864 vs 768 GB/s, about 12% more」，并指出「$0.38 vs $0.30 per GPU-hour，单用户 chat 在旧卡上更便宜」。
- **更可信：B 对本题**。本题是 low-batch decode（每流一条），FP16 算力只在 prefill 上起作用，而 prefill 只占 T 的 19%。**L40S 的 2.3 倍算力在本画像下几乎无法兑现。**
- **边界类型：① 数学/理论边界** —— decode 是带宽受限过程（`tok/s ≤ 带宽 ÷ 每 token 读量`），算力不进入这个不等式。

**X3 · 「统一内存带宽跨度 5.6 倍」**
- 源 A：compute-market（2026-07-16）「the Halo owns the 27B–120B MoE sweet spot」。
- 源 B：本 run 的对照：M5 Ultra 1,200 与 Strix Halo 215 同为「LPDDR5X 统一内存」，差 5.6 倍。
- **两者不冲突但暴露一个术语陷阱**：「统一内存」在 2026 年已不代表任何性能水平。**采信 B 的分档结论**：LPDDR5X 内部分裂成 0 档（215–273）与 1–2 档（614–1,200）。
- **边界类型：③ 信息边界** —— `research_required: 各 SoC 的实测带宽（名义 vs 实际差 15–20%）；路径 = 同一 STREAM-like 测试`。

**X4 · H100 PCIe 的带宽：2,039（HBM2e）vs 3,350（HBM3）**
- 源 A：topcpu 规格对照（2026-10）「H100 PCIe: HBM2e 2,039 GB/s; SXM5: HBM3 3,350 GB/s」，并给 SM 数差（114 vs 132）与 TDP 差（350 W vs 700 W）。
- 源 B：部分产品页把 3,350 标在「H100 PCIe 80GB」上。
- **更可信：A**（区分了 SM 数、TDP、显存类型三处一致的证据）。**采信 2,039**；若误用 3,350，S 会从 3 变 4、成本从 1.101m 降到 0.826m——**一个规格错误就能改变排名**。
- **边界类型：③ 信息边界** —— `research_required: 目标 SKU 的 datasheet 逐条核对（PCIe 与 SXM 是两款不同的卡）；路径 = NVIDIA 官方规格页`。

**X5 · 量化位宽与权重体积：Q4 的 27B 到底多大**
- 源 A：insiderllm（2026-10-15）对 4060 Ti 的「up to about 26B at Q4」暗示 14–15 GB 级。
- 源 B：本 run 用 17.1 GB（Q4_K_M 的 27B）。
- **两者不冲突**：A 的 26B 是「能装下」的表述（含 15 GB 的 Gemma 变体），B 是本题的 Qwen 级 27B。**采信 17.1 GB**；若取 15.7 GB，24 GB 卡的槽位从 1 变 1（不变），40 GB 卡从 4 变 4 —— **对结论无影响**。
- **边界类型：① 数学/理论边界** —— 体积 = 参数量 × 位宽 ÷ 8，可直接算；差异只在是否含 embedding。

**OPEN 清单**
- **O1「5090 换一套内核能不能把效率从 0.32 提到 0.72？」** → **③ 信息边界**：`research_required: 5090 在 TensorRT-LLM / NVFP4 下的 64K 单流；路径 = 官方 benchmark 或自测`。
- **O2「H100 的带宽能不能靠 FP8 KV 换算成更多槽位？」** → **① 数学/理论边界**：FP8 KV 把 5.0 GiB 压到 2.5，槽位翻倍，但**速度闸不变**（S=min(槽,档)）。到此为止因为档位由带宽决定。
- **O3「LPDDR5X 能不能堆到 442 GB/s 又不贵？」** → **① 数学/理论边界**：LPDDR5X 单颗 8533 MT/s × 256 bit ≈ 273 GB/s，要 442 需 384 bit 以上或双通道堆叠；DGX Spark 已经是 273。到此为止因为**封装位宽是硬约束**（更宽就得更大 SoC，成本跳到 HBM 区间）。
- **O4「把 27B 换成 MoE 能不能绕开带宽墙？」** → **② 实操边界**：题面指定 27B 规模，换 MoE 是换模型不是换硬件；且 MoE 激活参数少但显存需求升。到此为止因为超出选型范围（Z = 质量评估）。

## 8. 交付

- **最优：1×A100 80GB（$7,400），0.403×10⁻³ $/验收任务**；次优 **A100 40GB（0.454m，价格 51%）**、RTX PRO 6000（0.830m）。
- **本 run 的判据**：**显存介质决定台阶，台阶决定成本**。`S = min(槽位, ⌊带宽×效率/442⌋)`，而分子里的「效率」在 0.32–0.84 之间——**同介质的两张卡可以差 2.2 倍**。
- **最重要的经济学观察**：**每美元带宽的排序与可用性几乎完全相反**（P40 1,367 → H100 73 GB/s per $K）。带宽的价值是**阶跃的**，按 $/带宽 选卡会系统性地推荐「便宜但跨不过门槛」的方案。
- **最实用的一条**：**A100 40GB 是本画像下的甜点**——比 80GB 便宜 49%，性能只差 8%，因为 80GB 多出的 8 个槽位在速度闸（3）面前全死。
- **该先测的三件事**：①5090 的 64K 实现效率（0.32 还是 0.72，决定它第 4 还是第 9）；②H100 的二手实价；③各机的 64K 深度单流。
- **一句话**：这道题真正的自变量是**显存介质的带宽 × 实现效率**——HBM 与高效 GDDR7 能跨到 2–3 档，GDDR6 只能守 1 档，GDDR5 与低端 LPDDR5X 连门都进不去。
