## 3. 成本结构

```
C = c_hour ÷ (3600 ÷ T × S × p)
c_hour = capex/H + P_kW × 0.270
S = min( ⌊(VRAM − 18.6)/5.0⌋ , ⌊decode/20⌋ )
```

W=17.1 GB；KV 64K=5.0 GiB；开销 1.5 GiB；H=26,280 h；p=0.90；电价 0.270 USD/kWh；T=3500/prefill+500/decode。

## 4. 分解树

```
C 每验收任务成本 [$/任务]                          SHARE 1.00  BOUND 7.1x
├── A c_hour [$/h]                               SHARE 0.43  BOUND 3.1x
│   ├── A1 capex / H                             SHARE 0.62  BOUND 7.6x（$950–28,700）
│   └── A2 电费                                  SHARE 0.38  BOUND 4.6x（0.14–0.68 kW）

```

份额：0.43+0.47+0.10 = 1.00 ✅；A1 0.62+A2 0.38 = 1.00 ✅；B1 0.15+B2 0.85 = 1.00 ✅。

## 6. 检验「$/带宽」这个轴——**它失败了**

| $/K 带宽排名 | 候选 | $/任务排名 |
|---|---|---|
| 1 | 5090（432） | 3 |
| 2 | A100-40（409） | 2 |
| 3 | **5060 Ti（396）** | **不合格** |
| 4 | 3090（374） | 6 |
| 5 | **P40（365）** | **不合格** |
| 6 | A100-80（261） | **1** |
| … | … | … |
| 12 | Strix Halo（61） | 不合格 |
| 13 | DGX Spark（58） | 不合格 |

**四个反例足以判定这个轴无效**：最高 $/K 的 4 名里有 2 个不合格（5060 Ti、P40），第 6 名的 A100-80 却是冠军，第 12/13 名也全不合格。**相关性接近 0。**

**为什么无效**：`$/带宽` 的分母是「带宽」，而成本的分母是「`T × S`」。**带宽只是 `decode` 的分子，`decode` 要先被 `⌊·/20⌋` 取整、再被容量闸 `min` 一次**——两次非线性变换之后，线性指标就失效了。

**BOTTLENECK: B2「并发流 S」——而 S 的两个闸里，本表两种都有。**

打分：B2 = 0.47 × 0.85 × 3.0 = **1.20**；A1 = 0.43 × 0.62 × 7.6 = **2.03**。裸分 A1 更高，但 A1 的 7.6× 区间**几乎全部来自 H100（$28,700）这一个点**——剔掉它之后 capex 收敛到 $950–9,465（10×→仍是 10×？）……

**换个方式判断**：用「弹性」而不是「区间宽度」。把每张卡的 capex 翻倍，看 $/任务涨多少；再把带宽翻倍，看 $/任务降多少：

| 操作 | A100-80 | 5090 | 3090 | A6000 |
|---|---|---|---|---|
| capex ×2 | 0.403 → 0.72（×1.79） | 0.536 → 0.98（×1.83） | 1.289 → 2.41（×1.87） | 1.621 → 3.01（×1.86） |
| **带宽 ×2** | 0.403 → 0.403（**不动**，S 已封顶 3） | 0.536 → 0.536（**不动**，速度闸 3→容量闸 2） | 1.289 → **0.87**（S 1→2） | 1.621 → **1.09**（S 1→2） |

**这张表把瓶颈说清楚了**：

- **对 A100-80 与 5090，带宽已经过剩**——再给一倍带宽，成本一分不降，因为**容量闸接管了**（A100-80 的 12 槽对 3 档；5090 的 2 槽对 3 档）。
- **对 3090 与 A6000，带宽是真瓶颈**——翻倍后 S 从 1 到 2，成本掉 30%。
- **所以「瓶颈」不是全表统一的**：**四张冠军候选卡里，两张的瓶颈是容量、两张是带宽**。这是本 run 唯一需要分开说的结论。

## 7. 矛盾清单

**X1 · RTX 5090 在 64K 深度到底多少 t/s：62.1 / 26.2 / 89 / 75.5**
- 源 A：**quantized.fyi（2026-05-03）深度曲线**：4K 87.4 → 16K 81.2 → 32K 74.6 → **65,536 上下文 62.1** → 131K 48.3；prompt processing 同深度 1,650。
- 源 B：modelfit（2026-10-31）「Qwen3.8 27B 估 89 tok/s（典型误差 5%）」——**未说明上下文深度**，应是短上下文。
- 源 C：Reddit r/LocalLLM（2026-08-20）转述一张「4-bit，5090 32GB，75.5 tok/s」的表，但**发帖人自己说「看不出是哪个 runtime」**；同帖还有 133 t/s、140 t/s（MTP 投机解码）等数字。
- 源 D：本 run 的带宽模型校验：`1,792 × 0.80 ÷ 23.0 = 62.3`——**与源 A 的 62.1 吻合到 0.3%**。
- **更可信：A**。理由不是「它数字大」，而是**它的整条曲线都与带宽模型自洽**（4K 时读量 16.8 GiB → 85 t/s，实测 87.4；131K 时读量 26.7 GiB → 53.7，实测 48.3），而 B/C 都缺上下文深度这个关键条件。
- **这条改写了本轮结论**：按 62.1 算，5090 的 S=2、$/任务 0.536m，**从第 7 名跳到第 3 名**。
- **边界类型：③ 信息边界** —— `research_required: 同一台 5090、Q4_K_M、64K、无投机解码的复测；路径 = llama-bench -d 60000`。

**X2 · Strix Halo 的 30B 是 100 t/s 还是 8 t/s**
- 源 A：runaihome（2026-06-03）标题「**100 t/s on 30B Models**」。
- 源 B：presenc.ai（2026-10-01）「7B **46–53** t/s、sparse 30B **72–75**、gpt-oss 120B 31–34、**dense 70B 约 5**」。
- **两者不冲突**：A 的「30B」是 **MoE（sparse）**，B 明确区分 sparse/dense。**dense 27B 按带宽 212 GB/s ÷ 23.0 GiB × 0.85 ≈ 7.8 t/s**——落在 B 的 dense 70B（5 t/s）与 sparse 30B（72–75）之间的合理位置。
- **采信 8.0 t/s，S=0，不合格。**
- **边界类型：③ 信息边界** —— `research_required: Strix Halo 上 dense 27B Q4、64K 单流；路径 = 机器实测（条目 13 已搁置）`。

**X3 · P40 的 347 GB/s 是不是「够用」**
- 源 A：everylocalai（2026-09-07）「P40 $150、5–8 t/s、347 GB/s」。
- 源 B：alibaba（2026-08-29）「P40 $220–250、**50–90 t/s**」。
- **更可信：A**。B 的 50–90 t/s 必然是**小模型**（7B 级）口径；对 27B@64K，347 ÷ 23.0 = 15.1 t/s 是物理上限，A 的 5–8 更接近。
- **采信 8.0，S=0，不合格。**
- **边界类型：① 数学/理论边界** —— `tok/s ≤ 带宽 ÷ 每 token 读量`，347 ÷ 23.0 = 15.1 < 20，到此为止。

**X4 · A100 80GB 的 capex：$7,400 还是 $4,000**
- 源 A：aitooldiscovery（2026-10-01）「二手 80G $4,000–9,000」。
- 源 B：pcserverandparts（2026-09-24）「80G $8–12k，40G $4,000–7,800」。
- **两者是同一区间的两种切法**，A 更宽（含裸卡与带平台）。**采信 $7,400（A 的区间偏上，因为本表口径含平台）。**
- **边界类型：③ 信息边界** —— `research_required: 裸卡与含平台的成交分离；路径 = eBay Sold 按 "only card" 过滤`。

**OPEN**
- **O1「$/带宽 这个指标能不能修正成有用的」** → **① 数学/理论边界**：可以，但修正后的形式就是 `$/（带宽 ÷ 读量 × 闸）`，**它已经是完整成本公式的一部分了，不是捷径**。到此为止。
- **O2「为什么 5090 的 $/带宽 最高却排第 3」** → **① 数学/理论边界**：它的容量闸只有 2（32 GB），把 3 档带宽砍成 2。**`min` 的第二次截断。**

## 9. 交付

- **最优：1×A100 80GB，0.403m**；次优 A100 40GB（0.454m）、**RTX 5090（0.536m）**。
- **本 run 的判据**：**`$/带宽` 这个直觉指标是无效的**（相关性≈0，最高 4 名里 2 个不合格），因为带宽要经过两次非线性（`⌊decode/20⌋` 取整、`min` 截断）才变成产能。
- **本轮最重要的发现**：**5090 在 64K 深度是 62.1 t/s，不是 26.2**。quantized.fyi 的整条深度曲线（4K 87.4 → 131K 48.3）与带宽模型吻合到 0.3%，**这把它从第 7 名推到第 3 名**。**如果这个数字成立，本题的前三名是 A100-80 / A100-40 / 5090，而不是任何「大显存」方案。**
- **瓶颈的正确说法**：**不是全表统一的**。A100-80 与 5090 的瓶颈是**容量闸**（带宽过剩），3090 与 A6000 的瓶颈是**带宽闸**。**「带宽翻倍」这个操作对前两者收益为 0、对后两者收益 30%。**
- **最反直觉的一条**：**H100 的带宽（2,039）比 A100-80（1,935）高 5%，但 `S` 都是 3，$/任务贵 2.71 倍。** 规格领先在整数闸上归零。
- **该先测的三件事**：①5090 的 64K 单流（决定第 3 还是第 7）；②各机 64K 单流；③Strix Halo / Spark 的 dense 口径（它们是否连门都进不去）。
