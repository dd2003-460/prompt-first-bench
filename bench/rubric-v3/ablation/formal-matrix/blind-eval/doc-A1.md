## 0. 根节点

**C = 每完成一个「验收通过」任务的成本（USD/任务）**

题面里有两个数决定了整个形状：64K 上下文（决定显存与 KV 容量）和「每流 ≥20 tok/s」（决定一台机器能挂几条流）。通过率不到 100% 意味着分母必须是**验收通过**的任务数，而不是尝试数。

```
C = c_hour / (3600/T × S × p)

c_hour = capex/H + P_kW × 0.270        H = 26,280 h（3 年 24×7）
T      = 3500/prefill_tps + 500/decode_tps   （前缀 60.5K 命中，只算 3.5K 新输入）
S      = min( ⌊(VRAM − 17.1 − 1.5) / 4.0⌋ , ⌊decode_tps ÷ 20⌋ )
p      = 0.90
```

口径声明（题面未给、由本 run 定）：权重 Q4_K_M = 17.1 GB；64K 单流 KV = 4.0 GiB（64 KiB/token，来自 openclawdc 对 Qwen3.8-27B 的 KV 说明）；运行时/CUDA graph 开销 1.5 GiB；电价 0.270 USD/kWh（东京第 3 档 40.49 円 ÷ 150）。

## 1. 分解树

```
C 每验收任务成本 [$/任务]                      SHARE 1.00  BOUND 5.7x（2.25m / 0.40m）
├── N-1 c_hour 每小时持有成本 [$/h]             SHARE 0.38  BOUND 2.2x（0.188–0.422）
│   ├── N-1.1 资本摊销 capex/H                 SHARE 0.72  BOUND 4.1x（1750–7200）
│   │   ├── 卡价 gpu_price                     leaf 可查
│   │   ├── 平台价 host_price                  leaf 可查 700–900
│   │   └── H 摊销小时 [h]                     leaf 可定 26,280
│   └── N-1.2 电费 P_kW × 0.270                SHARE 0.28  BOUND 2.8x（0.30–0.85 kW）
│       └── 整机功耗 power_kw [kW]             leaf 可测（TDP + 主机 100–150 W）
├── N-2 task/h 任务率 [任务/h]                  SHARE 0.52  BOUND 7.9x（135–1,069）
│   ├── N-2.1 T 单任务耗时 [s]                 SHARE 0.21  BOUND 2.6x（9.1–24.0 s）
│   │   ├── prefill 3500 tok                  leaf 实测（450–2,500 t/s）
│   │   └── decode 500 tok                    leaf 实测（26.2–65 t/s）
│   └── N-2.2 S 并发流数                       SHARE 0.79  BOUND 3.0x（1–3）
│       ├── 显存闸 ⌊(VRAM−18.6)/4.0⌋          区间 1–15
│       └── 速度闸 ⌊decode/20⌋                区间 1–3
└── N-3 p 通过率                               SHARE 0.10  BOUND 1.18x（0.85–1.00）
```

**份额自校验**：N-1 0.38 + N-2 0.52 + N-3 0.10 = 1.00 ✅。N-1.1 0.72 + N-1.2 0.28 = 1.00 ✅。N-2.1 0.21 + N-2.2 0.79 = 1.00 ✅。

## 3. 瓶颈

**BOTTLENECK: N-2.2 S 并发流数**（SHARE 0.52 × 0.79 × BOUND 3.0 = **1.23**，全树最高）。

三条理由：

1. **其余因子对结论只有线性影响，S 是台阶**。capex 从 $1,750 到 $7,200 差 4.1 倍，C 也只差 4.1 倍；而 S 从 1 到 3 直接让 C 掉三倍。本表里最贵的 5090（2.248m）和最便宜的 A100（0.395m）差 5.7 倍，其中 3 倍来自 S。
2. **S 被两条闸门夹住，两条都在硬件之外**。速度闸 ⌊decode/20⌋ 在 3090/4090/5090 上都等于 1（34.0、38.4、26.2 都进不了 40），显存闸在 24 GB 卡上也只等于 1（(24−17.1−1.5)/4.0 = 1.35）。**要跨档必须同时改硬件与部署方式**——这正是 2×3090 能到 0.727m 的原因。
3. **5090 是反例，正好反证**。它有 1,792 GB/s 的账面带宽和 32 GB 显存（显存闸 3），但 64K 下 decode 只有 26.2，速度闸给 1，于是成为全表最贵（2.248m）。**买的显存与带宽在速度闸面前都是废的**。

瓶颈的下一层：S 的分子是 decode t/s，而 decode t/s ≈ 有效带宽 ÷ 22.1 GiB（17.1 权重 + 4.0 KV + 1.5 开销）。跨 20 需 442 GB/s，跨 40 需 884 GB/s，跨 60 需 1,326 GB/s。24 GB 卡带宽都在 936–1,008，**刚好卡在第 1 档与第 2 档之间**——这是本题所有候选的共同天花板。

**四条要点**

1. **A100 的领先全部来自 S=3**：它的单流只比 3090 快 1.9 倍，capex 却是 4.1 倍；只有在「每美元买几条流」的口径下它才赢。
2. **2×3090 是唯一靠「买第二张卡」跨过第 40 t/s 门槛的方案**：单卡 34.0 差 6 就够 40，TP2 后 50.0 直接进第 2 档，C 从 1.119m 掉到 0.727m。
3. **4090 与 3090 几乎打平（1.134 vs 1.119）**：单流快 13%、prefill 快 2.5 倍，但 capex 高 49%，两相抵消。**在 S=1 的档位里，T 的改善打不过 capex 的上涨**。
4. **5090 最贵**：账面上它是最快的消费卡，但 64K 深度下 decode 只有 26.2（比 3090 还慢），S 锁死 1，且价格最高。

## 6. 矛盾清单

**X1 · RTX 3090 二手价：$600–850 vs $1,395**
- 源 A：alibaba 产品页（2026-10-06）「二手 eBay 上 $600–850」，并把 $1,395 归为「new-old-stock 收藏价」。
- 源 B：bestvaluegpu（2026-09）「RTX 3090 Price History — $1,395 used」；clustermelt（2026-08-01）给 $800–1,200。
- **更可信：A 与 clustermelt 的区间重叠（$800–1,200）**，B 的 $1,395 是「已停产的 NOS」口径。本 run 取 $1,050 并做上下沿敏感性（见 §5）。这条差 60%，直接对应 C 变动 ±20%。

**X2 · RTX 5090 的 64K 解码速度：26.2 vs ~38 t/s**
- 源 A：contextstudios（2026-09）同表同 build：5090 64K = 718 / 26.2，**比同表 3090 的 34.0 慢**。
- 源 B：openclawdc（2026-09）「一个 3090 上 8K 是 40 t/s，131K 只掉 33%」——按其衰减曲线外推 64K 应约 30 t/s 以上。
- **判为未解决**：A 是同表可比口径（三卡同 build），B 是单卡单文外推。本 run 采信 A（26.2），并把 30 放进敏感性——**即使取 30，5090 仍是 S=1、仍是最贵**，结论不变。

**X3 · 64K 单流 KV 到底多大：4.0 GiB vs 5.0 GiB**
- 源 A：openclawdc（2026-09）「64 KiB per token in f16」→ 4.0 GiB @64K。
- 源 B：按 GQA 参数复算（2 × 4 KV heads × 256 dim × 16 全注意力层 × 2 B = 64 KiB/token）——与 A 一致；但若按 40 层全注意力算则 160 KiB/token → 10 GiB。
- **采信 A 的 64 KiB/token**（它与官方 config 的 16/64 hybrid 层数自洽）。这条对 24 GB 卡的 S 无影响（1.35 与 1.02 都取 1），**只在 32 GB 卡上把显存闸从 3 压到 2，仍不改变 S**。

**X4 · 20 tok/s 是「单流」还是「每流」**
- 源 A：题面原文「每个并发流的解码速度不低于 20 token/s」。
- 源 B：openclawdc 的实测口径是「单请求 decode」，即 S=1 的特例。
- **两者不冲突但含义不同**：若按「每流 ≥20」检查 S>1 的情形，需要 per-stream = 总吞吐/S 的数据，本 run 无此数据，因此**保守假定 decode 不随并发下降**（对 2×3090 的 S=2 是乐观假设，见黑盒 B2）。

## 8. 交付

- **最优：1×A100 80GB 二手（$7,200 含平台），0.395×10⁻³ $/验收任务**；次优 2×3090 TP2（0.727m），第三 1×3090（1.119m）。
- **本 run 的核心判据**：`S = min(显存闸, ⌊decode/20⌋)`，而 24 GB 卡的 decode 全部落在 26–38 的区间里——**它们离第 40 个 tok/s 只差几个点，却整整差一个成本档**。所以决策问题不是「哪张卡便宜」，而是「能不能把单流推过 40」。
- **两个反直觉**：①最快的消费卡（5090）成本最高，因为 64K 深度下它反而最慢；②4090 比 3090 快 13%，但在 S=1 的档位里这点快被 capex 吃掉，两者打平。
- **该先测的三件事**：①2×3090 的 TP2 单流（唯一能确认 S=2 的量）；②各卡 64K 深度的 per-stream 衰减；③真实 p。
- **一句话**：这道题的答案不在「谁的显存大」，而在「谁的 64K 深度单流能跨过 40」——A100 用 1,935 GB/s 跨过了 60，2×3090 靠两块卡拼过了 40，其余全部停在 20 与 40 之间。
