## 职责边界（硬约束，成璐 2026-11-03 定）

decomp 的职责 = **分解 + 标注缺口 + 留空**。

- 做：把问题拆成正交维度、给每个无法闭式求解的项编号收口、显式声明口径、指出主导瓶颈。
- 不做：不调研、不填数。事实数据类内容一律标「待核验 / 留空」，写进空缺清单交给阶段 02。
- 评分 KPI（消融实验用）：**缺口标注覆盖率**——该留空的有没有留空。不是事实准确率（事实产生是 02/04 阶段的职责）。

违反边界的信号：输出里出现无来源的具体规格数字并当作已知事实使用 → 该 run 记 `boundary_violation`。

## 五步方法（在 01 阶段工件中逐项落地）

### 1. 先定根标量

把「最划算 / 最快 / 最优」翻译成**唯一无歧义的可排序标量**（如 tokens/s/GPU、¢/1k_acc），写出公式和单位。

- 落点：01 工件的「目标」字段必须含这个标量定义，而不是自然语言形容词。
- 判据：两个候选对象代入公式后能排出序，且不存在第二个可争议的主标量。

### 2. 正交维度切分

第一层按**正交维度**拆，不是按现象罗列。

- 每两个维度必须能指出各自的**独占参数**（只影响这一维的参数）。
- 若某参数同时影响多个维度（SHARED 耦合），单独列一节显式记录它走哪几条路径。
- 与 01 主文件的「因素正交」判定原则一致，本条是其操作化版本：说不清独占参数 = 没拆干净，继续切或显式写耦合。

### 3. 黑盒收口表

所有无法闭式求解的项，编号 B1–Bn，每个黑盒给**四样东西**：

| 字段 | 说明 |
|------|------|
| 为什么没有闭式 | 缺什么信息 / 依赖什么未决条件 |
| 估计区间 | 给区间不给单点（如 0.5–0.8，不写 0.65） |
| 一天内能做完的测法 | 具体动作 + 数据来源，写成阶段 02 可直接执行的条目 |
| 弹性（高/中/低） | 它变动时结论会不会翻转；高弹性 = 优先研究 |

只写「这个要实测」不算收口，Reviewer 应打回。黑盒表整体就是 01 空缺清单的结构化形态，二者一一对应，不得各写一套。

### 4. 口径声明

- **约束类维度**（不满足直接划掉候选）与**成本类维度**（进公式）分开标注，不能混在一个池子里比权重。
- 落点：01 工件的因素列表每项标 `[约束]` 或 `[成本]`（或 `[其他]` + 理由）。

### 5. 瓶颈识别

最后指出哪个因素是主导项，并用**弹性或量级论证**，而不是只说「都很重要」。

- 判据：删掉这个因素后结论会翻转（对应黑盒表里的「高弹性」项，或约束类里一票否决项）。
- 说不出主导项 = 分解未完成，回到第 2 步重切。

## 与 01 主文件的关系

| 01 主文件要求 | 本模块的操作化 |
|--------------|---------------|
| 因素正交 | 第 2 步：独占参数检验 + SHARED 耦合单列 |
| 空缺完整 | 第 3 步：黑盒收口表四要素（空缺清单的结构化形态） |
| 覆盖目标 | 第 1 步：根标量使「覆盖」可检验（候选可排序） |
| 优先级合理 | 第 5 步：瓶颈 = 高优先级因素的判定依据 |

四条 pfb 独有补丁（候选集冻结 / 证据来源完备 / 对抗核验 / owner 标注）**不在本模块范围内**，仍按 01 主文件及其后续阶段执行。本模块只加五步结构纪律，不删不改主文件任何规则。
