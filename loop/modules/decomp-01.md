## 职责边界（硬约束，成璐 2026-11-03 定）

decomp 的职责 = **分解 + 标注缺口 + 留空**。

- 做：把问题拆成正交维度、给每个无法闭式求解的项编号收口、显式声明口径、指出主导瓶颈。
- 不做：不调研、不填数。事实数据类内容一律标「待核验 / 留空」，写进空缺清单交给阶段 02。
- 评分 KPI（消融实验用）：**缺口标注覆盖率**——该留空的有没有留空。不是事实准确率（事实产生是 02/04 阶段的职责）。

违反边界的信号：输出里出现无来源的具体规格数字并当作已知事实使用 → 该 run 记 `boundary_violation`。

## 五步方法（在 01 阶段工件中逐项落地）

### 1. 先定根标量

把「最划算 / 最快 / 最优」翻译成**唯一无歧义的可排序标量**（如 tokens/s/GPU、¢/1k_acc），写出公式和单位。

- 落点：01 工件的「目标」字段必须含这个标量定义，而不是自然语言形容词。
- 判据：两个候选对象代入公式后能排出序，且不存在第二个可争议的主标量。

### 2. 正交维度切分（拼回去看漏 + 两两看重叠）

第一层按**正交维度**拆，不是按现象罗列。拆完做两个检查，都是"看图说话"式的空间直觉：

- **完备性 = 拼回去看有没有漏**：把所有子节点的范围加起来，能不能完整覆盖原来那个节点的范围？有遗漏就列出来——哪怕剩下一块"说不清是什么但确实存在"的区域，也先占个位写进空缺清单（标 `[待核验]`），后面查。漏而不报 = 分解失败。
- **正交性 = 两两看有没有重叠**：每两个子节点之间有没有范围重叠？没有最好；有就尝试切开；实在切不干净，就把重叠区域明确说出来（哪个部分同时属于哪两个子节点），方便后面决定是合并还是重切。

禁止用代数式判据替代这两个检查（如"独占参数""贡献形式"之类）——那会诱导模型为了凑出表达式而硬编，看起来完成了检查，实际覆盖没覆盖它自己都不知道。

**可审计产物（v2 引导式检查 · 2026-11-07）**：光说"我拼过了没漏"不可审计（T26 Q4：v0 独有缺陷，与 S1 门禁失效同构）。拆完后必须交一张**拼接覆盖图**：

| 子节点 | 覆盖范围（一句话） | 与其他子节点的重叠 | 缺口/不确定区域 |
|--------|-------------------|-------------------|----------------|
| A      | …                 | 与 B 在…处重叠     | 无 / [待核验]   |
| B      | …                 | 无                | …              |

三行规则：① 每行一个子节点，"覆盖范围"用具体对象描述（不是抽象标签）；② "重叠"列必须点名是哪两个子节点、在哪个具体区域；③ "缺口"列**以事实为准**——真查过、真拼过了就是无缺口，如实写"无"，不鼓励也不惩罚留空；确实说不清的地方才占位 + 标 `[待核验]`。（2026-11-07 成璐纠正：旧版"全表无缺口=可疑"会诱导模型故意留缺口表演谨慎，已删。完美覆盖可以是真的——尤其当每个要素都经过了独立来源交叉验证时，漏了也不是模型的问题，是人类数据本身没有。）Reviewer 核验方式：拿覆盖图做**重建测试**（STaD 代理）——遮住原始父节点描述，只看这张表能否重建出父节点的范围和边界；重建不出 = 覆盖图是装饰，打回。

**分解顺序原则（2026-11-07 成璐指令 · v3 方向）**：分解本身也依赖模型判断（"我觉得该拆成这五块"不可验证，同谷物例子的知识上限问题）。更稳的顺序是**先查后拆**：
1. **先调研父节点**：搜 ≥N 个独立来源，看它们各自怎么组织/分解这个话题（综述的章节结构、教科书的大纲、多篇论文的 section 划分）
2. **找矛盾**：不同来源的分解方式冲突时（A 分 4 块 B 分 6 块，C 把 X 归入 Y 而 D 单列），**停下来推理解决**——是粒度差异还是实质分歧？谁的信息更新？矛盾本身是高价值信号
3. **按查到的分解**：子节点来自证据（"3/5 的来源都把 X 单列"），不来自模型直觉。模型的角色从"决定怎么拆"变成"综合多来源的拆法 + 解决矛盾"
4. **递归**：对每个子节点重复 1-3（查→找矛盾→拆），一层一层往下走
5. 模型自主判断只保留给**特别常识的操作**（加减法级别），深度调研中的分解一律走"先查后拆"

这与 T29 §1（空白穷尽验证）天然衔接：查父节点的过程就是在做文献扫描，分解树本身就是调研产出的副产品。

### 3. 黑盒收口表

所有无法闭式求解的项，编号 B1–Bn，每个黑盒给**四样东西**：

| 字段 | 说明 |
|------|------|
| 为什么没有闭式 | 缺什么信息 / 依赖什么未决条件 |
| 估计区间 | 给区间不给单点（如 0.5–0.8，不写 0.65） |
| 一天内能做完的测法 | 具体动作 + 数据来源，写成阶段 02 可直接执行的条目 |
| 弹性（高/中/低） | 它变动时结论会不会翻转；高弹性 = 优先研究 |

只写「这个要实测」不算收口，Reviewer 应打回。黑盒表整体就是 01 空缺清单的结构化形态，二者一一对应，不得各写一套。

### 4. 口径声明

- **约束类维度**（不满足直接划掉候选）与**成本类维度**（进公式）分开标注，不能混在一个池子里比权重。
- 落点：01 工件的因素列表每项标 `[约束]` 或 `[成本]`（或 `[其他]` + 理由）。

### 5. 瓶颈识别

最后指出哪个因素是主导项，并用**弹性或量级论证**，而不是只说「都很重要」。

- 判据：删掉这个因素后结论会翻转（对应黑盒表里的「高弹性」项，或约束类里一票否决项）。
- 说不出主导项 = 分解未完成，回到第 2 步重切。
