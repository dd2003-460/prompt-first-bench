### R1-D4-S1 整体验证

- **类型**: verification
- **输入**: `loop/plan.md` 目标 + 所有子任务产出 + 各验证报告
- **输出**: `loop/1-loop/integrity-verify.md`
- **继续条件**: 整体置信度 ≥ 0.8 → 进入 2-loop
- **回退条件**: 置信度 < 0.5 → 回退到分解阶段（新轮次 R2）
- **继续输出**:
  - 置信度计算及依据
  - 遗留问题清单（如置信度 0.5-0.8）
  - 对下一步（2-loop）的指导建议
- **回退输出**:
  - 失败原因分析
  - 建议新轮次如何调整分解

## 置信度计算

- 基础置信度 = 已通过验证的子任务数 / 总任务数
- 修正因子：信息缺口 × 0.1 / 验证深度 × 0.05 / 假设覆盖 × 0.15
- 最终置信度 = min(1.0, 基础置信度 + 修正因子)

## 执行要求

1. 检查 plan.md 定义的目标是否达成
2. 检查所有约束是否满足
3. 检查所有假设是否验证
4. 诚实标注不确定性
5. 置信度 < 0.8 时，明确告诉 Commander 哪些环节需要加强

## Gold Case

- 诚实标注不确定性
- 置信度 < 0.8 时，明确告诉 Commander 哪些环节需要加强

## Bad Case

- 置信度 "看起来很高" 当实际验证不足
- 把 "未尝试" 当 "已通过"
