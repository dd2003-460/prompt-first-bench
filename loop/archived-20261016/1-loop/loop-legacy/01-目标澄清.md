# 01 目标澄清（目标 / 背景 / 约束 + 分解）

<!-- origin: ai -->

## 输入

- 用户原始意图（raw）、项目背景与已有资料。
- 当前 `loop-state.json.stage`、灵魂默认决策画像（`AGENTS.md` 默认偏好）。

## 本阶段要交付什么

把「要做什么」整理成 **task_spec**，包含四件事：

1. **目标**：要达成的结果、成功标准（success_criteria）。
2. **背景**：已知事实、上下文、相关领域知识。
3. **约束**：硬性边界（预算 / 平台 / 时间 / 技术栈 / 不可行项）。
4. **（初步）分解**：把目标拆成一组可调研 / 可执行的分解项（后续 02 会据此调研、03 会据此执行）。

## 字段表怎么填

- 在 `task_spec.attribute_matrix` 写入字段（**通过 `ralph field-apply` 命令，禁止直接 Write/Edit loop-state.json**）：
  - 目标 / 背景 / 约束 → `confirmed`（已知）或 `assumed_default`（不确定偏好，默认全范围）。
  - 分解项本身先记为 `concept`，其需要的事实标 `research_required`。
- 不确定偏好不追问，直接 `assumed_default`（默认全范围）。
- 只有「用户/项目/环境都无答案、不能推断或研究、且会改变硬可行性/硬预算/验收」的项，才用 `blocked_human`。

## 检查

- [ ] 目标可量化 / 可验证（有成功标准）。
- [ ] 约束显式列出，无隐藏假设。
- [ ] 分解项正交、可覆盖目标、无明显遗漏。
- [ ] 每个分解项已标注其需要的事实（research_required 字段）。
- [ ] 无 `pending` 字段残留。

## 分支

- 通过：返回 `advance`，进入 `02`。
- 信息不足：返回 `rollback`，补足字段后回到 `02` 新 revision。
- 等待人类：返回 `blocked_human`，调度器跳过当前任务。
- 无 ready 任务：返回 `explore`，生成 preference brief 与 candidate task。

## 结构化结果

```json
{
  "action": "advance",
  "status": "passed",
  "stage_id": "01",
  "revision": "r1",
  "next_stage": "02",
  "payload": {
    "task_spec": "<即 loop-state.json 里的 task_spec（含完整 attribute_matrix）>"
  }
}
```

## 必须遵守

1. 阶段编号 `01`；重新澄清用 `01-r2`、`01-r3`。
2. 禁止在本阶段做 deep-research / 最终推荐；只做澄清与分解。
3. 完成前须派发 requirements-auditor（需求分流闸门）。
4. 见 `loop/1-loop/00-综述.md` 字段中心模式与阶段管线。
