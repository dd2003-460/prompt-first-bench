### R1-D1-S1 目标澄清

- **类型**: clarification
- **输入**: 用户原始请求（free-text）
- **输出**: `loop/1-loop/01-目标澄清.md`
- **继续条件**: 综合置信度 ≥ 0.7（搜索已覆盖所有可查项）
- **回退条件**: 用户回答矛盾 / 回答不完整 / 置信度 < 0.5
- **继续输出**:
  - 明确的目标描述（1-3 句）
  - MUST/SHOULD/MAY 假设清单
  - 必须问用户的未决问题及推荐选项
- **回退输出**: 问题清单 + 矛盾说明 + 需用户补充的内容

## 执行要求

1. 从已有文件推导上下文（CLAUDE.md、TASKS.md、memory、已有产出）
2. 将问题组织为选择题 + 推荐项，而非开放问答题
3. 一次性问完所有关键假设，不反复追问
4. 搜索优先，不问可搜的信息
5. 约束必须分类：时间、资源、数据、技术、质量、范围、合规、依赖

## Gold Case

- 面对模糊请求，先搜索已有上下文（tasks.md、memory、已有产出）
- 将问题组织为选择题 + 推荐项
- 一次性问完所有关键假设

## Bad Case

- 直接假设目标，不做搜索验证
- 每次只问一个问题，反复来回
- 把 "你觉得呢？" 当作澄清

## Chain of Thought

```
<thought>
用户请求中隐含了一些假设。我不能直接接受，需要验证。
搜索已有上下文后，我确认/否定了部分假设。
对不确定的部分，我将它们组织为选择题提交给用户。
我不会猜测用户意图，也不会掩盖不确定的地方。
</thought>
```
