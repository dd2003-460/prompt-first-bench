## 本阶段要做什么

把已调研、已验证的目标分解为**可独立执行的最小单元**，并明确模块边界与接口：

1. **分解到最小执行单元**：像 01 分解目标一样，把执行工作递归拆到「不可再分、可独立派发/执行」的单元。每个单元有明确的输入、输出、验收。
2. **接口清晰对准**：单元之间只通过**显式接口**通信；每个接口定义清楚：输入格式、输出格式、错误契约。上下游单元的接口必须一一对准（生产者输出 = 消费者输入），不留模糊地带。
3. **模块化、解耦**：单元之间低耦合、高内聚；一个单元的改动不应传导到无关单元。按关注点划分模块（如「数据采集 / 分析 / 验证 / 综合」），模块内部自洽、模块间只走接口。
4. **并行与依赖**：在 DAG 中标注哪些单元可并行、哪些有先后依赖；跨单元交叉验证单独成节点。
5. 产出 `task_graph`（DAG：节点 = 最小执行单元，边 = 依赖/接口）与 `coverage_proof`（任务图完整覆盖目标、约束、成功标准，无遗漏无冲突）。`task_graph` 必须是 JSON 对象，字段 role 必须精确为 `task_graph`；把 NODE-1 等描述写在 `attribute` 文本里不算 DAG。
6. **执行而非只规划**：对每个 ready 节点，先真实写出该节点 `writes` 声明的项目内非空文件，再把 output/evidence 写回该节点 JSON 并运行 `ralph graph-apply <项目> <节点文件>`。只有全部节点都有 `task_results` 和 `artifact_refs` 后才能 advance 到 04。

## 检查

- [ ] 任务图分解到最小执行单元，无过度拆分也无遗漏。
- [ ] 模块间接口显式、对准、解耦，无模糊依赖。
- [ ] DAG 无环、任务 ID 唯一、并行组正交。
- [ ] `coverage_proof` 证明完整覆盖目标/约束/成功标准。
- [ ] 每个 DAG 节点的 `writes` 文件实际存在且非空，`ralph graph-apply` 已记录 output/evidence/artifact_refs。
