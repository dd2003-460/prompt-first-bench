# 02 任务分解（调研分解结果）

<!-- origin: ai -->

## 输入

- `01-目标澄清.md` 的结构化结果（task_spec + 分解项 + research_required 字段）。
- 技术背景与约束证据。
- 当前 `loop-state.json.stage`。

## 本阶段要交付什么

把 01 的分解项**调研清楚**，使每个分解项都带有可执行的调研结果：

- 对每个 `research_required` 字段派**窄调研 subagent**（只填这一个字段），带回 `evidence_refs`。
- 调研完成后字段处置变为 `confirmed` 或 `assumed_default`（若证据推翻原假设）。
- 调研中引出的新未知项，作为新的 `pending` 字段继续增殖，直到无 `pending`。
- 同时为每个分解项整理「后续执行需要什么」（研究计划 / 子任务雏形），供 03 细化。

## 执行要求

- [ ] 每个分解项的事实都已调研并通过 `ralph field-apply` 写回 attribute_matrix（禁止直接改 loop-state.json）。
- [ ] 每个 research_required 字段都带 evidence_refs。
- [ ] 无 `pending` 字段残留。
- [ ] 每个分解项标注：需不需要进一步执行（调研类 / 执行类 / 后续行动类）。
- [ ] DAG 无环、任务 ID 唯一、并行组正交。

## Gold Case

- 分解项的每个事实都有可溯源证据。
- 调研引出的新字段被消化，无遗留 pending。

## Bad Case

- 只列分解项不调研（字段停在 research_required 无 evidence）。
- 隐藏假设未标 assumed_default。

## 输出

- 完整 attribute_matrix（调研完成的字段）。
- 每个分解项的「后续执行计划」雏形（供 03）。
- 覆盖证明、风险注记。

## 必须遵守

1. 阶段编号 `02`；重新分解用 `02-r2`、`02-r3`。
2. 本阶段只做调研与分解确认，**不做交叉验证**（交叉验证在 02.5）。
3. 完成前须派发 dag-auditor（分解审计）。
4. 见 `loop/1-loop/00-综述.md` 与 `02.5-交叉验证.md`。

## 分支

- 通过：返回 `advance`，进入 `02.5`。
- 信息不足：返回 `rollback`，回到 `01` 或当前 `02` 新 revision。
- 等待人类：返回 `blocked_human`。
- 无 ready 任务：返回 `explore`。
