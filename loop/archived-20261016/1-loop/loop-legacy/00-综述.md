# 0 综述：RALPH 1-loop 阶段方法论

<!-- origin: ai -->

> 1-loop 是「信息搜集（AR）→ 澄清 → 规划 → 执行 → 验证 → 综合」的强制流程。
> 任何理论研究 / 调研任务，必须先经过 1-loop 信息搜集，才能进入执行（2-loop）。
> 本文件定义阶段总览；各阶段细节见 `01-目标澄清.md` ~ `04.5-交叉验证.md`。

## 阶段文件约定（每阶段只一对，命名 `0x-rx`，链式传递）

- 每个阶段只产出**一个 JSON**：`loop-artifacts/{阶段}-{轮次}.json`（结构化字段，agent 唯一要写的文件）。
- 对应的 `{阶段}-{轮次}.md`（易读 Markdown）**由 `ralph render` 或从 `field-apply` 落盘时自动从 JSON 生成，agent 不必手写**，避免 md/json 不一致、也减轻 agent 负担。
   例：`loop-artifacts/01-r1.json` + 自动生成 `loop-artifacts/01-r1.md`、`loop-artifacts/02.5-r1.json` + 自动生成 `loop-artifacts/02.5-r1.md` ……
- **上一阶段的 `0x-rx.json` 输出，即本阶段的输入**（链式 pipeline，读 json 即可；需人读看同目录 `.md`）；首阶段 01 从 `loop-state.json` 的任务与已知背景开始。
- 命名最简，方便校验按名找文件：`ralph validate --result loop-artifacts/{阶段}-{轮次}.json`。
- 字段落盘走 `ralph field-apply <项目> loop-artifacts/{阶段}-{轮次}.json`（校验通过才原子写入 `loop-state.json`，并自动渲染 `.md`）。

## 字段中心（轻量）模式

- 运行时以 `RALPH_FIELD_GATE=1` 启动时进入字段中心模式：Commander **通过 `ralph field-apply` 命令维护**
  `loop-state.json` 的 `task_spec.attribute_matrix`，不强制子代理卡片。
- **严禁 Commander 用 Write/Edit 直接修改 `loop-state.json`**（整文件手写极易产生非法 JSON 导致循环崩溃）。
  字段更新一律写成小增量 JSON，运行 `ralph field-apply <项目> <字段文件>`，校验通过才由 runtime 原子落盘。
  文件损坏或需回退时运行 `ralph recover-state <项目>`（默认从 `.bak` 恢复，或 `--stage <id>` 重置到上一阶段快照）。
- 每阶段结果是把该阶段需要的「事实」整理成一组字段写回 attribute_matrix；
  系统按 disposition 完整性（无 `pending`、无未带 `evidence_refs` 的 `research_required`）自动推进。
- 详见 `templates/stage_prompt_fieldcentric.md` 与各阶段文档（`loop/1-loop/0x-*.md`）。

## 交叉验证（X.5）统一机制

所有 `.5` 阶段（02.5 / 04.5）遵循同一机制，差异仅在「验证对象」：

1. **主 agent（Commander）只派发 subagent**，自身不直接去问；每条待验证字段生成一张
   builder 卡，**卡内嵌该字段的当前内容**作为参数（concept / attribute / disposition /
   evidence / rationale）。
2. **subagent 拿字段内容去问各种网页 LLM + 权威数据**，逐字段检查矛盾与冲突：
   - 网页 LLM 地址与做法见 `02.5-交叉验证.md` / `04.5-交叉验证.md` 的「网页 LLM 清单」。
   - 每条字段向至少 2~3 个不同网页 LLM 提同一验证问题；同时用 WebSearch 查权威来源
     （论文、官方规格、基准测试、厂商文档）。
3. **比较与裁决**：不同 LLM / 来源间是否矛盾冲突；更新字段的 confidence、disposition、
   evidence_refs、rationale（含矛盾说明），并产出交叉验证摘要。

## 公共纪律

- 所有产出文件标注 `# origin: human` 或 `# origin: ai`。
- 不静默 / 不暂停；过程可见；完成 ≠ 质量达标（对标顶刊 / 可扩散水平）。
- 缺信息先研究（WebSearch / WebFetch / 派调研 subagent），不可自行解析且改变硬可行性 / 硬预算 / 验收的才 `blocked_human`。
