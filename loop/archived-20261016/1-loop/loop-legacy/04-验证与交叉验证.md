# 04 验证与交叉验证

<!-- origin: ai -->

## 输入

- `03-子任务执行.md` 的产物（execution_summary + 子任务产出）。
- 任务定义中的成功、失败和证据条件。
- 代码测试、外部来源或交叉验证结果。

## 本阶段要交付什么

把 03 的执行产物整理成**事实账本（claim ledger）**并核验：

1. 每个关键 claim 必须有数值/上下文、来源链接、来源类型、日期、适用条件、复核者和状态。
2. 无来源或无法复核的断言必须标 `uncertain` / `rejected`，不能进入最终推荐。
3. 并行结果是否存在冲突；Join 输入是否完整。
4. 本阶段做「验证」（事实账本 + 一致性核验）；**逐源交叉验证在 04.5**。

## 检查

- [ ] 输出覆盖任务定义。
- [ ] 证据可复现。
- [ ] 无未声明的副作用。
- [ ] 并行结果冲突已记录。
- [ ] Join 输入完整。

## 输出

- 事实账本（claim ledger）：claim / source_url / source_type / checked_by / status。
- 核验摘要：结论与残余不确定性。

## 必须遵守

1. 阶段编号 `04`；重新验证用 `04-r2`、`04-r3`。
2. 完成前须派发 evidence-verifier。
3. 见 `04.5-交叉验证.md`（产出后交叉验证）。

## 分支

- 验证通过：返回 `advance`，进入 `04.5`。
- 验证失败：返回 `rollback`，创建修复任务或新 plan revision。
- 信息不足：标记 `blocked_human`。
- 无 ready 任务：返回 `explore`。
