## 本阶段交付物（每阶段只一对文件，命名 `0x-rx`，链式传递）

- `loop-artifacts/02.5-r1.json`：**你只需写这个**——结构化结果，含更新后的字段（矛盾处置、更新后的 `confidence`/`disposition`/`evidence_refs`），用 `ralph field-apply <项目> loop-artifacts/02.5-r1.json` 落盘。
- `loop-artifacts/02.5-r1.md`：可读性 Markdown，**由 `ralph render` / field-apply 自动从 JSON 生成，你不必手写**。
- **下一阶段（03）的输入就是本阶段的 `02.5-r1.md` / `02.5-r1.json`**。

## 本阶段要做什么

基于 02 的调研结果，逐字段交叉验证，检查矛盾与冲突：

1. **Commander 只派发 subagent**，自身不直接去问；每条待验证字段生成一张 builder 卡，**卡内嵌该字段的当前内容**（concept / attribute / disposition / evidence / rationale）作为参数。
2. **subagent 拿字段内容去核验**：用 `WebSearch`（论文、官方规格、基准测试、厂商文档——自动化环境最可靠）为主，可用 `WebFetch` 抓**公开文本页**（`https://arxiv.org/abs/<id>`、厂商规格页如 `nvidia.com/en-us/data-center/h100/`、`amd.com/.../instinct-mi300x`、`cloud.google.com/tpu/docs/...`）。**禁止对所有纯 JS 聊天页（perplexity.ai / chatgpt.com / claude.ai / gemini.google.com / grok.com / copilot.microsoft.com / arena.ai/agent / poe.com / bigmodel.cn / aistudio.google.com）做 WebFetch——这些页自动抓取返回空，会无限空转。** 对其中已由人类授权且受运行时支持的站点，字段 worker 必须把同一 claim 写进当前阶段 task/request JSON 并运行 `ralph web-llm-check . <request.json>`：该命令由**本地 Agent 自己**启动新鲜的可见 Playwright 窗口、逐字输入问题、提交并读取回复；它不读取 cookie/凭据，也不尝试登录。只有命令产生的、含 ≥2 个成功 provider 的回执才能声称“网页 LLM 已询问”。未授权或无回执时明确记为 `llm_status=not_authorized`，只能声称已做权威来源交叉核验。
3. **比较与裁决**：不同 LLM / 来源之间是否矛盾冲突；更新字段的 `confidence`、`disposition`、`evidence_refs`、`rationale`（含矛盾说明）。LLM 回答只能作为反驳/遗漏发现信号，不能替代两份独立权威来源来证明事实。**网页搜索/抓取/登录失败、返回空结果或无法获得具体页面时，必须保留 `research_required`/`uncertain` 并记录失败；严禁把训练记忆或站点首页改写成“已验证”。**
4. 产出交叉验证摘要，记录哪些字段被复核、哪些存在未决矛盾。

## 字段表怎么填（通过 `ralph field-apply`，禁止直接写 loop-state.json）

- 把更新后的字段写成 `02.5-r1.json`（列表，或 `{"fields":[...]}`），运行
  `ralph field-apply <项目> loop-artifacts/02.5-r1.json` 原子落盘（按 `concept` 合并）。
- 交叉验证字段必须包含 `validation_records` 数组；每条至少有 `claim_ref`（对应 02 字段 concept）、`source_refs`（两个不同域名的**具体** HTTPS 页面）、`observed_at`（ISO 日期/时间）和 `verdict`（`supported` / `contradicted` / `uncertain`）。一段“多源一致”的摘要不算记录。
- 已配置两个网页 LLM provider 时，`evidence_refs` 还必须引用 `ralph web-llm-check` 写入当前阶段 `web-llm/*.json` 的成功回执；没有成功回执时只能写 `llm_status=failed`/`not_authorized`，不得声称已询问网页 LLM。
