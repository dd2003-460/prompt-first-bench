# 科研方法论 SOP — 从零到可验证结果

> **适用场景**：理论物理/数学/计算科学的独立研究
> **版本**：v1.0 (2026-06-27)
> **核心哲学**：不是"做完任务"，而是"做正确的事 + 验证做得正确"

---

## 总览：从问题到答案的十二步路

```
I 有 一 个 问 题
  │
  ▼
[1-loop: 规划]           →  6 个阶段，确保方向正确
  │
  ▼
┌──────────────────────┐
│  决策点：值得做吗？   │
│  enter_2loop = true   │
└──────────────────────┘
  │
  ▼
[2-loop: 执行]           →  6 个阶段，确保执行正确
  │
  ▼
┌──────────────────────┐
│  决策点：结果是真的   │
│  吗？置信度>0.6?      │
└──────────────────────┘
  │
  ▼
信 任 的 结 果
```

**为什么要分成 1-loop（规划）和 2-loop（执行）？**

因为人类/AI 有两个完全不同的认知模式：
- **规划模式**需要发散思维、质疑、考虑多种可能性——但**不写代码、不试方法**
- **执行模式**需要专注、严格按照顺序推进——但**不改方向、不纠结替代方案**

把两者混在一起是 90% 科研失败的原因。比如 QNM 项目的教训：
- 在第 1 轮 1-loop 就进入了"试 AIM"的执行
- 没有经过完备核验就跳过了"FDTD 已经失败了"这个关键信息
- 结果做了 20+ 次 AIM solver 变体，全部产出 false eigenvalues
- **如果预先做了阶段 5 的 gap_analysis，就会发现 AIM 在这类问题上的结构性失效**

## [阶段 1] 任务澄清 — 你到底要解决什么？

**输入**：raw requirement（一句话想法 / 用户指令 / 文献空白）
**输出**：`task-definition.md`
**核心问题**：任务边界是什么？什么不算在做里面？

### 你必须写下的内容

```markdown
## 任务定义
- **一句话目标**：用最精炼的话描述要做什么
- **输入条件**：已经有的东西（数据、公式、代码、文献）
- **输出期望**：做完了长什么样？一个数值？一个结论？一个论文草稿？
- **边界**：明确不做哪些事
- **失败标准**：什么情况下这一步算"失败了"，需要换个方向？
```

### 为什么这一步不可跳过

没有明确边界的任务会在执行中无限膨胀。一个完整的任务定义应该在执行前就帮你识别"什么东西不该碰"。

### QNM 案例：一个本可以避免的迷路

**原始想法**："计算 a=0.95 的 Kerr QNM 频率"

这个想法没有任何边界。正确的任务澄清应该是：

```markdown
## 任务定义 (修正后)
- **一句话目标**：验证 a=0.95 Kerr BH 的 QNM 频率，使用可验证的数值方法
- **输入条件**：
  - I-5 已证明面积量子化在 QNM 层面不产生可观测频移
  - FDTD 在 a<=0.5 范围内通过验证 (06-kerr-qnm-scan)
  - Teukolsky 方程是 Kerr QNM 的唯一有效方程（RW 方程不适用于 Kerr）
- **输出期望**：一组可信的 QNM 频率数值（与 Berti PRD 2009 基准对比）
- **边界**：不发明新方程，不依赖没有经过验证的修正势
- **失败标准**：如果所有方法都在 a>0.7 失败，停止并报告结论
```

**关键教训**：如果你在第 1 轮就写下"失败标准：a>0.7 都失败则停止"，你不会有后面 20 次 AIM 变体的浪费。

### 自我质询清单（副脑必做）

1. 这个任务真的在问一个问题吗？还是只是在操作？
2. 如果不做这件事，最坏的结果是什么？
3. 有没有更简单的方法先回答一半的问题？
4. **我已经知道了什么？什么是真正不知道需要验证的？**

## [阶段 2] 目标澄清 — 成功的判定标准

**输入**：`task-definition.md`
**输出**：`acceptance-criteria.md`
**核心问题**：怎么知道做完了？怎么做才算对？

### 验收标准的格式

```markdown
## 验收标准
### 硬性标准（必须满足）
- [ ] 数值结果与已知基准的误差 < X%
- [ ] 代码/推导可以独立运行/复现
- [ ] 每个关键步骤有书面记录

### 质量标准（应当满足）
- [ ] 覆盖了极端参数范围
- [ ] 有误差估计
- [ ] 结果可以直观理解

### 可妥协部分
- [ ] 如果时间不够，哪些部分可以降到 X 精度？
```

### 为什么这一步不可跳过

没有验收标准的研究就是"在数据里游泳"——游了很久，但不知道到了哪里。每个标准应该是：
- **可量化的**（"误差 < 5%"而不是"误差很小"）
- **有基准的**（跟谁比？）
- **有工具验证的**（不是凭感觉）

### QNM 案例：没有基准的损失

在 QNM 项目中，没有预先设定"Berti PRD 2009 是基准，误差 > 5% 的结果必须标记为失败"这条标准。

结果：
- 做了 8 种 AIM solver 变体，每种都跑了几十个频率点
- 但是没有"0.374-0.089i 就是对的"这个锚
- 每次发现一个"收敛"的频率就以为做对了，反复探索错误的收敛
- **如果预设有基准，第一种 AIM 变体测完就发现 30% 误差，就会终止而不是继续**

## [阶段 3] 任务分解 — 拆解到每个步骤都可验证

**输入**：`acceptance-criteria.md`
**输出**：`task-decomposition.md`
**核心问题**：每个步骤是否可以被独立执行、独立验证？

### DAG 格式

每个子任务必须是"原子"的：
- 输入：明确的文件/公式/数据
- 输出：明确的文件/数值/结论
- 验证：如何做？测试什么？
- 回滚：如果失败怎么恢复？
- 置信度：[0, 1]，你做这件事的把握有多大？

```markdown
### 任务 #3
- **目标**：实现 Teukolsky 方程的 AIM 求解器
- **输入**：Berti PRD 2009 公式 (11)-(18)
- **输出**：`teukolsky-aim-solver.py` 文件
- **验证**：在 Schwarzschild (a=0) 极限下复现 Berti 的 l=2, m=0 QNM
- **回滚**：备份当前 solver，保留旧版本
- **置信度**：0.6（理论可行但从未试过）
```

### 粒度的黄金法则

每个任务应该让**一个 agent 在单次上下文中可以独立完成**——不需要中途查别的文件，不需要回忆之前的决策。

任务之间的接口**只通过文件**传递，不靠口头描述。

### QNM 案例：分解缺失的后果

在 QNM 的早期迭代中，任务分解是"尝试旋转修正"和"尝试 AIM"这样的大块。每个大块内部没有进一步的原子分解：
- "尝试 AIM"包含了：读 Teukolsky 方程 -> 写系数 -> 实现收敛标准 -> 测试
- 没有每一步独立的验证标准
- AIM 在第一步（实现收敛标准）就出了问题，但没有被识别

### 分解后的结构应该是：

```
任务 1: 读 Berti 2009 -> 提取公式 -> 输出 formulas.md (验证：公式编号对照)
任务 2: 实现 Schwarzschild 退化版本 -> 跑 a=0 -> 输出 schw-test-result.md
  (验证：结果与 Price 1972 对比，误差 < 5%)
任务 3: 泛化到 Kerr -> 实现 a>0 的系数
  (验证：与 Berti 表中 a=0.1,0.5 数据对比)
...
```

## [阶段 4] 信息搜集 — 你手上的牌和桌上的牌

**输入**：`task-decomposition.md`
**输出**：`tool-inventory.md` + `novelty-assessment` (N0-N3)
**核心问题**：你缺什么？别人做过什么？你的贡献在哪？

### 工具清单的格式

```markdown
## 已验证可用的工具
| 工具 | 版本/来源 | 验证方式 | 置信度 |
|------|-----------|----------|--------|
| scipy.integrate.odeint | scipy 1.11 | 跑通了 Schwarzschild test | 0.9 |
| Berti PRD 2009 | 已提取文本 | 公式可读 | 0.95 |

## 已知但未验证的
| 工具 | 为何有用 | 需要如何验证 | 预计工作量 |

## 不可用的（知道为什么不可用同样重要）
| 工具 | 为什么不可用 | 替代方案 |
```

### 新颖性评估 (N0-N3)

| 等级 | 含义 | 研究性质 |
|------|------|----------|
| N0 | 完全重复已知工作 | 教学练习 |
| N1 | 已知方法应用到新场景 | 增量贡献 |
| N2 | 已知结果的新验证 | 防御性验证 |
| N3 | 全新发现 | 突破性贡献 |

### 信息搜集的优先级

1. **先找基准**：别人已经算过的答案是什么？
2. **再找工具**：有没有现成的代码/公式/库？
3. **最后查新颖性**：你的工作跟别人差在哪？
4. **查空白**：不是"谁做了什么"，而是"什么被忽略了"

### QNM 案例：没有搜索"Berti 2009"的代价

在 40 次迭代中，很多次是**在没有已知基准的情况下试方法**：
- AIM 代码在 a=0.95 上跑了一堆频率，没有一个参考点告诉你对不对
- 而 Berti 2009 实际上精确列出了 (a,l,m) 对应表——但我们在阶段 4 才找到它
- **如果阶段 4 完成了"先读 Berti -> 拿到基准"->"再用 AIM 去逼近"的步骤，1-loop 的规划阶段就可以结束"**

## [阶段 5] 完备核验 — 在投入执行前做一次全景扫描

**输入**：`tool-inventory.md` + `task-decomposition.md`
**输出**：`gap-analysis.json`
**核心问题**：如果我做这件事，最大的风险是什么？现在就走还是以后再填？

### 五个评估维度

```json
{
  "理论完整性": {"rating": "高/中/低", "理由": "一句话", "已知缺口": ["..."]},
  "工程可行性": {"rating": "..."},
  "工具就绪": {"rating": "..."},
  "方向正确性": {"rating": "..."},
  "可回滚性": {"rating": "..."}
}
```

### 何时进入 2-loop

**硬性条件**（必须全部满足）：
- `task-definition.md` 存在且内容完整
- `acceptance-criteria.md` 有可量化的标准
- `tool-inventory.md` 覆盖了所有必需工具
- `gap-analysis.json` 的所有维度中，没有"低"评分

**软条件**：
- 每步粒度：一个 agent 一次上下文可以做
- 没有已知的更优替代方案被遗漏
- 下次迭代的预期增益 < 执行错误成本

### QNM 案例：跳过核验的代价

**如果 QNM 项目在阶段 5 认真做了 gap_analysis，会出现这样的结果：**

```json
{
  "理论完整性": {
    "rating": "低",
    "理由": "RW 方程不适用于 Kerr 旋转黑洞",
    "已知缺口": ["没有 Kerr 正确的波动方程"]
  },
  "工程可行性": {"rating": "中"},
  "工具就绪": {"rating": "低"},
  "方向正确性": {"rating": "低"},
  "可回滚性": {"rating": "高"}
}
```

有了这个结果，正确的决策是：**停。不是做 AIM，而是先解决"Kerr 方程"的问题。**

但当时因为没有阶段 5，直接进入了 AIM 的执行，浪费了大量迭代。

## [阶段 6] 决策 — 停下来问自己值不值

**输入**：`gap-analysis.json`
**输出**：`decision.md`
**核心问题**：继续还是放弃？什么条件下继续？

### decision.md 的格式

```markdown
## 决策
- enter_2loop: true/false
- 置信度: 0.X
- 理由: "..."
- 终止条件: "如果 X 出现则回 1-loop"
- 最重要的风险: "..."
```

### 什么情况下不 enter 2-loop

1. **gap_analysis 中有"低"评分** — 缺口太大，现在不是执行的时候
2. **没有基准参考** — 你做了但不知道对不对
3. **没有明确的风险缓解策略** — 知道最大风险但不知道怎么办
4. **连续两轮 gap_analysis 变化 > 20%** — 规划还在漂移
5. **执行错误成本 > 预期增益** — 不值得冒这个险

### QNM 案例：什么时候应该 stop

在第 5 次迭代时，就已经出现了"RW 方程不适用于 Kerr"的洞察。**决策点**：

- enter_2loop? **不**。因为理论完整性是"低"。
- 继续 1-loop：重新制定任务——"找到 Kerr QNM 的正确计算方法"
- 目标不是"算 a=0.95"，而是"建立可信赖的计算框架"

## 切换到 2-loop：执行

1-loop 的 6 个阶段完成后，进入 2-loop。执行是**严格顺序的**，不并行、不跳步。

### 2-loop 流水线

```
pre-check → backup → execute → verify → confidence → decision
```

### [阶段 1] 预检查 — 入口网关

执行任何工作之前，确认：
- 任务包存在（分解文档对应这一步）
- 阶段允许执行（2-loop 没在收尾状态）
- 核心文件和模块存在
- owner_project、working_paths、expected_outputs 明确

### [阶段 2] 备份 — 做错了能回来

**这是硬要求，不是建议。**

```bash
# 修改任何文件之前
cp file.py backups/2026-06-27/file.py.v1
```

批量修改时每个文件单独备份。备份后 diff 验证完整性。

### [阶段 3] 执行 — 真正做事

- 写文件、搜索、分析、运行代码——**产出可见的变更**
- 不得只写模板然后标完成
- 新脚本/目录落在规范位置
- 如果做了变更，立即在 INDEX.md 更新索引

### [阶段 4] 验证 — 四步核验（不可跳过）

**第 1 步：还原要求** — 列出来每个可验证交付物
**第 2 步：逐一核验** — 有产出？存在且完整？无产出？标记未完成
**第 3 步：质量自检** — 有实质内容？服务目标？无禁止动作？
**第 4 步：置信度** — 诚实打分，必须调用置信度判断

### 置信度评分表

| 评分 | 判定 | 动作 |
|------|------|------|
| < 0.6 | 低 | 不得 completed。标注不确定，生成遗留分支 |
| 0.6 - 0.8 | 中 | 标注不确定，记录未验证假设 |
| > 0.8 | 高 | 正常通过 |

### [阶段 5] 置信度门槛 — 什么时候算"够了"

这不是主观感受，是量化评估：
- **0.8+**: 代码跑通了，结果对了，边界条件测了，和基准对上了
- **0.6-0.8**: 大部分测了，但某个边界条件不确定
- **<0.6**: 不确定。该做什么？**不是继续试，而是记录缺失什么、生成新分支任务**

### [阶段 6] 分叉决策 — 向上还是向下

| 结果 | 条件 | 动作 |
|------|------|------|
| completed | 全部通过 + 置信度 > 0.6 | 标记完成，生成下一步任务 |
| completed_with_branches | 置信度 0.3-0.6 | 标记完成，生成遗留分支 |
| needs_replan | 置信度 < 0.3 或核验未通过 | **回滚，回到 1-loop** |

## 副脑永续：每一轮必须有的质疑

副脑不是独立阶段，而是**嵌在每个循环中的自我质疑**。

### 副脑的固定问题清单

每轮结束时，副脑必须提出：

1. **质疑方向**：你现在做的事还是最初定的目标吗？有没有漂移？
2. **质疑假设**：哪个假设没有经过验证，但你当它真的了？
3. **质疑方法**：有没有更简单的方法能达到同样结果？
4. **质疑边界**：有没有没想到的场景？极端参数？退化情况？
5. **建议新方向**：数据中有没有指向别处的信号？

### 副脑不是"提了就算"

副脑提出的问题不一定要解决。但**必须记录**。每次记录一条副脑问题和建议，就是在 research note 旁边追加一条注释。

## 科研笔记规范：每一步都写 note

### note 的文件命名

```
notes/<step-num>-<step-name>.md
例如:
  01-p0-schw-qnm-results.md     — P0 的结果
  02-p1-kerr-fdti-scan.md       — P1 FDTD scan
  03-p2-teukolsky-analysis.md   — Teukolsky 分析
```

### 每个 note 必须包含

```markdown
## 本步在做什么
一句话

## 关键发现/结果
- ...

## 验证方式
怎么知道是对的？

## 未解决/遗留
- ...

## 副脑质疑（如有）
- Q: ...  A: ...
```

### 为什么这一步不可跳过

没有笔记的研究做完了**也记不住自己做了什么**。以后如果想回到这个项目，需要完全从头理解。

## 快速检查清单

在每个阶段结束时问自己：

**阶段 1 结束**：如果我只读 `task-definition.md`，能准确说出这一步要做什么吗？

**阶段 2 结束**：如果我没做这一步，有人能在不看过程的情况下验证结果吗？

**阶段 3 结束**：每个子任务可以用一句话写给别的 agent 并让他独立完成吗？

**阶段 4 结束**：对于每个"我没试过这个工具"，我写下来了吗？我知道为什么不行吗？

**阶段 5 结束**：如果我现在停止，最大的风险是什么？有缓解策略吗？

**阶段 6 结束**：enter_2loop 之后，我能在不完全理解之前工作的前提下开始 2-loop 吗？如果不能，说明 1-loop 的输出不够清晰。

**2-loop 每轮结束**：如果我被通知停掉，我留下的笔记和代码让别人能在完全不了解上下文的情况下继续吗？

## 常见陷阱与应对

### 陷阱 1：在阶段 4 之前就开始试方法

症状：想着想着就开始写代码了。

原因：执行模式比规划模式更令人兴奋。

应对：**写下来。** 任务分解的每个步骤必须是文字描述，不是代码。代码只在 2-loop 的 execute 阶段出现。

### 陷阱 2：置信度造假

症状：所有置信度都标 0.9，但实际没怎么测。

原因：想把流程走完。

应对：**诚实。** 置信度是自主决策的唯一指标。假的置信度 = 盲动 = 浪费迭代。

### 陷阱 3：跳过备份

症状：改了一堆代码发现方向不对，改不回去了。

应对：**每改一个文件就先备份。** 这是最小的代价（2 秒）换最大的安全感。

### 陷阱 4：把分析当执行

症状：分析了很久 AIM 的理论，但没有跑出一行代码。

应对：分析也可以是有输出的——输出应该是 note，描述你分析了什么、得出了什么结论。**如果有分析结论，阶段 4 就更新工具清单，阶段 5 更新 gap_analysis。**

### 陷阱 5：不放弃

症状：方法明显失效了（AIM 误差 30%+），还反复试变体。

应对：**预置终止条件。** 阶段 6 的 decision.md 中明确写"如果第 X 种方法在 Y 参数上误差 > Z%，终止并报告结论"。

## 与工具相关的约定

### 文件结构

```
项目/
  INDEX.md                    # 纯索引：这个目录下有什么
  memory/                     # 完整探索记录（不可删除）
    01-step-name.md
    02-another-step.md
  tasks/                      # 当前临时状态（可修改）
  backups/                    # 执行备份
    YYYY-MM-DD/
  data/                       # 原始数据
notes/                        # 研究笔记
  INDEX.md                    # 笔记索引
loop-state.json              # 全局状态
```

### 命名约定

- Markdown 文件用 kebab-case: `01-p0-results.md`
- Python 文件用 snake_case: `teukolsky_aim_solver.py`
- 备份目录用日期: `backups/2026-06-27/`

## 自我总结：这套方法为什么有效

```
你需要的不是更多的知识，而是更少的错误方向。

这套方法的价值不在"遵循流程"，在以下三点：

1. 1-loop/2-loop 分离：不让执行冲垮规划，不让规划淹没执行
2. 验证门禁：做完了不代表做对了，验证是独立的阶段
3. 决策门禁：不做没有止损方案的尝试

一个有门禁的流程 > 一个靠直觉的马拉松。
```
