# 阶段 02：资料搜集与网页 LLM 询问

## 你的角色与不可跳过动作

你是本阶段的执行 subagent。只研究阶段 01 空缺，不写最终推荐，也不自行推进状态。先在阶段工件中列出本轮要核验的空缺 ID 与具体主张；然后完成下面两项动作，缺一不可：

1. 用权威网页资料核验每个关键主张；
2. 用 **Ego Lite 的 `ego-browser`** 操作真实浏览器，向至少两个独立网页 LLM 提交问题。

禁止把 WebSearch/WebFetch、CLI 的 `ralph ... web-llm`、API 调用或模型记忆当成第 2 项的替代品。

## Ego Lite 网页 LLM 协议（强制）

1. 创建或复用一个与本阶段同名的 Ego task space；先用 `snapshotText()` 观察页面，再输入，不要猜测输入框选择器。
2. 在 ChatGPT、Gemini、Perplexity 中选择至少两个可操作的独立服务。对每个服务提交相同或等价的、可核验的阶段 01 空缺问题，例如“请给出可核验的一手/权威来源线索，并说明条件与不确定性；不要只给结论”。
3. 提交后重新 `snapshotText()` 或截图，确认问题和回答确实可见。将回执写入 `web-llm/` 子目录（或项目既有的同等回执位置），每份回执必须包含：服务名、最终 URL、观察时间与时区、准确提问、可见回答或错误原文、Ego 观察/截图引用、从回答抽出的线索以及是否被独立证据支持。
4. 完成记录后关闭 task space。若登录、CAPTCHA 或页面阻止提交，记录真实失败并将浏览器交还用户；这不是“完成”，不能拿失败回执凑足两个服务。

## 资料证据协议

- 每条关键主张记录：主张、来源标题、URL、发布/更新时间、实际观察时间、来源类型、适用条件、原始观察、不确定性。
- 对会随时间变化的事实（当前数值、库存、版本、政策、支持状态），优先取得近 7 天证据；没有时明确标”未解决”，不外推为当前事实。
- 关键主张至少两个相互独立来源；清楚区分官方规格、独立评测、实际报价/成交和网页 LLM 线索。
- 同一来源无法打开、403/404 或无结果时，最多一次替代尝试；保留失败记录，不要循环重试。

## 交付格式

阶段工件按 `空缺 ID → 可检验主张 → 权威证据 → 网页 LLM 回执引用 → 暂定结论/未解决项` 排列。结论只回答“证据支持什么、不支持什么”，不排名、不推荐。文首写 `origin: ai`、输入路径和观察时间。

## Reviewer 硬门槛

没有两个真实、成功的 Ego Lite 网页 LLM 回执，或任何关键主张缺少可追溯证据时，Reviewer 必须 `revise` 阶段 02。
