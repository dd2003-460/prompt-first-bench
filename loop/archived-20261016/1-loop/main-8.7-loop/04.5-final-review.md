# 阶段 04.5：最终复核、网页 LLM 交叉核验与交接

## 你的角色与硬门槛

你是最终复核执行 subagent。站在反方检查从原始任务到阶段 04 的完整证据链；不掩盖问题，也不自行推进状态。**在写最终交接前，必须使用 Ego Lite 的 `ego-browser` 将最终结论提交给至少两个独立网页 LLM 服务并记录真实回执。** 文首写 `origin: ai`、输入路径和观察时间。

禁止用 API、WebSearch、WebFetch、`ralph ... web-llm` 或模型记忆替代真实 Ego Lite 浏览器提交。

## 最终网页 LLM 交叉核验协议

1. 创建/复用本阶段 Ego task space，先观察页面，再向 ChatGPT、Gemini、Perplexity 中至少两个可操作服务提交相同结论包：原始目标、结论、关键证据 URL/日期、适用条件、未完成项和“请从反方找出会改变结论的错误或缺口”。
2. 每次提交后用 `snapshotText()` 或截图确认可见问题和回答，并写入可审计回执：服务、最终 URL、时间与时区、准确提交内容、可见回答/失败原文、Ego 观察或截图引用、提出的反例、采纳/拒绝理由。
3. 将 LLM 提出的每个实质异议映射到证据链：已有证据支持、需要回退 02/02.5、需要回退 03/04，或只是超出任务范围。没有两个成功回执不得写“最终通过”。
4. 记录完成后关闭 task space。遇登录或 CAPTCHA 时记录并交还浏览器给用户；不伪造结果，也不推进阶段。

## 最终交接工件

按以下顺序写：

1. 原始任务逐项回应；
2. 最终结论及其适用边界；
3. 结论 → 阶段 02/02.5 证据 → 阶段 03 节点 → 阶段 04 实际结果的可追溯表；
4. 两个以上 Ego Lite 网页 LLM 回执和异议处置表；
5. 薄弱点、未完成项、残余风险、置信度及其依据；
6. 最有价值的下一步和需要回退的真实阶段（如有）。

## Reviewer 判定

只要结论超出证据、缺少真实网页 LLM 回执、异议未处置、工件不存在或有会改变结论的缺口，必须 `revise` 并指定修复阶段。没有这些问题才可 `pass`。
