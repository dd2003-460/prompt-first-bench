# 阶段 02.5：交叉核验与矛盾

## 操作流程

1. 逐项检查阶段 02 的关键主张、来源和观察时间。
2. 比较不同来源的定义、测量条件、样本、时间和利益关系。
3. **口径回溯一致性**（2026-11-07 补丁，源自 S10 "14x" 案例；同日两次修订：① 成璐指出不是单位换算问题，是控制变量问题；② 再次修订——"三要素"是 GPU 域特化枚举，通用形式是口径回溯）：两个数字被拿来比较或做比值前，先找到它们的**最近公共参考节点**（即两个数字在各自定义链上往上追溯时第一个汇合的基准量），然后检查从各自出发到该节点的每条中间边上口径是否一致。不一致的边（聚合方式、标称/实测、测试条件、统计口径等，具体变量名随领域而变）要么换算对齐再比，要么明确标注"不可比"。各自真实但口径链不同的数字不能直接比。**断言书写要求**：每个关键数字必须带完整口径描述（定义链上的关键节点都写出来），裸数字视为信息不完整，下游使用即出错。GPU 域的实例化：介质（HBM/NVLink/PCIe）、单双向、互联层级（die/chip/node）就是那条口径链上的三个中间边。
4. 解释一致处和矛盾处；不能解释时保留不确定性，不强行收敛。
5. 检查网页 LLM 的结论是否被独立来源支持。
6. **对抗核验**（2026-10-29 r29 补丁，成璐指令）：对 arena/LLM 给出的核验结论本身发起攻击——主动找其论证漏洞（前提未验证？样本偏置？把相关当因果？来源与结论不匹配？），反驳后继续追问下一轮，直到碰到硬边界才停：**数学理论瓶颈**（需要学界未定论的理论工具）或**个人信息搜集瓶颈**（穷尽可查渠道仍拿不到）。禁止把"对方说 pass/有效"直接当终局。
7. 形成可以交给行动分解阶段使用的证据边界。

## Reviewer 质检标准

- 关键结论是否真正经过独立来源比较；
- 矛盾是否有具体解释，而不是只写"基本一致"；
- 被比较的数字是否口径链一致（找到最近公共参考节点，逐边核对），不一致的是否已换算或标注"不可比"；关键数字是否带完整口径描述（裸数字 = 不合格）；
- 是否混淆理论规格、实测性能、当前价格和个人推断；
- 是否遗漏会改变结论的反例；
- 是否清楚标注仍未解决的问题；
- 对核验方结论是否做过至少一轮主动质疑，质疑点与停止理由（碰到的瓶颈类型）是否记录在案。

如果需要补充新资料，repair_stage 写 02；如果资料充分但核验表达不完整，repair_stage 写 02.5。
