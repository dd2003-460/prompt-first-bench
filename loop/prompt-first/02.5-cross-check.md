# 阶段 02.5：交叉核验与矛盾

## 操作流程

1. 逐项检查阶段 02 的关键主张、来源和观察时间。
2. 比较不同来源的定义、测量条件、样本、时间和利益关系。
3. 解释一致处和矛盾处；不能解释时保留不确定性，不强行收敛。
4. 检查网页 LLM 的结论是否被独立来源支持。
5. **对抗核验**（2026-10-29 r29 补丁，成璐指令）：对 arena/LLM 给出的核验结论本身发起攻击——主动找其论证漏洞（前提未验证？样本偏置？把相关当因果？来源与结论不匹配？），反驳后继续追问下一轮，直到碰到硬边界才停：**数学理论瓶颈**（需要学界未定论的理论工具）或**个人信息搜集瓶颈**（穷尽可查渠道仍拿不到）。禁止把"对方说 pass/有效"直接当终局。
6. 形成可以交给行动分解阶段使用的证据边界。

## Reviewer 质检标准

- 关键结论是否真正经过独立来源比较；
- 矛盾是否有具体解释，而不是只写"基本一致"；
- 是否混淆理论规格、实测性能、当前价格和个人推断；
- 是否遗漏会改变结论的反例；
- 是否清楚标注仍未解决的问题；
- 对核验方结论是否做过至少一轮主动质疑，质疑点与停止理由（碰到的瓶颈类型）是否记录在案。

如果需要补充新资料，repair_stage 写 02；如果资料充分但核验表达不完整，repair_stage 写 02.5。
