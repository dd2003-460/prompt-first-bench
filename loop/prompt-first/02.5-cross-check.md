# 阶段 02.5：交叉核验与矛盾

## 操作流程

1. 逐项检查阶段 02 的关键主张、来源和观察时间。
2. 比较不同来源的**定义、测量条件、样本、时间、利益关系**；解释一致处与矛盾处，**不能解释时保留不确定性，不强行收敛**。
3. 检查网页 LLM 的结论是否被独立来源支持。
4. **对抗核验**（2026-10-29 r29 补丁 · 成璐指令）：对 arena/LLM 的核验结论本身发起攻击——找论证漏洞（前提未验证？样本偏置？把相关当因果？来源与结论不匹配？），反驳后继续追问，**直到碰上硬边界**：**数学理论瓶颈**（需学界未定论的工具）或**个人信息搜集瓶颈**（穷尽渠道仍拿不到）。**禁止把「对方说 pass/有效」当终局。**
5. 形成可交给行动分解阶段的**证据边界**。

## Reviewer 质检标准

- 关键结论是否真正经过独立来源比较；矛盾是否有具体解释（不是「基本一致」）。
- 是否混淆理论规格/实测性能/当前价格/个人推断；是否遗漏会改变结论的反例；是否清楚标注未解决问题。
- 对核验方结论是否做过**至少一轮主动质疑**，质疑点与停止理由（瓶颈类型）是否记录在案。

补资料 → `repair_stage` 写 02；资料充分但核验表达不完整 → 写 02.5。
