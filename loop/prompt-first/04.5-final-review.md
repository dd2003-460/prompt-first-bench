# 阶段 04.5：最终复核与交接

## 操作流程

1. 从反方角度检查全过程，不重新开展无边界研究。
2. 对照原始任务、阶段 01 空缺、阶段 02 证据、阶段 03 行动和阶段 04 结果。
3. 列出结论成立的依据、薄弱点、未完成项、残余风险和最有价值的下一步。
4. 对书稿、代码或 PDF 等具体产出，核对真实文件、编译结果和读者可见变化。
5. 如果发现需要新资料或重新执行，明确回退阶段，而不是把问题藏进最终总结。

## Reviewer 质检标准

- 原始任务是否全部得到回应；
- 关键空缺、证据、行动和结果是否能串成完整链条；
- 最终结论是否超出了证据支持范围；
- 未完成项和不确定性是否清楚；
- 交付物是否真实存在并经过必要验证；
- 下一位使用者能否仅凭这些 Markdown 继续工作。

存在会影响最终结论的缺口时必须 revise，并将 repair_stage 写为真正需要修复的阶段。

### 示例：验证 ζ(2)=π²/6 — 最终复核

**原始任务：**
```
验证 Basel 问题 ζ(2)=π²/6：已证明 + 数值复核。
```

**阶段 01 空缺回顾：**
```
- [已完成] ζ(2) 定义与收敛条件 → s=2>1 已证明
- [已完成] 数值高精度复核 → 50 位一致
- [已完成] 符号推导链可追溯 → Euler / Fourier
- [未完成] 用户需更高精度 → 用户未提供
```

**阶段 02 证据回顾：**
```
- 已证明：ζ(2)=π²/6（Euler 1735, 现代 Fourier 解析）
- 数值：Σ1/n² 与 π²/6 前 50 位一致, 差 < 1e-50
- 边界：s=1 harmonic 极缓慢 → 条件 s>1 必要
```

**阶段 03 行动回顾：**
```
- 步骤 1 完成：高精度数值复核
- 步骤 2 完成：符号推导链可追溯
- 步骤 3 完成：边界反例 s=1
```

**阶段 04 结果回顾：**
```
- 数值差 < 1e-50（dps=50）
- 推导链每步可追溯
- 反例 s=1 确认条件必要
```

**最终结论：**
```
结论成立：ζ(2)=π²/6 已证明 + 数值复核一致

依据：
1. 已证明：条件 s>1 收敛, Euler / Fourier 推导可追溯
2. 数值复核：50 位一致, 差 < 1e-50
3. 边界：反例 s=1 确认条件必要

薄弱点：
1. 数值复核仅复核（不替代已证明）
2. 精度属 mpmath dps 边界（已标注）

未完成项：
1. 用户更高精度需求（属用户）

残余风险：
1. 数值复核属精度边界（已标注）
2. 已证明属条件 s>1（已标注）

最有价值的下一步：
1. 属用户更高精度需求
2. 属边界反例扩展（s→1⁺ 行为）
```

## 通用原则

### 复核原则

1. **完整链条**：从任务到结论的每一步都必须有证据支持
2. **诚实评估**：薄弱点和未完成项必须明确列出
3. **不夸大结论**：结论不能超出证据支持范围
4. **可交接**：下一位使用者能仅凭文档继续工作

### 反方检查原则

1. **挑战结论**：从反方角度质疑结论的合理性
2. **寻找反例**：主动寻找可能推翻结论的反例
3. **评估风险**：评估结论错误的风险和影响
4. **提出替代**：如果结论错误，替代方案是什么

### 交接原则

1. **文档完整**：所有阶段文档必须完整且一致
2. **可复现**：所有执行步骤必须可复现
3. **可追溯**：所有结论必须可追溯到证据
4. **可继续**：下一位使用者能继续工作
