# 阶段 03：具体行动分解

## 操作流程

1. 只使用已经通过 Reviewer 的证据，不把猜测写成行动前提。
2. 将目标拆成可执行步骤，每步写输入、动作、依赖、预期产出和验收方式。
3. 标注哪些步骤可以并行，哪些步骤必须等待前一步结果。
4. 为关键失败情况写替代路径和停止条件。

## Reviewer 质检标准

- 行动步骤是否覆盖目标，而不是只生成漂亮计划；
- 每步是否有明确产出和验收方式；
- 依赖关系是否完整且没有循环；
- 关键未知是否被错误地当成已知前提；
- 另一个执行者能否直接依据本工件行动。

如果行动计划依赖尚未核验的事实，repair_stage 写 02 或 02.5；否则写 03。

## 操作示例（数学领域, 仅方法示范, 无任务信息）

### 示例 1：验证 Basel 问题 ζ(2)=π²/6 — 行动分解

**阶段 02 证据：**
```
- 已证明：ζ(2)=π²/6（Euler 1735, 现代 Fourier 解析）, 条件 s>1 收敛
- 数值线索：Σ1/n² 与 π²/6 前 15 位一致
```

**行动分解：**
```
步骤 1：高精度数值复核
- 输入：已核验定义 ζ(2)=Σ_{n≥1} 1/n², 条件 s=2>1
- 动作：mpmath dps=50 计算 Σ1/n² 与 π²/6, 求差
- 依赖：无
- 预期产出：两数值 + 差
- 验收方式：|差| < 1e-40
- 并行：是（两计算可并行）
- 失败替代：换精度 / 换加速（Euler 加速）

步骤 2：符号推导链
- 输入：已核验条件（s>1 保证收敛）
- 动作：推导 ζ(2)=π²/6（Euler 方法 / Fourier 系列）
- 依赖：步骤 1 数值确认收敛
- 预期产出：推导链每步可追溯
- 验收方式：每步逻辑可追溯, 无跳
- 并行：否（依赖步骤 1）
- 失败替代：标注未证, 不伪装已证明

步骤 3：边界反例检查
- 输入：推导链 + 条件 s>1
- 动作：检查边界 s=1（harmonic 极缓慢）确认条件必要
- 依赖：步骤 2
- 预期产出：边界结论
- 验收方式：反例 s=1 确认条件必要
- 并行：否
- 失败替代：属边界不补造
```

### 示例 2：证明 √2 无理 — 行动分解

**阶段 02 证据：**
```
- 已核验：√2 定义, 有理 = p/q 整数比值
```

**行动分解：**
```
步骤 1：反证假设
- 输入：已核验定义
- 动作：假设 √2=p/q, gcd(p,q)=1
- 依赖：无
- 预期产出：假设 + 约定
- 验收方式：假设明确
- 并行：是
- 失败替代：属边界不补造

步骤 2：推导矛盾
- 输入：反证假设
- 动作：p²=2q² → p 偶 → p=2k → 2k²=q² → q 偶 → 无限 descent
- 依赖：步骤 1
- 预期产出：矛盾链
- 验收方式：每步可追溯
- 并行：否
- 失败替代：标注未证, 不伪装已证明

步骤 3：结论 + 边界
- 输入：矛盾链
- 动作：反证成立 → √2 无理; 边界 gcd 约定检查
- 依赖：步骤 2
- 预期产出：结论 + 边界
- 验收方式：结论属已证明范围, 不夸大
- 并行：否
- 失败替代：属边界不补造
```

## 通用原则

### 步骤设计原则

1. **原子性**：每步只做一个明确的事情
2. **可验证**：每步都有明确的验收方式
3. **可并行**：能并行的步骤明确标注
4. **有退路**：关键步骤有替代方案

### 依赖关系处理

1. **无依赖**：可以立即执行
2. **单依赖**：等待前一步完成后执行
3. **多依赖**：等待所有依赖完成后执行
4. **循环依赖**：重新分解步骤，消除循环

### 失败处理

1. **记录失败**：如实记录失败原因
2. **评估影响**：判断失败对后续步骤的影响
3. **执行替代**：使用替代方案或标记为未解决
4. **不掩盖问题**：不要把失败包装成成功
