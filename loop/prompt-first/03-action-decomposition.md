# 阶段 03：具体行动分解

## 操作流程

1. **只使用已通过 Reviewer 的证据**，不把猜测写成行动前提。
2. 拆成可执行步骤，每步写：**输入、动作、依赖、预期产出、验收方式**。
3. 标注可并行步骤与必须等待前一步的步骤。
4. 为关键失败情况写**替代路径和停止条件**。

## 步骤设计原则

- **原子**（每步只做一件明确的事）、**可验证**（每步有明确验收方式）、**有退路**（关键步骤有替代方案）。
- **owner 标注（防粒度混排）**：每步必须标 `user`（需用户交互/确认/登录态）或 `agent`（可离线执行）。**未标 owner，或 user/agent 混排导致执行顺序歧义 = revise，`repair_stage` 写 03**；依赖图须显式标出 user 步骤是同步阻塞点还是异步等待点。
- **依赖**：无 / 单 / 多依赖可执行；**循环依赖 → 重新分解消除循环**。

## Reviewer 质检标准

- 行动步骤覆盖目标（不是只生成漂亮计划）；每步有明确产出和验收方式；依赖完整且无循环。
- 关键未知没有被当成已知前提；另一个执行者能否直接依据本工件行动。

失败处理（记录→评估影响→执行替代→不掩盖）见 `04-execution-verification.md`。
行动计划依赖未核验事实 → `repair_stage` 写 02 或 02.5；否则写 03。
