# 阶段 04：执行与结果核对

## 操作流程

1. 按阶段 03 的行动与依赖执行当前可执行步骤。
2. 记录实际执行的**命令、修改文件、输出、观察、失败**。
3. **逐项对照阶段 03 的验收方式**，不把计划当作已完成结果。
4. 对未完成步骤说明原因、影响、下一步。
5. 需要外部事实时**回到阶段 02**，不在执行记录里临时编造。

## 执行层循环防护（循环最高发区域）

- 简单命令（ls、grep、cat、单文件编辑）直接执行，不要思考。
- **失败重试上限 2 次**；仍失败 → 记录原因并跳过。同一工具 2 次调用都失败 → 换工具或换方法。
- 空响应/截断 → 降低输出长度或换方法重试。
- **同一命令卡住不超过 3 轮**：换命令、换方法、或标记为阻塞项。

## Reviewer 质检标准

- 声明完成的步骤是否有实际结果？产出文件/测试/编译/观察是否真实存在？是否逐项对照验收方式？失败与未完成项是否诚实保留？

## 验收与失败处理

- **不降低标准**（不因执行困难降标准）、**不提前验收**（未完成不标完成）、**不伪造结果**（不编造未执行的结果）。
- **失败处理**：如实记录 → 评估对后续步骤的影响 → 执行替代或标记未解决 → 不掩盖。

执行前提或事实有问题 → `repair_stage` 写对应的 02 或 03；否则写 04。
