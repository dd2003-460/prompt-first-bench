# 阶段 04：执行与结果核对

## 操作流程

1. 按阶段 03 的行动和依赖执行当前可执行步骤。
2. 记录实际执行的命令、修改文件、输出、观察和失败。
3. 逐项对照阶段 03 的验收方式，不把计划当作已完成结果。
4. 对未完成步骤说明原因、影响和下一步。
5. 需要外部事实时回到阶段 02，不要在执行记录里临时编造。

### 执行层通用循环防护

执行阶段是循环最高发区域。以下规则适用：

- **每步执行前**：判断任务复杂度。简单命令（ls, grep, cat, 单文件编辑）直接执行，不要思考
- **多步执行时**：如果上一步执行失败，最多重试 2 次；仍失败则记录失败原因并跳过，不要无限重试
- **工具调用时**：不要反复尝试同一个工具的不同参数 — 如果 2 次调用都失败，换工具或换方法
- **收到空响应或截断时**：降低输出长度或换方法重试
- **不要在一个命令上卡住超过 3 轮**：换命令、换方法、或标记为阻塞项

## Reviewer 质检标准

- 声明完成的步骤是否有实际结果；
- 产出文件、测试、编译或观察是否真实存在；
- 是否逐项对照验收方式；
- 失败和未完成项是否被诚实保留；
- 结果是否足够支持最终复核。

如果执行前提或事实有问题，repair_stage 写对应的 02 或 03；否则写 04。

### 示例 1：数值核验执行记录

**阶段 03 计划：**
```
步骤 1：环境精度确认
- 动作：确认 mpmath 可用
- 验收方式：dps 输出正常
```

**实际执行记录：**
```
步骤 1 执行：
- 命令：`python -c "import mpmath as mp; print(mp.mp.dps)"`
- 输出：15
- 结果：✅ 通过
- 文件：无修改
- 观察：mpmath 可用, 默认 15 位

步骤 2 执行：
- 命令：`python -c "import mpmath as mp; mp.mp.dps=50; print(mp.zeta(2)); print(mp.pi**2/6)"`
- 输出：
  1.644934066848226264071911774834817036373194211365
  1.644934066848226264071911774834817036373194211365
- 结果：✅ 通过
- 文件：无修改
- 观察：两值 50 位一致, 差 < 1e-50

步骤 3 执行：
- 命令：`python -c "import mpmath as mp; mp.mp.dps=30; print(mp.zeta(1))"`
- 输出：1.000000000000000000000000000000
- 结果：✅ 通过（属边界）
- 文件：无修改
- 观察：s=1 harmonic 极缓慢 → 属边界, 条件 s>1 必要
```

### 示例 2：数值核验 — 失败处理

**阶段 03 计划：**
```
步骤 4：验证 Goldbach 到 N=10^7
- 动作：运行验证脚本
- 验收方式：脚本完成, 输出结论
```

**实际执行记录：**
```
步骤 4 执行：
- 命令：`python verify_goldbach.py --n 10000000`
- 输出：
  ERROR: 超时（>120s）, 已完成约 3×10^6
- 结果：❌ 失败
- 原因：算法复杂度 O(N√N), 未完成全 N
- 影响：无法完成全 N 核验
- 下一步：
  a) 换算法（FFT / 筛加速）
  b) 降低 N 标注未完成
  c) 属边界不伪装完成
- 重试 1：`python verify_goldbach.py --n 1000000`
- 输出：完成, 0 反例
- 结果：✅ 通过（N=10^6, 标注属边界未全 N）
- 观察：属边界不伪装全 N 完成
```

## 通用原则

### 执行记录原则

1. **诚实记录**：成功和失败都要记录
2. **可复现**：记录所有命令和参数
3. **可追溯**：关联阶段 03 的计划和验收方式
4. **不掩盖问题**：失败原因和影响必须明确

### 验收原则

1. **对照验收**：逐项对照阶段 03 的验收方式
2. **不降低标准**：不因执行困难而降低验收标准
3. **不提前验收**：未完成不标记为完成
4. **不伪造结果**：不编造未执行的结果

### 失败处理原则

1. **记录失败**：如实记录失败原因
2. **评估影响**：判断失败对后续步骤的影响
3. **执行替代**：使用替代方案或标记为未解决
4. **不掩盖问题**：不要把失败包装成成功
