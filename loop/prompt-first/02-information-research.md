# 阶段 02：资料搜集与网页 AI 交叉询问

## 操作流程

1. 读 01 的空缺清单，**只围绕这些空缺**搜集。
2. **先做网页 LLM 交叉询问**（`ego-browser` + `ego-verify` skill）：问题围绕 01 空缺，只要求可复核来源线索，把真实回执写入工件。**网页 LLM 只提供线索，不是事实来源。** 通道快速失败（未授权/未配置）→ 记录完整原因后继续公开网页搜集，**不得等待或循环重试**。
3. 每条关键主张记录：**来源标题、URL、发布/更新时间、实际观察时间、具体观察、不确定性**；关键主张至少 **2 个相互独立来源**，厂商规格/独立评测/实际价格/用户实测必须区分。
4. 易变事实（价格、库存、版本、政策、支持）优先用**最近 7 天内**资料，无足够新资料 → 明确标为未解决；稳定事实可用较早一手资料，但须说明为何仍适用。
5. 搜索失败/登录限制/网页 LLM 不可用/零结果——**不是证据，不得伪装成来源**。同一主张 WebSearch 失败 → 最多换一次关键词，仍失败则记录并停止。
6. WebFetch 只对**最多 4 个**已知具体 URL 各试一次；403/404/超时立即记录不重试；拿到 ≥1 个可读一手页面即停。
7. **本阶段不写最终推荐**，只收集证据、暂定结论和未解决空缺。

## 工具

`ego-browser`（唯一通道：网页搜索/登录态/动态渲染/网页 LLM 交叉验证，不用无头浏览器）；API 或静态页用 `curl`/`wget`。heredoc 模板、选择器、`task.finish` 必调——见 `references/ego-browser.md`。

## Reviewer 质检标准

- 01 的关键空缺是否逐项有证据或明确保留为未解决；关键主张是否有足够独立来源。
- **证据来源完备（防「名不副实」）**：每条关键主张必须附 **来源 URL/本地路径 + 快照时间戳**，缺一即降级为「存在性断言-未核验」，**不计入已核验证据**。无来源主张被当事实使用 = revise，`repair_stage` 写 02。
- 易变事实是否接近当前日期、观察时间是否明确；是否把网页 LLM 线索误写成事实来源；是否记录并处理来源矛盾；是否仍有会改变下一阶段方案的关键证据缺口。

缺独立来源、时效过期、有未解释矛盾 → 必须 revise，`repair_stage` 写 02。
