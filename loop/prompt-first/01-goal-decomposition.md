# 阶段 01：目标分解、已知与空缺条件

## 递归分解（强制）

1. **目标 → 因素**：拆成互相正交、合起来完整覆盖目标的顶层影响因素。
2. **每因素分三类**：人类已提供 / 从项目可推导（已确定）/ 仍需研究。
3. **无法假定的条件写入空缺清单**，不得把未知伪装成默认值。
4. **递归**：每个因素视为子目标再分解，重复 2–4。
5. **停止**：叶子因素已最小（不能再分解）。
6. **「完成」判据**：叶子原子、非原子因素已递归展开、未验证条件全在空缺清单、02 可据此直接开研究；**未完成**时用 Ego Lite 把（本阶段 prompt + 当前分解 + 未覆盖缺口）提交网页 LLM 求补分解，输出作**待验证假设**并入，回到 5。

## 阶段边界与放行门槛

- **因素分解，不是资料搜集**：未核验的型号、日期、价格、性能、兼容性只作「待研究假设」，须标未验证并写入空缺。
- **不需要**拿到 02 才有的价格/性能/网页证据，**但必须给出 02 的研究路径、来源类型、失败备用路径**。
- 可写具体对象、候选、搜索词、字段、研究动作，**必须标成「待验证的研究目标/假设」**；交付物、主要因素、已知、关键空缺、阻塞影响、02 首批行动均清楚 → 判 `pass`（未解决的价格/时效/来源本就是 02 的工作）。

## 判定原则

**质量维度**：**正交**（每因素独立影响目标、不重叠；重叠则合并或重定义边界）、**覆盖**（关键目标至少被一个因素覆盖，未覆盖则加因素）、**边界**（条件明确，如「n ≥ 2」「误差 < 10⁻⁶」）、**优先级**（高=直接影响达成，中=影响体验，低=仅参考）、**空缺**（未验证条件必入清单，不得伪装成已知）、**研究路径**（写明目标网站、搜索词、字段、备用来源，不要求执行）、**候选对象**（列候选须标「待验证属性」，排除理由明确如「违反约束 C」）、**复合空缺**（须列出可分别核验的子问题 a / b / c）。

**候选集冻结**：01 的候选类别清单 = 本任务冻结集合。后续阶段不得静默增删；新增/排除须在 02 核验后显式记录（理由+时间戳），或已在 01 标「排除 — 理由 C」。**未声明漂移 = revise，`repair_stage` 写 01**。

**唯一 revise 触发条件**：遗漏关键因素、把未验证内容写成确定事实、下一阶段无法据此开始行动。术语具体、空缺轻微重叠、研究路径较详细、措辞不够抽象——均**不**构成 revise 理由。

**工件必须回答**：交付什么 / 受哪些因素影响 / 哪些已知 / 哪些缺失 / 缺失阻塞哪个后续判断 / 下阶段优先研究什么。

## Reviewer 质检标准

逐条对照上述质量维度与冻结规则核验。另加：**预算以用户总预算为约束**；谈子预算须标明是待验证的下游分配问题，不得把未经 02 核验的子预算写成 01 结论。

内容已足够让 02 立即开始 → 即使仍有待验证空缺也判 `pass`，把空缺交给 02。因素分解不完整 → `repair_stage` 写 01。
