# 流程路由表（T5 索引+检索层）

咒语 = 调度器（索引 + 检索 + 执行），不是固定指针。见到"先压后展"先按本表路由，再执行检索到的流程。流程本体在 `pfb/loop/*.md`，本表只路由不复制。

**路由结果 = 流程 + 显式域声明**（T2c 实证 2026-11-25：软性自查锚点无效 0/3，显式域声明有效 3/3 域内真推理——27b 选域 gap 可由外部域注入补偿，路由器必须给域，不能指望模型自己找。详见 exp-results/scores_t2b_t2c.md）。

## 路由表

| 问题类型 | 路由判据（可观察特征） | 检索到的流程 | 显式域声明（注入执行 prompt） |
|---|---|---|---|
| 理论研究 | 新命题/新猜想/新系统设计，需要分解+取证+核验 | 六阶段全流程：01→02→02.5→03→04→04.5 | 按 01 分解确定的域（例："这是 loss landscape/非凸优化问题，不是物理动力学"） |
| 调试卡住 | 重试≥2 / 同错≥2 / 同文件≥5次编辑且有错 | T4 打转检测 + general 思考升级（目标对齐/general机制/可检验预言），必要时回 01 查分解或换域 | 按当前任务所在工程域（例："这是 shell 脚本问题，不是 Python 问题"） |
| 选域 | "这个问题该用什么框架/域？""现有框架解释不了" | 选域三步：①校验范围（框架公理/适用域覆盖本问题吗）②迁移条件（逐条列出并核验）③实验新条件（加项优先/换基最后，换基须 APPROVALS 留痕） | 选域三步的产出（候选域列表 + 逐域校验结果） |
| 证据质量 | "这个来源可靠吗？""多源一致能信吗？" | 02 证据质量四档：一手/可校准二手/不可校准二手/系统性偏差（判据=bias 可识别+可估计） | 按证据所属领域（例："这是 GPU 性能数据，基准测试口径优先"） |

**域声明写法**（T2c 有效格式）：`这是 <问题类型> 问题——<核心机制域>，不是 <易混淆域>。不要用 <易混淆域> 框架。` 例："这是一个计算复杂性/优化问题——算法空间对应 loss landscape（非凸优化），不是物理动力学系统。不要用混沌/动力系统框架。"

## 默认路由

匹配不到 → 理论研究（六阶段全流程）。宁全勿漏：多走的阶段可裁剪，漏走的阶段补不回来。

## 边界（诚实）

1. **检索依赖问题分类**——分类本身是选域问题，27b 分类弱（T2 实证 100% 域偏移），可能路由错。路由错了的症状 = 执行中发现流程与问题不匹配（跑着跑着发现步骤全是多余的/关键步骤缺失）→ 重路由。
2. **执行质量取决于模型底层能力**——路由解决"找对流程"，不解决"执行得好"。
3. **路由表是初稿**——4 类来自现有 SOP 资产盘点，不是完备划分。新流程类型出现时加行（加行可逆，随时改）。

## 维护

- 加新流程：`pfb/loop/` 加 SOP 文件 + 本表加行
- 路由判据要可观察（特征/症状），不要抽象（"复杂问题"不可路由）
- 本表与 `pfb/docs/pfb-steps-thinking-frame.md` 咒语节互为镜像，改一处查另一处
