# 阶段 02.5：交叉核验与矛盾

## 操作流程

1. 逐项检查阶段 02 的关键主张、来源和观察时间。
2. 比较不同来源的定义、测量条件、样本、时间和利益关系。
3. 解释一致处和矛盾处；不能解释时保留不确定性，不强行收敛。
4. 检查网页 LLM 的结论是否被独立来源支持。
5. **对抗核验**（2026-10-29 r29 补丁，D指令）：对 arena/LLM 给出的核验结论本身发起攻击——主动找其论证漏洞（前提未验证？样本偏置？把相关当因果？来源与结论不匹配？），反驳后继续追问下一轮，直到碰到硬边界才停：**数学理论瓶颈**（需要学界未定论的理论工具）或**个人信息搜集瓶颈**（穷尽可查渠道仍拿不到）。禁止把"对方说 pass/有效"直接当终局。
6. 形成可以交给行动分解阶段使用的证据边界。

## 效度判据（独立于来源数量）

「独立来源」只管数量，效度管质量，单列为判据（与 02 的证据质量分级配套）：

- **准确**：来源说法与一手来源是否一致？（二手转述须回溯一手核对）
- **独立**：来源是否真独立，还是同源转载？（同一博客的 3 个 URL = 1 个来源，防重复计数）
- **客观**：来源是否有利益关系（厂商/营销/竞品）？

效度不足 → 降级为「存在性断言-未核验」，不计入已核验证据。

## 选域 ①②（显式环节）

- **① 校验范围**：当前理论框架（01 选的「基」）的公理/适用范围是否覆盖本问题？问题超出范围 → 显式标记，不硬套。
- **② 迁移条件**：结论迁移到本场景需要什么条件？逐条列出并核验。

①②不成立 = 选域问题，不是「证据不够」——回 02 多搜证据解决不了（在错的域里搜再多还是错的），升级给 04.5 的换基判断或回 01 重选域。

## Reviewer 质检标准

- 关键结论是否真正经过独立来源比较；
- 矛盾是否有具体解释，而不是只写"基本一致"；
- 是否混淆理论规格、实测性能、当前价格和个人推断；
- 是否遗漏会改变结论的反例；
- 是否清楚标注仍未解决的问题；
- 对核验方结论是否做过至少一轮主动质疑，质疑点与停止理由（碰到的瓶颈类型）是否记录在案。

如果需要补充新资料，repair_stage 写 02；如果资料充分但核验表达不完整，repair_stage 写 02.5。
