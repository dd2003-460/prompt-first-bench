## F3 — 三候选公式数学性质核实

记号：n = 条目数（cell 数），r = 判者数（本协议 r=3），x_{ij} ∈ {0,1} = 判者 j 对条目 i 的二值判定。

### F3.1 F1-cohen：Cohen's κ（二判者）

```
po = (1/n) Σᵢ 1[x_1i = x_2i]                          （观察一致率）
pe = p̄₁(1−p̄₂) + (1−p̄₁)p̄₂，其中 p̄ⱼ = (1/n) Σᵢ x_ji   （边际独立期望一致率）
κ_cohen = (po − pe) / (1 − pe)
```

- **N=3 适用性**：**不适用**。定义域 = 恰 2 判者。r=3 时整体无定义，只能两两配对（C(3,2)=3 对）后聚合 → 退化为 F3-pairwise。
- **degenerate 行为**：两判者完全一致（或完全互补）时 po=pe，κ 未定义（0/0）。**基线风险**：identity-baseline 场景（rejudge 尚未执行、h_claim := h_id 恒等）下若拿旧数据自测，κ 直接未定义——这是「公式选择必须考虑 pre-execution 退化态」的实例。
- **边际效应**：κ 对边际分布敏感——同一 po，边际越不平衡 pe 越小、κ 越大（见 S1 小例 A/A'）。

### F3.2 F2-fleiss：Fleiss'κ（r ≥ 2 原生多判者）

```
P_i = k_i(r−k_i) / (r(r−1))，k_i = Σⱼ x_ij（条目 i 的 yes 计数）
P̄ = (1/n) Σᵢ P_i
p̄ = (1/(nr)) Σᵢⱼ x_ij（全局 yes 比例）
P̄_e = p̄(1−p̄)
κ_fleiss = (P̄ − P̄_e) / (1 − P̄_e)
```

（等价形式：P_i = (k_i/r)(1−k_i/r)，即条目级「不一致概率」均值。）

- **N=3 适用性**：**直接可用**，r=3 是其设计场景之一（r≥2 均适用）。
- **条目粒度**：原生粒度 = 单条目跨判者计数矩阵——与 o3-claim-list §4.3「条目层」措辞**逐字对齐**（每个 cell = 一个条目，3 判者投票 → k_i ∈ {0,1,2,3}）。
- **degenerate 行为**：所有判者在某条目上一致（k_i=0 或 r）时 P_i=0（该条目对分子零贡献）；全体一致时 P̄=P̄_e，κ 未定义（同 Cohen's）。
- **已知偏差**：Fleiss'κ 假设判者可交换（exchangeable）——它把 3 个判者视为同质样本，**无法表达「judge A 系统性偏严、B 偏松」**的不对称分歧。若 rejudge 三判者中有一个明显 outlier，Fleiss'κ 会把它平均掉（pairwise 能暴露）。
- **与 §4.2 聚合规则的关系**：Fleiss'κ 消费的是**投票计数**（k_i），与 §4.2 的 ≥2/3 聚合规则同源（都用 k_i）——κ 门禁与聚合在数据结构上零摩擦。

### F3.3 F3-pairwise：pairwise 平均 Cohen's κ

```
κ_pair(u,v) = Cohen's κ(x_u, x_v)，(u,v) ∈ C(r,2)
κ_pw = mean{κ_pair}（或 median）
```

- **N=3 适用性**：**可用**（3 对取均值/中位数）。
- **缺失标注处理**：某判者缺部分条目时，该 pair 在**共同标注子集**上计算——子集大小不一时均值有偏（向覆盖大的 pair 倾斜）；中位数对此稳健。
- **与 F2 的差异**：保留判者身份 → 能暴露单判者 outlier（见 S2 小例 B：mean=0.40 vs Fleiss'=0.333，方向一致但数值不同；构造极端例可拉开差距）。
- **成本**：3 次 Cohen's κ 计算，O(n) each——与 F2 同阶。

### F3.4 三方案速查表（材料主表的数学列依据）

| 维度 | F1 Cohen's | F2 Fleiss' | F3 pairwise-mean |
|------|-----------|-----------|------------------|
| 判者数要求 | 恰 2 | ≥2 | ≥2（每对 2） |

## F5 — 手算小例（数值自检，验证公式引用正确性）

### S1 — Cohen's κ 对称/非对称边际（2 判者 × 4 条目）

| 例 | judge1 | judge2 | po | pe | κ |
|----|--------|--------|-----|-----|---|
| A | 1,1,0,0 | 1,0,0,1 | 2/4=1/2 | (2/4)(3/4)+(2/4)(1/4)=1/2 | **(1/2−1/2)/(1−1/2)=0** |
| A' | 1,1,1,0 | 1,1,0,0 | 3/4 | (3/4)(2/4)+(1/4)(2/4)=1/2 | **(3/4−1/2)/(1/2)=1/2** |

- A 例同时演示两个性质：① po=pe 时 κ=0（观察一致完全是边际结构产物）；② 若两判者完全一致（如 [1,0,1,0] vs [1,0,1,0]），po=pe=1 → **0/0 未定义**（degenerate 实证）。
- A' 例：同一 po 水平附近，边际更不平衡 → κ 更大（边际敏感性实证）。
- 精确分数值（Fraction 复算）：A: pe=1/2, κ=0；A': pe=1/2, κ=1/2。✅ 与公式定义一致。

### S2 — 3 判者 × 4 条目：Fleiss'κ vs pairwise-mean（U-K1 核心对照）

标注矩阵（行=判者，列=条目；条目 4 为全一致 yes = Fleiss' 的 degenerate cell）：

| 条目 | J1 | J2 | J3 | k_i |
|------|----|----|----|-----|
| 1 | 1 | 1 | 0 | 2 |
| 2 | 1 | 0 | 0 | 1 |
| 3 | 0 | 0 | 0 | 0 |
| 4 | 1 | 1 | 1 | 3 |

**Fleiss'κ（精确 Fraction 复算，已机验）**：P_i = (k_i/r)(1−k_i/r) = [2/9, 2/9, 0, 0] → P̄ = (4/9)/4 = **1/9**。p̄ = 全局 yes 比例 = 8/12 = **1/2**（J1 三 yes + J2 两 yes + J3 三 yes）。P̄_e = (1/2)(1/2) = **1/4**。κ_fleiss = (1/9 − 1/4)/(1 − 1/4) = **(−5/36)/(3/4) = −5/27 ≈ −0.185**（负值！）。

**pairwise（精确 Fraction 复算，已机验）**：
- pair(1,2)：po = 3/4；边际 J1=3/4, J2=2/4 → pe = (3/4)(1/2)+(1/4)(1/2) = 1/2 → κ = **1/2**
- pair(1,3)：po = 2/4；J1=3/4, J3=3/4 → pe = (3/4)(1/4)+(1/4)(3/4) = 3/8 → κ = (1/2−3/8)/(5/8) = **1/5**
- pair(2,3)：po = 3/4；J2=2/4, J3=3/4 → pe = 1/2 → κ = **1/2**
- mean = (1/2+1/5+1/2)/3 = **13/30 ≈ 0.433**；median = **1/2**

**对照结论（精确值，Fraction 机验通过）**：同一份 3 判者数据，Fleiss'κ = −5/27 ≈ −0.185（**负一致性**），pairwise-mean = 13/30 ≈ 0.433，pairwise-median = 1/2，naive 全条目一致率 = 0/3 pairs = 0。**四个口径跨越 [−0.185, 0.5]**——0.6 阈值在任何口径下都不达标，但「差多少」和「是否为负」因公式而异。这正是 U-K1 不能靠直觉裁定的量化证据：**公式选择改变门禁结论的强度表述**（「远低于阈值」vs「负一致性」）。

### S3 — identity-baseline degenerate 实证

rejudge 未执行前的 identity 场景（h_claim := h_id）：若误用旧 hit-matrix 双判自测，两「判者」完全一致 → po=pe → **κ 未定义（0/0）**。含义：κ 门禁只能在**真实多判者数据**上有意义；pre-execution 状态的正确断言行为 = SIGNAL blocked-on-external（assert-o3-claim-rejudge.py 现状语义），不是 FAIL 也不是 PASS。

## F6 — 负面结果与边界声明

1. **公式定义式无仓库内第二来源**：Cohen 1960 / Fleiss 1971 为标准教科书形式，本仓无文献快照 → 标注 unverified（runner 协议网络受限条款）；但 S1/S2 手算小例提供了**内部一致性验证**（定义式 ↔ 数值实现互检），降低抄写错误风险。

3. **Fleiss'κ 的判者可交换假设**与 rejudge 场景的真实结构（3 个判者可能不同底座/不同 prompt 敏感度）存在张力——这是 F2 方案的实质弱点，材料中如实呈现，不隐藏。
4. **本 goal 不算真实 κ**：无 rejudge-results.json（blocked-on-external），S1-S3 全部是构造小例。真实数值计算 = RV3G4-kappa-gate-execution 的职责。
