## 对抗核验（按 SOP 第 5 条，对 02 暂定结论本身发起攻击）

### A1 攻击 Q1 方案：「V1-align 去掉价值判断词」的切分是否干净？

**攻击 1**：c 区准入条件改为中性可查属性后，「发布年代 ≥ N 年」本身仍是方向暗示——它把搜索引向老卡，而 V1-align 的本意是隔离「结构 vs 暗示」。若 V1-align 仍含「发布年代过滤」，则 V1 vs V1-align 的差异不只是价值判断词，还有**搜索空间形状**，归因不纯。

**反驳**：AUDIT-report B3 的处置原文是「去掉『发布 ≥5 年旧选项』具体锚点 → 抽象『非默认可行区间（由任务画像定义）』」——即**主补丁（V1）**本身就不再含年代锚点，而是让被测者从任务画像推导分区边界。V1-align 对照组是在这个已去锚点的题面上再剥离价值倾向，隔离的是「四分区强制搜索结构」vs「无结构」的贡献。所以切分对象是：**V1 = 结构 + （残余的）倾向提示；V1-align = 纯结构；V0 = 无**。三层对比才能拆出两个效应。我的 02 方案漏了这一点——修正：V1-align 保留四分区结构但分区名用域无关占位（「分区 a/b/c/d 由任务画像定义」），连「当代旗舰/上代主流/老马/非 GPU」这类带先验的分区标签也去掉；V1 保留分区标签（它们是倾向提示的一部分）。

**攻击 2**：三问改域无关占位后，judge 怎么判「三项检查各有可定位证据」（O1 条目）？占位太抽象会退化成 judge 自由裁量，违背 R-02 机械可判要求。

**反驳**：占位只作用于**题面**（被测者看到的指令），不作用于**评分表**。O1 二值条目的判据写死为：「产出中该候选名下存在 ①≥1 个可定位来源引用（URL/文档路径）②≥1 个数值 ③≥1 句约束判断（该候选在何条件下可行/不可行）」——这三项是从工件机械提取的（grep URL 模式 + 数字 + 条件句式），与被测者实例化什么指标无关。题面占位 ≠ 评分占位。两件事分开写，不冲突。

**攻击 3**：「单位显存价格低于当代旗舰 50%」这种阈值留在 V1 里算不算答案注射？

**反驳**：B3 认定的注射点是「发布 ≥5 年」+「保值性好/性价比可能更高」这类**指向特定卡型的价值断言**。「单位显存价格」是可查客观量，作为检索过滤条件（帮被测者找候选）不构成「哪个候选好」的断言。但 50% 阈值是具体数字——保守处理：V1 中保留「显著低于」（不给数字），把 50% 从题面删掉。登记为 02→02.5 修正 M1。

### A2 攻击 Q2 方案：sham 等长替换真的中性吗？

**攻击**：「每条 OPEN 条目须附状态注记 + 下一步动作 + 预计耗时」——「预计耗时」暗含时间预算意识，可能轻微影响 P4 行为（被测者会更早考虑停止），污染 sham 的「中性」。

**反驳**：P4 测的是「停在正确的边界类型」，V3 消融要隔离的是**边界类型声明要求**的因果贡献。sham 段只要不含三类边界词汇、不要求分类终止原因即可。通用记录规范（状态注记/下一步/耗时）不要求*为什么停*，只要求*记录状态*——对「是否声明边界类型」这个自变量是正交的。残余风险：耗时字段可能间接促发停止行为。更干净的替代：sham 段改为纯格式规范（「每条 OPEN 条目使用统一模板：ID / 描述 / 当前状态 / 关联条目」），完全不含时间与停止语义。采用后者。登记修正 M2。

### A3 攻击 Q4 解释：Jaccard 判据的解释性补充是否越权？

**攻击**：AUDIT-report 只写了「候选集 Jaccard<0.9」六个字，我补的「同题不同档位产出候选集合」是一种具体化，可能与作者本意不符（也许本意是 run 间一致性检测，防同一模型刷多档）。

**反驳**：#20 的 finding 是「维度自选退化」——被测者可以故意把候选集做得几乎相同来操纵档位差。两种读法都服务于防刷分，但「相邻档可测序数差」这条已经覆盖了档位区分度，Jaccard 更可能是**跨 run 候选集稳定性**（同一被测者多次产出的候选集不应 Jaccard≈1，否则说明候选集是先验固定而非搜索得出）。两种读法都有道理，无法从仓库内证据裁定 → 按 current-goal【失败降级】：DRAFT 中落笔时**同时写两种口径**（「同题重复 run 的候选集 Jaccard < 0.9，且相邻档候选集不得几乎相同」），revision-log 标「需人工裁决：AUDIT-report 未展开定义，此处为双口径兜底」。这是诚实处理，不是伪装已知。

### A4 攻击 Q5 边界切割：batch1 只做横切机制会不会产出「半成品 DRAFT」？

**攻击**：O2/O4/P1-P4 只给条目框架 + batch2 占位，新版 DRAFT 看起来完整但实际一半维度是空壳——下游消费者（开跑正式实验的人）可能误以为 v2 已定稿。

**反驳**：(i) AUDIT-report §9.1 明确批次划分「第一批 = 开跑前置条件（消除自相矛盾与答案注射）」，第二批可与 pilot 设计并行——即官方定位就是分批落地；(ii) v2 文头状态标「草案·batch1 修订落地·**batch2 未完成，不可用于正式实验计分**」，每个 `[batch2: R-xx]` 占位处加醒目标记；(iii) revision-log 首页列明「本版包含 R-01~R-03/R-06/R-10 + C3/C4 断言；不包含 R-04/R-05/R-07~R-09/R-11~R-15」。三重防护下「半成品被误用」的风险可控。接受攻击部分成立：必须做 (ii)(iii) 的显式标注，不能只靠文头一行。

### A5 攻击 E3 预检：容差 5e-5 的选择是否有依据？

**攻击**：new judge 侧 w2 是 3 位小数舍入（最大舍入误差 5e-4），我用 5e-5 容差复算 orig 侧通过，但 new 侧 `round(expected,4)` vs 落盘 3 位值——比如 expected=1.7369655...，round4=1.7370，落盘 1.737，差 0。但若某节点 expected round4 与 3 位值差恰在 5e-5 边缘呢？

**反驳**：实测验证过 new 侧 30/30 在 5e-5 容差下全部通过（E3 预检已跑）。原理：3 位小数值是 4 位值的进一步舍入，两者之界 ≤5e-4，但 expected 的 round4 与 3 位值之界 ≤ max(5e-4, 5e-5)……严格说 5e-5 容差对 3 位值**理论上不够**（如 expected=1.73699 → round4=1.7370 vs 落盘 1.737 差 0，OK；但 expected=1.73694 → round4=1.7369 vs 落盘 1.737 差 1e-4 > 5e-5，FAIL 误报）。正确做法：容差按落盘精度定——orig 侧 4 位 → 容差 5e-5；new 侧 3 位 → 容差 5e-4。脚本按文件分别取容差。登记修正 M3（比 02 的「统一 5e-5」更严谨）。
