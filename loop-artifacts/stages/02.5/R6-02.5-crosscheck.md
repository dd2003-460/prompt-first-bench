## 2. 矛盾记录

### C1（可解释）三层 vs「只许一层」

- E1 说三层（metadata → body → references），E2 说「Keep references one level deep」。
- 解释：两者不在同一维度——E1 数的是**加载层级**，E2 限的是**引用链深度**（A 指引 B、B 再指引 C）。
- 结论：**不矛盾**。对 INDEX 的要求是：阶段包里的文件不得再互相「见 xxx.md」式指引（否则就是第二层引用）。

### C2（**未解释**）结构化长上下文是否更安全

- 直觉/我们的设计假设：把当前阶段的 3 个文件**成套**给 agent，组织良好 → 比散放更好。
- 实测反例：Chroma 在 18 个模型上「logically structured haystacks scored worse than shuffled ones across all 18 models」（`https://glasp.co/articles/context-rot-rag-long-context-hybrid` 转述 Chroma 2025）。
- 这意味着：**「成套组织」本身可能不带来收益，甚至反向**。
- 处置：**标记为未解释**。理由——该结论来自二手转述，且「结构化」在 Chroma 的构造里指 haystack 的叙事连贯性，与我们「按阶段切包」不是同一变量。**不得据此宣称阶段门控有召回率收益**；R6 只主张 token 收益，不主张准确率收益。
- 影响面：报告 §5 结论里必须写「本轮不测准确率」。

### C3（可解释，但对结论不利）收益量级随覆盖率衰减

- E2 的 70,000 → 2,000 是「8 选 1」场景；本任务是**单 run 走完 6 个阶段**，最终仍会触达全部 7 个文件。
- 结论：**单 turn 峰值削减 ≠ run 总量削减**。账本必须同时报「单 turn 峰值」与「run 末累计」，只报前者会高估。
