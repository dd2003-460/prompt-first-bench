## 反方质询（逐条对 02 暂定结论）

### Q1 · 「验证链已闭合」是否过度乐观——你只复算了 JSON 内部一致性，没验证「分数 → 报告叙述」这一环？
**攻击**：F1 全部检查都是 stats-w3w4.json 自洽（分数 vs 原始数据、ρ vs 落盘值）。但任务书说的「未走完验证链」可能指 ablation-result.md 的叙述层：报告里的表格/结论句是否与 JSON 一致？G2 发现过 §6 W1=2/5→1/5 的口径错误（stats-w3w4.json 的 purpose 字段自己承认修正过），说明叙述层出过错。
**回应**：部分成立。本轮核对了关键数值段落（top-5 计数、conclusion 句、ρ 表），但未做全文逐句核对（02 空缺 G3 已登记）。修正表述：「**JSON 层验证链闭合**（本轮全复验通过）；**叙述层（ablation-result.md ↔ JSON）存在已知历史错配一处（§6 口径，已被 stats-w3w4.json correction 字段记录修复），其余段落未逐句核验**」。不影响 F1 主结论（事实源是 JSON 不是叙述），但 G6 综合报告引用 ablation-result.md 时应以 JSON 为准。

### Q2 · 「gold 平均排名最稳健」是不是事后挑指标——七个口径里挑唯一不翻转的那个，这是 p-hacking 吗？
**攻击**：O1 的子选项排序（平均排名 > top-10 > top-5）是在看到双 judge 结果之后选出来的。如果预注册的是 top-10，现在说「平均排名更稳健」就是事后合理化。
**回应**：部分成立，需要补一个预注册视角的检验。两点：(a) 选择标准本身可以先验陈述——「判据应对 p̃ 估计噪声稳健」是 G2 根因分析直接导出的要求（根因在 p̃ 层 → 判据应降低对 p̃ 点估计的敏感度），不是为迁就结果发明；(b) 但诚实地说，三个候选口径是并列提出的，「哪个更稳健」的比较确实在看数之后完成。**处置**：交付物中把「平均排名推荐」标注为「基于 G2 根因的先验标准 + 本轮数据支持」，并保留 top-10 作为同等地位的备选，最终选择权交 G6（G6 可以用第三 judge 数据再验一次）。这不是 p-hacking（没有对单一假设做选择性报告），但是 post-hoc model selection，必须显式声明。

### Q3 · W4「排序零扰动 = 抗噪声」会不会是假象——n=8 个 run，排序不变可能只是分辨率不够？
**攻击**：8 个 run 只有 8 个排序位置，W4 头部 gap 本来就只有 0.005-0.02，换 p̃ 后 gap 变了 2-4 倍但顺序没变——也许再来一个 judge 顺序就变了。「零扰动」在 n=8 下证明力很弱。
**回应**：成立，降级表述。准确说法：「W4 在**同族双 judge** 下排序稳定（8/8 位不变），但这只是两个观测点，不能外推为『W4 天然抗噪声』；结构性理由（加法混合稀释乘性放大）是机制解释而非统计证明」。同时注意反向证据：W4 的 gold 平均排名从 6.4→8.6 恶化了 34%（W3 从 6.4→8.6 相同幅度）——排序稳不等于构念效度稳，「W4 比 W3 好」的结论只在「run 排序稳定性」这一个维度上成立，构念效度维度两者同病。修正 F2 分级：W4 敏感性 = **中（排序维度）/ 高（构念效度维度）**，两维度分开报。

### Q4 · O3 的「实质代价」论证（ρ(W1,W4)=1.0）用对了指标吗？
**攻击**：ρ(W1,W4)=1.0 是因为 W4=W1+W2 且 w1 质量大——相关系数高不代表「W1 是 W4 的粗化版」。如果 W2 携带的信息恰好与 W1 正交，W1-only 损失的就是那部分正交信息，相关系数测不出来。
**回应**：部分成立。ρ=1.0 只能证明「W1 排序与 W4 排序完全一致」（n=8 下无逆序对），不能量化 W2 的正交信息量。补充一个可算的证据：W1 与 W4 的**分数差分布**——若 W2 携带独立信息，W4-W1 的 run 间方差应显著非零。实测：W4-W1 差值 {run1:-0.0627, run2:-0.0501, run3:-0.0418, run4:-0.0361, run5:-0.0225, run6:-0.0561, run7:-0.0330, run8:-0.0225}，mean=-0.0406，std≈0.015，方向 **8/8 为负**（W4 系统性低于 W1）——W2 分量确实改变了绝对分但几乎不改变相对序。修正表述：「W1-only 的损失 = surprisal 维度的**绝对分校准能力**（W4 系统性下压高频命中 run 的分），run 排序能力损失有限（ρ=1.0）。O3 的代价因此比 02 初稿说的『整个 p̃ 修正能力』要小——主要是校准而非区分」。
