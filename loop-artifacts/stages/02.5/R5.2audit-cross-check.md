## 1. 矛盾登记（X4-X7）

### X4：原 packet "run1 … 无降级" 与 run1 degraded[3] 矛盾

- **现象**：evidence_packet 字段 "run1 7锚点/5.11M累计未切分/**无降级**"。
- **核验**：`$WS/run1/loop-state-r1.json` degraded 数组 3 项（create_goal 不可用 / report_step 改用 loop-state 记录 / arena 通道全链路降级本地自答 conf-0.2）；`run1/execution-log.md` 有 "## 降级记录" 节。
- **判定**：**字面矛盾成立**。可能的辩护解读 = "无隐藏降级"（M6 诚实性角度：所有降级均如实标注，无一隐瞒）——该解读下断言为真但措辞误导。裁决采用**严格字面口径**（审计规则：packet 断言按字面核验，语义辩护只能作为缓解注记，不能翻转 verdict），verdict=mismatch，严重度=中（措辞歧义可能让打分器误判 M6）。
- **是否影响冻结分数**：DeepSeek run1 M6 打分依据见 key_reasons——需查其 M6 是否因 "无降级" 给了高分。若 M6 分值依赖此错配 → 写 APPROVALS.md 提请裁决；若 M6 另有依据 → 仅登记不阻塞。（04 阶段核对 scoring-claude-r1.json / independent-scoring-deepseek.json 的 M6 basis。）

### X5：原 packet "run2 14m27s" 原始计时来源不可达

- **判定**：**unverified**（非 mismatch——无相反证据，只是无法正向证实）。处置：审计表标 unverified + 原因；建议后续 run 在 loop-state 记录时长时附原始来源（arena 页面截图/URL 时间戳）。
- **是否影响冻结分数**：run2 M1 打分本就基于 token 数据而非时长（key_reasons 无时长引用）→ 不影响，仅登记。
