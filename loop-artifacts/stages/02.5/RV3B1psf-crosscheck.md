# 阶段 02.5：对抗性交叉核对 — RV3B1-prompt-side-freeze

## A1 · 「D2 段写入 02.5 会让 prompt-first 工作流的机械进程误把它当阶段规则执行」？

**攻击**：`loop/prompt-first/*.md` 是 ralph CLI 的阶段规则文件（`load_stage_rules(root, stage.id)` 读取）。往 02.5 里塞一段「被测者 prompt 的消融对象」，Reviewer/Stop Hook 可能把【边界类型声明】当成对 *runner 自己* 的要求（每条终止注记必须声明边界类型），污染 loop 行为。
**回应**：(a) 该段以显式小节标题承载——「【附录 · 冻结件】D2 边界类型声明段（rubric-v3 V0/V3 消融删除对象，非本 loop 规则）」——标题即声明其对象是被测者题面而非 runner；(b) 段内原文逐字保留但外层加引用块/代码块隔离，与 02.5 的操作指令文本在 Markdown 层级上可区分；(c) 风险残余诚实登记：prompt-first 的规则加载是全文注入（无结构化 schema），无法 100% 排除 LLM 混淆——缓解靠标题声明 + assert 锁定该段位置（文末附录区，不插入操作流程步骤之间）。
**判定**：攻击部分成立 → 采纳缓解设计（附录区 + 显式非规则声明），残余风险登记为 R6 进 04 日志。

## A2 · 「§4.4 新建 sham 段违反 batch1 冻结范围——R-10 冻结的是六变体矩阵，加第七个变体是越权」？

**攻击**：§3.2 标头「【v2 冻结 · R-10】」+ 冻结规则 B10「无 diff 记录的变体不得开跑」。queue 只授权「V3 sham 化联动设计」，没说要改冻结矩阵本身。
**回应**：queue 描述原文 = 「D2 边界类型声明段写入 loop/prompt-first/02.5（或 03）并 commit 冻结 **+ V3 sham 化联动设计**」——「联动设计」必然要求 §3.2 有 V3-sham 行可指（否则 V3-noboundary 的 sham 对照不存在，「联动」落空）。且 B10 约束的是「开跑」而非「登记」：新增行带完整冻结 diff（段落引用 + 行号 + 操作）恰好满足 B10 的合规路径。改动幅度 = 加一行 + 加一节（§4.4），既有六行零改动（assert 定点验证）。若成璐认为越权，回退成本 = 删两处新增（git revert 单 commit），不影响已冻结内容。
**判定**：失败（授权链完整：queue 明写联动设计；B10 合规路径满足）。

## A3 · 「等长标准 ±0 行数太死——中文换行导致行数对长度不敏感」？

**攻击**：J3 预注册「行数相等（±0）+ 字符数偏差 ≤10%」。但 Markdown 渲染下换行是软性的，两段落行数相同不代表视觉长度相同；反过来强行凑行数会扭曲措辞。
**回应**：sham 段是**代码块内文本**（同 §4.3 形态），代码块内换行是硬性的（逐行呈现给被测者），行数即真实长度维度之一。双指标设计正是为此：行数捕捉结构规模，字符数捕捉实际 token 量，两者都过才算等长。±0 行数针对的是「段落块数量级」（6 行 vs 6 行），不是逐句对齐——§4.4 允许内部句式自由，只要总行数 = 6 且总字符偏差 ≤10%。
**判定**：失败。

## A4 · 「写入 02.5 后，V3-noboundary 的『精确删除』执行目标从 DRAFT v2 变成了 02.5——两处源文本未来漂移怎么办」？

**攻击**：现在 D2 段同时存在于 DRAFT v2 L155-160 和 02.5 附录。实验执行时从哪删？若两处不同步，消融对象定义就二义了。
**回应**：单一事实源不变——**DRAFT v2 仍是 D2 段的权威定义**（§3.2 冻结登记表指向它）；02.5 附录是**执行侧副本**（供 prompt 组装脚本直接读取，避免跨目录拼接）。assert-psf-freeze.py 检查①强制两者 byte-exact（任一漂移即 FAIL），所以二义性在机判层面被消除。02 工件 §1 已写明此关系（「写入 02.5 时采用正文 6 行逐字抄录…assert 比对对象 = 正文 6 行，与 DRAFT v2 L155-L160 byte-exact」）。
**判定**：失败（byte-exact 断言承担同步义务）。
