## 攻击 J1（rank 方向 = descending weight）

**攻击角度 A**：如果 rank 0 = 最低权重呢？
- 验证：W3-orig ascending 下 gmr = ?
- 计算：W3-orig 权重排序（ascending）→ gold 节点 rank 变大 → gmr > 5.40
- 具体：W3-orig 的 5 个 gold 节点在 descending 下 rank 为 {0,1,2,3,4}（分属不同权重组，无并列）→ gmr = (0+1+2+3+4)/5 = 2.0? 
- **等等**——让我重新检查。W3-orig 有 31 个节点，gold 只有 5 个。gmr = Σ rank(gold)/5，rank 是全局 rank（0-30），不是组内 rank。
- W3-orig tie-robust 意味着 5 个 gold 节点各自所在权重组内没有非 gold 节点与它们并列 → 它们的 rank 由权重组的全局位置唯一确定，与 tie-break 无关。
- 在 descending 下 W3-orig gmr = 5.40（已验证）。如果 ascending，rank 全部翻转（rank' = 30 - rank），gmr' = (30×5 - Σrank)/5 = 30 - 5.40 = 24.60 ≠ 5.40。
- **结论**：ascending 无法得出 5.40。J1 = descending 是唯一自洽解。✅ 攻击失败。

**攻击角度 B**：AUDIT §8 表 W1 id-order = 9.8，本 goal 复算 = 10.20。是否说明 rank 方向理解错？
- 分析：如果 rank 方向错了，tie 组结构和 span 也会变（因为 lo/hi 的定义依赖方向）。但 tie 组结构一致 + span 一致 → 方向正确，只是绝对值有算术偏移。
- 具体验证：W1 的 tie 组 {5.0: N-2,N-4} {3.396: N-3.2.2} {2.0: N-1.3,N-2.1}——这些是权重值，在 descending 和 ascending 下都是相同的组（只是全局位置不同）。span = hi - lo 只取决于组内 gold 节点的相对排列数，不取决于全局方向。
- **结论**：id-order 偏差 0.4（9.8 vs 10.20）是 AUDIT 表的算术错误，不是方向错误。✅ 攻击失败。

## 攻击 J2（用本 goal 复算值替代 AUDIT §8 表）

- W3-orig 的特殊性：tie-robust（无含 gold 并列组）→ 不依赖 tie-break 实现细节，只依赖排序方向 + rank 公式。
- 如果排序方向错（ascending），W3-orig 会输出 24.60 而非 5.40。实际输出 5.40 → 方向正确。
- 如果 rank 公式错（比如 rank 从 1 起），W3-orig 会输出 (1+2+3+4+5)/5 = 3.0 或类似值。实际输出 5.40 → 公式正确。
- **结论**：W3-orig 锚点验证通过 → 脚本逻辑正确 → AUDIT §8 表其他行的绝对值是算术错误。✅ 攻击失败。

## 攻击 J3（退出条件 EC-3 = 任一方案对翻转）

**攻击角度 A**：「任一方案对翻转」是否太严格？两个方案的 gmr 都变了但相对顺序没变，算不算？
- 分析：EC-3 定义的是「跨方案排序反转」= 存在 A,B 使得 judge1 下 gmr(A)<gmr(B) 但 judge3 下 gmr(A)>gmr(B)。
- 如果 gmr 数值变了但相对顺序没变（如 W1 从 10.20 变成 11.00，W3 从 5.40 变成 6.00，W3 仍 < W1）→ 不算反转。
- 这正是 AUDIT §3.3 L122 原文「跨方案排序反转」的字面含义——排序（order）反转，不是数值变化。
- **结论**：J3 定义正确，与原文语义一致。✅ 攻击失败。

**攻击角度 B**：7 个方案（W1/W2/W3/W4 × orig/new）还是 4 个方案（W1/W2/W3/W4）？
- 分析：AUDIT §3.3 原文「gmr 在第三 judge 下出现跨方案排序反转」——「方案」指权重方案（W1/W2/W3/W4），judge 是数据来源。
- 第三 judge 下重算的是 W1/W2/W3/W4 四个方案（用第三 judge 的 p̃），与 orig/new judge 下的对应方案比较。
- 所以是 4 个方案的两两比较（C(4,2)=6 对），不是 7 个。
- **修正**：冻结件 §3 EC-3 写的「两两比较 7 个方案对」应改为「两两比较 4 个方案（6 对）」。
- ⚠️ **发现需修正**：EC-3 的机判方式描述有误（7→4）。

## 攻击 02 复算结论（系统性偏移）

**攻击角度 A**：偏移是否可能是 rank 起点不同（0-based vs 1-based）？
- 验证：如果 rank 从 1 起，所有 gmr 值 +1（每个 gold 节点 rank +1，Σ/5 → +1）。
- W3-orig 从 5.40 变成 6.40 ≠ AUDIT 的 5.40。→ rank 从 0 起正确。
- W1 从 10.20 变成 11.20，偏差从 +0.4 变成 +1.4（更大）。→ 不能解释 AUDIT 的 9.8。
- **结论**：rank 起点正确（0-based）。✅ 攻击失败。

**攻击角度 B**：偏移是否可能是 gold 集不同（用了不同的 5 个节点）？
- 验证：gold strict 集在 AUDIT §3.2 L100 和 stats-w3w4.json construct_validity.gold_strict 中均为 ["N-2.1", "N-3.2.2", "N-2", "N-4", "N-1.3"]。
- 如果用不同的 gold 集，W3-orig 的 tie-robust 性质也会变（因为 tie-robust 取决于 gold 节点是否与其他节点并列）。W3-orig 在当前 gold 集下 tie-robust → gold 集正确。
- **结论**：gold 集正确。✅ 攻击失败。

**攻击角度 C**：偏移是否可能是节点总数不同（31 vs 其他）？
- 验证：prior-estimates.json nodes 字段有 31 个条目（含根节点）。judge-blindtest-r1.json w3_full_ranking 也有 31 条。
- 如果节点数不同，W3-orig 的 gmr 也会变（因为 rank 范围变）。W3-orig = 5.40 在 31 节点下成立 → 节点数正确。
- **结论**：节点数正确。✅ 攻击失败。
