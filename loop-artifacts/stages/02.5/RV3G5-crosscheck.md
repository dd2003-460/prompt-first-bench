## Q-attacks（对阶段 02 证据的攻击与回应）

### Q1 · "w2 公式层 31/31 精确匹配"是否只是验证了存储值自洽，而非验证了公式正确性？

**攻击**：如果 `prior-estimates.json` 和 `judge-blindtest-r1.json` 的 w2 字段都是用同一个（可能有 bug 的）脚本生成的，那么"两者一致"只证明了一致性，没有证明正确性。

**回应**：部分成立。本阶段的复算是用独立实现的公式（`1+min(-log2(p), log2(100))`）重算的，不是从存储值推导的。但"公式本身是否正确"（即 surprisal 的定义是否应该是 `-log2(p)` 还是 `-log(p)/log(10)` 或其他变体）超出了本 goal 的范围——那是 G2 根因分析已确认的设计决策。本阶段验证的是"给定公式定义，计算实现无误"，这是断言脚本能防住的风险层级。

---

### Q2 · "new W3 top5_gold tie-sensitive [1,2]"是否削弱了 G1/G2 的核心结论？

**攻击**：G1 C4 和 G2 的核心发现是"orig W3=3/5 (pass) → new W3=1/5 (fail)"这一翻转。如果 new W3 的值可能是 2/5 而非 1/5（取决于 tie-break），那么"翻转"的幅度被高估了。

**回应**：部分成立，但不改变定性结论。即使 new W3=2/5，仍然 <3/5 门槛，构念效度否决不变。且 goldmeanrank（tie-robust 指标）从 6.4→8.6 的恶化幅度不受 tie-break 影响（范围仅 [8.40, 8.60]）。建议 G6 引用时改用 goldmeanrank 作为主判据，top5_gold 作为辅助并带 tie-break 限定语。

---

### Q3 · "W1 构念效度高度 tie-sensitive [9.60, 13.40]"是否意味着 W1 可能并不比 W2/W3 差？

**攻击**：如果 W1 的 goldmeanrank 在最优 tie-break 下可达 9.60（接近 W2 的 9.20），那么"W1 构念效度最差"的表述过于绝对。

**回应**：成立。修正表述：W1 的构念效度在 id tie-break 下是最差的（11.2），但在最优 tie-break 下可与 W2 相当（9.6 vs 9.2）。更准确的表述是"W1 的构念效度评估对 tie-breaking 规则敏感，不宜单独作为定稿依据"。这支持 G3 的推荐路径（O1 改判据为 goldmeanrank + top-10 辅助）而非简单废弃 W1。

---

### Q4 · "Per-run 口径下无 run 过线"是否与 G1 的记录矛盾？

**攻击**：G1 记录说"per-run top-5 口径下无任何 run 在任何方案下达 ≥3 gold 标记"，但本阶段 F3 表格显示 per-run top5_gold max=2（所有 scheme×judge）。如果 G1 当时用的是不同的 tie-break 或不同的 gold set，这个"一致"可能是巧合。

**回应**：不矛盾。G1 使用的是 strict gold set（5 节点）+ id tie-break，与本阶段一致。"max=2"与"无 run 达 ≥3"是同一事实的两种表述。

---

### Q5 · 机判化候选 C1-C5 的"实现成本估算"是否有依据，还是拍脑袋？

**攻击**：~50-200 行的成本估算缺乏量化依据。R5.2 系列脚本是 143 行，assert-g1-audit 是 137 行，但新脚本的复杂度可能不同（如 C3 需要实现 spearman，C1/C2 需要先定义 schema）。

**回应**：部分成立。成本估算是类比估算（基于已有脚本行数 + 输入复杂度），不是精确工时。已在 F4 中明确标注"按行数类比"。对于 C1/C2，schema 定义本身是额外工作（G1 gap），未计入脚本行数。建议 G6 将"schema 定义"列为前置任务而非脚本实现的一部分。

---

### Q6 · 并行化候选 P1-P5 的"执行保真度风险"是否过度悲观？

**攻击**：S3 教训是"纸面协议防护力为零"，但这针对的是 p̃ 多 LLM 盲生成降档为单 judge 自评的特殊情况。其他并行化候选（如 P5 arena 语义重判）的执行保真度风险可能较低。

**回应**：部分成立。P5 的风险确实较低（样本清单已就绪，只需执行通道）。但 P1/P2 的风险仍然高（外部依赖不可控 + 需实际执行多 judge）。建议区分"执行保真度风险高"（P1/P2/P4）和"执行保真度风险低"（P5），而非一刀切。
