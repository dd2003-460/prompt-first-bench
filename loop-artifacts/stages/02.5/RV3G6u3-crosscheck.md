## A1 · 「+1.0 全列匹配是巧合或系统性数据污染」？

**攻击**：7/7 列恰好 +1.0 太整齐——也许 G3 用的不是同一 gold 集或同一权重方案，只是碰巧；或者两边都读错了某个共享源。
**回应**：
- 若 gold 集不同（3 节点 vs 5 节点），均值差取决于具体成员 rank，不可能在 7 个不同权重方案下全部恰好 =1.0（rank 值域 0–30，3 子集均值与 5 全集均值的差随方案变化）；
- 若权重方案不同，复算值本身就会偏离 freeze doc §5（该表已被 assert-gmr-recompute.py 11 PASS 锚定到冻结 JSON），而我的复算与 §5 完全一致 → 权重侧无分歧；
- 唯一能产生「全列均匀常数偏移」的变换就是 rank 起点平移（r → r+1）。7/7 精确命中使巧合假设不可信。
**判定**：攻击失败。1-based 解释是唯一与全部证据兼容的机制。

## A2 · 「gold 平均排名」可能根本不是 gmr 构念（比如按 run 分位、或排除某类节点）？」

**攻击**：G3 没落盘计算脚本，「gold 平均排名」的定义只是表头一句话，凭什么认定它就是 Σrank(gold)/|gold|？
**回应**：定义等价性不需要 G3 的协议文档来证明——§2 的复算是从冻结 JSON 独立构造的：同一 7 套权重、同一 5 节点严格 gold 集、rank 后取均值。如果 G3 用的是别的构念，其数值不会与这个标准构念的 1-based 版本全列相等。数值指纹即身份。
**残余不确定性**：G3 当时是否真的用严格 5 节点集（而非窄 3 节点集）无法从落盘工件直接读出（stats-w3w4.json 只存 top-5 计数，不存 rank 均值）。但 7/7 全列 +1.0 已经排除了 3 节点集假设（见 A1），所以实际使用的必是 5 节点集——这是由数值反推的，已在 02 §2 标注为推断。
**判定**：攻击基本失败，留一条诚实注记（gold 集归属是数值反推而非协议直证）。

## A3 · 「加注路径违反 current-goal『二选一，不并存』」？

**攻击**：current-goal 要求 global gmr→勘误 / 其他口径→加注，二者不并存。02 的裁定说「6.4/8.6 保留 + 注明它等于冻结 gmr+1.0」——这算不算既承认它是 gmr 又把它当另一口径，自相矛盾？
**回应**：不矛盾。裁定的逻辑链是单值的：(a) 6.4/8.6 在其自身口径（1-based gold 平均排名）下数值正确 → 不满足「global gmr 数值错误」前提 → 勘误路径不触发；(b) AUDIT 把它标成「gmr」造成跨文档口径混淆 → 加注区分 → 加注路径触发。「1-based 等价物」只是注记内容里的事实说明（帮助读者换算），不是把两个口径并列为同等有效判据。冻结口径（0-based）仍是唯一定稿判据，注记明确指向它。
**判定**：攻击失败。二选一被干净地落在「加注」一侧。

## A4 · 「修订 L103 会削弱『扰动幅度最小』论证」？

**攻击**：L103 的论点结构是「top-5 翻转但 gmr 连续移动 → gmr 判据价值在于不反转结论」。如果把 6.4→8.6 换成/标注为 5.40→7.60，+40.7% 比 +34% 更陡，会不会动摇「连续移动」的温和性印象？
**回应**：「连续移动、方案间排序不变」的实质是**序关系不变**（W3/W4-new 仍劣于 W3/W4-orig，但仍优于 W1/W2 两侧——复算表 7.60 < 9.80 < 10.20 维持），不是增量绝对值小。5.40→7.60 下序关系逐对不变，论证原样成立；且 r122 erratum 已确立「勘误后定性结论更强」的先例，此处同理（精确值下 W3/W4-new 与 W2-new 的差距 7.60 vs 9.80 比 1-based 的 8.6 vs 10.8 更清晰地显示同层）。注记不改任何定性句，只补口径出处。
**判定**：攻击失败。

## A5 · 「assert 扩展会不会误伤 Erratum 节自身的合法引用」？

**攻击**：assert-audit8-erratum.py 现有黑名单扫描限定在 Erratum 标题之前的 body 区（r122 设计）。U3 段在 Erratum 节内，若新断言扫全文找「gmr 6.4→8.6」token，会命中 U3 登记段自己的引述。
**回应**：新断言设计为**定点行锚定**（L103/L166 所在行的正则），不做全文 token 扫描；U3 段更新文本中如需引述旧形式，用引号包裹的历史引用形式（如「原『gmr 6.4→8.6』表述」），与 L103/L166 的裸写形式可机判区分。变异测试验证：改 L103 去掉注记 → FAIL；恢复 → PASS。
**判定**：攻击失败（通过断言粒度设计规避）。
