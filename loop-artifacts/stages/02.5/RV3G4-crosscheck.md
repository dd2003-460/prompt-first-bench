## 反方质询（逐条对 02 暂定结论）

### Q1 · 「S1 已规避」是不是把『回避』当成了『规避』？
**攻击**：S1 说的是「短答案任务强加研究树测错构念」。我们的应对是「只在长程研究域用」（§3.1 域限定）。但第二格（新域可构建性验证）从未执行，本仓甚至没有 T17 文件——所以实际证据面只有一个域、一种任务形状。一个只在一个域里跑过的协议说「我规避了构念错配」，和说「我只在一个不会出事的域里测试」是一回事。真正的规避需要证明「在应该用的域里有效 + 在不该用的域里知道不用」，前者只有一个观测点。
**回应**：成立，降级表述。修正判定：**S1 = 部分规避**（原「已规避」撤销）。准确说法：「协议显式声明了适用域边界（设计层规避），且执行未越界（无错误套用实例）；但域边界的正确性本身未经第二域检验——这是『有意识的单域使用』，不是『已验证的域适配能力』」。02 暂定结论第 4 条的自我预警被证实。

### Q2 · S2「未规避」的证据里，adversarial-check 的 finding 是 arena 会话意见，算多硬的 evidence？
**攻击**：adversarial-check-rubric-v3.json 是另一个 LLM 会话写的评审，它的「同源依赖 blocker」本身也可能是误判。拿一个 LLM 的批评当「未规避」的主要证据，等于用一个未校准的 judge 定案——这正是 S3 批评我们做的事。
**回应**：部分成立，补硬证据。同源依赖不依赖 adversarial-check 也成立，仓库内有三个独立事实：(a) gold-tree.md 由 Lead 单人构建（文件头「长出这棵树的过程见 L0→L5」+ 全部数字来自单一 reference/calc.py）；(b) DRAFT §4 补丁文本与 gold 答案结构逐字同构（「生态/成本/瓶颈三问」vs O4「decomp gold 的标准答案形状」——同一作者的两处文本互引）；(c) O2 条款明文「gold 没有的新深层矛盾……不在本次计分内」（DRAFT §1-O2 原文可查）。adversarial-check 降为**佐证**而非主证据——它的外部价值在于独立指出了 (b) 的「答案注射」角度，但定性结论由 (a)(b)(c) 支撑。

### Q3 · S3/S4/S5 全判「部分规避」会不会是偷懒的中庸——三条都用同一个词，区分度在哪？
**攻击**：如果「部分规避」可以套在任何「有设计没完全执行」的情况上，它就失去了信息量。三条的「部分」指向完全不同的东西，应该拆开说。
**回应**：成立，拆分表述。三条的「部分」结构不同，交付物中必须显式区分：
- **S3 = 设计完整 / 执行降档**：纸面协议（≥3 LLM 盲生成 + κ 门禁）超前于 survey 多数 bench，但实际执行是单 judge 自评 + 无门禁回执。缺口在**执行保真度**。
- **S4 = 子项分裂**：版本依赖子项已规避（冻结纪律有字段有断言），跨域可比性子项未规避（主动放弃无补偿）。缺口在**覆盖范围**（一个子项管住了，另一个没管）。
- **S5 = 防护存在 / 被穿透**：截断 + 命名纪律 + 消融前置都在事前就位，但实证规模（头部权重 7.64→2.74 剧变、top-5 翻转）超出防护预期。缺口在**防护强度**。
三种「部分」对应 G5 三类不同的优化动作（强制机械化 / 补覆盖 / 加固阈值），不能混为一谈。

### Q4 · 判定规则「草案写了但没执行 → 最多部分规避」会不会系统性压低分数——有些防护的价值恰恰在于『写下来让未来执行者遵守』？
**攻击**：F1 口径规则把「纸面存在」一律封顶在部分规避。但预注册、协议文档本身就是风险管理工具（写下来 = 未来审计有锚点）。按这个规则，任何还没到执行期的设计都永远拿不到「已规避」，规则本身有偏。
**回应**：部分成立，加限定语。规则保留（本 goal 的判定对象是「当前可运行链条」，不是「设计愿景」），但每条判定附加**时间维度注记**：该防护是「待执行期未到」（如第二格实验，属计划内未到期）还是「执行期已到而降档」（如 p̃ 多模型盲生成，消融已经做完却没用协议方法）。「未到期」的部分规避比「降档」的部分规避乐观——前者等排期，后者要修流程。交付物汇总表加一列「缺口性质：未到期 / 降档 / 覆盖缺失 / 强度不足」。
