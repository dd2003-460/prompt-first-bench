## Q1 · 「总判定 = B 有条件定稿」是否自相矛盾——一边说 S2 未规避、O3 数字不可对外宣称，一边又「定稿」？

**攻击**：如果 O3（rubric-v3 的核心卖点维度）的所有构念效度数字都只能带「相对 Lead-gold」限定，那「定稿」定的只是一个自己都不信的量表。顶刊标准自评（任务书要求）下，这更接近 C（不定稿回炉）。

**回应**：部分成立，接受修正。「定稿」的对象要拆成两层：(i) **协议文本定稿**（DRAFT → 正式版：维度定义/判据/计分规则/实验设计修订完毕）——这个可以且应该现在做，因为 12 blocker 中 L1×5 是纯文本修订、L2×7 的处置方向已明确；(ii) **数值结论定稿**（哪些分数可进论文/排行榜）——这个**不做**，只给宣称边界（J4）。B 选项的准确表述改为「**协议层有条件定稿 + 数值层挂起**」。C 不选的理由不变：负面结果（p̃ 双源偏差、稀有≠重要）本身是可发表的学术贡献，回炉重做不会让它们消失，只会让审计链失去收口点。

## Q2 · E5 把 G3「唯一方向一致指标」降级后，O1 推荐路径还剩多少依据？会不会其实三个口径都不该用？

**攻击**：top-5 计数二元翻转（弃）、top-10 阈值敏感（G3 自己标 ⚠️）、gold-mean-rank 在合法 tie-break 下 W1 可反超 W3（E5 新发现）——那「改判据」改向哪里？也许正确答案是 O3（W1-only + 全部构念效度指标降级为探索性描述），而不是 O1。

**回应**：不成立，但理由表述必须换。O1 的依据不是「gmr 数值上永远优于 W1」（E5 证明这不是真的），而是三点：(a) **扰动幅度**：同一 p̃ 来源切换（orig→new judge）下，top-5 计数从 3/5 翻到 1/5（离散翻转，结论反转），gmr 从 6.4 移到 8.6（连续移动，排序不变）——判据的价值在于 *不反转结论*，不在于绝对值高低；(b) **头部席位解耦**：gmr 把「恰好挤进 top-5 的 3 个席位」稀释到 31 节点全排名，单席交换扰动 ≤ 1/5；(c) **可预注册**：gmr + 固定 tie-break 规则（如按节点 ID 字典序，落盘顺序即此规则）可以事前写死，消除 post-hoc 选择空间——这正是 G3 F3b 声明的 post-hoc model selection 风险的解法。**三口径都不裸用**的立场不变：gmr 为主 + top-10 为辅助描述 + 原 top-5≥3/5 废弃。若第三 judge（O2）数据到来后 gmr 也出现跨 judge 排序反转，则整体退到 O3——这条退出条件写入定稿建议。

## Q3 · 处置表把 B2（O3 同源依赖）标「延后 + 声明局限」，是否等于把 rubric-v3 最致命的洞留给未来，而报告却给出「可定稿」信号？

**攻击**：S2 未规避意味着 O3 测的是「像不像 Lead 的分解习惯」。一个明知核心维度测错构念仍宣布定稿的审计报告，其「定稿」二字会误导下游消费者。

**回应**：部分成立，接受强化。处置表的 B2 行与 R0 执行摘要必须写成：**「定稿 ≠ 通过验收」**——协议文本可以定稿（含 B2 的局限声明条款），但 O3 维度的 *使用* 被门禁住：对外引用 O3 构念效度前，双 gold 或异源 judge（R5.2-third-scorer）二者之一必须闭环。具体落地为 DRAFT 修订清单中的一条硬条款（§1-O3 加「宣称前置条件」小节），而非仅写在审计报告里。这样「定稿」信号被显式降档为「定稿 + 使用门禁」。

## Q4 · 维度级建议「无整维废弃」是否过于保守——P1/P3 在现有 run 中恒为 NA（finding #15），保留它们只是给 rubric 增加两个永远打 0/NA 的死维度？

**攻击**：一个 8 维量表里 2 维永远 NA，对外报分时要么撒谎（报 0）要么尴尬（报 NA）。不如直接砍掉 P1/P3，等通道可用时再作为 v3.1 新增。

**回应**：不成立。理由：(a) finding #15 的 fix 方案本身就是「改判据为可从工件机械提取的代理量」（外部来源比例/独立域名数），改造后 P1/P3 在**现有 run 上即可出分**，不是死维度；(b) 砍维度改变量表结构，破坏与旧版分数的可比性承诺（DRAFT §5 总量纲兼容）；(c) 「NA 档机制」（通道不可用时标 NA 而非 0 分）是 finding #15 fix(2) 的明确要求，它解决的是「基础设施缺口不被记成流程缺陷」的问题——这是评分公平性问题，不是维度存废问题。维持「修改不废弃」，但 R2 表中 P1/P3 的修改幅度标为「判据替换 + NA 档机制」，并注「若代理量改造后两维方差仍 ≈0，则 v3.1 合并入 P-cluster（呼应 finding #7 的簇报建议）」。

## Q5 · 报告要把 G1-G5 的 15+ 条负面结果去重合并，会不会在去重中丢掉某条的限定语（比如把「同族双 judge 范围内」的限定洗掉）？

**攻击**：负面结果声明是任务书明示的必含项，其价值恰在精确限定。合并去重是高风险操作——G4 第 3 条「blindtest 提供了独立校验被限定」和 G5 第 6 条「κ 值计算不可机判」表面都像在说「judge 独立性有问题」，合并时容易糊成一条。

**回应**：成立，接受流程约束。去重规则预注册：(i) 只在「同一假设 + 同一证据 + 同一结论」三条全同时才合并，否则并列保留并互相引用；(ii) 每条保留原始限定语原文（「同族双 judge 范围内」「在 id tie-break 下」等）不得缩写；(iii) 合并后的条目标注全部来源 goal（如 [G4-3, G5-6]）。预计合并后约 12-14 条（G1 3 + G3 3 + G4 3 + G5 6 = 15，其中 G3-1 与 G1 计算层排除相关但不合并、G4-3 与 G5-6 不合并）。

**回应**：部分成立，接受标注。gap-analysis 写作于 aea3d6b（本审计链启动前），其引用的 bench 细节（ResearcherBench 专家 criteria 1-3、RACE 动态 criteria）属结构性特征而非版本号敏感信息，短期内漂移概率低；但报告 R4 节头必须写「事实源 = aea3d6b 快照，外部在线复核 unverified（web-llm 登录过期）」，并把「刷新差异表」列入后续行动清单（R9）的低优先级项。
