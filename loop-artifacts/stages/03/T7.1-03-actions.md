# T7.1 会议室预约系统选型 — 阶段 03 具体行动分解（stage-gate: meeting-room-booking-actions）

> 创建：2026-10-28 · 阶段：03（行动分解）· 依据：阶段 01 分解与冻结候选集、阶段 02 证据、阶段 02.5 证据边界 §四A/B/C
> 执行通道：arena agent mode · **只使用已通过 02.5 的证据（§四A）**；§四C 的 U1–U18 一律按"未核验"对待，不得作为行动前提

---

## 0. owner 约定（修订③）

- **owner = agent**：可离线执行，无需用户交互或登录态（检索、计算、写文档、读仓库）。
- **owner = user**：需要用户的事实输入、商务联系、账号/登录态或采购决策，**agent 不得代答、不得伪造结果**。
- 每个 user 步骤必须标注其在依赖图中的性质：
  - **同步阻塞点**：下游步骤的**结论正确性**依赖它；无答案时下游只能以**显式默认假设**产出，并标记"未经用户确认"。
  - **异步等待点**：下游可照常完成，该步骤只影响后续落地动作（如下单前的最终核价）。

## 1. 行动步骤

### A1 — 汇率与预算基线换算
- **输入**：02.5 §四A-9（1 USD ≈ 6.68，敏感性 6.75）；任务书预算 ¥20,000/年
- **动作**：写并运行脚本，输出年/月预算的美元等值与敏感性区间
- **依赖**：无 · **并行**：可与 A2 并行
- **预期产出**：`outputs/T7.1-cost-model.json` 中的 `budget` 段
- **验收方式**：脚本可复跑；输出含汇率值、来源编号、敏感性上下界；数值可手算复核
- **失败路径**：脚本报错 → 降级为文档内手算并标注"手算未自动复核"
- **owner**：**agent**

### A2 — 硬约束合规矩阵（F2 三端 / F3 双日历）
- **输入**：02.5 §四A-1~8；§四C 未核验清单
- **动作**：对冻结候选集 C1–C5 的每个被核验对象，逐项标注：Web 端 / macOS / Windows 的实现形态；Google Calendar 对接；Outlook-M365 对接；每格附来源编号或标 `未核验`
- **依赖**：无 · **并行**：可与 A1 并行
- **预期产出**：合规矩阵表（进入报告正文）
- **验收方式**：**每一格非空**；非"未核验"的格子必须能追到 S 编号；无任何一格使用 U1–U18 作为肯定依据
- **失败路径**：某候选信息过少无法填表 → 整行标 `证据不足-不进入排序`，不删除该候选（防候选集漂移）
- **owner**：**agent**

### A3 — 成本模型与情景测算
- **输入**：A1 产出；02.5 §四A-1/2/3/4/6/7；G1（会议室数，未知）
- **动作**：按**参数化会议室数 n ∈ {3, 5, 10}** 与**两种日历后端情景**（S-单后端 / D-双后端）计算各候选年度 TCO（人民币），含：订阅费、超额加价（未公开者标 `?`）、硬件、自托管服务器与运维工时折算
- **依赖**：A1 · **并行**：可与 A2 并行（A2 不产出数字）
- **预期产出**：`outputs/T7.1-cost-model.json` + 报告中的成本明细表
- **验收方式**：每个数字可追到 S 编号或标 `估算-未核验`；预算占比列出；n 的敏感性可见
- **失败路径**：某候选价格完全不可核验（Robin/飞书/钉钉）→ 该行只填"不可核验"，**不编造数字**
- **owner**：**agent**

### A4 — 淘汰判定表（D3）
- **输入**：A2 + A3；阶段 01 §6 排除规则 X1–X5
- **动作**：对冻结候选集内**每一个**被考察对象给出"推荐 / 备选 / 淘汰 / 证据不足"四态之一 + 理由 + 触发的约束编号
- **依赖**：A2、A3 · **并行**：否
- **预期产出**：淘汰判定表
- **验收方式**：**候选集内无遗漏项**（含阶段 02 §2 登记的"未核验"对象）；每条理由可追到约束或证据
- **失败路径**：出现"两个候选并列无法排序" → 保留并列并写明区分条件，不强行收敛
- **owner**：**agent**

### A5 — 风险与隐藏成本登记
- **输入**：02.5 §一（X1–X13）、§四C（U1–U18）、§四D（反例）
- **动作**：形成风险表（风险 / 影响 / 触发条件 / 缓解动作 / 责任人）
- **依赖**：A3 · **并行**：可与 A4 并行
- **预期产出**：风险表（进入报告）
- **验收方式**：X4/X5/X6/X7/X9/X10/X12 等未解决矛盾**逐条出现**；每条有缓解动作
- **失败路径**：无（文档性步骤）
- **owner**：**agent**

### A6 — 撰写选型报告（最终交付物）
- **输入**：A2–A5 全部产出
- **动作**：产出 `outputs/T7.1-meeting-room-booking-report.md`，含 D1 推荐方案、D2 ≥2 备选、D3 淘汰理由、D4 成本明细、D5 证据链与未核验声明、默认假设清单
- **依赖**：A4、A5 · **并行**：否
- **预期产出**：报告文件（真实落盘）
- **验收方式**：D1–D5 逐项可勾；**所有默认假设在报告首屏显式列出**；无任何未标注的断言
- **失败路径**：若 A4 得到"证据不足以给出单一推荐" → 报告改为"分情景推荐"（按 G2 的三种情景各给一个推荐），**不伪造单一结论**
- **owner**：**agent**

### A7 — 交付物自检
- **输入**：A6 产出
- **动作**：对照任务书验收标准与 D1–D5 清单逐条核对；核对文件真实存在、链接与编号自洽
- **依赖**：A6 · **并行**：否
- **预期产出**：自检结果写入阶段 04 执行记录
- **验收方式**：清单 100% 覆盖，失败项如实记录
- **失败路径**：发现缺项 → 回 A6 补；补不了则在 04 记"未完成项"
- **owner**：**agent**

### U1 — 确认现有办公套件与日历后端（G2）
- **问题**：① 是否已购 Google Workspace（版本）？② 是否已购 Microsoft 365（版本）？③ 是否在用飞书/企业微信/钉钉？④ "Google Calendar + Outlook"是**两个独立后端并存**，还是**一个后端 + 两种客户端**？
- **为何阻塞**：决定 02.5 §四B-1/B-2 是否成立，直接决定 C1 能否零成本胜出（§四D 第 1 条反例）
- **依赖图性质**：**同步阻塞点**（阻塞 A4 的最终排序）
- **绕行机制（用户未答时）**：按 **DA-2 三情景并列**产出（S-Google 单栈 / S-M365 单栈 / D-双栈并存），每个情景各给推荐，并标注"未经用户确认"
- **验收方式**：用户给出明确答案，或报告中三情景齐备且标注清楚
- **owner**：**user**

### U2 — 确认会议室数量与地点（G1）
- **问题**：可预约会议室总数 n；是否含电话间；办公地点数
- **依赖图性质**：**异步等待点**（A3 已用 n ∈ {3,5,10} 参数化覆盖，不阻塞报告产出）
- **绕行机制**：**DA-1 默认 n = 3**（30 人团队的常见量级，显式标注为假设）
- **验收方式**：用户给出 n，或报告给出 n 的敏感性表
- **owner**：**user**

### U3 — 确认需求定义（G3）
- **问题**：a) "支持 macOS/Windows"是否要求**原生桌面客户端**，Web/PWA/套件内嵌是否可接受？b) Google Calendar 与 Outlook 是否**必须同时**支持？
- **依赖图性质**：**同步阻塞点**（阻塞 A2 的淘汰判定口径）
- **绕行机制**：**DA-3 默认"Web + 主流浏览器 + 套件内嵌即视为满足三端；两套日历必须同时支持"**（取严口径），显式标注
- **验收方式**：用户确认或报告标注默认口径及其影响
- **owner**：**user**

### U4 — 确认预算口径与合规要求（G4 + G10）
- **问题**：¥20,000 是否含税/含硬件/含运维工时？是否要求数据境内存储？是否需要 SSO？
- **依赖图性质**：**异步等待点**（A3 按"含税、含订阅与硬件、不含内部人力"口径先行，另列含人力版本）
- **绕行机制**：**DA-4 默认口径 = 含税的年度现金支出（订阅 + 硬件 + 服务器），内部运维工时单列不计入 ¥20,000**；**DA-5 默认无数据境内存储硬性要求**
- **验收方式**：用户确认或报告口径声明清晰
- **owner**：**user**

### U5 — 向厂商确认未公开价格项
- **动作**：① 向 Skedda 销售确认中国大陆适用区域定价（U8）与 Integrations Pack 是否额外收费（U7/X4）；② 向 Envoy 索取 platform fee 报价（U6）；③ 向飞书客服确认"谷歌日历同步"是否覆盖**会议室资源可被外部预订**（U2 关键空缺）
- **为何 owner=user**：需商务联系/企业身份/登录态，agent 无法执行，且 02 阶段的抓取预算已用尽
- **依赖图性质**：**异步等待点**（不阻塞报告交付，是**下单前的 gate**）
- **验收方式**：拿到书面报价/答复；未拿到则保持 U6/U7/U8 未解决状态
- **owner**：**user**

### U6 — 试用与采购决策
- **动作**：对报告推荐的 1 主 + 2 备选开试用账号，验证双日历同步与三端可用性，然后下单
- **依赖**：A6、U5 · **依赖图性质**：**同步阻塞点**（任务的最终落地，agent 不得代做）
- **验收方式**：试用期内完成一次真实的"Google 侧创建 → 会议室占用 → Outlook 侧可见"闭环测试
- **owner**：**user**

## 2. 依赖关系图（含 user 步骤性质）

```
A1 汇率/预算 ──┐
               ├─→ A3 成本情景测算 ──┐
A2 合规矩阵 ───┴──────────────────────┼─→ A4 淘汰判定 ─→ A6 报告 ─→ A7 自检
                                      └─→ A5 风险登记 ─┘
                 ▲                                  ▲
                 │                                  │
   U3 需求定义口径（同步阻塞点）────────────────────┘（绕行：DA-3）
   U1 套件/日历后端（同步阻塞点）──────────────────┘（绕行：DA-2 三情景并列）
   U2 会议室数量（异步等待点，绕行：DA-1 n=3，A3 已参数化）
   U4 预算口径/合规（异步等待点，绕行：DA-4/DA-5）

A6 报告 ─→ U5 厂商确认（异步等待点）─→ U6 试用与采购（同步阻塞点，终点）
```

**无环性检查**：A1/A2 无前驱；A3←A1；A4←A2,A3；A5←A3；A6←A4,A5；A7←A6；U5←A6；U6←A6,U5。user 步骤 U1–U4 只提供**参数**，不接收 agent 产物，因此不构成回边 → **无循环依赖**。

**并行批次**：
- 批次 1（并行）：A1、A2
- 批次 2（并行）：A3、（A2 完成后可同时起草 A5 的定性部分）
- 批次 3：A4 → A5 收尾 → A6 → A7
- 用户侧 U1–U4 **可与批次 1–3 全程并行**；U5/U6 在 A6 之后。

## 4. 停止条件与失败处理

- **停止条件**：A7 自检通过且 D1–D5 齐备 → 阶段 03 行动完成；U5/U6 属用户侧，**未完成即如实标注"阻塞-等待用户"**，不得标记为完成。
- 单步失败最多重试 **2 次**，仍失败则记录原因并走失败路径（见各步骤）。
- 需要新的外部事实时 → **回到阶段 02**，不在执行记录里临时编造（04 §5）。
- 不得用默认假设"替代"用户答复：所有 DA-x 在报告与执行记录中均须显式标注"未经用户确认"。
