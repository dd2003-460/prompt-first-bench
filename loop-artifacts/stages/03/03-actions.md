## 行动步骤（每步：输入、动作、依赖、并行性、预期产出、验收方式、owner）

### 步骤 S1：核验 Keychron Q1 Pro 规格与价格（主推候选）
- **输入**：阶段 02 来源 S1–S4
- **动作**：以官方站 S1 为准整理 Q1 Pro 规格表；将 S2/S3/S4 的分歧（键数、电池、价格）标注为未核验/价格区间
- **依赖**：无
- **并行**：可与 S2、S3、S4 并行
- **预期产出**：Q1 Pro 规格与价格摘要（带 URL + 2026-10-28 观察时间戳，conf 标注）
- **验收方式**：字段完备（布局/轴体/连接/电池/热插拔/键帽/保修/价格），每条带来源；分歧不被掩盖
- **失败路径**：官方站不可达 → 改用 S2/S3/S4，conf 降 🟡/🔴，标注“非官方来源”
- **owner**：agent

### 步骤 S2：核验 NuPhy Air75 V2 规格与人民币价格（低轮廓替代）
- **输入**：阶段 02 来源 S8–S11
- **动作**：整理官方规格（S8/S9）；记录京东 S10（2024 旧价，标注时效风险）与 Taobao S11（¥699）；不做未经核验的汇率换算
- **依赖**：无
- **并行**：可与 S1、S3、S4 并行
- **预期产出**：Air75 V2 规格与价格摘要（带 URL + 时间戳，conf 标注）
- **验收方式**：价格标明货币与来源日期；旧价（2024）明确标注“可能滞后”
- **失败路径**：商城页面 403/404 → 记录状态并停止（不重复抓取），保留官方源证据
- **owner**：agent

### 步骤 S3：核验 MonsGeek M1W 规格与价格（预算替代），并处理 QMK/VIA 矛盾
- **输入**：阶段 02 来源 S5–S7
- **动作**：整理规格；将 S5（支持 QMK/VIA）与 S6（非 QMK/VIA、专有软件）的矛盾原样保留，标注“存在性断言-未核验”；记录 S6 的 2.4G 不稳定体验
- **依赖**：无
- **并行**：可与 S1、S2、S4 并行
- **预期产出**：M1W 规格与价格摘要 + 矛盾登记表（带 URL + 时间戳）
- **验收方式**：矛盾被原样保留，未被任意一方“修正”；价格区间标注版本差异（M1W vs M1W SP）
- **失败路径**：厂商官方站无 M1W 页面 → 记录“未找到官方来源”，保留第三方评测，conf 降 🔴
- **owner**：agent

### 步骤 S4：核验 Leopold FC750R / FC750R BT（有线备选）
- **输入**：阶段 02 来源 S12–S13
- **动作**：整理规格；由于来源为非官方零售商/聚合页且互相矛盾，全部标注 conf 🔴，仅作为“有线 75% 方案存在”的存在性参考
- **依赖**：无
- **并行**：可与 S1–S3 并行
- **预期产出**：Leopold 规格摘要（conf 🔴 标注）
- **验收方式**：明确标注“数据弱，不进入排序依据”
- **失败路径**：无官方来源 → 记录“无官方规格页可核验”，保留零售商列表
- **owner**：agent

### 步骤 S5：核验 macOS + Windows 双系统切换与键帽兼容性
- **输入**：阶段 02 来源 S1, S3, S8, S9, S14, S15
- **动作**：汇总各候选的 Mac 键帽随盒情况、系统切换方式（物理开关 / 软件切换 / 无）、Fn 多设备切换
- **依赖**：S1–S4
- **并行**：不可并行（需 S1–S4 结果）
- **预期产出**：双系统兼容性对比表（带 URL + 时间戳）
- **验收方式**：每条带来源；无来源者标注“存在性断言-未核验”
- **失败路径**：某型号无公开资料 → 标注“未核验”，不影响其他型号推进
- **owner**：agent

### 步骤 S6：交叉核验矛盾，形成证据边界（阶段 02.5 产出确认）
- **输入**：S1–S5 产出；阶段 02.5 矛盾清单
- **动作**：确认哪些字段可计入已核验证据，哪些保留不确定性；输出最终证据边界（写入阶段 04 执行记录）
- **依赖**：S1–S5
- **并行**：否
- **预期产出**：证据边界声明（已核验字段 vs 不得计入字段）
- **验收方式**：与阶段 02.5 一致，无新增未声明的断言
- **失败路径**：无（文档性步骤）
- **owner**：agent

### 步骤 S7：撰写选购建议报告（主推 + 2 分层替代 + rationale）
- **输入**：S6 证据边界；阶段 01 预算/双系统/编程负载约束
- **动作**：在证据支持范围内给出：1 个主推型号 + 2 个分层替代 + 1 个有线备选；每个方案附 rationale、预估价格、风险；主观手感明确标注为未核验
- **依赖**：S6
- **并行**：否
- **预期产出**：选购建议报告（写入阶段 04 执行记录 §S7 输出）
- **验收方式**：每个方案的依据可追溯到阶段 02 来源；结论未超出证据范围（不承诺“最舒适”等主观判断）
- **失败路径**：证据不足以区分主推 → 保留两个并列主推，不强行排序
- **owner**：agent

### 步骤 S8：用户确认轴体偏好、预算上限并完成采购（用户交互，阻塞）
- **输入**：S7 选购建议报告
- **动作**：用户确认轴体类型（线性/段落/咔哒）、是否接受矮轴、最终预算；下单/采购
- **依赖**：S7
- **并行**：否（同步阻塞点）
- **预期产出**：用户确认记录 + 采购凭证（由用户提供）
- **验收方式**：用户明确确认；若用户未响应，步骤标记为“待用户，不伪造完成”
- **失败路径**：用户不答 → 按阶段 01 降级原则（性价比优先默认假设，显式标注），不强制下单
- **owner**：user
