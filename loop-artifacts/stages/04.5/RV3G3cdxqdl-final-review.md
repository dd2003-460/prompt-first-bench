# 阶段 04.5 — 反方复核（RV3G3cdx-queue-dedup-lint, r149）

> 方法：8 个独立攻击视角逐一尝试推翻「本 goal 交付达标」结论。每条给出攻击陈述 + 证据 + 裁决（驳 / 成立已修 / 部分成立登记）。

## W1 攻击：(a) 「吸收」子串匹配可被误触发——任意含「吸收」字样的行都会把真重复降级为 SIGNAL

**证据核查**：构造测试——同区两行同短名且其中一行含「吸收」字样。实跑 neg-a-samezone-dup 变体：`zones==1` 分支先于 `marked` 判定，同区重复无论是否含「吸收」都走 FAIL。**驳回**——三分支判定顺序（同区 → 跨区+吸收 → 跨区无吸收）使误触发面仅限「跨区真重复 + 恰好某行正文含『吸收』二字」。该残余风险存在但概率极低（goal 正文谈「吸收」需语义巧合），且后果是漏报一条 SIGNAL 级问题而非放行 FAIL 级事故；登记为边界不修（扩规则 = 引入语义判断，违背纯字符串机判原则）。

## W2 攻击：(b)B2 触发词 `**结果**：` 带全角冒号——若未来收口注记写成 `**结果**:`（半角）或 `**结果**: ` 则漏检

**证据核查**：当前 queue 22 处结果注记全部为 `**结果**：`（grep 实证）。脚本实现用子串 `"**结果**：" in body`——**与 docstring 声明不一致**：docstring 写「两种既有写法均命中」但代码只匹配带全角冒号的形态。初版草稿曾用裸 `**结果**` 子串（更宽），重写版收窄了。**部分成立——已修**：改为裸 `**结果**` 子串匹配（覆盖 `**结果：`/`**结果**：`/`**结果**:` 全部变体），重跑 A2/A3 零漂移（pos/neg 样例 verdict 不变，因样例均用标准写法）。

## W3 攻击：(c) 的 `—` 分隔符检查用裸字符——正文中任何破折号（如「r146-r148」外的 em-dash 用法、英文 "well-known" 型连字符混淆）都会让 C2 假通过

**证据核查**：脚本检查 `"|" not in body and "—" not in body`。em-dash `—`(U+2014) 与 hyphen `-`(U+002D) 是不同字符，`r146-r148` 型连字符不触发。但中文行文确实可能用 `—` 作语气破折号（非段分隔）。后果评估：C2 假通过 = 一行既无 pipe 也无真分隔符却因正文含破折号而放行——该行仍通过了 C1（短名非空），只是「段结构」未验证。(c) 的设计目标（02.5 X2）= 防「行格式崩坏到无法提出短名」，不是排版审计。**驳回**——按预注册最小规则，破折号歧义属排版统一范畴（已导出候选），不在 (c) 判定面内。

## W4 攻击：X4 提取式截断至首个括号——短名本身含括号的 goal（如 `R5.2audit-C12-mechanize (2026-10-30, r105)` 型）会被截成 `R5.2audit-C12-mechanize`，与另一行裸短名 `R5.2audit-C12-mechanize` 碰撞产生假重复

**证据核查**：这正是设计意图——L7-L12 完成行的短名段后紧跟 `(date, hash)` 元数据，不截断则同一 goal 的「待办完成行」与「候选区登记行」短名永不相等，(a) 对吸收登记形态失明（L8 vs L49 正是靠截断后才碰撞出 SIGNAL）。假碰撞场景 = 两个不同 goal 一个带日期括号一个不带且前缀相同——当前 46 行零实例，未来概率低。**驳回**（设计内行为，非缺陷）。

## W5 攻击：exit 2 路径 2「零 checkbox 行」会把合法的空 queue（刚初始化、尚未追加任何 goal）误判为错误

**证据核查**：queue 文件头部固定含标题+说明行，空 queue 仍是「有 markdown 无 goal 行」→ exit 2 + `[ERROR] no goal lines`。对 lint 工具而言「无可检查对象」报 ERROR 而非 PASS 是 fail-safe 方向（防止空文件被静默当健康）。ralph loop 协议规定 queue 空时 runner 自找 goal，不存在「合法空 queue」稳态。**驳回**。

## W6 攻击：A5 基线对比用了 git archive 到 /tmp 的 r147 树——/tmp 环境缺 .git 目录，依赖 git 的脚本行为可能与仓库内不同，对比无效

**证据核查**：七脚本中无一调用 git（全部消费 JSON/md 相对路径数据）——cwd 陷阱（04 负面结果 2 关联项）已实证其只依赖文件系统路径不依赖 git 元数据。/tmp/r147base 全树解压保留了完整相对路径结构，脚本行为与仓库内等价。**驳回**。但 04 已登记的 cwd 陷阱提示：该等价性以「完整树 + 正确 cwd」为前提，未来回归应固定 repo root。

## W7 攻击：SIGNAL 不影响 exit code——消费方（未来门禁接入）只看 exit 会漏掉 3 条重复短名信号，等于 (a) 检查形同虚设

**证据核查**：这是 r141 已裁定的仓库级约定（stdout `[SIGNAL]` 前缀分流，assert-goldrank-crossdomain D5 同款），非本脚本特有缺陷。且 (a) 的 FAIL 出口（同区/跨区无吸收）真实存在并被 N1/N2 样例实证——SIGNAL 只覆盖「带吸收声明的合法形态」这一窄集。「形同虚设」不成立：失控形态仍 exit 1 拦截。**部分成立登记**——门禁接入时消费方必须同时解析 stdout SIGNAL 行（与 closure-gate-integration 候选的分流规则同源要求），已在导出候选注记中重申。
