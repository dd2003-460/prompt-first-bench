## A2 · 逻辑攻击

**Q1 · 「协议层定稿 + 数值层挂起」是否只是把 C（回炉）换了个好听的名字？**
攻击：如果 O3 是核心卖点维度且其数字被门禁住，那「定稿」的协议里最值钱的部分恰恰不可用——下游拿到的是「可执行的评分流程 + 不可引用的核心分数」。
回应：部分成立，但 B 与 C 的区别不在 O3 可用性，而在 (i) 负面结果资产（§5 十五条）在 C 路径下同样存在却失去收口载体；(ii) 门禁本身是可执行条款（R-06 写入 DRAFT），C 路径没有这个退出机制；(iii) W1 主公式的 run 排序不受 S2 影响（S2 作用于 gold 命中度量，不作用于权重计算），即协议定稿后 *立即可用* 的产出非空。**维持双层判定**，但确认 §0 已写明「O3 分数在两个限定语之前不应被当作独立证据」——读者不会被误导。✅ 无需修改。

**Q2 · §2 八维全「修改」、零废弃，是否回避了「哪些维度废弃」的任务书问题？**
攻击：任务书问「保留/修改/废弃+理由」，全答「修改」等于没回答取舍。
回应：不成立。「无整维废弃」本身是一个有理由的取舍答案（理由 = Q4 02.5 三条：代理量改造后可出分 / 总量纲兼容承诺 / NA 档解决公平性），且给出了退出条件（P1/P3 方差仍 ≈0 → v3.1 合并）。任务书要求的是带理由的取舍，不是强制必须有废弃项。✅ 无需修改。

**Q3 · §7 零拒绝是否可疑——32 条 finding 一条都不拒，审计者变成橡皮图章？**
攻击：adversarial-check 给出 verdict=revise 和 32 findings，本审计链全盘接受，说明对抗只发生在形式上。
回应：部分成立，需补一句澄清。零拒绝的原因已在 §7.4 写明（12 blocker 的 issue 本身经复核全部成立，分歧只在修复路径），但应显式区分「issue 成立」与「fix 照单全收」：实际有多处 fix 被改道而非照搬——B1 弃 fix(c)、B4 把「预检」整体换成 pilot 两步走、B8 从「找证据源」改成「换判据」、B12 整个 n 估计方法重写、#30 的 κ 验收目标从 judge-judge 改为人-人参照。即 **issue 100% 采纳 + fix 多处改道**，这不是橡皮图章。✅ 表述已足够（§7.4 末句 + 各条理由列），无需修改。

**Q4 · §3.2 推荐 gmr 为主判据，但 gmr 过线阈值未论证——一个没有过线的判据怎么当主判据？**
攻击：top-5≥3/5 因「极严 + 翻转」被废，gmr 接棒却没有自己的过线规则，等于用未定义判据替换未定义判据。
回应：成立，这是真实缺口，但处置正确：§3.2 明确 gmr 的定位是 *方案间比较指标*（连续量、扰动幅度最小），不是单方案 pass/fail 过线指标；过线功能由 top-10 辅助口径承担且显式标「阈值待 RV3G3-goldrank-threshold-proof 正式论证」。两件事分开：比较判据（gmr，可用）vs 过线判据（top-10，待论证）。§3.2 现有文字已表达此分工，但「gmr 不做裸过线」这句可以更直白。→ **修改**：在 §3.2 定义段补一句。

**Q5 · §5 负面结果第 4 条「stats-w3w4.json 未走完验证链 → 证伪」——证伪一个从未正式成立的假设，算负面结果吗？**
攻击：这条其实是「好消息」（验证链其实闭合了），放在负面结果声明里语义错位。
回应：部分成立。它的价值在于修正任务书的原始表述（任务书写「验证链未走完」，G3 证明该担忧不成立）——属于「预期负面结果的排除」，学术写作中 negative-result section 常含此类「falsified concern」。保留，但加半句定位。→ **修改**：条目开头加「（排除项：原担忧不成立）」。
