## 攻击 5：超几何基线的「无效假设参照系」解读是否站得住？

**攻击**：L1 尾段称超几何基线是「零构念效度零偏置」下的参照系。但即使方案对 gold 毫无判别力，top-10 的选取仍依赖权重分布——如果权重本身有结构（如层级相关），「任意 10 节点等概率入 top-10」这个假设也不成立。

**验证**：
- 超几何模型假设的是：在 null 世界（gold 标记与权重独立）下，从 31 个节点中「均匀随机」抽 10 个进 top-10。这确实是标准 null 参照系构造方式（类比 Fisher 精确检验的超几何 null）。
- 权重结构问题（节点相关性、层级共享语境）已在 L3 边界声明第 2 条显式覆盖：「P(X≥t) 的有效样本量 < 名义值，实际置信区间比二项/超几何名义值更宽」。
- 关键逻辑链不受影响：即使真实 null 分布偏离超几何，**低基线率的方向性结论**（t=4 比 t=3 稀有得多）在合理偏离范围内稳健——因为 t=4 的基线率 2.7% 与 t=3 的 17.6% 相差 ~6.5 倍，需要相当强的结构性偏离才能抹平这个差距。

**裁决**：解读站得住，L3 边界声明已覆盖残余风险。✅ 攻击失败（部分成立已被 L3 吸收）。

## 攻击 6：assert 脚本的硬编码期望值是否构成循环验证？

**验证**：
- 脚本的防护目标分两层：(a) **文档↔数据一致性**（文档写的数字 == 从冻结 JSON 现场算出的数字）——这是核心功能，硬编码期望值只是加速 + 提供可读的 FAIL 信息；(b) **文档内部一致性**（L1/L2 表行逐格存在）——防文档文本被单独篡改。
- 若冻结 JSON 被篡改：检查⑤ FAIL（实算 ≠ 硬编码）→ 正确行为，提示「数据源变了，文档需重验」。这正是防漂移断言该有的反应——它守护的是「文档声明与当前数据源一致」这个不变量。
- 真正的循环验证风险（篡改 JSON + 同步篡改硬编码常数）超出单脚本防护范围，由 git 历史 + 冻结数据只读纪律（ralph-loop-runner.md 硬规则）兜底。

**裁决**：设计合理，非循环验证。✅ 攻击失败。

## 攻击 7：t=5「登记不推荐」的理由是否充分？

**攻击**：L2.2 说 t=5「n=31,k=5 下单域几乎不可达，无判别力」「当前数据 0 个过线 → 判据退化为恒 false」。但「当前数据 0 个过线」可能只是当前这批方案都不够好——未来更好的方案可能达到 5/5。拒绝 t=5 会不会过早关闭一个有效判据？

**验证**：
- P(X≥5) = 4/2697 ≈ 0.15%——即使在完美构念效度下，top-10 包含全部 5 个 gold 的概率也受组合空间限制（C(5,5)·C(26,5)/C(31,10)）。这不是「方案不够好」的问题，是**判据本身的可达性上限**。
- 更关键的统计论点：基线率 0.15% 意味着单次观测「过线」的 p-value 极低，看似强信号；但 n=31 单域下没有任何重复观测可以支撑这种极端阈值的校准——一次过线可能是真信号也可能是多重比较假阳性（7 个方案-judge 组合 × 多个候选阈值 = 隐性多重性）。
- 「登记不推荐」≠「永久禁止」：L4.2 的改分工条件机制允许未来数据（batch2 第二域）改变这一判断。

**裁决**：理由充分。t=5 的问题是统计功效（power）不足而非方向错误，「登记不推荐 + 条件开放」是正确的处置。✅ 攻击失败。
