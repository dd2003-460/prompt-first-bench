## 反方攻击记录

### A1「你的 M2=100/100/90 是不是被 bench.md 表格锚定了？」
bench.md r4 表 run1/run2 M2=100、run3 M2=95——我的分 100/100/90 同向。自查：run1/run2 的 100 有一手依据（gate-evidence 记 24 行 / wc -l 实测 25 行），不依赖 bench.md；run3 的 90 是我独立打的（DeepSeek 给 100，我反而更低）。**结论**：run1/run2 存在无法完全排除的锚定可能，但依据链独立成立；run3 反向差异证明非系统性照抄。**残余风险保留声明**（已写入 scoring JSON residual_risk 字段）。

### A2「M7 gate 你判 3/3 pass，但 run1 step3 标 ⏳ 待复验——是否放水？」
execution-log.md 步骤 3 状态 ⏳（'待本 run 内复验'），loop-state.json 记 ok。核验：锚点值 ls-remote=e0d6ddbe… 在日志中写明且可复核（该 hash 为当时 pfb HEAD，git 对象库可查）；⏳ 是流程状态不是锚点缺失。判 pass 成立，已在 basis 留痕。对照 run2：C 断点降级（分支 push）我扣到 85 而非 100——口径一致（降级扣分）。

### A3「per-metric ρ=M1 1.0 会不会让你高估一致性？」
M1 ρ=1.0 仅因 3 点排序相同（55/30/70 vs 55/25/60），绝对差 ≤10。若只看 ρ 会误读为'M1 完全一致'——agreement JSON 已用 full_18pt（r=0.6788）+ κ=0.55 交叉呈现，避免单指标 ρ 误导。n=3 描述性声明写在 method_note。**通过**。

### A4「4 个分歧项你全部倾向自己——自我偏袒？」
是的，4/4 倾向 Claude Code。但这有结构性原因且已如实写进 systematic_pattern：DeepSeek 的 key_reasons 自述 M2/M5 偏低源于 **evidence packet 缺字段**（'证据包未提供任务书行数'/'未提供达 conf≥0.7 所需轮数'），而原始仓库文件里这两个字段都存在（gate-evidence 24 行 / loop-state-r1.json 'conf 0.75' / execution-log '2 轮内完成'）。这不是判断力对比而是**输入不对称**。反证检查：若 DeepSeek 看到了同样的完整证据，其 note 中'当轮数表述明显时它能识别'（run2 M5=100）说明它会改判。裁定倾向标注的是'依据更贴合可验证口径的一方'，符合 G5 标准，且未覆盖任何一方分数。**保留但已充分披露**。

### A5「κ=0.55 的切点 40/70 是挑出来的吗？」
切点是取中方案（低/中/高三档等宽近似），在计算前未看数据分布选择；敏感性未穷举（换 30/70 或 40/60 κ 会变），caveats 已声明。Po=0.7222 的 raw agreement 不依赖切点细节（只依赖档位归属），方向稳健。**通过（带局限声明）**。

### A6「null_count=0 是否掩盖了 run3 M2 的证据缺口？」
run3 M2 原始任务书确实未落盘（只有 r3 json 转述 ~45 行）。我给了 90 而非 null：因为 ≤200 口径下即使保守估计也达标，缺口影响的是精度不是方向；basis 显式标注'二手转述，证据等级打折，扣 10'。按任务书降级规则'证据不足以打某指标→null'——此处足以打（方向确定），故非 null。**判定合理，缺口已留痕**。

## 风险清单（移交 Lead）

- W1 evidence packet 模板需固化『任务书 wc -l 输出 + conf/轮数原文』字段，否则下一独立打分器仍会在 M2/M5 结构性偏低（H2 的直接推论）

- W3 本 bench 的'过程纪律审计分'性质（已知缺陷 #6）再次显现：M6/M7 两打分器几乎零分歧，M4 分歧最小、M2/M5 分歧最大且可归因于输入——分数方差主要来自证据可得性而非质量差异
- W4 κ 切点敏感性与 n=3 局限：一致性结论只作描述，权重校准仍需 n≥5 run（已知缺陷 #1）

## 结论边界
