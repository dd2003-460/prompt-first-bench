## 2. 反方复核（找自己的矛盾）

### 2.1 我可能高估了自己

- 检测器只查「规则文件之间」的引用，**不查「规则 → 产出」的隐含依赖**。例如 03 要求「每步挂锚点」，
  但「锚点存在」这件事要等 04 执行完才知道；路由表无法表达这种时序依赖。
  → 所以我不能说「无漏载」，只能说「**无已声明的文件级漏载**」。
- 示例文件是否真被读，是推断不是实测（无服务端日志）。若实际没读，则 v1.1 的 3,913 是高估，应回到 3,431（body，无 INDEX 无示例）。

### 2.2 结论不能外推到「质量提升」

- 02.5 的 C2（Chroma：shuffled 反而优于 coherent）**未解释**，因此本轮**不得**主张「按阶段切包提升了输出质量」。
- 本轮只有 token 口径证据，没有质量对照（无 A/B 输出评分）。任何「更好」的措辞都越界。

### 2.3 M1 的口径依赖

M1 三个分量里，R 与 G 都依赖「首次」的定义：
- 若「首次」= 本 run 第一 turn 的阶段包 → R 会被算得更高（分母小）；
- 若「首次」= run2 基线的全量 12,086 → R 更保守。
本轮取**后者**（保守），并在 `run6-m1-score.json` 里给出双口径数值，避免单点结论。
