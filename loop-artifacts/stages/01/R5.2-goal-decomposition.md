## 正交因素分解

| # | 因素 | 说明 | 边界 |
|---|------|------|------|
| F1 | 字段完备性 | 模板必须覆盖所有"打分器自认缺字段"的指标维度。已知缺口 = M2/M5（R5.1 定位）；但需检查 M1-M6 是否还有隐性缺字段（如 M1 的 per-run token 切分当时也未给 DeepSeek——token-split.json 是 r4 才做的） | 只固化有直接文本证据支持的缺口为必填；其余进选填清单，不无限扩张 |
| F2 | 一手可提取性 | 每个必填字段必须能从仓库/workspace 原始证据一手提取（wc -l / grep 原文），不能靠转述 | 不可得字段 → null + 原因，禁虚构（沿用 R5.1 A6 先例） |
| F3 | 防虚构约束 | packet 是给独立打分器的输入——若 packet 本身含推断值，会把"结构性偏差"换成"污染性偏差" | 每字段强制三件套：值 + 来源路径 + 原文摘录/命令输出；无三件套 = 不得入包 |
| F4 | 可重放性验证方法 | "消除分歧源"如何可验证？本 goal 不跑第三打分器（外部依赖）→ 用**输入对称性断言**替代：逐项核对 4 个分歧点，确认补齐后的 packet 中该字段存在且与 Claude Code 侧 basis 引用同源 | 断言脚本化（python 校验 JSON 字段非空 + 来源路径存在），exit 0 = pass |
| F5 | 向后兼容 | 模板 v2 不能破坏已有回执结构（r4 deepseek json / r5 claude json 的字段命名习惯） | v2 是"发送前组装的输入包"，不是"打分回执"——两者 schema 分开，回执格式不动 |
