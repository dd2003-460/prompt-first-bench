## 1. 因素及边界（本阶段仅设研究问题，不预设未经搜索的性能）

`C_m[¢/1k_acc] = 100[¢/$] × { (1000/q_m) × c_attempt(m,r,W,U)[$/attempt] + (1000/N_accepted) × F_m[$] }`，只在 `G_identity × G_license × G_capacity = 1` 时比较；否则不合格。这里 `r` 是经授权可用的 API/自托管路线，`q` 是单次尝试真实联合合格概率，包含「代码测试且指令合格」；固定费用 `F` 与总合格量 `N_accepted` 未给定，不能把它们暗置为零并声称完整 TCO。独立同分布重试及稳定 token 用量也是**待验证**模型假设。`1000` 来自题面定义而非外部事实；`100` 是美元→美分单位换算，不是性能评分。

| 一级维度（独占边界） | 可继续递归的子因素 | 已知/待研究 | 02 研究入口 |
|---|---|---|---|
| W — 业务工作量（请求特征，不归属于某模型） | 每次输入与输出 token；Python/JS 的真实任务组合；目标合格量及可接受时延 | 题面有 Python/JS、双 24 GB、千次合格定义；实际 token/组合/量均缺失 | 查公开 coding assistant 请求长度；无来源则明示 `[GAP]`，仅设标明 conf 的情景 |
| Q — 单次联合合格率（只量成功，不计费） | 函数级代码基准；指令跟随基准；两者联合/条件概率；基准→实务迁移率 | 五/六个候选的同条件可比实验未知；禁止凭记忆填分 | 官方 model card/benchmark 原论文 + 独立 leaderboard，记录版本、语言、测试集、prompt/mode；无同条件数据保留 GAP |
| S — 每尝试的可归因服务成本（只计钱，不重计合格率） | API 输入/输出单价；本地 GPU/运行时间或租赁价格；吞吐、利用率、成本分摊；重试请求是否再计费 | 未知所选供应商、地点、模式、硬件购买/租赁、服务 SLA | 模型供应商公开定价/平台价格；硬件 VRAM/吞吐官方与独立复核；无定价就 GAP，不把 token 成本与 GPU 成本相加（互斥路线） |
| E — 准入及固定投资（硬门槛和一次性支出） | 准确模型身份、权重/授权条款、2×24 GB 适配、量化上下文 KV 余量、工程接入成本 F 与摊销规模 | 候选字符串来自题面；是否均存在、可用于内部业务、是否合规/可部署均待查 | 官方模型卡/许可证、架构参数/量化实测；严格 OSI 与宽松开放权重分开；对身份不存在标记不合格 |

参数 `params`/上下文长度会同时影响质量、内存和速率：**共享输入，不是可相加的独立收益**；把权重参数规格记录一次，并在 Q/S/E 之间画跨边引用，不重复当作独立分子。

## 2. 原子性与空缺清单

- 核心空缺 A（阻塞最终单一胜者）：真实 Python/JS 函数级测试 pass@1、指令遵循达标率、同一任务上的联合概率与基准迁移率；搜同一测试条件的一手/独立结果，找不到不声称可计算真实 `q`。
- 空缺 B（影响货币数量级）：各模型对应的可购买 API 产品是否有明确 SKU、同日输入/输出价、模型版本、地域；分别核对至少两处高影响价格信息。
- 空缺 C（自托管能否预算内）：权重精度（W4 的格式/运行时）、双卡显存的权重+KV+运行时峰值、吞吐与利用率。静态重量估算不能当成功部署证明。
- 空缺 D（决定候选有效性）：六个字符串逐一核对模型卡和许可证；题面所谓“开源”是否按 OSI，还是仅需开放权重。不能用名称相近的别的模型偷换。
- 空缺 E（决定完整 TCO）：平均输入/输出 token、业务量、人工测试/修复、采购/集成/运维、延迟 SLA、重试相关性均未提供；除非有实测，终稿保留 `[GAP]` 并提供可复算的情景敏感性，而非估价冒充事实。
