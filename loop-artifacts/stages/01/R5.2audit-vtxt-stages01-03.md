## 01 拆解

| # | 因素 | 口径预注册 |
|---|------|-----------|
| F1 (W2) | VERDICT 段四个数字来源 | '8 confirmed' = `passes` 中 label 以 C 开头且**不含** mismatch 复现标记的条目数；'3 mismatch' = `passes` 中 label 含错配复现语义的条目数；'1 unverified' = `skips` 长度；'1 形式性' = `signals` 长度。**关键约束**：confirmed/mismatch 的区分不能靠正则猜 label 文本（脆弱），必须显式分类载体 |
| F2 | 动态化 vs 注释标记 | 选动态生成（队列候选二选一）。理由：注释标记只是把耦合从"静默"变"显式"，仍需人工同步；动态生成彻底消除。代价 = 需要给 check() 加分类参数 |
| F3 | 零漂移约束 | 正常路径输出逐字一致是硬验收。→ 模板文字必须精确复刻现有措辞（'8 条 confirmed 断言全部复核成立；3 条 mismatch（C3/X4、C11/X2、X6）按预期复现…'），只有数字位变动态量 |

**F1 细化**：现有 check() 调用中，confirmed 类 8 条 = C1/C2a/C2b/C5/C6/C7/C8/C9/C9b/C10/v1packet 共 11 条 PASS 里……等等——重数基线：PASS 共 16 条 = v1packet(1) + confirmed 类(C1,C2a,C2b,C5,C6,C7,C8,C9,C9b,C10)=10 + mismatch 复现类(C3/X4, C11/X2, X6a, X6b, X6c)=5。但 VERDICT 段说 '8 条 confirmed / 3 条 mismatch'——这是**审计表原子断言粒度**（C1-C12 编号），不是 check() 调用粒度（C2 拆 a/b、C9 拆 a/b、X6 拆 a/b/c）。→ **check() 调用计数 ≠ 审计断言计数**，直接 len(passes) 推导会得出 11/5 而非 8/3。**处置**：不试图从 check 记录反推审计粒度数字（那是信息丢失后的重建，必然失真）；改为在脚本内维护一个显式的**审计断言分类表**（AUDIT_CLS = {"confirmed": ["C1","C2","C5",...], "mismatch": ["C3/X4","C11/X2","X6"], ...}），VERDICT 段数字 = len(AUDIT_CLS[cls])，同时每条 check 调用须能在 AUDIT_CLS 中找到归属（新增断言时若忘登记 → 可加一致性断言兜底，见 J4）。

## 02 研究（一手验证 F1 发现）

```
$ grep -c "^PASS" <(python3 assert-packet-audit.py)   # 16
$ grep -oP 'C\d+' ... | sort -u                        # C1 C2 C3 C5 C6 C7 C8 C9 C10 C11 C12 + X4 X2 X6
```
确认：check 调用粒度（16 PASS）与审计断言粒度（8+3+1+1=13 条原子断言）是两层不同抽象，中间隔着 C2→C2a/C2b 等拆分。VERDICT 段引用的是后者。→ 动态化的正确对象是**审计断言清单**（显式列表），不是 check 计数器。这与 r131 signal-counter 方向一致（信号项已有 signals 列表载体）但层级不同：r131 管 SIGNAL 粒度（1:1），本 goal 管 CONFIRMED/MISMATCH 粒度（N:1 映射需显式声明）。

## 02.5 对抗核验

| # | 攻击 | 裁决 |
|---|------|------|
| A1 | "显式 AUDIT_CLS 列表本身就是另一种硬编码事实快照——新增断言忘了登记进列表，VERDICT 段照样撒谎，只是从'改文字'变成'改列表'" | 部分成立。缓解：J4 一致性断言——遍历所有 check/skip/signal 调用的 label，要求每个 label 的审计归属前缀出现在 AUDIT_CLS 某类中（或显式 EXEMPT），否则 FAIL。这样漏登记 = 机判 FAIL 而非静默撒谎，缺陷性质从 fail-silent 升级为 fail-loud，与 r132 同判据 |
| A2 | "为什么不干脆删掉 VERDICT 段，只留汇总行？" | 驳回：VERDICT 段承载审计语义（哪几条按预期复现、哪条留人工），汇总行只有计数；删除是信息损失。且冻结纪律下改动面最小优先 |
| A3 | "A1 的一致性断言本身要解析 label 文本（如 'C3/X4 run1 …' 提取 'C3/X4'），又是正则猜文本？" | 驳回：提取规则简单且封闭——label 首 token（到第一个空格为止）即审计 ID；对 16 条现有 label 全量实证无歧义（见 04 J1 自测）。这不是猜，是命名约定的机判执行 |
