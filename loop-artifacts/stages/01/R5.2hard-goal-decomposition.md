# 阶段 01：目标拆解 — R5.2-sourcepath-hardening

> origin: ai · 2026-10-30 · 输入 = `tasks/current-goal.md` + `r5/assert-packet-symmetry.py` file_reachable (L72-97)

## 1. 问题定义（W1 原文）

R5.2 04.5 W1 登记："file_reachable 的 basename glob 兜底可能误判同名文件（run1/run2/run3 各有 execution-log.md / loop-state.json）；触发兜底的条目已人工核对路径真实存在。后续版本应让 source_path 强制完整相对路径。"

具体机制：`file_reachable()` 对 source_path 做 `re.findall(r"[\w./\-]+\.(?:md|json|txt)")` 提取路径 token，在 WS/PFB/workspace 三个 base 下 `os.path.join` 尝试命中；**全部 miss 时退化为 `glob(WS/**/<basename>)` / `glob(PFB/**/<basename>)`**——只要任意目录存在同名文件即返回 True。source_path 里的 `.../` 缩写前缀（如 "WS .../r3/run1/loop-state-r1.json"）使 token 变成 `r3/run1/loop-state-r1.json` 之类，join 到 WS 根必然 miss → 落入 glob 兜底。

## 3. 改造方案（F 因素分解）

- **F1 脚本侧**：`file_reachable()` 重写为严格模式——
  1. git 对象形式（`commit <hash>` + `tasks/*.md`）→ `git show` 可达性检查（保留，本就无 glob）；
  2. 本地文件：提取所有路径 token，**每个 token 必须在某 base 下 join 命中**；任一 token miss → 该 source_path FAIL（删除 L92-96 glob 兜底整段）；
  3. 多文件 source_path（`+` 分隔或空格并列）→ 逐 token 独立判定，全部命中才算 PASS（语义收紧：原来"任一命中即可"）。
- **F2 packet 侧**：把 6 条 GLOB-FALLBACK + 4 条含缩写段的 source_path 规范化为完整相对路径（base 前缀用可解析形式，如 `WS:` 标记或直接写绝对路径——与现有 JOIN 命中的条目风格一致，即直接写 WS 绝对路径）。字段值（wc_l_output/rounds/source_quote 等）**一律不动**，只动 source_path 字符串。
- **F3 验收映射**：current-goal 验收 6 = 重跑 exit 0 且 PASS ≥ 67。注意：严格化后 check 数量可能变化（原脚本对每个 source_path 只做 1 次 file_reachable 调用；若改为逐 token 报告则 PASS 数增加）——设计为保持原 check 粒度（每 source_path 一条 check），PASS 数维持 67。
- **F4 不做的事**：不改 assert-packet-audit.py（那是 r103 交付物，逻辑独立）；不改任何分数/字段值；不改模板 v2 的 schema（source_path 填写规则可在模板里补一句"禁 `...` 缩写"，属可选加固，见 03 A4）。

## 4. 风险预判

| 风险 | 预案 |
|------|------|
| 某 source_path 规范化后 join 仍 miss（路径记错） | 诊断已预验 6 个目标文件全部存在（ls exit 0）→ 预期不发生；若发生 → 按 current-goal 失败降级条款进 EXEMPT 显式豁免清单 |
| 逐 token 收紧导致原本 PASS 的 P4/P6 条目 FAIL（其裸相对尾段 token 无法独立 join） | F2 同步把这 4 条也规范化（写全路径），不依赖"首 token 命中即过"的旧宽松语义 |

**判定：pass（18 条 source_path 全分类，6+4 条待规范化且目标文件预验存在，改造方案双向（脚本+packet）闭环）。**
