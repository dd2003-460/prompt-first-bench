# R6 · 阶段 01 目标分解：漏载失效模式

> 规则包：`00-common-review.md` + `01-goal-decomposition.md` + `02-information-research.md`（4,091 o200k，阶段门控）
> 父任务：`bench/self-opt-tester/runs/r6/task-brief.md`

## 1. 目标重述（一句话）

阶段门控把「每轮全量 7 文件」换成「按阶段读 2–3 文件」；本阶段要回答的是：**这种削减会不会让 agent 在某个阶段手里缺料**，且缺料必须可被机器检出，而不是靠人肉 review。

## 2. 正交分解（4 类，互不重叠）

| 编号 | 失效模式 | 定义 | 判据（可机检） | 与其它类的边界 |
|---|---|---|---|---|
| R-miss | 规则缺载 | 进入阶段 N 时，该阶段规则文件未加载 | INDEX 路由包的成员集合 ≠ 该阶段规则文件集合 | 只谈「规则文件」，不谈产出 |
| A-miss | 产出缺载 | 阶段 N 需要上游 `loop-artifacts/stages/M/` 的产出但文件不存在/未读 | 规则文件里声明的上游产出路径 → 目录内是否存在对应文件 | 只谈「loop-artifacts 产出」 |
| G-miss | 门禁缺载 | 阶段 N 未执行判定就进入 N+1 | 每个 stage 目录下有判定行（pass/revise） | 时序性质，与内容无关 |
| X-miss | 路由缺载 | INDEX 路由表本身漏画某条跨阶段依赖 | 规则文件 A 引用了规则文件 B，但 B ∉ route(stage(A))，且 B ≠ A | 元层：前三类都合规仍可能发生 |

**正交性**：R=规则文件层 / A=产出层 / G=时序层 / X=路由表层，四者两两不可推出。
**覆盖性**：任一「进入阶段后信息不全」的事件，必然落在「规则没读（R）／产出没读（A）／没走门禁（G）／路由表没写（X）」之一，不存在第五种。
**原子性**：每条都有 ≥1 个可执行判据（文件存在性 / 集合包含 / 文本引用），不依赖人工判断。

## 3. 已知 vs 空缺

- 已知：7 个规则文件、6 个阶段、INDEX 路由表（已落盘）；阶段包 token 已实测。
- 空缺：
  - H1：规则文件之间的跨阶段引用到底有多少条？（需扫文本，`见 0X-` / `参考 0X-`）
  - H2：哪些阶段声明了「读上游产出」？（需扫 `loop-artifacts/stages/`）
  - H3：INDEX 是否把 H1 的引用都覆盖了？（= X-miss 是否真实存在）

## 4. 阶段判定

- 正交/覆盖/原子三项自检通过；H1–H3 三个空缺全部可在阶段 02–04 用脚本闭合。
- **verdict: pass** → 进入阶段 02。
