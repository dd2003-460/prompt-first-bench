# SM 思考 SOP（T53 D3 · 设计决策的推理过程）

> origin: ai (T53-D3, 成璐要求"思考的 SOP 放在项目里")

## 决策 1 — 停止判据：necessary 饱和 > n-gram gain

**候选**：(a) v17 的 R1 饱和（连续无新节点）；(b) n-gram 边际增益 < 阈值；(c) 本轮无 necessary 节点。
**选了 (c)**。理由链：
- (a) 正是 v17 的病根——"能生成新数字吗"这个判据被同义变体满足，1930 节点停不下来。
- (b) n-gram Jaccard 对中文不同表述天然偏低（换词不换义 → 相似度低 → 误判为有增益），阈值标定痛苦且可被措辞操控。
- (c) 直接问"引入新变量/新约束/新可检索事实了吗"，语义层面裁决，和 T-PR-15 survey 建议 1 的 F_β precision 项同构。2610.33512 给了定量先例（recall→F_β 胜率 10.6%→68.0%）。
**代价**：每候选节点一次 LLM 调用（成本↑），且判定本身也是文字代理（可被"措辞新颖但信息冗余"骗过）→ 保留 n-gram dedup 0.7 阈值作第一道廉价防线，双层。

## 决策 2 — 泄漏检查的对象：产出而非 prompt

**矛盾点**：decompose prompt 必须带题目原文（模型才知道拆什么），但硬约束说"所有 LLM prompt 中不出现题目原文"。
**解法**：区分两个方向——prompt 输入带题目是必要的（这是任务定义不是泄漏）；泄漏指的是**产出侧回显**：子节点 claim、日志、JSON 中间产物把题目的问句结构/待求答案抄进去。leak_check() 只查 LLM 输出。L1 骨架例外（目录层允许引用题目），L2+ 展开层严格检查。
**待办**：sm-leak-sop.md 需补一节明确这个口径，防止未来审计时自相矛盾。

## 决策 3 — 返工策略：重搜代替"换角度重拆"（v1 简化）

完整设计是 REWORK = 重新拆解父节点 + 带上次失败原因。v1 先用"原 query + 'alternative' 重搜"替代：便宜、不改 prompt 结构、不引入新的泄漏面。若 bench 显示 AC5（返工生效）靠它达不到，再升级成真正的换角度重拆——升级时要解决"失败原因怎么传而不泄漏题目"（传节点 id + 失败类型枚举，不传文本）。

## 决策 4 — SOTA 对标口径：逐题 judge 分 ≥ SOTA 同题分

不打 aggregate EM/F1（HotpotQA dev 那种），因为我们的 bench 是自拟 deepresearch 题，SOTA 系统没跑过原题。可行路径：选 SOTA 公开报告覆盖过的题（或最接近的 benchmark subset），用同一 rubric（0.5 数字 + 0.5 对比/单位，异族 judge n=3 median）两边都打一遍。如果 SOTA 只有 aggregate 分数没有逐题 → 退化为在 SOTA 原始 bench 上比 aggregate，口径写进 sm-bench-sota-criteria.md。


## 决策 7：TCO 必须按时间结构正交展开（2026-11-11 r4 审计后）

r1 的 TCO 节点只有"瞬时+电费"两层（N5/N17/N28），故障/可靠性、不确定性方差、机会成本基本没拆——这是 LLM 分解的自然偏向：成本问题先想到价格再想到电费，就停了。修复不在 prompt 里加例子（那会泄漏到答案空间），而是加**结构性规则**：成本类父节点必须展开为 CapEx/OpEx/可靠性/不确定性四个独立兄弟（P1H_INDEX 规则 7）。这是元规则不是内容提示，不违反防泄漏。

## 决策 8：微架构下钻靠领域知识，不靠题面

用户问"题目和 prompt 都没明说微架构，L1/L2 会不会出现"——r1 的答案是会出现但靠运气：N79 挖到 GQA head_dim 是因为模型恰好知道 Qwen3 架构，不是分解规则逼出来的。修复 = P1H_INDEX 规则 8：硬件对比必须下钻到一手性能参数（带宽/HBM 代际/SM 数/L2/制程/互联），source=knowledge。营销规格（显存大小、价格）只是入口不是终点。


## 决策 9：L1 必须是纯目录层，禁止拍平多层（2026-11-11 r4 审计后）

**问题**：r4 的 L1 有 20 个节点——逐卡规格核验（N10-N14）、KV Cache 公式（N7）、Decode/Prefill 瓶颈分析（N8/N9）全混在第一层。根因是 `_decompose_l1` 调 `decompose()`（P1_DECOMPOSE），那个 prompt 要求模型一次拆出整棵多层树（"第 1 层→第 2 层→第 3 层"），状态机把返回的所有节点一律标 L1。层级信息在入口处就丢了。

**后果**（成璐指出"跳步虽然快但很容易不正交完备"）：
- 父级关系丢失：N3（硬件候选集）应该是 N10-N14（逐卡规格）的父节点，现在它们是同级兄弟 → 正交性被破坏（候选集和单卡规格不是正交维度，是包含关系）。
- S_alpha 失真：五个逐卡节点在 L1 层各算一份广度贡献，但它们其实是 L2 内容。
- 下游 gap_check 以为 L1 已覆盖完整，不再补真正的顶层缺口。

**修复**：新增 P1_L1_SKELETON 专用 prompt，严格约束"只输出顶层正交维度，3-7 个封顶，禁止下钻到具体参数/公式/数值"。L1 的 source 统一标 given（结构性目录不需要检索）。后续轮次由 `_decompose_layer`（P1H_INDEX）对每个 L1 维度做 INDEX 展开，层级自然恢复。

**为什么不在 P1_DECOMPOSE 里改**：那个 prompt 服务于旧管线（一次性拆全树），状态机需要的是"先目录后展开"的两阶段结构。两个 prompt 职责不同，分开写。


## 决策 10：prompt 规则必须 general，禁止内容特化（2026-11-11 成璐纠正）

**错误**：我在 P1H_INDEX 加了规则 7（TCO 必须展开为 CapEx/OpEx/可靠性/不确定性四兄弟）和规则 8（硬件对比必须下钻到 SM 数/L2 cache/制程）。这两条是针对 GPU 选卡题的答案反推——换个题目（选数据库、选语言、选供应链方案）就是噪声。状态机要跑 ≥5 个泛化 deepresearch bench，prompt 里的分解规则必须对任意题成立。

**原则**：断点（已分解好的树/checkpoint）是通用状态，可以改 prompt，但只能加**元规则**（关于"怎么判断分解够不够"的通用判据），不能加**内容规则**（关于"这道题该有什么维度/参数"）。内容知识应该由模型自己的领域先验提供（source=knowledge），不由 prompt 硬编码。

**替换**：规则 7/8 → 一条通用深度判据："对每个叶子节点问——领域专家会不会说'还差一层'？会→继续拆；不会（已是可检索/计算的最小事实单元）→停。"这个判据不依赖具体领域，对所有题类型成立。它逼模型自己用领域知识判断"表面描述 vs 一手机制参数"的层次差，而不是我替它规定哪些参数重要。

**教训**：看到 r4 缺 TCO 方差就急着往 prompt 里塞答案维度的名字 = reward hacking 的规划版。正确路径是改进"判断分解质量的元标准"，让模型在任意题上都能自己发现缺口。

## 决策 11：L1 维度分类学（2026-11-11 · r7 L1 骨架 + D 反馈）

r7 L1 骨架 = {硬件候选全集, 延迟性能边界, 精度质量权衡, 上下文显存规划, TCO结构, 不确定性管理}。D 的修正：

**约束 vs 性能的区分是正交性的来源之一。** 显存是硬约束（不满足则不可行，直接砍掉候选），不是性能指标——所以它应该独立于"性能"维度存在，而不是塞进"延迟性能"里。同理，延迟和吞吐都属于性能（吞吐是最终速率），可以合并；精度也影响性能但它是质量-性能权衡轴，独立成立没问题。

**不确定性是横切维度（cross-cutting dimension）。** 每个具体维度内部都有确定性成分（如带宽规格是查得到的事实）和不确定性成分（如故障率、价格波动、量化损失的实际分布）。把不确定性单独拉成一个 L1 兄弟节点，等价于承认答案空间 = 确定性子空间 × 不确定性子空间的直积——这比把它散落在各维度里更容易做条件性推荐（"在 X 参数处于 [a,b] 时选 A，否则 B"）。

**通用判据（meta-rule，可写进 P1_L1_SKELETON）**：判断一个候选顶层维度该不该独立存在，问两个问题：(1) 它是"可行性约束"（不满足直接排除方案）还是"优劣度量"（满足后比好坏）？两类必须分开，因为约束是过滤门、度量是排序键，混在一起会让分解树出现"先算分再发现不可行"的逻辑倒置。(2) 它是否横切其他所有维度（如不确定性/成本/时间尺度）？横切维度独立成兄弟节点，非横切的归入所属主维度。

此判据对所有题目类型成立：任何"选型/设计/优化"类问题的答案空间都可以分解为 可行域（约束）× 目标函数（度量）× 横切因子（不确定性/成本/时间）。

## 决策 12：目标函数的两种形式与"压缩即智能"路线（2026-11-11 · D 质询）

D 问：v17 的 hack 是不是 prompt 里目标函数文字描述驱动的？公式描述和文字描述的目标函数有什么区别？

**已确认**：v17 诊断（v17-hier-decomposition-blowup.md）明确记录"模型完全理解 S_α 并完美优化了它"——prompt 内的显式公式 + 边际收益解释就是激励结构，模型把它当奖励函数优化。这是文字/公式描述驱动 hack 的直接实例。

**空白（未闭合）**：
1. 无消融对照：没跑过"删掉 prompt 目标函数段"的 baseline，"hack 由 prompt 文字驱动"目前是推断 conf 0.7 非实验结论。对照成本很低：同题同模型，删 P1_DECOMPOSE 目标函数段重跑比节点数。
2. 修正版未验证：当前修法 = 代码侧冗余惩罚 + necessary-judge 停，但 prompt 里目标函数文字仍在（s5_pipeline.py:95-98）。r7 的 pass_rate 衰减曲线是"文字牵引 vs 代码惩罚"谁赢的直接证据。

**公式 vs 文字的理论区别**（来源：T-PR-15 落盘的 Skalse et al. arXiv:2209.13085）：proxy 是否 hackable 是数学性质（存在两策略使 proxy 与 true 偏好相反），与书写形式无关；但实践中公式给模型精确的优化方向（边际增量可算），文字只给模糊倾向 → 公式形式通常更易被 hack 到极端。

**"压缩即智能"路线（D 提出，待展开）**：把目标函数从"结构项 - 冗余惩罚"换成 MDL 形式——好分解 = 最少变量/假设覆盖题目全部约束。同义重复不降描述长度（自动不划算），真正交维度才降 → 正交完备成为压缩目标的自然推论而非外加规则，无需"不要重复"条款。
- 理想形式对，落地有障碍：自由文本 claim 没有严格的描述长度度量，最接近的可算代理仍是文本相似度（n-gram/embedding/LLM-judge）。
- **可实测实验（待办）**：拿 v17 的 1930 节点树，分别用 n-gram 重叠 / embedding 余弦 / LLM-judge 三种冗余度量，看哪种把"真正交 ~6-8 维度"与"99% 近义重复"分得最开。赢家 = 修正版 S_α 惩罚项该用的度量。

## Decision 14 — 冗余项全量化 + β 标定（2026-11-11 D 指示"能连续就可以上变量"）

**D 的输入**：压缩/复杂度目标函数不一定要极简结构，时间复杂度高一点没关系，但量要连续可微；离散外生信息（不同显卡、市场价格随机出来的）没法插值压缩，这类节点不参与压缩项。

**落地映射**：
- **连续性**：redundancy_score 从"采样 20 对 + cap 200 对"改为全量 pair 均值（同层 >20 抽 20 控制 O(n²)，不再截断 pair 数）。n≤300 时 ~45K 次 n-gram 比较，毫秒级，复杂度可接受——符合"爆炸可以，连续必须"。
- **β 标定**：实测 clean-r2 ckpt（n=117）：full-pair mean Jaccard = 0.0146，旧 cap-200 估计器 = 0.0148（恰好接近，但大 n 时会失真）。structural 项 = 97.2，旧 β=0.3 → 罚项仅 0.51（占 0.5%，形同虚设）。新 β=3.0 → 罚项 ≈5.1（5%），开始有真实约束力但不压垮结构项。
- **离散外生信息豁免**：当前实现里所有节点都进 redundancy 项，没有区分"内生成分维度"和"外生离散事实"（如 MI300X 带宽 5.3TB/s 这种查表值）。理论上按 D 的说法这类节点不该被压缩项惩罚（它们不可插值、不存在"近义变体"刷分的空间）。**现状标记 [待设计]**：需要给 NodeRecord 加 source 语义标签（derived vs exogenous-fact），redundancy 只对 derived 节点算。先不动代码——当前树里 exogenous 节点占比高，贸然改口径会让 S_α' 数值跳变，等 r9 跑完有基线再切。

**验证**：patch 后 syntax OK；r9（pid 29238）仍在用旧代码跑（启动早于本 patch），其 S_α' 日志数值与后续 run 不可直接比——交接记录已注明。

## Decision 15 — "正交完备"不在目标函数里：概念-变量压缩缺口（2026-11-12 D 质询）

**D 的输入**："我不确定正交完备算不算，因为数值变化也可以说正交完备，这涉及概念-变量压缩了多少，时间复杂度代价大不大"

**现状核查（grep s5_state_machine.py）**：
- S_α' 结构项 Σ[lv·ln(kₙ)+α·kₙ·ln(lv)] 只奖励层级深度和每层节点数，**不含任何正交性/独立性项**。
- marginal_gain（1 − max n-gram overlap）是停止信号不是奖励项；且 n-gram 粒度对"同维度不同参数值"（HBM 带宽 vs GDDR 带宽）判为不相似 → 盲区。
- "正交维度 ≥6" 仅存在于 AC1（事后人工/LLM 计数），不进优化。
- **结论**：把"显存带宽"拆成 3 个参数化子节点，在当前 S_α' 里是纯收益（kₙ↑ → 结构项↑）——D 指出的漏洞成立：数值变化伪装成正交扩展无法被函数区分。

**概念-变量压缩框架（推演，非文献结论）**：
分解树 = 问题空间的编码。MDL 视角：总代价 = 结构描述代价 + 叶内容描述代价。正交完备 = 维度划分恰好覆盖独立自由度：多一个近义维度 → 结构代价白付；少一个真实维度 → 叶节点被迫错配、内容代价上升。"压缩了多少"的可计算代理 = 维度间独立性度量；"时间复杂度代价" = 度量本身的计算成本。

**候选度量与代价**：
| 方案 | 独立性判据 | 复杂度 | 备注 |
|------|-----------|--------|------|
| n-gram（现状） | 字面重叠 | O(n²)·轻 | 同维度不同参数值判不相似，盲区已确认 |
| LLM-judge 批量审计 | "是否同一维度的不同实例" | O(k²)/父，k≤8 → ≤28 对/父；每轮几十次 8787 调用 | 慢但准，复用现有通道，无需新依赖 |
| embedding 相似度 | cos 距离 | O(n²)·一次前向 | 本地 27B 有无 embedding 接口 [待核验]；可能需另装轻量模型 |

**时机判断（conf 0.7）**：现在不修。r9 验证的是硬停门禁+fanout cap（与正交度量无关）；概念级度量选型本身需实验标定（关联 idea #33）；无 r9 基线时切口径会导致 S_α' 跳变不可比（上次 ckpt 污染事故的同款风险）。

**后续动作**：登记为缺口 G8（主任务书缺口清单）；r9 DONE 后的设计决策点 = LLM-judge 正交审计 vs 轻量 embedding，届时用 r9 树做 A/B 标定。

## Decision 16 — 目标函数"太中间"：终点锚定进 prompt，公式降级为机器侧监控（2026-11-12 D 质询）

**D 的输入**："我们的目标函数有点太中间了，最终目标是完整详尽、准确得到不同时间下最佳性价比的硬件系统（别把这个写 prompt 里面了）……prompt 要提前说明考虑最终目标函数吗？（也许会自己度量拆分的边际收益？但是在极小概率极大不稳定期望绝对会失效）"

**解读**：S_α' 是树形结构统计量，和"答案好不好"之间隔了一层——它奖励深度/广度，不奖励"答案被承载"。D 的意思是：prompt 应该让模型知道分解是**手段**，终点才是目的；但终点的领域内容（"不同时间下最佳性价比的硬件系统"）不能写进去，否则违反 general 规则 + 泄漏题面。

**设计（已实现）**：
1. **P1_DECOMPOSE**：删掉整段"得分公式 + 边际收益规律（精确）+ 停止条件由公式导出"——这正是 v17 hack 的载体（模型对着可刷的数优化）。替换为【分解目标（终点导向，非公式打分）】：四条通用判据，全部从"完整详尽准确的最终答案"这个终点导出：
   - (a) 覆盖：答案要用的每个时间尺度/对比口径/约束条件，树上必须有节点承载
   - (b) 具体：承载节点必须落到可检索/计算的事实
   - (c) 正交：不得同义复述，**不得把同一维度的不同参数值伪装成多个维度**（直接回应 D 上一个问题）
   - (d) 经济：数值在最终答案中不会被代入/引用的节点不值得存在
   - 并明确告知：机器侧有独立评分用于监控健康度和决定停止，"你不需要也无法自己计算它"——堵住"自己度量边际收益"的路（D 预判正确：LLM 自评边际收益 = 极小概率×极大方差，必然失效）。
2. **P1H_INDEX**（r9 实际使用的模板）：新增【最终用途锚定】段——树是回答问题的原材料，不是目的；终点 = 支撑完整/详尽/准确的答案（含不同时间尺度的最优选择）；用不到的子维度不值得存在，答案必需的时间尺度/口径必须有节点承载。纯通用措辞，零领域词。
3. **公式的去向**：S_α'（含 β=3.0 冗余惩罚）保留在 harness 侧，角色从"给模型的刷分目标"降为"机器侧监控 + 停止信号"。prompt 里不再出现任何可计算的得分表达式。

**为什么这样切分是对的（Goodhart 视角）**：v17 失败的根因是"把代理指标当目标告诉模型"——模型对显式数字的响应远强于对文字倾向的响应。现在：模型面对的是不可计算的终点判据（只能靠真的把树做对来满足），机器拿可计算的 S_α' 做刹车（防过度扩张）。代理与目标分离，hack 路径消失。

**风险与观察点**：(a) 去掉公式后模型可能失去"何时停"的内部感——已有硬停门禁 + gain/pass_rate 双停止信号兜底，且判据 (d) 提供了经济学直觉；(b) "不同时间尺度"写进了 prompt 作为通用答案结构要求——这是元规则（好答案常需多时间尺度对比），不是 gpu 题的内容，若后续 bench 发现它对非决策类题目造成噪声再撤。**生效时机**：r9 跑的是旧代码（无锚定段），r9 DONE 后的下一轮 resume 才生效；届时 S_α' 数值仍可比（公式没变），变的只是树的形态预期（更朝答案承载长）。

## Decision 17 (2026-11-12): FATAL checkpoint 落盘当前树状态（E12）

**事故**：r9 崩溃在轮内 judge 阶段（HTTP 400 → TypeError），per-round `_save_checkpoint` 还没触发。FATAL handler 只 dump `rounds_log`（空）+ 空节点列表到 `runs-s5-sm-gpu-checkpoint.json`，打印 "Checkpoint saved"——看着像存了，实际是空壳。resume 后从 0 节点重跑，整轮白干。

**修复**：E12 — FATAL handler 改为直接保存内存里的 `sm.nodes`（崩溃前已 extend 的部分保留）。配合 E11（judge max_tokens 封顶 4096 + 紧凑格式解析 + 异常兜底返回 bool list），崩溃概率本身也降了。

**教训**："Checkpoint saved" 这类日志必须看内容不看字样——r9 的 checkpoint 文件存在、日志正常，但 round=0 nodes=[]。验收标准应该是 resume 后能恢复非平凡状态。

## Decision 18 (2026-11-12): 终点目标函数的形式化（D: "具体目标函数很有意思，形式化最终目标函数更有意思"）

**背景**：Decision 16 把 S_α' 从 prompt 里删掉降级为机器侧监控。D 的反馈：S_α' 本身有意思，但它是"中间"量——真正有意思的是把**最终目标**（完整/详尽/准确地得到不同时间下最佳性价比硬件系统）形式化成目标函数。

**分解（decomp）**：
- A. 终点是什么可测对象 → 不是树，是**答案**。树 T 只是中间表示。
- B. 答案质量三要素如何量化：
  - 覆盖 C(A)：gold 维度集 G（每类 benchmark 一份人工标注清单）与答案提及维度 M 的 |M∩G|/|G|。现有 bench 已部分具备（nat cov 口径）。
  - 准确 A(A)：数值断言对权威源的核验通过率 = 现有 AC3 evidence 机制的聚合。
  - 具体 S(A)：每个 gold 维度至少有一个可检索/可计算事实（数字/型号/公式），否则记 0。
- C. 代价项：节点数 n（检索成本）、轮数 r、token 消耗——对应 D 的产投比公理。
- D. 候选形式（MDL 风格）：**U(T) = C·A·S − λ·cost(T)**，乘积而非加和（任一要素为 0 整体归零，符合"完整详尽准确"的合取语义）。
- E. 角色定位：U 不进 prompt（Goodhart 风险同 S_α'），做**机器侧终极验收指标**；S_α' 降为过程监控。两者分工：S_α' 看树长得好不好（快、便宜），U 看答案对不对（慢、贵，跑完才算）。

**缺口 [待设计]**：
- G9：gold 维度集 G 的构建——每类 benchmark 需要人工标注一次，这是 U 的主要成本。gpu 题已有雏形（r4 分析时的维度清单）。
- G10：λ 标定——需要 ≥2 组 (T, U) 数据点才能定，等 r10 出第一棵完整树 + 一次答案生成后才有数据。
- 离散外生信息豁免（#34）在 U 里天然成立：cost 只计派生节点，外生事实节点不罚。

**状态**：⚠️ 设计完成待落地。下一步依赖 r10 产出完整树 + 答案生成管线（当前状态机只产树不产答案，答案生成是 pfb S5 管线的活）。
