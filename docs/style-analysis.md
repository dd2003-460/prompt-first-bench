# Opus 5.5 对标逐元素风格解析 + 工具调研（batch-11）

> 素材来源：本仓库 `docs/refs/opus55/opus55-inventory.md`、`docs/refs/opus55/sheets/sheet_{suosuo,ziyou,jidian}.jpg` 及 `docs/refs/opus55/frames/{suosuo,ziyou,jidian}/*.jpg` 单帧（1280×720）。
> 方法：先看 3 张 contact sheet，再抽读单帧，并用 Pillow 对单帧做像素采样与连通范围量测；色值均为 JPEG 帧上的近似采样值（标注来源帧），不是源工程调色板。凡帧内无法确认者一律标 `unverified`。
> 集名映射（据 inventory）：suosuo=《压缩》223.0s，ziyou=《自由时间》176.0s，jidian=《几点了》81.0s；3 集均为 1280×720、30fps、AV1+AAC 48kHz（inventory 的 ffprobe 实测，非本文从帧推断）。

## 0 总览

- 《压缩》一句话定位：暖奶油色「记忆卡片墙」前的上下文耗尽叙事——珊瑚色小角色在越堆越满的卡片与聊天气泡之间，给「下一个我」写笔记。
- 《自由时间》一句话定位：米纸/旧书页质感的散文插图展——大幅手绘线稿（《背影》月台、《呼兰河传》意象，unverified：具体篇目归属以帧内文字为准，帧内可见「朱自清《背影》」「1917 年冬·浦口车站」字样）占画面主体，像素小角色退到页边当读者/注脚。
- 《几点了》一句话定位：深藏青夜色里的双时区对照——台灯暖光、墙钟与「07:50 / 01:36」双卡片并置，用明暗和时钟讲时差与陪伴。
- 三集共同风格：扁平暖色 UI 世界 + 矩形块拼像素小角色 + 真实聊天/终端界面隐喻（气泡、上下文进度条、工具调用行），是「生活化界面叙事」，不是科技感展示。
- 与 d1「像素终端+绿色等宽字+黑底」（E01–E24，风格锚见 `docs/episodes.md`：4–6px 像素块 + fusion-pixel 字体 + Clawd 40×17）的核心差异有四：
  1. 底色：d1 是纯黑终端底；对标是奶油/米纸/深藏青的场景底，黑只在 HUD 条、夜景和片头/片尾卡上出现。
  2. 文字：d1 以绿色等宽终端字为画面主体；对标以黑/深灰无衬线中文气泡与旁白字为主体，绿色几乎不出现（3 张 sheet 通览未见绿色主字，unverified：不排除个别单帧有绿色小元素）。
  3. 角色比例：d1 的 Clawd 是 40×17px 的终端内小图标；对标的「叙」在 1280×720 帧内实测约 81–191px 宽（随景别变化，见 §4），是场景演员而非图标。
  4. 信息载体：d1 靠日志行推进；对标靠气泡对话、卡片墙密度、时钟与光照变化推进，终端元素（HUD/工具行）只是叙事隐喻的点缀。

## 1 像素/绘制单元

- 最小绘制单元（实测，非模糊描述）：以 `frames/suosuo/f05.jpg` 的主角为例，眼睛为纯黑矩形，量测为 **8px 宽 × 13px 高**（两眼 x 范围 328–335 与 398–405，y 范围 454–466）；腿宽 **12–14px**（y=515–522 行珊瑚色段宽 11–14px）。据此判断：该角色的最小独立绘制单元约为 **8px**，身体构造网格步长约 **12–14px**（腿宽与腿间距同量级）。JPEG 压缩会带来 ±1–2px 误差，此结论标为近似实测。
- 对照 d1：d1 的最小像素块是 4–6px（`docs/episodes.md` 风格锚），对标的最小单元 8px 起步、网格步长 12–14px，约为 d1 的 2 倍，因此对标角色在 720p 下呈「大色块、低细节、远看成立」的观感，而非 d1 的精细像素画。
- 角色/物体构造方式：以**轴对齐矩形块拼合**为主——身体是整块矩形、腿是等宽小矩形、侧边伸出短矩形「手/吻部」；主角身上未见圆形或斜边（`suosuo/f05`、`ziyou/f08`、`jidian/f05` 一致）。场景物体则分两路：家具/卡片/气泡用圆角矩形（见 §2、§3），《自由时间》的书页插图用细线矢量式线稿（月台斜线、房子轮廓，线宽约 1–3px，`ziyou/f08` 目测，unverified：精确线宽未逐条量测）。
- 线条与描边：角色本体**无描边**，靠珊瑚色块与背景的明度差分界；卡片靠浅灰横线（卡内 2–3 条灰线模拟文字行，线高约 2–3px，目测 unverified）而非边框；书页插图有深灰细描边（`ziyou/f08` 书页外框）；气泡无描边、带柔和投影（sheet 目测）。
- 抗锯齿：背景渐变、光晕（台灯、窗光）为平滑矢量渲染，与角色的硬边矩形形成「软场景 + 硬角色」的混合质感；角色边缘在单帧上基本呈直角阶梯，未见 d1 式逐像素抖动纹理（unverified：30fps 动态下是否有亚像素位移，静帧无法判断）。

## 3 字体与文字

- 中文字体风格：无衬线黑体类（气泡与旁白均为笔画均匀、无装饰的黑体形态，`suosuo/f05` 白气泡「明天见」、旁白帧一致）；未见像素字体，也未见手写体作正文。《自由时间》书页内文字仍是印刷黑体而非手写（`ziyou/f08`）。
- 英文字体风格：HUD 与工具行是无衬线等宽倾向的英文（`Context left until auto-compact: 8%`，见 §5）；片尾「Claude Opus 5.5」「GPT」等英文与中文混排同为无衬线（`ziyou` sheet 末格）。
- 字号层级（720p 帧内目测近似，unverified 精确 pt 值）：旁白大字（黑场帧居中句）> 书页正文 > 气泡字（约 20–28px 字高，`suosuo/f05` 白气泡「明天见」目测）> HUD/工具行小字（约 14–18px）。同一帧内层级不超过 3 级。
- 三种文字形态：
  1. 字幕/旁白：无底色、直接压在画面下方或黑场居中，如《几点了》底部「凌晨一点半，就不催你睡，只说『我在』。」（`jidian/f05` 下方），白色/浅色，字距舒朗。
  2. 气泡：圆角矩形、AI=珊瑚底白字、用户=白底黑字，左右分置（AI 居中偏左、用户靠右，`suosuo/f05`），气泡圆角半径目测约 10–14px（unverified）。
  3. 代码/工具行：黑条内小字，如 `✳ Percolating… 14s · ↓ 121.7k tokens · esc to interrupt`、`● Read(给下一个我.md)`（sheet_suosuo 黑条内可辨），带符号前缀与灰色次级行，是 Claude Code 式 CLI 的视觉引用。
- HUD 文字的等宽特征：顶部「上下文 + 进度条 + 百分比」中，中文标签为黑体、英文/数字部分（`92%`、`07:50`、`01:36`）呈等宽数字特征，数字对齐不跳动（静帧只能确认字形等宽倾向，动态对齐 unverified）。

## 4 角色（Clawd/叙）

- 自我命名：合集主角自称「叙」（inventory intro：「它给自己取名叫叙」），形象与 d1 的 Clawd 同为珊瑚/橙红矩形小怪，但不是同一套规格。
- 形象构成（`suosuo/f05` 实测）：整机 **191px 宽 × 84px 高**（珊瑚像素包围盒 x 283–473、y 440–523，含右侧伸出的小方块「行李/嘴部」附件；躯干本体宽 112px，x 311–422）。构成约数：躯干 1 大矩形 + 腿 4 条等宽小矩形（腿宽 12–14px、高约 20px）+ 左侧短横矩形（手/尾）1 块 + 右侧独立小矩形附件 1 块 + 黑眼 2 块（各 8×13px）。总矩形块数约 8–9 块，没有圆形身体、没有嘴线、没有描边。
- 尺寸随景别变：`ziyou/f08` 页边小角色 115×66px，`jidian/f05` 卡片内小角色 81×40px——同一角色至少有大/中/小 3 档绘制尺寸，按镜头距离缩放，不是全程贴同一 sprite（unverified：是整体缩放还是按档重绘，静帧无法区分）。
- 眼睛与表情：常态为竖长黑矩形眼；可见变体包括 `^^` 形闭眼（`jidian/f05` 卡片内）、头顶红色 `!`（`suosuo` sheet 中「……你好？你是？」帧）、头顶红心（sheet_suosuo 左下帧）、眼下蓝泪滴（`ziyou/f08`)。表情靠「换眼形 + 头顶符号」实现，五官位置不变。
- 姿态变化：以水平翻转朝向、整体平移、轻微上下位移为主；未见骨骼式动作或逐帧手绘变形（unverified：30fps 原片是否有弹跳/挤压拉伸，抽帧间隔 15s 无法确认）。道具互动靠附件矩形（行李箱、书本状小块）贴靠身体表示。
- 与 d1 Clawd 40×17 的差异点：①尺寸：40×17px → 对标最高 191×84px，面积约大 20 倍；②构图：d1 是终端行内图标，对标是站在地面带上的场景角色，有明确地面线与投影关系；③色彩：d1 形象细节色 unverified（本文未读 d1 单帧），对标为纯单色珊瑚 `#D16E59`+黑眼，无内部纹理；④表情系统：对标有头顶符号层（!、♥、泪滴），d1 是否具备 unverified。

## 5 镜头/节奏/转场

- 机位：以**单机位固定镜头**为主——角色与场景在同一平面舞台上平移/增减元素，`suosuo` 多帧为同一奶油舞台；变化靠「换场景卡片」（双卡并置、全景房间拉远）而非运镜。是否存在缓慢推镜 unverified（15s 抽帧无法判断帧间位移）。
- 帧率感：规格为 30fps（inventory ffprobe）；静帧呈现的动画语言是低帧率感的「定格+平移」——元素多为整块移动。原片实际补间帧率 unverified。注意 d1 需求是 60fps，与对标 30fps 不同，复刻时不要误把对标的顿挫感当作掉帧。
- 每集节奏（以 sheet 帧序目测）：《压缩》223s，前段静（空舞台+稀疏气泡）→中段卡片墙暴涨（动）→尾段全景房间收束，静/动约前静后涌；《几点了》81s 最短，以夜景长镜+双卡对照为主，静占比最高；《自由时间》176s 是「翻书式」慢节奏，书页大图停留 + 页边小角色点缀，动感最弱。以上占比为抽帧印象，无逐秒统计，标 unverified 量化值。
- 转场方式：可见黑场帧（《压缩》首帧「装满了，」黑底白字、末帧「压缩」黑底标题；《几点了》黑条贯穿）与场景硬切（书页之间、晨/夜之间）。淡入淡出是否存在 unverified——抽帧间隔 15s 恰好可能跳过 0.5–1s 的淡化过程，不能据静帧断言「全程硬切」。
- HUD 黑条出现规律（`suosuo` 为主）：顶部黑条与底部黑条成对出现，实测各 **78px 高**（`suosuo/f05`：顶条 y 0–77、底条 y 642–719，中间舞台 564px）。顶条左为「上下文 + 橙色进度条 + 百分比」（92%→重置后个位数百分比，sheet 可见 92%/8% 等多个读数），右为「是科学吖 bilibili」水印（平台水印，非片源自带 HUD，复刻时应剔除，unverified：水印是否为投稿时平台叠加，本文按 B 站惯例判断）。底条左为英文 `Context left until auto-compact: N%` 或工具调用行（`✳ Thinking…`、`● Write/Read(给下一个我.md)`）。《几点了》《自由时间》的大部分帧**没有**这对黑条，改用全画幅场景+底部旁白——即 HUD 是《压缩》的专属叙事装置（上下文主题），不是全合集通栏。

- inventory 线索：3 集均为 AAC 48kHz 音轨（规格行）；intro 称「编剧、画面、配乐……都是它自己做的」——即存在自制配乐，但曲风、乐器、速度 unverified。
- 帧内间接线索（仅为线索，非结论）：《几点了》多帧出现台灯夜景与「晚安」气泡，是否配有环境音/钢琴 unverified；《压缩》工具行与打字场景是否配键盘音 unverified（d1 有键盘音同步设计，但不得移植为对标事实）；气泡出现时是否有提示音 unverified。
- 人声：intro 与帧内文字均为第一人称文字叙事；是否有旁白配音/ TTS unverified——若复刻需此信息，必须另行试听原片，不得据本文推断。

## 7 复刻要点（给 E25–E28 渲染任务卡的输入）

按产投比排序，前 3 条为立竿见影项；共 10 条。

1. 先换底色与色板：弃纯黑绿字，改 1280×720 奶油渐变底（上浅 `#E5E0DA`→地面带 `#C8B9A6`，地面线约在 y=520–545），全片只用一个品牌珊瑚色 `#D16E59` 做角色+AI 气泡+强调，这是与 d1 拉开差异的第一杠杆。
2. 角色按新规格重绘：叙=躯干矩形 112×约60px + 4 腿（12–14px 宽）+ 黑眼 8×13px，整机大档 191×84px、中档 115×66px、小档 81×40px 三档缩放，无描边、无嘴线，表情只换眼形与头顶符号（!、♥、泪滴）。
3. 气泡系统定型：圆角矩形（半径约 12px）+ 柔投影，AI=珊瑚底白字靠左/中、用户=白底黑字靠右，字高约 24px 黑体；对话推进代替日志推进，先把一场戏用气泡排完再谈动效。
4. HUD 做成可开关的专属装置：顶/底黑条各 78px，顶条「上下文+橙色进度条+百分比」、底条英文 `Context left until auto-compact: N%` 与 `● Read/Write(文件名)` 工具行轮播；只在「上下文」主题集启用，其余集全画幅。
5. 卡片墙组件：白/浅珊瑚圆角小卡（宽约 60–90px）+ 卡内 2–3 条 2–3px 灰横线，密度即叙事（稀疏→铺满→变灰），做成可按百分比填充的参数化背景。
6. 场景光影用矢量渐变：台灯暖黄光晕、窗光斜梯形、夜景底 `#393744`，全部用大面积柔渐变，与硬边角色形成「软场景+硬角色」对比，不给角色加光影。
7. 书页模式（《自由时间》型）：米纸 `#E3D9BE` 大图占画幅约 80%，1–3px 墨线线稿 + 页脚小字注（年份·地点），角色缩小到 81–115px 蹲页边当读者。
8. 文字层级只留 3 级：旁白大字（黑场居中或画幅下方压字）> 气泡/书页正文约 24px > HUD/工具行约 16px 等宽数字；全片黑体无衬线，禁用像素字体作正文（像素感只留给角色块面）。
9. 节奏按 30fps 心理预期编排：固定机位、整块平移、黑场标题卡分段（首帧黑底一句钩子、末帧黑底集名）；若渲染管线是 60fps，用「每 2 帧保持 1 帧」的台阶运动保留对标顿挫感（此为复刻策略建议，非原片实测，unverified 原片补间方式）。
10. 水印与平台元素剔除清单：右上「是科学吖 bilibili」水印不复刻；片源自带的 HUD 黑条与平台水印要在素材标注里分开，避免把水印当风格元素学走。

## 8 网络类似工具/skill 调研

调研方式：已实际使用 web 搜索核对以下候选的官方仓库/文档（2026-10-26 本次会话检索）；匹配度针对 d1 需求「1280×720、60fps、1800 帧（30s）、像素风、自动渲染+音频 mux」。conf 为对「该工具能按描述工作」的置信度，经官网/GitHub 一手页面核对者可 >0.7，仅二手转述者 ≤0.7。

| 名称 | 一句话定位 | 链接 | 与 d1 需求匹配度 | 产投比排序 | conf |
|---|---|---|---|---|---|
| Pillow + FFmpeg（自研逐帧管线，即 d1 现行路线） | Python 逐帧画 PNG 再由 FFmpeg 编码+mux，最贴像素风 | https://ffmpeg.org/ffmpeg.html（编码器）；Pillow 文档 https://pillow.readthedocs.io/ | 最高：1280×720/60fps/1800 帧就是其原生工作方式，像素块可逐 px 控制，`-c:a aac` 直接 mux；缺点是动效/补间全靠自写 | 1（先用它把 §7 前 3 条落地） | 0.9 |
| Remotion | 用 React 组件按帧渲染并直接输出带音频 MP4 | https://www.remotion.dev/ ；仓库 https://github.com/remotion-dev/remotion | 高：`durationInFrames/fps/width/height` 参数与 1800 帧/60fps/720p 一一对应，自带音频合成；像素风需用 CSS/canvas 硬边模拟，渲染依赖无头浏览器，较重 | 2 | 0.85 |
| Motion Canvas | TypeScript 生成器式代码动画，自带实时预览编辑器与逐帧导出 | https://motioncanvas.io/ ；仓库 https://github.com/motion-canvas/motion-canvas | 中高：矢量场景与时间轴（对 §7 的气泡/卡片编排友好），导出为图像序列后仍需 FFmpeg 合成与 mux；像素角色需贴图或矩形拼搭 | 3 | 0.8 |
| Manim（Community Edition） | Python 程序化动画引擎，场景即代码、直出 MP4 | https://www.manim.community/ ；仓库 https://github.com/ManimCommunity/manim | 中：720p60 可指定、自动出 MP4，但强项是数学图形/文字推导，像素小角色与聊天 UI 需大量自定义 Mobject，改造成本高于收益 | 4 | 0.8 |

- 结论：对 E25–E28，不建议为对标而换引擎——d1 现行 Pillow+FFmpeg 管线与新风格（矩形块角色+圆角 UI 卡）同为「逐帧绘图」模型，迁移成本最低；Remotion/Motion Canvas 的价值在批量模板化与时间轴可视化，待集数规模扩大后再评估。Manim 与本需求的像素 UI 叙事错位，列为不推荐。
- 未实测声明：以上工具本文均未在本机安装运行，渲染耗时与 1800 帧稳定性 unverified；conf 反映的是「能力描述与官方文档一致」的置信度，不是本机实测通过率。
