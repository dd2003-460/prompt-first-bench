# Opus 5.5 合集《每次醒来》逐元素风格解析（batch-11 对标）

> 对标对象：【Opus 5.5】一个 AI 给自己拍的短片（UP=是科学吖，BV1hHHC6YEdw / BV1urJU6MEGg / BV1xUpZ6NErC，1280×720 30fps av1+aac48k）。
> 对照物：本仓库 d1-video-recreation E01–E24 的「像素终端 + 绿色等宽字 + 黑底」风格（实现见 `src/pixel_arena_v2.js`：640×360 逻辑坐标 ×2 → 1280×720 @60fps/1800 帧，fusion-pixel 10px 点阵字，Clawd 40×17 + 腿 4×6）。
> 取证方式：只读仓库内素材（`docs/refs/opus55/`），不下载外网视频。所有 hex 与 px 均为我用 Pillow 对 JPEG 帧直接采样/量测所得（采样点写在括号里，格式 `帧:坐标`）。JPEG 有压缩与抗锯齿，数值取±2 容差；量不出来的（声音、帧间运动、时间轴）一律标 **unverified**。
>
> 实际看过的帧：`suosuo` f01–f15（全 15 帧）、`ziyou` f01–f12（全 12 帧）、`jidian` f01–f06（全 6 帧）+ 3 张 contact sheet + `covers/_season-cover.jpg`。抽帧间隔 ≈15s（223s/15、176s/12、81s/6），所以「帧内」结论可靠、「帧与帧之间」的结论多为推断。
>
> 置信度约定：`实测` = 像素级量测；`推断` = 从 1–2 帧推断，可能被中间帧推翻；`unverified` = 帧内无法证实。

**与 d1「像素终端 + 绿字 + 黑底」的核心差异（4 条，都是结构性的）**

1. **没有像素栅格**。d1 是 640×360 逻辑画布 ×2 放大，1 个「像素」= 2×2 物理像素，所有边都是 2px 台阶；本片直接在 1280×720 上画矢量矩形，边缘只有 1px 抗锯齿（`suosuo f02:318–320, y500` 的过渡只有 2–3px，且不成阶梯）。
2. **底色从黑变暖奶油**。d1 是 `#0A0E14/#14161C` 终端窗 + 扫描线；本片 ep1 是 `#F2E3D0` 中心 → `#C6B9A5` 边缘的径向渐变 + 四角压暗，ep3 是 `#E3D9BE` 旧纸，ep2 是夜蓝 `#2E3144`。**没有扫描线、没有 CRT 边框**。
3. **文字系统从「点阵等宽」变成「多字体混排」**。d1 全片 fusion-pixel 10px 点阵 + 绿 `#7EE787`；本片同一集里同时出现：无衬线黑体（气泡 25px）、等宽拉丁（终端行 28px）、手写行书（便签 44px）、细衬线（ep2 字幕 30px）、超大字片名（86px）。
4. **叙事界面换了隐喻**。d1 用「终端窗口 + 底部字幕条」；本片用「聊天气泡 + 记忆卡片墙 + 顶部上下文进度条 + 便签纸」。角色也从绿色 `#7B9E6B` 变成珊瑚色 `#D16E59`，并多了两条手臂。

> 一句话给 Lead：**这不是「更高分辨率的 d1」，而是另一个物种**——扁平暖色 UI 拟物 + 少量像素化装饰（爱心、便签上的手绘格子角色）。E25–E28 若照搬 d1 渲染器，只能复用「时间轴/音频/编码」外壳，画面层几乎要重写。

## 1 像素/绘制单元

### 1.1 最小绘制单元 = 1px，不存在像素网格

| 证据 | 量测 | 结论 |
|---|---|---|
| 角色躯干左上角 | `suosuo f02:315–330 × 437–450`，行 440 起满宽、四角 90° 直角，边缘仅 1px 过渡 | 矢量直角，**无圆角、无 2×2 台阶** |
| 角色眼睛 | `suosuo f02:333–350 × 449–470`，精确 8×14 px 纯色矩形，四角硬边 | 绘制单元精度 = 1px |
| d1 对照 | d1 的 1 个像素在 1280 输出上占 2×2 px | 两者「最小单元」差 2 倍以上 |

### 1.2 三类「像素化」装饰（全片唯一的像素语言）

| 装饰 | 规格 | 帧 |
|---|---|---|
| 像素爱心 | 38×33 px，硬边无抗锯齿，由 8×7 个 ≈4.8px 方块拼成（例：行 391 的两段各 10px 宽） | `suosuo f10:376–413 × 391–423` |
| 便签上的「手绘版角色」 | 纸面小格 ≈5–6px 方格网，约 20×12 格，眼为 2 格深色块 | `suosuo f09:290–470 × 240–345`（放大 4× 观察） |
| 卡片里的「文字占位」 | 2 条 4px 高圆角横线，间距 10px，左缩进 10px | `suosuo f05:407–492 × 80–116` |

### 1.3 角色/物体的构造方式

- **角色**：纯矩形拼装（躯干 1 块 + 手臂 2 块 + 腿 4 块 + 眼 2 块），无描边、无渐变，靠一层 **8–12px 模糊软阴影** 脱离背景（`suosuo f11` 角色脚下阴影最清楚）。
- **房间物件**：矩形为主（窗、书架、日历、书脊），圆形/半圆为辅（挂钟 φ98、台灯罩半圆 53×12 弧形、花盆椭圆叶）。
- **气泡/卡片**：圆角矩形（气泡 r≈16px，卡片 r≈9px，便签 r≈11px），**无描边**、纯色填充 + 下方 → 右下方 soft shadow。
- **纸页场景（ep3）**：1–2px 墨线（`#312610`），明显手抖：`ziyou f07` 的斜线由 2–3 段折线拼成，不是直线；`f01` 自行车轮辐为 1px 放射线。
- **描边总原则**：**扁平色块不加描边**（角色、卡片、气泡都没有 border）；只有「纸/画框/线稿」世界才有墨线。

### 2.4 色温与集间差异

- **ep1 暖**（色相 30–40°，明度 85–93%），**ep2 冷暖对撞**（夜蓝 225° 背景 + 2700K 感暖光 `#FAD392`/`#C86E53`），**ep3 最暖最脏**（旧纸 40°、低饱和、整体降对比）。

### 3.3 三种文字形态的排版规则

1. **字幕（独白）**：居中、无底、无描边，只靠「黑底」或「压暗背景」保证可读（`suosuo f01`、`ziyou f04`）；ep3 里改为左上角贴边放置（`ziyou f03` x108 y102）。
2. **气泡**：**右对齐堆叠**、左边缘不齐、垂直间距 ≈12px（`f03` 四条气泡 y≈312/378/... 依次向下）；白=对方/系统，珊瑚=自己；最小高度 50–62px，内边距横向 ≈28px、纵向 ≈18px。
3. **代码/HUD**：严格等宽、行首符号 `*`（珊瑚，表示忙）/`●`（绿 `#8BBB71`，φ10）/`└`（树形），两行结构（`Read(给下一个我.md)` / `└ Read 16 lines`）；**这就是 Claude Code 终端 UI 的排版**，是可复用的强风格锚点。
4. ep3 的「纸页 caption」是第四种：左下角、小字、宽字距、贴页边框内侧 10px。

## 4 角色（Clawd /「叙」）

### 4.1 形象构成（实测，`suosuo f02`，1280×720）

| 部位 | 尺寸(px) | 相对躯干偏移 | 颜色 |
|---|---|---|---|
| 躯干 | **107 × 66**（四角 90°） | — | `#D16E59` |
| 左/右手臂 | **27 × 13** | x −27 / +107；y +26 | 同色 |
| 四条腿 | **14 × 14** ×4 | x 0 / +27 / +67 / +94；y +66 | 同色 |
| 双眼 | **8 × 14** ×2 | x +18 / +85；y +12 | ≈`#1A1412` |
| 整体外框（含手臂+腿） | **161 × 81**（宽高比 1.99:1） | — | — |
| 软阴影 | 8–12px 模糊，右下沉 ≈6px | — | 黑 12% |

同一角色在别处是**等比缩放**的同一形状：`ziyou` 页脚 129×65、`jidian` 桌面 112×57、ep1 便签手绘版 ≈220×119（方格稿）。三处比例都是 2.0:1，说明角色是「一个符号位 + 缩放置换」，不是重画。

### 4.2 姿态/表情变化（帧内可证）

- **眼睛三态**：①竖矩形 8×14（中性，f02/f03/f04）；②`^  ^` 弯眼（开心，f05/f10/f12/f13/f14）；③手绘版方块眼（f09 便签）。
- **头顶符号**：`!`（f08 惊讶）、`?`（ziyou f05 迷惑）、`❤`（f10 像素爱心）、`…`（ziyou f02 省略号）、`Z`（jidian f02 睡着）。
- **手臂动作**：抱卡片/便签（f05、f11、f12）、举手（f08）、平伸（多数）。
- **体态**：始终站在同一条地平线上，脚底 y 固定；躯干整体只有 1–2px 的呼吸浮动（`suosuo f11` vs f02 位置差 ≤2px）。
- **颜色状态**：`jidian f02` 睡着时角色被去饱和成灰色 ≈`#8F8D90`，醒来恢复 `#D0745D` → **用去饱和表示「不在线/低电量」**。

### 4.3 与 d1 的 Clawd（40×17）差异

| 维度 | d1 Clawd | Opus 5.5「叙」 | 影响 |
|---|---|---|---|
| 输出尺寸 | 躯干 80×34（40×17 ×2） | 躯干 **107×66** | 宽 1.34×、高 1.94×，比例从 2.35:1 变 1.62:1（更方、更「矮胖」） |
| 手臂 | **无** | 27×13 ×2 | 是识别度最大的一条差异 |
| 腿 | 4 条 6×7 → 输出 12×14 | 4 条 14×14，内间距 26px | 腿更粗、更分开 |
| 眼睛 | 4×4 → 输出 8×8，带 1px 高光 | 8×14 竖矩形，**无高光** | 更「呆萌/无机质」 |
| 嘴 | 有（1px 平嘴/弯嘴/惊讶圆点） | **没有嘴** | 表情全靠眼睛 + 头顶符号 |
| 腹部/顶暗条 | 22×4 浅色块 + 2px 深色顶条 | 无 | 本片角色是纯单色块 |
| 配色 | 绿 `#7B9E6B`（思考时紫 `#6B5B95`） | 珊瑚 `#D16E59`（去饱和为灰） | 情绪编码从「换色」变「去饱和 + 换眼型」 |
| 绘制 | 整像素对齐，阶梯边缘 | 抗锯齿直边，浮点位移动 | 前者「像素」，后者「扁平插画」 |

## 5 镜头 / 节奏 / 转场

### 5.1 机位：**单机位 + 场景硬切**（不是多机位、没有运镜）

- 同一场景内背景逐像素重合：`suosuo f11/f12/f13/f14` 的窗（x≈545–745）、书架（x≈840–975）、日历（x≈1105–1175）位置完全一致 → **固定机位**，无推拉摇移。
- 角色在同一场景内 x/y 不变（f02 与 f03 角色 x0=292 一致；f11/f12/f13 角色 x0=293 一致）。
- 变化来自**道具增量**：f11（空房+一张便签）→ f12（+书桌、窗、多肉）→ f13（+满墙卡片、书架、日历、地毯）→ f14（+彩灯、相框、收音机）。**同一布景做「记忆越积越多」的递进**，是本片最省钱也最有效的叙诡手段。
- 机位远近只有 3 档：全身（161×81）、中景（129×65）、特写（便签字条全屏 826×479）。

### 5.2 节奏（15s 抽帧估算，±1 镜）

| 集 | 时长 | 内容帧 | 估计镜头数 | 平均镜长 | 静/动抽样 |
|---|---|---|---|---|---|
| 压缩 | 223s | 13（f02–f14） | ≥13 | ≈15–17s | 大面积静态：11/13 帧为「不动背景 + 气泡逐条出现 + 角色呼吸」；2/13 为整幅字条特写（f06/f09） |

### 5.4 HUD 黑条的出现规律（**只有 ep1 有**）

- 上黑条：**y 0–77（78px）**；下黑条：**y 642–719（78px）**；内容区因此是 78–641（**564px**）。三集里只有 `suosuo` 的 13 个场景帧出现，片头 f01 与片尾 f15 是无 HUD 的纯黑整幅。

## 6 声音

**帧内无法判断**，因此本节几乎全是 unverified：

- **音乐**：`unverified`。仓库里没有这 3 集的音频文件（`docs/refs/opus55/` 只有 jpg + inventory.md），无法测量 BPM/响度/频段。唯一线索是 inventory 抄录的简介全文：「编剧、画面（用代码一帧一帧写出来的动画）、**配乐**……都是它自己做的」——即 **BGM 系模型自制**（inventory 一手引用，conf 0.8；但「自制到什么程度」unverified）。
- **音效**：`unverified`。终端行（`* Thinking…` / `● Read(...)` / `└ Read 16 lines`）强烈暗示有 UI 音/键盘音，但**没有任何帧能证明**。
- **人声**：`unverified`。三集都是「角色说话」的叙事，但**抽帧中没有任何字幕对应的人声线索引**（对白全部在气泡里），因此无法判断是否有旁白配音。
- **编码参数**（可靠性高，来自 inventory 的 ffprobe 实测）：av1 + aac 48k。**注意**：这意味着原片是 **48kHz AAC**，d1 现有管线若用 44.1k 会在拼接对比时产生 0.09% 的时长差。

**选型结论（给 E25–E28）**

1. **继续用仓库现有的 @napi-rs/canvas + ffmpeg 管线**，只把画布从「640×360 ×2」改成「1280×720 直绘」。理由：本片的核心视觉（1px 直角矩形、8×14 眼睛、径向渐变、软阴影）在 canvas 2D 里都是一行调用，而迁移到 Remotion/Revideo 会重写全部绘制代码，收益只是排版舒服一点。**产投比 1**。
2. 如果 E25–E28 出现「大量混排文字 + 复杂布局」（本片 ep3 的纸页 caption、ep2 的衬线字幕确实有这个倾向），再评估 Remotion 作为**第二条管线**（只渲文字层，导出带 alpha 的序列帧，回灌到 canvas 管线合成）。
3. 不建议 Manim/Motion Canvas；`remotion-dev/skills` 只作为 prompt/工程结构参考。
4. 音频侧不要换工具：仓库的 JS 混音 + ffmpeg 封装已经能保证「逐样本可审计」和 A/V 同步校验，这比任何框架的内置音频都更可靠。
