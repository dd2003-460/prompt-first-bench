# Metacognition Under Compute Limits: Monitoring, Repair, and the Breadth-without-Depth Budget Curve in a 27B Research Agent

*Workshop draft v0.1 — 2026-11-22 — status: DRAFT (numbers verified from local artifacts; see §6 limitations)*

---

## Abstract

Autonomous research agents are typically evaluated end-to-end, conflating what the model does with what the harness (prompt structure, verification loops, budget control) adds. We study this separation under an explicit compute constraint — a 27B open-weight model on 4×V100, no weight updates — where "more compute = better" cannot be assumed. Our methodological contribution is a **two-axis measurement framework**: a gold-free metacognition axis (the agent's information-state monitoring, computed from node fields alone; the gap marker is *prompt-elicited* — the harness instructs the model to tag uncertain claims, §6 — so the axis measures elicited, not spontaneous, monitoring) paired with a gold-conditioned quality judge (a frozen reference tree per domain; the coverage, source-verification, and conclusion layers are mechanical and deterministic with no LLM in the scoring path, while the depth layer is an LLM rubric judge — same-model, self-biased — flagged as such, §4.3). The metacognition axis is validated across three domains (GPU serving, natural science, social science; 83 runs); the quality axis is fully worked for one domain (GPU); the *method* generalizes by construction to any domain with a frozen reference tree, while the *quality scores* are per-domain and per-reference — the reference tree is itself a designer artifact (AI-reconstructed, §6), so scores measure similarity to that reference, not to a ground-truth decomposition. We report four findings across 100+ runs (104 unique: 83 cross-domain metacognition runs — which already include the 15 K7 budget-scan runs — plus 6 idea-2 checkpoint runs and 15 rep-scan runs; the K7 runs are a subset of the 83, not an addition). Findings (1, 3, 4) are GPU-domain (finding 1's two-mechanism gap split is cross-domain, §4.1); finding (2) is cross-domain. (1) **Monitoring is present, repair is low-yield**: the agent marks information gaps with a healthy gap rate (93.5% of *search-source* degraded nodes are correctly classified as "unverifiable" rather than "contradicted"; 84% when the ambiguous class is included in the denominator), and the mark→retrieve trigger is functional in prompt-elicited form (claim-field gap markers written before retrieval predict search_query generation at 79/64/67% vs 44/23/49% baseline, §4.1), but its rework loop fixes only 1.6–2.1% of flagged nodes (node-level, era-scoped; 3.7% node-level global / 3.1% event-level global, 80-run corpus, §4.1) — the metacognitive loop behaves as a *filter* (mark, retrieve, classify) with a low-yield repair tail, not a *repair cycle*; the tree grows around its 52.5% unverified nodes (5,630/10,730 across the 33-tree GPU-domain corpus, deduped) rather than repairing them. (2) **Gap marking is functional, not noise**: the defensive-marking rate rises with question difficulty (era-matched, raw detector: nat 0.025 < soc 0.056 < gpu 0.119; after cleaning the detector's domain bias — the mathematical term *uncertainty* inflates the social-science domain, §6 — the ordering is preserved and the two comparisons against the hardest domain stay significant (soc<gpu, nat<gpu, p<0.01), while the nat<soc step becomes non-significant), consistent with calibrated uncertainty monitoring with the nat<soc step not robust to the detector's domain bias. (3) **More budget buys breadth, not a more stable answer — the robust claim is mechanical; the non-monotonic peak is not reproduced on the self-bias-free axis**: the L4 conclusion layer (mechanical, self-bias-free) never converges to the gold winner at any budget tier (0/21 strict, §4.4), and a bare-arm control (state machine off, model self-controls the loop) reproduces the breakage — 0/6 runs reach the conclusion layer — so the failure is a capability/evidence bottleneck, not a prompt artifact; a separate cross-domain observation (T-PUB-1 math benchmark) shows a deterministic repetition-degeneration loop on structurally-ambiguous multi-subquestion items that a no-LLM mechanical detector (repeated block + absent answer block) catches 5/5 (§4.4); and 719 buys ~700 nodes vs ~380 at 150; the mechanical depth layer (a 3-level step function) rises with realized node count and saturates at max_depth=5, so extra budget past ~300 nodes buys nodes, not additional depth steps (§4.3). The non-monotonic depth peak (highest at budget 150, 0.474, plateau 0.428–0.438 within one run-sd) lives only on the LLM-judged depth axis — same-model, self-biased, absent on the self-bias-free mechanical axis (see §4.3 provenance note); at n=3/budget it is suggestive, not significant. A control arm on the same 15 K7 runs pairs each LLM depth score with the mechanical tree-depth score of the same run: cor = +0.049 (t=0.18, p ≈ 0.86) — the LLM answer-depth axis is uncorrelated with the mechanical tree-depth axis (flat across mechanical levels: 0.431/0.430/0.441), so the peak is not a property shared by both axes; since the LLM axis also shows no significant budget trend (tier means 0.384/0.435/0.474/0.428/0.438 at n=3, 150-vs-plateau gap 0.9 run-sd), and a second control arm shows the LLM depth score tracks answer *length* (cor = +0.648, p<0.01; the budget signal vanishes when length is controlled, partial +0.047) — a **verbosity bias** in the same-model rubric judge, with the 150 "peak" coinciding with the two longest answers — the peak is best read as verbosity-driven rubric noise on a flat, self-biased axis rather than a demonstrated self-preference mechanism (control arms: `research/llm-vs-mech-depth-control-arm.py`, `research/verbosity-bias-control-arm.py`). The queued replication (5 added reps per tier at 100/150/300, n=3→8 per tier, 15 runs) is run *without* synthesis, so it extends the coverage and L4 axes to n=8/tier, while the metacognition axis's *invariance finding* remains scoped to the rep-scan era (n=5/5/5; one-way ANOVA across tiers F(2,12)=0.036, p ≫ 0.05 — the budget effect is below run-to-run noise resolution) and to the detector's pattern set (§6 ii — under an extended 22-pattern detector the pooled rate rises with budget, while the claim-field monitoring axis stays flat): the same compute_metacog code on the K7-era trees gives a different budget shape (gap_rate 0.134/0.047/0.075 at 100/150/300, spread 0.087 — the era difference is as large as the budget effect), so the budget-invariance claim is era-scoped, not corpus-wide; it **cannot** re-score the LLM-judged depth (which needs the synthesis answer); it therefore pins the mechanical-axis budget curve, not the LLM-depth peak. (4) **Checkpoint reuse trades coverage for metacognitive precision** (n=2–3/arm, suggestive): resuming from a verified checkpoint lowers coverage/composite (A>B on 3/3 reps) but raises gap-marking rate (3/3 reps) and source-verified retrieval quality (vsr 0.66 vs 0.46 on the two channel-healthy reps; r3 excluded — retrieval channel outage) — the checkpoint's verified gap nodes act as reusable metacognition seeds, so the "judge own information sufficiency" step accumulates across runs. Which arm to prefer depends on the downstream objective: breadth (coverage) vs precision (metacog). Under compute limits, harness metacognition helps most where the model's own monitoring is weakest — the hard questions — and spending more budget past the depth-saturation point (~300 nodes) buys nodes, not depth.

## 1. Introduction

Research-agent evaluations usually fix the model and vary the task, or fix the task and vary the model. We fix both and vary the **harness** — the prompt structure, verification loop, and node budget — because under a compute constraint the harness is the only degree of freedom left. The question: *what does structured metacognition (gap marking, retrieval, verification, rework) actually add, and when does it stop paying?*

Our setting is deliberately unglamorous: Qwen3-27B (NVFP4) on 4×Tesla V100, serving via vLLM, no weight modification. This is not a limitation to apologize for — it is the experimental condition. Conclusions are scoped to open-weight models in the 27B range; the claim is about the *shape* of the budget–quality relationship and the *location* of the metacognitive breakpoint, both of which should hold across models of similar capability.

Three contributions:
1. A **two-axis measurement framework** that separates what the harness adds from what the model does: a **gold-free metacognition axis** (the agent's information-state monitoring — gap marking, retrieval, self-classification — computed from node fields alone, no reference needed; the gap marker is prompt-elicited, §6, so the axis measures elicited rather than spontaneous monitoring; validated across three domains: GPU serving, natural science, social science, 83 runs) and a **gold-conditioned quality judge** (frozen reference tree per domain; coverage, source-verification, and conclusion layers are mechanical and deterministic with no LLM in the scoring path, while the depth layer is an LLM rubric judge — same-model, self-biased — flagged as such in §4.3; fully worked for the GPU domain; the *method* generalizes by construction to any domain with a frozen reference tree, while the *scores* carry the reference's designer bias — the reference is an AI-reconstructed decomposition, not an independent ground truth, §6). This makes the *mechanical* axes reproducible without an LLM judge, and makes the gold-dependency and the LLM-dependency of each axis explicit.
2. **Four findings** (§4–§5): monitoring/repair dissociation, difficulty-calibrated gap marking, a budget–quality curve whose *robust* (mechanical, self-bias-free) claim is the L4 zero-convergence — more budget buys breadth, not a more stable answer (0/21 at every tier, §4.4) — with a bare-arm control showing the breakage is a capability bottleneck rather than a prompt artifact, a cross-domain observation of a mechanically detectable repetition-degeneration loop (§4.4), the non-monotonic depth peak confined to the self-biased LLM rubric axis (§4.3), and a checkpoint-reuse tradeoff (coverage for metacognitive precision).
3. **An honest scope statement** (§6): the quality axis is per-domain foundational work (each domain needs its own frozen reference tree); the metacognition axis is the general component, and the two-axis *combination* is the methodological claim — the general part is the metacognition axis plus the framework, not the quality scores.

## 2. Setup

**Questions.** Three research questions of increasing difficulty: *nat* (natural-language reasoning), *soc* (sociotechnical), *gpu* (GPU performance modeling with a 37-node gold decomposition tree). Difficulty ordering is by gold-tree depth and domain specificity, not by our score.

**Pipeline.** A state-machine research loop (S5): decompose → expand nodes → mark gaps → retrieve → verify → rework (max 2 reworks per node). The nominal node budget (max_nodes) is set to 50/100/150/300/719, but it is a *soft* cap — checked once per round, before a round's expansion — so a single round can overshoot it. Realized node counts overlap across tiers (budget 50 → 103–175 nodes; 100 → 122–314; 150 → 167–392; 300 → 364–415; 719 → 665–747). The budget parameter is therefore a *lower bound with overshoot*, not a clean independent variable; the realized node count (which proxies compute cost) is the effective one, and the two are conflated at the low tiers. We report both and scope the budget-tier claims accordingly (§4.3).

**Judge (frozen, v1.0; coverage layer patched 2026-11-23).** Three layers: (L-struct) depth score — fraction of gold-tree depth reached, normalized; (L-cov) coverage — embedding match of model nodes to gold units (cosine ≥ 0.70), counted with per-unit deduplication (a gold unit matched by ≥1 node counts once). The original v1.0 "magnet" rule (a unit matched by ≥3 nodes was *excluded* entirely) was found to be a measurement artifact: it anti-correlated coverage with node count (a 401-node run scored 0.0 while a 316-node run scored 0.22, despite covering more units), so it was removed and retained only as a diagnostic field. Scores computed before the patch (noted in §4.3 and the supplementary) are flagged; the depth-only table in §4.3 is unaffected by the patch. (L-mech) formula/symbol check — diagnostic only (mechanical symbol alignment between model and gold is infeasible, not merely unsolved: the model's formulas use TCO/economics variables — `Hardware_Cost_USD`, `Quality_Score`, `Throughput_tokens_per_sec` — while the gold tree uses physical-constraint symbols — `w_bytes`, `kv_per_stream`, `bw_eff`, `n_cards` — with 0/4 idea-2 trees showing any variable overlap; the two model the same question in orthogonal quantity spaces, so a no-LLM numeric layer has no mechanical anchor. It is excluded from the composite; the numeric self-consistency that *is* mechanically checkable — KV-cache, working-point, per-card, card-VRAM — lives in the L1 physical layer instead). Composite = 0.5·depth + 0.5·coverage. Thresholds calibrated on 15 runs (cosine 0.80 collapsed coverage to 0.015; 0.70 gives 0.350 with per-run spread 0.11–0.56 — discriminative). **Mechanical vs. LLM:** the coverage and L4 (conclusion) layers are mechanical and deterministic (same input → same output, no LLM in the scoring path); the *depth* layer of the §4.3 budget table is an LLM rubric judge (same model as the generator, self-biased) — see the §4.3 provenance note. The metacognition axis is gold-free and computed from node fields alone (no LLM in its scoring either).

**Metacognition axis.** Four metrics from node fields (scoring is deterministic — no LLM in the scoring path; the node fields themselves are produced by the agent's own verification step during the run, which is exactly what this axis measures): gap_rate (defensive markers / total nodes), retrieval_rate (source=search / total), healthy_gap_rate (unverifiable / (unverifiable + contradicted) among degraded nodes), post_retrieval_accuracy (verified / (verified + contradicted)). Provenance note: the `status` field is assigned by the harness's verification call (a structured LLM prompt with an adversarial-challenge step, same 27B model), so the axis measures the self-assessment the harness's verification loop *induces* — the metacognition of the full system, not the base model's unaided self-monitoring. This is consistent with the paper's question (what does *structured* metacognition add) and is stated here so the "no LLM" claim is read precisely: no LLM in *scoring*, LLM in *data generation* (the agent itself). The v1.1 key correction: "degraded" splits into *unverifiable* (source lacks the value — a healthy "I checked, I can't verify") and *contradicted* (source conflicts — a true failure). Conflating them (v1.0) measured verification strictness, not self-awareness. **Provenance caveat (2026-11-23):** of the 2196 search-tagged nodes in the 19-tree corpus, 60.6% carry no stored URL; of those, 80% show citation traces in evidence (real retrieval, URL lost in the pipeline) and 20% show none (suspected over-tagging). retrieval_rate's numerator therefore includes ~20% suspected false search tags: the axis is an *upper bound* on true retrieval rate (lower bound ≈ 0.8× current value). This does not change the arm-split direction (§4.4) but bounds the absolute retrieval_rate claims.

**Reproducibility.** Per-run results are *not* reproducible by design (temp 0.7, top_p 0.95, anti-cache perturbation, vLLM concurrent non-determinism). The pipeline and statistical conclusions are: all metrics are deterministic functions of the saved run JSON.

## 3. Related work (positioning, condensed)

- **Metacognition in LLMs**: factual self-awareness is documented (arXiv:2505.21399); metacognitive myopia — monitoring present, control absent — is the open gap (arXiv:2408.05568). We provide a *measured* instance of this dissociation in a research pipeline, with the breakpoint located (repair loop, not monitoring).
- **RSI / self-improvement**: greedy acceptance of single-run score gains misclassifies noise as progress (45.6% of accepts are degradations; statistical gates reduce to 2.8%, arXiv:2611.10787). Our budget scan is a controlled instance: more budget does not monotonically improve the score, so any self-improvement loop on this harness must use statistical gates.
- **Budget/effort scaling in reasoning**: compute-optimal scaling (Kaplan, arXiv:2001.08361; Chinchilla, arXiv:2203.15556) fixes the task and varies scale; we fix the task *and* the model and vary the harness budget — the regime where scaling-law promises do not apply (no loss to optimize, metacognition is not a parametric capability).
- **Self-preference bias in LLM judges**: LLMs systematically favor their own generations when acting as evaluators — established since arXiv:2404.13076 (Panickssery et al., 2024), quantified at scale on 20 models with an automated, human-gold-free framework (arXiv:2604.22891), and shown to persist even on fully objective rubric-based verdicts (arXiv:2604.06996), with self-recognition itself failing at near-chance (arXiv:2510.03399). Our depth axis is an instance of this bias (same model judges its own synthesis, §4.3 provenance); the coverage and conclusion layers are constructed to be *immune* (mechanical, no LLM in the scoring path), which is the paper's structural answer to a bias the literature documents but does not eliminate by construction.
- **Deep-research benchmarks** (DREAM, arXiv:2602.18940; DR-Bench, arXiv:2510.02190; BrowseComp, arXiv:2504.12516): assume tool access and measure end-to-end success; we isolate the harness under a no-weight-update constraint with a mechanical judge.

## 4. Findings

### 4.1 Monitoring is present; repair is low-yield

Across 83 runs: healthy_gap_rate mean 0.938 (range 0.667–1.0) — when the agent cannot verify a claim *after a search*, 93.5% of the time (unverifiable ÷ (unverifiable + contradicted); 84% if the ambiguous class is included in the denominator) the correct diagnosis is "unverifiable" (the source genuinely lacks the value), not "contradicted". The agent *knows the difference between "I don't know" and "I'm wrong"*.

But the rework loop — the control mechanism — fixes only **1.6–2.1%** of reworked nodes (36/2298 budget-scan, 61/2919 era-matched). Event-level dry-run over the 80-run corpus (rework_events.reason, pre-rework evidence, 10,702 attempts; `research/repair-closure-dryrun.py`): no_source 4.0% (116/2874), value_mismatch 2.4% (22/932), other 2.8% (193/6894), global 3.1% (331/10702); node-level (rework_count>0, final status) 3.7% (331/8870). The no_source fix rate is *higher* than value_mismatch — the initial "rework mis-targeted at no_source" hypothesis is rejected. Bottleneck: 27b directed-fix capability (judging which side of a contradiction is credible and producing a corrected claim), not trigger targeting.

**Claim**: the metacognitive breakpoint in a 27B research agent is the repair loop, not monitoring. This refines the myopia framing of 2408.05568: monitoring is healthier than reported; the missing piece is *fix capability* — the 27b model cannot reliably judge which side of a contradiction is credible and produce a corrected claim (value_mismatch fix rate 2.4%, the lowest of any failure mode), so the loop is mark→retrieve→classify with a low-yield repair tail (3.1% global event-level fix rate), not a repair cycle.

**Two distinct gap mechanisms** (discovered 2026-11-23, cross-domain, cleaned detector §6): the gap-marked nodes are not one population. Splitting them by the node's `source` field (model-assigned: `search` = the node was retrieved, `knowledge` = the node was produced from the model's own prior without retrieval) gives two mechanistically distinct subgroups:

| domain | gap nodes | search-source | knowledge-source | knowledge share |
|---|---|---|---|---|
| GPU | 331 | 235 | 89 | 27% |
| nat | 89 | 41 | 45 | 51% |
| soc | 299 | 162 | 135 | 45% |

The **search-source** gaps are post-retrieval critique: the model retrieved, got an insufficient source, then marked the gap (evidence text like "[质询]…reference source only gave an overview") — the (b)→(a) direction. The **knowledge-source** gaps are the other direction: the model marked a gap on a node it produced from its own prior — it knows it does not know, but only partially triggers a retrieval (47–59% carry a search_query vs 18–40% for non-gap knowledge nodes, the within-source (a)→(b) effect, supplementary 43). This subgroup is 27–51% of all gap nodes and is present in all three domains (not a single-domain artifact). Its nodes sit at L2–L4 (mid-depth, not the structural L1 top), and ~1/3 (36–40%) carry a non-zero rework count — yet finding (1) shows the rework loop fixes only 1.6–2.1% of reworked nodes (node-level, era-scoped; 3.7% node-level global, §4.1), so most are not repaired.

The net reading for the AGI question, corrected by the claim/evidence field separation (2026-11-23, supplementary 40): **the (a)→(b) trigger chain exists, in prompt-elicited form**. Gap markers written in the *claim* field at decomposition time — i.e. *before* retrieval — predict retrieval: claim-gap nodes generate a search_query at 79% (GPU) / 64% (NAT) / 67% (SOC) vs 44%/23%/49% for non-gap nodes (z = +12.47/+9.40/+7.23, all p<0.001; search_query is model-generated at decomposition, prompts.py:337, so this is a model judgment — source=search — not a mechanical rule). The model's "I do not know this" is functionally wired to "go retrieve it". Stratifying by source to remove the source-mix confound (gap nodes are 68% search-source vs 31% baseline, and search-source nodes carry queries at 83–92% regardless of gaps), the clean within-source (a)→(b) effect is +12 to +30 pp: knowledge-source gap nodes trigger retrieval at 47–59% vs 18–40% without gaps; search-source gap nodes at 92–94% vs 59–83%. The trigger is thus a *gradient*, not a binary: given-source gaps essentially never retrieve (0% for GPU/SOC; NAT 33% but n=6, small-sample noise), knowledge-source gaps partially retrieve (the model upgrades "prior knowledge" to "external check" for ~half), search-source gaps almost always retrieve. This refines the "monitoring outruns control" reading: the knowledge-source residual is not "marked but never retrieved" in full — 41–53% of it is never retrieved, the rest is. And the sharpest prompt-elicitation evidence yet (supplementary 45): *within* knowledge-source gap nodes, the prompt-injected `[待核验]` tag itself is the trigger — tagged gaps retrieve at 66%/60% (GPU/NAT) vs 14%/0% untagged (z = +3.63/+3.52; pooled 59% vs 44%, z = +2.96), while the other gap features (depth, claim length, numeric content) barely differ between triggered and untriggered; the tag effect is domain-specific (SOC ns, consistent with the 42% technical-term dilution of `[待核验]` there, §6). What is *not* implemented: (i) the spontaneous form — without the prompt's `[待核验]` scaffolding (supplementary 37), self-initiated gap markers trigger retrieval at baseline rates (6–49%); (ii) the repair closure — finding (1) stands: the rework loop fixes only 1.6–2.1% of flagged nodes (node-level, era-scoped; 3.7% node-level global, §4.1), so the loop is mark→retrieve→classify without repair. The knowledge-source subgroup (27–51% of gap nodes, §4.1) is the residual where (a) fires without (b) — the monitoring that outruns the trigger. *(Caveat: `source` and the gap markers are model-assigned (self-reporting), so this split carries the same provenance as the rest of the metacognition axis (§3); the three-domain consistency bounds the single-domain reading.)*

### 4.3 Budget–quality is flat-to-weakly-non-monotonic

Depth score by nominal budget tier (n=3/tier, bootstrap 95% CI; realized node counts in §2):

| budget | mean depth | CI95 |
|---|---|---|
| 50 | 0.3842 | [0.3597, 0.4126] |
| 100 | 0.4352 | [0.4276, 0.4392] |
| **150** | **0.4743** | [0.4300, 0.5184] |
| 300 | 0.4275 | [0.3516, 0.4811] |
| 719 | 0.4376 | [0.4042, 0.4782] |

**Provenance of this table (checked 2026-11-23, source ①):** the depth values above are *not* produced by the mechanical judge_v1 depth layer described in §3. They come from `judge_v2_depth.score_run(qid, answer)` (s5_state_machine.py:1595–1597), which calls the LLM (ablation_harness `call_llm` → 127.0.0.1:8787 / qwen3.8-27b, **the same model that generated the answer**) to score the synthesis answer against a depth rubric. Two consequences. (i) The §3 claim "three mechanical layers, no LLM" applies to the coverage and L4 layers; the *depth* axis of this table is an LLM rubric judge with same-model (self) bias — the §6 "self-judge bias" note refers to this axis. (ii) The mechanical judge_v1 depth layer (`min(max_depth/5, 1.0)`) is a 3-level step function (30 trees: 12 at 0.6, 16 at 0.8, 2 at 1.0). At the original K7 n=3/tier it carried no *nominal-tier* discrimination (50/100/150 tiers all averaged 0.667 — a small-sample artifact of the soft-cap overlap, §4.3 caveat); the rep-scan replication (n=8/tier at 100/150/300, `rep_scan_analyze.py`) resolves this: tier means are 0.625/0.725/0.800 at 100/150/300 (719 = 0.933, n=3) — a monotone rise with realized node count (depth~n_nodes r=+0.944, n=30), with the 300 tier saturated at 0.8 (sd=0, 8/8 runs) and the 1.0 step reached only at 665–747 nodes. The gradient is era-consistent (K7 and rep-scan runs each show budget→depth rise internally), so it is not a pooling artifact; the robust reading is that mechanical depth tracks *realized compute* and saturates at max_depth=5 (~n=665), so extra budget past ~300 nodes buys nodes, not additional depth steps. Its attribution to self-preference bias (the judge scoring its own synthesis) is *consistent* with the literature (arXiv:2404.13076; 2604.22891; 2604.06996). A control arm now exists on the same 15 K7 runs: pairing each LLM answer-depth score with the mechanical tree-depth score of the *same run* gives cor = +0.049 (t=0.18, p ≈ 0.86). Note the two axes score *different objects* — the LLM scores the prose synthesis answer, the mechanical layer scores the tree structure — so this correlation tests whether answer-depth tracks tree-depth, and it does not (flat across mechanical levels: 0.431/0.430/0.441). The peak is therefore not a property shared by both axes; combined with the LLM axis showing no significant budget trend at n=3 (150-vs-plateau gap 0.9 run-sd), the 150 "peak" is best read as rubric noise on a flat, self-biased axis rather than a demonstrated self-preference mechanism (control arm: `research/llm-vs-mech-depth-control-arm.py`). **A second control arm now identifies the mechanism** (2026-11-23): the 15 K7 synthesis answers were recoverable from the archived run trees (each budget dir's `runs-s5-sm-gpu-synth.json`), so the previously-unrun verbosity check is now computable. Pairing each LLM depth score with its answer's character length gives cor = +0.648 (t=+3.07, df=13, p<0.01) — the LLM depth score tracks answer *length*; answer length is not budget-driven (cor(length, budget)=+0.153, ns); the LLM↔length correlation survives controlling for budget (partial +0.641) while the LLM↔budget correlation vanishes when length is controlled (partial +0.047 vs raw +0.135). The 150-tier "peak" (0.474/0.518) coincides with the two longest answers (24770/24197 chars) — a **verbosity bias** in the same-model LLM rubric judge, not a budget effect and not a demonstrated self-preference mechanism. The robustness of this correlation is not an outlier artifact: Spearman ρ = +0.681 (p=0.005, rank-based), and dropping either the two longest or the two shortest answers leaves r ≈ +0.64–0.67 (both still significant); the within-tier LLM↔length correlation is positive in 4 of 5 budget tiers. The robust claim is unchanged: the peak is absent on the self-bias-free mechanical axis (control arm: `research/verbosity-bias-control-arm.py`). The same-model-judging-another-model arm (the design that would isolate self-preference per se) remains unrun; the robust claim is the negative one: the peak is not reproduced on the self-bias-free mechanical axis, so it is not a robust structural finding. The mechanical-axis budget findings that do hold are the coverage rise-to-plateau (0.259/0.264/0.278/0.358/0.352 at 50/100/150/300/719, §4.3 — rises to 300 then plateaus; 719 is *not* higher than 300, so "monotone rise" is not supported at n=8; size-confounded, cor(cov, n_nodes)=+0.563), the vsr budget trend (§4.4), the L4 zero-convergence (0/21), and the metacognition axis's budget-invariance, stated on the **gap_rate component** (defensive-marking rate / total nodes — retrieval-independent by construction): 0.099/0.100/0.107 across 100/150/300 on the 15 rep-scan runs (n=5/5/5). The between-tier mean spread (0.008) is **6.5× smaller than the pooled within-group run-to-run sd (0.054)**; a one-way ANOVA across the three tiers gives F(2,12)=0.036 (p ≫ 0.05; stored computation: `research/gap-rate-anova-rep-scan.py`). Recomputed with the cleaned detector (raw minus the bare "uncertain" term, §6): F(2,12)=0.003 — *closer to zero*, so the detector's domain bias does not weaken the invariance claim, it strengthens it. **Detector-scoped caveat (2026-11-23, §6 ii):** the pooled gap_rate (claim + evidence + corrected_claim) invariance holds under the 8-pattern and 7-pattern-cleaned detectors but *not* under a 22-pattern detector that adds verification-stage phrasings ("cannot verify / lacks direct source support") the 8-pattern set misses — under that detector the pooled rate rises with budget (0.39/0.41/0.44 at 100/150/300, F=1.02), driven by the evidence field (verification-stage text); the claim-field (monitoring-axis) rate stays flat under both detectors (F=0.033). The invariance claim is therefore detector-scoped on the pooled axis and detector-robust on the monitoring axis. **Provenance caveat (2026-11-23, supplementary 41–42):** the 15 rep-scan runs were executed *before* the per-node hard clamp on `--max-nodes` landed (commit 47a8543cd), so the budget axis is a soft cap — realized node counts are 103–166 (nominal 100), 178–360 (nominal 150), 271–462 (nominal 300), and the 150/300 tiers overlap. The tier-grouped ANOVA therefore tests *nominal* budget; a zero-cost robustness check regresses gap_rate on *realized* node count (continuous) instead: cor = −0.034 (t=−0.12, df=13, ns; low-half n≈157 gap=0.1033 vs high-half n≈344 gap=0.1014) — the invariance holds against the realized compute, not just the nominal grouping, so the claim is not an artifact of the dirty axis. A hard-clamp re-run (K7, 47a8543cd) would clean the nominal axis but is no longer a prerequisite for the invariance claim. The budget-invariance claim is properly read as "the budget effect on gap_rate is below the resolution of run-to-run noise," not "gap_rate is pinned to 0.100±0.008" — individual runs vary 0.028–0.184 within a tier, and the invariance is a statement about tier means, not about any single run. The full metacog total is flat-to-mildly-declining after a scoring correction (0.246/0.247/0.232, spread 0.014; the 300-tier dip is driven by r8, a channel-healthy run — 32 whitelist lines — whose gap_rate of 0.028 is an outlier low vs its tier's 0.103–0.175: the model tagged 109 search nodes but only 10 defensive markers, i.e. a genuinely overconfident run, not a channel artifact; the r7 record had been scored against a mid-write 329-node snapshot rather than the final 311-node artifact — supplementary 17), but with a caveat: retrieval_rate (search-tagged / total) is *blind* to channel outages — the model tags search nodes even when retrieval returns nothing (r7: 97 tags, 3 URLs) — so the flat total partly reflects a measurement blind spot, not successful retrieval. gap_rate remains the clean, construction-independent component. Budget buys breadth, not metacognition.

Run-to-run sd (0.046) vs the 150-vs-plateau gap (0.041, plateau = mean of 100/300/719): the 150 "peak" is **0.9 run-sd above the plateau — suggestive, not significant at n=3**. Dropping the 300-r3 outlier (0.3516) moves 300 to 0.465, within 0.009 of 150. Two caveats scope this claim. First, the budget tiers are soft caps with overlapping realized node counts (§2): tiers 50/100/150 realize 103–392 nodes and overlap, so a depth "peak at 150" cannot be cleanly attributed to the budget parameter rather than to realized node count; any replication must re-analyze on realized node count as the x-axis. Second, the queued replication (5 added reps per tier at 100/150/300, n=3→8) is run without synthesis, so it settles the *mechanical-axis* budget curve (coverage, metacognition, L4) but **not** the LLM-judged depth peak (the new runs carry no synthesis answer to re-score; see provenance note above). The control arm (provenance note) shows the LLM answer-depth axis is uncorrelated with the mechanical tree-depth axis (r=+0.049, n=15) and has no significant budget trend at n=3; the verbosity control arm (same note) shows the LLM score tracks answer length (r=+0.648, p<0.01) rather than budget, so the 150 "peak" is best read as verbosity-driven rubric noise on a flat, self-biased axis. The robust, n-independent part of the finding is the *breadth-vs-depth* split, stated on realized node counts: ~700 nodes (tier 719) vs ~380 (tier 150) with at most a modest, saturating mechanical depth gain (the 3-level step rises 0.625→0.800 across 100→300 then holds; §4.3 provenance note) — the agent spreads budget across sibling branches and fills in at most one more depth step, instead of pushing down the gold tree's spine. (The breadth claim rests on realized node counts and the depth axis, both question-agnostic; the coverage reading of breadth is partially confounded by the construct mismatch in §6.) **Under compute limits, the harness's budget allocation — not the budget size — is the quality variable.**

| L2 | 855 | 364 | 328 | 163 | 42.6% | 16/447/392 |

Table total 8,767 nodes (matches the header; the earlier table omitted L5 and summed to 8,006).

Four structural observations:
1. **Verification rate is source-determined, not depth-determined** (42.6/48.1/52.7/58.2% for L2→L3→L4→L5 *appears* to rise monotonically, but this is a source-mix confound): the per-layer source composition shifts with depth (knowledge share 52% at L2 → 68% at L4), and ver% differs by source by a factor of ~20 (knowledge 74.4% / given 32.7% / search 3.2%, all layers). The prompt instructs that given/knowledge nodes are verified on logical self-consistency alone (no external source needed), so the rising knowledge share mechanically raises the aggregate rate. Standardizing each layer to the L2 source composition, ver% is **flat** (42.6/41.0/41.9/42.3%) — the apparent depth rise disappears. Within-source: knowledge ver% is flat-to-rising (71.1→77.7%), while **search-node ver% declines with depth (9.4/4.6/0.9/0.0% for L2→L5)** — deeper retrieved claims verify *less* often, the real depth effect runs opposite to the aggregate. So depth is not a verification cliff in the aggregate, but it *is* one for the retrieval channel: the deeper the tree grows, the less of its retrieved content is source-verifiable. (L4 rate conditional on the 18 trees that grow an L4 layer; L5 = the two 719-budget trees only, n=2.) What degrades with depth is *coverage* (judge §4.3) — though the coverage axis is partially confounded by the construct mismatch in §6 (model and gold not on the question surface), so the *depth* of the degradation is not yet cleanly attributed.
2. **The conclusion layer (L4) does not exist in 12/30 trees, and its absence rate is budget-dependent**: in 12/30 trees the max node depth is 3 — the tree never grows an L4 layer at all, so there is no conclusion layer to verify (the 12 "failures" are 12 trees with *zero* L4 nodes, not 12 trees with L4 nodes but zero verified). The absence rate by budget tier: 50 → 2/3, 100 → 7/8, 150 → 3/8, 300 → 0/8, 719 → 0/3. This is *not* a channel artifact: only 1 of the 12 (100-r5) is in the channel-outage FLAG list; the other 11 are channel-healthy. It is the per-layer signature of the depth~budget relation already established in §4.3 (mechanical depth ~ realized node count, r=0.98, p<0.001; budget 100 realizes the smallest trees): low budget → shallow tree → no L4. Crucially, once a tree *does* grow an L4 layer (the 18 trees with max_depth ≥ 4), every one of them has at least one verified L4 node (18/18) — so the "chain break" is a property of *depth*, not of *verification*: the loop does not fail to certify the conclusion, it fails to *reach* it. This complements obs 4's zero-convergence: obs 4 says that the synthesis recommendation (when the run carries a synthesis answer — all 15 K7 budget-scan runs do; the rep-scan runs do not) still does not converge to the gold winner (0/21); obs 2 says that at low budget the tree's *structural* conclusion layer (level-4 nodes) does not exist at all. The two failures are on different objects — the synthesis answer vs the tree's own deepest layer — but both point at the same (a)→(b)→(c) closure gap: even where a final answer exists, the tree behind it often has no conclusion layer to ground it.
3. **The loop is continuous but not cumulative**: with a 1.6–2.1% rework fix rate (node-level, era-scoped; 3.7% node-level global, §4.1), rework does not repair the 45.5% of nodes that fail verification (9,984/21,945, full 160-tree corpus, 6 duplicate archive files deduped) — they stay degraded and the tree simply grows *around* them. The metacognitive loop therefore behaves as a **filter** (mark + retrieve + classify), not a **repair cycle** (mark → fix → re-verify → improved). This is the precise sense in which continuity holds while the (a)→(b)→(c) loop fails to close.
4. **The conclusion layer does not converge across budgets** (judge layer 4, "final answer vs gold winner" — distinct from tree-depth L4 above): across all 15 budget-scan runs, **0/15** final recommendations match the gold winner (4× RTX 3090 / W4 / n=2, L0-verified); the full-text string "3090×4" never appears (0/15), while "3090" alone appears in 15/15 runs (full-text, re-verified 2026-11-23) and in the final recommendation line of 2/15 runs (both as *2×* 3090 or single 3090/4090, never the 4-card winner configuration; per the L4 winner table, manually extracted). The 15 winners scatter across A100 / M3 Max / 2×4090 / 1×4090 / 5090 / W7900. The model *knows the candidate* but never *commits to the configuration* — and more budget does not fix this: the zero-convergence holds at every budget tier. This is a stronger signal than the score non-monotonicity in §4.3: budget buys more nodes, not a more stable answer. **Cross-dataset check (idea-2 arm, n=6, same question):** the L4 conclusion layer is empty for these runs (answer = 0 chars — the idea-2 trees carry no synthesis-answer node), so strict winner-configuration commits are 0/6 and the loose "3090 in the conclusion layer" is also 0/6 (a full-text grep finds "3090" in 4/6 trees, but that is the candidate layer, not the conclusion layer, so it does not count as a loose L4 hit). The zero-convergence therefore holds on idea-2 too (0/6), and the arm split does *not* appear on L4 (the conclusion layer is empty for both arms); it appears instead on the metacognition axis (below). A further, mechanical refinement of the retrieval axis shows the same arm split: **source-anchored numeric verification** (judge layer — fetch each node's cited URL, check the claimed number appears in a 20-char window on the page; no LLM) gives resume-arm vsr 0.66 vs fresh-arm 0.46 on the two channel-healthy reps (B-r1 0.62, B-r2 0.71 vs A-r1 0.50, A-r2 0.42; n=2/arm). **Contamination note (checked 2026-11-23):** the r3 reps were run during a retrieval-channel outage — A-r3's search nodes are 90% source-empty (8 whitelist lines, all in the first minute) and B-r3's 70% (0 whitelist lines), vs 2%/36% for the healthy A-r2/B-r2. The r3 vsr values (A 0.00, B 0.82) therefore reflect the dead channel, not the arm, and are excluded from the arm-split estimate; including them would inflate the split from +0.21 to +0.41. The arm split is thus computed on r1–r2 only (n=2/arm, suggestive). **Independence caveat (checked, 2026-11-23, n=6):** vsr is *not* an independent axis — it correlates 0.89 with the metacognition axis total (0.99 at n=4 before r3) on the 6 idea-2 trees (both are computed over the same search-node population; vsr is retrieval rate re-weighted by "did the cited source actually back the number"). The arm split it shows is therefore the metacognition arm split re-expressed on a quality-weighted metric, not a third independent confirmation. What it *does* add is a budget-trend finding the metacognition axis does not cover (below), and a mechanical, source-grounded way to score retrieval quality that an embedding-based proxy cannot. Caveat: only 12–57 candidate nodes per run because 60.6% of search-tagged nodes across the 19-tree corpus carry no stored URL (pipeline provenance gap, §6), so the arm split is computed on a small, retention-biased subset. The same layer also shows a **budget trend the metacognition axis does not cover**: across the 15 budget-scan runs, vsr falls from 0.76 at budget 50 to 0.53–0.54 at 300/719 (cor(n_nodes, vsr) = −0.47, n=14, not strictly monotone — budget 100 is n=1 and 719 slightly exceeds 300; suggestive). More budget buys nodes whose cited sources verify less often — the breadth expansion leans on less verifiable sources. This joins the depth-score non-monotonicity, the coverage degradation, and the L4 zero-convergence as another dimension pointing at the same conclusion: budget buys breadth, not depth or verifiability. The trend survives the obvious confound: URL retention also falls with budget (cor(n_nodes, retention) = −0.51, n=14), but retention is nearly uncorrelated with vsr (+0.18, n=14) and the partial correlation controlling for retention remains substantially negative (−0.45, n=14) — so the decline is source quality, not a survivorship artifact of which URLs the pipeline happened to store. **Third, the within-arm metacog total appears to fall with node count — but decomposition shows this is a small-denominator artifact, not a budget effect (idea-2 arm A, 3 reps, 2026-11-23).** The metacog total reads A-r1 (n=316) 0.237 → A-r2 (n=394) 0.150 → A-r3 (n=435) 0.115 while the composite total stays flat at 0.594 across all three. Decomposing the axis (total = 0.4·gap_rate + 0.3·retrieval_rate + 0.3·post_retrieval_accuracy) shows the two full-population components are essentially flat (gap 0.063/0.066/0.069; retrieval 0.304/0.279/0.290). The entire decline is in post_retrieval_accuracy — verified/(verified+contradicted) among search nodes — whose denominator shrinks 10 → 15 → 2 (A-r3 is 0/2, a two-sample ratio). The apparent monotone drop is therefore a small-denominator artifact in one term, not a budget-driven degradation of the monitoring axis; we do not claim a within-arm metacog trend from this. (n=3/arm, declining term n≤15.) This also explains the 0.89 vsr↔metacog correlation above: both are dominated by the same handful of verified search nodes, so the correlation is a shared small-sample artifact, not an independent confirmation.

**Bare-arm control (state machine off, n=6, 2026-11-21–23)**: to test whether the (a)→(b)→(c) breakage is an artifact of the state machine's prompt scaffolding (i.e. whether a bare "recursive decomposition" instruction with full goal but no process control would avoid it), we ran the bare arm — model self-controls the loop (what to split, what to search, when to stop); the machine only provides the search tool and records the tree, no state machine, no rework, no forced closure. The 6 runs span three questions (gpu×1, nat×4, soc×1). Result: **the breakage reproduces without the state machine** — 0/6 runs reach L4 (max_depth 2–3; 5 at depth 3, 1 at depth 2), a question-independent structural metric. On the gold-commit axis (only the gpu question has a defined gold configuration, 4× RTX 3090 / W4 / n=2): the single gpu bare run recommends 1× RTX 5090 as first choice, with 3090 appearing only as a 2× budget-compression fallback — i.e. 0/1 on the gold commit, matching the SM arm's L4 zero-convergence (0/21 on the same gpu question). **The failure to commit to the configuration is not a prompt/state-machine artifact; it is a capability/evidence bottleneck that persists with or without process control.** The state machine's value is therefore not "it prevents the breakage" but "it makes the breakage measurable" (per-node status, rework events, verification evidence — the bare arm's runs carry none of these). *(Caveat: n=6 with only one gpu rep on the gold-commit axis; the depth-3 ceiling is the robust cross-question result, and it may partly reflect the bare protocol's text-based tree format, which the 27B finds harder to deepen than the SM arm's structured format.)*

**Cross-domain degeneration observation (separate dataset, T-PUB-1 math benchmark, 2026-11-23)**: a mechanically detectable failure mode — *repetition degeneration* — was found on a 7-question math/GPU-memory benchmark (same 27B, temperature=0, mt12000). On question Q04 (multi-subquestion, structurally ambiguous: "KV-pool total size vs per-token KV"), 2/5 runs enter a deterministic loop (byte-identical outputs, 390-char block repeated 45×, "the user's question is probably…" ×90, no final answer block ever emitted); the other 3 runs commit the answer before degenerating. A mechanical detector (repeated-block + no-answer-block) classifies all 5 paths correctly (5/5, threshold-stable at min_repeat_count 2–5). Across the full 35-run corpus the degeneration is Q04-specific (2/35; zero on the other six questions, including a 19k-char non-degenerate run), so it is *not* a systemic long-output failure but is triggered by multi-subquestion + structural ambiguity. Provenance: `D1-generalization/scripts/degeneration_detector.py` + `tasks/T-PUB-1/full7-mt12000.json`. This is a concrete, mechanically testable target for the verification layer the paper argues is necessary — the degeneration is detectable without an LLM (repeated block + absent answer block), which strengthens the "mechanical judge is feasible and necessary" claim in §5.2.

**Predicted failure mode for the fix**: the event-level dry-run (§4.1) shows the rework loop is not mis-targeted — no_source rework (4.0% fix) outperforms value_mismatch rework (2.4%). The falsifiable branch point is therefore capability, not targeting: a stronger directed-fix model (or a human-in-the-loop correction step) on value_mismatch nodes should raise that mode's fix rate above the 27b ceiling; if it does not, the bottleneck is the contradiction evidence itself (insufficient to disambiguate), not the fixer.

**5. The self-report is calibrated in direction, weak in strength** (calibration check, `calibration_check.py`, 359 numeric+URL nodes across the 19-tree corpus): cross-tabulating the model's self-assigned node status against the mechanical source verification, nodes the model marked *verified* verify at 0.78 (n=9 reachable, not significant), *degraded* at 0.56 (n=191), and *pending* at 0.55 (n=20). Two clean readings: (i) the self-report points the right way — verified-marked nodes do verify more often mechanically — but the verified group is too small to be significant; (ii) 56% of *degraded*-marked nodes still have their claimed number present on the cited page, i.e. the model's downgrade is conservative relative to a text-level check. Part of this gap is granularity (the mechanical check tests the first number of the claim against the first cited URL; the model judges the whole claim, often multi-number/multi-source), so it is not all misclassification — but the direction is a real signal: the agent's "I can't verify this" is more cautious than the page-level evidence warrants. This refines §4.1's "the agent knows the difference between 'I don't know' and 'I'm wrong'": the distinction is present but asymmetric — under-claiming (degrading verifiable nodes) rather than over-claiming.

## 5. Implications

1. **For harness design**: the event-level dry-run (§4.1) rules out trigger re-targeting as the fix — no_source rework already outperforms value_mismatch rework. The actionable changes are (a) stop reworking value_mismatch nodes (2.4% fix, 932 wasted attempts) and mark them degraded directly, and (b) route directed-fix to a stronger model or human step where capability is the ceiling. Measurable prediction: value_mismatch fix rate rises above the 27b's 2.4% under the stronger fixer, with no change to no_source rework (4.0%, retained). (Planned as the next experiment; acceptance via statistical gate, not single-run — per §2 related work, greedy gates misclassify 45.6% of accepts.)
2. **For evaluation**: a mechanical, frozen judge is feasible and necessary for harness ablation — LLM judges inject family bias and non-determinism into the very variable being measured.
3. **For compute-limited research**: the robust (mechanical) finding is that more budget buys *breadth* (more nodes, wider coverage) and a *modest, saturating* depth gain — the mechanical depth layer (a 3-level step) rises with realized node count (tier means 0.625/0.725/0.800 at 100/150/300, 0.933 at 719; depth~n_nodes r=+0.944, n=30, §4.3) but saturates at max_depth=5 (~n=665), so budget past ~300 nodes buys nodes, not additional depth steps; and the L4 conclusion layer does not converge to the gold winner at any tier (0/21). This is a warning against "just give it more budget": extra budget spreads the tree sideways and fills in at most one more depth step, not down the gold spine. (The non-monotonic *peak* on the LLM-judged depth axis is a weaker, self-biased, n=3-unsignificant signal — §4.3 — and is not the basis of this implication.)
4. **For checkpoint reuse** (idea-2 arm, n=2–3/arm, suggestive): resuming from a verified checkpoint trades *coverage* (composite, A>B 3/3 reps) for *metacognitive precision* (gap marking 3/3 reps higher on the resume arm) and *source-verified retrieval quality* (vsr 0.66 vs 0.46 on the two channel-healthy reps; r3 excluded — retrieval channel outage, §4.4). The checkpoint's verified gap nodes act as reusable metacognition seeds — the (a) "judge own information sufficiency" step accumulates across runs rather than restarting. Which arm to prefer depends on the downstream objective: breadth (coverage/composite) vs precision (metacog).

## 6. Limitations (stated up front)

- **Gold-conditionality of the quality axis** (the core scope limit): the mechanical quality judge is per-domain foundational work — each domain needs its own frozen reference tree (gold), and the quality *scores* (depth/coverage) are only as general as those trees. What is general is (i) the *method* of building the judge (frozen reference + deterministic mechanical layers, no LLM) and (ii) the gold-free metacognition axis, which needs no reference at all and is validated across three domains. The full two-axis methodology generalizes only insofar as a domain can supply a frozen reference tree; where it cannot, the metacognition axis alone still applies.
- **"Mechanical" means deterministic scoring, not designer-free reference** (stated 2026-11-23): the coverage and conclusion layers are mechanical in the scoring path (same input → same output, no LLM, no self-preference), but the *reference tree they measure against is itself a designer artifact* — the GPU gold tree was reconstructed by the same research process that produced the runs (origin: ai, 2026-11-22 rebuild from the project's own L3/L4/L5 derivation docs; the original file was lost and is not in git history), and the second (dual-gold) tree is likewise AI-constructed. Consequence: the coverage score measures similarity to *this* decomposition, not to a ground-truth decomposition; the L4 zero-convergence (0/21) means the model did not reach *this* reference's conclusion, not that it reached no correct conclusion. The bias did not disappear — it moved from the scoring function into the reference. Two partial mitigations, stated for honesty: (i) the reference is *harder* than the model's natural output — mean coverage ~0.35 with per-run spread 0.11–0.56, and a model scoring its own output against its own reference would sit near 1.0, so the gold is not a self-transcription; (ii) the cross-domain near-zero-coverage result (§7: Q6 runs scored against the GPU gold yield ≤8% coverage at every budget tier, versus 6–13% in-domain, and the residual hits are generic hardware-cost units rather than domain-specific ones) shows the reference is question-specific rather than a generic "model-like" prior; (iii) a run-time leakage check passed — the task prompt contains none of the gold tree's proprietary symbols (cost variables, hardware configs, node count; 0 hits across the prompt template), so the coverage score is not inflated by the model seeing the reference during generation. What is *not* controlled: the reference and the evaluated model share the same 27B family prior, so a same-family reference could in principle inflate coverage; the observed low coverage is consistent with the reference being harder, but the clean same-family-inflation control (an independent expert-annotated gold, or a cross-family reference) is not run. The "generalizes by construction" phrasing in the abstract should be read as: the *method* generalizes (any domain with a frozen reference tree can be scored); the *quality scores* are per-domain, per-reference, and carry the reference's designer bias.
- **Single model** (27B): no capability curve. The model-capability axis (7b/27b/70b) is planned but not run; claims are scoped to "open-weight, ~27B range".
- **Self-judge bias**: the depth axis is same-family; the report notes r=0.861 with an older LLM-judge cov axis. Heterogeneous re-judging (frontier API) is blocked (no API key) — a known gap, stated, not hidden.
- **n=3/budget at 50/719, n=8/tier at 100/150/300** (rep-scan completed 2026-11-23): the mechanical-axis curve (coverage, metacognition, L4, depth step) is now settled at n=8/tier for the three middle tiers — the depth gradient (0.625/0.725/0.800) is era-consistent across K7 and rep-scan runs, and the 300 tier saturates (sd=0, 8/8 at 0.8). The non-monotonicity on the *LLM-judged* depth axis (peak at 150) remains a weaker, self-biased signal: the queued replications ran without synthesis, so they settle the mechanical axis but not the LLM-depth peak location (§4.3 provenance note). The 50 and 719 tiers stay at n=3 (K7 only) — their 95% CIs are wide (±0.29) and the 719 "peak" (0.933) is not yet a strong claim. **Power analysis of the metacognition null (2026-11-24):** the flatness claim is an ANOVA null (monitoring/gap axis F(2,12) = 0.036, recomputed from the 15 rep-scan runs; per-tier means 0.099/0.100/0.108, pooled sd 0.085). At n = 15 the power to detect a *large* budget effect (Cohen f = 0.40, i.e. budget shifting the gap rate by ~40% of the within-run sd) is only **21.5%**; for a medium effect (f = 0.25) it is **11.0%**. The null is therefore **severely underpowered**: "metacognition is flat across budget" must be read as *no change detected at 21.5% power for a large effect*, **not** as evidence of invariance. The detector-robustness check (8-pattern vs 22-pattern, monitoring axis flat under both) mitigates detector-dependence but does not substitute for power; the queued replication raises n for the three middle tiers but the 50/719 endpoints stay underpowered. Until the replication lands, the headline "budget buys breadth, not metacognition" is a **suggestion with stated power limits**, not a verified dissociation.
- **Mech layer diagnostic-only**: mechanical symbol alignment between model and gold is infeasible, not merely unsolved — model formulas use TCO/economics variables, gold uses physical-constraint symbols, 0/4 idea-2 trees share any variable (orthogonal quantity spaces). The numeric self-consistency that *is* mechanically checkable lives in the L1 physical layer instead.
- **One question family** for the gold tree (gpu); the two other domains (CDN caching, second-hand pricing) have metacognition-axis coverage only — no quality gold for those exact questions (five out-of-domain gold trees exist for *different* questions, Q6–Q10, and are the ready-made asset for the next budget scans, §7).
- **Construct mismatch between question text and gold tree** (discovered 2026-11-23): the question states "context window ≥ 32K as a capacity floor" and asks the model to *search* its own hardware candidate set, while the gold tree is anchored at a fixed 64K context and a fixed candidate set (3090/M2Ultra/L40S/A100/V100/TPU). All 20 trees inspected (15 K7 + idea2 A-r1 + B-r1) take the 32K floor; the candidate-set overlap varies by run (K7 trees keep 3090 in-candidate, 7–40 mentions; idea2 B-r1 is closest to gold, 3090×78; idea2 A-r1 is the outlier — it excludes V100 explicitly and never considers 3090). Consequence: part of the low coverage scores reflects the model legitimately solving a *different* question than the gold encodes, not merely insufficient search depth. The depth axis (structural, question-agnostic) is unaffected; the coverage axis is partially confounded. Fix direction: pin context length and candidate set in the question text before drawing coverage-based conclusions.
- **Provenance retention gap** (discovered 2026-11-23): 60.6% of search-tagged nodes across the 19-tree corpus (1330/2196) carry no stored source URL, and retention varies 0–100% across runs (pipeline inconsistency, not model behavior). Consequence: the source-anchored verification layer (§4.4 obs 4) is computable only on the URL-retained subset and is a per-run diagnostic, not a cross-run ranking; cross-run comparisons must control for retention. Fix direction: persist retrieval URLs unconditionally at retrieval time.
- **Retrieval-channel silent outage** (discovered 2026-11-23): the multi-channel retrieval hook (local/wiki/arXiv/webfetch/DDG) can fail *silently* — returning empty source lists without raising an error — so a run can complete normally while 70–90% of its search nodes carry no source. This happened during the idea-2 r3 window (A-r3 90% / B-r3 70% source-empty vs 2%/36% for the healthy r1–r2; the whitelist log lines drop from dozens to 0–8). Because the failure is silent, a run's retrieval health must be checked *post hoc* (count the whitelist log lines per run; a healthy run has dozens) before any retrieval-dependent metric (vsr, post-retrieval accuracy) is trusted. The r3 vsr values were contaminated by this and are excluded from the arm-split estimate (§4.4). Distinct from the retention gap above: retention is "URL not stored though retrieval succeeded"; this is "retrieval itself returned nothing".
- **Domain bias in the defensive-language detector** (discovered 2026-11-23): the gap marker is a regex over defensive phrases (e.g. "uncertain / cannot verify / awaiting confirmation"). In the social-science domain, 42% of its hits are the mathematical term *uncertainty* used as a technical concept (e.g. "high uncertainty", "σ_pref positively correlated"), not epistemic hedging; in the GPU domain the share is 15%. Consequences: (i) the social-science gap_rate is inflated up to ~1.7× relative to the GPU domain, so cross-domain *levels* of the pooled gap_rate are not comparable — the "validated across three domains" claim above applies to the axis's *computability*, not to its cross-domain *calibration* (the *ordering* on the monitoring axis survives the cleaning, though: claim-field rates nat 0.0162 < soc 0.0261 < gpu 0.0921 with the same significance pattern, §4.2 third correction — the pooled *levels* are inflated in soc, the *gradient* is a monitoring-axis phenomenon); (ii) the within-domain budget-invariance claim needs a field-level qualification — the paper's gap_rate pools claim + evidence + corrected_claim, and under the 8-pattern detector this pooled rate is flat (ANOVA F(2,12)=0.036), but under a 22-pattern detector (adding the verification-stage phrasings the 8-pattern set misses, e.g. "cannot verify / lacks direct source support") it rises with budget (0.39/0.41/0.44 at 100/150/300; F=1.02). Decomposing by field: the *monitoring* axis (claim field) is flat under both detectors (current 0.090/0.090/0.096; extended 0.105/0.106/0.114; ANOVA F=0.033), so the monitoring-axis invariance is detector-robust; the *verification-stage* (evidence field) text rises with budget under the extended detector, consistent with the vsr budget trend and the search-ver% depth decline. Consequence: the paper's pooled gap_rate invariance is detector-scoped (it depends on the 8-pattern set not capturing verification-stage phrasings); the detector-robust core claim is the monitoring-axis invariance. Note: with n=15 (5 per tier) the ANOVA has low power, so "flat" means "no budget effect detected," not "invariance proven"; (iii) the node-level coupling of gap-marking with retrieval sources survives the cleaning (search-source 71.0% vs 27.7% in the GPU domain; z = +16.24 / +8.13 / +11.73 across the three domains, all p < 0.001). Long-term fix: an LLM classifier separating epistemic hedging from the uncertainty concept; not run in this paper.
- **Gap marker is prompt-elicited, not spontaneous** (discovered 2026-11-23): the harness prompt explicitly instructs the model to tag qualitative-only claims with a "[待核验]" (to-verify) marker (prompts.py:78, 312). This instructed tag is the dominant component of the defensive-marking rate — 82% of gap hits in the GPU domain, 72% in natural science, 51% in social science; the remaining seven marker words (which the prompt does *not* instruct) contribute 18–49%. Consequence: gap_rate measures *prompt-elicited* uncertainty monitoring (the model decides where to apply an instructed tag), not *spontaneous* self-monitoring — a model-vs-harness conflation that the paper's two-axis framework is designed to avoid. The instruction is conditional ("only when a claim has no quantitative form"), so the judgment of *where* to tag is still the model's; this is not a pure harness artifact. None of the budget-invariance or difficulty-gradient conclusions depend on the elicited-vs-spontaneous distinction (the prompt is identical across runs, budgets, and domains), but the *interpretation* of gap_rate as "the agent knows it doesn't know" should be read as "the agent, when prompted, marks its uncertain claims" — and the cross-domain [待核验] share difference (82% vs 51%) is itself evidence that the social-science domain elicits more spontaneous (non-instructed) uncertainty language.
- **Workshop scope**: this is a measurement + diagnosis paper, not a fix paper. The repair-loop fix is designed and predicted, not yet run.
- **Executor continuity (meta)**: the agent running this study is itself continuity-bound — its actions are passively triggered (user message or background-process completion), so a goal state-machine records *where to resume* but does not *drive* resumption. Continuity here is achieved by synchronous in-session progress + background processes covering GPU waits (auto-wake on completion) + planning written to seamless-resume granularity. Self-triggered unattended action is unavailable to the executor — a property of the research *process*, stated for honesty, distinct from the evaluated 27B system's metacognitive limits.

## 7. Future work

- **Structural stop-criterion axis (L2, new diagnostic layer).** A BOUND-weighted mechanical check of whether the agent expands where the gold decomposition requires expansion and stops where its stopping criteria (information-sufficient / black-box / business-data) apply. Across 14 runs the agent systematically over-expands (50 over- vs 24 under-expansions, 2.08:1) and the axis is near-orthogonal to the depth score (r = −0.23) — the model does not know when to stop. Not yet in the composite (representative-node assignment is the main measurement-error source); a replication with pinned question text is the next step.
- **Tree-level conditional information gain for bottleneck localization.** A follow-up direction: quantify, per reasoning-tree node, the conditional information gain of expanding that node toward the final answer, and use the gain profile to localize which layer of the decomposition is the bottleneck. A collision survey (2026-11-23) found the single components mature (Roofline bottleneck analysis: arXiv:2402.16363; information-gain CoT: arXiv:2411.11984; mechanistic NPU critics: arXiv:2611.24733) but the tree-level combination unclaimed — full-text check of the closest paper (2611.24733, 131K chars) shows zero overlap with reasoning-tree or information-gain content.
- **Replication and capability axis.** The queued replication (5 added reps per tier at 100/150/300, n = 3→8) settles the mechanical-axis budget curve (coverage, metacognition, L4) but not the LLM-judged depth peak (runs without synthesis; §4.3 provenance note); a 7b/70b capability curve is planned but not run.
- **From per-domain foundation to general methodology.** The quality axis is currently one fully-worked domain (GPU, 55 unique runs: the 34 GPU trees in the 83-run cross-domain corpus plus the 6 idea2 and 15 rep-scan runs, all on the GPU question) plus metacognition-axis-only coverage of two more (CDN caching, second-hand pricing; 49 runs combined, no quality gold for those exact questions). The general-methodology claim requires showing the budget–quality curve shape and the monitoring/repair dissociation hold on 2–3 more domains with quality scores. **The cost is lower than it looks, but not zero**: five frozen reference trees already exist for out-of-domain questions (Q6 networking, Q7 storage, Q8 LLM-evaluation, Q9 VLM, Q10 RLHF; 41-node gold trees, built 2026-11-07, registered in `ablation_harness.QUESTIONS`). The metacognition axis reuses the frozen pipeline end-to-end — a Q6 budget scan is a parameter change. The quality axis needs one preparation step per domain: the mechanical judge consumes a *structured* gold (36 units with units/formulas/bounds, `gold-gpu-units.json` / `gold-gpu-formulas.json`), while the Q6–Q10 trees are markdown. **This preparation step is now implemented and validated, not merely described** (2026-11-23): the markdown→units converter (`gold_md_to_units.py`) is verified on all five out-of-domain gold trees (Q6 46, Q7 52, Q8 36, Q9 34, Q10 36 units; share weights match the gold source; the 4 `kind=None` entries in Q6/Q7 are the gold source's own "contract & risk (nuisance)" branch carrying no leaf/split marker — a gold-format convention that does not affect the coverage layer, which reads text only), and the judge is parameterized over the gold (`judge_v1.py --gold-units`), with a regression check confirming the GPU default score is unchanged (0.3972) and the cross-domain injection path returns the correct zero-coverage behavior on a non-matching run. The conversion procedure itself (units → JSON schema) is part of the method and is what generalizes; the per-domain cost that remains is *running* the budget scan on the new question (a parameter change to the frozen pipeline, queued behind the current vLLM workload) plus the L1 physical layer's `formulas.json` (sympy/reference/bound fields are domain-specific and require manual or LLM-assisted annotation — the coverage axis, which is what tests the curve shape, needs only the auto-extracted units). A capability axis (7b/27b/70b) is the second, independent generalization. **The Q6 budget scan is now complete (15/15 runs; 50/100/150/300 tiers × 3 reps, 719 × 3 reps) and the cross-domain data points refine four claims**: (i) the *quality axis* is domain-specific in a stronger sense than the metacognition axis — in-domain coverage rises with budget at the tier-mean level (Q6 runs scored against the Q6 gold: tier means 0.058 → 0.073 → 0.087 → 0.130 → 0.167 at 50/100/150/300/719, n=3/tier, monotonic non-decreasing). Per-run, the picture is noisier: within-tier rep variance is large (e.g. at budget 100 the three reps score 0.130 / 0.044 / 0.044), and the 719 tier's three reps *realized* 197 / 351 / 379 nodes and score 0.130 / 0.174 / 0.196 — so realized node count explains the within-719 spread (197→0.130 ≈ the 300-tier level; 351→0.174; 379→0.196) but is not a clean monotonic predictor across all 15 runs (a budget-100 rep at 0.130 exceeds every budget-150 rep). The 719 tier's three reps all terminate on the harness tree-depth ceiling (`max_depth=4` hit), not the node budget, so on the realized-node-count x-axis they sit at ~197–379 rather than at 719. Decomposing the in-domain judge total (0.5·tree-depth + 0.5·coverage; both components mechanical and self-bias-free — the LLM rubric depth axis of §4.3 is a separate scoring path that does not enter this composite) shows the post-300 rise is carried entirely by the coverage layer — the tree-depth component (normalized to the GPU gold's depth of 5; the Q6 gold's max depth is 3, so under its own normalization it would be saturated at every tier) saturates at 0.800 from the 150 tier onward (Δdepth = 0 across all three 719 reps) — so the continued in-domain quality gain at higher realized node counts is on the self-bias-free axis, and in this domain the budget–coverage curve is purely coverage-driven, consistent with §4.3's finding that the non-monotonic peak lives only on the self-biased LLM axis. The 719 tier exposes a *stopping-mechanism* distinction the lower tiers do not: at 50–300 the run terminates on the node budget cap (`max_nodes` hit; realized = budget on all 12 runs), whereas at 719 it terminates on the harness tree-depth ceiling (`max_depth=4` hit) before the node budget is spent — realized 197 / 351 / 379 nodes across the three reps (large rep-to-rep spread: the depth ceiling is hit after a variable number of expansions). The 719 tier therefore does not test "what happens when the model gets more budget than it wants"; it tests what the tree looks like when the *depth ceiling*, not the node budget, is the binding constraint. In-domain coverage tracks realized node count within this regime (0.130 at r3/197 → 0.174 at r1/351 → 0.196 at r2/379), so the quality gain at higher realized node counts is real but is confounded with the depth-ceiling regime — a clean "budget past saturation" test requires raising `max_depth` (a harness parameter, not a pipeline change; approved and queued as a 3-rep 719-node run with `max_depth=10`, §7 data note). (ii) *Cross-domain coverage is near-zero* (Q6 runs scored against the GPU gold: 0.009 / 0.009 / 0.019 / 0.046 at the same tiers, and 0.0 / 0.083 / 0.056 at the three 719 reps, i.e. 0–3 of 36 gold units, ≤8%) — the residual cross-domain hits are a fixed set of five *generic hardware-cost* units (purchase amortization, power draw, electricity price, failure loss, feasibility constraints; verified per-run, none of the eight cache/hit-rate units ever matches), so the coverage layer's domain specificity is *strong but not binary*: the embedding matcher cannot separate generic hardware vocabulary (shared by any hardware-domain question) from domain-specific technical concepts, and its exact zero-ness is gold-artifact-dependent (a raw-markdown gold yields exactly zero; the enriched judge gold yields ≤8%). Either way the two axes carry different cross-domain comparability, and any cross-domain quality comparison requires the per-domain gold. (iii) the *monitoring-axis* budget-invariance so far does not transfer to Q6: claim-field gap rates are 0.073 / 0.003 / 0.016 / 0.026 at 50/100/150/300 (n=3/3/3/3, suggestive; the three 719-budget reps at ~197/~351/~379 realized nodes sit at 0.000 / 0.029 / 0.005, n=3, with large rep-to-rep spread) — low level and non-flat after the 50 tier, versus the GPU domain's flat 0.105/0.106/0.114. The invariance is thus currently a GPU-domain result, which is exactly the cross-domain validation this scan was designed to test. (iv) the *repair low-yield* finding does transfer: on the frozen node-level metric (nodes with rework_count > 0 that end verified; identical code to the GPU 3.7% = 331/8870 figure, §4.1), the 15 Q6 runs give 32/621 = 5.2% — same order of magnitude, confirming the "filter with a low-yield repair tail" characterization is not a GPU-domain artifact (n=15 runs). The Q6 scan is complete (15/15); the remaining generalization evidence is a second full out-of-domain scan (e.g. Q7) plus the queued rep-independence rerun (rep-isolated source cache; §7 data-quality note). Until those land, the paper's honest position is: the metacognition axis and the two-axis framework are the general contribution; the quality scores are per-domain foundational results.

**Data note (queued experiments, 2026-11-23).** Two queued batches refine the Q6 results above; neither changes the frozen pipeline, only run parameters. (a) *Rep-independence rerun* (300/719 tiers × 3 reps, rep-isolated source cache): the original Q6 scan's three reps shared the retrieval source cache (cache key omits the rep index), which is a mechanism-level fact (code + arithmetic: hit counts exceed files written in each run's window) but whose behavioral effect on rep variance is still unquantified — the rerun's verdict is a metacognition-axis standard-deviation comparison (the coverage axis is at coarse 46-unit resolution saturation at 300 nodes, so its sd is not a usable variance probe). An early observation from the first rerun run (300-r1, n=1): it terminates on the depth ceiling (`max_depth=4` hit, 252 nodes) where the original 300-tier reps all terminated on the node budget (`max_nodes=300` hit, exactly 300 nodes) — so the original batch's "realized = budget" clean x-axis at 300 is a property of the cache-shared expansion path, not a robust one, and the depth ceiling bites at lower budgets than the 719 tier once retrieval is independent. The stopping-mechanism difference is recorded per run and flagged as a confound in the variance comparison. (b) *Depth-ceiling-free 719 batch* (3 reps, `max_depth=10` vs the original 4): the original 719 tier's three reps terminated on the harness tree-depth ceiling (realized 197/351/379 nodes), so that tier measures the depth-ceiling regime, not the model's budget demand; the depth-ceiling-free batch makes the node budget the sole binding constraint and is the clean "budget past saturation" test referenced in (i). Its stopping criterion is verified per run (must be `max_nodes` hit or natural completion, not a depth hit). Until (a)/(b) land, the Q6 numbers above carry the depth-ceiling and cache-sharing caveats stated inline. (c) *Depth-ceiling parameter differs across domains*: the GPU K7 scan ran with `max_depth=5` (the GPU gold's trunk depth), the original Q6 scan with the harness default 4, and the depth-ceiling-free Q6 batch with 10 — the depth-component absolute values are per-domain normalizations and are not directly comparable across these three batches; cross-domain budget-effect comparisons must hold the depth ceiling constant, which only the depth-ceiling-free batches (Q6 `max_depth=10`, and Q7 `max_depth=10` once it lands) satisfy.
