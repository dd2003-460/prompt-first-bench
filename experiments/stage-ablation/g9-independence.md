- g0×g4：维度 i 中的“四卡 VRAM 门槛”是维度 j 中“KV cache 估算”在特定硬件配置（4卡）下的直接应用与验证；若改变硬件配置（如改为单卡或双卡），维度 i 的数值（总显存）会随之改变，而维度 j 的 KV cache 需求（由模型结构和上下文长度决定）保持不变，导致“是否装得下”的结论发生根本性变化，二者在“可行性判定”这一逻辑层级上紧密耦合。
- g0×g6：VRAM容量（维度i）直接决定了单卡能否承载模型权重，从而决定了所需的最小卡数（N）；而TCO公式（维度j）中的总成本与卡数N成正比（N×卡价 + N×功耗），因此i的变化（如从单卡可行变为必须多卡）必然导致j中硬件成本和能耗项的结构性变化。
- g0×g9：VRAM容量（维度i）直接决定了模型是否能在单卡/多卡上完整加载（硬门槛），若装不下则必须分片或量化，这直接改变了推理时的内存访问模式和调度策略，从而必然影响有效利用率（维度j）；反之，若容量充足，调度效率主要受限于带宽和计算，但容量不足时的调度开销（如offload、swap）会显著降低u，两者在物理部署层面强耦合。
- g0×g10：维度 i 中的 VRAM 容量（如 4090 的 24GB vs L40S 的 48GB）直接决定了维度 j 中显存闸（S ≤ VRAM/KV_bytes）的上限，因此 i 的变化必然导致 j 中显存闸约束的变化。
- g0×g12：VRAM容量门槛（i）直接决定了硬件的代际与价格档位（如4090 vs A100），而硬件价格档位是计算自建TCO的核心变量，进而直接改变云租与自建的利用率分水岭（j）；i的变化必然导致j的阈值发生位移。
- g0×g13：VRAM容量门槛（i）直接决定了模型权重的存储精度上限（j中的量化选择），因为若硬件VRAM不足以容纳高精度权重，则必须通过量化降低精度以适配硬件，从而同时影响成本和质量。
- g1×g2：维度 i 中的具体数值（如 5090≈33 tok/s）是基于 BF16 精度计算的，而维度 j 明确涉及 INT8 精度下的容量与性能重算（5090≈66 tok/s）；若 i 的数值发生显著变化（例如从 BF16 变为 INT8），j 中的容量约束（27GB vs 32GB）和性能上限（66 tok/s）必然随之联动变化，二者在“精度-带宽-容量”的物理约束链上不可分割。
- g1×g10：在硬件规格（Spec）层级，带宽（BW）和显存容量（VRAM）是独立设计的参数，可以独立变化；但在性能（Performance）层级，单流速度（i）决定了单位时间内的吞吐上限，而并发流数（j）受限于显存中KV Cache的总容量，两者共同决定了系统的总吞吐量（Total Throughput = S * tokens/s）。若仅改变带宽而不改变显存，单流速度变化会改变“速度闸”的阈值，从而改变最终取min后的并发流数S，导致j的数值发生变化。
- g2×g3：维度 i 中的“可装性”（容量约束）直接决定了维度 j 中“Prefill/Decode 阶段划分”是否成立：若模型无法装入显存（如 4090 24GB 装不下 27GB 权重），则根本不存在 Prefill 和 Decode 的独立性能瓶颈分析，整个推理流程无法启动；即使能装入，显存占用率（i 的变化）也会通过影响 KV Cache 可用空间，间接改变 Decode 阶段的带宽压力（j 的一部分），从而耦合两个维度的物理表现。
- g2×g4：维度 i 中的“可装性”（Capacity Fit）直接由权重体积与 KV Cache 体积之和决定，若 i 中硬件显存容量或权重精度变化导致总占用超过物理上限，则 j 中关于 KV Cache 对显存余量的评估将因“无余量”或“溢出”而失效或发生质变，二者在显存预算约束下逻辑耦合。
- g2×g6：维度 i 中的硬件选型（如 5090 vs A100）直接决定了维度 j 公式中的“卡价”、“功耗”和“残值”变量，因此 i 的变化必然导致 j 的数值发生显著变化。
- g2×g9：维度 i 中的 'INT8 后权重 ~27GB' 是硬件容量约束（Spec 层），而 '5090≈66 tok/s 上限' 是性能预测（Performance 层）。维度 j 的 '有效利用率 u' 是性能层指标。在 Spec 层，权重大小（i 的一部分）与利用率（j）独立；但在 Performance 层，权重大小决定了内存带宽压力，进而直接决定调度效率和占空比（即 j 的构成要素），因此 i 的性能部分与 j 强耦合。
- g2×g10：维度 i 中的显存容量（VRAM）是维度 j 中显存闸（S ≤ VRAM/KV_bytes）的直接输入变量；当 i 因硬件更换导致 VRAM 显著变化时，j 的显存闸上限必然随之线性变化，二者在性能约束层存在直接因果耦合。
- g2×g13：维度 i 中的“INT8 后权重 ~27GB”是维度 j 中“量化改变成本（权重变小）”的具体数值体现，且 i 中基于 INT8 的 roofline 计算隐含了 j 中“精度损失”这一前提，两者在物理存储占用和性能/质量权衡上存在因果耦合。
- g2×g14：维度 i 中的硬件选型（如 5090 vs 4090）直接决定了维度 j 中“条件性推荐”的具体条件参数（如功耗、价格、可用性），因此 i 的变化必然导致 j 的推荐逻辑和条件集合发生实质性改变。
- g4×g10：KV cache 的显存占用（维度 i）直接决定了显存闸的上限（维度 j 中的 S ≤ VRAM/KV_bytes），因此 i 的变化必然导致 j 中显存约束项的变化，两者在逻辑上存在直接的因果依赖。
- g5×g10：缓存命中率（i）直接决定了每个请求实际消耗的 KV Cache 显存大小（bytes/tok 或 KV_bytes），从而直接改变显存闸（j）中 S ≤ VRAM/KV_bytes 的右端项；同时，跳过 prefill 改变了计算与访存的平衡，可能间接影响有效带宽利用率，进而影响速度闸。
- g6×g7：维度 i 中的 TCO 公式明确包含“功耗×电价×u”这一项，而维度 j 正是对该项（电费）的独立、精细化计算要求；j 是 i 中一个子项的展开与约束，二者在逻辑上存在包含关系，i 的变化必然涉及 j 的计算精度或数值。
- g6×g8：维度 j（故障损耗）在数学定义上是维度 i（TCO 完整公式）中的一项组成部分，j 的变化必然导致 i 的数值变化，二者是整体与部分的关系，而非独立变量。
- g6×g12：维度 i 中的'利用率 u'是计算自建 TCO 的核心变量，而维度 j 明确将'利用率阈值'定义为云租与自建的分水岭；i 的数值变化（特别是由 u 驱动的部分）直接决定了 j 中比较结果（自建是否优于云租）的翻转，二者在逻辑上互为因果。
- g7×g12：维度 i 中的'占空比'（Duty Cycle）是决定维度 j 中'利用率阈值'的核心变量；自建 TCO 中的电费项直接由 i 计算得出，而云租 vs 自建的盈亏平衡点（Break-even）正是基于自建总成本（含电费）与云租固定成本的比较，因此 i 的变化必然改变 j 的判断结果。
- g9×g10：在硬件规格层（Spec Layer），u（由CPU调度、PCIe拓扑、驱动效率决定）与 S（由VRAM容量和KV Cache大小决定）是独立参数；但在性能/TCO层（Performance Layer），u 直接决定单流吞吐量，进而决定达到目标并发 S 所需的硬件数量或单卡负载，从而在 TCO 计算中产生耦合。
- g9×g12：维度 i 中的'占空比'（Duty Cycle）是维度 j 中'利用率阈值'的直接物理输入变量；在 TCO 模型中，自建成本分摊与云租固定费率之间的盈亏平衡点（Break-even Point）在数学上直接由占空比决定，因此 i 的变化必然导致 j 的判定结果（云租 vs 自建）发生翻转或边界移动。
- g10×g13：在性能/吞吐量层级，量化精度（j）直接决定每token字节数（bytes/tok），从而线性改变速度闸的并发上限 S_speed；同时量化改变权重体积，间接影响显存闸的剩余空间分配。因此，改变量化方案（j）必然导致并发流数上限（i）发生显著变化，两者在性能约束层面强耦合。
- g11×g14：维度 i（市场价格波动）直接决定了维度 j 中“条件性推荐”的核心变量（采购时点/成本），若 i 不变（价格稳定），j 中的“采购时点”条件即失去意义或权重大幅降低，二者在决策逻辑上强耦合。
- g12×g14：维度 i 的核心输出（利用率阈值）是维度 j 所要求的“条件性推荐”中“利用率”这一关键变量的具体量化定义；若 i 的阈值判断发生变化（例如从 30% 变为 50%），则 j 中“在什么利用率下哪张卡最优”的条件边界必然随之改变，二者在逻辑上构成定义与被定义、参数与结论的强耦合关系。
- g13×g14：维度 i 中“精度损失导致的质量下降”直接决定了模型是否满足业务可用性阈值，而该阈值是维度 j 中“条件性推荐”的核心约束变量；若质量损失不可接受（i 变化），则无论成本多低（j 中的成本变量），该硬件/精度组合在逻辑上都会被排除出“最优”候选集，因此 i 的变化必然牵动 j 的最终推荐条件。
