## 解释（为什么闸没把无锚点率打下来）

0. **gold 值命中（r1 的编造检查）**：r1 里 B 臂编造的 TFLOPS 395/340 在 r2 **未复现**——B 两次 run 都给出 989 TFLOPS FP16 Tensor Core（与 gold 一致），A/C 全部 4 runs 根本没提 989/756。方向与 r1 相反（r1 是 C≥B on facts，r2 是只有 B 说出正确标称值），n=2 不足以定论，但「结构提示让模型想起真实规格」这条线索值得 S5 消融时单独看。

1. **闸是隔离器不是验证器**：apply() 把无锚点数字行替换成 `[隔离：unverified]` 占位符，post 分析的分子分母同时缩小，比率基本不变。设计意图就是如此（gates-postcheck.md：隔离 ≠ 删除，可回滚），所以「post 无锚点率 ≈ raw」是预期行为，不是 bug。
2. **真正的信号在绝对量**：B 臂（decomp 结构）产出 133 个数字断言，是 A 臂（67）的近 2 倍——结构化拆解逼模型把更多规格摆上台面，但也让无锚点数字的暴露面翻倍。闸的价值体现在**这些数字被逐行标记并可回滚**（quarantine 列表完整保留原文+行号+原因），而不是自动变干净。
3. **A 组输出里确实零 URL**：grep 确认 gpu-A 两 run 全文无 http/URL/datasheet 引用，只有「NVIDIA 官方白皮书和社区 benchmark」这种口头引用——r1 的「纯 prompt 不产生事实」结论在 r2 复现。

## 与 r1 的一致性

- r1：C≥B on facts（仅限纯结构分解）、B 编造 TFLOPS 395/340、HBM 带宽两版本共存 → r2：B 数字量最大且 100% 无锚点、显式矛盾 0（窄检测下）。方向一致：**结构提高暴露度，不提高准确性**。
- 新信息：C 臂（minimal+数字闸）gpu 无锚点率 90.9%，是六格中最低——单挂数字闸对裸奔模型有轻微收敛作用（可能因为闸的存在改变了生成时的自我约束，conf 低，n=2 不足以定论）。

## 诚实条款

- n=2/臂，所有比例都是方向性证据，不是统计结论。
- 闸 2 矛盾检测是窄模式（单 SKU 带宽冲突），「0 矛盾对」的上限意义有限。
- accuracy 维度 = null（需人工冻结原子事实标签后核验，本轮未做）。
- judge/检测全为启发式正则，precision/recall 未标注集校准（test_gates.py 4 例通过仅证明样例行为）。

## 对 S5 配置的影响（DESIGN.md D-a 回填依据）

三道闸**保留**进 S5：它没有让数字变准，但它提供了 r1 完全没有的东西——逐行 quarantine 审计链（哪个数字没来源、在哪一行、原文是什么）。S5 vs D1 对比时，「可审计性」本身就是一个独立于准确率的系统能力维度。若后续要检验「闸是否改变模型生成行为」（C 臂那个 90.9% 的线索），需要单独加一组 n≥4 的对照，不在本轮预算内。
