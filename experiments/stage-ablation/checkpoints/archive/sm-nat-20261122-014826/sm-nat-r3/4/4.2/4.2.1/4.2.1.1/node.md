## Corrected Claim

工作点1（高吞吐/低驻留）：假设 P[hit]=0.5, E[Size|hit]=0.5KB，则 T_avg_residency = 128GB / (100,000 * 0.5 * 0.5KB) ≈ 1.5 小时。此时 P_stale = 1 - exp(-0.01 * 1.5/24) ≈ 0.000625 (0.0625%)。

## Evidence

先验知识/题面给定，逻辑校验通过：128GB / (100,000 * 0.5 * 0.5KB) = 131,072,000 KB / 25,000 KB/s = 5242.88 s ≈ 1.456 小时。等等，这里计算有误。重新计算：128GB = 131,072 MB = 134,217,728 KB。分母：100,000 req/s * 0.5 hit_rate * 0.5 KB/req = 25,000 KB/s。时间 = 134,217,728 / 25,000 = 5368.7 s ≈ 1.49 小时。原陈述称 3.7 小时，数值不符。但检查单位：若 128GB 指 128 * 1024 * 1024 KB，则 134,217,728 KB。若 100,000 是每秒请求数，0.5 是命中率，0.5KB 是平均大小，则吞吐量为 25,000 KB/s。134,217,728 / 25,000 = 5368.7 秒 = 1.49 小时。原陈述 3.7 小时错误。但是，如果 100,000 是每分钟？或者 128GB 是 128 * 1000^3？通常 GB 在计算机存储中指 1024^3。若 128GB = 128 * 10^9 bytes = 125,000,000 KB。125,000,000 / 25,000 = 5000 s = 1.38 小时。仍不是 3.7。若分母是 100,000 * 0.5 * 0.5 = 25,000。若 128GB 是 128 * 1024 * 1024 * 1024 bytes = 137,438,953,472 bytes = 134,217,728 KB。134,217,728 / 25,000 = 5368.7 s。5368.7 / 3600 = 1.49 小时。原陈述 3.7 小时明显错误。然而，source 是 knowledge。根据规则，knowledge 节点逻辑自洽即 verified。但这里数值计算错误属于逻辑不自洽（算术错误）。规则说“逻辑自洽即判 verified”，如果算术错误，则逻辑不自洽。因此 logic_ok 应为 false。若 logic_ok 为 false，则不能判 verified。根据判定规则，failed 仅当与来源矛盾或硬逻辑错误。算术错误属于硬逻辑错误。因此应判 failed。
