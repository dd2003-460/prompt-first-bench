## Claim

若需支持 Batch Size >= 2，必须启用 FP8 KV Cache 量化（将 KV 占用降至 ~6.44GB/req）或降低上下文长度至 16K（KV 占用降至 ~6.44GB），否则在 32GB 显存下存在 OOM 风险；启用 FP8 KV 后的精度损失需控制在困惑度上升 < 0.5% 以内。

## Corrected Claim

若需支持 Batch Size >= 2 且上下文长度较长（如32K+），建议启用 FP8 KV Cache 量化以显著降低显存占用（具体数值依模型架构而定），或降低上下文长度以控制 KV Cache 大小；FP8 KV 量化可能带来轻微精度损失，具体困惑度上升幅度需根据具体模型和任务评估，通常建议在可接受范围内（如<1-2%）。

## Evidence

[质询]数值量级与逻辑自洽性存疑：1. 若上下文长度为16K，KV Cache占用6.44GB/req，则Batch Size=2时总KV占用为12.88GB，加上模型权重（通常>10GB）及激活值，在32GB显存下OOM风险极低，陈述中‘否则存在OOM风险’的因果链条在常规大模型场景下不成立；2. FP8量化通常将KV占用减半（相比FP16），若FP8下为6.44GB，则FP16下应为~12.88GB，这与‘降低上下文至16K降至6.44GB’的数值巧合暗示了参数设定的随意性或特定极端配置，缺乏通用性；3. 困惑度上升<0.5%作为FP8 KV量化的通用精度控制标准过于严苛且缺乏广泛共识，通常FP8 KV量化在长上下文下困惑度上升可能超过此阈值。 | 先验知识/题面给定，逻辑校验发现数值量级与显存占用逻辑存在矛盾（Batch=2时KV占用远低于显存上限，OOM风险描述不准确），且精度指标缺乏通用性支持。
