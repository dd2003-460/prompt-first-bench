## 执行摘要

1. **操作性激活是成立的，神经层面的“本来已会”未证实。** 同一冻结权重在不同提示下的表现可明显不同 [R1, R2, R3]；不能仅凭覆盖差异认定存在可稳定调用的贝叶斯程序。
2. **有具体贝叶斯和敏感性先例，但效果高度依赖任务。** QUITE 中 CausalCoT 对 Llama-3-8B 准确率 7.0%→11.4%，Mixtral 9.6%→7.0% [R8]；E-value 案例未做无提示对照，不能计算提示增益 [R9]。
3. **P3 结构化证据槽是值得试验的假说，不是纯格式中立，也不是已被验证的胜者。** 强制输出 `f(x±Δ)` 已经规定了分析行为与假设，可能挤占上下文或凭空造值。
4. 第一优先：在保留原 P3 核验结果的前提下，局部、可拒答地追加条件证据槽；不修改 P1，不强迫每节点量化。
5. 第二优先：独立试验 P3 的**一条跨域结构示例**；该机制不同于 schema，本身包含过程信息，需等长控制与泄漏检查。
6. 两种机制必须分别对照当前 S5、非内容等长 sham；先看全题基础覆盖与无支持主张，再看条件点收益。
7. 文献同时提示 CoT、贝叶斯术语、强 JSON 可能伤分 [R8, R10, R11]；“多提示=更强”并无保证。

## 0. 对象、术语和边界

### 0.1 可观测的激活定义

- 固定模型、权重、题目、检索语料和评分规则，记默认方法对某项目的成功率为 `p0`。
- 用触发器 T 后成功率为 `pT`，若独立重复中 `pT > p0`，称为**操作性 elicitation gap**。
- 比较应同时报告调用率、正确率、覆盖率、成本及错误类型，不能只数关键词或格式合规率。
- 有“间接提示可做、开放任务不做”才支持可访问能力的行为证据。
- 即便如此也无法单凭结果断言模型内部存有独立、可泛化的程序模块。
- 提示中的示例或公式可在上下文中提供新信息；冻结权重≠没有任何学习/新信息。
- 外部检索可以引入事实；计算器可以引入精确计算；二者都不是单纯发现模型早已掌握全部信息。
- 默认未提及也可能是任务歧义、缺参数、预算截断、节点未生成、评分不充分或确实不会。

### 0.2 项目问题的分解

- 激活检测：原节点是否包含可验证的参数依赖，或上游问题是否明确提出相关变化？
- 能力检测：同一节点、给定必要事实，直接问条件关系能否正确求解？
- 引用检测：依赖关系是否由可靠证据或明确公式支持？
- 传播检测：P4 是否保留经核验的依赖、限定条件和缺失信息？
- 覆盖检测：新机制是否挤掉已有、直接计算或事实型 gold 点？
- 这些环节出错的处置不同；不能把所有错误都命名为“不会激活”。
- 本任务不建议再次往 P1 叠加“必须做 X 分析”的全局内容规则。

## Q1：已有能力默认不调用是否被研究？

**判决：部分成立。** 有成熟的行为级能力诱发、prompt sensitivity 和 ELK 等相邻术语；没有一个已获普遍证明的、适用于本项目的单一神经机制。

### 1.1 Capability elicitation / chain-of-thought elicitation

- Wei 等称之为 prompting “elicits reasoning”，冻结模型，改变示例中的中间步骤 [R1]。
- PaLM 540B 在 GSM8K：标准 few-shot 17.9%，CoT few-shot 56.9%，差 39.0 个百分点 [R1, Appendix Table 6]。
- 这是特定模型、数据和示例的成绩，不是 27B nat 的预测。
- CoT 同时改变了示例信息、输出长度和计算量，因此不能将收益全归因于单一既有模块。
- 同论文指出在较小模型上效果不一定存在，计算错误依然常见 [R1]。
- “latent capability”在此只作为可操作隐喻，不表明权重里有可识别的“贝叶斯函数”。

### 1.2 Bayesian normative mode 与 representativeness

- Li 与 Rui 对 posterior judgment 分 structured、semi-structured 和 unstructured 三种信息设定 [R7]。
- 当先验和似然明确给定时，先进模型表现出较强规范计算；缺少似然、增加代表性描述后，表现可偏离先验。
- 替换 `indicate` 为 `compute` 等在半结构化设定改变了行为；不等价于仅改 JSON 字段。
- 更强提示在非结构化设定仍不能稳定纠正类比偏差，先验召回尤其不可靠。
- 作者提出后训练过程解释，但明确是猜想；本报告不把 RLHF 归因为既定事实。

### 1.3 ELK：隐含知识提取的邻近术语

- Mallen 等将 ELK 用于从激活中寻找与真实答案相关的信息 [R3]。
- 他们对有意微调成特定上下文出错的“quirky”模型训练线性 probe。
- 实验支持表征可在错误输出时仍存在；它是白盒、部分带监督的实验，不是本任务的零训练 prompt 机制。
- 知识 probe 不等价于发现概率更新算法，不能直接迁移到开放式 nat 题。
- “隐藏知识”和“默认不做一个推理步骤”应区分，而不能据词面混同。

### 1.4 Prompt sensitivity 与开放式输出

- POSIX 研究发现语义等价改写可能改变输出，few-shot 可降低部分测量到的敏感性 [R4]。
- 这是行为变化与稳健性证据，不单独证明表现改善或概率推理正确。
- Q1 的最稳妥解释：生成受上下文条件化及任务/解题分布影响；模型可能具有某些可组合的先验表示。
- 补充候选解释包括输出预算竞争、缺少证据、参数绑定错误、样本偏置与后训练偏好。
- 这些机制并非已证明的互斥解释，也没有公认“最被接受”的单一因果解释。

## Q2：CoT 为何有效：机制与反证

**判决：部分成立。** 自条件化、逐步计算与示例诱导有明确机制假说和局部实证；不存在对所有任务和模型成立的统一因果解释。

### 2.1 外部工作空间与自条件化

- 自回归模型产生中间文本 `z`，其后答案依据 `P(answer | question, z)` 继续生成。
- 这给每个中间 token 增加一轮前向计算，并把子结果留在上下文，后续 token 可读取。
- 它是条件概率和计算路径层面的机制假说，而非证明文本准确披露内部思维。
- Wei 等将复杂问题分解和额外计算作为 CoT 的可能优势 [R1]。
- 对 P3 而言，先记可审查的参数、依据和中间量，可减少单步跳到结论的负担。
- 错误中间量也会成为后续条件，带来错误传播。

### 2.2 注意力路径与局部因果干预

- Dutta 等 [R5] 使用 Llama-2 7B、虚构本体 PrOntoQA 及 activation patching/probing。
- 他们观察到多个路径，部分 attention heads 搬运本体关系，较深层形成答案信号。
- 这支持 CoT 内容可能改变后续信息流，但不是对贝叶斯任务或 27B 的普适证明。
- 将其简化成“注意力集中所以必然正确”是不成立的。
- 中间步骤可以被读取，同时也可能引入误导性证据或覆盖上游信息。

### 2.3 分解与示例的提示效应

- Least-to-most [R6] 将复杂问题拆成子问题，依次解答并把先前结果加入后续上下文。
- GPT-3 code-davinci-002 在 SCAN length split：该方法至少 99%，普通 CoT 16%；14 个示例 [R6]。
- 这是玩具组合泛化且示例固定，不等于可以直接把收益迁移到 PFB 全题覆盖。
- PFB 已经有分解管线；需要检查新增分解是否重复、遗漏或传播错误，而非再套一次大框架。
- 示例同时改变模型看到的解题形状、步骤与事实；实际机制不能从结果单独分离。

### 2.4 真实性和反例

- Turpin 等 [R12] 改变偏置特征，观察答案与解释随之偏移，解释却可能不披露该特征。
- 在 13 个 BIG-Bench Hard 任务中，偏置条件下准确率下降最高达 36 个百分点；并非所有任务都是 36 点。
- 因此合理的步骤文本不等于忠实因果记录，更不等于已经核验的证据。
- QUITE 显示 CoT 对概率推理的不同模型有正、负及近零效果 [R8]。
- Schoenegger 等 [R10] 在真实预测问题中发现鼓励 Bayesian reasoning 的提示反而降低准确性。
- 最小可证实结论是：CoT 改变了推理时的条件、可用计算和输出；是否改善应靠任务级对照。

## Q3：零训练候选机制（按预计工程改动由小到大）

**判决：成立。** 至少七类机制可在冻结权重下部署；排序反映预计工程改动，不代表效果、风险或成熟度排序。

### M1. 可选条件证据槽（局部 schema / 内容契约）

- 触发：仅 P3，先按既有协议完成节点核验；若 claim 或用户原问题明确含参数依赖，则追加一个可拒答的条件证据记录。
- 表达：`parameter`、`baseline`、`variation`、`outcome`、`support`、`status`；均可为 null。
- 若并无依据、参数取值或可计算关系，返回 `insufficient_evidence`，不得发明 ±Δ、先验或来源。
- 调用原理：通过输出槽提高任务相关信息的可见性与后续读取机会；仅是路径诱导假说。
- 接入：旧字段、节点 id、核验文本和原 P4 输入保持原样；追加字段隔离存放。
- P4 只消费通过引用/算术检查的记录，未证实内容标注未知；不覆盖旧字段。
- 风险：条件字段虽形式化，但 `outcome` 和变化本身是语义要求，并非纯“只改格式”。
- 风险：JSON 硬约束、增加输出长度、参数绑定错误或虚构上下界均可伤基础覆盖。
- 证据边界：JSONSchemaBench [R13] 与 Tam [R11] 的模型、任务和格式不同，方向不一致。
- **工程量：最小到小**；尚无研究直接证明此特定条件证据槽可改善 PFB。

### M2. 一条跨域结构示例（few-shot）

- 触发：P3 已识别条件性节点时，提供一条与待测题目不共享事实、数字、答案的已核查示例。
- 例子体现“变量变化—其他条件不变—有依据时输出变化—无依据时说未知”。
- 此方法改变输入示范而非仅增加输出键；不可和 M1 当成同一席次。
- 调用原理：示例改变任务条件分布，诱导模仿可组合的程序形状 [R1, R4]。
- 它也提供了过程性知识，不能说完全没有知识注入，更不能说证明模型预先会。
- 接入：P1/P2 完全不变，P3 每个目标节点输入同一冻结示例，控制总预算。
- 保留反例：示例中同时展示无证据时 abstain，避免模型推断每个节点必有可算结果。
- 边界：例子可复制错单位或表面模板，造成领域迁移失败；高相似示例可泄漏 gold。
- 使用等长、与参数无关的示例 sham，并做未见领域、近义改写与例子顺序鲁棒性检查。
- **工程量：小**；至少一次人审，避免与 schema 叠加后无法归因。

### M3. 软触发的短 CoT / 程序提示

- 触发：P3 节点单独要求先写简短的“已知/缺失/依据/结论”，不要求无条件应用某个公式。
- 若询问贝叶斯，只有先验、条件似然和事件定义明确时才计算后验。
- 原理：中间文本提供工作空间及后续自条件化 [R1, R5]。
- 接入：在节点核验之前或之后各需独立实验，不能默默覆盖原核验文本。
- 限制：更多 token 和错误传递；“先写得像合理推理”并非验证。
- 不把此前 P1 中全局“必须分析 X”换个阶段无差别重放。
- **工程量：小**，但模型与语言条件敏感。

### M4. 输入表示变换：自然频数 / 明确条件

- 触发：已有概率、样本量与依赖关系时，把题目等价改写为自然频数或具名条件事件。
- 如抽象概率无法映射为整数个案，应使用比例或符号表示，不得把四舍五入当真实样本。
- 原理：呈现模型熟悉的数量关系并减少条件概率方向混淆。
- 接入：只对符合前提的概率节点生成辅助表示；同时留存原始依据及单位。
- Araya [R14] 在单个案例的不同模型中发现对自然频数提示的服从并不一致；不是强效果量证据。
- 风险：改写过程引入数据或四舍五入错误；“格式转换”仍改变上下文信息。
- **工程量：小到中**；不得用它填补不存在的先验或似然。

### M5. 条件子问题 / least-to-most

- 触发：当节点包含多个前提或一项已核验结果是另一项前提时，提出有序的局部子问题。
- 问题如“变量和单位是什么？依据给了哪些范围？在此范围内结论如何变化？”
- 先验/似然子问题只有在问题本身要求概率判断且证据允许时出现。
- 原理：降低每次请求的组合负担，让先前子结果成为明确上下文 [R6]。
- 接入：P3 内临时子调用，不修改上游 P1 树，也不把每条子问题都当新 gold 节点。
- 边界：子问题遗漏、上游误差传播、节点拆得过细及 P4 去重均可能降低覆盖。
- **工程量：中**；增加调用次数，需记录每节点延迟和失败原因。

### M6. 缺信息触发检索 / ReAct 式交互

- 触发：P3 能识别具体未知项时，提出有限次的针对性查询，如参数物理边界、来源或定义。
- 用外部 evidence 更新节点，但必须保留来源、时间、适用范围与相互冲突。
- 原理：检索将外部证据带入上下文，帮助选用程序；不是只激活权重中已有知识 [R15]。
- 接入：复用 P2 检索基础设施；把候选事实写入独立来源表，逐项核验。
- 边界：污染、失效来源、检索结果矛盾、公开来源不适用与额外延迟。
- ReAct 任务不同；其问答成功不能证明此路线上 nat 参数点提升。
- **工程量：中**；若原 P2 已检索充分，边际收益可能很低。

### M7. self-consistency / 多路径聚合

- 触发：对经标记且重要的可客观对比节点，采样多个独立路径并聚合结论 [R2]。
- 对数值以容差和单位归一，对结论记录分歧；条件范围不能简单做字符串多数投票。
- 原理：在冻结模型的多个候选中利用答案一致性；不保证独立性或真值。
- 接入：P3 只对少数高价值节点采样，保留原路径及各条来源供审计。
- 证据：PaLM 540B GSM8K 的 40 路采样相对 greedy CoT +17.9 个百分点 [R2]。
- 边界：开放式多答案、系统性共同错误、算术错误及生成成本会使多数表决失败。
- **工程量：中到大**；不应将投票比例解释为已校准的正确概率。

### M8. 程序辅助计算 + 可验证执行

- 触发：已有明确、可信的公式与输入，且节点需要多次数值代入或后验归一。
- 生成小型可检查表达式，经过沙箱、单位和参数范围校验，再由确定性计算器运行。
- 原理：把算术交给外部工具；属于混合系统，不是纯 prompt 单调用。
- 接入：P3 先取得可审查表达式和引用，执行后将输入、代码、结果及失败状态附回节点。
- QUITE [R8] 的无训练 ProbLog-Prompt 有大量解析失败，不能只计算成功子集的准确性。
- 错误公式、遗漏约束、代码执行安全、无穷解和先验不可信都不会因计算器自动解决。
- **工程量：大**；本项目的首轮 pilot 不应同时引入它和其他机制。

### M9. 选择机制时的实务准则

- 当模型在显式提问下也不会，优先验证数据/程序和工具，而不是继续堆触发词。
- 当有候选但计算易错，考虑 M8，而不是把 M7 多数当计算器。
- 当缺少现实参数，考虑 M6 或直接标记未知，而不是逼 M1 输出具体范围。
- 当输出不稳定但可能存在可核验答案，才试 M7；无客观聚合标准时记录分歧。
- 每个机制的调用门控及漏触发率本身也是实验对象。

## Q4：贝叶斯、最大似然和敏感性设计的先例

**判决：部分成立。** 贝叶斯推理提示和某类敏感性任务已有具体研究；针对本项目“开放 nat 题、P3 节点、参数±Δ、27B、基础覆盖不损失”的效果仍是未确认的实证空白。

### 4.1 贝叶斯：直接比较与效果量

- QUITE [R8, Table 4] 用真实文本风格概率网络，比较 zero-shot 与 CausalCoT。
- GPT-4-Turbo：正确率 36.7%→37.1%（+0.4 个百分点），RMSE50 0.304→0.326（变差）。
- Llama-3-8B：正确率 7.0%→11.4%（+4.4 点），RMSE50 0.521→0.403。
- Mixtral-8x7B：正确率 9.6%→7.0%（-2.6 点），RMSE50 0.441→0.486。
- 准确是严格数值容差，且错误/拒答按论文约定纳入；不是普通概念覆盖率。
- CausalCoT 明确要求建立概率图、识别问题类型与逐步计算，属于内容型提示，不是中性 schema。
- 切勿把 Llama-3-8B 的 +4.4 点预测为本地 27B 的效应。
- Bayesian Teaching [R16] 的多轮偏好更新中，普通 CoT 与替代表征未产生有意义改善；其后训练结果超出本任务零训练范围。
- 反证：动态更新本身可能尚未可靠，不能仅凭数学定义断言每个模型具备可调用能力。

### 4.2 贝叶斯：真实预测的负收益

- Schoenegger 等 [R10] 对 100 道预测问题、四个模型，比较 37 种提示与 control，预注册混合效应分析。
- 论文报告 Bayesian Reasoning 相对 control 的 Brier 分数差为 +0.030，校正后 p<0.001；Brier 越低越好，故为退步。
- 该效果是跨模型的研究设定，不是声称四模型各自均独立显著，也不是所有贝叶斯方法必然无效。
- 同研究中 base-rate 提示点估计略有帮助，但在预注册混合效应分析中未达显著；另一不考虑聚类的 t 检验才达到显著。
- 直接写“用贝叶斯推理”也可能诱发编造先验或表面说理。

### 4.3 敏感性：E-value 与未测混杂

- Xiang 等 [R9] 对四篇观察研究的 11 个 exposure/outcome 组合，以结构化提示要求计算 E-value。
- ChatGPT、Claude 和 Gemini 在论文报告的 11 个 E-value 计算上与原研究给出的值一致；DeepSeek 偏差 -0.01 至 +0.23。
- 提示要求使用适当公式，但不直接提供该公式；结果表明在这些题中可调用相关计算形式。
- 这是一种针对未测混杂的稳健性分析，不等同于普遍 `f(x±Δ)` 参数扫描。
- 没有无提示随机对照，无法计算“激活带来多少百分点”的因果效应。
- 公开研究可能存在记忆/污染；只 11 个值，不能外推到本地 27B 或开放领域。
- 因此“一篇都没有做敏感性提示”的 gap 被该论文否定；狭义 PFB 设定仍待测试。

### 4.4 最大似然与最概然

- 必须区分样本数据上 `argmax_θ P(data|θ)` 的最大似然估计、带先验的 MAP、分布的众数和生成时 token 概率最大化。
- 数据、概率模型、参数空间或约束缺失时，不能凭语言模型的先验直接给出可信 MLE。
- 检索具体 MLE 估计提示时，本次未识别到可直接支持“27B 开放生成中 MLE 激活增益”的原始对照研究。
- 这只是本次有限检索的 **gap 存疑**，不是“文献无人做”或“模型不会 MLE”。
- 区分研究者用 MLE 衡量模型、模型自己计算数据 MLE、贝叶斯先验构造的不同问题。

## Q5：schema 约束 vs prompt 知识注入

**判决：部分成立，尚无普遍优胜者。** 对 PFB 的首个低风险试验，优先局部可拒答的 schema；不能声称文献证明 schema 比内容提示更优，或 schema 完全不注入行为要求。

### 5.1 不同层面的“约束”

- 仅句法：对象括号、字段类型和是否为空；语法有效不意味着数值真实。
- 语义槽：字段名 `parameter`、`outcome_if_changed` 已提示模型关注和填入的内容。
- 解题程序：要求求 `f(x±Δ)` 指定了变量扰动、计算顺序和量化行为。
- few-shot：提供可供复制的具体程序、事实和表达风格，虽不改模型权重，仍有上下文教学效应。
- 知识注入：提供概率公式、参数范围、领域事实；质量可能高，但会改变可用信息。
- 因此“schema vs 注入”不是二元纯实验；要拆分格式、行为、外部事实、预算和示例因素。

### 5.2 正反证据链

- Tam 等 [R11] 测试格式约束、JSON mode、自然语言后转格式，发现受限格式在多个推理任务退化。
- 在其设定下更严格的格式通常更差；自由回答再转换是缓解方案，不保证所有任务优于原始格式。
- Geng 等 [R13] 系统比较 JSON Schema 解码框架，质量分析在部分任务/框架显示与非约束接近或更好。
- 两篇不矛盾：模型、提示、schema、字段顺序、解码器和测试任务均不同。
- 格式符合率是必要的工程指标，而不是证明依赖关系正确或覆盖增加。
- 研究所见不能推出“加 JSON 一定有效”，也不能推出“严格格式一定伤害推理”。
- T54 所建议的 `f(参数±Δ)` 比一般 JSON 类型约束更强，既是格式也是内容要求。
- 加一句“未知就留空”可减少被迫造数，但不能保证模型真的选择未知。

### 5.3 P3 执行的具体语义

- **识别依据**：节点原文明确含参数关系，或用户原问题明确要求该关系；不能事后依据 gold 标注触发。
- 检测器可由冻结、盲测的规则或模型实现；提前记录版本并在人审样本上测 precision/recall。
- 对“隐含但没有出现在节点”的条件点，检测器可能漏掉；这是该方法的核心边界。
- 没有变量、基线、可解释的变化范围或函数/证据时：`status=insufficient_evidence`。
- 若原文仅支持定性方向，允许 `outcome` 为定性，禁止伪装精确区间。
- 报告 `unknown` 应与“已验证没有参数影响”分开。
- 若触发器失败或输出不可解析，回退原 P3，不删原结论、不把未知视为已核验。
- 新信息不能由 P4 无条件提升为事实；每个结论携带输入条件和来源。

### 5.4 两个路线上都必须检查

- 将相同节点分别分配 baseline、sham、M1 或 M2，比较净新增与丢失，而非只看触发次数。
- 固定最大输出预算，同时单独记录实际 token；做等总预算和额外预算两个成本口径。
- 若加槽压缩其他内容，先看是否会造成基础覆盖下降，再决定是否考虑扩大预算。
- schema 对象合法但数据错，应按语义错误计；解析失败不得排除出分母。
- 用条件节点误触发率、漏触发率及造数率监督门控，而不是只报告正向样本。

## 最小验证实验规格（建议；尚未运行）

### E1. 人审前置与固定样本

1. 冻结一个本地 27B 模型版本、tokenizer、量化、上下文长度及 P1/P1.5/P2/P3/P4 代码和 prompt。
2. 固定题集及领域配比；例如 nat/soc/gpu 各 10 题，若现有题不足则全量报告，不虚构样本。
3. 固定每题现有 gold 点，人工标记条件/基础两类；允许一条点多标签但分母事先固定。
4. 不将 gold 内容输入触发器、示例或 P3；示例从未重叠的外部合成题中选取并人审。
5. 尽量缓存同一 P1/P1.5/P2 输出供各处理臂使用，先测 P3 的局部效果。
6. 另做少量端到端复跑确认收益能否经 P4 保留；这不能替代局部配对试验。
7. 在所有臂相同的缓存节点上，盲评门控，记录命中与漏检；对无原节点的 gold 明确记上游遗漏。

### E2. 对照臂与处理方式

1. A：当前 S5 P3 baseline；不变更提示或预算。
2. B：等长 sham，在相同位置加入与参数条件无关的中性格式/示例文本，不泄漏目标答案。
3. C：M1 条件证据槽；使用统一门控、可空字段，先自由核验再追加记录。
4. D：M2 跨域结构示例；同一门控但不使用 M1 的新 schema；示例先冻结。
5. A/B/C/D 在同一题、同一缓存节点上配对；为避免次序效应随机化执行次序。
6. 原分解树和证据缓存不可随臂变化；相同 token 上限、停止条件与重试策略。
7. 确定性运行先做一遍；若支持采样，再预设例如 3 个固定 seed，不把重复视为独立题。
8. 并列基准 S0 只使用同题相同评分，提供整体上下文；不能把 S0 与固定节点 P3 干预混为同一因果对照。

### E3. 主指标、守护指标与决策

1. 主指标：每题条件 gold 点命中率（包含上游未生成节点）；并报告仅可触发节点的条件点命中率。
2. 守护指标：全题覆盖、基础 gold 覆盖、事实/计算型 gold 覆盖、错误断言率及 P4 遗漏。
3. 各臂差值按题配对，按题而非节点 bootstrap 95% 区间；报告每领域和每 gold 点的原始分母。
4. 报告 C-A、D-A 及各自对 B 的差异、漏触发率、误触发率、未知率、解析失败率。
5. 审计新增答案的引用支持率、单位/数值正确性和无证据造值率。
6. 报告 prompt 与 completion token、节点数、调用次数、每题延迟和截断率。
7. 示例可执行门槛（须在实验前与 lead 确认）：条件点覆盖至少 +0.05 绝对值，且总覆盖与基础覆盖各不下降超过 0.02。
8. 对安全性采用非劣效下界：总覆盖和基础覆盖的配对差值 95% 区间下界均高于 -0.02；样本不足时结论为不确定，不宣称通过。
9. 上述双重保护与小样本下界要求可能非常难通过；30 题仅为可行性 pilot，并非充分功效保证。
10. 对多臂多指标预先指定唯一主比较与调整方式；其余作为探索性结果。
11. 若 C/D 任一臂增加条件覆盖但基础守护失败，不部署；分析截断、来源质量、门控与错误传播。
12. 若 A/B/C/D 都无法完成显式指定的贝叶斯或参数计算，对“默认不调用”的假说降级，转向工具/数据不足诊断。

### E4. 假说可证伪检查

- 用与开放题相同数据的显式子问题测试能力上限；人工另定正确答案与有效拒答。
- 若显式子问题正确而开放题未覆盖，可支持行为级 elicitation gap，但仍不能证明神经模块。
- 若显式子问题也错，应区别算术、公式、参数绑定、识别性缺失四类错误。
- 若只改变输出槽后“条件词”增加但错误率升高，不能称为成功激活。
- 若条件点收益来自 P4 篇幅增加而基础内容被截断，应作为预算竞争而不是认知改进。
- 若只在 nat 有效、soc/gpu 基础覆盖下降，应保留分域结果，不做跨域泛化宣称。

## 给 pfb 的接入建议

首选 **M1 可拒答条件证据槽**：只在 P3 门控后的节点追加，保留原核验与未知状态；风险是误触发、造数及格式挤占覆盖。次选 **M2 跨域 few-shot 示例**：独立在 P3 展示变量变化与证据不足，不与 M1 同时叠加；风险是模板迁移失败和信息泄漏。最小试验固定上游节点，按题配对 baseline、等长 sham、M1、M2，盲评条件点及基础覆盖、造数率和成本；覆盖守护不通过或样本不足就不部署。
