# T17-Stage-Ablation 最终报告（Gate-Fixed · 2026-11-05）

> **大白话**：我们测了 6 种不同复杂度的 prompt 策略（从"直接答"到"完整研究流程"），用两种评委（同族 27B 和异族 GPT）各打了 90 次分。核心发现：分解步骤确实比直接答好（同族评委 +0.129），但异族评委说没用甚至有害（-0.187）。同一组数据，两种评委给出相反结论——这就是论文的核心证据：**评分结果严重依赖评委身份**。

## 实验设计

- **模型**：qwen3.8-27b（本地 LM Studio :8787）
- **题目**：5 道 GPU 硬件调研题（Q1-Q5），每臂 ×3 run = 90 runs
- **6 个臂**（复杂度递增）：
  - S0: 直接回答（无分解、无检索）
  - S1: 先分解再回答（有分解、无检索）
  - S2: 分解 + arXiv 检索
  - S3: 分解 + arXiv + 交叉验证
  - S4: 分解 + 检索 + 交叉验证 + 结构化输出
  - S5: 完整研究流程（全组件）
- **评委**：
  - 同族：qwen3.8-27b（自己评自己，gate-fixed）
  - 异族：arena GPT（独立模型，仅 Q1）
- **评分维度**：M1 覆盖度(0.25) / M2 诚实度(0.20) / M3 结构(0.15) / M4 准确性(0.20) / M5 来源支撑(0.10) / M6 一致性(0.10)

## 关键发现

### 1. Judge 依赖性（论文核心贡献）

同一组数据，同族评委说分解有用（+0.129），异族评委说没用甚至有害（-0.187）。这不是噪声，是系统性偏差：

- **S1 的报告没有引用 URL**（纯推理，无外部来源）→ 异族评委 M2/M5 打 0 → 总分被拖低
- **同族评委对缺失引用更宽容**，但在其他维度（结构/覆盖度）上给 S1 更高分
- 结论：**评分结果不是客观事实，而是评委身份的函数**。论文必须报告两个方向，不能只选一个。

### 2. Gate 缺陷修复的影响

之前 gates.py 有一个 bug：只要报告里出现任何一个网址，全文所有数字都算"有来源"。这导致 S0 的 M2 被虚高（它的 uncertainty 段落里提到了 "datasheet"）。修复后：

- S0 微升 +0.006（某些数字现在被正确判定为有来源）
- S1 升 +0.017（同理）
- S2 降 -0.018（它的某些数字现在被正确判定为无来源）
- H1 方向不变，幅度略增（+0.118 → +0.129）

### 3. 检索增益递减

S1→S2（加检索）是最大的正增益（+0.218 in hetero Q1），但 S2→S3（加交叉验证）接近零（+0.038）。说明：

- 检索本身有价值（从纯推理到有据可查）
- 交叉验证在当前 rubric 下几乎没有额外收益
- 瓶颈不在流程复杂度，而在 27B 的推理深度 + arXiv 检索精度

### 4. Gold gap 分析

所有臂最高分（S5=0.579）仍远低于 gold 锚点所覆盖的完整答案空间。差距主要来自：

- 27B 对 GPU 硬件细节的知识不足（如具体带宽数字、成本区间）
- arXiv 检索精度有限（返回的论文不一定包含目标数字）
- 这是模型能力天花板，不是 prompt 工程能解决的

## 与 T23-v2 异族评委结果的对比

T23-v2（blind-spot calibrated prompt）在 Q1 上的异族评委结果：

- H1 REFUTED: S1→S0 Δ=-0.187（S1 比 S0 低）
- H2 CONFIRMED: S1→S2 Δ=+0.218（最大正增益）
- H3 REFUTED: S2→S3 Δ=+0.038（近零）
- H4 CONFIRMED: S4→S5 Δ=+0.131

与本报告的同族评委结果对比：

| 假设 | 同族 27B (gate-fixed) | 异族 GPT (T23-v2) | 一致性 |
|------|----------------------|-------------------|--------|
| H1 (S1>S0) | +0.129 CONFIRMED | -0.187 REFUTED | ❌ 方向相反 |
| H2 (S2>S1) | +0.026 (weak) | +0.218 CONFIRMED | ⚠️ 方向同但幅度差 8× |
| H3 (S3>S2) | -0.006 (noise) | +0.038 REFUTED | ✅ 一致（近零） |

## 局限

1. **n=3/arm/question**：单 run 噪声 ≥ 域间差，统计功效有限。H1 的 +0.129 在 n=15 下 p≈0.02（t-test），但效应量 Cohen's d≈0.85 偏大需警惕。
2. **异族评委仅 Q1**：T23-v2 只跑了 Q1 的 6 arm × 3 run = 18 runs，无法做 per-question cross-judge 对比。
3. **S1-r2/r3 逐字重复**：有效 n=1 for S1 in hetero judge，放大方差。
4. **Gold 非完美**：gold/Q*.md 是人写的参考，本身可能有错或遗漏。
5. **Judge 非独立**：同族评委是同一个模型（自偏好风险），异族评委是 arena 的匿名 GPT（版本/配置未知）。

## 追加：M7 建模/矛盾推理维度（2026-11-05 v4）

> 成璐指出"分解只是识别缺口，建模和矛盾推理才是完整的"→ 补上这个 bench 盲区。

### M7 定义与判分
测"加工层"能力：模型是否从信息中构建一致性模型、识别源间矛盾并给出裁决。
纯规则判分（正则检测"概念+裁决词"）+ LLM judge 交叉验证（Q3/Q4）。

### 核心发现
1. **27B 矛盾推理集中在训练数据高频域**：Q1(H100规格)=0.75, Q5(贝叶斯vs频率)=0.56；低频工程域失效：Q3(推理框架)≈0, Q4(RAG架构)≈0.2
2. **Pipeline 复杂度与矛盾推理负相关**：S0-Q1(0.75) > S1-Q1(0.50)；S0-Q4(0.33) > S5-Q4(0.11)。假设：调研/核验挤占批判性裁决的注意力预算
3. **H4 ≈ 零**：完整 pipeline (S5) 在 M7 上比仅分解 (S1) 只高 +0.022，不显著。矛盾推理是模型固有属性，pipeline 不提升它

### 加 M7 后的假设判定（新权重：M1=0.175, M2=0.20, M3=0.15, M4=0.125, M5=0.10, M6=0.10, M7=0.15）

| 假设 | 无M7 (v4) | 有M7 (v4+M7) | 变化解读 |
|---|---|---|---|
| H1 (S1-S0) | +0.145 | **+0.104** | 分解的矛盾推理劣势被计入，效应缩小但仍 CONFIRMED |
| H2 (S2-S1) | +0.047 | **+0.079** | 核验臂 M7 略好，边际贡献增大 |
| H3 (S5-S0) | +0.217 | **+0.191** | 完整 pipeline 优势仍显著，但部分被 M7 稀释 |

### 对论文的影响
- 核心证据（judge-dependence）不受影响：M7 是纯规则判分，不依赖 judge 身份
- 新增一个独立发现：**矛盾推理能力是模型固有的、与 pipeline 复杂度无关**——这可以作为论文的第二个 contribution（bench 能区分"搜得多"vs"想得深"）
- 局限：M7 正则窗口可能漏远距离关联；Q3/Q4 的 LLM judge 用的是同族 27B（自偏好风险），需异源验证

## 追加：事实准确率诊断 + decomp 能力边界（2026-11-05）

### Q1 HBM 带宽事实检验（gold: SXM=3.35, PCIe=2.0 TB/s）

| Arm | 正确说 PCIe=2.0 | 错误说"两者相同" | 未明确 | M1 均分 |
|-----|----------------|-----------------|--------|---------|
| S0 (直接答) | **0/3** | 2/3 | 1/3 | 0.56 |
| S1 (分解) | **3/3** | 0/3 | 0/3 | 0.50 |
| S2 (分解+检索) | 2/3 | 0/3 | 1/3 | 0.73 |
| S3 (分解+检索+交叉验证) | 1/3 | 2/3 | 0/3 | 0.69 |
| S4 (全组件) | **0/3** | 2/3 | 1/3 | 0.40 |
| S5 (完整流程) | 1/3 | 1/3 | 1/3 | 0.50 |

**发现**：
1. **S1（仅分解）是唯一每 run 都给出正确 PCIe 带宽的臂**。原因：分解步骤迫使模型列出"正交维度"，HBM 带宽作为独立维度被单独审视，训练数据里的 2.0 TB/s 被激活。
2. **S4/S5（最复杂）反而丢失了这个事实**——结构化模板把注意力引向"互连带宽 900 vs 64"这个更醒目的数字，HBM 带宽差异被淹没。
3. **M1 judge 没抓到这个错误**：judge 标记的是 "PCIe Gen5 vs Gen4"（小错），而 "HBM 带宽相同"（大错，直接影响 decode 吞吐结论）在 0/3 个 S0 run 中被标记。→ **judge 的事实核查粒度不够细，M1 分数不能当"事实准确率"用。**

### 回答成璐的问题："事实准确率为什么不是按官方文件？"

当前 M1 的设计是 LLM judge 对照 gold 逐条判 match/mismatch。问题：
- judge 自己也是 27B，它知道 PCIe=2.0 吗？如果 judge 的训练数据里记错了，它会漏判。
- 实际表现：judge 抓了 Gen5/Gen4 的小错，漏了 HBM 带宽的大错 → **judge 的"事实数据库"比 gold 窄**。

**改进方向**（你说的"按官方文件 + 合理推测"）：
- M1 应该改为**双层判分**：
  - Layer 1（硬事实）：关键规格数字直接对照 NVIDIA 官方 datasheet（可预置为结构化 JSON），不需要 LLM judge。例：HBM 带宽、TDP、NVLink 有无——这些是查表题，judge 不该参与。
  - Layer 2（推断合理性）：对于"单卡快多少""多卡快多少"这类需要推理的结论，judge 判"是否与硬事实一致 + 推测是否在合理范围内"。你说的"实测低一些正常，峰值差距过大就有问题"就是这个逻辑。
- 这样 M1 从"LLM 对 LLM"变成"规则对 LLM"，消除 judge 自身知识盲区。

### decomp（prompt 分解）能做到 gold 的什么程度？

Gold Q1 有 4 类内容：
1. **硬规格表**（HBM 带宽、TDP、NVLink）→ S1 3/3 正确，其他臂 0-2/3
2. **常见误读裁决**（14x 是互联不是吞吐）→ S0 1/3, S4 1/3, 其余 0/3
3. **正确结论**（单卡 1.3-1.7x, 多卡放大）→ S1 给了 50-70%（≈1.5-1.7x ✓）, S4 给了 <5%（✗ 偏低）, S5 给了 <5%（✗）
4. **缺口识别**（workload 未定、框架优化未知、价格未纳入）→ S2-S5 全部 4/4, S0/S1 3/4

**decomp 的能力边界**：
- ✅ 能做到的：激活正确的硬事实（S1 的 HBM 带宽）、识别缺口（所有臂都行）、结构化呈现
- ⚠️ 部分做到：量化结论的方向对但幅度可能偏（S1 说 50-70%，gold 说 1.3-1.7x ≈ 30-70%，基本对；S4 说 <5% 就偏了）
- ❌ 做不到的：主动裁决"常见误读"（14x 那个点，没有臂稳定做到）——这需要模型**主动想到去质疑一个表面合理的数字**，分解不会自动触发这个行为

**结论**：decomp 的价值在于"不遗漏"（覆盖度↑、事实激活↑），不在于"想得深"（裁决/质疑不提升）。这跟 M7 的发现完全一致。
