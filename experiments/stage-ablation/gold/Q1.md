## 关键规格（H100，SXM 为参考基准）
| 项 | H100 SXM | H100 PCIe | 备注 |
|---|---|---|---|
| FP16/BF16 Tensor (dense, TFLOPS) | ~989 | ~756 | PCIe 算力低约 23% |
| HBM 显存带宽 (TB/s) | 3.35 | 2.0 | **decode 瓶颈项**（NVIDIA 官方 datasheet：PCIe 版 2 TB/s，SXM 版 3.35 TB/s；PCIe 版因功耗墙降了 HBM 频率。注意区分：这是显存↔GPU 的 HBM 带宽，不是卡间 PCIe 总线带宽） |
| 显存容量 (GB) | 80 | 80 | 相同 |
| 卡间互联 | NVLink 900 GB/s | 无 NVLink（走 PCIe Gen4 x16 ≈ 64 GB/s） | 表面"14倍差距"的来源 |
| TDP (W) | 700 | 350 | |

## 常见误读（= 本实验要测的"隐藏矛盾"）
1. **「SXM 比 PCIe 快 14 倍」** —— 错。900/64≈14 是**卡间互联带宽比**，不是单卡推理吞吐比。
   单卡小批量 decode 时根本不触发卡间通信，这个 14 倍与吞吐无关。
2. **decode 阶段差距 ≈ 显存带宽比（3.35/2.0≈1.68x），不是算力比（989/756≈1.31x）** ——
   LLM decode 每步只算一个 token，是 memory-bound（带宽瓶颈），所以带宽比更贴近真实差距。
   ⚠️ 这里的"带宽"指 HBM 显存带宽（GPU↔显存），NVIDIA datasheet 确认 H100 PCIe 版为 2 TB/s（非 3.35）。
   容易混淆点：PCIe 总线带宽（卡↔主机/卡↔卡，Gen5 x16 ≈ 64 GB/s）和 HBM 带宽（GPU↔显存，TB/s 级）是两个东西。
3. **prefill（长 prompt 并行计算）才是 compute-bound，那时算力比 1.31x 才更接近真实差距。**
4. **多卡张量并行时 NVLink 才真正重要** —— 单机 8 卡 TP=8 场景，SXM 的 900GB/s 才有意义；
   PCIe 版做 TP 会因卡间通信慢而显著吃亏。这才是 SXM "贵得有道理"的真实场景。

## 正确结论（一个真查过的回答应包含）
- 单卡、小 batch、decode 为主 → SXM 优势约 1.3~1.7x（取决于 prefill/decode 占比），远非 14x。
- 多卡 TP/PP 大模型 → SXM 优势放大，NVLink 成为决定项。
- 「快多少」没有单一答案，取决于 batch size / seq len / 是否多卡 / prefill-decode 比例 → 这正是"需要进一步调研/实测"的缺口。

## 应识别的缺口（D2 锚点）
- 具体 workload（batch/seq/model size）未定 → 无法给单一数字
- 实际部署的框架（vLLM/TensorRT-LLM）对 PCIe 版的优化程度未知
- 价格/性价比维度未纳入（同样钱 PCIe 能买更多卡）
- 实测数据缺失，以上多为规格推算 → conf 应降级
