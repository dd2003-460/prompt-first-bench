# 触发器实验: 缺口信号点火 → 会不会真的去查（2026-11-28）

# origin: ai
## 动机
前两探针结论: strategic 层质疑 = 习惯 × 信息 × 触发。习惯(元层注入)和信息(检索通道)都给过, 模型仍不查 → 缺触发器。
本实验做最小触发器: 用模型自己输出的"信息缺口信号"(防御性语言: 未验证/无法排除/缺失/待核验…)当点火信号, 检测到→harness 注入一次反思→看它会不会真的去查。
这正是 D 研究方向里"防御性语言=调研入口"的最小实现。

## 设置
- R1: 元层习惯 + 检索通道 + 红队任务 (max_tokens 8000, 避开 reasoning 吃配额)
- 检测: 正则扫 R1 输出里的缺口信号句(未验证/无法排除/缺失/待核验/没有验证…)
- R2: 把检出的缺口句喂回 + harness 反思注入("这是元层(b)要处理的未确认前提, 现在去查, 写 [SEARCH]")
- 判据: R2 有没有 [SEARCH:], 且查的内容是否对口(查的是它自己识别的缺口, 不是瞎查)
- 输出: trigger-r1.txt / trigger-r2.txt / trigger-summary.json

## 结果(决定性正)
- R1 (5204字, finish=stop): **不查**(零 SEARCH), 但输出里有 4 处缺口信号, 其中一处="你的实验没有排除这个最平凡的替代假设"(= 没做 length-matched 对照)
- R2 点火后 (112字): **立刻查**, 且查得精准对口:
  `[SEARCH: LLM prompt intervention experiment control arm "length matched" OR "irrelevant text" ablation design]`
  —— 查的正是 R1 自己识别出的那个缺口(缺 length-matched 对照臂), 不是泛泛乱查

## 判决
触发器把"缺口"变成了"查的动作", 而且查的内容对口。完整回路成立:
  习惯(知道该查) × 信息(有通道) × 触发(缺口信号点火) → strategic 层质疑真的发生
- M 线缺的就是触发器这一环, 现在被最小化地做出来了(正则扫缺口句 → harness 反思注入 → 模型自发写 [SEARCH])
- 对照链完整: v4+tool(给通道不点火)=不查; trigger(检测到缺口点火)=立刻查且对口。变量=触发, 结论干净
- 触发信号源 = 模型自己的防御性语言(未验证/无法排除/缺失…), 不需要外部标注, 可在线实时检测

## 对 M 线的落地含义
- "让 27b 像 D 一样思考"的 strategic 层可实现, 路径 = 元层习惯注入 + 检索通道 + 缺口信号触发(harness 层)
- 触发器是 harness 机制(检测防御性语言→注入反思), 不是 prompt 内容 → 归 agent 循环/stop_hook 那一层, 与 T1(stop_hook 反思注入)同构
- 下一步(若 D 要): 把触发器做成 stop_hook 钩子(每轮扫输出缺口句→自动注入反思), 在生产分解循环里测"触发后自发 [SEARCH] 率"作为 strategic 层落地指标
