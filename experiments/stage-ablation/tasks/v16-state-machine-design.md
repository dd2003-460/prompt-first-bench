# v16 状态机臂 — 设计记录（commit 000903f9）

## 定位

v3 plan 分支 B（主赌注）的第一个可运行版本。北极星裁定后的全部重心：
把分解循环做到稳定 —— 状态机 + S_α 停止判据 + 跨域饱和验证。

## 机制（P1e exploratory decomposition loop）

每轮循环：
1. **decompose(整题 + 已确认事实块)** — 前几轮 P2/P3 核验过的节点以
   【已确认事实】注入下一轮 P1 prompt，模型不重复拆它们，只找未覆盖维度继续深挖
2. **gap_check** — 只对新增节点跑广度审查（补 L1/L2 正交维度缺口；无新增则跳过省调用）
3. **一轮 P2/P3 核验** — 本轮新增的 search 节点真实联网核验（每轮 ≤12 个控 wall time）
4. **S_α 计算 + 日志** — harness 侧用与 P1 prompt 同一公式算树形得分，逐轮留痕

**回退是无限的（v16.1）**——没有固定轮数上限。停止判据全部来自边际收益/行为证据：
- **R1 饱和**：本轮**所有层合计**新增节点 = 0（模型找不到新东西可拆 = 定义级粒度自然停）。
  口径是"整棵树"不是"某一层"——某层被限流截断不算饱和，剩余维度下一轮继续消化；
  只有全树都长不出新节点才是真饱和。**这是唯一的硬停止条件之一。**
- **R2 预算阀**：累计节点 ≥ 40 —— **软约束，不停止循环**。超过后在日志里标记
  `compress_triggered=True`（提示该做层级压缩：把深层叶子折叠成中间层摘要），树继续长。
  general 超级工程（如"造一台粒子对撞机"）拆到定义级粒度节点数可达千级，硬上限会砍掉合法深度。
- **R3 停滞**：连续 2 轮 S_α 无增长（新增节点都是同义复述 → 目标函数直接驱动）。
  **这是另一个硬停止条件。**

也就是说真正能停掉循环的只有 R1（零新增）和 R3（S_α 不涨）两个行为信号；
R2 只是提醒"树大了，该考虑压缩了"，不干预生长。

**层内限流（v16.2，commit 3878498a）**：每层每轮最多吸收 `per_layer_cap=6` 个新节点，
超出的留到下一轮。深层同层数量大时（如 L3 一次出 15 个），单轮全吃下会导致 token 溢出
和注意力稀释；截断后下一轮模型看到已确认事实块会继续消化剩余维度。日志里
`capped_layers` 字段标记哪些层被截断了，方便复盘时区分"模型不想拆"和"被限流挡住"。

## 为什么是"回退到 P1"而不是"无限返回"

文献三源共识（RT-RAG depth 4 饱和 / Dissecting 2 轮≈5 轮 95% / Self-Refine 无外部信号失效）
+ T55 发现（"分解深度作为激活度量"无人做过 → pfb 差异化空间）→ 必须有外部化停止信号。
但"有停止信号"≠"设固定轮数上限"：回退本身是无限的，停不停由 R1/R3 的行为证据决定。
R1 就是这个外部化信号：不是问模型"你拆够了吗"（Self-Refine 证明这不可靠），
而是看它**实际产出了几个新节点**——行为证据，不是自我报告；R3 则是目标函数侧的
佐证（S_α 不涨 = 拆出来的东西没有信息增量）。两个信号独立，互为冗余。

## 与旧管线的关系

- `--state-machine` flag 开启新臂（arm=S5-sm），默认关闭，不影响既有 S5 跑法
- 给定/knowledge 节点在最终 P2/P3 阶段直接标 verified（不触发检索，与 search_node 逻辑一致）
- judge 口径不变（binary cov + depth-continuous），与 S0/S5-v15 可比

## 参数审计（每个设置的依据 / 欠债 / 待定）

| 参数 | 当前值 | 依据 | 状态 |
|------|--------|------|------|
| R1 阈值 | 全树零新增 | 定义级粒度的操作化定义；行为证据非自我报告（Self-Refine 先例） | ✅ 有依据 |
| R3 窗口 | 连续 2 轮 S_α 不涨 | 单轮不涨可能是噪声，最小可辨变化需重复观测 | ✅ 有依据（统计直觉） |
| per_layer_cap | 6/轮/层 | 防 token 溢出 + 注意力稀释；粗估每节点 ~300 token，6×300=1800 < 单轮 prompt 预算 | ⚠️ 待实测验证（应测模型在多少节点后分解质量开始掉） |
| budget_nodes (R2) | 40 → 软约束 | 原意是 smoke 控时长，非设计边界；改为压缩触发信号后，合理值 = S_α 增长曲线拐点 | ⚠️ 欠债，等 smoke 数据定拐点 |
| 每轮核验上限 | 12 search 节点 | wall time 控制（~1-2 min/轮）；并行化后可放大 | ⚠️ 工程约束，非算法选择 |
| max_rounds | 8（已失效） | v16.1 无限回退后仅防御性兜底，实际停止由 R1/R3 决定 | ✅ 无影响 |

**原则**：任何参数如果没有推导过程就是欠债。有依据的写清楚逻辑链；缺数据的标"待 X 实验验证"，不假装确定。

## 已知限制（下轮修）

1. 每轮 decompose 重发整题 → token 成本 ∝ 轮数×树大小；后续改增量式（只喂上轮叶子）
2. gap_check 每轮都跑一遍 A+B 两次调用 → 可只在 R1 未触发时跑
3. 已确认事实块目前最多注入 24 条截断 → 大树场景会丢早期节点
4. 停止判据还没接 S_α 边际增量（当前 R1 用新增节点数近似）→ 下一步改成 ΔS_α < ε
5. **v16.3 遗留 bug（2026-11-09 smoke 发现）**：`decompose_explore(max_rounds=8)` 参数声明后从未使用——R2 改软约束后循环真的无限了，只靠 R1/R3 停。gpu 域 R1 迟迟不触发（每轮还能拆出几个新节点），单 rep 预计 >1h，smoke 不可行。修法：把 max_rounds 恢复为**防御性硬上限**（默认 8 轮），与 budget_nodes 的 compress_flag 并存——R2 管"该压缩了"，max_rounds 管"别失控"。两者语义正交，不冲突。[待核验] 修后 gpu 单 rep wall 是否 <30min
