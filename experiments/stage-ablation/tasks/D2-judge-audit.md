# D2: S0-gpu 低分 rep judge 打分合理性核查

**日期**: 2026-11-09 · **方法**: 逐点统计 gold 覆盖 + 人工核 reason（全部来自本轮工具输出）

## 结论先行

S0-gpu cov 均值 0.167（n=10）**不是 judge 过严，是 S0 单 pass 确实答不出 gpu 题的硬要点**。judge 打分本身合理：covered 点的 reason 具体且与答案内容对得上；未覆盖的点确实是答案里不存在的内容。

## 证据

### 1. gold 15 点的覆盖分布（n=10 个 S0-gpu prod run）

| 点 | 覆盖数 | 内容 |
|---|---|---|
| pt15 来源标注+条件性推荐 | **10/10** | 元认知层，所有 run 都做到了 |
| pt5 KV cache 估算 | 4/10 | 有公式有数值即算覆盖 |
| pt8 电费独立计算 | 4/10 | |
| pt14 SHARED 参数交互 | 4/10 | |
| pt3 INT8 权重装载 | 1/10 | |
| pt4 prefill/decode 瓶颈分离 | 2/10 | |
| **pt1,2,6,7,9,10,11,12,13** | **0/10** | 见下 |

9 个点全军覆没。这些点分两类：

- **需要外部市场数据**（pt12 价格波动 $4,599→$16,000、pt13 云租阈值 $0.22–0.50/h）——单 pass 不联网查价确实给不出
- **需要完整推导链**（pt1 四卡 VRAM 门槛表、pt2 roofline 具体数值、pt7 TCO 完整公式、pt11 并发双闸分析）——单 pass 时间预算内推不完

### 2. covered 点的 reason 质量抽查（r1/r2/r3/r4/r10）

reason 都指向答案里的具体内容（"提供了 KV 估算公式和数值 ~6GB"、"独立计算了不同方案的电费"），没有发现放水或误判。pt15 满分是因为 prompt 本身就要求标 [待核验]，属于格式合规项，不算 judge 偏松。

### 3. 口径结论

- **gpu 线的 cov 数字可信**，不需要重算口径
- 但 0.167 这个基线偏低意味着：**goal 里 "gpu depth≥0.50" 用的是 depth_score（k·ln(k+1) 加权连续分），不是 cov**——cov 在 gpu 域天花板本来就低（单 pass 最多到 0.3-0.4），depth 才是 v16 状态机能拉开差距的指标
- v16.0 smoke gpu depth=0.343（R2 硬上限砍断时），v16.3 放开后目标 ≥0.50，空间存在但要看 R1/R3 自然停止点

## 对 nat 线的附带发现（顺手核的）

v16 smoke nat cov 0.667 vs S0 0.634 的 +0.033，per-point 看：两个 rep 丢的都是 pt3（LFU 频率表老化）和 pt5（驻留时间 100 天推导），而 S5-nat prod (n=100) 这两个点也只有 28% / 14% 覆盖。**v16 的提升主要发生在 pt1/pt2/pt4（基础推导点），弱项没动**——方向对但幅度小，n=2 功效不足，等 v16.3 全量再下结论。
