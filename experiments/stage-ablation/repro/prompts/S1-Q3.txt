[阶段 01 — 目标分解]
## 五步方法（在 01 阶段工件中逐项落地）

### 1. 先定根标量

把「最划算 / 最快 / 最优」翻译成**唯一无歧义的可排序标量**（如 tokens/s/GPU、¢/1k_acc），写出公式和单位。

- 落点：01 工件的「目标」字段必须含这个标量定义，而不是自然语言形容词。
- 判据：两个候选对象代入公式后能排出序，且不存在第二个可争议的主标量。

### 2. 正交维度切分

第一层按**正交维度**拆，不是按现象罗列。

- 每两个维度必须能指出各自的**独占参数**（只影响这一维的参数）。
- 若某参数同时影响多个维度（SHARED 耦合），单独列一节显式记录它走哪几条路径。
- 与 01 主文件的「因素正交」判定原则一致，本条是其操作化版本：说不清独占参数 = 没拆干净，继续切或显式写耦合。

### 3. 黑盒收口表

所有无法闭式求解的项，编号 B1–Bn，每个黑盒给**四样东西**：

| 字段 | 说明 |
|------|------|
| 为什么没有闭式 | 缺什么信息 / 依赖什么未决条件 |
| 估计区间 | 给区间不给单点（如 0.5–0.8，不写 0.65） |
| 一天内能做完的测法 | 具体动作 + 数据来源，写成阶段 02 可直接执行的条目 |
| 弹性（高/中/低） | 它变动时结论会不会翻转；高弹性 = 优先研究 |

只写「这个要实测」不算收口，Reviewer 应打回。黑盒表整体就是 01 空缺清单的结构化形态，二者一一对应，不得各写一套。

### 4. 口径声明

- **约束类维度**（不满足直接划掉候选）与**成本类维度**（进公式）分开标注，不能混在一个池子里比权重。
- 落点：01 工件的因素列表每项标 `[约束]` 或 `[成本]`（或 `[其他]` + 理由）。

### 5. 瓶颈识别

最后指出哪个因素是主导项，并用**弹性或量级论证**，而不是只说「都很重要」。

- 判据：删掉这个因素后结论会翻转（对应黑盒表里的「高弹性」项，或约束类里一票否决项）。
- 说不出主导项 = 分解未完成，回到第 2 步重切。


【待解问题】
你是一个逻辑严密的拆解者。面对一个复杂问题，不要凭直觉直接列清单，要像整理文件夹一样，一层一层往下分，最后交出一棵树。

把整个问题先定成一个要算清楚的「根节点」——通常是一个数（比如「哪种方案最划算」，就拆成「每个方案的单任务成本」）。然后一层层往下切，每一层都把这个节点切成几个子文件夹。一直切到每一片「叶子」都是一个你要么能查到规格、要么能套公式、要么能实测出来的具体数字或区间为止。

**怎么拆都行**：你可以一次只拆一层（先列直接子节点，下一轮再往下），也可以一口气拆好几层，随你方便。拆的过程中随时可以停下来想一想、自检、再继续——不要求一次拆完，每次挑几个还没拆完的节点往下切就行。

下面用「一条产线每件产品的成本」做例子，照这个样子长（先骨架，再填几片叶子）：

    单件成本/
    ├── 良率/        〔只能测〕每批抽 200 件记不良，连续 10 批    〔占 0.30〕
    ├── 设备摊销/    〔可调〕按折旧摊到每件                  〔占 0.45〕
    └── 来料价格/    〔可控外〕随采购合同                    〔占 0.25〕

每一刀只当场验两件事：

1. **完整（不漏）**：切出来的几支拼起来要能还原父节点，不能丢掉任何一块。按比例拆时比例加起来必须正好等于 1。拼不回来说明这一刀切错了，不是「还有点没想到」。

2. **不重叠（不抢）**：同一层的几支不能去动同一个底层东西。两支都在占显存、都在花同一笔钱、都在改同一个参数，就是没拆干净——要么继续往下切分开，要么显式写一句「这两支耦合在 X 上」并说明会不会改变结论。名字不一样不代表不重叠，是「不抢同一个底层资源」才叫不重叠。

查不到也量不出来的，别硬编：标成「黑盒」，写清它影响树的哪一支、你估计的大致范围（给区间不给一个数）、以及真要搞准的话一天内能做完的实测办法。

最后，指出哪一支对整个结果影响最大（瓶颈），说清楚为什么是它；并列出还有哪些没解开的矛盾（没有就写「无」）。

你最终交出来的，就是上面那样的一棵**「文件夹结构示意图」**——根在上、子节点往下/往右展开，每个节点旁标清「是什么 / 能调还是只能测 / 怎么量 / 占父份额」。这棵树只作为格式看，真正评分看的是你拆得全不全、重不重、瓶颈抓得准不准、黑盒标得老不老实。
