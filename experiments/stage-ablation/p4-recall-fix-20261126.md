# P4 口径召回修复设计（nat gold 要点 5：树有 verified 节点但 P4 没引用）

## §1 P4 节点选择机制

nat 的 P4 走 **SM 路径** `s5_state_machine.py::synthesize_answer`（L1598-1669），不是 `s5_pipeline.py` 的 P4（L284/L1244，仅非 SM 管线用）。机制 = **无显式选择，两步隐式丢失**：
1. **分层全量拼接 + LLM 压缩**（L1602-1633）：278 节点按 level 分组（L1=5/L2=23/L3=71/L4=179），每层全量拼成 seg 喂 per-layer LLM（`max_tokens=4000`），由模型自行决定摘要保留哪些节点——这是第一道"选择"，纯注意力/位置驱动，无 score（所有节点 `score=null`）。
2. **截断**（L1615-1618，commit `8975685d6` 2026-11-17 加入）：seg>12000 时保头 8000 + 保尾 4000，中段丢弃。L4 seg=46643 字符 → 丢 132/179 节点。
3. **merge**（L1635-1652）：各层摘要（非原始节点）合并成最终答案，`max_tokens=8000`。
注意：synth.json（2026-11-16T05:52）生成时截断尚不存在（当时代码 `0d00fb95c` 全量 seg 进 per-layer prompt）；口径分离硬约束（L1625-1629/L1645-1649，`26122880d` 2026-11-26）也晚于该文件。

## §2 N247 丢失原因（一行 + 证据）

**N247 丢失 = 位置驱动的 LLM 压缩丢失（生成时）+ 截断结构性丢弃（现状），非 score/层级/状态筛选**——6 节点 status 全 `verified`、score 全 `null`（N17=L2，其余=L4），无字段级差异；N247 位于 L4 seg 第 36685/46643 字符（~79% 处），per-layer LLM 以 4000-token 输出压缩 46K 字符时未把它带进摘要（答案引用了同在 L4 中段的 N182/N193/N260 却独漏 N247，说明是选择性遗忘而非整段不可见）；且按当前代码 N247 落在中段（head<8000，tail 起点 42643）→ 截断直接丢弃，N262/N182/N193/N260 同样在中段——现状下 5 个 L4 目标节点全部进不了 prompt。

## §3 候选修复

**候选 A：P4 prompt 注入「口径覆盖清单」（prompt 级，推荐方向）**
- 改法：`synthesize_answer` 内新增 ~15 行 helper：遍历 `status==verified` 节点，regex 抓数值口径（`数字+单位`、`1/x=天数`、公式片段如 `1-exp(-λT)`），按量级去重，生成 ≤20 行的清单（每行 `Nid: 口径原文片段`）；追加到 **merge prompt**（L1635 起）与 per-layer prompt 尾部，要求「对清单每条口径：采用（引用 Nid）或显式说明为何不用，不得静默丢弃」。
- 为什么治本：清单直接从**树**抽取（不经 per-layer LLM），N247 即使被截断/遗忘，其「u=1%/天→100 天/对象」口径仍强制出现在 merge 上下文；merge LLM 必须表态。
- 代价：不改节点选择/截断逻辑，不增 LLM 调用；清单本身 ≤20 行，prompt 膨胀 <500 token。

**候选 B：P4 前「口径召回」预处理 + 截断保口径节点**
- 改法：同 A 的 regex 抽取，但把命中口径的 verified 节点**整条 claim 强制追加到截断保留区**（L1615-1618 的 tail 之后），保证它们完整进入 per-layer prompt；merge prompt 同 A 加覆盖检查。
- 优点：per-layer 摘要源头就有 100 天口径，不只靠 merge 兜底。
- 代价：改截断逻辑（L1615-1618），保留区可能膨胀（L4 命中口径节点可能 10+ 条，需限长）；两处改动 vs A 一处。

## §4 推荐

**选 A**：改动最小（1 个 helper + 1 处 prompt 拼接，全在 `synthesize_answer` 内，~20 行），不触碰截断与节点选择现有行为，且清单源自树而非 LLM 摘要——对「压缩遗忘」和「截断丢弃」两种丢失机制都免疫；B 的截断改造可作后续独立小修（同一 helper 复用），不必耦合进本次。

## §5 验证方案

- **最小探针**：`python3 synth_only.py runs-s5-sm-nat.json nat`（现成工具，复用现有树，不重跑 SM）。
- **通过判据**：① 答案出现「100 天」口径或引用 N247；② judge 要点 5 由 0→1（coverage ≥ 0.833）；③ 要点 1/2/4/6 不回退（仍为 1）；④ 答案未新增幻觉数值（对照树内口径清单抽查）。
