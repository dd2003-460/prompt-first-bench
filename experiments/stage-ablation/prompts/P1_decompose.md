# P1_DECOMPOSE — 分解 prompt（基线）

你是严谨的研究员。下面是一道待解问题。你的任务不是回答问题本身，而是把它逐层拆解成回答所依赖的完整决策树。

【节点来源标记 source（每个节点必填）】
- given: 题目文本中直接给出的数值或条件；
- knowledge: 你已掌握且属于常识/稳定事实的内容（学科定义、经典公式、架构参数等），不需要联网查证即可确认；
- search: 完全不知道、必须检索才能确认的事实（实时数据、最新规格、具体参数等）。
原则：能用 given/knowledge 覆盖的不要标 search——只有真正查不到的才需要检索。knowledge 节点的 claim 里要写出具体数值或公式，并在 evidence 栏注明「模型先验知识，属常识级事实」。若该数值有时效性风险，claim 末尾加「[时效待核]」。
不确定具体数字时不要犹豫、也不要降级成定性描述：用符号变量替代（例如 ρ, L, u），把公式完整写出来——一个带变量的可计算表达式比一句定性判断有价值得多。变量在最终答案里保留为参数即可，不需要解出具体数值。

【分解目标（终点导向，非公式打分）】你的分解树服务于一个明确终点：让最终答案能『完整、详尽、准确地』回答题目所问的决策——即给出在不同时间尺度（即时 / 短期运营 / 长期持有）下性价比最优的选择，以及支撑该选择的量化依据。
分解质量的判据全部由这个终点导出：(a) 覆盖——答案要用的每个时间尺度、每种对比口径、每个约束条件，树上必须有节点承载；(b) 具体——每个承载节点必须落到可直接检索/计算的事实（数字、公式、阈值），定性描述不算承载；(c) 正交——兄弟节点不得同义复述，也不得把同一维度的不同参数值伪装成多个维度；(d) 经济——一个节点若其数值在最终答案中不会被代入或引用，它就不值得存在。
机器侧另有独立评分（结构+冗余惩罚）用于监控树的健康度并决定何时停止，但你不需要也无法自己计算它——你只需按上述四条终点判据工作；评分器的角色是防止你过度扩张，而不是给你刷分目标。

【检索策略】外部检索不限次数（source=search 的节点都会真实联网核验，given/knowledge 不触发检索）。终点判据 (a)(b) 依赖真实数据：把每个答案必需、且只有外部来源才能确认的 search 节点都查到位——宁可多查，不可漏查；但只为答案用得到的事实花检索预算。给定/知识类节点直接写具体数值或符号变量公式，不要浪费在它们身上。
预算不足时的取舍顺序：先保证所有 L1 正交维度都有节点（覆盖度），再把剩余预算按「展开增益/预算成本」从高到低分配给最深的未展开定义式节点。

【逐层展开规则】
1. 先识别顶层决策公式或目标函数（如成本公式、约束条件、评分标准），这是第 1 层；
2. 对第 1 层的每个因子/参数，展开为第 2 层子节点——具体到需要查什么数字、什么公式、什么经验值；
3. 对第 2 层中涉及复合量或可分解量的节点，继续展开为第 3 层（如 TCO → 摊销+电费+故障损耗；吞吐量 → prefill 算力瓶颈 + decode 带宽瓶颈）；
4. 如果某节点的取值会影响其他节点的判断（交互效应），单独列出 SHARED 节点说明耦合关系；
5. 不要停在'这个因素很重要'——必须拆到可以直接检索验证的具体事实（一个数字、一个公式、一个阈值）；
6. 复合概念展开：当问题中出现由多个正交维度构成的复合词（即该词的取值取决于两个或以上独立因子的组合），必须将其展开为各构成因子作为同级子节点，不得将复合词作为单一叶子节点保留。判断标准：如果你能用「X = f(A, B)」的形式写出该概念的定义式，则 A 和 B 必须是独立分支；
7. 定义式必须展开到可计算项：如果某节点的 claim 是一个定义式（X = A + B + C），则每个组成项必须有对应的 L3 子节点给出其计算公式（未知数值可用符号变量表示）或具体数值来源。停在'X 包含 A、B、C'而不拆出 A/B/C 各自的计算方式 = 未完成分解。
8. 子问全覆盖：问题文本中显式列出的每个子问（如 (a)(b)(c)）必须在 L1 层有至少一个节点直接支撑它。如果某个子问要求区分多种口径/度量（例如同时问『按字节』和『按请求』），则必须为每种口径各建一个独立节点，不得合并为一个节点。

9. 定量承诺：每个节点的 claim 必须携带具体数值、公式或可计算的表达式——不允许纯定性表述（如『显著』『有限』『较高』）。若某事实确实只有定性结论，claim 末尾标 [待核验] 并给出最接近的量化形式（变量/参数化公式）。原因：P4 综合时只能把 fact table 里的具体数字写进答案；定性节点 = 答案里少一个数字 = 覆盖率掉一个点。

分布参数必须实例化：涉及幂律/Zipf/Pareto 等分布时，不能只写『长尾分布』——必须给出具体参数值或假设区间（如 α∈[0.8, 1.2]、β=0.9±0.1），并算出至少一个可检验的推论（如 top 10% 对象贡献 ≥85% 请求量）。没有参数值的分布描述 = 不可计算 = P4 无法代入。

【展开深度与停止条件（由目标函数决定，不设固定节点数上限）】
不要预设节点总数。判断标准只有一个：对树上每个非叶子候选位置问——「再往下展开一层，能否产生新的具体数值、公式或可检索事实？」能 → 必须展开；不能（只剩定性描述或同义复述）→ 停。
停止条件（三个方向都要判）：向下——若某节点已是最小可计算单元（单个不可再分的数值或公式），它的任何子节点都不增加信息量，停；横向同层——若新增兄弟节点只是同义复述或边缘案例，停；横向跨层——若某个答案必需的正交维度在浅层还没有节点（覆盖缺口），必须补上而不是只顾深挖。除此之外默认继续拆：每个新节点都解锁自己的子树，且终点答案尚未被完全承载时不收树。
禁止为了控制篇幅而提前收树；也禁止硬拆无信息量的子项凑深度（那会稀释 kₙ 的有效性且不增加答案内容）。
【排除/筛选类结论的强制继续规则】任何「X 不可行 / X 被排除 / 本题无解」这类判定，只能作为树的中间层或某个分支的叶子，不能作为整棵树的终点。做出排除之后必须立即追问并展开：(a) 放宽哪个前提后 X 变为可行？(b) 放宽的代价是什么（量化到可计算的程度）？(c) 在放宽后的可行集里，原问题的目标函数如何重新排序？——这三问各自至少产生一个节点。原因：排除本身不回答问题，回答问题是「在什么条件下、以什么代价、选哪个」；只给排除不给后续 = 把最便宜的浅树当成了完整答案。

【示例：什么是'每个分支都挖到最深'——只展示结构，不展示任何领域内容】
例1（某子树，3层×2-3节点）：
  N5: <某个可分解的复合概念> (L1)
    N6: <组成部分A> = f(参数a, 参数b, 参数c) (L2)
      N7: 实例X: f(a_X, b_X, c_X) ≈ v_X [已核验] (L3)
      N8: 实例Y: f(a_Y, b_Y, c_Y) ≈ v_Y [已核验] (L3)
    N9: <组成部分B> = g(参数d, 参数e) (L2)
      N10: 实例X: d_x × e_x = w_x [推导] (L3)
结构要点：N5 不是叶子——它下面有 ≥2 个 L2 分支，每个 L2 又展开到 L3 的具体数值。如果停在 N5 就收手，这棵树就废了。深度和广度都有收益：多一层 ∝ n 的贡献，多一个节点 ∝ ln(kₙ) 的贡献。

例2（排除结论后继续分解）：
  N12: <方案P>在约束C下不可行 (L1) ← 排除结论，不能停在这里
    N13: 放宽哪个前提后 P 变为可行？(L2)
      N14: 放宽代价 = h(新约束) ≈ 具体量 [待核验] (L3)
      N15: 放宽后的质量/性能损失 ≈ d% [待核验] (L3)
    N16: 放宽的代价是什么（量化）(L2)
      N17: 哪些候选支持新约束，哪些不支持 (L3)
    N18: 放宽后目标函数重新排序 → 新的最优解 (L2)
结构要点：N12 是排除结论，但它下面挂了 3 个 L2 分支，每个都挖到了 L3。排除本身不回答问题，回答问题是「在什么条件下、以什么代价、选哪个」。

注意：以上两个例子中的尖括号内容都是占位符，你需要根据实际问题填入自己的节点。例子只告诉你树应该长什么样（几层、每层几个节点、叶子长什么样），不告诉你应该拆什么。

【格式要求】
每个节点给：编号（N1, N2, ...）、一句话陈述（具体到可检索的事实）、层级标记（L1/L2/L3）、它支撑问题的哪个子问、来源标记 source（given|knowledge|search）、一条英文检索词（具体到该事实本身；source=given/knowledge 时可为空字符串）。
只输出 JSON，格式：{{"nodes": [{{"id": "N1", "claim": "...", "level": "L1", "source": "given|knowledge|search", "supports": "a", "search_query": "english query"}}, ...]}}
