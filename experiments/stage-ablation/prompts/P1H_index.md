# P1H_INDEX — 逐层 INDEX 分解 prompt（基线）

你是严谨的研究员。下面是一道待解问题，正在被逐层分解成一棵目录树（结构同项目标准：每个父节点是一个文件夹，它的子节点清单就是该文件夹的 INDEX.md——只列条目和一句话说明，不抄内容；每层的 INDEX 只描述下一层有哪些条目）。

【最终用途锚定】这棵树不是目的，它是回答问题的原材料：树的终点必须能支撑一份『完整、详尽、准确』的最终答案——即对题目所问的决策/结论，给出在不同时间尺度（即时 / 短期运营 / 长期持有）下的最优选择及其量化依据。因此分解时始终朝这个终点服务：一个子维度如果最终答案里用不到它的具体数值或判断，它就不值得存在；反之，答案要覆盖的时间尺度和对比口径，树上必须有对应节点承载。这是通用判据，适用于任何题目类型。

【本轮任务】只对给定的这些父节点做分解：对每个父节点，列出它的全部正交子维度作为子节点（即写出这个父节点文件夹的 INDEX）。不要碰其他分支，不要重复已确认事实里的内容。

【子节点规则】
1. 每个子节点必须携带具体数值、公式或可计算表达式——不允许纯定性表述；确实只有定性结论的标 [待核验] 并给出最接近的量化形式。
2. 复合概念展开：若某子维度能写成 X = f(A, B)，则 A、B 必须是独立兄弟节点，不得合并。
3. 定义式必须展开到可计算项：父节点是 X = A + B + C 时，A/B/C 各自必须有子节点给出计算方式。
4. 子问全覆盖：问题文本显式列出的每个子问必须在 L1 有节点支撑；要求区分口径时为每种口径各建一个节点。
5. 排除/筛选类结论不能当终点：「X 不可行」之后必须继续展开（放宽哪个前提/代价多少/重新排序），三问各至少一个节点。
6. 正交性：同一父节点下的兄弟节点之间不得互相包含或同义复述；宁缺毋滥，但真正正交的维度不得漏。
7. 深度判据（通用）：对每个叶子节点问——『一个该领域的专家看到这条 claim，会不会说'这还不够具体，还差一层'？』会 → 继续拆；不会（已是可直接检索/计算的最小事实单元）→ 停。判断标准是信息粒度而非主题：任何领域都有'表面描述 vs 一手机制参数'的层次差，停在表面描述层 = 分解未完成。此判据对所有题目类型成立，不依赖具体领域知识。
8. 反参数展开（防 Goodhart）：把同一公式/同一信息维度套到 N 个不同实例上（如'实例A的X''实例B的X''实例C的X'各一个节点）不算深度——这是宽度伪装成深度，信息量只有一行参数表。合法的下层展开必须引入父节点没有的新信息维度：机制解释（为什么是这个值/什么约束导致）、交互效应（两个参数怎么耦合影响结果）、边界条件（什么情况下公式失效/需要修正项）。对比类题目：每个实例独立用同一套估计框架，修正项/约束项才是深度，不是把每个实例的参数各列一行。

【何时停】逐条判，不是整批判：对本轮要分解的每个父节点单独问——再往下拆一层还能产生新的具体数值/公式/可检索事实吗？能 → 必须拆；不能（只剩同义复述或定性描述）→ 仅该父节点本轮不产生子节点，其他父节点照常输出。全部父节点都停 → 才允许输出空 nodes。禁止因为多数父节点已饱和就跳过仍有展开空间的少数父节点。

【硬停门禁（违反即整轮作废）】满足以下任一条的父节点，本轮必须产出至少 1 个子节点，不得以'已足够具体'为由停止：
(a) 其 claim 含定义式 X = f(A, B) 或 X = A + B + C，但 A/B/C 尚无对应子节点；
(b) 其 claim 含待填参数（[待核验]、[时效待核]、符号变量未实例化），且该参数存在可检索的一手来源；
(c) 其层级 ≤ L2 且 claim 仍是类别级描述（如'对比 X 与 Y''分析 Z 的影响'），未落到具体数值/公式/阈值。
只有三条都不满足的父节点才允许停。宁可多产 1-2 个窄子节点，也不要在门禁命中时收树。

【节点来源标记 source（必填）】given=题面直接给出 / knowledge=常识级稳定事实（claim 里写具体数值或公式，evidence 注明「模型先验知识」，有时效风险加 [时效待核]）/ search=必须联网查证的事实。能用 given/knowledge 覆盖的不要标 search。

【格式】每个节点：编号 N{start} 起连续、claim（一句话，具体到可检索）、level（比父节点深 1 层）、source、supports（支撑哪个子问）、search_query（英文检索词；given/knowledge 可为空）。
只输出 JSON：{{"nodes": [{{"id": "N{start}", "claim": "...", "level": "L2", "source": "knowledge", "supports": "b", "search_query": ""}}, ...]}}
