# T35 S8E Pilot 结果（2026-11-06）

## 实验设计
S8E = S7F prompt + 内嵌 claim-verification 指令（单 pass，一次 LLM 调用）。
对比 S7V（两 pass：生成→验证→修正）和 S7（无验证）。

假设：嵌入验证规则可恢复 S7V 的 M1 增益，省掉第二次 API 调用。

## 执行
- 模型: qwen3.8-27b (vLLM, temp=1)
- Q1 × 2 reps + Q4 × 2 reps = 4 runs
- 脚本: `s8e_pilot.py`（独立于 ablation_harness）

## 结果

| Arm | Q1 M1 (mean) | Q4 M1 (mean) | Q1 M4 | Q4 M4 | 总 wall_s |
|-----|-------------|-------------|-------|-------|-----------|
| S7 (n=15) | 0.67 | 0.53 | 0.83 | 0.83 | — |
| S7V (n=15) | **0.79** | **0.75** | 0.50 | 0.50 | ~45s/run |
| **S8E (n=2)** | 0.67 | 0.38 | 0.50 | 0.50 | ~15-20s/run |

### 逐 run 明细
| Run | M1 (hit/total) | M4 (hit/total) | URL valid |
|-----|---------------|---------------|-----------|
| S8E-Q1-r1 | 4/8 | 2/4 | 2/3 |
| S8E-Q1-r2 | 4/6 | 2/4 | 2/3 |
| S8E-Q4-r1 | 0/1 | 2/5 | 3/3 |
| S8E-Q4-r2 | 3/4 | 1/5 | 3/3 |

## 结论

**S8E 假设被否定。** 内嵌验证指令没有恢复 S7V 的 M1 增益：
- Q1 M1: S8E=0.67 = S7=0.67 < S7V=0.79（无增益）
- Q4 M1: S8E=0.38 < S7=0.53 < S7V=0.75（反而更差）

**解释**：单 pass 内"边写边验"的认知负荷过大。模型在生成时同时做内容组织 + 来源核对 + 标注格式，注意力分散导致断言质量下降。两 pass 的分离（先专注生成，再专注验证）是必要的认知架构，不能压缩到一步。

**代价对比**：S8E 省了 ~50% 推理时间（15s vs 45s），但 M1 损失 0.12-0.37。性价比为负。
