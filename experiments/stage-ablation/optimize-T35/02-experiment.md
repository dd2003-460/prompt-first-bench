# 02 · 实验（T35 阶段 B）

> 对应 1-loop 04 执行验证。执行通道：本地降级（不外包 arena），conf 标 0.2，loop 不豁免。
> 所有新文件仅在 `optimize-T35/` 下；未修改任何已有文件。
> 术语直白定义：**单次生成** = 只调用模型一次就出最终答案（S8E）；**两遍调用 / Pass2** = 先出初稿、再第二次调用模型逐条核验数字（S7V）；**judge** = 给答案打分的模型，本轮是被测的同一个 27B；**gold** = 人工写好的标准答案，judge 拿它当对照；**嵌入** = 把新规则改写进 prompt 原有的句子里，不另起一段。

## 1. S8E 臂定义（嵌入式验证）

**基座来源的发现**：`ablation_harness.py` 的 `build_prompt()` **没有独立的 S7 分支**（第 102-207 行）：S7T/S7F/S7V 三臂共用的是「资深研究员 + 5 条思考方式建议 + 来源说明 + 作答要求」这套骨架（即 S6 风格的模糊启发式 + 来源段，第 135-171 行）。paper §3.2 描述的 "S7 hybrid ~2.6k chars" 在 harness 里并不存在独立实现。因此本轮的「S7 既有节点」按 T30–T32 实际落盘产物定义为：

- 节点 1–5：5 条「思考方式建议」bullet；
- 节点 6：`【工具说明】` 段；
- 节点 7：结尾「请基于以上来源回答…」作答要求。

**S8E = 上述骨架 + 4 处「嵌入式」改写**（依据 T34 负面结果：新增规则必须嵌入既有节点，不能挂独立段落/附录）：

| # | 既有节点 | 嵌入内容 |
|---|---|---|
| 1 | 第 4 条 bullet（数字/标称值） | 末尾追加「写下的每个数字都要能在下面来源里找到支持它的原句，找不到就只做定性描述、不写这个数字」 |
| 2 | 第 5 条 bullet（缺口/不编） | 扩展为「凡是写下数字断言，必须紧跟其后标注它所依据的来源原句…来源里没有对应原句的数字一律不写」 |
| 3 | `【工具说明】` 段 | 段内追加「每条含数字的断言都要能指回这里的某条来源原句」 |
| 4 | 结尾作答要求 | 段内追加「每条数字断言后面紧跟其来源原句，无来源原句支撑的数字改为定性描述或不写」 |

**明确没有做的事**：不新增任何独立段落、不追加附录、不调用第二次（Pass2）、不联网检索。
**来源**：离线读取对应 `runs/S7V-Q{q}-r{rep}.json` 的 `sources` 字段，用 harness 的 `inject_sources_into_prompt()` 注入 → S8E 与 S7V 使用**完全同一批来源**，唯一变量是「验证规则实现方式 + 调用次数（1 vs 2）」。S7 为无来源基线，只作方向参照。

## 7. 口径声明（避免与 paper 表格混用）

3. M6 为 `score.py` 的 URL 存活检查口径；本轮不联网检索（只读取已有 JSON 的来源），S8E 与 S7V 同来源 → M6 相等是受控设计的结果。
4. M7（`score_m7.py`）不在本轮 total 内，用户本轮未要求。
