- 口径：以 `score.py::judge_m1` / `judge_m4` 的定义为准；Gold 为 `gold/Q1.md`–`Q5.md`。M1 = match / (match + mismatch)，undecidable 不进分母；M4 = 明确识别的 Gold 黑盒数 / Gold 黑盒总数。
- 输入校验：30 个 run 均可解析且输出长度 >100 字符；五份 pack 内 Gold 与磁盘 Gold 完全相同。
- 重复性：同一 arm × question 的 r1/r2/r3 `output_text` 逐字相同（SHA-256 核验）。因此先判 10 份唯一输出，再将相同分数复制到 30 行；三份重复不代表独立生成或独立判分。

## 差异分析

- 异源 M1/M4 的 arm 平均值：S6 M1=0.643、M4=0.610；S7 M1=0.761、M4=0.650。
- 相对本地 27B 总分，异源 judge 不支持把总体总分简单解读为 M1/M4 的替代值：Q4 两臂均因把 Gold 的 500 万 token 规模写成约 1.5–2.5 亿 token 而在 M1 受到明确扣分；S7-Q3 对 KV cache“指数级增长”的说法未获 Gold 中明确公式支持，故作为不可判定项处理，而非外部事实核查结论。
- M4 方面，S7-Q4 的覆盖较好（4/5），识别检索召回、长上下文定位、幻觉/正确率和业务量等验证项；S6-Q3 覆盖 2/4 个框架黑盒。短板集中在 S6-Q2（2/5）以及 Q2/Q3 中未明确识别 p99/维护风险、KV 碎片实测或利用率 breakeven 的输出。
- 总分对照仅作背景：本地 27B 报告均值 S6=0.462、S7=0.559；此次只评 M1/M4，且重复文本完全相同，不能推断为 30 个独立生成样本的显著差异。
