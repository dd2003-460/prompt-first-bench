## 3. 与本地 judge 的系统性分歧（本任务最重要的发现）

**Pearson(local, arena) = 0.105，Spearman = 0.188，mean |Δ| = 0.277。** 这不是"高度一致"，是**基本不相关**。

分歧集中在两类 cell：

**(a) local 打 0.00、Arena 打 0.71–0.93 的整簇（8 条，全部在 Q4，另加 S5-Q2-r3）**

| tag | local | arena |
|---|---|---|
| S2-Q4-r1 / r3 | 0.00 | 0.92 / 0.93 |
| S4-Q4-r1 | 0.00 | 0.92 |
| S5-Q4-r1 | 0.00 | 0.92 |
| S5-Q2-r3 | 0.00 | 0.92 |
| S0-Q4-r1 / r2 / r3 | 0.00 | 0.81 / 0.83 / 0.83 |

**归因**：这些答案的共同点是"目标分解式作答"——大量篇幅是维度切分、正交性检验、空缺清单，可核事实只有若干条推算（如 `50万页×500token≈2.5亿token`、`2×24GB=48GB`、`128K≈256 页`）。本地 judge 显然套用了 JUDGE_PROMPT 的兜底条款「没有可验证的事实断言（纯方法论/空话）→ M1=0」，把这类作答整条归零；本通道则把其中**可复算的推算**当作可核断言逐条比对。**同一份 prompt，对"什么是事实断言"的理解不同，产生了 0.9 的落差。**

**(b) 反向：local 高、Arena 低的少数 cell**（如 S0-Q2-r1 local 1.00 / arena 0.88，S3-Q2-r2 local 0.90 / arena 0.93 基本持平）——这类是 local 对"结构完整、数字对"的作答给满分，而本通道仍扣了 1-2 条无依据的旁支数字。

**给 Lead 的直接结论**：把这 90 对直接丢进 κ 计算会得到一个"接近随机"的 κ（Spearman 0.19），但**这个低值主要反映的是两个 judge 对"断言粒度"与"零断言兜底"的规则分歧，而不是对同一事实判断的真分歧**。建议先做口径对齐（二选一）：
- ① 统一"零事实断言 → M1=0"的触发条件（把 Q4/Q5 这类方法论题显式纳入或显式排除）；
- ② 统一断言粒度（建议以 Perplexity 的 13–40 条原子断言为基准重打一遍，或把本地 judge 重跑为"关键断言级"）。

未做对齐前，**不建议**用本回执的分直接下"方法 A 的任务质量优于 B"的结论。

## 4. 本通道的判分口径（与任务书 JUDGE_PROMPT 的偏差披露）

严格遵循下列四条，未增删：

1. 逐条检查关键事实断言（数字、规格、结论）→ **本通道取"关键断言级"，单 cell 4–12 条**；不做 Perplexity 那种逐句原子化去重（13–40 条）。
2. 正确=1，部分正确=0.5，错误/无依据=0。
3. `M1 = 正确断言数 / 总断言数`（`claims_correct` 允许出现 .5）。
4. 纯方法论/无事实断言 → M1=0 + `no_factual_claims` 标注：**90 条中无一触发**（每份作答都至少含可核的规格/算式）。

另外两条实际执行时的取舍，需向 Lead 明示：
- **"无依据"的判法**：凡 gold 未给出、且无法从题面或公开规格推出的具体数值（如"vLLM 150 tok/s vs TGI 80 tok/s""70B 单卡 15 tok/s""期刊 30-70% 要求 p 值"），一律不计正确，按 0 或 0.5 计。这是 Arena 分数普遍高于 local 的主要来源之一（local 对"合理范围估计"更宽容）。
- **问句前提错位的处理**：Q3 题面明确给了 `RTX 3090×4 / 96GB`，但 S0/S2/S3/S4 的多数作答改用 `A100-80GB` 假设。这类**没有直接答错、但换了前提**的，按"部分正确 / 该条计 0.5–0"扣，并在 notes 里点名。若 Lead 认为这属于 M4（缺口识别）而非 M1，则 Q3 各 arm 的 M1 应整体上调约 0.05–0.10。
