# G9 nat 维度集 v2 合并提案（2026-11-20）

> 状态：提案，未改 GOLD。等 gpu/soc 全量独立性结果回来一起决策。
> 输入：g9-independence-nat.json（15 对，LLM-judge 本体论反例判据，Decision 22）
> 判据：能构造 i 变 j 不变的真实产品 → 独立；不能 → 相关 → 候选合并。

## 当前 GOLD（nat，6 维）

- g0: Pareto 热度下 LRU 命中率可用 Zipf/Pareto 累积质量估算（头部 k% 对象承载大部分请求）
- g1: α=1.1 接近临界 → 缓存容量利用率对头部集中度敏感，128GB 能覆盖的头部比例决定命中率量级
- g2: LFU 优势上限受对象更新/热度漂移限制（1%/天更新 → LFU 频率表老化），提升有限且需量化
- g3: 大小-热度负相关意味着按字节命中率 ≠ 按请求命中率，口径要分开报
- g4: 更新率 1%/天 → 有效驻留时间 ~100 天量级 vs 访问间隔，折扣幅度应给出推导而非拍脑袋
- g5: 明确标注哪些数字是估算、哪些是假设（如 miss 惩罚、对象不可分割性）

## LLM-judge 结果

13 对独立（conf 0.85-0.95，反例均为具体 CDN/流媒体场景），2 对候选合并：

### 候选 1：g0 × g1（conf 0.95）

- **judge 机制**：α 同时决定头部集中度（g0 的核心变量）和容量利用率对头部集中度的敏感度（g1 的核心变量），互为因果。
- **我的语义判断**：⚠️ 倾向**不合并，但 g1 应降级为 g0 的题面实例**。
  - g0 是**方法维度**（Zipf/Pareto 累积质量能否估算 LRU 命中率）——跨题可迁移。
  - g1 是**题面参数敏感度**（α=1.1 临界 + 128GB 覆盖比例）——只属于这道题。
  - 合并会把方法维度和题面细节焊死，U(T) 的 C 项就失去跨题可比性。
  - 正确做法：GOLD 保留 g0；g1 的内容并入 g0 的"本题实例"字段（不改维度数，改维度结构）。
- **conf**：0.7（语义判断，非 judge 输出）。

### 候选 2：g2 × g4（conf 0.95）

- **judge 机制**：同一物理参数（1%/天更新率）的两个映射——LFU 频率表老化（g2）和驻留时间折扣（g4），因果同源不可分割。
- **我的语义判断**：✅ **倾向合并**。
  - 两者都是"更新率 → 缓存行为"的推论，只是推论方向不同（策略上限 vs 驻留折扣）。
  - 一个答案若给出"1%/天更新 → 频率表老化 → LFU 优势有限 + 驻留 ~100 天"的完整推导，两个维度同时满足；分开计分 = 同一推导计两次分（C 双重计数，正是 G9 要防的）。
  - 合并后维度文本：「更新率 1%/天 的完整推导：LFU 频率表老化限制策略优势上限 + 有效驻留时间 ~100 天量级，折扣幅度需推导而非拍脑袋」。
- **conf**：0.8。

## 提案：nat GOLD v2（5 维）

- g0': Zipf/Pareto 累积质量估算 LRU 命中率（含本题实例：α=1.1 临界、128GB 覆盖头部比例决定命中率量级）
- g2': 更新率 1%/天 的完整推导（LFU 频率表老化 → 策略优势上限有限 + 有效驻留 ~100 天，折扣需推导）
- g3: 大小-热度负相关 → 按字节 vs 按请求命中率口径分开
- g4: 估算 vs 假设标注
- ~~g1~~ 并入 g0'；~~g4(旧)~~ 并入 g2'
