## 3. 上限交叉验证（0.813 对不对）

**先纠正一个前提**：`NodeRecord.status` 默认值就是 `pending`（`s5_state_machine.py:407`），所以 **pending = 尚未核验，不是核验失败**；且 pending 节点 `evidence` 与 `retrieval_sources` **全部为空**（77/77）。0.813 的推法（"77 pending 中 46 个 knowledge/given 可翻"）把"未跑核验"当成了"难以核验"。conf 0.9

**真实结构（checkpoint 交叉表）**：

| source | verified | pending | degraded | failed | 合计 |
|---|---|---|---|---|---|
| knowledge | 171 | 45 | 3 | 0 | 219 |
| search | **0** | 27 | 28 | 1 | **56** |
| given | 3 | 5 | 0 | 0 | 8 |

- **knowledge 通道实际通过率 171/174 = 98.3%**；**search 通道 0/56 = 0%** → 全部缺口集中在 search 一个通道（占全树 19.8%）。conf 0.9
- 若 search 继续全挂、knowledge/given 按 98% 放出：174 + 50×0.98 + 3 ≈ **226/283 = 0.799**。→ **0.813 只在"search 完全不修"的前提下略偏乐观（差 4 个节点）**。conf 0.75
- 若 search 修好（哪怕一半）：+28 → **0.90**，足以过 0.898 gate。反之"不修通道只重跑 verify"最多 0.80。conf 0.7
- degraded 的失败原因实测两类：①`检索失败: no sources from any channel (all 5 failed)`（通道问题，可救）；②"逻辑自洽但来源不支持该具体数值"（N10 阈值0.85、N27 中位数+10-15%、N31 损失厌恶参数）——**②类即使通道修好也无公开来源**，因为这些数是本题自造的平台内部参数。conf 0.8

**按节点类型的可溯源判断**（对 77 pending + 31 degraded 逐条分类）：

| 类型 | pending | degraded | 有无公开来源 |
|---|---|---|---|
| 参数估计（数值区间/系数/百分比） | 35 | 18 | **基本没有**（平台内部数据，或行业类比值不可直接当同一断言） |
| 公式/定义（Spence、损失厌恶、DID/Heckman、GMV/NPS） | 30 | 5 | **有**（教科书/百科可核定义），但不可核"本题取值" |
| 设计/论证（构建假设链、识别驱动方、设计干预） | 9 | 3 | **没有**（规范性断言，只能逻辑自洽核验） |
| 其他/含机构年报词 | 3 | 5 | 少数有（eBay 费率、闲鱼佣金政策） |

**判决：0.813 作为"不修通道时的天花板"数值上基本成立（我算 0.80，差 ~4 节点），但归因错误——决定上限的不是"哪 46 个节点可翻"，而是 search 通道 56 个节点 0 通过；且 35+18 个参数估计类节点即使通道全修也不会有公开来源，只能降级或改判据。conf 0.78**

## 核心发现（≤10 行）

1. search 通道 **0/56 通过**、knowledge 通道 **171/174 通过** → 缺口是单通道故障，不是"知识型节点难核验"。
2. `pending` 是默认状态 = 未核验（77/77 无 evidence、无 retrieval_sources），0.813 的"46 可翻"前提不成立。
3. 不修通道：上限 ≈ 0.80；修好一半 search：≈ 0.90（可过 0.898 gate）。
4. DDG **lite 端点通、html 端点 500**；Wikipedia/arXiv/NBS 网站通；**统计局数据库 API 403 WAF**；Bing 通但无 cookie 时结果是噪音；Mojeek 需人机验证。
5. `research_hook._bing_search` 的 `except: return []` 会把"解析失败"伪装成"通道无结果"——这是 search 0 命中的头号嫌疑。
6. 参数估计类（53 个）与设计类（12 个）节点本质无公开来源，任何"修通道→全翻"的期望都会落空。
7. 世行 vs NBS 人口差 0.12% → 跨源核对必须标口径，不能互相当作"证实"。
8. 结论 conf：通道诊断 0.9 / 上限 0.78 / 来源类型 0.85 / 代码嫌疑 0.75。
