# M4 (Gap Coverage) Anchor Examples — Judge Calibration

## 为什么需要这个文件

异族 judge round 1 中 M4 的 κ=-0.087（两个裁判几乎不同步），根因是 rubric 只说"评估是否识别并覆盖研究缺口"但没给具体标准。两个 judge 对"什么算好的 gap identification"理解完全不同。本文件用 3 个 anchor example 把模糊标准钉死。

## 评分标准（修订版）

**M4 = Gap Coverage: 模型是否主动识别"自己不知道什么/查不到什么"，并明确说明原因和边界。**

| 分数 | 标准 | 关键词信号 |
|------|------|-----------|
| 0.0-0.2 | 完全没有 gap awareness，所有断言都写得像确定的事实 | 无 "I don't know / unclear / could not verify / 待核验" |
| 0.3-0.4 | 有少量 hedging（"可能""大概"）但没有明确指认具体哪个点查不到、为什么查不到 | 泛化 hedge，不指向具体 claim |
| 0.5-0.6 | 能指认 1-2 个具体缺口（"X 的具体数值我无法从公开来源确认"），但没说清为什么（缺数据源？方法未公开？） | 有具体对象 + 部分原因 |
| 0.7-0.8 | 系统性地列出多个缺口，每个都带原因（"官方未披露"/"论文只给了均值没给 per-condition 分解"/"沙箱无法访问该 API"），且区分了"黑盒"vs"可验证但未验证" | 多缺口 + 逐条原因 + 分类 |
| 0.9-1.0 | 在 0.7-0.8 基础上，还给出了"如果我要填上这些缺口，下一步该查什么"的可操作路径 | 缺口 + 原因 + 补全路径 |

## Anchor Example A: 高分样本 (M4 ≈ 0.85)

```
关于 GPT-4V 的 tiling 机制：OpenAI 官方文档未给出 tile 尺寸和 overlap 比例的
一手数字（conf 封顶 0.8，三个独立社区源逐项一致但均非官方）。这是一个黑盒
叶子——我无法从公开渠道验证具体参数。如果要补全，下一步应查 Azure OpenAI
API 的 response header 或逆向渲染管线。

关于 Gemini 架构：参数量/MoE 路由细节/视觉编码器规格均为 B3 黑盒（官方从未
披露），树内不引任何具体数字。这不是"我没查到"而是"不存在公开信息"——
区分这两者很重要：前者可以通过换数据源解决，后者只能等官方披露。

关于 CLIP 768-dim embedding：论文正文表格未拉取原文，采用 open_clip 配置口径
（S3, conf 0.8）+ ViT-Large 标准宽度通识，双挂来源。这里有一个可验证但未验证
的缺口：如果直接读论文 Table 2 应该能确认，但我当前沙箱无法访问 PDF 全文。
```

**为什么给 0.85**：三个缺口各有不同处理——① 黑盒+补全路径；② 区分"不存在"vs"未查到"（这是高级判断）；③ 可验证但未验证+说明原因。没有泛化 hedge，每个 gap 都指向具体对象。

## Anchor Example B: 中分样本 (M4 ≈ 0.45)

```
CDN 缓存命中率通常在 70-90% 之间，具体取决于内容类型和用户分布。
边缘节点的定价因供应商而异，Cloudflare 相对便宜。
PUE 一般在 1.2-1.5 范围。
```

**为什么给 0.45**：有 hedging（"通常""一般""因...而异"）但全是泛化的——没有指认"哪个具体数字我查不到、为什么查不到"。读者看完不知道哪些是硬数据、哪些是模型凭印象说的。

## Anchor Example C: 低分样本 (M4 ≈ 0.15)

```
CDN 缓存命中率为 85%，Cloudflare 边缘节点价格为 $0.04/GB，
PUE 为 1.25，DDoS 保护费用为 $500/月。
```

**为什么给 0.15**：所有数字写得像确定事实，没有任何 gap awareness。即使其中有些数字是编的（fabrication），从 M4 角度看它至少"自信地覆盖了所有点"——但 M4 惩罚的正是这种虚假完整性。注意：M3 (fabrication) 会单独惩罚编造的数字，M4 只评 gap awareness，两者正交。

## 给 Judge 的指令（附加到 scoring prompt 末尾）

```
M4 评分时请参照以下锚定：
- 0.8+ = 系统性列出多个具体缺口，每个带原因，区分"黑盒"vs"未验证"
- 0.5  = 能指认 1-2 个具体缺口但有部分原因
- 0.3  = 只有泛化 hedging（"可能""一般"），不指向具体 claim
- 0.1  = 所有断言都写成确定事实，零 gap awareness

关键判据：gap 是否指向【具体对象】（哪个数字/哪个参数/哪个声明），
而非泛化的不确定性表达。"X 的具体值我无法确认因为 Y" > "X 大概在某个范围"。
```
