# 阶段 01：目标分解、已知与空缺条件

## 1. 目标交付物定义

**最终交付物**：一份供决策者使用的《20人混合办公团队网盘选型报告》，包含：
1. **3个候选方案对比表**：覆盖功能（版本管理、外链权限、离线同步）、部署模式（SaaS/自托管）、安全合规。
2. **TCO估算模型**：基于20人规模，周期为1年，包含软件订阅费、存储扩容费、IT运维人力成本（针对自托管）、迁移实施成本。
3. **迁移风险评估矩阵**：识别从现有环境（假设通用场景）迁移至各候选方案的数据完整性、业务中断、用户习惯改变风险。
4. **来源索引与不确定性标注**：所有关键数据均附带来源编号，未验证项明确标记为“待研究”。

**约束条件**：
- 人数：20人
- 预算上限：$8/人/月 → 总月度预算 $160，年度预算 $1,920（仅软件许可部分，不含一次性迁移和额外硬件）
- 核心功能硬指标：版本管理、外链分享权限控制、离线同步
- 备选要求：必须存在可自托管的版本或路径

## 2. 顶层影响因素分解（正交性检查）

将目标拆分为以下5个互相正交且完整覆盖的影响因素：

| 因素ID | 因素名称 | 定义与边界 | 优先级 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| F1 | **功能符合度** | 候选产品是否原生支持版本历史回溯、细粒度外链权限（如有效期、密码、下载限制）、全平台离线同步客户端。 | 高 | 不满足任一硬指标则直接排除。 |
| F2 | **经济性与TCO结构** | 在$8/人/月约束下的实际报价、存储配额是否够用、自托管的隐性成本（服务器、电力、运维时间）。 | 高 | 决定候选是否进入决赛圈。 |
| F3 | **部署与运维复杂度** | SaaS开箱即用程度 vs 自托管的技术门槛（Docker/K8s需求、备份策略、升级频率）。 | 中 | 影响IT人员投入，进而影响TCO中的运维成本。 |
| F4 | **数据安全与合规** | 传输加密、静态加密、SSO集成、审计日志、数据驻留选项。 | 中 | 虽非硬指标，但混合办公涉及敏感数据，需评估风险。 |
| F5 | **迁移可行性与风险** | 现有文件导入工具、API开放程度、元数据保留能力、回滚机制。 | 中 | 决定实施周期的长短和失败概率。 |

*正交性检查*：F1关注“能不能用”，F2关注“贵不贵”，F3关注“难不难管”，F4关注“安不安全”，F5关注“换不换得动”。五者独立且合起来覆盖了选型全流程。

## 3. 递归分解与条件区分

### F1: 功能符合度
#### 子因素 F1.1: 版本管理深度
- **人类已提供**：需具备版本管理。
- **可推导**：主流网盘通常保留最近N个版本或无限版本（取决于套餐）。
- **仍需研究**：各候选的具体版本保留数量、是否支持分支合并（类似Git，网盘较少见，通常仅为快照）、大文件版本存储开销。
- **空缺清单**：[待研究] 候选A/B/C的具体版本保留策略及超限处理机制。

#### 子因素 F1.2: 外链分享权限控制
- **人类已提供**：需外链分享权限控制。
- **可推导**：基础控制包括公开/私有链接、密码保护。高级控制包括有效期、IP白名单、禁止下载仅预览。
- **仍需研究**：各候选对“细粒度”控制的实现程度（例如：能否按部门设置不同外链权限？能否追踪外链访问记录？）。
- **空缺清单**：[待研究] 候选A/B/C的外链高级权限特性列表。

#### 子因素 F1.3: 离线同步能力
- **人类已提供**：需离线同步。
- **可推导**：需支持Windows/Mac/Linux客户端，支持选择性同步（Select Folder Sync）。
- **仍需研究**：冲突解决机制（Last Write Wins? Manual Merge?）、大文件断点续传稳定性、移动端离线编辑能力。
- **空缺清单**：[待研究] 候选A/B/C的冲突解决逻辑及客户端平台覆盖情况。

### F2: 经济性与TCO结构
#### 子因素 F2.1: 直接软件成本
- **人类已提供**：≤$8/人/月。
- **可推导**：20人 * $8 = $160/月。
- **仍需研究**：各候选是否有20人起购优惠？教育/初创企业折扣？年付vs月付价差？
- **空缺清单**：[待研究] 候选A/B/C的最新官方定价页数据（需近7天抓取）。

#### 子因素 F2.2: 存储配额匹配度
- **人类已提供**：无具体存储量需求。
- **可推导**：一般文档型团队人均5-20GB，设计/视频团队人均100GB+。
- **仍需研究**：默认套餐存储是否足够？超出后单价是多少？
- **空缺清单**：[待研究] 假设场景下（待定：文档为主 or 多媒体为主）的存储缺口及扩容成本。*注：此处需向用户确认团队主要文件类型，暂列为阻塞性空缺。*

#### 子因素 F2.3: 自托管隐性成本
- **人类已提供**：数据可自托管备选。
- **可推导**：自托管需服务器硬件/云主机、域名、SSL证书、定期备份存储。
- **仍需研究**：推荐的最小硬件配置？预估电费/云租赁费？运维所需IT工时折算成金钱。
- **空缺清单**：[待研究] 候选A/B/C自托管版的最低系统要求及社区推荐的基准硬件配置。

### F3: 部署与运维复杂度
#### 子因素 F3.1: 初始部署难度
- **人类已提供**：无特定IT技能描述。
- **可推导**：SaaS注册即用；自托管需Linux基础。
- **仍需研究**：自托管版是否提供一键安装脚本/Docker Compose模板？官方文档完善度。
- **空缺清单**：[待研究] 候选A/B/C自托管版的部署指南复杂度评估。

#### 子因素 F3.2: 日常运维负担
- **人类已提供**：无。
- **可推导**：SaaS零运维；自托管需监控磁盘、更新补丁、处理故障。
- **仍需研究**：自托管版的更新频率、是否存在破坏性变更、社区活跃度（StackOverflow/GitHub Issues响应速度）。
- **空缺清单**：[待研究] 候选A/B/C自托管版的维护频率和社区健康度指标。

### F4: 数据安全与合规
#### 子因素 F4.1: 加密标准
- **人类已提供**：无。
- **可推导**：TLS 1.2+ 传输加密是底线。
- **仍需研究**：静态数据是否端到端加密（E2EE）？密钥由谁掌握？
- **空缺清单**：[待研究] 候选A/B/C的加密架构白皮书或安全FAQ。

#### 子因素 F4.2: 身份认证集成
- **人类已提供**：无。
- **可推导**：SaaS通常支持Google Workspace/Microsoft 365 SSO。
- **仍需研究**：自托管版是否支持LDAP/SAML/OAuth2？
- **空缺清单**：[待研究] 候选A/B/C的SSO/LDAP支持矩阵。

### F5: 迁移可行性与风险
#### 子因素 F5.1: 数据导入工具
- **人类已提供**：无现有网盘品牌指定（假设为通用文件系统或其他网盘）。
- **可推导**：WebDAV接口是通用迁移桥梁。
- **仍需研究**：各候选是否提供官方迁移助手？API速率限制？
- **空缺清单**：[待研究] 候选A/B/C的API文档及迁移工具可用性。

#### 子因素 F5.2: 元数据保留
- **人类已提供**：无。
- **可推导**：文件名、修改时间、权限组是关键元数据。
- **仍需研究**：批量上传时是否能保留原始权限结构和文件夹层级？
- **空缺清单**：[待研究] 候选A/B/C在批量导入时的元数据映射规则。

## 4. 候选对象初步筛选（待验证假设）

基于市场知名度、自托管能力和功能匹配度，初步锁定以下三类作为**待验证候选**：

1.  **候选 A: Nextcloud (Enterprise Edition / Community)**
    *   *假设理由*：开源标杆，自托管首选，功能模块化强，有商业版提供SLA。
    *   *待验证属性*：EE版价格是否超标？CE版运维难度？版本管理插件成熟度？
2.  **候选 B: Synology Drive (Standard/Professional)**
    *   *假设理由*：NAS厂商原生软件，若团队已有NAS则成本极低；SaaS版亦存在。
    *   *待验证属性*：SaaS版定价？无NAS情况下自建服务器的可行性？外链权限细节？
3.  **候选 C: Seafile (Pro/Community)**
    *   *假设理由*：高性能同步引擎，专注同步速度，自托管友好。
    *   *待验证属性*：UI易用性？版本管理界面？商业版定价？

*排除理由示例*：
*   排除 Dropbox Business：虽功能强大，但无自托管选项，违反“数据可自托管备选”硬约束。
*   排除 Google Drive for Work：无自托管选项，外链权限控制较粗，且价格可能随存储波动，难以精确控制在$8/人/月以内（取决于用量）。
*   排除 OneDrive for Business：绑定M365套件，单独购买网盘困难，无自托管选项。

## 6. 阶段 02 研究入口与行动路径

### 第一批优先研究动作（对应 GAP-03, GAP-05）

1.  **目标网站**：Nextcloud.com, Synology.com, Seafile.com 的官方 Pricing 页面。
2.  **搜索词**：
    *   `"Nextcloud Enterprise Edition pricing per user"`
    *   `"Synology Drive Standard pricing cloud service"`
    *   `"Seafile Pro pricing plan"`
3.  **字段提取**：
    *   每人每月单价（USD）
    *   最小起购人数
    *   包含的存储配额
    *   外链分享的高级功能描述（关键词：expiration, password, permission level）
4.  **备用来源**：
    *   G2/Capterra 上的最新用户评论（查找关于价格和功能的近期反馈）。
    *   官方 Blog 或 Release Notes（查找最近的价格调整公告）。

### 第二批研究动作（对应 GAP-04, GAP-02）

1.  **目标网站**：GitHub Repositories (nextcloud/server, seafile-server), 官方 Documentation。
2.  **搜索词**：
    *   `"Nextcloud system requirements minimum hardware"`
    *   `"Seafile server docker compose example"`
    *   `"Synology Drive self-hosted without NAS feasibility"`
3.  **字段提取**：
    *   CPU/RAM/Disk 最低要求
    *   支持的操作系统
    *   依赖组件（数据库、PHP版本等）

### 第三批研究动作（对应 GAP-01, GAP-06 - 需用户交互）

*   **注意**：此步可能需要 `user` 介入确认。
*   **动作**：向用户询问：“请提供团队目前的人均存储占用量估计（如：每人50GB）以及主要文件类型（文档/图片/视频）。”
*   **若用户未提供**：阶段 02 将基于“保守估计（人均20GB文档为主）”和“激进估计（人均100GB多媒体为主）”两种场景进行敏感性分析。
