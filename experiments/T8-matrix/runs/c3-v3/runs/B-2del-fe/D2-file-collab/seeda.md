# 阶段 01：目标分解、已知与空缺条件

## 1. 目标交付物定义
**核心交付物**：一份包含以下内容的决策支持文档（供后续阶段执行）：
1. **3 个候选网盘对比矩阵**：覆盖版本管理、外链分享权限控制、离线同步、自托管能力。
2. **TCO（总拥有成本）估算模型**：基于 ≤$8/人/月预算，计算 20 人团队在 1-3 年周期内的直接订阅费 + 潜在运维/存储溢出成本。
3. **迁移风险评估报告**：针对从当前状态（假设无特定遗留系统或通用文件服务器）迁移至候选方案的流程风险、数据一致性风险和回滚难度。
4. **推荐结论与理由**：基于上述分析给出首选方案及备选方案。

## 2. 顶层影响因素分解（正交性检查）

我们将目标拆解为以下四个互相正交的顶层因素：

### 因素 A：功能合规性 (Functional Compliance)
*   **定义**：候选产品是否满足硬性功能需求。
*   **子因素**：
    *   A1: 版本管理深度（文件级 vs 文件夹级，保留历史版本数量限制）。
    *   A2: 外链分享权限粒度（仅查看/可编辑/密码保护/有效期/禁止下载/水印等）。
    *   A3: 离线同步机制（客户端类型、冲突处理策略、选择性同步、断网重连稳定性）。
    *   A4: 自托管可行性（是否提供 Docker/K8s 部署包、许可证是否允许私有化部署、功能阉割情况）。
*   **边界条件**：若某项功能完全缺失，则该候选直接淘汰（除非该功能被降级为非强制）。

### 因素 B：经济性与预算约束 (Economic & Budget Constraints)
*   **定义**：在给定预算下的成本结构及长期支出预测。
*   **子因素**：
    *   B1: 标准 SaaS 订阅单价（Per user/month, PUM）。
    *   B2: 存储容量配额（基础包含量 vs 超额购买价格）。
    *   B3: 隐藏成本（API 调用费、高级安全功能附加费、最低起购人数限制）。
    *   B4: TCO 计算模型（1年/3年视角，含通胀率假设）。
*   **边界条件**：总成本必须 ≤ $8 × 20 = $160/月（即 $1920/年）。若超出，需评估是否可通过降低存储规格或选择入门版解决。

### 因素 C：运维与迁移复杂度 (Ops & Migration Complexity)
*   **定义**：实施、日常维护及数据迁移的技术与人力成本。
*   **子因素**：
    *   C1: 客户端兼容性（Windows/macOS/Linux/iOS/Android 支持情况及成熟度）。
    *   C2: 迁移工具链（官方迁移助手、Rclone 支持、API 导出便利性）。
    *   C3: 数据一致性风险（大文件传输校验、并发写入冲突、元数据丢失风险）。
    *   C4: 回滚难度（数据导出完整性、格式兼容性、时间窗口预估）。
*   **边界条件**：迁移风险需量化为“低/中/高”，并指出关键阻塞点。

### 因素 D：数据安全与合规 (Security & Compliance)
*   **定义**：数据主权、隐私保护及企业级安全特性。
*   **子因素**：
    *   D1: 数据驻留地（服务器地理位置，是否符合当地法规）。
    *   D2: 加密标准（传输中 TLS 版本、静态存储 AES-256、端到端加密 E2EE 支持）。
    *   D3: 审计日志（操作记录保留时长、导出格式）。
    *   D4: SLA 保障（可用性承诺、数据恢复 RPO/RTO）。
*   **边界条件**：虽非用户明确提出的硬性指标，但作为“团队协作”场景，基本的安全基线是隐含前提。若候选存在重大安全漏洞史或无审计功能，应标记高风险。

### 3.3 仍需研究的条件 (Unknowns / Gaps) -> **阶段 02 研究入口**

#### Gap Group 1: 候选对象筛选与属性核验
*   **G1.1 [待研究] 符合 K3+K5 的顶级候选名单**
    *   *子问题*：哪些主流网盘同时支持 SaaS 和 Self-hosted？（例如：Nextcloud, Seafile, Synology Drive, Dropbox, OneDrive, Google Drive, Box, Egnyte, Citrix ShareFile 等）。
    *   *排除逻辑*：纯 SaaS 且无自托管版本的（如 Dropbox, OneDrive, Google Drive）可能不符合 K5 的“自托管备选”这一整体语境，但如果任务意思是“选一个网盘，它最好能自托管，或者如果不自托管也行但要有其他优势”，则需澄清。*注：根据 K5“数据可自托管备选”，通常解读为：所选方案应具备自托管能力，以便未来迁移或数据主权考虑。因此，纯 SaaS 锁死数据的方案可能被降权或排除。*
    *   *假设候选池（待验证）*：
        1.  **Nextcloud** (开源, 可自托管, 有付费企业版 SaaS 或托管服务)
        2.  **Seafile** (开源, 可自托管, 有云服务)
        3.  **Synology Drive** (NAS 绑定, 强自托管属性, 也有云备份服务)
        4.  **Dropbox** (纯 SaaS, 功能极强, 但无法自托管 - 用于对比基准)
        5.  **OneDrive for Business** (纯 SaaS, 微软生态, 无法自托管 - 用于对比基准)
    *   *行动*：确认最终对比的 3 个候选。建议策略：2 个支持自托管的（Nextcloud/Seafile/Synology 中选 2）+ 1 个顶级纯 SaaS 作为功能/体验基准（Dropbox/OneDrive），或者 3 个均支持自托管的方案。*鉴于 K5 强调“可自托管备选”，建议选取 3 个均具备自托管能力的方案，或 2 个自托管 + 1 个高体验 SaaS 以展示 trade-off。此处暂定研究 3 个具备自托管潜力的方案：Nextcloud, Seafile, Synology Drive。若 Synology 硬件成本过高导致 TCO 超标，则替换为另一个如 OwnCloud 或 FileRun。*

*   **G1.2 [待研究] Nextcloud 具体属性**
    *   子问题 1: 最新版本管理中，免费版与企业版的区别？
    *   子问题 2: 外链分享的权限控制细节（是否支持细粒度 ACL？）
    *   子问题 3: 官方托管服务 (Nextcloud Plus) 的价格是多少？是否 ≤ $8/人/月？
    *   子问题 4: 自托管时的硬件资源需求（CPU/RAM/Disk IOPS）估算。

*   **G1.3 [待研究] Seafile 具体属性**
    *   子问题 1: Seafile Pro 的价格结构？
    *   子问题 2: 其版本管理算法（Chunk-based）对大文件的性能影响？
    *   子问题 3: 外链分享的安全性特性。
    *   子问题 4: 自托管部署的复杂性（Docker Compose 一键部署难度）。

*   **G1.4 [待研究] Synology Drive 具体属性**
    *   子问题 1: Synology Drive 本身免费，但依赖 NAS 硬件。如何计算 TCO？（需将 NAS 折旧计入 TCO）。
    *   子问题 2: 是否有纯软件版可在普通服务器上运行而不依赖 DSM 系统？（通常没有，需确认）。
    *   子问题 3: 外链分享功能的限制。
    *   *替代候选*：若 Synology 因硬件绑定导致 TCO 复杂度过高，替换为 **FileRun** 或 **ownCloud**。

*   **G1.5 [待研究] 基准候选 (如 Dropbox)**
    *   子问题 1: Dropbox Business 当前价格是否 ≤ $8/人/月？（通常更高，需确认是否有促销或旧价）。
    *   子问题 2: 其版本管理和分享功能的具体参数。

#### Gap Group 2: TCO 计算所需数据
*   **G2.1 [待研究] 各候选的精确 PUM (Price Per User per Month)**
    *   需获取最新官网价格表。
    *   注意：是否有年付折扣？（TCO 估算通常按年付计算更准确）。
*   **G2.2 [待研究] 存储配额与扩容价格**
    *   20 人团队的平均存储需求假设：每人 50GB? 100GB? (需设定合理假设，例如人均 100GB，总 2TB)。
    *   各候选的基础配额是多少？超出部分每 GB 多少钱？
*   **G2.3 [待研究] 自托管方案的隐性成本**
    *   服务器租赁成本（AWS/GCP/Azure 或本地机房电费/带宽）。
    *   运维人力成本（虽然题目未要求算人力，但 TCO 应注明是否包含运维）。*注：通常 TCO 指直接财务支出，运维人力可作为定性风险提及，不纳入硬性 TCO 数字，除非用户要求。此处假设 TCO 仅含软件/硬件/云资源直接费用。*

#### Gap Group 3: 迁移风险具体化
*   **G3.1 [待研究] 各候选的官方迁移工具**
    *   Nextcloud: 是否有从 Dropbox/OneDrive 导入的官方 App？
    *   Seafile: 是否支持 Rclone 高效迁移？
    *   Synology Drive: 是否有 Hyper Backup 或专用迁移工具？
*   **G3.2 [待研究] 元数据保留能力**
    *   迁移时，创建时间、修改时间、作者信息、权限组是否能完整保留？
    *   版本历史能否一起迁移？（大多数情况下不能，需确认）。

#### Gap Group 4: 安全性与合规细节
*   **G4.1 [待研究] 数据驻留地选项**
    *   Nextcloud/Seafile 自托管：由用户决定（灵活）。
    *   Nextcloud Plus/Seafile Cloud：服务器在哪里？
*   **G4.2 [待研究] 审计日志功能**
    *   免费/基础版是否包含审计日志？还是仅企业版？

## 5. 阶段 02 研究路径规划

### 5.1 第一批行动（立即执行）
1.  **确定候选名单**：
    *   搜索词：`"best self-hosted file sharing software 2024 comparison nextcloud seafile synology"`
    *   目标：确认 Nextcloud, Seafile, Synology Drive 是当前最主流的三个支持自托管的企业级网盘。若发现有更合适的（如 FileRun），则替换。
    *   备用：若 Synology Drive 被认为过于依赖硬件而不适合作为“软件选型”对比，替换为 **FileRun** 或 **ownCloud**。
2.  **获取价格数据**：
    *   访问 `nextcloud.com/pricing`, `seafile.com/pricing`, `synology.com/drive` (或相关云服务页面)。
    *   记录：PUM, 年付总价, 基础存储, 超额存储单价。
    *   交叉验证：查看 G2, Capterra 上的用户评论中提到的实际价格。
3.  **获取功能规格**：
    *   访问各产品的 `features` 或 `specs` 页面。
    *   重点核对：Version History limit, Link Sharing options, Offline Sync clients, Audit Log availability.

### 5.2 第二批行动（深入挖掘）
1.  **TCO 模型构建**：
    *   基于 GAP-02, GAP-03, GAP-04 的数据，建立 Excel/Markdown 表格。
    *   场景 A：SaaS 模式（若候选提供）。
    *   场景 B：Self-hosted 模式（计算服务器成本 + 软件许可（如有））。
    *   比较两者在 1 年和 3 年周期的差异。
2.  **迁移风险调研**：
    *   搜索词：`"migrate to nextcloud from dropbox tool"`, `"seafile migration guide"`, `"synology drive import external files"`。
    *   关注：官方工具是否存在、社区推荐的第三方工具（如 Rclone）、已知陷阱（如符号链接、权限丢失）。

### 5.3 失败备用路径
*   若某候选官网价格页面加载失败或信息模糊：
    *   尝试联系销售（邮件表单）获取报价单（记录发送时间，若 24h 内无回复则标记为“未解决”）。
    *   查找第三方评测网站（TechCrunch, The Verge, G2）中近半年的文章，提取价格截图或文字描述。
*   若自托管硬件成本难以标准化：
    *   采用“中等配置云服务器”作为统一基准（例如：4 vCPU, 16GB RAM, 2TB SSD on AWS us-east-1），以此作为所有自托管候选的硬件成本基准，确保公平对比。

3.  **研究路径具体**：给出了具体的搜索词、
