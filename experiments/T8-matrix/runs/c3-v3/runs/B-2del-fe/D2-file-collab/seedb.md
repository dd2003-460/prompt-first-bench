# 阶段 01：目标分解、已知与空缺条件

## 1. 目标交付物定义

**核心交付物：**
1. **3 个候选网盘的对比矩阵**：覆盖版本管理、外链分享权限控制、离线同步三大功能维度。
2. **TCO（总拥有成本）估算模型**：基于 ≤$8/人/月预算约束，包含订阅费、潜在隐性成本（存储超额、高级功能附加费）、自托管备选方案的硬件/运维摊销成本。
3. **迁移风险评估报告**：涵盖数据导出兼容性、客户端兼容性、用户习惯改变、业务中断风险。
4. **自托管备选方案评估**：明确哪些候选支持自托管，及其技术门槛与维护成本。

**非目标（Out of Scope）：**
- 不替代最终采购决策（需用户确认）。
- 不涉及具体合同谈判细节。
- 不深入比较所有可能的网盘产品（仅聚焦 3 个高潜力候选）。

---

## 2. 顶层影响因素分解（正交性检查）

| 因素 ID | 因素名称 | 对目标的影响 | 边界条件 |
|---------|----------|--------------|----------|
| F1 | 功能合规性 | 直接决定候选是否满足硬性需求 | 必须同时满足：版本管理 + 外链权限控制 + 离线同步 |
| F2 | 成本结构 | 直接决定是否在预算内 | 人均月成本 ≤ $8；TCO 需考虑 3 年周期 |
| F3 | 部署模式 | 影响 TCO 结构和数据安全自主权 | SaaS vs 自托管；自托管需评估运维能力 |
| F4 | 迁移可行性 | 影响实施风险和用户接受度 | 数据格式开放性、API 可用性、客户端平台支持 |
| F5 | 安全与合规 | 间接影响长期风险 | 数据加密标准、审计日志、GDPR/本地法规合规性 |
| F6 | 可扩展性与稳定性 | 影响 20 人团队未来增长 | 存储上限、并发连接数、SLA 承诺 |

> **正交性说明**：F1-F6 互相独立。例如，一个产品可能功能齐全（F1 高）但价格超标（F2 低），或 SaaS 便宜（F2 高）但不支持自托管（F3 受限）。

## 3. 递归分解与条件分类

### 3.1 F1: 功能合规性

#### 子因素：
- **F1.1 版本管理**
  - 已提供条件：无具体版本号要求，仅需“有版本管理”。
  - 可推导条件：主流网盘通常保留最近 N 个版本或无限历史版本。
  - **空缺条件 [待研究]**：各候选的版本保留策略（数量限制？时间窗口？是否可按文件自定义？）。
  - **阻塞影响**：若某候选仅保留 3 个版本且不可配置，可能不满足工程类文档需求。

- **F1.2 外链分享权限控制**
  - 已提供条件：需“权限控制”，未指定粒度。
  - 可推导条件：基础权限包括“任何人可读”、“特定人可读”、“密码保护”、“有效期”。
  - **空缺条件 [待研究]**：
    1. 是否支持细粒度权限（如仅下载不可预览）？
    2. 是否支持链接水印或访问日志？
    3. 外链是否计入存储配额？
  - **阻塞影响**：若无法控制“仅下载”，可能存在敏感信息泄露风险。

- **F1.3 离线同步**
  - 已提供条件：需“离线同步”，未指定平台。
  - 可推导条件：桌面端（Windows/macOS/Linux）和移动端（iOS/Android）均需支持。
  - **空缺条件 [待研究]**：
    1. 同步引擎类型（全量 vs 增量 vs 选择性同步）？
    2. 冲突解决机制（自动合并？手动选择？）？
    3. 大文件同步性能（断点续传？）？
  - **阻塞影响**：若仅支持全量同步，20 人团队带宽压力巨大。

#### 叶子原子判定：
- F1.1/F1.2/F1.3 的子问题已细化到可查询规格表的字段级别，停止分解。

---

### 3.2 F2: 成本结构

#### 子因素：
- **F2.1 订阅费用**
  - 已提供条件：预算 ≤ $8/人/月。
  - **空缺条件 [待研究]**：
    1. 各候选的定价阶梯（按人还是按总量？）。
    2. 是否有教育/初创优惠？
    3. 年度支付折扣幅度？
  - **阻塞影响**：若按总量计费，20 人 × 平均 50GB = 1TB，需查 1TB 套餐价格。

- **F2.2 隐性成本**
  - **空缺条件 [待研究]**：
    1. 超额存储单价？
    2. 高级功能（如 DLP、SSO）是否额外收费？
    3. API 调用次数限制及超额费用？
  - **阻塞影响**：隐性成本可能导致实际 TCO 超预算。

- **F2.3 自托管成本（备选）**
  - **空缺条件 [待研究]**：
    1. 自托管许可费（一次性 or 年度）？
    2. 推荐硬件配置（CPU/RAM/Disk）及市场价？
    3. 运维人力成本估算（内部 IT 人员小时费率 × 预估工时）？
  - **阻塞影响**：自托管 TCO 可能远高于 SaaS，需量化对比。

#### 叶子原子判定：
- 成本项已拆解到可查询定价页的字段，停止分解。

---

### 3.3 F3: 部署模式

#### 子因素：
- **F3.1 SaaS 可用性**
  - 已提供条件：默认首选 SaaS。
  - **空缺条件 [待研究]**：各候选是否提供企业级 SaaS 计划？
  - **阻塞影响**：部分开源工具仅有社区版 SaaS，功能受限。

- **F3.2 自托管支持**
  - **空缺条件 [待研究]**：
    1. 官方是否提供 Docker/Kubernetes 镜像？
    2. 自托管版本是否与 SaaS 版本功能一致？
    3. 备份与灾难恢复方案？
  - **阻塞影响**：若自托管功能阉割，则“自托管备选”无效。

#### 叶子原子判定：
- 部署模式已细化到技术实现层面，停止分解。

---

### 3.4 F4: 迁移可行性

#### 子因素：
- **F4.1 数据导出**
  - **空缺条件 [待研究]**：
    1. 是否支持批量导出原始文件？
    2. 元数据（版本历史、权限设置）是否可导出？
    3. 导出格式（ZIP? API?）？
  - **阻塞影响**：若无法导出元数据，切换供应商将丢失版本历史。

- **F4.2 客户端兼容性**
  - **空缺条件 [待研究]**：
    1. 支持的操作系统版本（Win10/11, macOS 12+, Ubuntu 20.04+）？
    2. 是否需要安装插件或修改系统设置？
  - **阻塞影响**：若不支持 Linux，部分开发人员将无法使用。

#### 叶子原子判定：
- 迁移风险已细化到具体操作层面，停止分解。

---

### 3.5 F5: 安全与合规

#### 子因素：
- **F5.1 加密标准**
  - **空缺条件 [待研究]**：传输加密（TLS 1.2+）和静态加密（AES-256）是否标配？
  - **阻塞影响**：若缺少端到端加密，可能不符合某些行业合规要求。

- **F5.2 审计与日志**
  - **空缺条件 [待研究]**：是否提供管理员审计日志（谁在何时访问了什么文件）？
  - **阻塞影响**：缺乏审计日志会增加内部泄密调查难度。

#### 叶子原子判定：
- 安全要素已标准化，停止分解。

---

### 3.6 F6: 可扩展性与稳定性

#### 子因素：
- **F6.1 SLA 承诺**
  - **空缺条件 [待研究]**：SaaS 版本的正常运行时间保证（99.9%? 99.99%?）？
  - **阻塞影响**：低 SLA 可能导致业务中断。

- **F6.2 存储上限**
  - **空缺条件 [待研究]**：单文件大小限制？总存储弹性扩展能力？
  - **阻塞影响**：若单文件限制 2GB，视频团队将无法使用。

#### 叶子原子判定：
- 稳定性指标已量化，停止分解。

## 5. 阶段 02 研究路径

### 5.1 候选对象筛选策略

**原则**：优先选择市场知名度高、支持自托管、功能完整的 3 个候选，避免小众产品导致研究偏差。

**初步候选类别（待验证）**：
1. **商业 SaaS + 自托管双模**：如 Nextcloud、Seafile、ownCloud（需验证其企业版定价和功能）。
2. **纯 SaaS 但功能强大**：如 Dropbox Business、Google Workspace（需验证是否符合预算和自托管要求——若不满足自托管，可能排除）。
3. **新兴协作平台**：如 Synology Drive、Tresorit（需验证版本管理和外链权限）。

**具体候选（待阶段 02 验证属性）**：
- **候选 A**：Nextcloud Enterprise — *待验证：版本管理深度、外链权限粒度、20 人定价、自托管许可费*
- **候选 B**：Seafile Pro — *待验证：版本管理策略、离线同步性能、SaaS 定价、自托管硬件要求*
- **候选 C**：Dropbox Business — *待验证：是否支持自托管（预计否，作为对照组）、外链权限细节、20 人定价*

> **排除理由示例**：若 Google Workspace 不支持自托管，且用户明确要求“数据可自托管备选”，则可能排除，除非其 SaaS 合规性极高且用户接受放弃自托管选项。此判断需在阶段 02 后由用户确认。

### 5.2 研究动作与来源

| 研究问题 | 目标来源类型 | 搜索词示例 | 备用来源 |
|----------|--------------|------------|----------|
| G1-G3 (功能) | 官方文档、帮助中心 | "Nextcloud version history limit", "Seafile external link permissions" | 第三方评测（G2, Capterra） |
| G4-G5 (成本) | 官方定价页、销售咨询 | "Nextcloud enterprise pricing 20 users", "Dropbox business price per user" | 用户论坛、Reddit r/selfhosted |
| G6-G7 (自托管) | GitHub 仓库、Docker Hub | "Nextcloud self-hosted license cost", "Seafile hardware requirements" | 社区 Wiki、Stack Overflow |
| G8 (迁移) | 官方迁移指南 | "How to export Nextcloud metadata", "Seafile data migration guide" | 用户案例博客 |
| G9-G10 (安全/SLA) | 安全白皮书、SLA 文档 | "Nextcloud SOC2 compliance", "Dropbox SLA uptime guarantee" | 第三方安全审计（Synack, HackerOne） |

### 5.3 失败备用路径

- 若官方定价页隐藏 20 人价格 → 联系销售获取报价单（记录为“销售报价，未公开”）。
- 若自托管硬件要求不明确 → 参考社区基准测试（如 Nextcloud Performance Test）。
- 若某候选无公开 SLA → 标记为“未披露”，在对比中标注为风险项。
