# 阶段 01：目标分解、已知与空缺条件

## 1. 目标交付物定义

**核心交付物：**
1. **选型推荐报告**：包含主选方案 + 备选方案，明确技术栈、部署模式、集成方式。
2. **年度成本表**：精确到 ¥20,000/年 预算内的各项费用（软件许可、基础设施、维护、可选功能）。
3. **风险清单**：技术兼容性、数据隐私、供应商锁定、扩展性、运维复杂度等维度的风险评估及缓解措施。
4. **实施路线图**：从选型到上线的关键步骤和时间估算。

**非目标（Out of Scope）：**
- 具体代码实现。
- 硬件采购（门禁控制器、传感器等），仅评估软件联动接口。
- 内部组织架构调整或流程变革建议。

## 2. 顶层影响因素分解（正交且覆盖完整）

| 因素 ID | 因素名称 | 说明 | 优先级 |
|---------|----------|------|--------|
| F1 | **功能完整性** | 是否满足预约、冲突检测、日历同步、多端访问、门禁联动（可选） | 高 |
| F2 | **平台兼容性** | macOS/Windows/Web 三端体验一致性，移动端支持（隐含需求） | 高 |
| F3 | **日历集成能力** | Google Calendar + Outlook 双向同步的可靠性、延迟、冲突处理机制 | 高 |
| F4 | **成本结构** | 初始投入 + 年度运营成本 ≤ ¥20,000/年，含隐藏成本（如 API 调用费、存储费） | 高 |
| F5 | **部署与运维** | SaaS vs 自托管、数据安全、备份恢复、升级维护工作量 | 中 |
| F6 | **可扩展性与定制** | 未来团队规模增长、自定义审批流、报表导出等扩展能力 | 中 |
| F7 | **门禁联动可行性** | 可选功能的技术实现路径、API 开放程度、额外成本 | 低（可选） |

> **正交性检查**：F1-F7 各自独立影响最终决策。例如，即使功能完整（F1），若成本超标（F4）或日历集成不可靠（F3），仍不可行。无重叠。

## 3. 递归分解与条件分类

### F1: 功能完整性

#### 子因素：
- F1.1 基础预约功能（房间选择、时间段选择、冲突检测）
- F1.2 用户管理（30人账号、角色权限）
- F1.3 通知提醒（邮件/IM推送）
- F1.4 会议室资源管理（设备配置、容量标注）
- F1.5 可选：门禁联动（刷卡/扫码开门）

#### 条件分类：
| 条件类型 | 内容 |
|----------|------|
| **人类已提供** | 30人研发团队；门禁联动为“可选” |
| **可推导** | 需支持至少30并发用户；需支持会议室资源 CRUD |
| **仍需研究（空缺）** | [待研究] 主流系统对“可选门禁联动”的支持深度 —— 子问题：1) 哪些SaaS原生支持？2) 哪些需自建中间件？3) 额外成本？ |

### F2: 平台兼容性

#### 子因素：
- F2.1 Web 端响应式设计（浏览器兼容性）
- F2.2 macOS 客户端（原生 or Electron）
- F2.3 Windows 客户端（原生 or Electron）
- F2.4 移动端支持（iOS/Android，虽未明说但研发场景常见）

#### 条件分类：
| 条件类型 | 内容 |
|----------|------|
| **人类已提供** | 必须支持 macOS/Windows/Web 三端 |
| **可推导** | Web 端应兼容 Chrome/Safari/Edge 最新两个大版本 |
| **仍需研究（空缺）** | [待研究] 候选系统在 macOS/Windows 上的客户端形态及体验评分 —— 子问题：1) 是否有原生客户端？2) 用户反馈如何？3) 安装包大小与启动速度？ |

### F3: 日历集成能力

#### 子因素：
- F3.1 Google Calendar 双向同步（OAuth 授权、事件创建/删除/更新）
- F3.2 Outlook (Microsoft 365) 双向同步（OAuth 授权、Exchange Online 支持）
- F3.3 冲突解决策略（本地优先 vs 云端优先）
- F3.4 同步延迟与可靠性（SLA）
- F3.5 多日历源合并视图

#### 条件分类：
| 条件类型 | 内容 |
|----------|------|
| **人类已提供** | 必须集成 Google Calendar + Outlook |
| **可推导** | 需支持 OAuth 2.0；需处理时区转换；需处理重复事件 |
| **仍需研究（空缺）** | [待研究] 候选系统对 GCal + Outlook 双集成的实际稳定性 —— 子问题：1) 是否存在已知 bug？2) 同步频率是多少？3) 冲突时的行为逻辑？4) 是否需要企业版才支持？ |

### F4: 成本结构

#### 子因素：
- F4.1 软件许可费（按用户数/会议室数/功能模块）
- F4.2 基础设施费（若自托管：服务器、域名、SSL）
- F4.3 第三方服务 API 费用（如短信、邮件网关）
- F4.4 实施与维护人力成本（内部或外包）
- F4.5 隐藏成本（超量使用费、数据导出费、高级支持费）

#### 条件分类：
| 条件类型 | 内容 |
|----------|------|
| **人类已提供** | 总预算 ≤ ¥20,000/年 |
| **可推导** | 30人 × 人均成本上限 ≈ ¥666/人/年；若含基础设施，软件许可需更低 |
| **仍需研究（空缺）** | [待研究] 各候选系统的真实定价模型 —— 子问题：1) 免费额度是否够30人？2) 付费版起步价？3) 是否有教育/初创优惠？4) 年度 vs 月度支付差异？5) 门禁联动是否单独收费？ |

### F5: 部署与运维

#### 子因素：
- F5.1 部署模式（SaaS / 私有化 / 混合）
- F5.2 数据安全（传输加密、静态加密、GDPR/等保合规）
- F5.3 备份与灾难恢复（RPO/RTO）
- F5.4 升级与维护（自动更新、停机窗口）
- F5.5 监控与告警

#### 条件分类：
| 条件类型 | 内容 |
|----------|------|
| **人类已提供** | 无明确安全合规要求，但研发团队通常关注数据主权 |
| **可推导** | SaaS 降低运维负担；自托管增加控制权但提高复杂度 |
| **仍需研究（空缺）** | [待研究] 候选系统的数据驻留位置与合规声明 —— 子问题：1) 数据存储在哪国？2) 是否通过 SOC2/ISO27001？3) 数据导出格式？4) 服务中断历史？ |

### F6: 可扩展性与定制

#### 子因素：
- F6.1 API 开放程度（REST/GraphQL/Webhook）
- F6.2 插件生态（Slack/Teams/钉钉/飞书集成）
- F6.3 自定义字段与工作流
- F6.4 报表与分析功能

#### 条件分类：
| 条件类型 | 内容 |
|----------|------|
| **人类已提供** | 无明确扩展需求，但研发团队可能未来需要 |
| **可推导** | API 文档质量是关键指标 |
| **仍需研究（空缺）** | [待研究] 候选系统的 API 文档完备性与社区活跃度 —— 子问题：1) 是否有官方 SDK？2) GitHub Star/Fork 数量？3) 最近一次重大更新？4) 社区问答响应速度？ |

### F7: 门禁联动可行性（可选）

#### 子因素：
- F7.1 主流门禁品牌 API 支持（HID、ZKTeco、Dahua、Hikvision 等）
- F7.2 认证协议（OAuth、Token、Webhook）
- F7.3 实时性要求（预约后多久内开通权限？）
- F7.4 故障降级策略（门禁失效时如何进入？）

#### 条件分类：
| 条件类型 | 内容 |
|----------|------|
| **人类已提供** | “可选”功能，非强制 |
| **可推导** | 若无原生支持，需开发中间件，增加成本与复杂度 |
| **仍需研究（空缺）** | [待研究] 候选系统与主流门禁品牌的集成案例 —— 子问题：1) 是否有官方连接器？2) 用户社区分享的实现方案？3) 额外开发成本估算？ |

## 5. 阶段 02 研究入口

### 第一批行动（按优先级排序）：

1. **识别候选系统列表**：
   - 搜索词：`"meeting room booking software for small teams"`、`"Google Calendar Outlook integration meeting room app"`、`"open source meeting room scheduler"`
   - 目标来源：G2, Capterra, Product Hunt, GitHub, 厂商官网
   - 预期产出：10-15 个候选系统清单，初步筛选出 5-8 个进入深度评估

2. **成本核验**：
   - 对每个候选系统，访问官网定价页，记录：
     - 免费计划限制（用户数、会议室数、功能）
     - 付费计划起步价（月付/年付）
     - 30 人规模的精确报价
     - 是否有隐藏费用（API 调用、存储、高级支持）
   - 备用来源：用户评论中的价格提及、Reddit/HN 讨论

3. **日历集成验证**：
   - 查阅各系统文档，确认：
     - 是否支持 Google Calendar OAuth
     - 是否支持 Microsoft 365/Outlook OAuth
     - 同步方向（单向/双向）
     - 同步频率（实时/定时）
     - 冲突解决策略
   - 搜索用户反馈：`"[system name] calendar sync issues"`、`"[system name] outlook conflict"`

4. **平台兼容性调研**：
   - 查阅各系统下载页/应用商店：
     - 是否有 macOS 原生客户端？
     - 是否有 Windows 原生客户端？
     - Web 端是否响应式？
   - 搜索用户评价：`"[system name] mac client experience"`、`"[system name] windows app review"`

5. **门禁联动探索**（低优先级，可延后）：
   - 搜索：`"[system name] access control integration"`、`"[system name] badge reader api"`
   - 查看是否有官方连接器或社区项目

### 失败备用路径：
- 若某系统官网信息不全 → 联系销售获取报价单（记录邮件往来）
- 若公开资料矛盾 → 以厂商官方文档为准，并标注不确定性
- 若无法找到足够独立来源 → 标记为“未解决”，并在风险清单中注明
