# 阶段 01：目标分解、已知与空缺条件

## 1. 目标交付物定义

**最终交付物**：一份包含以下三部分的选型报告工件：
1. **选型推荐**：针对30人研发团队（macOS/Windows/Web）的会议室预约系统具体产品/方案组合。
2. **成本表**：年度总成本 ≤ ¥20,000 的详细预算分配（含软件订阅、集成开发费、硬件门禁费等）。
3. **风险清单**：技术兼容性、数据隐私、供应商锁定、维护成本等关键风险及缓解措施。

**核心约束**：
- **人数**：30人研发团队（规模较小，非大型园区，无需复杂权限体系，但需高效协作）。
- **终端**：macOS / Windows / Web 三端全覆盖。
- **日历集成**：必须支持 Google Calendar + Outlook（双向同步或至少单向推送+冲突检测）。
- **门禁联动**：可选功能（若选，需评估额外硬件/接口成本）。
- **预算**：≤ ¥20,000 / 年（硬约束）。

### 顶层因素（正交覆盖）

| F2 | **日历集成能力** | 对Google Calendar和Outlook的支持深度（OAuth、双向同步、Webhook） | 高 |

### 递归分解：F1 软件平台选型

#### 子因素 F1.1：候选技术路线
- **路线A：成熟SaaS产品**（如：Roomle, OfficeTime, BookRoom, 钉钉/飞书会议室模块, 腾讯会议/Zoom Rooms）
- **路线B：开源/自托管方案**（如：Cal.com, Resource Planner, 自研基于Next.js+Postgres）
- **路线C：混合方案**（SaaS前端 + 自建后端逻辑，或反之）

> **待验证假设**：
> - H1.1a: 主流SaaS产品（Roomle等）是否提供中文界面及人民币支付？
> - H1.1b: 开源方案（Cal.com）是否原生支持Outlook集成？
> - H1.1c: 钉钉/飞书内置会议室功能是否满足独立预约需求，还是仅作为附属功能？

#### 子因素 F1.2：终端覆盖能力
- **Web端**：所有现代浏览器兼容。
- **macOS/Windows桌面端**：是否有原生客户端，还是仅通过Electron/PWA包装？
- **移动端**：iOS/Android App支持情况（虽未明确要求，但研发团队常需移动查看）。

> **待验证假设**：
> - H1.2a: 候选SaaS是否提供官方macOS/Windows桌面App？
> - H1.2b: PWA在macOS/Windows上的体验是否足够稳定（通知、离线）？

#### 子因素 F1.3：会议室管理功能
- 房间列表、容量显示、设备标签（投影仪、白板等）。
- 预约时段冲突检测。
- 取消/修改规则。
- 等待名单（Waitlist）支持。

---

### 递归分解：F2 日历集成能力

#### 子因素 F2.1：集成协议
- **OAuth 2.0**：标准授权流程。
- **CalDAV**：部分老系统使用，需确认候选方案是否支持。
- **Microsoft Graph API**：Outlook集成的现代标准。
- **Google Calendar API**：Gmail/GCal的标准接口。

#### 子因素 F2.2：同步方向与实时性
- **单向推送**：预约后推送到个人日历（简单，成本低）。
- **双向同步**：个人日历更改能反映到会议室系统（复杂，易冲突，成本高）。
- **实时性要求**：延迟 < 1分钟 vs < 1小时。

> **待验证假设**：
> - H2.1a: 候选方案是否同时支持Google Calendar API和Microsoft Graph API？
> - H2.1b: 双向同步是否产生额外费用（高级版功能）？
> - H2.1c: 是否存在“只读”集成模式以降低安全风险？

#### 子因素 F2.3：多账号支持
- 每个员工绑定自己的Google/Outlook账号。
- 管理员能否批量导入账号？

---

### 递归分解：F3 成本结构

#### 子因素 F3.1：软件许可费
- **按用户计费**：30人 × 单价。
- **按会议室计费**：N个会议室 × 单价。
- **一次性买断**：开源/自研无许可费，但有服务器成本。
- **免费额度**：是否有免费版限制功能（如最多5个会议室）？

> **待验证假设**：
> - H3.1a: Roomle/OfficeTime等SaaS的30人套餐价格是多少？
> - H3.1b: 钉钉/飞书专业版是否包含会议室功能，还是需额外付费？
> - H3.1c: Cal.com Cloud版的价格模型是什么？

#### 子因素 F3.2：基础设施成本（若自研/自托管）
- 云服务器（阿里云/AWS）：CPU/RAM/存储。
- 域名、SSL证书。
- 备份服务。

> **待验证假设**：
> - H3.2a: 运行Cal.com自托管实例所需的最低云资源配置及月费？

#### 子因素 F3.3：实施与定制开发费
- 初始配置时间（管理员设置房间、用户邀请）。
- 自定义UI/Logo（通常免费或小额）。
- API对接开发（若需对接内部系统）。

#### 子因素 F3.4：门禁联动成本（可选）
- **硬件**：智能门锁（如Aqara, Yale）单价 × 数量。
- **软件**：门禁系统API调用费或中间件开发费。
- **集成复杂度**：是否需要IoT网关？

> **待验证假设**：
> - H3.4a: 主流智能锁是否开放API供第三方预约系统调用？
> - H3.4b: 实现“预约成功自动解锁”的技术路径及大致成本？

---

### 递归分解：F4 门禁联动可行性

#### 子因素 F4.1：现有门禁现状
- **未知**：公司当前是否已有门禁系统？品牌型号？是否支持API？
- **若无**：需采购新硬件（智能锁）。

#### 子因素 F4.2：集成方式
- **直接API**：预约系统 ↔ 门禁厂商云平台。
- **中间件**：预约系统 → MQTT/Webhook → 本地控制器 → 门禁。
- **手动触发**：预约后生成二维码，员工扫码开门（降低自动化程度，但简化集成）。

> **待验证假设**：
> - H4.1a: 公司现有门禁系统是否具备API接口？（**关键空缺，需用户提供信息**）
> - H4.2a: 若采用二维码方案，主流SaaS是否支持生成动态二维码？

#### 子因素 F5.1：数据驻留
- SaaS数据存储位置（美国/欧洲/中国）。
- 中国《数据安全法》/《个人信息保护法》对跨境数据传输的要求。

> **待验证假设**：
> - H5.1a: 海外SaaS（Roomle等）在中国大陆访问速度如何？是否有国内节点？
> - H5.1b: 钉钉/飞书数据是否完全存储在境内？

#### 子因素 F5.2：隐私合规
- 员工日程数据敏感性。
- 访客信息管理（若有外部访客预约）。

### 递归分解：F6 用户体验与运维

## 3. 条件分类汇总

### A. 人类已提供的确定条件
1. 团队规模：30人。
2. 终端环境：macOS, Windows, Web。
3. 日历系统：Google Calendar + Outlook。
4. 预算上限：¥20,000 / 年。
5. 门禁联动：可选（非强制）。
6. 行业背景：研发团队（隐含：技术接受度高，可接受一定程度的自研或配置）。

### B. 可从项目推导的条件
1. **会议室数量估算**：30人团队，通常每5-8人共享一个中型会议室，预计需要 4-6 个会议室。（*注：此为经验值，需在阶段02确认实际房间数*）
2. **并发预约峰值**：早会、站会、评审会集中时段，系统需支持快速查询和抢占。
3. **网络环境**：办公室内网/公网均可访问Web端。

## 4. 阶段 02 研究路径与行动建议

### 第一批优先研究动作（对应高优先级空缺）

#### 动作 1：核验主流SaaS候选产品
- **目标对象类别**：国际通用型SaaS（Roomle, OfficeTime, BookRoom, Calendly for Teams）
- **目标来源类型**：
  1. 官方网站 Pricing 页面（获取最新价格）。
  2. 官方文档 Integration 章节（确认Google/Outlook支持）。
  3. G2/Capterra 评测网站（查看用户反馈，特别是关于稳定性和支持的评论）。
  4. 官网 FAQ 或 Trust Center（查看数据驻留和SLA）。
- **搜索词示例**：
  - `"Roomle pricing 30 users"`
  - `"OfficeTime Google Calendar Outlook integration"`
  - `"BookRoom China access speed"`
- **字段提取**：
  - 年费总额（USD/CNY）。
  - 是否包含双向同步。
  - 是否提供中文界面。
  - 数据中心位置。
- **失败备用路径**：若官网信息模糊，联系销售获取报价单（记录邮件往来）。

#### 动作 2：核验国内协同办公套件内置功能
- **目标对象类别**：钉钉、飞书、企业微信
- **目标来源类型**：
  1. 官方帮助文档（会议室管理模块）。
  2. 开发者社区（API文档）。
  3. 实际试用账号（申请试用，测试日历集成）。
- **搜索词示例**：
  - `"钉钉 会议室 预约 日历集成"`
  - `"飞书 会议室 外部日历 同步"`
- **字段提取**：
  - 是否支持独立于IM的会议室预约。
  - 是否支持与Google/Outlook双向同步。
  - 30人团队所需版本及价格。
- **失败备用路径**：若文档不全，咨询客户经理。

#### 动作 3：核验开源自托管方案成本
- **目标对象类别**：Cal.com, Resource Planner (open-source fork)
- **目标来源类型**：
  1. GitHub 仓库 README 和 Issues（查看Outlook集成状态）。
  2. Docker Hub 镜像大小和资源消耗。
  3. 云服务商（阿里云/AWS）轻量应用服务器定价页。
- **搜索词示例**：
  - `"Cal.com self-hosted cost AWS"`
  - `"Cal.com Microsoft Outlook integration issue"`
- **字段提取**：
  - 最低云配置（2vCPU/4GB RAM?）月费。
  - Outlook集成是否为实验性功能。
  - 社区活跃度（Star数、Commit频率）。
- **失败备用路径**：若开源方案不支持Outlook，标记为“不可行”，转向纯SaaS或自研。

#### 动作 4：门禁联动初步调研（若用户确认可选）
- **目标对象类别**：Aqara, Yale, 海康威视门禁
- **目标来源类型**：
  1. 产品官网 API 文档。
  2. 电商平台（京东/天猫）查看智能锁单价。
- **搜索词示例**：
  - `"Aqara smart lock API developer"`
  - `"Yale lock open API"`
- **字段提取**：
  - 是否有公开API。
  - 单把锁价格区间。
  - 集成难度评级（高/中/低）。
- **失败备用路径**：若无API，考虑“二维码开门”替代方案。

### 研究入口总结

阶段 02 应首先执行 **动作 1** 和 **动作 2**，因为这两类覆盖了最可能的解决方案（专用SaaS vs 现有办公套件），且直接影响预算和技术可行性。动作 3 和 4 可作为并行任务或后续补充。
