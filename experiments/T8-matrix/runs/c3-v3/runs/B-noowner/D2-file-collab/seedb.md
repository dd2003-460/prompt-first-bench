# 阶段 01：目标分解、已知与空缺条件

## 1. 目标交付物定义
**核心目标**：为 20 人混合办公团队选定一款团队协作网盘，并输出包含 **3 个候选对比**、**TCO（总拥有成本）估算** 和 **迁移风险评估** 的完整决策工件。

**关键约束（硬性边界）**：
- **用户规模**：20 人。
- **功能底线**：必须支持版本管理、外链分享权限控制、离线同步。
- **预算上限**：≤ $8/人/月（即月度总预算 ≤ $160）。
- **架构备选**：数据可自托管（Self-hosted）作为备选路径。
- **输出要求**：完整工件，含来源索引、矛盾处置、不确定性标注，不可仅给结论。

## 2. 顶层影响因素分解（正交覆盖）

为了达成上述目标，任务被分解为以下 5 个互相正交的顶层影响因素。这些因素合起来覆盖了从“选型”到“落地”再到“成本核算”的全过程。

### 因素 A：候选对象筛选与功能合规性 (Candidate Selection & Feature Compliance)
*   **定义**：识别满足所有硬性功能约束（版本管理、外链权限、离线同步）且符合预算或自托管能力的候选产品类别及具体产品。
*   **子因素分解**：
    *   A1: **SaaS 云服务商候选集**：需筛选出单价 ≤ $8/人/月 的主流 SaaS 网盘。
    *   A2: **自托管软件候选集**：需筛选出具备企业级功能（权限、审计、同步客户端）的开源自托管网盘。
    *   A3: **功能映射矩阵**：将“版本管理”、“外链细粒度权限”、“离线同步稳定性”三个硬指标映射到每个候选的具体实现方式。
    *   A4: **排除逻辑**：明确哪些常见网盘因不满足某项硬指标而被排除（例如：某些网盘免费版无版本历史，或自托管版缺乏原生桌面客户端）。

### 因素 B：总拥有成本 (TCO) 建模 (Total Cost of Ownership Modeling)
*   **定义**：基于候选对象，计算 20 人团队的年度/月度实际支出，涵盖直接费用与隐性运维成本。
*   **子因素分解**：
    *   B1: **SaaS 直接订阅费**：License 费用 × 20 人。需注意阶梯定价（Tiered Pricing）是否导致人均成本突破 $8。
    *   B2: **存储容量溢价**：基础套餐容量是否足够？若不够，扩容包的成本是多少？
    *   B3: **自托管基础设施成本**：服务器硬件/云主机租赁费、带宽费、域名费。
    *   B4: **人力运维成本折算**：自托管所需的 IT 维护时间（备份、升级、故障排查）折算为机会成本。
    *   B5: **集成与插件成本**：是否需要付费插件才能实现特定的权限控制或版本管理高级功能。

### 因素 C：迁移风险与实施复杂度 (Migration Risk & Implementation Complexity)
*   **定义**：评估从当前状态（假设通用起点）迁移至新网盘的技术难度、数据丢失风险和业务中断时间。
*   **子因素分解**：
    *   C1: **数据迁移工具可用性**：是否有官方 CLI/API 支持批量导入/导出？
    *   C2: **元数据保留能力**：文件修改时间、创建者、文件夹结构、共享链接能否完整迁移？
    *   C3: **并发同步冲突机制**：多端同时编辑时的合并策略及其对业务的干扰程度。
    *   C4: **回滚方案可行性**：若新系统失败，数据能否快速迁回旧系统？

### 因素 D：安全、合规与数据主权 (Security, Compliance & Data Sovereignty)
*   **定义**：评估数据安全性、隐私政策及是否符合“数据可自托管”的战略需求。
*   **子因素分解**：
    *   D1: **传输与静态加密标准**：TLS 版本、AES-256 等标准的支持情况。
    *   D2: **访问控制粒度**：是否支持部门级、项目级隔离，而不仅仅是个人账号。
    *   D3: **审计日志能力**：谁在何时下载/删除了文件，是否可查询。
    *   D4: **数据驻留地**：SaaS 数据中心位置是否符合团队所在地的法律要求（虽未指定国家，但需列为待研究变量）。

### 因素 E：用户体验与协作效率 (User Experience & Collaboration Efficiency)
*   **定义**：评估非技术成员的使用门槛及混合办公场景下的协作流畅度。
*   **子因素分解**：
    *   E1: **客户端跨平台兼容性**：Windows/macOS/Linux/iOS/Android 客户端的功能一致性。
    *   E2: **大文件传输体验**：断点续传、限速策略对混合办公网络环境的影响。
    *   E3: **在线预览与编辑能力**：是否支持 Office/PDF 在线编辑，还是仅能下载后编辑。

## 4. 空缺清单与阶段 02 研究入口

为了确保阶段 02 可以直接开始行动，以下是针对上述空缺的具体研究路径设计。

### 4.1 候选对象初步假设（待验证）
*注意：以下为基于行业常识的**初始假设集合**，用于指导搜索，**并非**最终确认的合格候选。阶段 02 必须逐一核验其是否符合 K3-K6 约束。*

**SaaS 类候选假设：**
1.  **Dropbox**: 假设 Team Plan 可能超出 $8/人/月，需核验 Business Standard 起步价。
2.  **OneDrive for Business (Microsoft 365)**: 假设捆绑销售，需单独核算仅含 OneDrive 功能的最低套餐。
3.  **Google Workspace (Drive)**: 假设 Business Starter/Standard 套餐价格在 $6-$12 区间，需核验 20 人档位的具体单价。
4.  **Box**: 假设入门版价格较高，可能超预算，需核验。
5.  **Proton Drive**: 假设较新的竞争者，价格可能有优势，需核验功能完整性。

**自托管类候选假设：**
1.  **Nextcloud**: 开源免费，但企业功能（如高级版本控制、审计）可能需要付费 App 或 Enterprise License。需核验社区版是否满足 K3-K5。
2.  **Seafile**: 开源，强调高性能同步。需核验其权限控制和版本管理深度。
3.  **Synology Drive Server**: 依赖硬件（NAS），软件许可免费但硬件成本高。需核验 20 人并发下的 NAS 最低配置及成本。
4.  **OwnCloud**: 类似 Nextcloud，需对比两者在当前市场的活跃度与支持力度。

### 4.2 阶段 02 具体研究动作与来源类型

#### 研究任务 R1：SaaS 价格与功能核验 (对应 U1, U3, U4)
*   **目标**：确定 3 个最有可能入选的 SaaS 候选。
*   **搜索词示例**：
    *   `"Dropbox Business pricing 2024 per user"`
    *   `"Microsoft 365 Business Basic OneDrive price 20 users"`
    *   `"Google Workspace Business Starter price 2024"`
    *   `"Best cloud storage for teams under $8 per user 2024"`
*   **目标来源类型**：
    *   官方定价页面 (Official Pricing Pages) - *最高优先级*
    *   独立评测网站 (e.g., PCMag, TechRadar, G2 Reviews) - *用于交叉验证功能描述*
    *   近期新闻稿 (Press Releases) - *用于捕捉价格变动*
*   **核验字段**：
    *   20 人规模的月度总价。
    *   是否包含“版本历史” (Version History)。
    *   是否包含“外部共享链接设置” (External Sharing Settings)。
    *   是否提供全平台桌面客户端 (Desktop Clients)。
*   **失败备用路径**：若官网无法直接显示 20 人定制价，记录标准列表价，并标记为“需联系销售确认”，在 TCO 中按列表价上限估算。

#### 研究任务 R2：自托管方案成本与功能核验 (对应 U2, U5)
*   **目标**：确定 1-2 个可行的自托管候选，并估算基础设施成本。
*   **搜索词示例**：
    *   `"Nextcloud vs Seafile enterprise features comparison"`
    *   `"Nextcloud version history limit community edition"`
    *   `"VPS hosting cost for 20 users file server 2024"`
    *   `"Synology DS920+ or DS1522+ price 2024"`
*   **目标来源类型**：
    *   GitHub 仓库 README / Official Docs - *用于确认功能边界*
    *   云服务商 (AWS/Azure/GCP/DigitalOcean) 定价计算器 - *用于估算 VPS 成本*
    *   电商网站 (Amazon/Newegg) - *用于估算物理 NAS 硬件成本*
*   **核验字段**：
    *   社区版/开源版是否原生支持“无限版本历史”或“可配置版本数”。
    *   是否原生支持“细粒度外链权限”（如只读、禁止下载、密码保护）。
    *   推荐的最低服务器配置 (CPU/RAM/Disk) 以支撑 20 人并发。
*   **失败备用路径**：若某开源软件的高级功能需付费插件，将其计入 TCO 的“软件许可费”；若无可靠硬件成本数据，采用中等配置的云服务器作为基准估算。

#### 研究任务 R3：迁移风险与技术细节 (对应 U6, U7)
*   **目标**：评估迁移难度。
*   **搜索词示例**：
    *   `"How to migrate from Dropbox to Google Drive tool"`
    *   `"Nextcloud migration assistant documentation"`
    *   `"Cloud storage conflict resolution strategy multi-device"`
*   **目标来源类型**：
    *   官方文档 (Documentation) - *关于迁移 API 和冲突处理*
    *   技术博客/StackOverflow - *关于实际迁移中的坑*
*   **核验字段**：
    *   是否存在一键迁移工具。
    *   元数据（权限、标签）是否随文件迁移。
    *   冲突文件的命名规则和处理逻辑。

### 4.3 阶段 02 的第一批行动建议

1.  **并行执行 R1 和 R2**：因为 SaaS 和自托管是两条独立的技术路径，可以同时进行资料搜集。
2.  **优先锁定 SaaS 候选**：由于 SaaS 无需考虑硬件运维，决策链路较短，先完成 SaaS 的 3 选 1 或 3 选 2，再补充 1 个自托管选项作为对比组，这样更符合“3 候选对比”的要求（通常建议 2 SaaS + 1 Self-hosted 或 1 SaaS + 2 Self-hosted，取决于哪边更有竞争力）。
3.  **建立对比表格骨架**：在搜集过程中，立即填充以下字段：`产品名称`, `类型(SaaS/Self-hosted)`, `人均月费`, `版本管理详情`, `外链权限详情`, `离线同步客户端`, `迁移工具`, `主要风险`。
