# 阶段 01：目标分解、已知与空缺条件

## 1. 目标交付物定义
**核心交付物**：一份针对 20 人混合办公团队的网盘选型报告，包含以下四个具体组件：
1. **3 个候选方案对比矩阵**：基于版本管理、外链分享权限控制、离线同步三大功能维度。
2. **TCO（总拥有成本）估算**：在预算 ≤$8/人/月（即 $160/月总额）约束下的 1-3 年成本模型。
3. **迁移风险评估**：从当前未知状态（或假设通用状态）迁移到候选方案的潜在风险点及缓解措施。
4. **自托管备选方案说明**：明确哪些候选支持自托管，及其对“数据可自托管”这一需求的满足程度。

**关键约束**：
- 团队规模：20 人。
- 工作模式：混合办公（意味着离线同步和跨设备一致性至关重要）。
- 硬性预算上限：$8/人/月（SaaS 视角）或等效的自托管运维成本折算。
- 功能硬性要求：版本管理、外链分享权限控制、离线同步。
- 战略要求：数据可自托管（作为备选或主要路径）。

## 2. 因素分解树（递归结构）

### 顶层因素（正交覆盖）

#### A. 功能合规性 (Functional Compliance)
*   **A1. 版本管理深度**
    *   *子因素 A1.1*: 历史版本保留策略（无限 vs 有限天数/数量）。
    *   *子因素 A1.2*: 版本恢复粒度（文件级 vs 文件夹级 vs 全局快照）。
    *   *子因素 A1.3*: 版本冲突处理机制（自动合并 vs 副本创建）。
    *   *[待研究]*: 各候选在 A1.1-A1.3 的具体实现差异。
*   **A2. 外链分享权限控制**
    *   *子因素 A2.1*: 链接类型控制（仅查看/可编辑/密码保护/有效期）。
    *   *子因素 A2.2*: 细粒度权限（能否限制特定 IP/域名访问？能否禁止下载仅预览？）。
    *   *子因素 A2.3*: 审计日志（谁分享了什么给谁，何时过期）。
    *   *[待研究]*: 各候选在 A2.1-A2.3 的控制力层级。
*   **A3. 离线同步能力**
    *   *子因素 A3.1*: 客户端平台覆盖（Win/Mac/Linux/iOS/Android/Web）。
    *   *子因素 A3.2*: 选择性同步（Selective Sync）支持（大文件/敏感目录排除）。
    *   *子因素 A3.3*: 冲突解决逻辑（Last Write Wins vs User Resolution）。
    *   *子因素 A3.4*: 弱网环境下的同步稳定性（断点续传、增量同步效率）。
    *   *[待研究]*: 各候选在 A3.1-A3.4 的实际表现，特别是 Linux 客户端支持情况（混合办公常见痛点）。

#### B. 部署架构与数据主权 (Deployment & Sovereignty)
*   **B1. SaaS 模式可用性**
    *   *子因素 B1.1*: 官方云存储区域选择（数据驻留地）。
    *   *子因素 B1.2*: SLA 保证（可用性百分比、故障赔偿条款）。
    *   *[待研究]*: 各候选 SaaS 版的数据驻留选项及 SLA 细节。
*   **B2. 自托管可行性 (Self-Hosting)**
    *   *子因素 B2.1*: 开源协议与许可限制（AGPL vs MIT vs Proprietary On-Premise License）。
    *   *子因素 B2.2*: 部署复杂度（Docker/K8s 依赖、数据库要求、最小硬件配置）。
    *   *子因素 B2.3*: 功能完整性差距（自托管版是否缺失 SaaS 版的高级功能，如 AI 搜索、高级权限）。
    *   *子因素 B2.4*: 社区/厂商支持级别（LTS 版本周期、安全补丁频率）。
    *   *[待研究]*: 各候选自托管版的真实功能阉割情况及运维负担评估。

#### C. 经济性与 TCO (Economics & TCO)
*   **C1. 直接订阅成本 (SaaS Path)**
    *   *子因素 C1.1*: 标准定价（Per user/month）。
    *   *子因素 C1.2*: 存储配额限制（GB/TB per user 或 team pool）。
    *   *子因素 C1.3*: 超额费用（超量存储/流量费）。
    *   *[待研究]*: 20 人规模下，满足基本存储需求（假设人均 50GB-100GB）的最便宜套餐价格。
*   **C2. 自托管隐性成本 (On-Premise Path)**
    *   *子因素 C2.1*: 基础设施成本（服务器/云 VPS 租金、带宽、备份存储）。
    *   *子因素 C2.2*: 人力运维成本（IT 人员时间折算，包括升级、监控、故障排查）。
    *   *子因素 C2.3*: 许可证成本（若为商业软件需购买 On-Premise License；若开源则主要为运维成本）。
    *   *[待研究]*: 运行一个稳定服务 20 人的自托管实例所需的最低硬件/云资源规格及月度成本。

#### D. 迁移与连续性风险 (Migration & Continuity Risk)
*   **D1. 数据迁移难度**
    *   *子因素 D1.1*: 导入工具链（是否有官方 CLI/API 批量导入现有网盘数据）。
    *   *子因素 D1.2*: 元数据保留（修改时间、权限组、共享链接是否能在迁移中保留）。
    *   *[待研究]*: 主流竞品（如 Dropbox, OneDrive, Google Drive）到候选方案的迁移工具成熟度。
*   **D2. 锁定效应 (Vendor Lock-in)**
    *   *子因素 D2.1*: 数据导出格式（原始文件 vs 专有格式）。
    *   *子因素 D2.2*: API 开放程度（能否通过 API 完全重建外部系统）。
    *   *[待研究]*: 各候选在退出时的数据提取便捷性。

## 4. 候选对象初步筛选逻辑（阶段 02 研究入口）

由于阶段 01 不执行搜索，此处仅建立**候选类别假设**，供阶段 02 验证并冻结最终 3 个候选。

**筛选逻辑**：
1.  **必须支持自托管**：排除纯闭源 SaaS（如 Microsoft OneDrive, Dropbox Business, Box）。
2.  **必须支持版本管理与外链**：排除仅做文件同步的工具（如 Syncthing 虽强于同步但缺乏中心化管理和外链权限 UI，通常不作为“团队协作网盘”的首选，除非配合 Nextcloud 等前端）。
3.  **市场知名度与社区活跃度**：确保有足够的文档和社区支持以降低运维风险。

**假设候选类别（待阶段 02 验证具体型号/版本）**：

*   **候选类别 1: Nextcloud**
    *   *理由*：开源标杆，功能全面（版本、外链、Office 集成），自托管生态极成熟，有商业 SaaS 版本（Nextcloud Hub）。
    *   *待验证假设*：Nextcloud SaaS 版价格是否在 $8/user 内？自托管版性能如何？
*   **候选类别 2: Seafile**
    *   *理由*：以高性能同步著称，底层引擎强大，提供专业版 SaaS 和企业版自托管。
    *   *待验证假设*：Seafile 的免费版/基础版是否包含所需的所有功能？SaaS 价格？
*   **候选类别 3: OwnCloud**
    *   *理由*：Nextcloud 的前身，仍有大量存量用户，提供 SaaS 和 Enterprise 自托管。
    *   *待验证假设*：OwnCloud 近年发展停滞吗？其 SaaS 价格竞争力？
*   **备选/干扰项检查**：
    *   *Syncthing*：无中心服务器，难以实现“统一外链分享权限管理”和“集中版本库”，通常被排除出“协作网盘”范畴，归为点对点同步工具。
    *   *Bitwarden/1Password*：非网盘，排除。
    *   *Google Workspace/MS 365*：不支持自托管，排除。

**阶段 02 行动指令**：
1.  验证 Nextcloud, Seafile, OwnCloud 是否为当前最佳 3 候选。
2.  若发现更优候选（如 Zoho WorkDrive 若有自托管？通常没有；Turtl? 小众），需记录替换理由。
3.  收集上述 3 个候选在 U2-U7 空缺条件下的具体数据。

## 5. 阶段 02 具体研究路径

### 研究任务 1：功能合规性核验 (U3, U5)
*   **目标**：确认 Nextcloud, Seafile, OwnCloud 的自托管版和 SaaS 版是否均支持：
    *   版本历史保留（天数/数量限制）。
    *   外链分享（密码、有效期、只读/可写）。
    *   离线同步客户端（Win/Mac/Linux）。
*   **来源类型**：
    *   官方文档（Documentation）：查找 "Versioning", "Sharing", "Client Support" 章节。
    *   官方 GitHub 仓库：查看 Issue 跟踪中关于功能缺失的报告。
    *   独立评测博客：TechCrunch, The New Stack, 或专门评测 Nextcloud/Seafile 的技术博客。
*   **搜索词示例**：
    *   `"Nextcloud self-hosted versioning limit"`
    *   `"Seafile external link sharing permissions"`
    *   `"OwnCloud linux desktop client support 2024"`
*   **失败备用路径**：若官方文档模糊，查阅 GitHub Discussions 或 Reddit r/selfhosted 板块的用户反馈。

### 研究任务 2：SaaS 定价核验 (U2)
*   **目标**：获取 20 人规模的月度/年度价格。
*   **来源类型**：
    *   官方网站 Pricing Page。
    *   G2/Capterra 上的用户评论中提到的价格信息（作为交叉验证）。
*   **搜索词示例**：
    *   `"Nextcloud SaaS pricing per user 2024"`
    *   `"Seafile professional plan price"`
    *   `"OwnCloud business edition cost"`
*   **注意**：区分 "Free Tier" 与 "Paid Tier"。免费层通常有存储限制或功能阉割，需确认 20 人团队是否需要付费才能解锁全部功能。

### 研究任务 3：自托管 TCO 估算 (U4)
*   **目标**：估算运行 20 人实例的云资源成本。
*   **方法**：
    1.  查找官方推荐的最低硬件配置（CPU, RAM, Disk IOPS）。
    2.  假设存储量为 20 users * 50GB = 1TB（保守估计），加上冗余（RAID/LVM）需 2TB 物理空间。
    3.  查询 AWS Lightsail, DigitalOcean, Hetzner 等低成本云服务商的对应实例价格。
    4.  计算带宽成本（假设每月 100GB 入站/出站）。
*   **来源类型**：
    *   官方部署指南（Hardware Requirements）。
    *   云服务商定价计算器（AWS, DO, Hetzner）。
    *   社区基准测试文章（Benchmarking Nextcloud on VPS）。

### 研究任务 4：迁移风险与锁定 (U6, D2)
*   **目标**：评估从现有系统迁移的难度。
*   **来源类型**：
    *   官方 Migration Guide。
    *   第三方迁移工具网站（如 CloudMigrator, Mover.io 是否支持这些目标）。
    *   开发者论坛关于 API 限制的讨论。

## 6. 矛盾处置与不确定性标注原则

1.  **价格波动**：SaaS 价格经常调整。阶段 02 必须注明“观察日期”。若官网价格与第三方聚合网站（如 G2）不一致，以官网为准，但需标注差异。
2.  **功能描述歧义**：例如“版本管理”在不同产品中含义不同（有的只保留最后 10 个版本，有的无限保留）。阶段 02 必须引用具体参数（如 "retains versions for 30 days"），避免使用模糊词汇。
3.  **自托管 vs SaaS 功能不对等**：这是最大的风险点。如果某产品 SaaS 版有高级权限控制，但自托管版没有，必须在报告中显著标注：“自托管备选方案存在功能降级风险”。
4.  **TCO 模型简化**：阶段 01 不计算具体数字，但阶段 02 必须建立公式：
    *   `SaaS_TCO = (Price_per_user * Users) * Months`
    *   `SelfHosted_TCO = (Cloud_Resource_Cost + Backup_Cost) * Months + (IT_Hours * Hourly_Rate)`
    *   其中 `IT_Hours` 是一个假设值（如 2 hours/month），需在报告中注明此假设的可变性。
