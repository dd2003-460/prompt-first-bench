# Rubric 设计迭代史（v2 → v11）

> origin: ai · 2026-10-31 r62w · 来源：rubric-v2-density-test.json + 各版本 sweep 回执

## 设计目标

C3 v3 消融实验需要区分「真实执行了核验工作」与「结构完整但内容空转」的工件。核心挑战：sham 配置（等长填充文本替换真实指令）产出的工件在结构上与真实配置几乎相同，只有内容密度和特异性有差异。

## 十轮迭代

| 版本 | 规则名 | 核心机制 | sham gap | freeze rank | 判定 |
|---|---|---|---|---|---|
| v2 | 密度审计 | 空转检测（信息密度低 → fail） | -0.045 | 1/9 | 可用密度参照 |
| v3 | anti-template | 模板句检测（重复句式 → fail） | -0.478 | 2/9 | 诊断用（误杀 75%） |

## 设计轨迹分析

### 第一阶段：直接检测（v2-v4）
- v2 试图直接度量信息密度 → 太宽松，sham 也能维持表面密度
- v3 试图检测模板化句式 → 太严格，真实工件也有重复句式（误杀 75%）
- v4 试图用「零数值断言」抓空转 → sham 编造具体数字（如 "Zapier $30/mo"）绕过

### 第二阶段：语义区分（v5-v6）
- v5 试图区分「计划」和「发现」→ 模型自然用未来时态描述推理过程，导致全场归零
- v6 加例外：带具体参数的计划句算发现 → 修复了 v5 的过度修正，但 sham 的编造参数也过了

### 第三阶段：间接信号（v7-v10）
- v7 度量「回声率」（复述 prompt 内容的比例）→ sham 回声率高，分离成功
- v8 检测「冻结痕迹」（引用不存在的上下文）→ 模型不会真的引用不存在的东西，失效
- v9 检测「方法回声」（复述方法论而非执行结果）→ 真实工件也包含方法论描述，失效
- v10 度量「指令依赖度」→ A-full 得分 1.0（天花板坍缩），无法区分顶部

### 第四阶段：指纹法（v11）
- v11 不试图理解内容语义，而是统计「具体性指纹」：含具体数字/型号/字段名的句子占比
- 真实工件：高占比（引用真实数据点）
- Sham 工件：低占比（填充文本没有真实数据点，即使编造数字也是孤立的）
- 阈值 0.2 是校准出来的：低于此值 → floor_fail

## 为什么 v11 赢

1. **不依赖语义理解**：LLM judge 对「这句话是不是真发现」的判断不稳定，但对「这句话里有没有具体数字」的判断稳定
2. **sham 的结构性弱点**：填充文本可以模仿句式结构，但很难模仿数据密度
3. **无误杀**：真实工件天然包含大量具体数据点，不会触发 floor
4. **可解释**：floor_fail 的原因可以直接指出哪些句子缺乏具体性
