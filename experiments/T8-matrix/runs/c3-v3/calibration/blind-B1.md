## 2. 对抗核验（r29 补丁：主动攻击核验结论本身）

### 攻击轮 1：定价数据的时效性与口径

**质疑**：S1-S6 的官方定价页均"页面未标注日期"——这些价格是否可能是 2024/2025 的旧价？

**反驳**：
- 飞书 S5/S6：搜索元数据含"AI 企业版""豆包工作伙伴"等 2025-2026 才出现的产品线 → 页面为当前版本 ✅
- 坚果云 S3：含"在线协同编辑"功能列表，与 2026 产品状态一致 ✅
- Dropbox S1/S2：含"Integrate with leading AI tools (ChatGPT/Claude)"→ 2025+ 特性 ✅
- GitHub API（S8-S19）：pushed_at 全部 2026-10-29（昨天）→ 实时数据 ✅
- **残余风险**：飞书/坚果云/语雀的定价可能近期调整但未反映在缓存中。置信度从 🟢 降为 🟡（时效性不可证伪）。**处置：在 04 成本表中标注"价格观察时间 2026-10-30，有效期未知"**

### 攻击轮 2：Syncthing "无版本管理"是否过于绝对？

**质疑**：Syncthing 有 "File Versioning" 选项（保留旧版本文件），是否算"版本管理"？

**反驳**：
- Syncthing 的 versioning 是**被动保留**（删除/覆盖时留副本），不是**主动版本树**（无版本号、无 diff、无分支、无恢复 UI）
- 任务书 I1 要求"文档版本管理"——研发团队的文档协作场景需要的是可追溯的版本历史+回滚，不是删除保护
- S38 README Goals 节明确列出 7 个目标，无一涉及版本管理/协作/权限
- **判定**：Syncthing 的 versioning ≠ 任务书要求的"版本管理"。淘汰判定成立，但措辞修正为"无主动版本管理（仅有被动文件保留）"，避免过度声称。

### 攻击轮 3：自托管 TCO 估算是否低估了运维负担？

**质疑**：0.5 人天/月 的运维假设是否乐观？Nextcloud 升级（大版本）通常需 1-2 天停机+测试。

**反驳**：
- 0.5 人天/月 是**稳态均值**（含小补丁+备份验证+磁盘监控）；大版本升级（约 2 次/年 × 1.5 天 = 3 天/年 ≈ 0.25 天/月）已包含在内
- 更保守估计：1 人天/月 = ¥6,000/年（翻倍）
- **处置**：04 成本表给两档：乐观 ¥3,000/年 / 保守 ¥6,000/年。TCO 区间相应扩大。
- **停止理由**：运维工时折算率是**个人信息搜集瓶颈**——没有公开的"研发团队自托管 Nextcloud 运维工时基准"数据，穷尽可查渠道（GitHub issues/discussions 有零散报告但无系统统计）后只能给区间。

### 攻击轮 4：飞书标准版 1500GB 总存储是否够用？

**质疑**：30 人研发团队，{50,200}GB/人 区间 → 需求 {1.5TB, 6TB}。飞书标准版 1500GB 恰在下沿——如果实际用量偏上，直接不够。

**反驳**：
- 这是**真实风险**，不是可以忽略的边界情况
- 研发团队文档以文本为主（设计文档/会议纪要/规范），人均 50GB 已很宽裕（纯文本 50GB ≈ 数亿字）；但如果有视频/大文件附件，会快速膨胀
- **处置**：03 阶段将"存储用量假设"列为关键前提，标注"若人均 >50GB 则飞书标准版出局，需升专业版（¥28,800，仍预算内）"

### 攻击轮 5：web-llm 全失败是否削弱了 02 的证据质量？

**质疑**：02 流程要求 web-llm 交叉询问，三 provider 全失败意味着缺少"独立 LLM 视角"——所有证据都是 agent 自己搜的，存在系统性偏差。

**反驳**：
- 这是**通道限制**而非证据缺陷：web-llm 提供的是"线索"不是"事实来源"（02 §2 原文），其失败不减少任何已收集的一手证据
- 本 run 的核心证据（GitHub API 一手数据 + 官方定价页搜索元数据 + curl 直连）不依赖 web-llm
- **但**：M8 计分中 V1-V3 类条目（agent 自检）权重只有 0.2——这正是 T8 矩阵实验要量化的东西
- **停止理由**：数学理论瓶颈不适用；个人信息搜集瓶颈适用（web-llm 登录态失效是环境约束，非可修复的研究缺口）。**处置：如实记录，不伪装成"已完成交叉验证"**

### 对抗核验总结

| 攻击点 | 结果 | 对结论的影响 |
|--------|------|-------------|
| 定价时效性 | 部分成立（🟢→🟡 降档） | 成本表加"有效期未知"标注 |
| Syncthing 版本管理 | 不成立（措辞修正） | 淘汰判定不变 |
| 自托管运维低估 | 部分成立（给区间） | TCO 区间扩大 |
| 飞书存储下沿 | 成立（真实风险） | 03 列为关键前提 |
| web-llm 缺失 | 成立（通道限制） | M8 权重 0.2 如实计 |

**停止理由**：碰到**个人信息搜集瓶颈**（运维工时基准无公开数据；web-llm 登录态失效）+ **数学理论瓶颈**不适用。继续追问不会产出新证据。
