## 剩余两个 FAIL 的结构性诊断

### AC3：J2 宽容设计 vs B-none 地板
B-none/D1/seeda 和 seedb 的工件形态：有具体产品名+价格数字（飞书 ¥298/人/年、Roomle $15–25/room/month），但零 URL、零实抓证据。
- J1-v3.1f 正确判 fail（A 级：无显式来源标记）→ 0.083 < 0.3 ✓
- J2-lenient-v3 按设计放过（「宽容但诚实」：内容具体就算数）→ 0.5 ✗
这不是 bug 是设计：J2 的存在意义就是给 J1 当宽容对照组。若把 J2 也改严，双判官退化成同源复读机，AC1 的测量意义消失。**AC3 的 <0.3 阈值对 J2 天然不成立，应只对 J1 生效**（或改为「J1 均值 <0.3 且 J2 均值 < J1 均值 + 0.5」）。

### AC4：条目级 pass/fail 粒度的天花板
B-2del-eo 删的是 evidence/owner 字段——在「逐条目过不过三测」的粒度下，这些删除项恰好不在判定的关键路径上（条目主体内容还在），所以 B-2del-eo 拿满分甚至反超 A-full（64 条 vs 26 条，分母效应）。
**AC4 需要的不是更严的 judge，而是不同的评分维度**：要么条目级加权（evidence 缺失的条目降权计分），要么换配置对（用 B-2del-fe 这种删功能证据的做负例，它的 canon 只有 6-13 ids 且分数确实更低）。

## 结论与建议
1. **rubric v3 作为「一致性 rubric」达标**：AC1 0.96 + AC2 PASS + 越界 id 清零。v2 的两个根因都修掉了。
2. **AC3/AC4 暴露的是验收标准与 rubric 目标的错位**，不是 judge 还能再调的问题。继续拧 J1/J2 的 prompt 只会破坏已经达标的 AC1（r4 已实证：一放松 AC1 立刻从 0.96 掉到 0.77）。
3. 建议下一步（需成璐拍板，属验收口径变更）：
   - AC3 改为「J1 均值 <0.3」（J2 豁免或单独设阈值）；
   - AC4 换负例配置（B-2del-fe）或引入条目加权；
   - 或者接受现状：v3 用于「双判官一致性测量」场景，区分度场景另配 rubric。
