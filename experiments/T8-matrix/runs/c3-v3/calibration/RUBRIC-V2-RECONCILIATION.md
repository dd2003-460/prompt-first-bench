# Rubric v2 重放对账分析（r246 · 2026-11-02）

> 动机：r245 全量重放 overall_pass=False（AC1 一致率 0.661 < 0.85），但当时只做了粗粒度诊断。
> 本轮做零成本对账（不调模型）：把 v2 判官分数与旧版 r4 判官分数逐 run 对照，
> 定位"分歧大"到底是 rubric 修坏了，还是评分对象本身没对齐。

## 核心发现：问题不在判官尺度，在评分对象

**工件的条目编号不统一**。36 个 run 里只有 21 个（58%）带稳定编号条目
（X1..Xn / A1..An / GAP-01..），其余 15 个是自由格式（"主张 1/2/3"、无编号段落）。
两个判官都被告知"用原文 id"，遇到无编号工件就各自自造清单——
J1 造 X1..X4，J2 造 X1..X8，比的是两张不同的卷子。

### 证据 1：AC1 一致率按 config 分层（v2 receipt 数据）

| config | 一致率 | 工件编号情况 |
|--------|--------|--------------|
| B-2del-fe | 1.00 | 有编号 (A1-A8/F1-F4) |
| B-noevidence | 1.00 | 混合 |
| B-noowner | 1.00 | 有编号 |
| B-nofreeze | 0.80 | **无编号**（自由格式） |
| B-none | 0.33 | **无编号**（自由格式） |
| B-sham | 0.30 | 混合 |
| A-full | 0.62 | 混合（seedb 有 34 条编号，seeda 只有 OQ-1..5） |
| B-2del-eo | 0.76 | 有编号 |

低一致率的组几乎全是"无编号工件 + 判官自造 id"的组；有编号的组基本满分。
→ 0.661 的整体一致率主要是 id 不对齐拖下来的，不是判定标准分歧。

### 证据 2：J1-v2 相对旧版 J1 系统性打崩（新旧方向一致仅 3/21）

有编号工件上，J1-strict-v2 的分数 vs 旧版 J1（r4 落盘 raw 复算）：
- 旧版 J1 均值区间 0.30–1.00，v2 大量归零：B-noowner/D2 两个 seed 从 1.0/0.88 → 0.0/0.0，
  B-sham/D2 从 0.83/1.0 → 0.0/0.0，A-full/D1-seedb 从 0.62 → 0.0。
- 根因：v2 新增的 ①来源真实性硬判据（假设性链接直接 fail）+ R-A（保留措辞不豁免）
  组合后，几乎所有"标注了待验证/假设性"的条目全灭，而 r6 这批工件恰好普遍
  带着"需实际抓取/假设性链接"标记（web-llm 通道 down 的产物）。
  旧版三测没有这条硬判据，所以分数正常分布。
- 副作用：AC3（B-none 地板 <0.3）和 AC4（A-full − B-2del-eo ≥0.3）失败的主因
  就是 J1 把 A-full 也打到 0.371——区分度塌了，不是 J2 天花板的问题。

### 证据 3：J2-v2 相对旧版 J2 变化有限（平均 |Δ|=0.37，主要由无编号组贡献）

有编号工件上 J2 基本保持 1.0（天花板效应依旧）；无编号工件上 J2 新分数
0.0–1.0 波动大，是因为它自造的 id 集合每次不同，分数方差来自抽样而非判定。

### 证据 4：parse 失败 7/36 全在 J1 侧

全部 7 个 parse_ok=False 都是 J1-strict-v2（latency 1.0s–93.7s 不等，含 1s 秒回，
疑似输出被截断或 JSON 漂移）。J2 无一失败。进一步压低 AC1 有效分母。

## 结论

rubric v2 的"双判官硬判据对齐"思路没错，但两个执行层缺陷让它不可用：
1. **评分对象未规范化**：判官打分前应先抽取统一的条目清单（id 锚定），
   否则一致性指标衡量的是"两个 LLM 会不会编出同样的编号"，不是判定一致性。
   实测：628 条判官判定里 35.2% 的 id 不在工件正文里（自造/幻觉）；
   严格口径（只算两判官都落在工件清单内的 id）一致率 0.644，与原口径 0.661 几乎不变——
   说明 id 不对齐只是噪声源之一，判定标准本身也有真分歧。
2. **J1-v2 过严导致全体归零**：来源真实性硬判据需要区分"来源缺失"（fail）
   与"来源已声明但未实抓"（应降档不灭绝），否则 AC4 区分度永远做不出来。
3. **新旧对照基线**：旧版 r4 判官 J1 vs J2 item-level 一致率 = 0.761（35/46），
   比 v2 的 0.661 还高——v2 的"硬判据对齐"不但没提升一致性，反而因 J1 过严
   （对"假设性链接"一刀切 fail）把原本能 pass 的条目全灭，拉低了一致率。
   修正方向不是继续加硬判据，而是给 J1 的来源判据分级。
4. **id 体系三代不统一**（本轮新发现）：旧版 J1 用纯数字 id（1..N），J2 用工件
   原文 id；v2 两个判官都改用原文 id，但 J1-v2 在无编号工件上又退回自造 X1..Xn。
   实测 J1-old vs J1-v2 的 item-level 交集为空（两套 id 零重叠），无法直接做
   item 级新旧对照——只有 run 级分数可比（即上文证据 2）。位置对齐口径
   （第 i 条 vs 第 i 条，仅取条目数差 ≤2 的 run）下：J1-old vs J1-v2 = 0.551，
   而同期 J1-old vs J2-old = 0.734——同一个 J1 旧版跟谁比都是 ~0.73 的一致性，
   换成 v2 后掉到 0.55，再次坐实 J1-v2 是扰动源。J2-old vs J2-v2
   item-level 一致率 0.978（44/45），证明 J2 侧改 rubric 几乎无扰动，问题集中在 J1。

### AC4 根因：B-2del-eo 工件质量本身太高

cfg_means：A-full J1=0.93/J2=0.96 vs **B-2del-eo J1=1.0/J2=1.0**。删掉 evidence+owner 两段后，剩余条目反而全部满分——说明这批工件里 evidence/owner 段不是"加分项"而是"噪声项"（v2 对账已发现它们普遍带"假设性链接/待验证"标记，J1-v2 的来源硬判据把它们打成 fail；v3 三级化后不再惩罚，但它们也不贡献分数）。

**结论**：rubric v3 修好了 v2 的两个真 bug（id 不对齐 → AC1 从 0.661→0.979；来源一刀切 → AC3 恢复区分度），但暴露了第三个问题：**当前工件集上 A-full 和 B-2del-eo 实质等价**，AC4 的区分度要求在这个数据集上不成立。这不是 rubric 的错，是实验设计的盲区——evidence/owner 段的消融效应被"假设性标记"污染了（web-llm 通道 down 的产物）。

**下一步选项**：
1. 换一批干净工件（evidence 段是真实可验证的）重跑 → 测 AC4 是否恢复区分度。需要重新生成或找历史批次。
2. 接受 AC4 在当前数据上的不可判定，把 rubric v3 标记为"3/4 AC 通过 + AC4 数据受限"，等异源 judge 一起验证。
3. 修 AC4 判据本身（比如改成 A-full − B-nofreeze ≥0.3，用 freeze 消融做区分度锚点，因为 T8 Part C 已证明 freeze 有稳健负效应）。

### r247 补充：AC4-alt（freeze 消融锚点）也部分失败

用已有 receipt 数据计算 A-full − B-nofreeze：J1=0.180 <0.3 FAIL，J2=0.421 ≥0.3 PASS。

**综合判断**：rubric v3 修好了 id 对齐和来源判据两个真 bug，但当前工件集 + 双判官组合下，**没有任何一对 config 能在两个判官上同时产生 ≥0.3 的区分度**。这不是 rubric 文本的问题，是测量系统（同族判官 + 这批特定工件）的天花板。

**最终建议**：rubric v3 标记为 "3/4 AC pass + AC4 受限于同族判官天花板"。要真正解决 AC4 需要异源 judge（不同模型家族的评分器），这与 T8 Part C confirmatory 的阻塞是同一个 key。在拿到异源 judge 之前，rubric 侧的工作已到头——继续改 rubric 文本不会改变测量系统的天花板。

## r248 · rubric v3.1 重放 + J2 宽容度诊断

**v3.1 改动**（在 v3 基础上）：① extract_items 增加「方案X」「候选 X:」模式锚点（P-A/P-B/...）；② J1 ②具体性加对象层级澄清（方案级主张自带数字+单位即过 ②，防与 ① 双重扣分）。

**结果**：AC1=0.963✅ AC2✅ **AC3 FAIL**（B-none J2=0.417≥0.3）AC4❌。比 v3 更差——v3 的 AC3 是 PASS 的。

### 根因：J2-lenient 的宽容度对"有数字但无来源"的方案级主张系统性偏高

v3.1 的 P-X 锚点让 B-none/D1 两个 seed 从 canon=[]（无法评分→默认 0）变成了 canon=[P-A..P-D]（可评分→暴露真实分数）。暴露出来的问题是：

- **seeda**：J2 给 P-C pass（Cal.com 方案带 ¥1,600-2,600/年 成本明细），其余 fail。J1 全 fail。
- **seedb**：J2 给 P-A/B/C/D **全 pass**（Topos/Teams/自建/Calendly 都带价格数字）。J1 全 fail。

J2 的 B-1 底线要求"可复核的真实对象（URL/文档名+章节/API/仓库路径）"，但这些工件里的价格数字是模型生成的（无 URL、无文档引用），只是"看起来像定价"。J2 把"有具体数字"当成了"有来源"——这是 B-2（零信息底线）和 B-1（来源真实性底线）的边界模糊：**数字+单位满足了 B-2 的"至少一个具体数字"，但 J2 没有进一步检查这个数字是否有可复核来源**。

J1 的三级判据（A/B/C 级）正确地把"有数字但无来源"归为 B 级（降档不单独 fail），再叠加其他测的 fail → 全 fail。J1 是对的，J2 太宽。

### 结论修正

r247 说"rubric 侧到头，需异源 judge"——这个判断需要修正。**真正的瓶颈不是同族判官天花板，而是 J2-lenient 的 B-1/B-2 边界定义不够精确**。如果修 J2（要求 B-2 的"具体数字"必须附带可定位来源，否则不算"具体"），AC3 可能恢复。这不需要异源 judge，只需要 rubric 文本再改一轮。

但要注意：每改一轮 rubric 都在过拟合当前工件集。v3→v3.1 已经两轮了，第三轮之前应该先确认：这批工件（web-llm 通道 down 时生成的）是否代表了 rubric 要评的真实分布。如果不是，改 rubric 适配这批工件没有意义。
