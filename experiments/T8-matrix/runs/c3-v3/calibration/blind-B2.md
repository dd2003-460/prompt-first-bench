## 2. 反方检查（挑战结论）

### 挑战 1：推荐坚果云 Standard 是否过于保守？

**质疑**：¥10,800/年 只用了预算的 36%，为什么不用余量升级更好的方案（如飞书标准版 ¥18,000 或坚果云 Advanced ¥18,000）？

**反驳**：
- 任务书约束是"预算 ≤¥30,000/年"，不是"花完预算"
- 推荐方案的判定标准是**满足全部硬约束 + 最小必要成本**，不是最大化功能
- 如果团队需要 IM 捆绑（飞书）或更长版本保留（Advanced），那是需求变更，不是本 run 的决策范围
- **但**：备选层已给出升级路径（飞书/Advanced/Nextcloud），用户可根据实际需求选择
- **判定**：推荐逻辑成立，不修改

### 挑战 2：坚果云权限粒度是否真的满足"细粒度权限控制"？

**质疑**：S3 只说"增加权限数量"和"Limit Sharing / IP restrictions"——这是"细粒度"吗？对比 Seafile Pro 的 "Fine-grained folder permission"，坚果云可能只是文件夹级共享，不是 ACL 级。

**反驳**：
- 任务书原文："细粒度权限控制"——未定义具体粒度（文件夹级？文件级？角色级？）
- 坚果云 Standard 有：文件夹共享 + 权限数量限制 + IP 白名单 + 两步验证 + 远程擦除
- Seafile Pro 有：Fine-grained folder permission（明确写了 fine-grained）
- **诚实评估**：坚果云的权限粒度**可能不如** Seafile Pro 细，但任务书未要求"文件级 ACL"，文件夹级+IP 限制对 30 人研发团队通常够用
- **处置**：在推荐方案中加一条注："若'细粒度'指文件级 ACL，则 Seafile Pro（备选 3）更匹配"
- **判定**：不改变推荐（任务书措辞模糊，按最合理解释处理），但显式标注歧义

### 挑战 3：国内可达性 U7 是否应该淘汰所有海外 SaaS？

**质疑**：Google Drive / Box / Dropbox 被标"国内可达性差"而淘汰——但很多国内公司用 VPN 访问 Google Workspace，这不算"不可用"。

**反驳**：
- 本 run 的实验参数设定是"30 人研发团队"（默认国内，因预算单位为 CNY）
- 如果团队已有 VPN 基础设施，Google Workspace BS（¥18,037）是合理选项
- **但**：U7 是 lead-unverifiable（本环境非国内出口），不能确认"可用"还是"需代理"
- **处置**：淘汰理由修正为"国内可达性未验证（U7），若团队有稳定代理则 Google WS BS 为可行备选"——从"淘汰"降为"conditional 淘汰"
- **判定**：不影响推荐方案（坚果云不受此影响），备选池微调

### 挑战 4：M365 超预算仅 ¥62（+0.2%）是否应该保留？

**质疑**：¥30,062 vs ¥30,000 只差 ¥62——汇率波动 ±0.05 就能翻过来。这是"超预算"还是"贴线"？

**反驳**：
- 预算约束是硬约束（≤¥30,000），不是软目标
- ¥62 超出 = 违反约束，无论幅度多小
- 且 M365 的 OneDrive 1TB/user（30TB 总量）对 30 人研发团队严重过剩——溢价买的是不需要的容量
- **判定**：淘汰维持不变。但备注"若预算上调至 ¥30,100 则 M365 进入备选池"

### 挑战 5：自托管 TCO 区间（¥5,400-9,000）是否过宽？

**质疑**：Nextcloud TCO 给了 ¥5,400-9,000 区间（跨度 67%）——这个精度够做决策吗？

**反驳**：
- 区间宽度反映的是**真实不确定性**（服务器配置 ×2 + 运维工时 ×2 = 4 种组合）
- 收窄区间需要更多假设（如固定 4C8G 服务器 + 0.5 人天/月），但这些假设本身也是推导
- 对决策的影响：即使取上沿 ¥9,000，仍低于推荐方案 ¥10,800 → 排序不变
- **判定**：区间合理，不修改。决策稳健性已验证（上下沿不改变排序）

| M365 贴线 | 不成立（硬约束） | 无 |
| 自托管 TCO 过宽 | 不成立（决策稳健） | 无 |
