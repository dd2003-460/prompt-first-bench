# 阶段 01：目标分解、已知与空缺条件

## 1. 目标交付物定义

**最终交付物**：一份针对 30 人研发团队的团队文件协作/网盘选型报告。
**核心内容要求**：
1.  **推荐方案**：明确选定的具体产品及其配置（版本、存储量、用户数）。
2.  **备选方案**：至少 1-2 个次优选择，说明在何种情况下可替换推荐方案。
3.  **淘汰理由**：列出主要候选池中未被选中的产品，并给出基于约束条件的具体淘汰逻辑。
4.  **成本明细**：包含许可证费用、实施/迁移潜在费用（如有）、年度总拥有成本（TCO），且总额必须 $\le \yen 30,000$。

## 2. 影响因素递归分解

### 顶层因素 (Level 1)

#### F1: 功能合规性 (Functional Compliance)
*   **定义**：方案是否满足核心业务需求和非功能性需求。
*   **子因素**:
    *   **F1.1: 文档版本管理 (Version Control)**
        *   *边界*：支持历史版本回溯、差异对比（diff）、版本恢复。对于研发团队，需确认是否支持代码类文件的轻量级版本管理或仅支持二进制/文档类的快照版本。
        *   *状态*：**待研究**。不同网盘对“版本管理”的定义差异巨大（如 Dropbox 是快照，Git-based 工具是提交记录）。需明确“文档”是指 Office/PDF 还是包含源码/配置文件。
        *   *空缺*: [待研究] 各候选方案对非文本文件（图片、二进制）和文本文件（MD, Code）的版本管理机制及保留策略（如保留最近 N 版 vs 无限版）。
    *   **F1.2: 细粒度权限控制 (Granular Access Control)**
        *   *边界*：支持文件夹/文件级别的读/写/评论/所有者权限；支持基于角色（Role-based）或组（Group-based）的权限分配；支持外部访客链接权限限制。
        *   *状态*：**待研究**。
        *   *空缺*: [待研究] 各候选方案的最小权限单元（是文件级还是文件夹级？）、是否支持继承权限覆盖、是否支持审计日志（Audit Log）以追踪谁修改了权限。
    *   **F1.3: 多平台客户端支持 (Multi-platform Client Support)**
        *   *边界*：必须提供 Web 端、macOS 原生客户端、Windows 原生客户端。
        *   *状态*：**已知/可推导**。主流商业网盘均支持。
        *   *空缺*: [待验证] macOS 客户端是否支持 File System Integration (FUSE/APFS)，即能否像本地文件夹一样操作而不必依赖专用 App 窗口；Windows 客户端是否支持 OneDrive-like 的文件占位符技术以节省本地磁盘空间。
    *   **F1.4: 离线可用性 (Offline Availability) - 加分项**
        *   *边界*：在无网络环境下可访问已同步文件，并在网络恢复后自动同步更改。
        *   *状态*：**待研究**。
        *   *空缺*: [待研究] 各候选方案的离线缓存机制（全量下载 vs 按需加载）、冲突解决策略（Last-write-wins vs Manual Merge）。

#### F2: 成本可行性 (Cost Feasibility)
*   **定义**：方案总成本是否符合预算约束。
*   **子因素**:
    *   **F2.1: 年度订阅费用 (Annual Subscription Cost)**
        *   *边界*：$\le \yen 30,000$ / 年。
        *   *状态*：**待研究**。
        *   *空缺*: [待研究] 各候选方案针对 30 名用户的官方定价（Business/Enterprise 层级）。需注意汇率波动风险（若为美元计价）。
    *   **F2.2: 隐性成本 (Hidden Costs)**
        *   *边界*：包括数据迁移服务、API 集成开发费、超量存储费、高级安全模块附加费。
        *   *状态*：**待研究**。
        *   *空缺*: [待研究] 是否提供免费数据迁移工具；超出基础存储包后的单价；是否需要额外购买 SSO/SAML 集成模块。

#### F3: 技术与运维兼容性 (Technical & Operational Compatibility)
*   **定义**：方案是否与现有研发基础设施兼容，以及运维复杂度。
*   **子因素**:
    *   **F3.1: 身份认证集成 (Identity Authentication)**
        *   *边界*：是否支持 SSO (SAML/OIDC) 以对接公司现有的 Active Directory 或 Okta/Azure AD。
        *   *状态*：**待研究**。
        *   *空缺*: [待研究] 哪些价格层级包含 SSO 功能。对于 30 人团队，若无法 SSO，密码管理复杂度增加。
    *   **F3.2: 数据驻留与安全合规 (Data Residency & Security)**
        *   *边界*：数据存储地点（中国大陆境内 vs 海外）；加密标准（AES-256 at rest, TLS in transit）。
        *   *状态*：**部分已知/待研究**。
        *   *空缺*: [待研究] 各候选方案在中国大陆的数据中心位置。若数据存储在海外，可能面临访问延迟或合规风险（视公司合规要求而定，此处作为待确认条件）。
    *   **F3.3: 性能与稳定性 (Performance & Stability)**
        *   *边界*：大文件上传速度、并发同步稳定性、SLA 保证。
        *   *状态*：**待研究**。
        *   *空缺*: [待研究] 各方案在典型企业网络环境下的实际表现评价（来自 Gartner, Forrester 或用户社区）。

#### F4: 生态与扩展性 (Ecosystem & Extensibility)
*   **定义**：方案与其他研发工具的集成能力。
*   **子因素**:
    *   **F4.1: 第三方集成 (Third-party Integrations)**
        *   *边界*：与 Slack/Teams/DingTalk/Feishu 的通知集成；与 Jira/GitHub/Jenkins 的关联能力。
        *   *状态*：**待研究**。
        *   *空缺*: [待研究] 各候选方案的 API 开放程度及预置连接器列表。

## 3. 条件分类清单

### 3.1 人类已提供的确定条件 (Known Constraints)
1.  **用户规模**：30 人研发团队。
2.  **预算上限**：$\le \yen 30,000$ / 年。
3.  **平台要求**：Web + macOS + Windows 客户端必须可用。
4.  **核心功能 1**：文档版本管理。
5.  **核心功能 2**：细粒度权限控制。
6.  **加分功能**：离线可用。
7.  **交付物格式**：选型报告（含推荐、备选、淘汰理由、成本明细）。

### 3.2 从项目可推导的条件 (Derived Conditions)
1.  **许可类型**：由于涉及 30 人和细粒度权限，个人版（Personal Plan）通常不满足 B2B 需求（缺乏集中管理、SSO、审计日志），因此应排除纯个人版，聚焦于 Business/Team/Enterprise 计划。
2.  **存储估算**：虽然未明确存储量，但研发团队通常包含设计稿、编译产物等较大文件。假设基础存储需求在 1TB - 5TB 之间（此为假设，需在阶段 02 中通过调研典型研发团队存储用量来验证或修正，若预算不足则成为约束瓶颈）。
3.  **部署模式**：考虑到预算仅 3 万/年，自建私有云（On-premise）或大型公有云存储实例的成本极高，因此**排除自建方案**，聚焦于 SaaS 托管服务。

## 4. 候选对象初步界定（待验证假设）

*注：以下为基于市场常识生成的**初始候选池**，所有属性均为**待验证假设**，需在阶段 02 中逐一核验。*

**类别 A：国际主流协同办公套件附属网盘**
1.  **Microsoft OneDrive for Business** (随 Microsoft 365 捆绑)
    *   *假设*：与 Office 集成度高，版本管理强（保留 30 天+ 版本），权限继承 SharePoint 体系。
    *   *待验证*：30 用户 M365 Business Standard/Premium 的中国区价格；中国大陆访问速度；SSO 支持。
2.  **Google Drive for Workspace (Business/Enterprise)**
    *   *假设*：版本管理优秀，权限控制细致，Web 体验好。
    *   *待验证*：中国大陆访问稳定性（通常需代理或特定节点，可能不符合“开箱即用”的运维低要求）；中国区定价；离线功能限制。
3.  **Dropbox (Business/Standard)**
    *   *假设*：同步速度快，版本保留 180 天，跨平台体验极佳。
    *   *待验证*：中国区访问速度；30 用户价格；是否支持细粒度文件夹权限（Dropbox 权限相对较粗，需核实）。

**类别 B：专业文件协作/网盘服务商**
4.  **Box (Business/Enterprise)**
    *   *假设*：企业级安全，权限极其细粒度，审计日志完善。
    *   *待验证*：价格是否超标（Box 通常较贵）；中国区节点；最小起步用户数。
5.  **Nextcloud (Self-hosted? No, exclude)** -> **替代：Nutstore (坚果云) 企业版**
    *   *假设*：国内服务商，访问速度快，符合国内合规，支持增量同步（适合研发小文件频繁修改）。
    *   *待验证*：企业版价格；权限控制深度；版本保留策略；SSO 支持。
6.  **Tencent Weiyun (腾讯微云) 企业版 / 企业网盘**
    *   *假设*：国内大厂背书，微信/QQ 集成好，带宽优势。
    *   *待验证*：企业版具体功能集（版本管理、权限）；30 人报价。
7.  **Alibaba Cloud Drive (阿里云盘) 企业版**
    *   *假设*：国内访问极速，与钉钉/阿里系集成好。
    *   *待验证*：企业版独立功能（非 C 端共享）；权限模型；价格。

**排除理由示例（基于已知约束的初步过滤）**：
*   **排除 GitHub/GitLab (Code Repositories)**：虽然版本管理最强，但它们的核心是代码仓库，不具备通用的“文件协作/网盘”属性（如 Office 文档在线预览、非代码文件的大容量存储、通用权限管理界面），不符合“文件协作/网盘”的任务定义。
*   **排除 Notion/Confluence**：它们是知识库/Wiki 工具，侧重于结构化文档编写，而非二进制文件（图片、视频、压缩包）的存储和版本管理，不符合“网盘”核心定义。

## 5. 阶段 02 研究路径与行动指南

### 5.1 研究目标
1.  构建一个包含 5-7 个有效候选的评估矩阵。
2.  获取每个候选在 30 用户规模下的准确年度成本（人民币）。
3.  验证每个候选对“细粒度权限”和“版本管理”的具体实现能力。
4.  评估中国大陆地区的可用性和合规性。

### 5.2 具体研究动作 (Action Items)

#### Step 1: 价格与套餐核验 (Priority: High)
*   **来源类型**：官方网站定价页 (Pricing Pages)、销售咨询表单 (Sales Inquiry)。
*   **搜索词示例**：
    *   `"Microsoft 365 Business Premium price China 30 users"`
    *   `"Dropbox Business pricing 30 users CNY"`
    *   `"Box business plan pricing per user"`
    *   `"坚果云企业版 价格 30人"`
    *   `"腾讯微云企业版 报价"`
*   **字段提取**：
    *   单用户月/年费用。
    *   包含的存储总量（Total Storage Pool vs Per User Storage）。
    *   最低起订人数（Minimum Seats）。
    *   是否包含 SSO/SAML。
*   **失败备用路径**：若官网无中国区直购价，记录“需联系销售获取报价”，并在报告中注明“价格待商务确认”，同时参考全球均价进行预算风险评估。

#### Step 2: 功能特性深挖 (Priority: High)
*   **来源类型**：官方帮助文档 (Help Center/Docs)、功能对比表 (Feature Comparison Charts)、G2/Gartner Peer Insights 评论。
*   **关键问题清单**：
    1.  **版本管理**：保留多少个版本？保留多久？是否支持版本间的 Diff 视图？
    2.  **权限控制**：
        *   能否对单个文件设置“可看不可下”？
        *   能否创建嵌套文件夹并应用不同权限？
        *   是否有详细的审计日志（谁在何时访问/修改了什么）？
    3.  **客户端**：
        *   macOS/Windows 客户端是否免费？
        *   是否支持文件选择器（File Picker）集成到 Office/VS Code 等应用中？
*   **搜索词示例**：
    *   `"[Product Name] file version control retention policy"`
    *   `"[Product Name] granular permissions folder level"`
    *   `"[Product Name] audit log features"`

#### Step 3: 区域可用性与合规 (Priority: Medium)
*   **来源类型**：官方数据中心地图 (Data Center Locations)、隐私政策 (Privacy Policy)、中国工信部备案信息（针对国内厂商）。
*   **关键问题**：
    *   数据是否存储在中国大陆境内？
    *   若在海外，是否有中国大陆加速节点？
    *   是否符合《网络安全法》和《数据安全法》的基本要求？
*   **失败备用路径**：若无明确公开信息，标记为“合规风险未知”，建议在报告中建议企业进行法律合规审查。

## 6. 阶段判定

*   **因素覆盖完整性**：已覆盖功能、成本、技术兼容、生态四个维度，且递归至原子层面（如具体到 SSO、版本保留策略）。
*   **已知/未知区分**：明确区分了用户给定的硬约束和待研究的软约束。
*   **研究入口清晰度**：阶段 02 可直接依据 5.2 节的 Action Items 开始搜集数据。
*   **无伪装事实**：所有候选产品的具体价格和性能均标记为“待验证”。

**判定
