# 阶段 03：具体行动分解（无 owner 组件）

**说明**：本阶段基于阶段 02 的结论，将“产出可交付的选型报告”这一最终目标拆解为具体的、可执行的操作步骤。每个步骤明确了输入、动作、依赖关系、预期产出及验收标准，确保团队可以按部就班地推进直至完成报告交付。

---

## 1. 行动步骤总览

| 步骤 ID | 步骤名称 | 关键目标 | 预计耗时 |
| :--- | :--- | :--- | :--- |
| **S1** | 商务询价与功能确认 (飞书) | 获取正式报价，锁定会议室高级功能范围 | 2-3 个工作日 |
| **S2** | 技术预研：门禁对接可行性 | 评估现有门禁系统与飞书 API 的集成成本 | 1-2 个工作日 |
| **S3** | 试点测试：日历同步稳定性验证 | 验证 Google/Outlook 双向同步的实际表现 | 3-5 个工作日 |
| **S4** | 备选方案快速核验 (钉钉) | 确认钉钉外部日历集成的具体配置路径或插件费用 | 1 个工作日 |
| **S5** | 数据整合与报告撰写 | 汇总所有证据，生成最终选型报告 | 1-2 个工作日 |

---

## 2. 详细步骤分解

### S1: 商务询价与功能确认 (针对首选方案 C1: 飞书)

*   **输入**:
    *   阶段 02 确定的候选名单（C1）。
    *   公司基本信息（人数：30人，行业：研发，预算上限：¥20,000/年）。
    *   具体功能需求清单（重点：会议室预约、排队机制、黑名单、报表导出）。
*   **动作**:
    1.  联系飞书官方销售或当地代理商，发起企业版/商业版咨询。
    2.  明确询问：30 人规模的年度总价；是否包含“会议室管理”模块的所有高级功能（如设备联动、复杂权限控制）；是否有初创/中小企业优惠折扣。
    3.  要求提供一份正式的《产品功能对比表》或《解决方案建议书》，特别标注哪些功能是免费版限制而需付费解锁的。
    4.  确认发票类型（增值税专票）及付款周期（年付/季付）。
*   **依赖**:
    *   需要一名具备采购权限的人员参与沟通。
    *   需准备公司的营业执照扫描件等基础资质信息（如需）。
*   **预期产出**:
    *   《飞书正式报价单.pdf》
    *   《飞书会议室功能明细确认函.txt》（记录销售口头承诺的功能点）
*   **验收方式**:
    *   拿到盖章或官方邮件形式的正式报价。
    *   确认报价总额 ≤ ¥20,000。
    *   书面确认“会议室管理”核心功能在所选套餐中可用，无需额外购买高价插件包。

### S2: 技术预研：门禁对接可行性 (针对 C1: 飞书)

*   **输入**:
    *   公司现有门禁系统的品牌型号（例如：海康威视 DS-K1T671、大华 DH-ATCB 等）及其 API 文档。
    *   飞书开放平台开发者文档（特别是“智能硬件”或“IoT 接入”部分）。
*   **动作**:
    1.  指派一名后端工程师查阅飞书开放平台关于“设备接入”或“Webhook 事件订阅”的文档。
    2.  查找是否存在现成的中间件或 SDK 支持主流门禁品牌（如海康、大华、熵基科技）与飞书的直接对接。
    3.  若无现成 SDK，评估开发一个简单网关（接收门禁刷卡信号 -> 调用飞书 API 更新房间状态/发送通知）的工作量。
    4.  记录预估的开发工时（人天）和潜在的技术风险（如网络延迟、鉴权复杂度）。
*   **依赖**:
    *   需要 IT 部门提供现有门禁系统的技术规格书。
    *   需要一名熟悉 RESTful API 的后端工程师投入时间。
*   **预期产出**:
    *   《门禁对接技术评估备忘录.md》
    *   内容包含：可行性结论（可行/不可行）、预估开发成本（人力/软件）、推荐的技术架构简图。
*   **验收方式**:
    *   明确回答：“能否实现门禁刷卡后自动释放/占用会议室？”
    *   若可行，给出预估开发成本是否低于预算剩余空间（通常预留 ¥5,000 - ¥8,000 用于此类轻量级开发）。

### S3: 试点测试：日历同步稳定性验证 (针对 C1: 飞书)

*   **输入**:
    *   飞书试用账号（申请企业体验版或让销售开通临时测试租户）。
    *   3-5 名核心研发成员的 Google Calendar 和 Outlook 账号。
    *   测试用例脚本（见下方）。
*   **动作**:
    1.  **环境搭建**: 在飞书中创建测试会议室资源，配置好 3-5 名测试人员的权限。
    2.  **正向同步测试**:
        *   在 Google Calendar 创建一个会议并添加会议室，检查飞书端是否实时出现该预订。
        *   在 Outlook 创建一个会议并添加会议室，检查飞书端是否实时出现该预订。
    3.  **反向同步测试**:
        *   在飞书 Web 端直接预订会议室，检查 Google/Outlook 中是否生成对应的忙闲状态或事件。
    4.  **冲突处理测试**:
        *   模拟两个不同来源（如 GCal 和 Outlook）同时预订同一时间段，观察系统报错提示及数据一致性。
    5.  **取消/修改测试**:
        *   在源头（GCal/Outlook）取消或修改会议，检查飞书端状态是否即时更新。
    6.  **记录日志**: 记录每次操作的响应延迟（秒级）和任何 Bug。
*   **依赖**:
    *   测试人员需拥有独立的 Google Workspace 和 Microsoft 365 账号。
    *   需确保测试期间网络环境稳定，排除本地网络干扰。
*   **预期产出**:
    *   《飞书日历同步测试报告.xlsx》
    *   包含：测试项、操作步骤、预期结果、实际结果、延迟时间、Bug 描述、截图证据。
*   **验收方式**:
    *   双向同步成功率 ≥ 95%。
    *   平均同步延迟 < 5 秒。
    *   无严重数据丢失或死锁 Bug。若有轻微 Bug，需确认是否有官方修复计划或 Workaround。

### S4: 备选方案快速核验 (针对 C2: 钉钉)

*   **输入**:
    *   阶段 02 识别的风险点：钉钉外部日历双向同步不稳定。
    *   钉钉应用市场链接。
*   **动作**:
    1.  登录钉钉管理员后台，搜索“日历同步”、“Google Calendar”、“Outlook”相关的应用或连接器。
    2.  查看第三方 ISV（独立软件开发商）提供的插件评价、价格及更新频率。
    3.  若存在官方“连接平台”模板，尝试在测试环境中配置一个简单的 ICS 导入导出流程，验证其局限性。
    4.  联系钉钉销售，询问是否有原生的“跨平台日历同步”高级功能，以及 30 人专业版的精确报价。
*   **依赖**:
    *   需有钉钉企业管理员权限。
*   **预期产出**:
    *   《钉钉备选方案核验笔记.md》
    *   内容包含：是否需要额外付费插件、插件年费估算、同步机制是单向还是双向、用户反馈摘要。
*   **验收方式**:
    *   明确钉钉方案的总拥有成本（TCO）= 软件费 + 插件费。
    *   明确其日历同步体验是否显著劣于飞书（作为报告中“淘汰理由”或“备选劣势”的依据）。

### S5: 数据整合与报告撰写

*   **输入**:
    *   S1 产出的《飞书正式报价单》
    *   S2 产出的《门禁对接技术评估备忘录》
    *   S3 产出的《飞书日历同步测试报告》
    *   S4 产出的《钉钉备选方案核验笔记》
    *   阶段 02 的综合评估矩阵。
*   **动作**:
    1.  **成本汇总**: 制作详细的《年度成本明细表》，列出飞书主套餐、可能的门禁开发分摊成本、钉钉备选方案成本。
    2.  **决策论证**:
        *   撰写“推荐理由”：结合 S3 的测试数据证明飞书满足核心痛点（双日历同步），结合 S1 证明预算合规。
        *   撰写“备选分析”：基于 S4 说明钉钉为何作为第二选择（生态优势 vs 集成劣势）。
        *   撰写“淘汰理由”：引用阶段 02 对 Calendly（超预算/功能错位）、RoomGuru（网络/支付障碍）、Nextcloud（运维成本高）的分析。
    3.  **实施路线图**: 制定上线后的 2 周实施计划（账号迁移 -> 日历绑定 -> 门禁调试 -> 全员培训）。
    4.  **评审与定稿**: 邀请 IT 负责人和行政负责人审阅报告，确认无误后定稿。
*   **依赖**:
    *   S1-S4 全部完成。
*   **预期产出**:
    *   《会议室预约系统选型报告_final.pdf》
    *   结构包含：
        1.  执行摘要（一页纸结论）
        2.  背景与需求回顾
        3.  候选方案详细评估（含测试数据截图）
        4.  成本对比明细
        5.  最终推荐方案及实施计划
        6.  风险与应对策略
*   **验收方式**:
    *   报告逻辑闭环，所有结论均有阶段 02-03 产生的证据支撑。
    *   成本明细清晰，无隐藏费用。
    *   获得决策层签字批准。

## 3. 风险管理与应急预案

在执行上述步骤时，可能遇到以下风险，需提前准备预案：

| 风险点 | 触发条件 | 应对措施 |
| :--- | :--- | :--- |
| **飞书报价超标** | 正式报价 > ¥20,000 | 1. 谈判：强调 30 人小团队规模，争取折扣。<br>2. 降级：询问是否可以只购买“会议室应用包”而非全量商业版（如果允许）。<br>3. 切换：立即启动钉钉（C2）的深度测试，将其提升为首选。 |
| **日历同步严重 Bug** | 测试中发现同步延迟 > 30s 或频繁丢数据 | 1. 提交 Bug 给飞书技术支持，要求紧急修复或提供临时脚本。<br>2. 评估使用 Zapier/Make 等第三方自动化工具作为中间层进行桥接（增加成本和复杂度）。<br>3. 若无法解决，重新评估 Nextcloud (C5) 或定制开发轻量级前端的可能性。 |
| **门禁对接工作量过大** | 评估发现需 > 5 人天开发 | 1. 放弃门禁联动，采用“人工+APP 扫码签到”的过渡方案。<br>2. 寻找支持飞书集成的第三方门禁厂商更换硬件（长期方案）。 |
| **钉钉插件不可用** | 发现无可靠的双向同步插件 | 强化飞书的优势论述，彻底排除钉钉，将 RoomGuru 列为仅当团队全面国际化时的远期选项。 |

## 4. 交付物检查清单 (Definition of Done)

在宣布阶段 03 完成前，请核对以下清单：

- [ ] **报价确认**: 已收到飞书 30 人规模的正式年度报价，且金额 ≤ ¥20,000。
- [ ] **功能确认**: 已书面确认飞书套餐包含会议室管理、Google/Outlook 双向同步功能。
- [ ] **测试通过**: 已完成至少 3 人的真实日历同步测试，成功率符合预期，无致命 Bug。
- [ ] **门禁评估**: 已明确门禁联动的技术路径和成本估算。
- [ ] **备选核实**: 已核实钉钉方案的具体限制和额外成本。
- [ ] **报告产出**: 《会议室预约系统选型报告》已撰写完毕，包含推荐、备选、淘汰理由及成本明细。
- [ ] **审批通过**: 报告已通过内部评审并获得批准。
