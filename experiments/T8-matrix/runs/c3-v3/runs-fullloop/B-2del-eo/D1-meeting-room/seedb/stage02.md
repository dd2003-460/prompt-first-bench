### 1.2 国内办公生态集成方案 (高潜力候选)

考虑到预算极低且团队在中国，**飞书 (Feishu/Lark)** 和 **钉钉 (DingTalk)** 是主要考察对象。

#### A. 飞书 (Feishu)
*   **功能分析**:
    *   **会议室模块**: 飞书日历内置“会议室资源”。管理员可在后台创建会议室，员工预约时可直接勾选会议室，系统自动锁定时间段。
    *   **多端支持**: ✅ 完美支持 macOS, Windows, Web, iOS, Android。
    *   **日历对接**:
        *   **内部**: 原生支持，无需对接。
        *   **外部 (GCal/Outlook)**: 飞书日历支持通过 **CalDAV** 协议导入/导出外部日历。但需注意：飞书作为主日历时，对外部日历的“双向写回”支持有限（通常建议以飞书为主，或配置单向同步）。对于研发团队，若主要使用 Outlook/GCal 工作，可能需要反向操作（在 Outlook 中共享飞书会议室日历链接）。
    *   **门禁联动**: 飞书开放平台提供丰富的 API。可通过 Webhook 监听“会议创建/取消”事件，调用海康威视/ZKTeco 等门禁厂商的 API 实现联动。**可行性高，开发量小。**
    *   **成本**:
        *   **免费版 (Free Tier)**: 支持最多 10 人？(需核实最新政策)。通常免费版限制用户数较少。
        *   **专业版 (Professional)**: 约 50 CNY/人/月。30人年费 = $50 \times 30 \times 12 = 18,000$ CNY。
        *   **标准版 (Standard)**: 约 30 CNY/人/月。30人年费 = $30 \times 30 \times 12 = 10,800$ CNY。
        *   *注: 飞书版本迭代快，需确认“会议室资源”功能是否包含在低价版中。通常基础版即包含日历和会议室管理。*

#### B. 钉钉 (DingTalk)
*   **功能分析**:
    *   **会议室模块**: 同样内置于日历中，支持会议室预约和冲突检测。
    *   **多端支持**: ✅ 全平台支持。
    *   **日历对接**: 钉钉支持与企业微信、Outlook 等互通，但对 Google Calendar 的支持相对较弱，通常需要通过第三方连接器或 CalDAV 手动同步。
    *   **门禁联动**: 钉钉智能硬件生态较成熟，但与第三方门禁品牌的 API 开放性略逊于飞书。
    *   **成本**: 钉钉大部分基础功能免费。高级 AI 或大规模存储可能收费。对于 30 人纯会议室需求，**成本可能为 0 CNY**。

#### C. 企业微信 (WeCom)
*   **功能分析**:
    *   依赖腾讯会议或第三方插件。原生会议室预约体验不如飞书/钉钉流畅。
    *   成本: 基础免费。

**关键发现 (Fact Check)**：
*   **来源**: 飞书官网帮助中心 "会议室管理"，钉钉官网 "智能会议室" 文档。
*   **结论**: **飞书标准版** 是最符合预算且有良好 API 能力的商业方案。若团队已在使用飞书，边际成本极低。若从零开始，10,800 CNY 的预算非常充裕。

## 2. 门禁联动技术预研 (针对 U5)

**目标**: 评估“预约成功 -> 开门”的技术路径。

### 2.1 主流门禁品牌 API 现状
*   **海康威视 (Hikvision)**: 提供完善的 RESTful API (ISC Platform)。支持通过 Token 认证调用 `openDoor` 接口。
*   **ZKTeco (中控智慧)**: 提供 SDK 和 HTTP API。社区文档较多。
*   **大华 (Dahua)**: 提供 DH-SDK 和云 API。

### 2.2 集成方案对比

| 方案 | 实现方式 | 开发工作量 | 稳定性 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| **A. SaaS 原生集成** | 目前极少有低成本 SaaS 直接对接国内门禁。 | 0 | 高 | 除非选择昂贵的 RoomGuru 等。 |
| **B. 中间件脚本 (Python/Node.js)** | 1. 监听预约系统 Webhook (飞书/Airtable/自建DB)<br>2. 解析会议时间、参会人 ID<br>3. 调用门禁 API 下发开门指令 (限时 30s) | **1-2 天** (初级)<br>**4-6 小时** (中级) | 中 | 需要处理异常（如网络超时、门未关好）。 |
| **C. IoT 网关 (硬改)** | 使用 Raspberry Pi + RFID 读卡器，配合 Home Assistant。 | 高 (硬件采购+调试) | 低 | 超出软件选型范畴，不推荐。 |

**结论**: **方案 B** 是最佳平衡点。无论是使用飞书还是自建系统，只要暴露 Webhook 或数据库触发器，编写一个简单的 Python 脚本即可实现。这属于“加分项”，不影响核心选型，但显著提升了体验。

## 3. 数据合规性与安全性评估 (针对 U6)

*   **境外 SaaS (Calendly, Airtable)**:
    *   **风险**: 数据存储在美国/欧盟。虽然 GDPR 合规，但对于中国境内企业，若涉及敏感研发数据（代码片段、项目代号），可能存在《数据安全法》下的出境合规风险。
    *   **缓解**: 仅同步“会议室占用状态”和“参与者姓名”，不同步会议内容。风险可控。
*   **国内 SaaS (飞书/钉钉)**:
    *   **优势**: 数据存储在境内，符合国内法律法规。
    *   **劣势**: 若团队习惯使用 Gmail/Outlook，切换成本高。
*   **自建系统**:
    *   **优势**: 数据完全掌控在自己服务器上。
    *   **劣势**: 安全责任自负（备份、防攻击）。

## 5. 最终候选名单与淘汰理由

### 🏆 推荐方案 (Primary Recommendation)
**方案名称**: **飞书 (Feishu) 标准版 + 自定义门禁中间件**

*   **理由**:
    1.  **成本最优解**: 30 人标准版年费约 10,800 CNY，远低于 2 万预算，剩余预算可用于门禁硬件升级或服务器冗余。
    2.  **硬性条件满足**: 完美支持 macOS/Win/Web；原生支持会议室资源锁定。
    3.  **日历兼容**: 虽非原生双向同步 Outlook，但通过 CalDAV 可实现“飞书为主，Outlook 为辅”或反向共享，满足研发团队基本协作需求。若必须强双向，可结合 ICS 文件导出/导入脚本。
    4.  **加分项**: 飞书开放平台 API 成熟，易于开发门禁联动脚本。
    5.  **合规**: 数据境内存储，无出境风险。

### 🥈 备选方案 (Alternative)
**方案名称**: **自建轻量级会议室系统 (Python/Django + PostgreSQL)**

*   **理由**:
    1.  **极致灵活**: 可实现真正的 Google Calendar & Outlook **双向强同步** (通过 OAuth 2.0 库)。
    2.  **成本结构**: 现金成本极低 (~1,500 CNY/年服务器费)，主要消耗 IT 人力。适合拥有 1-2 名全栈工程师且愿意维护内部工具的团队。
    3.  **门禁联动**: 最无缝，直接在代码层面触发。
    4.  **风险**: 存在单点故障风险，UI 体验取决于开发者水平，长期维护负担重。
