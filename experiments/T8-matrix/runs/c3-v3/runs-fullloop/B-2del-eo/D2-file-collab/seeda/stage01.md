# 阶段 01：目标分解、已知与空缺条件

## 1. 任务交付物定义
**最终交付物**：一份可执行的《团队文件协作/网盘选型报告》。
**核心内容要求**：
1. **推荐方案**：满足所有硬性约束且综合评分最高的单一方案。
2. **备选方案**：至少 1-2 个次优方案及其适用场景。
3. **淘汰理由**：对未入选候选的具体排除依据（基于事实或明确标注的假设）。
4. **成本明细**：精确到人头或总额，验证 ≤¥30,000/年 的预算合规性。

---

## 2. 影响因素递归分解

### 顶层因素 (Level 1)

#### F1: 功能符合性 (Functional Fit)
*   **F1.1 文档版本管理 (Core Requirement)**
    *   F1.1.1 自动保存与历史版本回溯能力。
    *   F1.1.2 多人协同编辑时的冲突解决机制（如 Git-like merge vs Last-write-wins）。
    *   F1.1.3 版本保留策略（保留时长、数量限制）是否满足研发需求。
    *   *状态：待研究具体实现细节，需区分“在线协作文档”与“离线文件同步+版本控制”。*
*   **F1.2 细粒度权限控制 (Core Requirement)**
    *   F1.2.1 权限层级深度（文件夹级 vs 文件级）。
    *   F1.2.2 角色自定义能力（能否创建“只读”、“评论者”、“编辑者”等自定义角色）。
    *   F1.2.3 外部协作者权限隔离（防止内部敏感数据泄露给外部人员）。
    *   F1.2.4 审计日志能力（谁在何时修改了什么）。
    *   *状态：待研究各候选产品的权限模型差异。*
*   **F1.3 客户端支持 (Hard Constraint)**
    *   F1.3.1 Web 端可用性。
    *   F1.3.2 macOS 原生客户端存在性及稳定性。
    *   F1.3.3 Windows 原生客户端存在性及稳定性。
    *   *状态：已知主流产品均支持，但需验证特定版本兼容性（如 M1/M2 芯片优化）。*
*   **F1.4 离线可用 (Bonus Requirement)**
    *   F1.4.1 本地缓存机制（全量 vs 按需加载）。
    *   F1.4.2 离线编辑后的同步冲突处理。
    *   F1.4.3 离线状态下哪些功能受限（如搜索、预览）。
    *   *状态：加分项，不影响入选资格，但影响体验评分。*

#### F2: 商业与成本约束 (Commercial & Cost Constraints)
*   **F2.1 年度总成本 (Hard Constraint)**
    *   F2.1.1 单用户年费 × 30人 ≤ ¥30,000。
    *   推导：单用户年费上限 = ¥30,000 / 30 = **¥1,000/人/年**。
    *   *注意：此计算假设无额外存储费用、无实施费、无折扣。若含存储超量费，实际单价需更低。此为待验证的财务边界。*
    *   F2.1.2 计费模式（按席位、按存储量、混合计费）。
    *   F2.1.3 汇率波动风险（若为海外产品，需考虑 USD/CNY 汇率及支付渠道手续费）。
    *   F2.1.4 隐藏成本（SSO 集成费、高级安全模块费、技术支持费）。
    *   *状态：价格信息具有时效性，必须作为阶段 02 首要核验对象。*
*   **F2.2 采购与部署复杂度**
    *   F2.2.1 账号体系集成（LDAP/SAML/OIDC 支持情况）。
    *   F2.2.2 数据迁移成本（从现有工具迁移的人力/时间成本）。
    *   *状态：中优先级，影响落地速度。*

#### F3: 技术架构与安全 (Technical & Security)
*   **F3.1 数据存储位置与合规性**
    *   F3.1.1 数据中心地理位置（中国大陆境内 vs 境外）。
    *   F3.1.2 是否符合中国网络安全法/数据安全法要求（尤其涉及研发代码时）。
    *   *状态：关键决策点。若公司无特殊出海业务，境内节点通常优先；若需全球协作，境外节点可能更优但合规风险高。此点需结合“研发团队”的具体业务性质判断，目前未知，列为空缺。*
*   **F3.2 文件类型支持**
    *   F3.2.1 对研发常见格式的支持（PDF, Office, Markdown, Code files, Design files）。
    *   F3.2.2 大文件上传限制（研发常有大二进制文件或压缩包）。
    *   *状态：待研究。*

#### F4: 用户体验与生态 (UX & Ecosystem)
*   **F4.1 移动端支持 (Implicit Need)**
    *   虽未在任务书中明确要求，但研发团队可能有移动查阅需求。
    *   *状态：低优先级，不作为否决项。*
*   **F4.2 第三方集成**
    *   与 Jira, Confluence, Slack, WeChat Work, DingTalk 等的集成能力。
    *   *状态：中优先级，影响工作流效率。*

### 子因素递归展开示例 (以 F1.1 为例)

**F1.1 文档版本管理**
*   **F1.1.1 版本机制类型**
    *   类型 A: 连续版本快照（类似 Dropbox, OneDrive）。
        *   优点：简单直观。
        *   缺点：难以进行代码级别的 diff 对比。
    *   类型 B: 分支合并式（类似 Git-based docs, Notion 部分功能, Obsidian Sync 等）。
        *   优点：适合研发逻辑，可回滚。
        *   缺点：学习曲线陡峭。
    *   *判定：需根据“研发团队”的具体文档类型（是设计稿？还是代码注释？还是项目计划？）来加权。目前未知文档主要类型，列为空缺。*
*   **F1.1.2 并发编辑**
    *   实时协同（Real-time collaboration）vs 异步锁定（File locking）。
    *   *待研究：各候选产品在 30 人规模下的并发性能表现。*

## 3. 条件分类清单

### A. 人类已提供的确定条件 (Knowns)
1.  **用户规模**：30 人。
2.  **预算上限**：≤ ¥30,000 / 年。
3.  **平台要求**：Web + macOS + Windows 客户端。
4.  **核心功能 1**：文档版本管理。
5.  **核心功能 2**：细粒度权限控制。
6.  **加分项**：离线可用。
7.  **目标受众**：研发团队（隐含：可能对代码、技术文档有较高要求，注重安全性）。

### B. 从项目推导的条件 (Derived)
1.  **人均预算上限**：约 ¥1,000 / 人 / 年（基于无额外费用的理想情况，实际需预留缓冲）。
2.  **候选范围限定**：必须同时具备 Web/Mac/Win 三端支持的企业级 SaaS 或私有化部署方案。
3.  **排除标准**：纯个人版网盘（无细粒度权限）、仅支持单一平台的工具、超过预算的方案。

### C. 仍需研究的条件 (Unknowns / Gaps) -> **阶段 02 研究重点**

| ID | 空缺描述 | 阻塞的判断 | 优先级 |
| :--- | :--- | :--- | :--- |

| **G2** | **各候选产品的版本管理机制细节** | 无法判断哪个产品最契合“研发团队”的版本管理需求（快照 vs 分支）。 | **P0 (Critical)** |
| **G3** | **各候选产品的权限模型颗粒度** | 无法确认是否满足“细粒度”要求（如能否按部门+项目双重维度授权）。 | **P0 (Critical)** |

## 4. 候选对象类别冻结 (Candidate Set Freeze)

基于行业常识和初步筛选，将候选对象分为以下三类。**此列表为阶段 02 的研究基准，后续不得随意增减，除非有显式理由。**

### 类别 A: 国内主流协同办公/网盘平台 (High Probability for China Context)
*   **候选 1**: 飞书 (Feishu/Lark) - 文档 + 云盘
    *   *待验证*: 企业版价格、版本管理细节、权限粒度。
*   **候选 2**: 钉钉 (DingTalk) - 钉盘
    *   *待验证*: 企业版价格、版本管理细节、权限粒度。
*   **候选 3**: 腾讯企业微信 (WeCom) - 微盘
    *   *待验证*: 企业版价格、版本管理细节、权限粒度。
*   **候选 4**: 坚果云 (Jianguoyun) - 企业版
    *   *特点*: 以同步速度快、版本管理著称。
    *   *待验证*: 30 人套餐价格、权限粒度、离线能力。
*   **候选 5**: 阿里云盘 / 百度网盘企业版
    *   *特点*: 存储为主，协同较弱。
    *   *待验证*: 是否满足“文档版本管理”核心需求（可能不满足，待验证后可能淘汰）。

### 类别 B: 国际主流协作/网盘平台 (Global Standards)
*   **候选 6**: Microsoft 365 (OneDrive for Business + SharePoint)
    *   *特点*: 行业标准，Office 集成好。
    *   *待验证*: 中国区服务可用性、价格、合规性。
*   **候选 7**: Google Workspace (Drive)
    *   *特点*: 实时协同强。
    *   *待验证*: 中国大陆访问稳定性（通常需要代理，可能违反合规或体验差）、价格。
*   **候选 8**: Dropbox Business
    *   *特点*: 老牌网盘，稳定。
    *   *待验证*: 中国区访问速度、价格、文档编辑能力（较弱）。
*   **候选 9**: Box
    *   *特点*: 企业级安全。
    *   *待验证*: 价格（可能超预算）、中国区访问。

### 类别 C: 自托管/开源方案 (Self-hosted / Open Source)
*   **候选 10**: Nextcloud
    *   *特点*: 开源，可私有化部署，高度可定制。
    *   *待验证*: 运维成本（人力/服务器）、30 人规模的硬件成本、软件许可费（免费但需运维投入）。
*   **候选 11**: Seafile
    *   *特点*: 国产开源，专注同步，版本管理强。
    *   *待验证*: 企业版功能、运维成本、UI 友好度。

> **排除说明**：
> *   **纯个人网盘**（如普通版百度网盘）：因缺乏细粒度权限和企业级审计，直接排除。
> *   **仅限 Web 的服务**（如某些在线笔记工具若无客户端）：因违反 Hard Constraint，直接排除。

## 5. 阶段 02 研究路径与行动指南

### 第一批行动 (Priority P0)
1.  **价格核验 (对应 G1)**:
    *   **动作**: 访问各候选官网，查找“企业版”、“Business”、“Professional”套餐页面。
    *   **搜索词**: "[Product Name] enterprise pricing", "[Product Name] 30 users cost", "[Product Name] 企业版 报价".
    *   **字段提取**: 单用户月费/年费、最低起购人数、存储包含量、超出存储单价。
    *   **备用来源**: 联系销售顾问获取正式报价单（针对大客户折扣）、第三方比价网站（如 G2, Capterra, 36kr 评测）。
    *   **失败备用**: 若官网无公开价格，标记为“需询价”，并估算市场均价区间。

2.  **功能核验 - 版本与权限 (对应 G2, G3)**:
    *   **动作**: 查阅官方 Help Center 或 Documentation。
    *   **搜索词**: "[Product Name] version history limit", "[Product Name] granular permissions", "[Product Name] folder level access control".
    *   **关键字段**:
        *   版本保留期（天/月/无限）。
        *   权限层级（Root > Folder > File?）。
        *   是否支持自定义角色。
        *   是否支持外部链接分享且可设密码/有效期。

### 第二批行动 (Priority P1)
3.  **合规与访问性 (对应 G4, G8)**:
    *   **动作**: 检查数据中心位置声明，查看 SLA 协议。
    *   **测试**: 若有试用账号，测试在国内网络环境下的下载速度（特别是大文件）。
    *   **搜索词**: "[Product Name] data center location China", "[Product Name] compliance GDPR PIPL".

4.  **离线能力 (对应 G5)**:
    *   **动作**: 查阅客户端特性介绍。
    *   **搜索词**: "[Product Name] offline editing sync conflict".

### 第三批行动 (Priority P2)
5.  **生态与集成 (对应 F4.2)**:
    *   **动作**: 检查 API 文档或集成市场。

## 6. 风险与依赖

1.  **价格波动风险**: SaaS 价格随汇率和市场策略调整。
    *   *缓解*: 阶段 02 需记录查询日期，并在报告中注明价格有效期。
2.  **功能定义模糊**: “细粒度权限”在不同产品中定义不同。
    *   *缓解*: 阶段 02 需建立统一的评估矩阵（Rubric），例如：
        *   Level 1: 整个空间读写。
        *   Level 2: 文件夹级读写。
        *   Level 3: 文件级读写。
        *   Level 4: 自定义角色 + 继承规则。
        *   *达标线*: 至少达到 Level 3。
3.  **研发团队特殊性**: 如果团队主要使用代码库（Git），网盘可能不是最佳方案，而是需要 GitLab/GitHub Enterprise。
    *   *缓解*: 任务书明确指定“团队文件协作/网盘”，暗示非代码源文件管理为主。但若发现候选方案均不适合代码管理，需在报告中指出局限性，或建议组合方案（网盘 + Git）。*此为潜在的范围蔓延，需在阶段 02 初期确认。*
