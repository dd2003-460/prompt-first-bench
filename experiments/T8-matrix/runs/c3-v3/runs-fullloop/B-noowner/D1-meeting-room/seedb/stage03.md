## 行动分解列表

### 步骤 1：候选方案初筛与硬约束过滤
- **输入**：
    - 硬性条件清单：年度预算 ≤ 20,000 CNY；支持 macOS/Windows/Web；支持 Google Calendar & Outlook 双向同步。
    - 市场主流 SaaS 会议室预约工具列表（如：Calendly, Calendso, RoomGuru, Slack Connectors, Microsoft Teams Rooms 等）。
- **动作**：
    1. 遍历候选列表，逐一查询官方定价页，计算 30 人团队年度总成本。
    2. 检查技术文档，确认是否原生支持 Web 访问及桌面客户端（或 PWA 可安装性）。
    3. 核查 API 文档或集成列表，确认是否提供 Google Calendar 和 Microsoft Graph (Outlook) 的双向同步能力。
    4. 标记不满足任一硬性条件的方案为“淘汰”。
- **依赖**：
    - 无外部依赖，仅需互联网访问权限查阅官网。
- **预期产出**：
    - 《候选方案初筛表》：包含所有候选方案的名称、预估年费、三端支持情况、日历对接情况、初步淘汰理由（若适用）。
    - 剩余符合硬约束的短名单（预计 3-5 个）。
- **验收方式**：
    - 短名单中每个方案均明确标注其满足所有硬性条件的依据链接或截图。
    - 被淘汰方案均有明确的“违反哪条硬性条件”的理由。

### 步骤 2：深度功能验证与成本精算
- **输入**：
    - 步骤 1 产出的短名单（3-5 个方案）。
    - 门禁联动需求（可选加分项）。
- **动作**：
    1. **注册测试账号**：对短名单中的每个方案注册免费试用或沙盒环境。
    2. **功能实测**：
        - 在 macOS、Windows 浏览器及移动设备上模拟预约流程。
        - 实际配置 Google Calendar 和 Outlook 账户，执行创建会议->同步->修改->取消的全链路测试，验证双向同步的实时性与准确性。
        - 查找是否有现成的门禁系统（如 ZKTeco, HID, 或通用 REST API）集成插件或 Webhook 支持。
    3. **成本精算**：
        - 获取 30 用户规模的具体报价（注意区分按席位计费 vs 按房间计费）。
        - 计算隐性成本：实施费用、API 调用超额费、存储扩容费等。
        - 确认付款方式及汇率波动风险（若为海外服务）。
    4. **门禁联动评估**：记录各方案对门禁联动的支持程度（原生支持 / 需开发中间件 / 不支持）。
- **依赖**：
    - 需要可用的 Google Workspace 和 Microsoft 365 测试账户。
    - 需要至少一个可模拟的门禁 API 接口（或使用 Mock Server）。
- **预期产出**：
    - 《深度测试报告》：包含每个短名单方案的功能实测结果截图、同步延迟数据、门禁联动可行性分析。
    - 《精确成本明细表》：列出每个方案的直接成本、隐性成本、年度总计。
- **验收方式**：
    - 每个方案都有完整的同步测试日志。
    - 成本明细精确到小数点后两位，并包含货币单位。
    - 门禁联动部分有明确的“可行/不可行/需定制”结论。

### 步骤 3：综合评分与推荐决策
- **输入**：
    - 步骤 2 的《深度测试报告》和《精确成本明细表》。
    - 加权评分标准（建议权重：成本 30%，日历同步稳定性 30%，三端体验 20%，门禁联动 10%，易用性 10%）。
- **动作**：
    1. 根据加权标准对短名单方案打分。
    2. 确定**首选推荐方案**（得分最高且成本在预算内）。
    3. 确定**备选方案**（第二高分，且成本在预算内）。
    4. 整理所有被淘汰方案（包括初筛淘汰和深度测试后淘汰）的最终淘汰理由。
    5. 撰写推荐理由摘要，突出关键优势与潜在风险。
- **依赖**：
    - 步骤 2 完成且数据完整。
- **预期产出**：
    - 《最终选型决策矩阵》：包含评分详情。
    - 《推荐方案陈述》：一段式总结为何选择该方案。
    - 《备选方案陈述》：一段式总结备选方案的优势。
- **验收方式**：
    - 评分过程透明，每项分数有对应的事实依据（引用步骤 2 的报告内容）。
    - 推荐方案和备选方案的成本均严格 ≤ 20,000 CNY/年。

### 步骤 4：编制可交付报告
- **输入**：
    - 步骤 1 的《候选方案初筛表》。
    - 步骤 2 的《深度测试报告》、《精确成本明细表》。
    - 步骤 3 的《最终选型决策矩阵》、推荐/备选陈述、淘汰理由汇总。
- **动作**：
    1. 按照以下结构组装报告：
        - **执行摘要**：直接给出推荐方案、备选方案及核心理由。
        - **需求回顾**：重申硬性条件。
        - **推荐方案详情**：功能亮点、成本明细、实施路径。
        - **备选方案详情**：同上。
        - **淘汰方案分析**：表格形式列出所有被排除的方案及其具体淘汰原因。
        - **成本对比总览**：可视化图表展示各方案年度成本。
        - **风险评估与建议**：针对推荐方案的风险提示（如汇率、供应商锁定）及缓解措施。
    2. 格式化为 PDF 或 Markdown 文档。
    3. 内部审阅：确保所有数字一致，逻辑闭环，无遗漏硬性条件。
- **依赖**：
    - 步骤 1-3 所有产出物。
- **预期产出**：
    - 《会议室预约系统选型与成本分析报告 v1.0》（最终交付物）。
- **验收方式**：
    - 报告包含所有要求章节。
    - 所有成本数据加总正确，且不超过 20,000 CNY。
    - 每个被淘汰方案都有独立且合理的淘汰理由。
    - 门禁联动选项在报告中有所体现（即使是不支持，也需说明）。
    - 文档格式规范，可直接提交给管理层。

## 关键风险与应对（嵌入在上述步骤中）

| 风险点 | 影响步骤 | 应对措施 |
| :--- | :--- | :--- |
| 某些 SaaS 价格隐藏（需销售联系） | 步骤 1, 2 | 优先选择公开透明定价的工具；若必须联系销售，记录沟通时间线并在报告中注明“报价有效期”。 |
| 日历同步存在冲突或延迟 | 步骤 2 | 在测试中故意制造并发预约场景，记录日志；若问题严重，降级为备选或淘汰。 |
| 门禁联动需额外开发成本 | 步骤 2, 3 | 明确区分“软件授权费”与“集成开发费”。若集成成本导致总预算超标，则在不考虑门禁的情况下重新评估，或在报告中明确标注“门禁联动需额外支出 X 元，超出基础预算”。 |
| 汇率波动导致年度成本超支 | 步骤 2, 4 | 在成本明细中增加 5-10% 的汇率缓冲系数，或建议使用人民币结算渠道（如有）。 |
