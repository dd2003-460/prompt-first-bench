# 会议室预约系统选型报告 (v1.0)

**日期**: 2023-10-XX
**受众**: CTO, CFO, IT 部门负责人
**项目背景**: 为 30 人研发团队引入会议室预约系统，预算上限 20,000 RMB/年，需支持 macOS/Windows/Web 三端及 Google Calendar/Outlook 双日历集成。

---

## 1. 推荐方案：Roomle (Premium Plan)

### 1.1 核心推荐理由
经过对候选方案的全面评估（见阶段 02 证据），**Roomle** 是唯一能在预算内同时满足“全平台支持”、“双向日历同步”和“低维护成本”的商业 SaaS 解决方案。

*   **功能完备性**: Roomle 原生支持 Web、iOS、Android 客户端，完美覆盖 macOS/Windows/Web 需求。其核心优势在于**双向日历同步**（Two-way Sync），能实时在 Google Calendar 和 Outlook 中锁定会议室时段，避免双重预订，这是国内主流 SaaS（如飞书/钉钉）难以直接通过插件稳定实现的特性。
*   **成本可控**: 针对 5 间会议室（基于基线数据假设，若实际数量不同需重新核算，但在此范围内），Roomle Premium 计划约为 $90-$120/月。按汇率 7.2 计算，年费约 **8,640 - 10,368 RMB**。即使加上潜在的 API 开发或硬件微调成本，总年度成本仍远低于 20,000 RMB 预算红线，留有充足的安全边际。
*   **部署与维护**: 作为纯 SaaS 服务，无需内部服务器资源，无需专职运维人员。IT 团队仅需配置初始的 OAuth 授权和 iCal 链接即可投入使用，后续维护成本极低。
*   **门禁联动可行性**: Roomle 提供开放的 REST API 和 Webhooks。虽然不直接内置主流国产门禁品牌驱动，但通过轻量级的中间件脚本（Node.js/Python）监听 Webhook 并调用门禁控制接口，技术实现难度低（预计 1-2 人天工作量），且符合“可选门禁联动”的需求定位。

### 1.2 关键前提条件
*   **财务合规**: 需确认公司财务政策是否接受海外 SaaS 服务的形式发票（Proforma Invoice）及代扣代缴流程。若必须开具国内增值税专票，则此方案不可行（触发备选方案）。
*   **语言适应**: Roomle 界面主要为英文。鉴于研发团队普遍具备英语能力，且 UI 逻辑直观，预计学习曲线较短。建议制作一份简化的《中文操作指引》供行政和非技术人员参考。

## 2. 备选方案

若推荐方案因财务合规（无法开票）或重大功能缺陷被否决，以下方案按优先级排序作为备选。

### 备选方案 A: Frontdesk (Starter Plan)

*   **对比优势**:
    *   **本地化与合规**: Frontdesk 在中国市场有较好的落地经验，通常能提供符合中国财务要求的发票服务，彻底消除合规风险。
    *   **UI 友好**: 拥有优秀的中文界面和支持，员工上手零门槛。
    *   **生态整合**: 与微信/企业微信等国内办公生态结合较好。
*   **对比劣势**:
    *   **价格压力**: Starter 计划起步价较高，针对小团队（<10 用户或 <5 房间）往往没有明显的折扣空间。初步估算可能接近或超过 20,000 RMB/年的预算上限，需要极强的销售谈判能力才能压入预算。
    *   **日历集成深度**: 对 Google Calendar 的双向同步支持不如 Roomle 原生和稳定，可能需要依赖第三方连接器（如 Zapier），增加额外成本和故障点。
*   **适用场景**: 当公司财务强制要求国内发票，且 Roomle 无法解决时，Frontdesk 是首选替代，但需做好超预算或功能妥协的准备。

### 备选方案 B: 开源自托管方案 (例如: Booking.com 自托管版 或 定制 CalDAV 应用)

*   **对比优势**:
    *   **极致低成本**: 软件许可费为 0，仅需支付云服务器费用（约 1,000-2,000 RMB/年）。
    *   **数据主权**: 数据完全存储在内部服务器，无数据出境合规风险。
    *   **高度定制**: 可完全根据门禁型号定制对接逻辑，无任何 API 限制。
*   **对比劣势**:
    *   **开发与维护成本**: 需要 IT 部门投入显著的人力进行部署、安全加固、版本更新和 bug 修复。对于 30 人团队，若无专职后端开发人员，这将占用核心研发资源，隐性成本高。
    *   **用户体验**: 开源项目的 UI/UX 通常不如商业 SaaS 精致，移动端体验可能不佳，导致员工使用意愿低。
    *   **稳定性风险**: 缺乏 SLA 保障，出现故障时需自行排查解决。
*   **适用场景**: 仅当所有商业 SaaS 均因合规或价格被排除，且 IT 部门愿意承担长期维护责任时考虑。

## 3. 淘汰理由

以下候选方案在阶段 02 评估中被明确排除，依据如下：

| 候选方案 | 淘汰理由 |
| :--- | :--- |
| **Resource Guru** | **预算超标**: Resource Guru 的标准定价模式通常要求按“付费用户数”而非“会议室数量”收费。对于 30 人团队，即使只让部分人预订，其起价也往往远超 20,000 RMB/年。此外，其入门级套餐对高级日历集成的限制较多。 |
| **飞书 (Feishu) / 钉钉 (DingTalk)** | **功能局限**: 虽然免费或极低成本，但其会议室管理主要绑定在其自身的 IM 生态内。**不支持原生的 Google Calendar 双向同步**。若要实现跨平台日历集成，需依赖复杂的第三方插件或手动导出/导入 iCal，无法实现实时的冲突检测和自动锁定，违背了“自动化预约”的核心目标。 |
| **Microsoft Bookings** | **生态锁定**: 仅适用于 Outlook/Microsoft 365 环境。由于团队混合使用 Google Calendar 和 Outlook，Bookings 无法有效管理 Google 侧的会议室状态，会导致 G-Suite 用户看到错误的空闲状态。 |
| **传统 Excel/共享文档** | **效率低下**: 缺乏并发控制机制，极易出现双重预订。无法实现日历集成，人工协调成本高，不符合现代研发团队的工作流需求。 |

## 5. 风险与缓解措施

| 风险类别 | 风险描述 | 可能性 | 影响程度 | 缓解措施 (Mitigation) |
| :--- | :--- | :--- | :--- | :--- |
| **合规风险** | 公司财务拒绝报销海外 SaaS 费用，要求必须提供国内增值税专票。 | 中 | 高 | 1. **前置确认**: 在签约前务必获得 CFO 书面确认可接受 Proforma Invoice。<br>2. **备选切换**: 若被拒，立即启动备选方案 A (Frontdesk) 的谈判流程。<br>3. **税务咨询**: 咨询会计师关于跨境服务采购的代扣代缴操作流程，确保合规入账。 |
| **技术风险** | Google/Outlook 双向同步出现延迟或冲突漏检。 | 低 | 中 | 1. **POC 验证**: 在正式采购前完成为期 1 周的 POC 测试，重点模拟高峰期的并发预订。<br>2. **监控告警**: 利用 Roomle 的管理后台日志，定期检查同步状态。<br>3. **降级预案**: 若同步严重失效，临时改用单向 iCal 订阅 + 人工核对模式。 |
| **运营风险** | 员工因英文界面不熟悉而抵制使用，继续使用口头预约。 | 中 | 中 | 1. **简易手册**: 制作一页纸的《Roomle 快速指南》，包含截图和中英对照。<br>2. **行政推动**: 规定行政前台仅在系统中查询可用房间，不再接受口头预订。<br>3. **激励措施**: 初期鼓励大家使用，对频繁违规者进行温和提醒。 |
| **集成风险** | 现有门禁系统老旧，无法通过 API 联动，导致“可选功能”无法实现。 | 中 | 低 | 1. **分步实施**: 将门禁联动定义为 Phase 2 项目。Phase 1 先上线软件预约功能。<br>2. **独立硬件**: 若旧门禁无法改造，考虑在关键会议室安装独立的智能门锁（如小米/凯迪仕），通过 Roomle API 直接控制新锁，绕过旧系统。 |
| **数据安全风险** | 员工个人信息（姓名、邮箱）存储于海外服务器，涉及 PIPL 合规问题。 | 低 | 高 | 1. **DPA 签署**: 与 Roomle 签署数据处理协议 (Data Processing Agreement)，明确数据保护责任。<br>2. **最小化原则**: 仅收集必要的邮箱地址用于日历同步，不存储密码或其他敏感信息。<br>3. **出口评估**: 若公司有大额数据出境申报要求，需提前完成安全评估备案（通常小型团队豁免，需法务确认）。 |

## 6. 下一步行动计划 (Next Steps)

1.  **本周内**: 向 CFO 提交本报告，重点说明成本优势及合规处理方式，获取预算批准。
2.  **下周初**: IT 部门注册 Roomle 试用账号，执行阶段 03 中的步骤 2（POC 验证），重点测试日历同步稳定性和 API 连通性。
3.  **下周中**: 根据 POC 结果，若一切正常，联系 Roomle 销售获取正式报价单和合同草案；若发现致命问题，立即启动 Frontdesk 备选评估。
4.  **下周五**: 确定最终供应商，启动合同签署流程。

**结论**: 建议批准采用 **Roomle** 作为会议室预约系统，预计年度总成本约 **9,600 RMB**，节省预算近 50%，并能有效解决当前会议室管理混乱的问题。
