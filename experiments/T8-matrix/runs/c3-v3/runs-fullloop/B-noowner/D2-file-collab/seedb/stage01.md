# 阶段 01：目标分解、已知与空缺条件

## 1. 目标交付物定义
**最终交付物**：一份可执行的《30人研发团队文件协作/网盘选型报告》。
**核心内容**：
1. **推荐方案**：满足所有硬性约束且综合得分最高的单一方案。
2. **备选方案**：至少1个次优方案，作为风险对冲。
3. **淘汰理由**：对主要候选竞品逐一列出因违反某项硬约束或关键短板而被排除的理由。
4. **成本明细**：基于30人规模、年度总花费≤3万元人民币的详细预算拆解（含软件订阅费、可能的硬件/带宽附加费等）。

---

## 2. 影响因素递归分解

### 顶层因素 (Level 1)
为了选出最佳方案，必须评估以下正交维度：
1. **功能合规性 (Functional Compliance)**：是否满足Web/macOS/Windows全平台支持及两大核心功能。
2. **经济性 (Economic Feasibility)**：是否在3万元/年的预算内，且具备性价比优势。
3. **体验与扩展性 (UX & Extensibility)**：离线能力、同步性能、团队管理便捷性等加分项。
4. **安全性与稳定性 (Security & Stability)**：数据主权、访问控制粒度、服务SLA。

#### Level 2 分解与原子化

##### 2.1 功能合规性
*   **2.1.1 平台覆盖 (Hard Constraint)**
    *   **子因素 A**: Web端可用性（浏览器兼容性、在线编辑能力）。
    *   **子因素 B**: macOS客户端存在性及原生体验。
    *   **子因素 C**: Windows客户端存在性及原生体验。
    *   *状态*: **已知约束**。所有候选必须同时具备三者。
*   **2.1.2 文档版本管理 (Core Feature)**
    *   **子因素 A**: 历史版本保留策略（无限 vs 有限天数/数量）。
    *   **子因素 B**: 版本对比/回滚操作便捷性。
    *   **子因素 C**: 多人并发编辑时的冲突处理机制（合并 vs 覆盖）。
    *   *状态*: **待研究**。需验证各候选的具体实现深度。
*   **2.1.3 细粒度权限控制 (Core Feature)**
    *   **子因素 A**: 权限层级（文件夹级 vs 文件级 vs 块级/行级）。
    *   **子因素 B**: 角色预设丰富度（仅所有者/编辑者/查看者 vs 自定义角色）。
    *   **子因素 C**: 外部协作者权限隔离与管理。
    *   *状态*: **待研究**。“细粒度”定义模糊，需界定为“文件/文件夹级+独立链接权限”即达标，还是必须达到“文档内段落级”。

##### 2.2 经济性
*   **2.2.1 直接订阅成本 (Hard Constraint: ≤30,000 RMB/Year)**
    *   **子因素 A**: 单用户单价 (Per User Per Month/Year)。
    *   **子因素 B**: 最低起购人数限制（是否有50人起买等门槛）。
    *   **子因素 C**: 存储容量包含量 vs 超额费用（30人团队预计占用空间？若默认容量不足，额外费用是否计入总预算？）。
    *   **子因素 D**: 计费模式（按席位 vs 按容量 vs 混合）。
    *   *状态*: **待研究**。需获取最新企业版定价表。
*   **2.2.2 隐性成本**
    *   **子因素 A**: 实施/迁移成本（人力投入估算，通常不计入现金预算但影响ROI）。
    *   **子因素 B**: 集成成本（如需对接现有SSO/LDAP，是否产生额外API费用或定制开发费）。
    *   *状态*: **低优先级**。主要关注现金支出，隐性成本仅作备注。

##### 2.3 体验与扩展性
*   **2.3.1 离线使用 (Bonus Feature)**
    *   **子因素 A**: 客户端本地缓存机制（断网时可读/可写？）。
    *   **子因素 B**: 同步队列可靠性（重连后数据一致性保证）。
    *   *状态*: **待研究**。标注为加分项，不作为一票否决项。
*   **2.3.2 协同效率**
    *   **子因素 A**: 实时协同编辑延迟。
    *   **子因素 B**: 移动端支持情况（虽非硬性要求，但研发场景可能涉及移动审批/查看，属参考因素）。

##### 2.4 安全性与稳定性
*   **2.4.1 数据主权与合规**
    *   **子因素 A**: 数据存储地（国内节点 vs 海外节点，影响访问速度及合规性）。
    *   **子因素 B**: 私有化部署选项（若SaaS不满足安全审计，是否需要On-Premise？注：On-Premise通常成本远超3万，大概率排除，除非有极廉价社区版+自建服务器方案，但运维成本高，需评估）。
    *   *状态*: **推导条件**。3万预算基本锁定SaaS模式，除非是开源自托管。
*   **2.4.2 访问控制增强**
    *   **子因素 A**: SSO/SAML/OIDC支持（企业级身份认证标准）。
    *   **子因素 B**: 审计日志（谁在何时下载/修改了什么）。

## 3. 条件分类清单

### 3.1 人类已提供的确定条件 (Given)
1.  **团队规模**: 30人。
2.  **年度总预算上限**: 30,000 RMB / Year。
3.  **强制平台**: Web, macOS, Windows。
4.  **核心功能1**: 文档版本管理。
5.  **核心功能2**: 细粒度权限控制。
6.  **加分项**: 离线使用。

### 3.2 从项目推导的确定条件 (Derived)
1.  **服务模式倾向**: 鉴于3万/年预算和30人规模，**SaaS订阅制**是最可能的主路径。私有化部署（On-Premise）通常涉及服务器硬件、运维人力，首年成本极易突破3万，除非使用极轻量级的开源方案（如Nextcloud Community Edition）且已有闲置服务器。因此，候选集应聚焦于主流SaaS网盘/文档协作工具，辅以少量低成本自托管开源方案作为极端备选。
2.  **人均月预算**: $30,000 / 30 \text{ people} / 12 \text{ months} = 83.33 \text{ RMB/person/month}$。这是筛选候选的关键阈值。任何人均月费显著高于此值（例如 >100 RMB）的方案需警惕超支风险（考虑汇率波动、涨价、存储超额）。
3.  **“细粒度权限”基线定义**: 在无特殊说明下，定义为：**支持文件夹/文件级别的读写/只读/无权限区分，且支持生成带有效期/密码保护的分享链接。** 若方案仅支持“全员可见”或仅两级权限，则视为不满足核心功能2。

### 3.3 仍需研究的条件 (Unknowns / Gaps) -> **阶段 02 研究入口**

| ID | 空缺条件描述 | 阻塞后续判断 | 优先级 |
|----|-------------|--------------|--------|
| **G1** | **候选名单冻结**: 哪些主流产品符合“Web+Mac+Win”基础形态？（需排除纯移动端优先、纯Linux、或仅Web无桌面客户端的产品） | 无法开始具体属性比对 | P0 |
| **G2** | **精确价格结构**: 各候选针对30人规模的**当前有效**报价（含存储配额）。是否区分“基础版/专业版/企业版”？哪一档才解锁“细粒度权限”？ | 无法计算是否在3万预算内 | P0 |
| **G3** | **版本管理深度**: 各候选的版本历史保留时长（如：永久、30天、90天？）及并发冲突处理逻辑。 | 无法判断是否满足核心功能1的深度要求 | P1 |
| **G4** | **权限控制粒度实测**: 各候选是否支持“特定用户只能看特定文件”？是否支持“外部访客单独授权”？ | 无法判断是否满足核心功能2 | P1 |
| **G5** | **离线同步能力**: 各候选桌面客户端是否支持完整的离线编辑与自动同步？ | 用于评分加分项 | P2 |
| **G6** | **数据存储位置与合规**: 各候选在中国大陆的数据中心节点分布，以及是否提供国内发票/合同主体（影响采购流程）。 | 影响实际可用性和采购可行性 | P1 |
| **G7** | **SSO支持**: 是否支持LDAP/AD/SAML？（研发团队常依赖内部账号体系） | 影响集成难度和安全性评价 | P2 |

## 4. 候选对象类别与初步假设 (Candidate Hypotheses)

*注意：以下列表仅为基于市场常识的**待验证假设**，未进行任何价格或功能核验。阶段 02 必须逐一核验并显式记录增删理由。*

### A类：国际主流云盘/协作套件 (High Probability Candidates)
1.  **Dropbox**: 假设支持全平台，版本管理强，但价格较高，需验证30人是否在预算内。
2.  **OneDrive for Business (Microsoft 365)**: 假设绑定Office套件，权限依托SharePoint/Teams，需验证单独购买OneDrive或M365 Basic/Business Standard的价格及权限粒度。
3.  **Google Workspace (Drive)**: 假设全平台支持好，版本管理优秀，但中国大陆访问稳定性存疑（需验证是否有合规加速通道或接受不稳定风险）。
4.  **Box**: 假设企业级权限极强，但价格昂贵，可能超出预算。
5.  **Nextcloud (Self-Hosted or SaaS like Nextcloud Plus)**: 假设开源免费但需运维；SaaS版价格适中。需验证其“细粒度权限”配置复杂度。

### B类：国内主流网盘/协作平台 (High Relevance for CN Context)
1.  **腾讯企业微信/腾讯微云企业版**: 假设与IM深度集成，权限跟随组织架构，需验证独立文档版本管理能力。
2.  **钉钉 (DingTalk) + 钉盘/语雀**: 假设生态封闭，权限随钉钉组织，需验证跨组织权限及版本管理细节。
3.  **飞书 (Feishu/Lark) + 云文档**: 假设文档协同体验极佳，版本管理原生支持，需验证30人套餐价格及离线能力。
4.  **坚果云 (Jianguoyun)**: 假设专注增量同步，版本管理细致，需验证企业版价格及权限粒度。
5.  **百度网盘企业版**: 假设存储便宜，但文档协同和版本管理可能较弱，需验证是否满足“文档版本管理”核心功能。

### C类：垂直领域/新兴工具
1.  **Notion**: 假设适合知识管理，但作为“网盘”替代品可能在二进制文件同步上不如传统网盘，且价格需验证。
2.  **Confluence (Atlassian)**: 假设偏向Wiki而非文件存储，需验证是否被归类为“文件协作”，通常不作为主网盘，可能排除。

### 排除逻辑预判 (To be verified in Stage 02)
*   **排除**: 仅提供Web端无稳定桌面客户端的产品（违反平台约束）。
*   **排除**: 仅支持个人版、无企业级权限控制功能的产品（违反核心功能2）。
*   **排除**: 30人起步价超过3万/年的方案（违反预算约束），除非有明确的折扣渠道（需标记为高风险）。

## 5. 阶段 02 研究路径规划

### 5.1 第一批行动 (Priority Actions)

1.  **构建候选短名单 (Verify G1)**:
    *   **动作**: 访问上述 A/B/C 类候选的官网。
    *   **搜索词**: "[Product Name] enterprise pricing", "[Product Name] desktop client download", "[Product Name] file versioning".
    *   **字段提取**: 确认是否有 Mac/Win 客户端下载链接；确认是否有企业版/团队版。
    *   **失败备用**: 若官网信息不全，查阅 G2 (Geekbench/PCMag) 或国内 IT 媒体评测。

2.  **价格核验 (Verify G2)**:
    *   **动作**: 进入各候选的 Pricing 页面。
    *   **关键查询**: 寻找 "Business", "Team", "Enterprise" 档位。记录每用户每月价格 (USD/RMB) 和包含的存储空间 (GB/TB per user)。
    *   **计算**: `Total_Cost = Users(30) * Price_Per_User_Month * 12`。检查是否 ≤ 30,000 RMB。
    *   **汇率**: 若为 USD 计价，使用近期平均汇率（约 7.1-7.2）换算，并预留 5% 缓冲。
    *   **来源类型**: 官方定价页（一手）、第三方比价网站（二手）。

3.  **功能深度核验 (Verify G3, G4)**:
    *   **动作**: 查阅 Help Center / Documentation。
    *   **搜索词**: "version history limit", "permission levels", "granular access control", "offline editing".
    *   **判定标准**:
        *   版本管理: 是否明确写出保留时间？是否支持恢复任意版本？
        *   权限: 是否支持 "Specific users only"？是否支持 "Link sharing with expiration"？
    *   **来源类型**: 官方文档、YouTube 演示视频截图、用户论坛反馈。

4.  **离线与稳定性 (Verify G5, G6)**:
    *   **动作**: 查找 "offline sync" 相关文档。
    *   **地域**: 确认服务器节点是否位于中国境内（对于国内团队至关重要）。
    *   **来源类型**: 官方 FAQ、知乎/Reddit 用户讨论（关于国内访问速度）。

### 5.2 数据来源优先级
1.  **官方一级来源**: 官网定价页、官方技术文档、官方博客。
2.  **二级权威来源**: Gartner, Forrester 报告摘要, TechCrunch, InfoQ 等专业科技媒体报道。
3.  **三级用户实证**: Reddit (r/sysadmin, r/productivity), V2EX, 知乎, 用户评论（用于验证实际体验和隐藏坑点）。

### 5.3 失败处理策略
*   若某候选无法找到公开的企业版详细权限说明 -> 标记为“信息不透明”，降低优先级或联系销售（若时间允许，否则排除）。
*   若价格页面动态加载且无法抓取 -> 使用 `ego-browser` 模拟浏览或查找最近 3 个月内的第三方评测文章中的价格截图。

## 6. 空缺条件与阻塞关系总结

| 空缺 ID | 缺失内容 | 若不解决将导致 | 阶段 02 必须产出 |
|---------|----------|----------------|------------------|
| G1 | 最终候选名单 | 无法进行横向对比 | 一张包含 5-8 个候选的表格，注明入选/初筛理由 |
| G2 | 准确年费总额 | 无法判断是否符合 3 万预算 | 每个候选的精确年费计算过程及结果 |
| G3 | 版本管理规则 | 无法确认核心功能1达标 | 每个候选的版本保留策略摘要 |
| G4 | 权限粒度详情 | 无法确认核心功能2达标 | 每个候选的权限层级矩阵（用户/组/外部） |
| G5 | 离线能力 | 无法完成加分项评分 | 每个候选的离线支持 Yes/No 及简要说明 |
| G6 | 国内可用性 | 可能导致方案落地失败 | 每个候选的国内节点/访问速度评估 |

**结论**: 阶段 01 已完成目标分解，明确了已知约束、推导条件和关键空缺。阶段 02 可直接依据上述“研究路径”和“空缺清单”开始执行资料搜集。无需进一步细化阶段 01。
