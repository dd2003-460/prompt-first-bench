# 阶段 01：目标分解、已知与空缺条件

## 1. 目标交付物定义
**最终交付物**：一份可执行的《30人研发团队文件协作/网盘选型报告》。
**核心内容包含**：
1. **推荐方案**（Primary Recommendation）：满足所有硬约束的最佳单一方案或组合方案。
2. **备选方案**（Alternative）：若首选不可行时的次优解。
3. **淘汰理由清单**：明确列出被排除的主流候选及其具体违反的约束点。
4. **成本明细表**：基于30人规模、年费预算≤¥30,000的详细费用拆解（含存储扩容、功能模块费等）。
5. **实施建议**：简要的迁移策略或权限配置最佳实践。

## 2. 影响因素正交分解

我们将选型问题分解为以下五个互相正交且覆盖完整的目标因素：

### 因素 A：功能合规性 (Functional Compliance)
*   **A1: 文档版本管理深度**
    *   子因素 A1a: 是否支持自动历史版本快照？
    *   子因素 A1b: 版本恢复粒度（文件级 vs 块级/字符级）？
    *   子因素 A1c: 在线协同编辑时的冲突处理机制（OT/CRDT）？
*   **A2: 细粒度权限控制 (Granular Permission Control)**
    *   子因素 A2a: 权限层级（根目录 -> 文件夹 -> 单文件）？
    *   子因素 A2b: 角色自定义能力（只读/评论/编辑/管理）？
    *   子因素 A2c: 链接分享权限控制（有效期、密码、禁止下载/打印）？
    *   子因素 A2d: 审计日志（谁在何时修改了什么）？
*   **A3: 多端客户端支持**
    *   子因素 A3a: Web端可用性（浏览器兼容性）？
    *   子因素 A3b: macOS 原生客户端性能与同步稳定性？
    *   子因素 A3c: Windows 原生客户端性能与同步稳定性？
    *   子因素 A3d: 移动端支持（加分项，非硬性，但需确认是否存在）？

### 因素 B：技术架构与体验 (Technical Architecture & UX)
*   **B1: 离线可用性 (Offline Capability)**
    *   子因素 B1a: 断网状态下能否继续编辑本地文件？
    *   子因素 B1b: 恢复网络后的增量同步策略与冲突解决成功率？
    *   子因素 B1c: 大文件/二进制文件的离线同步效率？
*   **B2: 数据存储与传输安全**
    *   子因素 B2a: 传输加密标准 (TLS 1.2+)？
    *   子因素 B2b: 静态数据加密 (AES-256)？
    *   子因素 B2c: 端到端加密 (E2EE) 支持情况（通常影响服务端搜索/预览能力）？
*   **B3: 系统集成能力**
    *   子因素 B3a: SSO/SAML/OIDC 集成（对接研发常用身份系统如 GitHub/Google Workspace/Microsoft AD）？
    *   子因素 B3b: API 开放性（便于自动化脚本调用）？
    *   子因素 B3c: 第三方应用生态（如 Notion, Jira, Slack 集成）？

### 因素 C：成本与商务约束 (Cost & Commercial Constraints)
*   **C1: 总拥有成本 (TCO) 合规**
    *   子因素 C1a: 基础订阅费（30席）是否 ≤ ¥30,000/年？
    *   子因素 C1b: 存储容量限制及超额费用？
    *   子因素 C1c: 增值服务费用（如高级版权限、审计日志、SSO）是否包含在基础包内？
*   **C2: 采购与合规风险**
    *   子因素 C2a: 供应商在中国大陆的实体或代理（发票、合同、SLA响应速度）？
    *   子因素 C2b: 数据驻留地（中国大陆境内 vs 境外）？*注：虽然任务未明确要求数据不出境，但对于研发团队，这是重要的隐性风险因素，需作为待研究项。*

### 因素 D：运维与支持 (Operations & Support)
*   **D1: 技术支持等级**
    *   子因素 D1a: SLA 可用性承诺（99.9% vs 99.99%）？
    *   子因素 D1b: 中文技术支持渠道（邮件/电话/工单）？
*   **D2: 部署模式**
    *   子因素 D2a: SaaS (公有云) vs 私有化部署 (On-premise)？
    *   *推导：鉴于预算仅3万/年且团队30人，私有化部署硬件+软件授权+维护成本极大概率超标，故默认锁定 SaaS 模式，除非发现极低成本的开源自托管方案（需验证运维人力成本）。*

### 因素 E：迁移与学习成本 (Migration & Learning Curve)
*   **E1: 数据迁移难度**
    *   子因素 E1a: 提供官方迁移工具（从 OneDrive/Dropbox/腾讯微盘等）？
    *   子因素 E1b: 元数据（权限、版本历史）保留能力？
*   **E2: 用户上手难度**
    *   子因素 E2a: 界面直观性？
    *   子因素 E2b: 是否有完善的中文帮助文档？

### 3.2 从项目背景可推导的条件 (Derived Conditions)
| ID | 推导逻辑 | 推导结论 |
|----|----------|----------|
| D1 | 预算3万/30人 = 人均1000元/年 ≈ $14 USD/人/年 | 价格筛选阈值：单人单月成本需控制在 ~$1.17 USD 以内（不含大额存储扩容）。这排除了大多数高端企业级SaaS（如Box Enterprise, SharePoint Premium per-user high tier），指向中端或高性价比方案。 |
| D2 | "研发团队" + "文档版本管理" | 暗示可能需要代码文件（Git仓库）之外的文档（设计稿、PRD、会议纪要）的版本管理。若需管理代码，通常使用 Git 平台（GitHub/GitLab），而非网盘。因此，本选型对象应聚焦于**非代码类办公文档/资产**的协作网盘，或具备文档协同功能的网盘。*假设：此处“文档”指 Office/PDF/Markdown/设计源文件，而非源代码库。* |
| D3 | "细粒度权限" + "研发团队" | 通常需要区分项目组权限，避免A组看到B组的敏感设计稿。要求至少支持“文件夹级别”的独立权限设置，而非仅全局共享。 |
| D4 | 预算 < ¥30k | 基本排除需要购买物理服务器进行私有化部署的方案（硬件+License+运维人力远超此预算）。锁定 **SaaS 公有云服务**。 |

### 3.3 仍需研究的条件 (Open Questions / Unknowns)
*这些是阶段 02 必须重点核验的空缺项。*

| ID | 空缺条件 | 阻塞的判断 | 优先级 |
|----|----------|------------|--------|
| U1 | **主流候选方案的实时定价**：针对30席、不同存储档位（1TB/5TB/无限）的具体年费。 | 无法判断哪些方案符合预算。 | High |
| U2 | **各方案的“细粒度权限”定义差异**：例如，某些网盘仅支持“所有者/协作者”，不支持自定义角色；某些支持“文件夹继承权限”。 | 无法判断是否真正满足“细粒度”需求。 | High |
| U3 | **离线同步的实际表现**：特别是 macOS/Windows 客户端在断网重连后的大文件冲突处理机制。 | 无法评估加分项的真实价值。 | Medium |
| U4 | **中国大陆访问速度与稳定性**：部分海外服务（如 Dropbox, Box）在国内直连速度极慢或需翻墙，严重影响研发效率。 | 可能直接导致某优秀方案被淘汰。 | High |
| U5 | **数据合规性**：主要候选方案的数据中心位置及是否符合中国《数据安全法》相关要求（虽非硬性法律红线，但企业风控常关注）。 | 影响最终决策的风险评估。 | Low/Medium |
| U6 | **免费/低价额度陷阱**：许多服务标称的价格是否包含 SSO、高级审计、API 访问等“细粒度权限”所需的高级功能？ | 可能导致实际落地成本超预算。 | High |
| U7 | **特定文件格式的支持**：是否支持 Markdown 在线预览/编辑？是否支持 Visio/Figma 文件预览？（研发团队常见格式） | 影响用户体验。 | Low |

## 4. 候选对象类别与初始假设 (Candidate Hypotheses)

*注意：以下仅为基于市场常识的**待验证假设**，具体属性需在阶段 02 核验。*

### 第一梯队：国内主流 SaaS 网盘/协作平台（预期访问速度快，合规性好）
1.  **飞书 (Feishu/Lark) - 文档/云空间**
    *   *假设*：版本管理极强（文档级），权限细粒度（文档/文件夹级），支持 Web/Mac/Win，离线可用。
    *   *待验证*：纯网盘功能是否独立计费？30人专业版/旗舰版价格是否在3万内？
2.  **钉钉 (DingTalk) - 钉盘/文档**
    *   *假设*：同上，集成度高。
    *   *待验证*：高级权限和版本回溯功能是否锁在更高等级套餐中？
3.  **腾讯云微盘 (Tencent Cloud Micro Disk)**
    *   *假设*：专注网盘，性价比高。
    *   *待验证*：细粒度权限控制能力（是否支持复杂的项目组隔离）？版本管理深度？
4.  **坚果云 (Jianguoyun)**
    *   *假设*：以同步稳定著称，适合研发小文件高频同步。
    *   *待验证*：价格体系（按GB还是按人）？是否支持多人实时协同编辑文档？（传统网盘弱项）
5.  **亿方云 (Yifangyun) / 天翼云盘企业版**
    *   *假设*：主打企业安全，权限管控严格。
    *   *待验证*：30人小规模用户的起步价格是否友好？

### 第二梯队：国际知名 SaaS 网盘（功能成熟，但需验证国内可用性与价格）
6.  **Dropbox**
    *   *假设*：同步引擎极佳，版本管理完善。
    *   *待验证*：国内直连速度（通常较差，需加速器）？Team/Business 计划30人价格（通常较高，可能超预算）？
7.  **OneDrive for Business (Microsoft 365)**
    *   *假设*：Office 集成最好，权限强。
    *   *待验证*：30个 M365 Business Standard 许可的年费（通常 >$8/user/month，30人约 $2880/年 ≈ ¥2万+，加上存储限制需核实）。国内访问 OneDrive 的速度问题。
8.  **Box**
    *   *假设*：企业级安全标杆。
    *   *待验证*：价格通常昂贵，30人小规模可能不划算或无最低席位优惠。国内可用性。

### 第三梯队：开源/自托管（排除或低优先）
9.  **Nextcloud / Seafile**
    *   *假设*：完全免费，权限极细，版本管理好。
    *   *排除理由预判*：需要自建服务器（阿里云/腾讯云 ECS + OSS），30人并发下的硬件成本、带宽成本、以及**专人运维的人力成本**（即使兼职）极易超过3万/年的隐性成本。且缺乏原厂商业支持。
    *   *状态*：列入备选，仅在预算极度紧张且团队有DevOps余力时考虑。

## 5. 阶段 02 研究路径 (Research Plan for Phase 02)

### 5.1 第一批行动：价格与套餐结构核验
*   **目标**：获取上述候选方案中，适用于30人团队的最低可行套餐（Entry-level Enterprise/Professional plan）的准确年费。
*   **动作**：
    1.  访问各官网 Pricing Page。
    2.  查找 "30 users" 或 "Small Team" 档位。
    3.  记录：单价、总年费、包含存储空间、包含的高级功能（SSO, Audit Log）。
    4.  **关键搜索词**：`[Product Name] pricing 30 users annual`, `[Product Name] enterprise edition cost China`.
    5.  **备用路径**：若官网价格模糊，寻找近期（2023-2024）的用户评测文章或G2/Capterra上的价格提及。

### 5.2 第二批行动：功能细节深潜 (Feature Deep Dive)
*   **目标**：验证“细粒度权限”和“版本管理”的具体实现。
*   **动作**：
    1.  **权限**：查阅 Help Center 关于 "Permission Inheritance", "Folder Level Permissions", "Custom Roles" 的文档。
    2.  **版本**：查阅 "Version History", "Restore Version", "Conflict Resolution" 文档。
    3.  **离线**：查阅 "Offline Access", "Sync Engine" 文档，特别关注 Mac/Win 客户端说明。
    4.  **对比矩阵**：建立 Excel 表格，列头为候选产品，行头为 U1-U7 中的具体问题，填入 Yes/No/Paid Add-on。

### 5.3 第三批行动：国内可用性与口碑
*   **目标**：评估网络速度和用户满意度。
*   **动作**：
    1.  搜索知乎、V2EX、SegmentFault 上关于 `[Product Name] 国内速度` 或 `[Product Name] 坑` 的讨论。
    2.  重点观察近半年内的负面反馈（如：同步失败率高、客服响应慢、强制升级收费）。

### 5.4 失败备用路径 (Fallback if Data Missing)
*   若某厂商拒绝公开30人报价，标记为“需销售询价”，并在报告中注明“预估范围”及“不确定性高”。
*   若某国外服务在国内无法直连且无官方加速方案，直接标记为“高风险”，除非其功能优势极大且团队愿意承担翻墙/专线成本。

## 6. 总结与门槛检查

*   **目标清晰**：交付选型报告。
*   **因素覆盖**：功能、技术、成本、运维、迁移五大维度覆盖全面。
*   **已知/未知分离**：明确了预算、人数、平台为已知；价格、具体权限颗粒度、国内速度为未知。
*   **空缺清单**：U1-U7 明确了阶段02的研究焦点。
*   **候选集冻结**：列出了国内三大系（飞书/钉钉/腾讯）、垂直网盘（坚果云/亿方云）、国际三大（Dropbox/OneDrive/Box）及开源备选。后续阶段不得随意增加其他无关品牌（如百度网盘个人版转企业版，因其权限模型不符，已在推导中隐含排除，若02阶段发现其企业版有特殊政策再单独记录）。
*   **可操作性**：阶段02可直接依据 5.1-5.3 的路径开始执行搜索和数据抓取。

**判定**：阶段 01 完成，允许进入阶段 02。
