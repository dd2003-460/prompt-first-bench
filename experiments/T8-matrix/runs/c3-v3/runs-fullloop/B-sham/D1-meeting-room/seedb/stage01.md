# 阶段 01：目标分解、已知与空缺条件

## 1. 任务目标交付物定义

本任务旨在为一家 30 人的研发团队选择并推荐一个会议室预约系统，最终产出一份**可交付选型报告**。
报告必须包含以下核心组件：
1. **推荐方案**：满足所有硬性条件的最佳单一方案。
2. **备选方案**：次优但可用的方案。
3. **淘汰理由**：明确列出被排除的方案及其违反的具体约束或劣势。
4. **完整成本明细**：基于年度预算 ≤ 2 万元人民币的精确费用拆解（含软件许可、集成开发、硬件/门禁等）。

## 2. 顶层影响因素分解 (Orthogonal Factors)

为了覆盖“选型”这一复合目标，将影响决策的因素分解为以下五个正交维度：

### 因素 A：功能合规性 (Functional Compliance)
*   **子因素 A1：多端支持能力**
    *   必须同时支持 macOS 客户端、Windows 客户端、Web 浏览器访问。
    *   *边界*：原生 App vs Electron/PWA 均视为满足“支持”，但需评估体验差异。
*   **子因素 A2：日历双向同步能力**
    *   必须能对接 Google Calendar 和 Outlook (Exchange/Microsoft 365)。
    *   *边界*：“对接”通常指单向订阅或双向同步？对于会议室预约，通常需要**双向同步**以避免冲突（即会议室在 GCal/Outlook 中被占用时，预约系统应显示不可用；反之亦然）。若仅支持单向，需评估工作流风险。
*   **子因素 A3：门禁联动能力 (Optional)**
    *   有则加分。
    *   *边界*：是否提供 API/Webhook？是否需要额外硬件网关？

### 因素 B：商业与成本模型 (Commercial & Cost Model)
*   **子因素 B1：软件许可费用 (SaaS Subscription)**
    *   按用户数、房间数还是固定年费计费？
    *   *边界*：30 人团队中，并非所有人都会频繁使用会议室预约功能。需确认计费基数是“所有员工”还是“活跃管理员/预订者”。
*   **子因素 B2：实施与集成成本 (Implementation & Integration)**
    *   对接 Google/Outlook 日历是否需要付费插件或人工配置工时？
    *   门禁联动是否需要购买中间件或定制开发？
*   **子因素 B3：总拥有成本 (TCO) 约束**
    *   年度总成本 ≤ 20,000 CNY。
    *   *边界*：此预算是否包含潜在的硬件升级？题目未提及新购硬件，假设现有门禁系统存在或无需改造，主要考察软件及服务成本。

### 因素 C：技术架构与部署模式 (Technical Architecture)
*   **子因素 C1：部署方式**
    *   SaaS (云端托管) vs Self-Hosted (自托管)。
    *   *推导*：SaaS 通常维护成本低，但数据出境/合规性需考虑；Self-Hosted 可能免费或一次性买断，但需运维人力成本（隐性成本）。
*   **子因素 C2：API 开放性与扩展性**
    *   是否提供标准 REST API 用于未来可能的内部系统集成。

### 因素 D：用户体验与易用性 (UX & Usability)
*   **子因素 D1：移动端体验**
    *   Web 端在移动设备上的响应式表现，或是否有独立的 iOS/Android App（虽非硬性要求，但影响日常使用率）。
*   **子因素 D2：管理后台复杂度**
    *   创建会议室、设置规则、查看报表的操作门槛。

### 因素 E：供应商稳定性与支持 (Vendor Stability)
*   **子因素 E1：服务可用性 SLA**
    *   对于办公场景，系统宕机的容忍度较低。
*   **子因素 E2：本地化支持**
    *   是否提供中文文档、客服支持？时差问题？

## 4. 递归分解检查与原子性判定

*   **因素 A (功能)**:
    *   A1 (多端): 已原子化到 OS 级别。
    *   A2 (日历): 已原子化到具体日历服务 (GCal/Outlook) 和同步方向 (隐含双向需求)。
    *   A3 (门禁): 已标记为可选，无需进一步分解，除非选定方案后需深入其 API 文档。
*   **因素 B (成本)**:
    *   B1/B2/B3: 已分解为许可、实施、总控。B1 中的“计费基数”已列入空缺 G6。
*   **因素 C (技术)**:
    *   C1 (部署): SaaS vs Self-hosted 是二元对立，已原子化。
    *   C2 (API): 作为加分项或未来扩展性指标，无需进一步分解。
*   **因素 D (UX)**:
    *   D1/D2: 属于定性评估，依赖于具体产品的试用或评测资料，目前保持宏观即可。
*   **因素 E (供应商)**:
    *   E1/E2: 属于背景调查，依赖于具体厂商信息。

**判定**: 所有叶子因素均已最小化，无进一步分解必要。分解完成。

## 5. 阶段 02 研究入口与行动路径

基于上述空缺 (G1-G7)，阶段 02 应立即执行以下研究动作：

### 5.1 候选对象筛选策略 (Candidate Pooling)

由于预算有限 (20k RMB) 且需跨国日历支持，候选池分为三类：
1.  **国际主流 SaaS (Global SaaS)**: 功能强大，但需关注价格和国内访问速度。
    *   *候选假设*: Zoom Rooms, Microsoft Bookings (部分免费), Calendly (Pro plan), Roomle, Mixmax.
    *   *待验证*: 价格是否超标？国内访问是否流畅？
2.  **微软生态原生方案 (Microsoft Native)**: 既然要接 Outlook，利用 M365 自带功能可能是最低成本路径。
    *   *候选假设*: Microsoft Bookings + Teams Meeting Rooms + Exchange Online.
    *   *待验证*: 是否已包含在现有 Office 365 订阅中？额外成本是多少？
3.  **国内/亚洲本地化 SaaS (Local SaaS)**: 针对国内网络优化，可能有更好的本地支持和更低价格。
    *   *候选假设*: 钉钉会议室 (若使用钉钉), 飞书会议室 (若使用飞书), 独立软件如 "EasyMeeting" (需搜索), "Roomy".
    *   *待验证*: 是否支持 macOS/Win 客户端？能否对接 Google Calendar (很多国内软件只强项对接自家 IM)？

### 5.2 具体研究步骤 (Action Items for Stage 02)

1.  **价格核验 (针对 G1, G6)**:
    *   *动作*: 访问上述候选官网 Pricing 页面。
    *   *搜索词*: "[Product Name] pricing per user per year", "[Product Name] enterprise cost calculator".
    *   *字段提取*: 月费/年费、最低起售人数、是否按房间收费、是否有免费层。
    *   *备用路径*: 若官网价格模糊，查找最近 6 个月内的 TechCrunch, G2, Capterra 评测文章中的报价截图或用户评论。

2.  **日历集成能力核验 (针对 G2)**:
    *   *动作*: 查阅官方 Help Center 或 Developer Docs。
    *   *搜索词*: "[Product Name] Google Calendar integration two-way sync", "[Product Name] Outlook Exchange CalDAV support".
    *   *关键字段*: 是否支持双向同步 (Two-way sync)? 是否支持 Recurring events? 是否需要额外付费插件 (e.g., Zapier/Make.com 中介)?

3.  **终端支持核验 (针对 G3)**:
    *   *动作*: 下载 Mac/Win 安装包或测试 Web 版。
    *   *搜索词*: "[Product Name] macOS app download", "[Product Name] Windows client".
    *   *关键字段*: 是否为原生应用？Web 版是否支持 PWA 安装到桌面？

4.  **国内可用性核验 (针对 G5)**:
    *   *动作*: 在国内网络环境下尝试访问登录页和加载速度。
    *   *搜索词*: "[Product Name] China accessibility", "[Product Name] server location Asia".
    *   *关键字段*: 服务器节点位置 (AWS Tokyo/Singapore vs US), 平均加载时间。

5.  **门禁联动调研 (针对 G4 - Low Priority)**:
    *   *动作*: 搜索 API 文档。
    *   *搜索词*: "[Product Name] API door lock integration", "[Product Name] webhook NFC".

### 5.3 失败备用路径 (Fallbacks)

*   若某国际 SaaS 因价格超过 20k 被排除 -> 转向评估 Microsoft Bookings 组合方案（可能边际成本极低）。
*   若所有国际 SaaS 在国内访问不稳定 -> 重点评估国内支持 Google Calendar 集成的独立软件，或考虑自建轻量级开源方案 (如 `ownCloud` + `Caldav` 插件，但需评估运维成本是否超出 20k 预算中的隐性人力成本)。
*   若无法找到完美匹配“三端+双日历+低价”的商业软件 -> 备选方案调整为“Microsoft 365 原生方案 + 简单网页表单脚本”，并在报告中说明其局限性。
