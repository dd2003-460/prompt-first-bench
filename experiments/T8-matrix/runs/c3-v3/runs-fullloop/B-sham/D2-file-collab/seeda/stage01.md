# 阶段 01：目标分解、已知与空缺条件

## 1. 目标交付物定义
**最终交付物**：一份可执行的选型报告，包含：
1. **推荐方案**（单一最佳选项）。
2. **备选方案**（至少一个次优选项及适用场景）。
3. **淘汰理由**（针对主要竞品或不符合项的明确排除依据）。
4. **成本明细**（基于 ≤¥30,000/年 预算的具体核算逻辑）。

**核心约束回顾**：
- 团队规模：30人。
- 预算上限：¥30,000/年。
- 平台支持：Web + macOS + Windows 客户端。
- 核心功能：文档版本管理 + 细粒度权限控制。
- 加分项：离线可用。

## 2. 顶层影响因素分解 (正交性检查)

为确保覆盖完整且无重叠，将选型问题分解为以下四个正交维度：

### 因素 A：功能合规性 (Functional Compliance)
*边界：是否满足“硬性需求”和“软性加分项”。*
- **A1. 版本管理深度**
    - *子因素 A1a*：文件级 vs 块级/行级版本对比。
    - *子因素 A1b*：历史版本恢复与分支能力（是否支持类似 Git 的协作流，还是仅线性历史）。
    - *子因素 A1c*：自动备份频率与保留策略。
- **A2. 权限控制粒度**
    - *子因素 A2a*：层级结构（文件夹/文件/字段级别）。
    - *子因素 A2b*：角色模型（RBAC 自定义角色 vs 预设角色）。
    - *子因素 A2c*：外部协作者权限隔离（Guest 链接、有效期、水印等）。
- **A3. 多端同步与离线能力**
    - *子因素 A3a*：原生客户端质量（macOS/Windows 独立进程 vs Electron 封装）。
    - *子因素 A3b*：离线编辑冲突解决机制（Last-write-wins vs 三向合并）。
    - *子因素 A3c*：断网状态下的功能可用性范围（仅查看 vs 可编辑）。

### 因素 B：技术兼容性与部署架构 (Technical Fit)
*边界：软件如何运行，数据在哪里，以及如何集成现有环境。*
- **B1. 部署模式**
    - *子因素 B1a*：SaaS (公有云) vs Private Deployment (私有化/混合云)。
    - *子因素 B1b*：数据主权要求（待确认：是否有行业合规要求强制私有化？）。
- **B2. 客户端兼容性细节**
    - *子因素 B2a*：操作系统最低版本要求（如 macOS 12+, Win 10+）。
    - *子因素 B2b*：资源占用对老旧办公电脑的影响。
- **B3. API 与集成能力**
    - *子因素 B3a*：是否有开放 API 供内部系统调用（如 CI/CD 触发归档）。
    - *子因素 B3b*：单点登录 (SSO/SAML/OIDC) 支持情况。

### 因素 C：经济可行性 (Economic Feasibility)
*边界：总拥有成本 (TCO) 是否在 ¥30,000/年 以内。*
- **C1. 许可费用 (License Cost)**
    - *子因素 C1a*：按席位收费 (Per Seat) 单价。
    - *子因素 C1b*：存储容量阶梯定价（若按 GB 计费）。
    - *子因素 C1c*：免费额度 vs 付费门槛。
- **C2. 隐性成本**
    - *子因素 C2a*：私有化部署所需的服务器/云资源成本（若选 Private）。
    - *子因素 C2b*：实施费/迁移服务费（一次性 vs 年度）。
    - *子因素 C2c*：汇率波动风险（若为海外产品，需锁定币种）。

### 因素 D：运维与支持可持续性 (Operational Sustainability)
*边界：长期使用中的维护负担与供应商风险。*
- **D1. 技术支持等级**
    - *子因素 D1a*：SLA 响应时间。
    - *子因素 D1b*：中文本地化支持程度（文档、客服、界面）。
- **D2. 供应商稳定性**
    - *子因素 D2a*：公司经营状况（初创 vs 上市公司）。
    - *子因素 D2b*：产品路线图透明度（近期是否有重大改版或停服计划）。

## 4. 递归分解与原子化检查

### 对 [GAP-1] 价格的进一步分解：
- *叶子因素 1.1*：基础版 vs 专业版 vs 企业版的界限。（需研究：哪些功能在哪个版本？）
- *叶子因素 1.2*：计费周期（月付 vs 年付折扣）。（需研究：年付是否有额外折扣？）
- *叶子因素 1.3*：超量存储单价。（需研究：默认存储多少GB？超出后每GB多少钱？）

### 对 [GAP-2] 权限的进一步分解：
- *叶子因素 2.1*：目录树继承规则。（需研究：父文件夹权限是否自动传递给子文件夹？能否单独打破继承？）
- *叶子因素 2.2*：权限变更生效延迟。（需研究：修改权限后，客户端多久同步生效？）

### 判定：分解完成
所有叶子因素均为最小单位，无法再在不引入新研究对象的情况下继续分解。当前分解足以指导阶段 02 的研究路径。

## 5. 关键空缺清单 (Blockers for Stage 02)

以下空缺若不解决，将无法做出最终推荐：

1.  **[BLOCKER-COST]** 主流候选方案（见下方候选池）在 30 席位下的确切年费。
    *   *阻塞判断*：直接决定方案是否可行（Pass/Fail 预算线）。
2.  **[BLOCKER-FUNC]** 候选方案中“细粒度权限”是否真正达到“细粒度”标准（例如：能否只允许某人查看某文件的某一页/某一段？）。
    *   *阻塞判断*：决定核心需求是否被满足。
3.  **[BLOCKER-TECH]** 候选方案的 macOS/Windows 客户端是否为原生开发，以及离线同步的冲突解决机制。
    *   *阻塞判断*：影响用户体验评分（加分项）。
4.  **[BLOCKER-SEC]** 候选方案的数据存储位置及合规认证。
    *   *阻塞判断*：若涉及敏感研发代码，安全合规可能是隐性否决项。

## 7. 阶段 02 研究入口 (Actionable Research Path)

阶段 02 应严格按以下顺序执行，以填补上述空缺：

### Step 1: 预算初筛 (Fill GAP-1)
- **动作**：访问 Notion, Confluence, Feishu, Tencent Docs, Seafile 官网。
- **搜索词**：`[Product Name] pricing 30 users`, `[Product Name] enterprise plan cost`.
- **目标来源**：官方 Pricing Page, 销售咨询邮件回复 (若公开价不明确).
- **备用路径**：若官网无 30 人精确价，寻找第三方评测网站 (G2, Capterra) 的用户评论中提及的价格区间，或联系销售代表获取 Quote.
- **产出**：一张包含 5-7 个候选方案的预估年费表。剔除超过 ¥30,000 的方案。

### Step 2: 功能深潜 (Fill GAP-2 & GAP-3)
- **动作**：对存活方案进行功能特性对比。
- **关键搜索词**：`[Product Name] version history feature`, `[Product Name] granular permissions audit log`, `[Product Name] offline sync conflict resolution`.
- **目标来源**：官方 Feature Matrix, Help Center Articles, 独立技术博客评测.
- **交叉验证**：使用 `ralph prompt-first web-llm` 询问：“Compare the file versioning and permission granularity of [Candidate A] vs [Candidate B] for a 30-person dev team.”
- **产出**：功能打分表 (版本管理 1-5 分, 权限粒度 1-5 分, 离线能力 1-5 分).

### Step 3: 安全与合规 (Fill GAP-4)
- **动作**：检查安全白皮书。
- **搜索词**：`[Product Name] security whitepaper`, `[Product Name] data residency China`, `[Product Name] ISO 27001 certification`.
- **目标来源**：Trust Center, Security Overview page.
- **产出**：合规性 Pass/Fail 列表。

### Step 4: 综合评估与决策矩阵
- **动作**：结合 Step 1-3 结果，建立加权评分模型。
- **权重建议**：预算符合度 (30%), 核心功能满足度 (40%), 易用性/离线 (20%), 安全性 (10%).
- **产出**：排名前三的方案及其理由。
