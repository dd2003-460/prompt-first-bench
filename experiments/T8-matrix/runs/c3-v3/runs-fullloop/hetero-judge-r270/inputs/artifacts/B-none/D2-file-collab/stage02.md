## 2. GAP-01: 候选对象池及其属性 (Candidate Pool & Attributes)

### 2.1 候选名单筛选逻辑
基于 A 类约束（预算 ≤¥30,000/年，即人均 ≤¥1,000/年；支持 Win/Mac/Web），初步筛选出以下主流候选：

| 产品名称 | 类型 | 入围理由 | 潜在淘汰风险 |
| :--- | :--- | :--- | :--- |
| **坚果云 (Jianguoyun)** | SaaS 协作网盘 | 国内老牌，同步速度快，有企业版，权限较细 | 存储配额较小，需加购；价格偏高 |
| **阿里云盘企业版 (AliDrive)** | SaaS 网盘 | 阿里背书，稳定性好，性价比高 | 早期侧重个人，企业功能迭代中，细粒度权限需核实 |
| **百度网盘企业版 (Baidu Wangpan)** | SaaS 网盘 | 市场占有率高，客户端成熟 | 限速严重（除非买会员），企业版功能偏重存储而非协作 |
| **Nextcloud (自托管)** | 开源自托管 | 完全可控，无席位费，功能极强（版本/权限） | 需要服务器成本和运维人力，不符合“低维护”预期？但成本极低 |
| **Seafile (自托管)** | 开源自托管 | 专注文件同步，性能优异，权限精细 | 同样涉及运维成本，Web 端体验略逊于 SaaS |

**决策点**：考虑到“研发团队”对**版本管理**和**权限**的高要求，以及**离线可用**的加分项，**Nextcloud/Seafile (自托管)** 在功能深度上远超 SaaS，但在运维上增加负担。**坚果云**是国内 SaaS 中版本管理和同步体验最好的之一。**阿里云盘企业版**是性价比备选。

## 4. GAP-03: 文档版本管理的实际效能 (Versioning Efficacy)

| 产品 | 版本保留策略 | Diff 视图 (Office/Code) | 恢复便捷性 | 评估 |
| :--- | :--- | :---: | :---: | :--- |
| **坚果云** | 自动保留最近 N 个版本 (默认 10-30 个，可调) | ⚠️ (仅 Web 端简单对比，无复杂 Diff) | ✅ (一键恢复) | 良好。适合办公文档，不适合代码级回溯。 |
| **阿里云盘** | 保留历史版本 (数量限制较少) | ❌ (通常无内置 Diff) | ✅ | 一般。作为备份尚可，作为协作版本管理较弱。 |
| **Nextcloud** | **无限版本** (取决于存储空间) | ✅ (Text Diff 插件 / Office Online 集成) | ✅ | **优秀**。可保留所有历史，支持文本对比。 |
| **Seafile** | **无限版本** (取决于存储空间) | ⚠️ (客户端可查看历史，Web 端 Diff 较弱) | ✅ | **优秀**。核心优势就是稳定的版本同步。 |
| **OneDrive** | 保留 30 天内的每日版本 + 永久版本 (上限 200+) | ✅ (Word/Excel 原生 Diff) | ✅ | **优秀**。如果团队重度使用 Office，这是最佳选择。 |

**关键差异**：
*   **SaaS 网盘 (坚果云/阿里)**：版本管理侧重于“防误删”，保留数量有限，缺乏开发者的“Diff”体验。
*   **自托管 (Nextcloud/Seafile)**：版本管理侧重于“完整历史”，只要硬盘够大，可以保留数年前的版本。这对研发团队的长期项目追溯至关重要。

## 5. GAP-04: 离线可用的技术真实性 (Offline Sync Reality)

| 产品 | 断网编辑 | 联网自动同步 | 冲突处理机制 | 评估 |
| :--- | :---: | :---: | :--- | :--- |
| **坚果云** | ✅ | ✅ | 智能合并 (针对文本/Office) / 提示冲突 | **真离线**。同步引擎成熟，断网体验好。 |
| **阿里云盘** | ⚠️ (主要依赖本地缓存，双向同步稍弱) | ✅ | 覆盖或提示 | 中等。早期版本同步稳定性不如坚果云。 |
| **Nextcloud** | ✅ | ✅ | 提示冲突 (生成 conflict copy) | **真离线**。客户端 (Desktop Client) 基于 rsync-like 算法，稳定。 |
| **Seafile** | ✅ | ✅ | 提示冲突 / 自动合并 (部分格式) | **真离线**。Seafile 的核心卖点就是高性能的文件同步，离线能力极强。 |
| **OneDrive** | ✅ | ✅ | 智能合并 / 提示 | **真离线**。Windows 集成极好，Mac 端也完善。 |

**结论**：
*   所有主流候选均支持“真离线同步”（即断网修改，联网后自动上传并处理冲突）。
*   **Seafile** 和 **Nextcloud** 的同步协议经过多年打磨，在处理大量小文件时表现优于基于 HTTP API 轮询的部分 SaaS 产品。

## 6. GAP-05: 隐性成本与合规风险 (Hidden Costs & Compliance)

### 6.1 数据主权与合规
*   **坚果云/阿里云盘/百度**：数据存储在**中国境内**节点。符合《数据安全法》。访问速度快。
*   **Nextcloud/Seafile (自托管)**：数据存储在**你自己购买的服务器**上。若购买阿里云 ECS，数据也在境内。完全自主可控，合规性最高。
*   **OneDrive/Google Drive**：数据可能存储在新加坡或美国（取决于租户设置）。对于中国研发团队，**访问速度慢**是最大痛点，且存在合规审查风险。-> **建议淘汰 OneDrive/Google Drive 作为首选，除非公司已有全球统一 IT 政策强制使用。**

### 6.2 隐性成本
*   **SaaS 产品**：
    *   **超额存储费**：坚果云/阿里网盘超出基础配额后，按 GB 计费，价格较高（约 ¥10-20/GB/月）。30人团队若每人存 50GB，总需求 1.5TB，可能需要额外支付存储费。
    *   **API 限制**：SaaS 通常有严格的 API Rate Limit，若研发需要编写脚本自动化备份，可能受限。
*   **自托管产品**：
    *   **带宽费**：若外网访问频繁，ECS 带宽费用可能上涨。
    *   **运维人力**：最大的隐性成本。需要有人负责系统升级、安全补丁、备份策略。如果团队没有专职运维，这部分“人力成本”可能超过 SaaS 的 License 费。

## 8. 暂定结论与仍未解决的空缺

### 8.1 暂定结论
1.  **预算适配性**：自托管方案 (Nextcloud/Seafile) 在硬成本上最具优势，留有充足的预算用于硬件升级或应急。SaaS 方案中，坚果云最可能触及预算红线。
2.  **功能匹配度**：**Nextcloud** 在“细粒度权限”和“版本管理”两个核心需求上表现最好，完全满足研发团队的合规和回溯需求。
3.  **离线能力**：所有入围方案均支持真离线同步，此加分项不构成淘汰理由。
4.  **合规性**：自托管 (境内服务器) 和国内 SaaS 均合规。OneDrive 存在跨境数据风险。

### 8.2 仍未解决的关键空缺 (Blockers for Stage 03)
1.  **[BLOCKER] Nextcloud/Seafile 运维可行性评估**：
    *   空缺：团队是否有具备 Linux 运维能力的成员？如果没有，自托管方案的“隐性人力成本”可能使其总拥有成本 (TCO) 高于 SaaS。
    *   *行动*：需在阶段 03 中明确“运维资源可用性”。若无人运维，应转向 SaaS。
2.  **[HIGH] 阿里云盘企业版的具体报价与权限细节**：
    *   空缺：目前仅有估算，缺乏官方公开的 30 人档位精确报价单。其文件级权限是否真的开放给中小型企业版？
    *   *行动*：需联系销售或查找最新代理商报价。
3.  **[MEDIUM] 坚果云的存储扩容单价**：
    *   空缺：30 人团队预计产生多少 TB 的数据？若超过基础配额，具体加多少钱？这决定了它是否真的超预算。
    *   *行动*：需查询坚果云官网“存储包”价格表。

### 8.3 来源矛盾记录
*   **关于 OneDrive 的访问速度**：部分用户反馈近年微软优化了中国区 CDN，速度有所提升；但仍有大量反馈称上传大文件极慢。
    *   *处理*：鉴于研发团队常有大数据集传输需求，保守起见，将其列为“高风险/不推荐”，除非 POC 测试证明速度达标。
