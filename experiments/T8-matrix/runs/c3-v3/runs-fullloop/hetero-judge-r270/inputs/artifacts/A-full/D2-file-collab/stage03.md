# 阶段 03：具体行动分解

## 1. 执行前提与依赖声明
本阶段行动严格基于 **阶段 02** 中状态为 `[已核验]` 或 `[未解决-需人工核实]` 的证据。
*   **硬性约束确认**：预算 ≤ ¥30,000/年；平台 = Web + macOS + Windows；核心功能 = 版本管理 + 细粒度权限。
*   **关键未知处理**：阶段 02 指出坚果云、OneDrive、Dropbox 的具体价格存在不确定性（U1, U2, U4）。因此，**“获取精确报价”是本阶段的首要阻塞性任务**。在获得确切报价前，不产生最终选型结论，仅产出“待决方案对比表”。
*   **Owner 标注规范**：
    *   `agent`: 可离线执行、无需用户交互、基于公开信息或内部逻辑推导的步骤。
    *   `user`: 必须用户参与（如登录账户、联系销售、确认内部IT资源、批准采购）的步骤。

## 2. 行动步骤分解

### 模块 A：数据主权与内部环境预检 (Pre-checks)
> **目的**：排除因合规或网络环境导致的“一票否决”项，避免无效询价。

| ID | 动作描述 | Owner | 输入 | 依赖 | 预期产出 | 验收方式 |
| :--- | :--- | :---: | :--- | :--- | :--- | :--- |
| **A1** | **确认团队地理位置分布**：询问团队负责人，确认 30 名成员是否全部位于中国大陆境内，还是有部分成员常驻海外/港澳台。 | `user` | 团队花名册/口头确认 | 无 | 《团队地域分布声明》：全境内 / 混合分布。 | 获得明确文字确认。若混合分布，需在后续评分中对“国内访问速度”和“海外访问速度”加权调整。 |
| **A2** | **确认数据合规红线**：询问法务或安全负责人，研发文档是否包含受《数据安全法》或行业监管限制出境的数据（如核心算法源码、用户隐私数据）。 | `user` | 公司合规政策 | 无 | 《数据出境风险评估》：允许出境 / 严禁出境 / 需脱敏后出境。 | 若“严禁出境”，直接淘汰所有纯海外 SaaS（Dropbox, Box, OneDrive国际版），锁定国产方案或自托管。 |
| **A3** | **评估内部 IT 运维能力**：确认团队是否有专职 IT 人员或 DevOps 工程师能承担自托管方案（Seafile/Nextcloud）的日常维护（备份、升级、故障排查）。 | `user` | 团队组织架构/访谈 IT 负责人 | 无 | 《IT 运维资源评估》：有专人（可自托管） / 无专人（仅限 SaaS）。 | 若无专人，将自托管方案的隐性成本估算上调至 >¥50,000/年（含外包运维费），从而在成本维度淘汰自托管。 |

*   **并行策略**：A1, A2, A3 均无相互依赖，可完全并行执行。
*   **失败路径**：若 A2 回答模糊，默认按“严禁出境”处理（保守策略），优先考察国产方案。

### 模块 B：候选方案精准询价 (Precise Quoting)
> **目的**：填充阶段 02 中的 U1, U2 空缺，将估算价格转化为合同级报价。
> **前置条件**：根据 A2 的结果，确定询价对象列表。
> *   *场景 1（严禁出境）*：仅询价 [坚果云, 阿里云盘企业版, 百度网盘企业版]。
> *   *场景 2（允许出境）*：询价 [坚果云, OneDrive M365 Business Standard, Dropbox Business]。
> *   *注*：Box 因预估超预算且非主流小团队选择，除非 A2/A3 结果极端特殊，否则暂不列入本轮询价，仅在备选库保留。

| ID | 动作描述 | Owner | 输入 | 依赖 | 预期产出 | 验收方式 |
| :--- | :--- | :---: | :--- | :--- | :--- | :--- |
| **B1** | **联系坚果云销售获取 30 人报价**：<br>1. 官网提交“企业咨询”表单。<br>2. 邮件/电话跟进，明确要求：<br>- 30 席位的年度总价（含税）。<br>- 基础套餐包含的总存储容量。<br>- 超出基础容量后的扩容单价。<br>- 是否支持“文件夹级”及“文件级”权限控制的具体演示链接。 | `user` | 坚果云官网联系方式 | A2 (若允许出境也需询此作为基准) | 《坚果云正式报价单》(PDF/Excel)，含有效期。 | 收到盖章或官方邮箱发出的书面报价。若 7 个工作日内未回复，标记为 `响应超时`，启用备用路径 B1-alt。 |
| **B2** | **联系微软授权合作伙伴获取 M365 报价**：<br>1. 查找本地 Microsoft Gold Partner。<br>2. 索取 30 席位 Microsoft 365 Business Standard 的年付打包价。<br>3. 特别询问：该价格是否包含 OneDrive 1TB/用户？是否包含 SharePoint Online 的基础权限管理功能？ | `user` | 微软合作伙伴目录 | A2 (仅当允许出境时执行) | 《M365 渠道报价单》，注明代理商名称及折扣率。 | 收到包含明细的报价单。若直销价高于渠道价 10% 以上，以渠道价为准。 |
| **B3** | **联系 Dropbox 中国区代理或直接销售**：<br>1. 若 A1 显示全员在国内，重点询问是否有“中国区加速节点”或专用线路。<br>2. 索取 30 席位 Business 计划年付报价。<br>3. 确认版本历史保留天数（Standard vs Advanced）。 | `user` | Dropbox 官网/代理商 | A1, A2 (仅当允许出境且 A1 显示有海外成员时优先级提高) | 《Dropbox 正式报价单》。 | 收到书面报价。若标准价 >¥30k，询问是否有 3 年期合同折扣。 |
| **B1-alt** | **[备用路径] 若 B1 超时或拒绝提供详细报价**：<br>查阅坚果云最新公开的“团队版”定价页，使用最高档位的单价 × 30 进行顶格估算，并标记为 `[估算值-高风险]`。同时搜索知乎/V2EX 近半年内关于“坚果云涨价”或“企业版坑”的帖子，评估其服务稳定性风险。 | `agent` | 坚果云官网、搜索引擎 | B1 失败 | 《坚果云估算成本表》+《风险预警备忘录》。 | 估算值若 >¥30,000，则坚果云降为备选；若 <¥30,000，保留为首选但标注“需最终确认”。 |

*   **并行策略**：B1, B2, B3 互不依赖，可并行发起。
*   **时间盒**：设定 5 个工作日为询价窗口期。

### 模块 C：功能深度验证 (Feature Validation)
> **目的**：验证阶段 02 中 `[已核验-中置信度]` 的功能点，确保“细粒度权限”和“版本管理”满足研发需求。
> **注意**：此步骤依赖于 B 阶段确定的“入围方案”（通常最多 2-3 家）。

| ID | 动作描述 | Owner | 输入 | 依赖 | 预期产出 | 验收方式 |
| :--- | :--- | :---: | :--- | :--- | :--- | :--- |
| **C1** | **注册试用账号并执行“权限穿透测试”**：<br>针对入围方案，创建测试空间。<br>1. 建立文件夹 `Project_A`。<br>2. 邀请测试用户 User_B (只读), User_C (无权限)。<br>3. **关键测试**：User_B 尝试下载文件后修改再上传，观察系统是否提示冲突或覆盖；User_C 尝试通过 URL 直接访问，观察是否返回 403。<br>4. 测试“外部协作者”链接：生成一个带密码和过期时间的链接，验证过期后是否失效。 | `agent` (需 user 协助注册) | 入围方案名单 | B1/B2/B3 完成 | 《功能测试日志》：记录每项权限操作的截图和实际行为。 | 测试脚本执行完毕，所有截图存档。若发现“只读”用户仍可下载，则该方案在“细粒度权限”维度扣分。 |
| **C2** | **执行“版本回溯压力测试”**：<br>1. 创建一个 Word/PDF 文档，连续修改 5 次并保存。<br>2. 检查版本列表是否清晰显示 V1-V5。<br>3. **关键测试**：尝试恢复 V2，验证其他在线用户是否会同步看到 V2 的内容（即版本恢复是全局生效还是仅个人视图）。<br>4. 检查版本保留策略：查看帮助文档确认是“永久保留”还是“保留 N 天”。 | `agent` (需 user 协助注册) | 入围方案名单 | B1/B2/B3 完成 | 《版本管理测试报告》。 | 确认版本恢复机制是否符合团队工作流（例如：如果恢复会强制覆盖他人正在编辑的版本，需标记为“高危操作”）。 |
| **C3** | **离线同步实测 (加分项)**：<br>1. 在 macOS 客户端上，断开 Wi-Fi。<br>2. 打开本地同步的文件进行修改并保存。<br>3. 重新连接 Wi-Fi。<br>4. 观察同步延迟及冲突提示弹窗。 | `user` | 入围方案客户端安装包 | B1/B2/B3 完成 | 《离线体验主观评分》(1-5分)。 | 用户亲自操作并给出主观评分。若同步超过 1 分钟或出现静默覆盖，评分低于 3 分。 |

*   **并行策略**：C1, C2, C3 针对不同方案可并行；同一方案内的测试建议串行以避免干扰。
*   **依赖说明**：此模块必须在 B 模块结束后执行，因为需要知道哪些方案进入了决赛圈。

### 模块 D：综合评估与决策矩阵构建 (Evaluation & Decision)

| ID | 动作描述 | Owner | 输入 | 依赖 | 预期产出 | 验收方式 |
| :--- | :--- | :---: | :--- | :--- | :--- | :--- |
| **D1** | **构建加权评分卡**：<br>基于 A, B, C 阶段的产出，填写以下表格。<br>**权重分配**：<br>- 成本经济性 (30%)：基于 B 阶段精确报价。若 >¥30k 直接记 0 分。<br>- 核心功能符合度 (30%)：基于 C1, C2 测试结果。版本管理和权限各占 15%。<br>- 安全与合规 (15%)：基于 A2 结果。数据不出境得满分，出境酌情扣分。<br>- 用户体验与离线 (15%)：基于 C3 评分及 A1 地域分布。<br>- 生态集成 (10%)：基于阶段 02 知识，是否支持与现有工具（如 Slack/Teams）集成。 | `agent` | A, B, C 阶段所有产出物 | A, B, C 完成 | 《选型评分矩阵 Excel》。 | 每个单元格必须有数据来源引用（如“来源：B1 报价单第 2 行”）。 |
| **D2** | **计算总分并识别 Top 1**：<br>1. 计算各方案加权总分。<br>2. 识别得分最高的方案为“推荐方案”。<br>3. 识别第二名为“备选方案”。<br>4. 对于被淘汰的方案，撰写具体的“淘汰理由”（如：成本超标、缺乏原生 Mac 客户端、权限粒度不足）。 | `agent` | D1 评分矩阵 | D1 完成 | 《初步排名与淘汰理由草案》。 | 逻辑一致性检查：总分第一必须是推荐方案。若 Top 1 和 Top 2 分差 < 5 分，需触发 D3 敏感性分析。 |
| **D3** | **[条件执行] 敏感性分析与风险对冲**：<br>若 Top 1 存在重大风险（如：唯一供应商、价格临界点、网络不稳定），执行以下分析：<br>1. **价格敏感性**：若汇率波动 10%，Top 1 是否仍最优？<br>2. **功能敏感性**：若移除“离线可用”这一加分项，排名是否变化？<br>3. **替代方案可行性**：备选方案是否能无缝承接？迁移成本估算（人力小时数）。 | `agent` | D2 草案 | D2 完成 | 《风险对冲分析报告》。 | 若 Top 1 在任一敏感性测试中跌出 Top 2，则将备选方案提升为推荐方案，或在报告中强烈建议采用“双轨制”（主用 Top 1，备用 Top 2 保持小规模试用）。 |

*   **并行策略**：D1 -> D2 -> D3 为严格串行流程。

### 模块 E：最终报告生成与交付 (Final Report Generation)

| ID | 动作描述 | Owner | 输入 | 依赖 | 预期产出 | 验收方式 |
| :--- | :--- | :---: | :--- | :--- | :--- | :--- |
| **E1** | **起草《团队文件协作方案选型报告》**：<br>结构如下：<br>1. **执行摘要**：推荐方案名称、年度总成本、核心理由（3 句话以内）。<br>2. **需求回顾**：重申硬性约束。<br>3. **候选方案对比**：包含阶段 02 筛选出的主要竞品表格。<br>4. **推荐方案详情**：<br>   - 成本明细（列出单价、人数、折扣、总计）。<br>   - 功能映射（如何满足版本管理和权限需求）。<br>   - 实施路线图（账号开通、数据迁移、培训计划）。<br>5. **备选方案**：简述优势及适用场景。<br>6. **淘汰理由**：针对落选的大牌方案（如 Dropbox, OneDrive）的具体技术/商务原因。<br>7. **附录**：原始报价单截图、测试日志摘要。 | `agent` | D3 最终结论、B/C 阶段证据 | D3 完成 | 《选型报告 v1.0》(Markdown/Word)。 | 报告内容完整覆盖阶段 01 定义的四个核心组件。无“待定”、“可能”等模糊词汇（除非是明确的风险提示）。 |
| **E2** | **内部评审与定稿**：<br>将报告发送给 IT 负责人和业务负责人进行最终审阅。<br>1. 确认成本数字与销售承诺一致。<br>2. 确认功能描述与实际测试体验一致。<br>3. 签署《选型决议书》。 | `user` | E1 报告草稿 | E1 完成 | 《选型决议书》(签字版) + 《最终选型报告 v1.1》。 | 获得两位关键干系人的书面批准（邮件回复“同意”或电子签名）。 |

*   **并行策略**：E1 -> E2 串行。
