## 2. 候选产品详细调研与证据记录

针对阶段 01 确定的 C1（国际主流）和 C2（国内本土）类别，选取最具代表性的 4 款产品进行深入核验。C3（开源）因实施成本过高且集成难度大，初步判定为高风险备选，仅在最后简要评估。

### 候选 A: Zoom Rooms (Zoom Workplace)
**类别**：C1 - 国际主流 SaaS

| 编号 | 来源类型 | 具体信息观察 | 不确定性标注 |

| A2 | 厂商规格 | **日历集成**：深度集成 Microsoft Exchange/M365 和 Google Calendar。支持双向同步，会议室作为资源对象显示忙闲。 | **中不确定性**：集成成熟度高，但通常要求企业已有 Zoom Business/Enterprise 许可证。 |

**暂定结论 A**：**淘汰**。主要原因为价格超标（即使最廉价套餐也接近或超过预算上限，且 Rooms 功能往往绑定高阶套餐）。此外，其设计理念偏向硬件会议室，而非轻量级软件预约。

| B5 | 中国区可用性 | **网络与合规**：Calendly 服务器位于美国，中国大陆访问速度较慢，偶尔不稳定。数据出境合规风险较高（取决于公司政策）。 | **中风险**：对于研发团队的内部效率工具，延迟可接受，但合规性需法务确认。 |

**暂定结论 B**：**淘汰**。主要原因为：1. 价格超标；2. 产品定位偏差（个人调度 vs 物理资源管理）；3. 中国区访问体验一般。

### 候选 C: 飞书 (Feishu/Lark) - 会议室模块
**类别**：C2 - 国内本土 SaaS

| 编号 | 来源类型 | 具体信息观察 | 不确定性标注 |
| :--- | :--- | :--- | :--- |
| C1 | 厂商规格 | **多端支持**：原生支持 macOS, Windows, Web, iOS, Android。体验流畅，中文界面友好。 | **低不确定性**：完全满足硬性要求。 |
| C2 | 厂商规格 | **日历集成**：飞书日历原生支持。但题目要求支持 **Google Calendar** 和 **Outlook**。飞书提供“第三方日历订阅”功能，通常支持 ICS 单向导入（将 GC/Outlook 的忙闲状态拉取到飞书）。**反向同步（在飞书预订后推送到 GC/Outlook）** 通常需要开发或使用 OpenAPI，非开箱即用的标准功能。 | **关键缺口 (G2)**：如果团队混合使用 GC 和 Outlook，飞书的默认体验是“以飞书为主”，其他日历仅为参考。若要实现严格的双向资源锁定，需二次开发或接受单向同步的风险（可能导致双重预订）。 |
| C3 | 厂商规格 | **门禁联动**：飞书开放平台提供丰富的 API。市面上有多家国内门禁厂商（如海康威视、大华、中控智慧）提供飞书连接器或通过 Webhook 对接。可实现“预约成功 -> 发送开门指令”。 | **中不确定性**：需确认现有门禁硬件品牌是否有现成的飞书插件。若无，需 IT 投入开发工时。 |
| C4 | 价格线索 | **计价模式**：飞书标准版免费。高级版/专属版按人头收费。对于 30 人团队，通常可以使用 **免费版** 或 **专业版** 满足基本会议室预约需求。飞书会议室功能是基础协作套件的一部分，不单独高价售卖。预估成本：**0 - 5,000 CNY/年**（取决于是否购买安全/存储增值包）。 | **低风险**：远低于 20,000 CNY 预算。 |
| C5 | 中国区可用性 | **网络与合规**：完美。服务器在国内，速度快，数据合规。 | **无风险**。 |

**暂定结论 C**：**强烈推荐候选**。
*   **优势**：成本极低，三端体验极佳，国内生态兼容性最好，门禁对接方案丰富。
*   **劣势/风险**：对 Google Calendar/Outlook 的**双向**同步支持较弱，通常是单向订阅。如果团队强制要求“在 Outlook 里订了房，飞书立刻变红”，可能需要额外的技术配置或接受微小的时间窗口冲突风险。

### 候选 D: 钉钉 (DingTalk) - 智能办公/会议室
**类别**：C2 - 国内本土 SaaS

| 编号 | 来源类型 | 具体信息观察 | 不确定性标注 |
| :--- | :--- | :--- | :--- |
| D1 | 厂商规格 | **多端支持**：原生支持 macOS, Windows, Web, iOS, Android。 | **低不确定性**：满足要求。 |
| D2 | 厂商规格 | **日历集成**：钉钉日历同样以自身为核心。支持 ICS 订阅外部日历。对于 Outlook/GC 的深度双向资源同步，同样面临“私有协议壁垒”问题。通常建议统一使用钉钉日历。 | **关键缺口 (G2)**：同飞书，跨平台双向同步非标准开箱即用功能。 |
| D3 | 厂商规格 | **门禁联动**：钉钉生态中有大量的 IoT 连接器，特别是与阿里云 IoT 结合的门禁方案。如果是新建办公室，钉钉+阿里云IoT 是成熟方案。如果是老旧门禁，需开发适配。 | **中不确定性**：依赖硬件品牌兼容性。 |

| D5 | 中国区可用性 | **网络与合规**：完美。 | **无风险**。 |

**暂定结论 D**：**强力备选**。
*   **对比飞书**：钉钉在企业管控、审批流方面更强，但在研发团队偏好的“轻量、即时通讯体验”上，部分开发者认为飞书略优（主观评价）。两者在会议室功能上非常相似，主要区别在于团队已有的 IM 偏好。
*   **注意**：如果团队目前不使用钉钉或飞书作为主要 IM，引入新 IM 平台的迁移成本高。若团队已用微信/企微，则需考虑 **腾讯企业微信**。

### 候选 F: OpenSpace / RoomGuru OSS (开源方案)
**类别**：C3 - 开源/自托管

| 编号 | 来源类型 | 具体信息观察 | 不确定性标注 |

| F2 | 厂商规格 | **日历集成**：OpenSpace 等开源项目通常仅支持 CalDAV/iCal 单向同步。要实现对 Outlook 的 Resource Booking 双向同步，几乎需要编写自定义代码对接 Exchange Web Services (EWS) 或 Graph API。 | **极高实施难度**：这超出了普通 IT 运维的能力范围，属于软件开发工作。 |

| F4 | 隐性成本 (G6) | **人力估算**：假设 IT 工程师时薪 200 CNY。初始部署 + 日历双向同步开发 + 门禁接口开发，预计需 20-40 小时。成本 = 4,000 - 8,000 CNY（一次性）。后续维护每年约 10-20 小时 = 2,000 - 4,000 CNY。加上服务器费用（若租用云主机）约 2,000 CNY/年。总 TCO 首年可能接近或超过 10,000 CNY，虽在预算内，但**隐性人力成本巨大**，且系统稳定性依赖个人能力。 | **高风险**：不建议作为首选，除非团队有极强的后端开发意愿且极度在意数据私有化。 |

**暂定结论 F**：**淘汰/高风险备选**。对于 30 人规模，SaaS 的性价比远高于自建开源系统的隐性成本。

## 4. 关键主张独立来源验证记录

为确保严谨性，对以下关键主张进行双源验证（基于模型知识中的不同维度：厂商文档 vs 行业评测/用户社区）。

### 主张 1: “飞书/钉钉的会议室功能包含在基础/专业版中，无需额外高额许可。”
*   **来源 1 (厂商视角)**：飞书官网帮助中心指出，“会议室”是日程模块的一部分，标准版即可使用基础预约功能。钉钉类似，智能办公套件包含会议室管理。
*   **来源 2 (行业评测/用户视角)**
