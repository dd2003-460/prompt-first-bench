# 会议室预约系统选型最终报告

**项目名称**：30人研发团队会议室预约系统选型
**日期**：2023年10月
**版本**：Final v1.0
**预算上限**：人民币 20,000 元/年

---

## 1. 执行摘要与推荐方案

### 核心结论
经过对市场上主流SaaS产品、开源项目及内部IM工具的综合评估，在严格满足“年度预算<2万元”、“支持macOS/Windows/Web三端”、“对接Google Calendar与Outlook双日历”的硬性条件下，**不存在单一商业SaaS产品能同时完美满足所有需求且成本可控**。

因此，我们采用 **“轻量级自研 + 成熟开源内核”** 的混合架构作为最佳解决方案。

### 推荐方案：基于 `Fullcalendar` (前端) + `Node.js/Python` (后端) + `CalDAV` (协议层) 的轻量化自建系统

**核心理由：**
1.  **成本极致控制**：利用团队现有开发资源（30人研发团队通常具备全栈能力），仅需支付云服务器费用（阿里云/腾讯云轻量服务器）和域名解析费，年度硬件/软件采购成本可控制在 **500-1,000元** 以内，远低于2万元预算。
2.  **双日历原生支持**：通过实现标准的 **CalDAV** 协议或调用 Google/Microsoft Graph API，可以无缝双向同步 Google Calendar 和 Outlook。这是商业SaaS常需额外付费解锁的高级功能，而自研可完全掌控。
3.  **三端全覆盖**：Web端直接访问；macOS/Windows端可通过 Electron 封装或直接嵌入企业内网浏览器书签，无需购买昂贵的跨平台客户端License。
4.  **门禁联动预留**：后端API设计时预留 `/api/access-control` 接口，未来若需接入海康威视等门禁系统，只需编写简单的中间件插件，无需重构核心逻辑。

## 2. 备选方案对比

### 备选方案 A：飞书/钉钉/企业微信 内置会议室功能（依赖已有订阅）

*   **适用前提**：公司已全员使用某一款IM工具，且拥有高级版权限。
*   **优势**：
    *   **零边际成本**：如果公司已购买企业版/专业版IM，会议室功能是免费附赠的。
    *   **极低学习成本**：员工无需登录新系统，直接在IM内操作。
    *   **移动端体验极佳**：原生App体验优于Web。
*   **劣势**：
    *   **日历隔离风险**：虽然支持绑定外部日历，但Google Calendar与Outlook的双向实时同步稳定性在不同IM厂商间表现不一，部分仅支持单向导入。
    *   **定制化受限**：无法自定义门禁联动逻辑，无法深度定制审批流程。
    *   **数据主权**：会议数据存储在第三方云端，若涉及敏感研发项目，可能存在合规顾虑。
*   **对比结论**：若公司**尚未**购买IM高级版，新增此成本可能接近或超过预算，且灵活性不如自研。若**已购买**，则此方案为第一推荐（因节省开发人力）。

### 备选方案 B：开源项目部署（如 Roomle / FreeRoom）

*   **具体产品**：以 GitHub 上高星的开源会议室系统为例。
*   **优势**：
    *   **社区活跃**：有现成的代码库，减少从零开发的工时。
    *   **成本低**：同样仅需服务器费用。
*   **劣势**：
    *   **维护风险**：开源项目更新频率不稳定，遇到Bug可能需要自行修复底层代码。
    *   **功能匹配度低**：大多数开源项目默认只支持单一日历或需复杂配置才能支持 CalDAV，对 Google/Outlook 的双向同步支持往往不完善，需要大量二次开发。
    *   **安全性**：未经过商业安全审计，需团队自行加固。
*   **对比结论**：相比推荐方案的“轻量自研”，备选B的代码复杂度更高，调试成本不可控，仅在团队极度缺乏开发时间时才考虑。

## 3. 淘汰理由（未入选候选）

| 候选类型 | 代表产品 | 淘汰理由 |
| :--- | :--- | :--- |
| **高端商业SaaS** | Zoom Rooms, Microsoft Teams Rooms | **成本超标**：按席位收费，30人团队年费通常在 5万-10万+ 人民币，远超2万元预算。 |
| **通用日程工具** | Calendly, Acuity Scheduling | **场景不符**：主要面向个人预约，缺乏“会议室资源管理”、“多人抢占冲突检测”及“门禁联动”等企业级会议室核心功能。 |
| **纯Web日历** | Doodle, WhenToMeet | **功能缺失**：仅为投票工具，不支持持久化的会议室状态管理，无法对接物理门禁，也无法实现真正的双向日历同步。 |
| **重型ERP/OA模块** | SAP Concur, Oracle Fusion | **过重且昂贵**：属于大型套件的一部分，单独购买授权费用极高，实施周期长，对于30人小团队而言是严重的过度设计。 |

## 4. 成本明细（年度总成本拆解）

**假设前提**：
1.  开发人员来自现有30人团队，不计入额外招聘成本（仅计算机会成本中的服务器支出）。
2.  开发工期预估：1-2周（由1名后端+1名前端兼职完成）。
3.  服务器选择：国内主流云厂商（阿里云/腾讯云）轻量应用服务器。

### 推荐方案（轻量自研）成本表

### 成本敏感性分析
*   **若增加门禁硬件**：若二期接入海康威视门禁SDK，需购买一个物联网网关（约500元一次性投入）及少量开发工时，年度运维成本增加不超过500元，仍在预算范围内。
*   **若选用商业SaaS**：即使是最便宜的国内协作工具（如飞书免费版），若要实现稳定的双日历双向同步和门禁联动，往往需要升级到付费版或购买第三方集成插件，成本极易突破5,000-10,000元/年，且灵活性差。

## 5. 风险与缓解措施

| 风险等级 | 风险描述 | 影响 | 缓解措施 (Mitigation) |
| :--- | :--- | :--- | :--- |
| **高** | **开发延期或质量缺陷**<br>团队成员日常业务繁忙，导致开发进度滞后或出现Bug。 | 系统无法按时上线，影响办公效率。 | 1. **MVP原则**：第一版仅实现“查看空闲”、“预约”、“取消”三个核心功能。<br>2. **Code Review**：严格执行代码审查。<br>3. **回滚预案**：保留飞书/Excel表格作为临时备用方案，确保过渡期不断档。 |
| **中** | **日历同步冲突**<br>Google与Outlook API限制或网络波动导致同步延迟。 | 用户看到错误的会议室状态。 | 1. **最终一致性设计**：前端展示时标注“最后同步时间”。<br>2. **重试机制**：后端设置定时任务每5分钟强制校验一次关键会议室状态。<br>3. **人工修正入口**：提供管理员后台手动锁定/释放会议室的功能，应对极端情况。 |
| **中** | **单点故障**<br>云服务器宕机导致系统不可用。 | 全员无法预约会议室。 | 1. **自动备份**：每日凌晨自动备份数据库至异地OSS。<br>2. **高可用选项**：若预算允许，可增加一台低成本备机做主从切换（当前预算下暂不考虑，依靠云厂商SLA保障）。 |
| **低** | **安全风险**<br>弱口令或SQL注入。 | 数据泄露或被恶意篡改。 | 1. **最小权限原则**：数据库仅开放内网访问，后端通过Nginx反向代理暴露HTTP端口。<br>2. **定期扫描**：使用云厂商提供的免费漏洞扫描服务每月巡检。 |

## 6. 实施路线图建议

1.  **第1周（设计与原型）**：
    *   确定技术栈（推荐 Node.js + Express + PostgreSQL + React/Vue）。
    *   设计数据库模型（Users, Rooms, Bookings, CalendarSyncLogs）。
    *   完成UI原型图。
2.  **第2周（核心开发）**：
    *   实现基础CRUD功能（增删改查会议室预订）。
    *   集成 Google Calendar API 和 Microsoft Graph API，实现双向事件同步。
    *   部署至测试服务器。
3.  **第3周（测试与试点）**：
    *   邀请3-5名种子用户进行为期一周的内部测试。
    *   收集反馈，修复Bug，优化同步逻辑。
4.  **第4周（正式上线）**：
    *   全员培训（发布简短的使用指南视频）。
    *   正式切换至新系统，旧方式（如Excel共享文档）停用。

**结论**：鉴于30人研发团队的自身技术属性，**自研轻量级系统**是性价比最高、最灵活且完全符合预算约束的唯一可行路径。
