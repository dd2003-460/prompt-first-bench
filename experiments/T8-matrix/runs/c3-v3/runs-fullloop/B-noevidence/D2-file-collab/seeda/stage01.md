# 阶段 01：目标分解、已知与空缺条件

## 1. 目标交付物定义
**最终交付物**：一份《30人研发团队文件协作/网盘选型报告》。
**核心内容**：
1.  **推荐方案**：单一最佳解决方案（含具体套餐版本）。
2.  **备选方案**：1-2个次优选择。
3.  **淘汰理由**：针对主要候选竞品或未入选方案的明确排除依据。
4.  **成本明细**：精确到元/年的预算拆解，证明 ≤¥30,000/年。
5.  **功能验证结论**：针对“文档版本管理”、“细粒度权限”、“Web/macOS/Windows客户端”、“离线可用”的具体支持情况说明。

## 3. 条件分类清单

### A. 人类已提供的条件 (Given)
1.  **团队规模**：30人。
2.  **预算上限**：≤ ¥30,000 / 年。
3.  **必需平台**：Web, macOS, Windows。
4.  **核心功能**：文档版本管理，细粒度权限控制。
5.  **加分项**：离线可用。
6.  **行业背景**：研发团队（隐含需求：代码/文档混存可能性高，重视权限隔离，可能涉及敏感数据）。

### B. 从项目可推导的条件 (Derived)
1.  **人均预算**：¥30,000 / 30人 = ¥1,000 / 人 / 年 ≈ ¥83 / 人 / 月。
    *   *推导意义*：这个人均月度预算处于主流企业云盘的中低端区间。高端国际方案（如 Box Enterprise, SharePoint Online Premium）通常超过此预算，需重点考察性价比高的国产方案或基础版国际方案。
2.  **存储需求预估**：研发团队通常存储中等大小文件（文档、图片、小型二进制包），假设每人平均占用 50-100GB，总存储需求约 1.5TB - 3TB。
    *   *注意*：此为假设值，需在阶段02通过询问用户或参考行业标准进行修正，但作为初步筛选依据是合理的。
3.  **合规性暗示**：既然使用人民币预算且未指定海外部署，默认优先考量中国本土服务商（数据落地国内），除非国际方案有显著功能优势且符合跨境合规。

### C. 仍需研究的条件 (Unknowns/Gaps) -> **写入空缺清单**

| ID | 空缺项描述 | 阻塞的判断 | 优先级 |
| :--- | :--- | :--- | :--- |
| G1 | **各候选产品的最新定价模型** | 无法确定哪个方案在 ¥30k 预算内能容纳 30 人及所需存储。 | P0 |
| G2 | **"细粒度权限"的具体定义验证** | 某些产品仅支持“共享链接权限”，不支持“文件夹继承权限”或“基于角色的访问控制(RBAC)”。需验证哪些产品真正满足“细粒度”。 | P0 |
| G3 | **"文档版本管理”的深度验证** | 区分“文件历史版本（Snapshot）”与“文档协同编辑版本（Track Changes/Diff）”。研发团队可能需要后者用于PRD/技术文档。 | P0 |
| G4 | **离线可用的具体机制** | 验证离线时是否真的能编辑并保存，还是只能读取。冲突解决策略是什么。 | P1 |
| G5 | **SSO/目录同步支持** | 研发团队通常使用 LDAP/AD 或 Okta/钉钉。若不支持 SSO，管理30个账号的成本会上升。 | P1 |
| G6 | **数据驻留地与合规资质** | 确认候选产品在中国大陆的数据中心情况及等保三级等资质。 | P1 |
| G7 | **移动端支持情况** | 虽然任务未强制要求，但研发人员常用手机查看文档。若完全无移动端，体验分降低。 | P2 |
| G8 | **免费试用期政策** | 影响 PoC（概念验证）阶段的可行性。 | P2 |

## 4. 候选对象类别与初始假设 (Candidate Set Freeze)

*注：以下候选仅为基于市场常识的**初始假设**，具体属性（价格、功能细节）均在阶段02中核验。本列表即为冻结集合，后续不得随意增删类别，除非在02中发现新的重大类别并显式记录。*

### 类别 A: 中国本土综合办公/云盘厂商 (High Probability for Budget & Compliance)
*   **候选 1: 腾讯微云 / 企业微信云文档**
    *   *假设*: 性价比高，与微信/企微生态集成好，权限控制较基础，版本管理依赖底层文件系统或特定文档工具。
*   **候选 2: 钉钉 (Teambition / 钉盘)**
    *   *假设*: 与项目管理结合紧密，权限随组织架构，版本管理在 Teambition 文档中较强，纯钉盘较弱。
*   **候选 3: 飞书 (Feishu/Lark Drive)**
    *   *假设*: 文档协同能力极强（Notion-like），版本管理优秀，权限颗粒度细。但需注意其计费模式（专业版/企业版门槛）。
*   **候选 4: 阿里云盘 企业版 / 百度网盘 企业版**
    *   *假设*: 存储能力强，价格低廉，但文档协作和细粒度权限相对弱于办公套件类厂商。

### 类别 B: 国际知名协作平台 (Potential for Feature Depth, Cost Risk)
*   **候选 5: Dropbox Business**
    *   *假设*: 客户端体验极佳，离线同步稳定，权限控制中等（Shared Links vs Team Folders），版本保留期长。价格较高，需验证30人是否在预算内。
*   **候选 6: Google Workspace (Drive)**
    *   *假设*: 文档版本管理（History）和权限（Share with specific people/groups）非常成熟。但在国内访问速度和合规性存在不确定性（需代理或特定网络环境），这是一个巨大的**风险点**。
*   **候选 7: Microsoft 365 (OneDrive for Business / SharePoint)**
    *   *假设*: 权限最细（ACL级别），版本管理最强（Site Collection/Library level）。但 M365 授权复杂且昂贵，30人全套 Office+M365 很可能超出 ¥30k 预算，需寻找轻量级订阅或仅 SharePoint Online 方案。

### 类别 C: 垂直领域研发协作/私有化部署 (Niche)
*   **候选 8: Nextcloud (自托管/云服务)**
    *   *假设*: 开源，可无限定制权限，版本管理插件丰富。但需要运维成本（服务器、维护），对于30人团队，自建的人力成本可能远超 ¥30k 预算，除非已有现成服务器。*暂定排除或列为高风险备选，因为“选一套方案”通常指SaaS。*
*   **候选 9: Confluence (Atlassian)**
    *   *假设*: 专注知识库，版本管理极强。但它不是传统“网盘”，不适合存放大型二进制文件（代码库、视频）。若团队只需文档，它是神器；若需通用网盘，它不适用。**需界定团队“文件”的定义**。

## 5. 阶段 02 研究路径 (Research Plan for Phase 02)

### 目标
验证 G1-G8 空缺，筛选出 Top 3 方案，并计算精确 TCO。

### 步骤 1: 候选资格初筛 (Knock-out Criteria)
*   **动作**: 访问上述 9 个候选对象的官网。
*   **搜索词/字段**:
    *   "Pricing", "Plans", "Enterprise pricing".
    *   "Data residency China", "Server location".
    *   "Offline editing", "Conflict resolution".
    *   "Granular permissions", "Role-based access control".
*   **判定标准**:
    *   若最低档套餐 > ¥30,000/30人/年 -> 标记为 `Over Budget` (除非有教育/初创优惠)。
    *   若明确声明数据存储在境外且无合规声明 -> 标记为 `Compliance Risk`。
    *   若无 macOS 或 Windows 客户端 -> 标记为 `Incompatible`。
*   **产出**: 缩小后的候选名单（预计剩余 4-5 家）。

### 步骤 2: 功能深度验证 (Feature Deep Dive)
*   **动作**: 阅读候选产品的 Help Center / Documentation / Product Demos。
*   **关键问题**:
    1.  **版本管理**: 能否查看两个版本的 Diff？保留多少天？
    2.  **权限**: 能否给“单个文件”设置“仅张三可编辑，李四只读”？能否防止下载？
    3.  **离线**: 断开 Wi-Fi 后，打开 Word/PDF 是否能编辑并保存？重连后如何同步？
*   **来源类型**: 官方文档、YouTube/Bilibili 评测视频、G2/Capterra 用户评论（关注负面评价中的权限和同步问题）。
*   **备用路径**: 若官方文档模糊，注册 Free Trial 进行实际测试（PoC-lite）。

### 步骤 3: 成本建模 (Cost Modeling)
*   **动作**: 获取 30 人规模的报价单（Quote）。
*   **公式**: `(Per_User_Monthly_Price * 30 * 12) + (Storage_Overage_Cost) <= 30000`?
*   **注意**: 检查是否有首年优惠、预付款折扣。
*   **产出**: 每个候选方案的精确年化成本表。

### 步骤 4: 风险评估与排序
*   **动作**: 根据 F1-F7 权重打分。
*   **权重建议**:
    *   F1 (合规): 一票否决。
    *   F2 (核心功能): 30%
    *   F5 (成本): 25%
    *   F3 (体验): 20%
    *   F6 (安全): 15%
    *   F4 (离线): 10%
*   **产出**: 排名列表。

### 失败备用路径
*   **若所有国际方案均超预算**: 聚焦国产方案，特别是飞书/钉钉的高级版或阿里云盘企业版。
*   **若所有国产方案权限不够细**: 考虑引入第三方权限网关，或接受“文件夹级”而非“文件级”权限的妥协，并在报告中注明局限。
*   **若网络原因导致 Google/Microsoft 不可用**: 直接从候选集中移除，不浪费时间在合规绕行方案上（除非用户明确要求）。
