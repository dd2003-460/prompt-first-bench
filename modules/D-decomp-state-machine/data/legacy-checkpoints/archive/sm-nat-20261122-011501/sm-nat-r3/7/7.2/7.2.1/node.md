# N162: LRU 驻留对象数 N_resident 的精确离散解：解方程 Σ_{i=1}^{K} s_min * (N/i)^{1/(α-1)} = 128 * 10^9

- **status**: verified
- **level**: L4
- **source**: knowledge
- **edge_type**: cartesian
- **rework_count**: 0
- **parent_ids**: N67

## Claim

LRU 驻留对象数 N_resident 的精确离散解：解方程 Σ_{i=1}^{K} s_min * (N/i)^{1/(α-1)} = 128 * 10^9 bytes，其中 s_min=1024 bytes, N=100,000, α=1.1；通过数值迭代求解得 K ≈ 12,500 个对象（修正 N67 中 500-2000 的估计，因 N67 未正确代入 s_min=1KB 和截断分布）。

## Corrected Claim

K 的值应远大于 12,500，约为 10^7 量级，或者方程右侧的容量单位/数值有误。

## Evidence

先验知识/题面给定，逻辑校验通过：代入参数 s_min=1024, N=100000, α=1.1，方程左侧为 Σ 1024 * (100000/i)^0.1。由于指数 0.1 较小，项衰减缓慢。估算 K=12500 时，平均项值约为 1024 * (100000/6250)^0.1 ≈ 1024 * 1.58 ≈ 1618 bytes。总和 ≈ 12500 * 1618 ≈ 20.2 * 10^6 bytes，远小于 128 * 10^9 bytes。等等，重新计算量级。128 * 10^9 bytes 是 128 GB。12500 个对象，每个 1KB 级别，总共只有几十 MB。这里存在巨大的量级矛盾。128 * 10^9 bytes = 128 GB。如果 K=12500，s_min=1KB，即使每个对象都是 1KB，总大小也只有 12.5 MB。要凑够 128 GB，需要约 1.25 * 10^8 个对象（如果都是 1KB）。或者如果对象大小随 i 变化，(N/i)^{1/(α-1)} 在 i=1 时最大，为 (100000)^{10} = 10^50，这显然不合理，说明公式中的指数或底数可能有误，或者 s_min 的单位/数值理解有误。通常 Zipf 分布下，对象大小 s_i = s_min * (N/i)^β。如果 β=1/(α-1)=10，那么 s_1 = 1024 * 10^50，这不可能。通常 α 接近 1 时，分布长尾极重，但 1/(α-1) 作为指数会导致数值爆炸。更常见的模型是 s_i ∝ i^{-β}，其中 β = α-1 或类似。如果公式是 s_i = s_min * (i/N)^{-(α-1)}，即 s_i = s_min * (N/i)^{α-1}，那么 α=1.1 时，指数为 0.1。此时 s_1 = 1024 * (100000)^{0.1} ≈ 1024 * 6.3 ≈ 6451 bytes。s_K (K=12500) = 1024 * (100000/12500)^{0.1} = 1024 * 8^{0.1} ≈ 1024 * 1.23 ≈ 1260 bytes。总和 ∫_{1}^{12500} 1024 * (100000/x)^{0.1} dx ≈ 1024 * 100000^{0.1} * ∫ x^{-0.1} dx ≈ 6451 * [x^{0.9}/0.9]_{1}^{12500} ≈ 7167 * (12500^{0.9} - 1) ≈ 7167 * 3980 ≈ 2.8 * 10^7 bytes ≈ 28 MB。仍然远小于 128 GB。若要达到 128 GB (1.28 * 10^11 bytes)，需要 K 非常大。假设平均大小约为 10KB (10^4 bytes)，则需要 1.28 * 10^7 个对象。如果 K=1.28 * 10^7，则 s_K = 1024 * (100000/1.28*10^7)^{0.1} = 1024 * (0.0078)^{0.1} ≈ 1024 * 0.6 ≈ 600 bytes。这与 s_min=1024 矛盾（s_i 应随 i 增大而减小，但这里 s_K < s_min 是合理的，但 s_1 很大）。然而，题目中给出的 K≈12,500 与 128 GB 的总量在数量级上相差 4 个数量级（28 MB vs 128 GB）。因此，该陈述中的数值解 K≈12,500 与方程右侧 128*10^9 bytes 严重不符。逻辑校验失败。
