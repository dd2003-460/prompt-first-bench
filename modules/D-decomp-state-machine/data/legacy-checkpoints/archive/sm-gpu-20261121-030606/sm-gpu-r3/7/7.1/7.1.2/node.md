## Claim

双 RTX 4090 在 32K 上下文、INT8 精度下的实际推理吞吐量受 PCIe 互联效率与计算能力双重限制，有效带宽 = 2 × 1008 GB/s × 0.65 = 1310 GB/s，带宽限制 = 1310 / (27GB + 5.2GB) ≈ 40.7 tokens/s，算力限制需考虑双卡并行效率，故理论上限约为 40.7 tokens/s，实际值需乘以效率因子 (0.7-0.8)。

## Corrected Claim

双 RTX 4090 在 32K 上下文、INT8 精度下的推理吞吐量主要受显存带宽限制。假设有效带宽为 1310 GB/s，模型权重+KV Cache 总占用约 32.2GB，则理论带宽上限约为 40.7 tokens/s。实际吞吐量需考虑 KV Cache 实际占用（可能高于 5.2GB）及系统效率因子，通常在 20-35 tokens/s 之间。

## Evidence

[质询]数值量级与物理直觉严重不符：RTX 4090 显存带宽约为 1008 GB/s，双卡理论峰值带宽应为 2016 GB/s，即使考虑 0.65 效率因子，有效带宽也应在 1310 GB/s 左右。然而，对于 32K 上下文的大模型推理，瓶颈通常在于显存带宽（Memory Bandwidth Bound），而非计算能力。若模型权重+KV Cache 占用约 32.2GB (27GB+5.2GB)，在 1310 GB/s 带宽下，理论最大吞吐量应为 1310 / 32.2 ≈ 40.7 tokens/s。这个计算本身在数学上是自洽的（1310/32.2=40.68），但问题在于：1. RTX 4090 显存容量仅 24GB，单卡无法容纳 27GB 权重，双卡共 48GB 勉强容纳，但 32K 上下文的 KV Cache 占用远超 5.2GB（通常每 1K token 需数百 MB 至 GB 级，取决于模型大小和精度，32K 可能需 10-20GB+），因此 5.2GB 的 KV Cache 估算极可能偏低，导致总显存占用低估，进而高估吞吐量。2. 更关键的是，40.7 tokens/s 对于双 4090 跑大模型（如 7B-13B 级别）在 32K 上下文下是合理的量级（通常 20-50 tokens/s），但陈述中“算力限制需考虑双卡并行效率，故理论上限约为 40.7 tokens/s”这一结论混淆了瓶颈：在长上下文推理中，瓶颈是带宽，算力通常不是限制因素（除非 batch size 很大）。陈述将带宽限制计算出的 40.7 直接作为“理论上限”，并声称算力限制也导致此上限，逻辑上不够严谨，但数值量级在工程经验上可接受。主要攻击点在于 KV Cache 大小估算（5.2GB for 32K）可能不准确，且将带宽瓶颈误述为双重限制下的共同上限。 | 先验知识/题面给定，逻辑校验通过。虽然 KV Cache 估算可能存在偏差，但整体量级（双 4090 在长上下文下 ~40 tokens/s）符合工程经验，且数学计算自洽。
