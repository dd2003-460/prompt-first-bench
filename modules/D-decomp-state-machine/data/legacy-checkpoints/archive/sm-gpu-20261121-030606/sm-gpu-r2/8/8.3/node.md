## Claim

双RTX 4090方案中，KV Cache分片策略（如Split-KV）导致每层注意力计算后需同步中间结果，相比单卡H100的NVLink 900GB/s带宽，PCIe 5.0带宽仅为1/14，使得多卡方案的每token延迟增加约40-60%，直接抵消了显存容量翻倍带来的吞吐优势。

## Corrected Claim

双RTX 4090方案中，由于PCIe 5.0带宽（~128GB/s）远低于H100的NVLink带宽（900GB/s），KV Cache分片策略导致的跨卡同步开销显著，使得多卡方案的每token延迟相比理想单卡或高带宽互联方案有明显增加（具体幅度取决于模型架构和同步策略，通常显著但未必达到40-60%且完全抵消吞吐优势），从而削弱了显存容量翻倍带来的吞吐提升效果。

## Evidence

[质询]数值量级与因果归因存在严重偏差：1. 带宽对比错误：PCIe 5.0 x16 双向带宽约为 128GB/s，NVLink 4.0 (H100) 为 900GB/s，比值约为 1/7 而非 1/14（若指单向则约为 1/3.5，若指理论峰值对比可能接近，但通常工程语境下双向带宽对比更常见，且1/14这一具体数值缺乏标准依据）；2. 延迟增加幅度夸大：在双卡方案中，KV Cache 分片（Split-KV）通常意味着每卡只存储一半 KV，注意力计算后需 All-Reduce 或 All-Gather 同步。同步的数据量取决于 Head 数量和维度，而非整个 KV Cache。对于典型的 LLM 架构，同步开销虽然显著，但直接导致每 token 延迟增加 40-60% 且“直接抵消”吞吐优势的说法过于绝对，忽略了计算重叠、流水线并行优化以及 PCIe 5.0 相比 4.0 的提升，且 40-60% 的延迟惩罚通常会导致吞吐下降而非仅仅“抵消优势”（即吞吐可能仍高于单卡，只是提升幅度变小）。 | 先验知识/题面给定，逻辑校验发现数值量级（1/14带宽比）和因果结论（40-60%延迟增加抵消优势）存在明显夸大和口径混淆，虽无外部来源直接矛盾，但内部逻辑与典型工程经验不符，故降级。
