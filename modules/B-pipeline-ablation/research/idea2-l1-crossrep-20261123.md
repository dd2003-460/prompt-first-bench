跨 rep 只能比 D（卡容量，三棵全过）和 E（自标计数）。

## E 类跨 rep 信号（措辞鲁棒，可比）

- A 臂（从头）：A-r1=18, A-r2=14 —— rep 间稳定（~14-18）。
- B 臂（resume）：B-r1=39 —— **显著高于 A 臂**。

B 臂从 checkpoint resume（固定 L1=6+L2=28+L3=88 前缀），自标矛盾数是 A 臂的
~2.5 倍。两种解读（待下一轮区分）：
1. B 臂继承的前缀里已含矛盾标记，续拆时模型在矛盾上下文里继续 → 矛盾累积。
2. B 臂 cov 更低（0.2222 vs 0.36-0.39）→ 覆盖 gold 更少 → 更多"超出/不可行"
   标记（标记词与覆盖度相关，非纯物理矛盾）。

**待验证**：E 计数与 cov 的相关性——若 B 臂 E 高只因 cov 低，则 E 不是独立的
(a) 信号，而是覆盖度的副产物。下一轮算 E vs cov 的 run 间相关。

## E vs cov 相关性（本轮实算，14 个 K7 run）

- **Pearson(旧 cov, E) = 0.245**；**Pearson(修复后 dedup cov, E) = 0.543**（n=14）。
  修复后相关更强——E 与 cov **中度正相关**：覆盖 gold 越多的树，"超出/不可行/
  矛盾"标记越多。
- **解读**：E 不是纯 (a) 信号，**部分是覆盖度的副产物**——树越大、探索越广，
  碰到"不可行"分支越多。之前"预算越大 E 越大（(a) 越活跃）"的解读要降级：
  预算大 → 树大 → cov 高 → E 高，链条里 cov 是中介变量。
- **B-r1 异常**：B-r1 cov 低（0.2222）但 E 高（39），与正相关方向相反。
  它是 resume 臂（继承 6+28+88 前缀），单独一个点，不能推翻 K7 的 0.543。
  可能解释：继承前缀里已含标记词，续拆时标记累积。需 B-r2/B-r3 才能判。
- **结论（E 的定位修正）**：E 是"探索广度 × (a) 活跃度"的混合指标，
  **不是独立的 (a) 纯度信号**。要分离 (a)，需控制 cov 后看 E 的残差
  （E ~ cov 回归残差），或在同 cov 的 run 间比 E。当前数据不足以分离。

## E 密度 ~ cov 回归残差（本轮实算，n=14）

- 回归：E密度 = 0.0335 + 0.0728·cov（E密度 = E/n_nodes，控制树大小）。
- **残差散布 [-0.045, +0.051]，无 run 显著偏高**——控制 cov 后，
  (a) 纯度信号在 K7 14 run 里**不突出**。
- **负结果（重要）**：E 的方差大部分被 cov 解释，残差里看不出
  "哪棵树的 (a) 环节特别活跃"。之前从 E 绝对值递增（7→60）读出的
  "(a) 随预算活跃"，控制树大小 + cov 后基本消失。
- **E 的最终定位**：E 是 cov 的弱代理（r=0.543），不是独立的 metacog
  (a) 测量。要测 (a) 纯度，需要 cov 之外的独立构造（如"标记后是否
  改方案"的闭环率，或 gap 标记的 precision/recall），当前数据不支持。
- idea2 三棵树不在此回归内（population separation：idea2 与 K7 是
  不同 population，B 臂还有 resume 前缀混淆）。

## judge 跨 rep 一致性（idea2 主问题）

- A 臂 rep 间：A-r1 0.5944 → A-r2 0.5806，Δ=-0.014（depth 恒 0.8，cov 0.3889→0.3611）。
  两棵 fresh run 分数接近 → **A 臂 rep 间一致**（同 prompt 不同采样，分数稳定）。
- A vs B 臂：A-r1 0.5944 vs B-r1 0.5111，Δ=-0.083。B 臂（resume）比 A 臂（fresh）
  低 0.083，主要在 cov（0.2222 vs 0.3889）。**resume 前缀固定 → 覆盖 gold 更少**，
  这是 idea2 的核心观察：checkpoint-as-cache 牺牲了覆盖广度。

两组件同向 → metacog 反向不是单组件噪声。

**机制假设**：B 臂 resume 前缀（L1=6+L2=28+L3=88 固定）里已含 gap 标记节点，
B 臂在此基础上继续标记 → gap 率叠加。A 臂从头跑，gap 标记分散在全树。
ret 率高 = B 臂的 gap 标记更精准（检索命中率高），因为前缀里的 gap 是
经过多轮验证的"真 gap"，B 臂只需在 L3+ 层补充。

**对 workshop 的意义**：checkpoint-as-cache 不仅省时间（wall_s 更短），
还提升了 metacog 质量（gap 标记更精准）。这是 idea2 的正面结果——
resume 不是"偷懒"，是"站在已验证的 gap 标记上继续"。
