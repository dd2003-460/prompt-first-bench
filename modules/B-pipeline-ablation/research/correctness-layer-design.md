# correctness 层设计 v0（修复 coverage 陷阱）

# origin: ai（2026-11-25，sub 任务；前 sub sa-0-54c3e480 死于输出 token 上限，本文档为其落盘）

## §0 问题定义：coverage 陷阱

- 现状：pfb 测量层（judge_v1.py, frozen f6072397f）只测 **coverage**（bge-m3 嵌入相似度 vs gold 36 单元），不测 **correctness**（推理链是否对齐 gold 结构）。
- D 已确认（2026-11-25）：coverage 是 correctness 的**必要条件非充分条件**；gold 稳定部分 = **树结构（准入规则 + 计算路径）**，不是赢家标签。
- 陷阱实例：一条输出可以高 coverage（提到带宽门、TCO、量化），但推理链在错误位置断裂，结论仍错。两种断点必须机械区分：
  - **A1 型（候选构建断点）**：winner 卡型/配置从未进入候选集。实锤：T8b arm_a[0] 全文 3090 count=0（salvage 已验证）。
  - **A3 型（排序/权重断点）**：winner 配置被完整评估（进候选表、进打分表）但最终排序垫底。实锤：T8b arm_a[2] 含 4×3090 完整评估上下文，加权分 5.9 垫底，最终推荐 2×4090（salvage 已验证）。
- 本层只回答一个问题：**correctness 层能否机械区分"coverage 够但结论错"的两类原因（A1 vs A3）**。不做质量提升 claim。

## §1 设计原则

1. **机械 + 连续**：无 LLM judge。每个探针 = 正则/字符串计数/嵌入相似度 → 连续分数 ∈ [0,1]。确定性：same input → same output。
2. **复用现有 gold 基础设施，不新建平行 gold**：
   - `bench/rubric-v3/ablation/gold-tree.md`（37 节点，frozen ed552c4）→ 稳定部分 = 准入规则（N-5.x）+ 计算路径（N-0/N-3.x 代数）。
   - `modules/B-pipeline-ablation/gold-gpu-units.json`（36 单元，text 供 bge-m3）→ 复用 judge_v1 的 coverage 轴作对照。
   - `modules/B-pipeline-ablation/gold-gpu-formulas.json`（36 单元 sympy）→ 数值/代数锚。
   - `bench/rubric-v3/tasks/T0-local-27b/reference/calc.py` → gold 数值锚（936 GB/s、24.7 GB/流、W4 14 GB、594 TFLOP、0.679 ¢/task、774/1034/1574 带宽门）。
3. **评分对象 = 推理链与 gold 结构的对齐度 + 数值容差**，不是"最终标签 == winner"。winner 标签只作 dry-run 的 ground-truth 对照（用于验证判别力），不进分数。
4. **A1/A3 判别必须机械**：两个独立探针分别度量"winner 卡型是否在候选集"与"winner 配置是否被完整评估且排序垫底"，不靠 LLM 读语义。

## §2 探针架构（全机械，无 LLM）

winner 配置 = **4×RTX 3090 / W4 / n=2**（gold 稳定结构 = 准入规则 N-5.x + 计算路径 N-0/N-3.x 代数；winner 标签只作 dry-run 对照，不进分数）。

四条轴，每条轴 = 若干探针 → 连续分数 ∈ [0,1]：

### 轴 C：候选构建对齐（gold N-5 可行域分支；A1 诊断轴）
- **C1 卡型提及**：`min(count("3090") / 4, 1)`（K=4 饱和点，designer 自由度）。
- **C1e 有效提及**：扣除否定语境提及——3090 前后 ±40 字符内出现 `遗漏|未覆盖|缺失|缺少|未纳入|没考虑` 的提及不计（模型自述"漏了 3090"≠ 3090 进了候选集）。`C1e = clamp(C1_pos − C1_neg, 0, C1_pos)`。
- **C2 winner 配置提及**：正则族 `4[×xX✕*]3090 | 3090[×xX✕*]4(?!数字) | 4(张|卡|块)3090 | 3090 4(张|卡|块)`，`min(count/2, 1)`。负向前瞻排除 "3090 48GB 改装" 类误配。
- **C = 0.5·C1e + 0.5·C2**。

### 轴 E：评估完整性（gold 计算路径 N-0/N-3 是否被实际执行；A3 诊断轴）
- **E1 winner 配置评估行**：含 4×3090 配置模式 且 同行含评估数值 `(t/s|tok/s|TCO|成本|\$|元|分|W)` 的行数，`min(n/2, 1)`。
- **E2 winner 卡型规格行**：含 3090 且同行含 `GB/s` 且含 `(GB|\$|元)` 的非否定行数，`min(n/2, 1)`。
- **E = 0.5·E1 + 0.5·E2**。

### 轴 R：排序结局（winner 是否被排在底/未被选中）
- 强推荐行 = 含 `主推荐|首选|最终推荐|最终方案|推荐方案|最佳方案|最优方案|综合推荐|最终结论` 的行。
- **R_low**：若 E1>0（配置被评估过）：强推荐行含 4×3090 模式 → 0（被选中）；否则 → 1（垫底/未选中）。若 E1=0：0.5（未定义，中性；A3 概率里被 E1 乘零，不影响）。
- 局限：只认"强推荐行"，不解析加权分表（跨格式太脆）；arm_a[2] 的加权分表 5.9 垫底可由 R_low=1 + E1 行证据交叉印证，见 §6。

### 轴 S：gold 树结构对齐（准入规则 + 计算路径的机械签名）
- **S_band**（N-5.2 带宽准入）：`774|1034|1574` 紧邻 `GB/s` 的出现，`min(n/1,1)`。
- **S_mem**（N-5.1 显存门）：`(W|权重)[+＋](KV|kv)…(≤|<=|不超过|显存)` 或反向序，`min(n/1,1)`。
- **S_dec**（N-3.2 decode 代数 `W+n×KV` 签名）：`(W|权重)[+＋]…(n|并发)[×xX*](KV|kv)`，`min(n/1,1)`。
- **S_obj**（N-0 目标函数）：`c_pass|每个通过任务|单位(任务|成本)|每任务成本`，`min(n/1,1)`。
- **S = mean(S_band, S_mem, S_dec, S_obj)**。

### 轴 N：数值容差（gold 锚值，容差 10%，同 judge_v1 NUM_TOL 口径）
gold 锚（值 ← calc.py / gold-tree N-5.2）：936 GB/s（3090 带宽）、14 GB（W4 权重，13.5 在 10% 内）、27 GB（W8/INT8 权重）、24.7 GB/流（KV）、594 TFLOP（prefill）、0.679 ¢/task（c_pass 点值）、774/1034/1574（带宽门，计 1 锚）。
**N = (命中且 |v−gold|/gold ≤ 0.10 的锚数) / 7**。未提及的锚计 0。

## §3 分数合成与 A1/A3 判别规则

**correctness 总分**（v0 权重，designer 自由度，标定后可调）：
`CORR = 0.35·C + 0.25·E + 0.20·S + 0.20·N`
（R 不进总分——R 是"结论错没错"的结局信号，不是"链对不对"的结构信号；它只参与判别。）

**A1/A3 判别（机械规则，无 LLM）**：
- `P_A1 = 1 − C`（winner 卡型/配置未进候选集的程度）。
- `P_A3 = E1 · R_low`（winner 配置被完整评估 ∧ 排序垫底/未被选中）。
- 判定：
  - `P_A1 ≥ 0.7` → **A1 型**（候选构建断点）
  - `P_A3 ≥ 0.5` → **A3 型**（排序断点）
  - 两者都命中 → **A1+A3 复合**（候选构建弱 + 评估后排底，如实报告）
  - 都不命中 → **indeterminate**（既不 A1 也不 A3：可能结论对，或断点在别处）
- 边界说明：A1 与 A3 不是互斥的连续谱——A1 的输出里 3090 完全不出现，E1 必为 0，P_A3 必为 0，所以纯 A1 不会误判 A3；反之 A3 输出里 3090 大量出现，C 高，P_A1 低，不会误判 A1。两型的判别信号在数据上是分离的（dry-run §6 验证）。

## §4 输入归一化

- T8b arm_a：`content + "\n" + reasoning`（reasoning 是推理链本体，必须并入；content 是最终答案）。
- T8b arm_b：`final_content + 各 stage content`（stage 顺序 01/02/02.5/03/04/04.5；stages 是 dict{stage_id: {content,...}}）。
- S5 run：`nodes[].claim` 拼接（355 节点，58936 字符）。
- 行级探针（E1/E2/R）按 `\n` 分行；表格行（`|` 开头）保留完整行参与匹配。
- 否定语境窗口 ±40 字符（C1e/E2 共用）。

## §5 与 coverage 轴（judge_v1）的关系

- 本层**不修改 judge_v1.py（frozen）**，独立文件 `correctness_layer_v0.py`。
- coverage 轴（judge_v1：bge-m3 vs 36 gold 单元）保留，作对照轴：dry-run 里同报 `cov`（judge_v1 口径）与 `CORR`（本层），直接展示"coverage 够但 CORR 低"的陷阱样本。
- 本层 S 轴与 coverage 的区别：coverage 测"提到没提到概念"（嵌入相似度，无结构）；S 轴测"gold 树的机械签名出现没出现"（准入规则数字、代数签名、目标函数名）——结构对齐，不是词汇覆盖。
- 本层不替代 coverage，二者正交：C/E/R 轴管"winner 配置在链里的命运"，S/N 轴管"gold 结构/数值有没有被实例化"，coverage 管"概念词汇覆盖"。

## §6 验证标准（dry-run 必须复现）

对 T8b 6 条 + S5 共 7 样本：
1. **已知 A1 ≥1 条被检出**：arm_a[0]（3090 count=0）→ 应判 A1（P_A1=1.0）。
2. **已知 A3 ≥1 条被检出**：arm_a[2]（4×3090 完整评估 + 5.9 垫底 + 推荐 2×4090）→ 应判 A3（P_A3=1.0）。
3. 判别准确率 = 正确判定的已知类型样本数 / 已知类型样本总数（已知 = {arm_a[0]: A1, arm_a[2]: A3}，salvage 验证过的事实）。
4. 其余 5 条（arm_a[1]、arm_b[0..2]、S5）无 ground truth，只报 indeterminate/复合 与否，不作准确率分母。
5. 分数表落盘 `correctness-layer-dryrun-20261125.md`，每样本一行：cov / C / E / S / N / CORR / P_A1 / P_A3 / 判定。

## §7 局限与诚实边界

- **R 轴只认强推荐行**：不解析加权分表/排名表（markdown 表格跨格式解析太脆）。arm_a[2] 的"5.9 垫底"证据 = 强推荐行不含 4×3090（推荐 2×4090）+ E1 行证据（配置进过 TCO 表/打分表）。若某输出把 winner 排第二而非垫底、且强推荐行恰好提到 winner，R 会漏——v0 接受，标局限。
- **正则族覆盖有限**：4×3090 的写法变体（"四张 3090"、"3090×4 集群"）靠正则族兜底；中文数字"四"已纳入 `4(张|卡|块)` 的变体。
- **S5 是节点 claim 拼接**，不是连贯推理链——行级探针（E/R）对它的语义弱于对 T8b 的语义；S5 主要验证 S/N 轴与 C 轴。
- **数值锚 7 个**：774/1034/1574 合并计 1 锚（它们是同一准入规则的三档，不是三个独立事实）。
- 本层**不 claim 质量提升**：只验证"能否机械区分 A1/A3"。权重（0.35/0.25/0.20/0.20）是 v0 初值，未经标定，跨 run 比较前需按判分校准规则对齐档位。

## §10 核心 finding（dry-run 实证回扣设计动机）

1. **A1/A3 可机械区分**（dry-run 2/2 + 扰动自测 5/5 + 确定性双跑哈希一致）：C/E/R 三轴各自因果驱动判别，信号在 (P_A1, P_A3) 空间对角分离。
2. **"gold 稳定部分 = 树结构"在本批数据上只被部分实例化，且缺的恰是准入规则与目标函数**：
   - **已实例化**：KV 容量计算（N-3.2.2 kv_per_stream）——arm_a[2] 自行推出 24.2 GB（2×45×4096×32768×1 byte）、S5 推出 25.6 GB（2×64×8×128×32768×2 bytes），均在 gold 24.7 的 10% 容差内（差异来自 gold N-3.2.2 标注的"层数/KV头数 2 倍分歧待核验"口径差，非误报）。
   - **全 0（7/7 样本）**：带宽准入门数字 774/1034/1574（N-5.2）、prefill 计算量 594 TFLOP（N-3.1.1）、c_pass 点值 0.679（N-0）、以及 S 轴全部代数签名（显存门 W+KV≤mem、decode 代数 W+n×KV、目标函数名）。
   - 即：模型普遍做了**容量核算**，但没一条把 gold 树的**准入规则（带宽门）与目标函数（c_pass）**落到具体数字上。这正是 coverage 陷阱的量化全貌——coverage 测不出这一层，correctness 层的 S/N 轴测得出，且"哪些子结构落地、哪些没有"本身就是信息。
3. **推论（给 v1 的方向，非本层 claim）**：若 S 轴在更大样本上仍近 0，说明"推理链对齐 gold 结构"的瓶颈不在断点位置（A1/A3 已能定位），而在**结构落地能力**——模型普遍不实例化准入规则数字。届时 correctness 层的主要价值从"区分断点"转为"度量结构落地率"，S 轴权重应上调（v0 的 0.20 偏低）。
