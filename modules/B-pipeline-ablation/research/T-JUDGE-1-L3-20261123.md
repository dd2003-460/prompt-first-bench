## 结论（修正后）：子路 A 不可行，子路 B 机械可做

L3 = 数值层。此前状态 "blocked on symbol alignment"。本轮探测确认子路 A
（符号对齐）不可行的根因是量空间不同而非拼写；同时发现子路 B（数值 vs 来源）
是机械可做的独立校验层。

## 子路 A（符号对齐）不可行的三个证据

### 1. 变量空间零重叠（结构性根因）
- gold 40 个符号，全是**物理约束量**：`w_bytes`/`kv_per_stream`/`bw_eff`/
  `bw_floor`/`n_cards`/`tf_peak`/`mfu`/`t_decode`/`gpu_price`/`elec_cost`
- 模型 24-68 个符号，全是 **TCO/性价比语义量**：`Hardware_Cost_USD`/
  `Quality_Score`/`Throughput_tokens_per_sec`/`Annual_Power_Cost_USD`/
  `MMLU_score_base`
- 4 棵 idea2 树（A-r1/A-r2/B-r1/B-r2）**全部 0 重叠**。
- 解读：模型在**成本层**建模（性价比=吞吐×质量/成本），gold 在**物理约束层**
  建模（显存/带宽/卡数/TFLOPS）。两者回答的是同一问题的不同投影，
  符号交集为空不是 bug，是建模视角正交。

### 2. 机械可救子集太稀
"计算型全常量公式 + 声称值共现"（能直接 sympify 出数值、不依赖符号对齐、
且 claim 里有 ≈X GB 可比的）：
| 树 | 计算型全常量 | 带声称值共现 |
|---|---|---|
| A-r1 | 1 | 0 |
| A-r2 | 2 | 2 |
| B-r1 | 6 | 5 |
| B-r2 | 7 | 4 |
0-5 个/树，撑不起一个独立 judge 层（n 太小，分数噪声主导）。

### 3. KV 数值自洽已被 L1 A 类覆盖
L1 的 A 类检查（"KV 峰值 X GB（公式）→ 重算公式比对 X"）就是 L3 数值层
在 KV 公式上的子集。L3 的增量 = 非 KV 公式的数值自洽，而第 2 点证明
非 KV 的机械可判样本太稀。

## 为什么不做 LLM 符号对齐
D 2026-11-22 约束：judge 必须纯机械、无 LLM（LLM judge 注入 family bias +
非确定性，污染被测量的变量本身，见 workshop §5.2）。用 LLM 把
`Throughput_tokens_per_sec` 映射到 `t_decode` 违反该约束。
`tjudge1_llm_fallback.py` 是 LLM 兜底通道，只用于**补写符号**（把中文 claim
的公式转 ASCII），不用于**跨量空间语义对齐**——后者本质是判断不是抽取。

## 对 workshop 的含义
- "5 层机械 judge" 的方法论贡献里，L3 是**有意的留白**而非缺失：
  在"模型用 TCO 语义量、gold 用物理量"的设定下，数值层机械对齐被证明
  不可行，这本身是一个可报告的发现（量空间正交 → 数值层需 LLM → 违反
  无 LLM 约束 → 留白）。
- 数值自洽不是没有，是**分散在 L1**（KV A 类 + 工作点 B 类 + per-card C 类
  + 卡容量 D 类），L1 已经是"物理量数值自洽"的承载层。L3 作为独立层
  的增量价值不足以抵消其不可行性。

## 子路 B（数值 vs 来源）：机械可做

D 重框后的可落地层。`modules/B-pipeline-ablation/source_verify.py`：
- 候选节点 = claim 含 数值+单位(GB/tokens/s/GB/s/TFLOPS/W/美元) 且
  `retrieval_sources` 含 ≥1 URL。
- 取 claim 第一个 数值+单位、第一个 URL（去 `&rut=` DDG 尾巴）。
- 严格命中 = 数值 与 单位在 20 字符窗口内共现（压"24"撞日期/ID 的假阳性）。
- 分类 verified(严格) / weak(仅宽松) / not_verified(可达但皆无) /
  unreachable(抓取失败)；`vsr = verified / 可达节点`。
- 缓存断点续（`data/source-verify-cache.json`），确定、可复现、无 LLM。

**两个必须标注的边界**：
1. **可达性偏差**：zhihu/csdn 反爬挡住，而它们恰是模型主要来源
   （B-r2 URL hosts: csdn 58 / zhihu 36 居前二）→ 不可达集偏向模型真实来源，
   非随机。vsr 只在可达子集上算，分母须报 reach_rate。
2. **"数值在页"≠"数值对"**：页面出现 24GB 不代表就是 claim 说的那个量
   （可能是另一张卡、另一精度）。严格窗口共现压一部分假阳性，压不死
   语义错配。这是"来源可达性校验"，不是"来源正确性校验"——后者仍需
   判断 claim 的数值是否对应来源里的那个量（语义层，机械做不了）。

**对 judge 的含义**：子路 B 是第 6 个机械诊断层（L0 自洽 / L1 物理 / L2 结构 /
L4 结论 / 来源可达性），不进 composite（同 L2/L4），但补上了"模型声称有来源"
这一维的机械核验——此前 metacog 的 retrieval_rate 只数"标了 search 的节点占比"，
不查来源是否真可达、数值是否真在页里。

## 状态（修正后）
- 子路 A（符号对齐）= **mechanically infeasible**（量空间正交，非 unsolved）。
- 子路 B（数值 vs 来源）= **mechanically feasible**（`source_verify.py`，全量扫描中）。
- 若未来要完整数值层：子路 A 需 LLM 对齐（违反无 LLM 约束）或改 gold 用 TCO
  语义量（违反 gold 冻结），三条路都不成立 → 子路 A 留白；子路 B 不依赖这两条，
  独立成立。

## 教训（D 2026-11-23 纠正）
判"某层不可行"前，先**分解该层的子任务**，逐段判哪段依赖 LLM、哪段机械可做。
把整体判死 = 把可机械化的子段一起埋了。核验 = 分解 + 搜集 + 校验，三段里
只有前两段 LLM 不可靠；模型已带 URL = 前两段已外包给模型，第三段机械可收。

## 子路 B 全量扫描的两个附带发现（2026-11-23）

### 1. search_rate ~ coverage 弱负相关（-0.134, n=14 K7 树）
检索占比高的 run coverage 不升反略降。与 metacog 轴的反向信号一致：
retrieval_rate 不是质量信号（标了 search ≠ 搜到了对的东西）。来源校验层
（子路 B）正好补这个缺口——它查的不是"标没标 search"，而是"标了 search
的节点，URL 真可达吗、数值真在页里吗"。

### 2. budget-100-r2（314 节点）：117 个 search 节点但 0 URL
source=search 但 retrieval_sources 为空——数据管道缺口：标了检索却没存
来源 URL。该 run 的子路 B 无法施加（URL 缺失）。影响：source_verify 的
19 树里这一棵的 search 节点全部落入 unreachable/非候选。这是 provenance
完整性问题，须标注（不是模型没搜，是管道没存）。

### 3. URL 保留率跨 run 0-100% 波动 → 子路 B 适用域受限（2026-11-23，重要）
全 19 树：2196 个 search 节点，1330 个无 URL（**60.6% 缺口**）。保留率
跨 run 剧烈波动：
| run | 保留率 | run | 保留率 |
|---|---|---|---|
| budget-150-r1/r3 | 100% | budget-100-r2 | 0% |
| budget-50-r2 | 98% | budget-300-r1 | 10% |
| A-r2 | 98% | budget-300-r3 | 12% |
| A-r1 | 41% | budget-719-r3 | 22% |
| B-r2 | 64% | budget-719-r1 | 12% |

后果：子路 B（vsr）只在"存了 URL 的子集"上可算，而该子集占比跨 run
0-100% 不等 → **跨 run 比 vsr 被 URL 保留率混淆**（保留率低的 run 候选少、
vsr 方差大）。两个含义：
1. vsr 是**单 run 内的诊断**（这个 run 存下来的来源里多少数值真在页里），
   不是跨 run 的质量排名指标。
2. **URL 保留率本身是一个 provenance 完整性指标**（管道把多少检索结果存成了
   可核验的来源），60.6% 整体缺口说明管道在丢来源——这比 vsr 更基础，
   因为没存 URL 的节点根本无法核验。

对 workshop：子路 B 可作为"来源可达性 + 数值在页率"的单 run 诊断，但
跨 run 比较须先控制 URL 保留率；更优先的修复是管道层把检索 URL 完整存下来
（否则 60.6% 的检索节点天然不可核验）。

### 3b. 60.6% 缺口的性质分解：80% 管道丢源 vs 20% 疑似虚标（2026-11-23）
对 1330 个无 URL 的 search 节点查 evidence/corrected_claim 的引用痕迹
（来源[n]/参考/根据/检索/搜索/查到）：
- **80%（1070）有引用痕迹** → 真检索了，管道没存 URL（provenance 丢失）。
- **20%（260）无引用痕迹** → 疑似虚标 source=search（标了检索但 evidence
  里没有任何引用，可能根本没检索或引用没写进 evidence）。

含义（对 metacog retrieval_rate 轴）：
1. retrieval_rate = search 节点 / 总节点，**分子含 20% 疑似虚标** →
   该轴系统性高估真实检索率（上界 = 现值，下界 = 现值 × 0.8）。
2. 80% 管道丢源是**可修复的**（管道层存 URL），20% 虚标是**模型行为问题**
   （标了 search 没真检索）——两者修复路径不同，不能混为一谈。
3. 子路 B（vsr）的候选集只含"存了 URL 的节点"，天然排除了 20% 虚标 + 80%
   丢源 → vsr 是"存下来的来源里多少真支撑数值"，对虚标免疫（虚标节点
   不在候选集里），但对丢源敏感（丢源节点本可核验却没存）。

### 4. idea2 臂间 vsr：B 臂 > A 臂，独立复现 metacog 反向信号（2026-11-23）
| 臂 | run | 候选 | vsr |
|---|---|---|---|
| A | A-r1 | 16 | 0.5000 |
| A | A-r2 | 57 | 0.4167 |
| B | B-r1 | 21 | 0.6154 |
| B | B-r2 | 38 | 0.7059 |

B 臂均值 0.66 vs A 臂均值 0.46——**来源可达性 + 数值在页率 B 臂更高**，
与 metacog 轴的反向信号（B 臂 metacog 更好）同向。这是来源校验层**独立地**
（不经过 embedding/depth，纯 URL 可达 + 数值在页）复现了臂间差异，交叉验证
了"checkpoint-as-cache 用 breadth 换 precision"的 tradeoff：B 臂（带 prefix）
的来源更可达、数值更扎实。

**口径警告**：候选数小（16-57，受 URL 保留率限制），vsr 方差大，n=2/臂，
**suggestive 非 confirmed**。且 vsr 只在"存了 URL 的子集"上算，A 臂 URL 保留率
低（A-r1 41%）→ A 臂候选偏少、可能偏向"存下来的高质量来源"（幸存者偏差），
臂间差可能被低估或高估，方向待 K7 15 树 + r3 确认。

### 5. 全量扫描（19 树）+ budget 趋势（2026-11-23，扫描完成）
- **总体**：候选 359，可达 220（可达率 61%），加权 vsr = 124/220 = **0.564**。
- **K7 budget 趋势**（reach≥3 的 run）：
  | budget | mean vsr | n |
  |---|---|---|
  | 50 | 0.761 | 3 |
  | 100 | 0.846 | 1 |
  | 150 | 0.603 | 3 |
  | 300 | 0.533 | 3 |
  | 719 | 0.541 | 3 |
- **cor(n_nodes, vsr) = -0.472**（n=14，中等负相关）——节点越多，来源核验率越低。

**解读**：与"budget buys breadth, not depth"同向——更多预算 → 更多节点 →
来源核验率下降。breadth 扩张的节点引用了更不可核验的来源（更推测性、更不
扎实）。这是 depth score（§4.3 非单调）、coverage（部分混淆）、L4 零收敛
（§4.4 obs4）之外的**第 4 个独立维度**支持同一结论。

**口径警告**：
1. b100 仅 n=1（0.846），b719（0.541）> b300（0.533）→ **非严格单调**，是
   "下降趋势 / 负相关"，不是"严格单调递减"。
2. vsr 在"可达子集"上算，可达率跨 run 不等（与 URL 保留率混淆）→ 高 budget
   run 若 URL 保留率低，vsr 方差更大。
3. n=14，中等相关，**suggestive 非 confirmed**。

**替代解释检验（2026-11-23）：趋势不是保留率幸存者偏差**。
担心"高 budget vsr 低"只是"高 budget run 存 URL 少、存的是特意存的高质量
来源"（幸存者偏差）。量化：
- cor(n_nodes, vsr) = **-0.566**（n=13, reach≥3）
- cor(n_nodes, retention) = -0.607（高 budget 确实保留率低）
- cor(retention, vsr) = **+0.148**（保留率本身与 vsr 几乎无关）
- **partial(vsr ~ n_nodes | retention) = -0.607**——控制保留率后相关反而
  更强。

结论：budget→vsr 下降**不是**保留率混淆的产物（若只是幸存者偏差，控制
retention 后应消失；实际更强）。保留率与 vsr 独立，两者是不同维度：
retention 是管道行为，vsr 是来源质量。趋势成立（suggestive）。
