## 陷阱复现（coverage 够但结论错）

cov 列（judge_v1 bge-m3 口径）与 CORR 列对照：arm_a[2] cov=0.083 但 CORR=0.652（链结构对齐高，结论仍错→A3）；arm_a[0] cov=0.028 且 CORR=0.114（coverage 低 + 链断→A1）。本层 CORR 与 cov 不同源：CORR 捕捉"winner 配置在链里的命运"（C/E/R），cov 只捕捉"概念词汇覆盖"——正是 coverage 陷阱的量化体现。

## 已知局限（诚实边界，不影响 A1/A3 判别结论）

1. **N 轴数值锚缺指代校验**：936 GB/s 同时是 3090 与 A6000 的带宽。arm_a[0] 的 bw936 锚 3 次命中实为 A6000（误报），N 轴分数被抬高（arm_a[0] N=0.571 偏高）。N 轴不参与 A1/A3 判别（判别只靠 C/E/R），故核心结论不受影响；但 N 轴绝对值跨样本比较时需人工核指代。
2. **kv24_7 锚容差内混入 27.0**：24.7±10% = [22.2,27.2]，把 27.0（W8 权重）也纳入，属容差带过宽。v0 接受，标定期收紧。
3. **R 轴只认强推荐行**，不解析加权分表（arm_a[2] 的 5.9 垫底靠 R_low=1 + E1 行证据交叉印证，非直接读分表）。
4. **S 轴全 0**：gold 带宽门数字（774/1034/1574）、KV 点值（24.7）、decode 代数签名（W+n×KV）在全部 7 样本均未实例化——这是 coverage 陷阱的又一量化证据（词汇覆盖 ≠ gold 结构落地），但也说明 S 轴在本批数据上无区分度，需更多样本验证。
5. **权重 0.35/0.25/0.20/0.20 是 v0 初值**，未经标定；跨 run 比较前需按判分校准规则对齐档位。本 dry-run 只验证"能否机械区分 A1/A3"，不做质量提升 claim。
