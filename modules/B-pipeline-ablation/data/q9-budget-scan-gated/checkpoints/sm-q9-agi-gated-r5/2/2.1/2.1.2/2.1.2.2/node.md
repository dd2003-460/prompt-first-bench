## Claim

MTP×4投机解码在Decode阶段的接受率α对总延迟的影响：实际生成延迟 = 15ms / (1 + α*3)，当α=0.8时延迟降至6.25ms，当α=0.5时降至10ms，当α=0.3时降至11.5ms

## Corrected Claim

MTP×4投机解码在Decode阶段的接受率α对总延迟的影响：若基础延迟为15ms，采用公式 Latency = 15 / (1 + 3α)，则当α=0.8时延迟约为4.41ms，当α=0.5时延迟为6ms，当α=0.3时延迟约为7.89ms。（注：原题中数值与公式不符，若数值正确则公式应为 Latency = 15 / (3α) 或其他形式，但11.5ms无法简单由15/(3*0.3)得出）

## Evidence

先验知识/题面给定，逻辑校验通过：MTP×4意味着每步最多生成4个token（1个草稿+3个验证），若接受率为α，则平均每步生成 1 + 3α 个token。原单token延迟15ms，新延迟应为 15 / (1 + 3α)。计算验证：α=0.8 -> 15/(1+2.4)=15/3.4≈4.41ms（注：题目中6.25ms对应的是15/2.4，即假设分母为α*3+1? 不对，15/2.4=6.25。让我们重新检查公式。题目说 15ms / (1 + α*3)。当α=0.8，1+0.8*3 = 1+2.4=3.4。15/3.4 ≈ 4.41ms。但题目声称是6.25ms。6.25 * 2.4 = 15。这意味着分母是2.4，即 α*3。这说明题目中的公式描述可能有误，或者计算基于不同的假设（例如忽略了第一个token的固定开销，或者公式本身写错了）。然而，作为knowledge节点，我们需要判断其内部逻辑是否自洽。题目给出的公式是 `15ms / (1 + α*3)`。代入α=0.8，结果是4.41ms，而非6.25ms。代入α=0.5，15/(1+1.5)=15/2.5=6ms，而非10ms。代入α=0.3，15/(1+0.9)=15/1.9≈7.89ms，而非11.5ms。显然，题目中的数值计算与给出的公式不符。但是，如果我们看数值：6.25 = 15 / 2.4 = 15 / (0.8 * 3)。10 = 15 / 1.5 = 15 / (0.5 * 3)。11.5 ≈ 15 / 1.3 = 15 / (0.3 * 3 + 0.1?) 不对，15/1.3 = 11.53。这里分母似乎是 α*3 + 某个常数？或者公式应该是 15 / (α*3)？如果公式是 15 / (α*3)，那么α=0.8 -> 6.25, α=0.5 -> 10, α=0.3 -> 16.67 (不等于11.5)。再看11.5，15/11.5 ≈ 1.304。1.304 ≈ 0.3*3 + 0.4? 不太像。让我们重新审视常见的MTP延迟模型。通常延迟 = T_decode / (1 + k*α)。如果T_decode=15ms，k=3。α=0.8 -> 15/3.4=4.41。题目数据完全对不上公式。但是，题目陈述的是一个“事实节点”，其中包含了公式和计算结果。如果公式和结果矛盾，这就是一个内部矛盾（硬逻辑错误）。根据判定规则，“存在硬逻辑错误（量纲错/内部矛盾）时才判 failed”。这里的内部矛盾非常明显：公式计算结果与陈述的具体数值不符。因此，应判 failed。
