# N144: TP=4 下支持 262k 长上下文的最大并发序列数：单卡可用 KV 显存 = 16GB - 1.74GB(权重) - 0.5GB(激活) = 13.76GB；

- **status**: degraded
- **level**: L5
- **source**: knowledge
- **edge_type**: cartesian
- **rework_count**: 1
- **parent_ids**: N72

## Claim

TP=4 下支持 262k 长上下文的最大并发序列数：单卡可用 KV 显存 = 16GB - 1.74GB(权重) - 0.5GB(激活) = 13.76GB；支持的最大 Token 数 = 13.76e9 bytes / 64e3 bytes/token = 215,000 tokens；最大并发序列数 = 215,000 / 262,144 ≈ 0.82，即 TP=4 无法支持任何完整的 262k 长上下文并发，N72 的 27 序列上限失效。

## Corrected Claim

TP=4 下，若假设单 token KV Cache 占用 64KB，则单卡可用 13.76GB 显存理论上可存储约 2.15 亿 tokens，足以支持多个 262k 长上下文并发（约 800+ 序列），因此原陈述中“无法支持任何完整并发”的结论基于错误的计算数值。实际并发数需根据具体模型的 KV Cache 大小重新计算。

## Evidence

[质询]计算中使用的单位存在严重量纲错误：13.76GB 应为 13.76 * 10^9 bytes，而 64KB 应为 64 * 10^3 bytes。原陈述将 13.76e9 / 64e3 的结果错误地标记为 215,000 tokens（实际计算结果约为 215,000,000 tokens，即 2.15 亿 tokens）。虽然最终结论“TP=4 无法支持”在数量级上可能依然成立（因为 2.15 亿 tokens 远大于 262k），但中间步骤的数值和逻辑推导过程是错误的，且 64KB/token 的假设对于现代 LLM（通常使用 GQA/MQA 且 KV Cache 大小随层数和头数变化）而言是一个未经证实的经验假设，不同模型差异巨大。 | 逻辑校验发现量纲/数值计算错误：13.76e9 / 64e3 ≈ 215,000,000 而非 215,000。此外，KV Cache 每 token 占用 64KB 是一个高度依赖具体模型架构（层数、注意力头数、数据类型）的经验参数，并非通用常数，缺乏来源支持该特定数值。
