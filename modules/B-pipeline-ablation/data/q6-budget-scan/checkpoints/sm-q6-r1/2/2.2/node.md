# N11: 内存选型与缓存命中率：单节点内存 M_mem = 512GB，缓存对象大小 s = 10MB（图片+短视频平均），则单节点可缓存对象数 = M_mem / s 

- **status**: degraded

- **source**: knowledge
- **edge_type**: cartesian
- **rework_count**: 1
- **parent_ids**: N2

## Claim

内存选型与缓存命中率：单节点内存 M_mem = 512GB，缓存对象大小 s = 10MB（图片+短视频平均），则单节点可缓存对象数 = M_mem / s = 51,200 个；日均下载 2TB = 200,000 * 10MB，假设热点集中度 CR = 0.8（80% 流量来自 20% 对象），则需缓存对象数 = 200,000 * 0.2 = 40,000 个，缓存命中率 H_cache = 40,000 / 51,200 ≈ 78.1%；10 个 POP 点总缓存容量 = 5,120GB，总缓存对象数 = 512,000 个，全局命中率提升至 95%。

## Corrected Claim

单节点可缓存对象数为51,200个。假设热点集中度CR=0.8（80%流量来自20%对象），若缓存策略能完全覆盖这20%的热点对象（40,000个），则理论流量命中率约为80%（具体值取决于长尾分布）。10个POP点总缓存容量为5,120GB，总缓存对象数为512,000个，全局命中率将显著提升，但具体数值需基于实际流量分布模型计算，不能简单断言为95%。

## Evidence

[质询]缓存命中率的计算逻辑存在严重缺陷：将'需缓存对象数'（基于热点集中度CR=0.8推导出的40,000个）直接除以'总缓存容量'（51,200个）得出78.1%的命中率，混淆了'对象覆盖率'与'流量命中率'。实际上，命中率取决于请求分布，若80%流量来自20%对象，且这20%对象（40,000个）全部被缓存，则理论命中率应接近80%（取决于长尾分布的具体形态），而非简单的对象数量比。此外，全局命中率提升至95%缺乏推导依据，仅凭容量增加无法线性或非线性地直接得出该数值，属于经验性断言。 | 先验知识/题面给定，逻辑校验发现命中率计算公式错误（对象数比≠流量命中率），且全局95%命中率缺乏推导支持，属于经验事实且逻辑不自洽。
