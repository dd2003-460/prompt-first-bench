## Corrected Claim

S3 多可用区架构的故障检测时间：S3 自身不暴露健康检查 API，故障检测依赖于客户端重试逻辑；典型客户端（如 AWS SDK）采用指数退避策略，具体延迟和重试次数因 SDK 版本和语言而异（通常初始延迟在百毫秒级，重试次数在 3-10 次之间），总检测时间通常在秒级以内，对总 RTO 影响可忽略（< 0.01%）。

## Evidence

[质询]AWS SDK 的默认重试策略并非固定为“首次100ms、最大3次、总700ms”。不同语言/版本的 SDK 默认配置差异巨大（例如 Java SDK v2 默认最大重试次数通常为 3 次但退避算法更复杂，Python Boto3 默认最大重试次数为 10 次且初始延迟不同），且 S3 故障检测还涉及 DNS 解析、连接超时等网络层延迟，单纯用 700ms 概括“典型客户端”过于简化且缺乏通用性。 | source=knowledge，逻辑量级合理（毫秒级对小时级 RTO 影响确实可忽略），但具体参数（100ms/3次/700ms）属于经验事实且因 SDK 而异，缺乏统一标准支持，故降级。
