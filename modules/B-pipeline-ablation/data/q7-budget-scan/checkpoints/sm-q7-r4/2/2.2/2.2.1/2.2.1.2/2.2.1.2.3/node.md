# N516: 混合I/O干扰中的缓存污染成本：当温数据扫描占用SSD时，OS/文件系统缓存被填满，导致后续冷数据查询（若误存HDD）无法利用SSD缓存加速。量化缓存命中率下降

## Claim

混合I/O干扰中的缓存污染成本：当温数据扫描占用SSD时，OS/文件系统缓存被填满，导致后续冷数据查询（若误存HDD）无法利用SSD缓存加速。量化缓存命中率下降率：假设缓存大小100GB，扫描吞吐7GB/s，缓存刷新率 = 7GB/s / 100GB = 7%/s；若查询间隔<1s，命中率趋近0%，导致所有查询回源HDD，延迟增加 ΔT = T_HDD - T_SSD ≈ 22.5h/次扫描。

## Corrected Claim

混合I/O干扰中，高吞吐扫描（如7GB/s）会快速填充并替换OS缓存（100GB），导致缓存驻留时间极短（约14秒）。若冷数据查询间隔远大于缓存驻留时间，则缓存命中率显著下降，查询将回源至HDD，导致延迟从SSD级别（毫秒级）上升至HDD级别（十毫秒至百毫秒级），具体延迟增量取决于HDD与SSD的性能差距及查询并发度，而非固定的22.5小时。

## Evidence

[质询]数值量级严重失真：7GB/s的扫描吞吐在1秒内会写入7GB数据，远超100GB缓存容量，因此缓存刷新率应为700%/s（即每秒完全刷新7次），而非7%/s；此外，'22.5h/次扫描'这一延迟增量缺乏上下文支撑，属于无依据的经验数值。 | 逻辑校验发现内部矛盾：7GB/s / 100GB = 0.07 s⁻¹ 表示每秒刷新7%是错误的单位换算，实际应为每秒刷新700%（7GB/100GB * 100% * 10s? 不，7GB/s * 1s = 7GB, 7GB/100GB = 7% per second? 等等，7GB/s 意味着每秒写入7GB。100GB缓存。每秒写入量占缓存比例 = 7/100 = 7%。所以每秒刷新7%是正确的量纲理解？不对，如果每秒写入7GB，那么100GB缓存会在 100/7 ≈ 14.3秒 内被完全替换一次。所以刷新频率是 1/14.3 Hz ≈ 0.07 Hz。如果定义为'每秒刷新的缓存比例'，确实是7%。但是，如果查询间隔<1s，而缓存每14.3秒才完全换血一次，那么命中率不会趋近0%。只有当写入速率极高，使得缓存内容在查询前就被覆盖时，命中率才低。这里7GB/s对于SSD来说是非常高的顺序写速度，但对于随机读写的缓存污染，通常取决于工作集大小。更关键的错误在于最后的延迟计算：ΔT = 22.5h/次扫描。这个数值完全没有推导过程，且量级荒谬（单次扫描导致每次查询增加22.5小时延迟？还是总延迟？表述不清且数值离谱）。另外，'命中率趋近0%'的结论依赖于具体的访问模式，不能仅凭刷新率简单推断。由于存在明显的数值推导错误（特别是22.5h的来源不明且量级不合理）和逻辑跳跃，判定为degraded。
