## Q1 注入位置（conf 0.8）
- **主注入点 = P1H_INDEX 尾部（prompts.py L341-342，"【本轮要分解的父节点】"块之前）**。理由：
  ① 它是 OOD S1 臂唯一的逐层分解 prompt，每轮都过——机制习惯要挂在"生成 claim"的地方才有杠杆；
  ② P1H 已有"硬停门禁/反参数展开"这类行为规则先例（L321-334），模板同构，不破坏 JSON 输出契约；
  ③ 尾部追加不碰现有判据（正交/深度/门禁），回归风险最小。
- **次注入点 = P1_L1_SKELETON L19-24（目标函数段后）**：只放 T1 代价模型（"写出代价模型并验证原解是特例"），
  与既有"终点目标函数"步骤天然衔接。
- **不该注入**：T3 量化落地→P3_VERIFY（与"反方质询+经验事实排除条款"职责冲突，会干扰判档）；
  T5 判据瓶颈→P4_SYNTHESIZE（P4 是封闭推理，注入"找瓶颈/把世界变闭合"会诱导越权新增事实）；
  T4 类比审计→EDGE_TYPE_PROMPT（二分类任务，注入审计指令会稀释分类判据）。
- 5 模板里 T2 统一覆盖与 P1H 的"正交性判据"部分重叠，建议合并进 T1 而非独立注入。

## Q2 形式 vs 内容（conf 0.7）
- 机制假说排序（先验）：**知识/先验域分布 > 检索 > 推理深度 > prompt 锚定**。依据：T2c 显式域声明 3/3
  翻转且内容质检 3/3 域内真推理非回声（decomposition T2b/T2c 节）→ 推理深度和锚定都够；臂B 能推 D 原文
  没有的新预言 → 不是纯模仿；27b 把"敏感性"100% 解读成混沌域 = 训练先验里"敏感性→动力系统"的强关联，
  是**知识分布**问题。T2b 软锚点 0/3 说明"自查式"锚定无效——模型感知不到自己的漂移。
- 最便宜判别探针（一次实验）：**同题双臂，唯一变量=给不给域内知识锚点**（如给一段域内机制综述/
  3-5 条域内事实作为"已确认事实"块，复用 P1H 的 confirmed_block 通道，零 harness 改动）。
  判据：注入知识后 flip（域身份）0→1 且 form 不降 → "机制激活了但知识不够"；仍 flip=0 → "机制没激活"
  （或模型根本不用外部知识锚点，需第三臂排除）。n=3/臂 × 2 题，~30min。
- 注意：此探针测的是"知识缺口"，不测"能否自主选域"——T2c 已证后者仍是 gap，两件事别混。

## Q3 实验设计（conf 0.65）
- 样本量：3 域 × 2 reps × 40 节点 = 每臂 6 个观测。**不够**——K4b 已示范 n=1 rep 时 +5.4pp 贴边出带
  只能算弱证据。最小修正：reps 3（每臂 9 观测，域内做 paired 比较，域间只报方向）；若 GPU 不够，
  砍到 2 域 × 3 reps 优于 3 域 × 2 reps（域间方差 > rep 间方差，reps 更值钱）。
- "机制真的落地"判据（预注册，先 commit）：主指标 = **align = flip × form**（T3 已定义的 formalism 同构
  判据），不是 form 单维。V1 胜 = align 提升且 form 不降；form 升 align 平 = 形式模仿（T2 臂B 重演）。
- 可计算机械指标（全从 run json + transcript 算，无 LLM）：
  - 机制覆盖率 = 含"机制三要素 ≥2"（参数变化+因果说明+影响量，D 2026-11-27 判据）的节点 / 总节点；
    三要素用正则+关键词初筛 + 抽样 10 条人工核（防 judge 偏松前科）。
  - 量化 claim 密度 = 含数字/公式/区间的节点 / 总节点（正则：数字+单位/∈[]/=/≈）。
  - 域偏移率 = transcript（content+reasoning 都要抓，T2 陷阱）中域外机制词命中 / 域内机制词命中，
    词表预注册（如气象域：非凸/landscape/梯度 vs 混沌/李雅普诺夫）。
  - 三指标必须同向动才算"落地"；只动量化密度 = Goodhart（P1H 反参数展开条款的镜像）。

## Q4 失败预案（conf 0.7）
- V1 只升 form 不升 align（最可能，T2 已预演一次）时，按判别树走，别直接跳 hook：
  1. 先跑 Q2 的知识锚点探针（最便宜，~30min）：flip 翻转 → 是知识缺口 → 走 RAG/confirmed_block
     注知识，prompt 模板保留；
  2. 探针不翻转 → 换注入方式：模板从"通用指令"改"域条件化指令"（T2c 已证显式域声明 3/3 有效，
     软指令 0/3）——即 V1.5 臂 = 模板 + 每域显式域声明，成本仅加 3 段文案；
  3. V1.5 仍不翻转 → 才升级假设：27b 的域选择能力是能力缺口非 prompt 缺口 → 走 T5 路由器把选域
     外移（域由 harness 给，不指望模型选）或换模型；hook 级（stop_hook 反思注入）解决的是
     "做多想少"的触发频率，不解决域偏移，**不是本失败的对症药**，除非探针证明是激活频率问题。
- 预注册红线：V1 失败判据（align 提升 < 某阈值且 form 提升 > 阈值）必须在跑前 commit，防 post-hoc 挪门。

## 反对 Lead 可能倾向的地方（独立判断）
1. **反对"V2=调研 top 机制"作为并行臂**：V2 未定义就占 3 域 × 2 reps 的 GPU 预算是浪费——V1 的
   判别结果决定 V2 该调研什么（知识缺口→调研 RAG 注入；激活缺口→调研 CoT/反思）。V2 应串行在
   Q2 探针之后，不是并行。
2. **反对把"机制覆盖率"当主指标**：它是过程指标，可被刷（节点多→命中多，表面积混杂，post_acc
   救活探针已踩过同坑）。主指标必须是 align（对 gold 域身份），覆盖率只做诊断。
3. **对 K4b 判决的保留**：卡内把"域味=负资产"当硬约束，但 oood-column-status.md 自己注记了
   "+5.4pp 贴边出带、n=1 无 CI、S1 的 2 个命中非特异性"。设计 V1 时别把"域味该删"当成已证事实
   写进预注册——它只是方向性证据。
4. **40 节点/臂可能结构性封顶**：Q9E 已证 298 节点硬顶 + 深层零信息增益（代数展开非机制级）。
   40 节点下机制级节点可能本来就稀少，三域 × 40 的机制覆盖率差异可能全在噪声里——建议先跑 1 域
   × 40 节点 pilot 看指标方差，再决定 40 节点够不够分辨。
