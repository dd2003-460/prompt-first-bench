# 到可发表里程碑的最短路径（分析）

## 缺口登记（自驳失败保留的质疑）
1. "可发表"定义=内部完成口径（五子项+主端点输出），非发表标准：无统计有效性、无基线对比、无机制 claim；定案需：D 裁定发表的最低证据标准。
2. "每档 3 runs 足够、方差小"是未测量前提；主端点（首次 100%，即决定成败的唯一核心指标）是阈值跨越量，3 样本下一次 run 之差=67% vs 100%；定案需：12 个已落盘 run 的命中率实测方差 + 预注册的跨越判据。
3. 主端点可能无定义：若 719 档仍未达 100%，"首次 100%"无值，快照无后备定义；定案需：低档命中率趋势 + 预注册的未达 100% 后备口径。
4. 调度：D1 排序键裁定排在 4-6h 等待之后，但它是与 719 数据无关的定义选择，人工瓶颈应并行；定案需：确认 D1 不依赖 719 结果。
5. 4-6h 等待是最长杆，719 后两次 run 靠队列自动接力；接力或推理服务挂掉时无失效检测，路径静默延长；定案需：监控检查点或手动重启预案。

## 最短路径（关键路径 ≈ max(719 等待, D1 人工延迟) + 几分钟分析）
步 0（现在，分钟级）：对 12 个已落盘 run 跑扫描分析 → 临时主端点 + 每档方差。为何最短：零墙钟成本；把盲等变知情等；同时定案质疑 2/3；若低档已达 100%，719 等待退出端点的关键路径。
步 1（与步 0 并行，立即）：报 D 裁 D1（惩罚项 vs 纯后验准确率 post_acc）。为何最短：排序键是定义选择、不依赖 719 数据；人工响应是最长非计算杆，挪进等待窗口即移出串行链。
步 2（4-6h，不可压缩）：719 三连自动接力落盘；队列加一个监控检查点。为何最短：纯算力时间，无任何步骤能压缩它；监控防静默延长（质疑 5）。
步 3（落盘后，分钟级）：全 15 run 重跑分析 → 最终主端点 → 子项④收口。为何最短：端点是数据的确定性输出，"无需加 run"口径下不再需要额外实验。
步 4（D1 裁定后立即）：gold（标准答案集）冻结 → 子项⑤收口。为何最短：⑤ 唯一剩余依赖是裁定，题面/A-B 对照/评分细则均已就绪。
步 5：④⑤ 双收口 → 五子项 100% + 主端点输出 → 里程碑达成，上报。注意：达成里程碑 ≠ 可发表（质疑 1），发表证据标准需另裁。
