# 到可发表里程碑的最短路径（基于 11-28 快照）

## 缺口登记（质疑自驳失败后保留）
1. 「可发表」被定义为「五子项 100% + 主端点输出」，这是完成判据而非可发表判据：未预注册主端点取到什么值算阳性结果（若 100% 从未达到、或在最小预算就达到，端点还算「输出」吗）。定案需要：D 确认定义 + 预注册阳性判据。
2. 「每档 3 次足够、方差小」是断言不是测量：已有 12 个重复落盘，现在就能算出每档方差，但快照未附数字。定案需要：用 12 个落盘重复算每档标准差并附进口径（分钟级成本）。
3. 主端点聚合规则未写明：「gate 命中率首次 100%」是按单个重复还是按档均值？每档仅 3 个重复时两种口径可能给出不同答案；且若 100% 永不达到则端点无定义。定案需要：一行写明聚合规则 + 退化情形兜底定义。
4. ④↔⑤ 依赖不清：若主端点（gate 命中率）的参照是 ⑤ 的 gold 排序，则 ④ 收口实际也被 D 裁决门控，快照「④⑤ 并行」是假象。定案需要：一行确认命中率参照的是冻结题面还是 gold。
5. 快照「最便宜下一步」把两个独立动作串行了：D1 裁决（A: 惩罚项 vs B: 纯 post_acc）并不显然依赖主端点，却排在「报 D 裁」于端点之后。若裁决不依赖数据，现在就发起请求可严格缩短关键路径。定案需要：D 确认裁决是否需要主端点作为输入。

## 最短路径（关键路径 ≈ 等 719 档 3 个重复落盘的 4-6h + 分钟级脚本工作）
- 第 0 步（现在，并行，零成本）：用 12 个落盘重复算每档方差 + 锁定主端点聚合规则 + 预注册阳性判据。为什么在最短路径上：全是主端点可信的前置条件，且在等待窗口内做，不增加任何墙钟时间；若方差其实大，「无需加重复」的前提崩塌，必须在等待期发现而不是事后发现。
- 第 1 步（现在，并行，零成本）：向 D 发出 D1 裁决请求（一行：A vs B）。为什么在最短路径上：D 裁决是全路径唯一人工门控项，与 719 重复独立（见缺口 5），晚问一小时 = 关键路径长一小时。
- 第 2 步（~4-6h，被动）：等 719 档 3 个重复落盘（队列自动接力，无需动作）。为什么在最短路径上：第 15 个重复落盘前主端点在物理上不可计算，这是路径的不可压缩下界。
- 第 3 步（落盘后，分钟级）：重跑既有 Q9 扫描分析，出主端点（gate 命中率首次 100% 的最小预算）+ 预算曲线 → ④ 收口。为什么在最短路径上：④ 的收口就是一次脚本执行，第 0 步备好参数后它是一条命令。
- 第 4 步（裁决后，大概率在第 2 步期间）：按裁决冻结 gold → ⑤ 收口。为什么在最短路径上：⑤ 剩余工作只有裁决落地；裁决若在等待期到达，⑤ 先于 ④ 收口，里程碑宣告不再需要任何额外等待。
- 第 5 步（收尾，分钟级）：宣告里程碑：5/5 子项 + 主端点数值；满足预注册阳性判据即报 D 可发表。为什么在最短路径上：这就是里程碑本身，按定义其后无更多工作（写论文不在此里程碑范围内）。

结论：关键路径长度由第 2 步的 4-6h 决定（不可避免）；真正的风险不在时间而在缺口 1/3 的定义洞——第 0 步预注册判据把「第 5 步可能卡住」变成「结果已知」。
