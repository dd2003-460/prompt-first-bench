# 到可发表里程碑的最短路径（基于 11-28 16:05 快照）

## 缺口登记
1. “可发表”=五子项 100%+主端点输出，属内部完成门槛，非投稿级证据（新颖性/显著性/可复现均未验）——需 D 确认口径：内部门禁还是真论文。
2. “每档 3 runs 足够、方差小”是循环论证（用同样 3 runs 证明 3 runs 方差小），且“首次 100%”端点对单个 run 翻转敏感——需 12 个已完成 run 的实测方差，或对关键档做一次敏感性复查。
3. 若 719 档未达 100% gate 命中率，主端点无值，定义未给负端点处理——需预注册后备口径（最高达成命中率+饱和预算）。
4. 快照计划把 D 的 D1 裁定排在分析之后（串行），但裁定内容与 719 结果无关——需改为并行：719 在跑时即问 D。

## 最短路径
步骤 0（立即，与计算并行）：向 D 要 D1 排序键的一句话裁定。为什么最短：关键路径上唯一的人工依赖，且决策内容不依赖 719 结果；现在问就把“报 D→等裁定→冻结 gold”这段串行尾巴从关键路径上消掉，省一次人工往返。
步骤 1：等 719 档三连落盘（~4-6h，队列自动接力，无需人工干预）。为什么最短：最后一块缺失数据，④收口与主端点都卡在这；步骤 0 已并行化后没有其他可并行动作，等待是不可压缩的关键路径下界。
步骤 2：重跑分析脚本出主端点（gate 命中率首次 100% 的最小预算），顺带检查 719 档方差。为什么最短：分钟级机械步骤，直接收口 ④；方差检查搭同一份数据的顺风车，补齐缺口 2 的证据。
步骤 3：按 D 裁定（步骤 0 已拿到）冻结 gold → ⑤收口。为什么最短：裁定已在手，此处只剩分钟级机械动作，是里程碑的最后一个门；排在这里保证步骤 2 之后不再出现人工等待。
步骤 4：逐项核对五子项 100% 完成+主端点输出，宣布里程碑达成。为什么最短：这就是里程碑定义本身，核对成本趋近于零。
风险分支：若 719 档未达 100%，主端点无值——执行预注册后备口径（报最高达成命中率+饱和预算），同时问 D 负端点算不算可发表，避免事后新增阻塞问题。

总耗时：~4-6h（计算等待主导）+ 分钟级机械步骤；相比快照原计划，步骤 0 前移省掉一次人工往返。
