## soc：GOLD 不是维度集，是推理链（重大发现）

7 个维度：假设链起点 / 现象A解释 / 现象B解释 / 解释力评估 / 利益相关方 / 最小干预 / 置信度标注。
18/21 相关（conf 全 0.95），相关模式是**链式依赖**：

- g0（假设链起点）与 g1-g6 全部相关——起点变了，后面全变
- g3（解释力评估）依赖 g1+g2（它是后两者的元评估）
- g5（最小干预）依赖 g3（干预设计依赖归因）
- g6（置信度标注）与 g0-g5 全部相关——置信度是依附于断言的元数据，不是独立维度

**诊断**：soc 的 GOLD 把一条推理链（假设→解释→评估→利益相关方→干预→置信度）的每个环节都标成了"维度"。这不是 G9 要的正交维度集，是**答案结构 checklist**。

**后果**：若直接拿 7 维 soc GOLD 算 U(T) 的 C 项，C 会系统性虚高——一条完整推导同时满足 7 个"维度"，乘积语义完全失效。

**三个选项**（待 D 决策）：
1. **soc 换维度集**：把 7 环节压成 2-3 个真维度（如：归因质量 / 干预-受害者一致性 / 不确定性处理），环节降级为 rubric 细则
2. **soc 用链式 rubric**：承认 soc 是链式题，C 项改用"链完整度"（断链在哪一环）而非维度乘积
3. **维持现状**：soc 不进 U(T) 机器侧验收，只做 rubric 计分（nat/gpu 进）

## gpu：hub 结构（VRAM/TCO/条件性推荐 是枢纽维度）

- g0（VRAM 门槛）与 8 个维度相关——它是物理约束枢纽，容量决定精度/卡数/TCO/并发
- g6（TCO 公式）与 g7（电费）/g8（故障损耗）是**整体-部分**关系（g6 公式包含 g7/g8 项）→ 真合并候选
- g14（来源标注+条件性推荐）与 g11/g12/g13 相关——它是元维度（对其它维度的标注要求），不是独立维度
- 44/105 独立 + 8 层级相关（spec 层独立/性能层耦合，正是 Decision 22 预见的层级条件化）

**gpu 合并候选**（待重跑确认）：
- g6×g7（TCO 包含电费项）、g6×g8（TCO 包含故障损耗项）：整体-部分，合并
- g14：元维度，从 C 项里剔除（它不描述答案内容，描述答案的标注规范）

## 跨题模式（对 G9 设计的启示）

1. **"方法 vs 题面实例"混淆**（nat g0×g1 型）：GOLD 应拆成 维度（跨题方法）+ 实例（本题参数），U(T) 只对维度计分
2. **元维度混入**（gpu g14 / soc g6 型）：置信度标注、来源标注是 rubric 层要求，不是 gold 维度——混入会虚高 C
3. **整体-部分**（gpu g6×g7×g8 型）：公式与其子项不能同时计分
4. **链式结构**（soc 型）：某些题的"维度"本质是推理链环节，乘积语义不适用
